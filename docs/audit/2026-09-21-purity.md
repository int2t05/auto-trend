## Fixed

### 1. `scripts/main.py` — pipeline 重试捕获运行时异常（D11）

**Before**：`asyncio.run(run_pipeline(report_date))` 无 try/except。`run_pipeline` 抛异常时，异常直接传出 for 循环，进程崩溃退出。`MAX_PIPELINE_ATTEMPTS` 重试机制只对 `verify_report` 失败生效，对运行时异常无效——形同虚设。

**After**：`try/except Exception` 包住 `asyncio.run`。异常被捕获后：
- 打印异常摘要（type + message）
- `attempt < MAX_PIPELINE_ATTEMPTS` → `continue` 重试
- `attempt == MAX_PIPELINE_ATTEMPTS` → `sys.exit(1)`，不 commit

这是第一轮 purity audit 的 "待评审 A" 项——现在已从 "待评审" 变为 "已修复"。

### 2. `scripts/analyzer.py` — `_normalize_analysis` 规整 LLM 字段类型（第一轮已修，本次确认在位）

`_normalize_analysis` 在 `json.loads` 之后立即调用：string 字段统一 str，list 字段统一 `list[str]`。LLM 偶尔把 `use_cases` 返回成数组时，此函数在 LLM 边界兜底，下游 `rss.py` 和 `renderer.py` 拿到的数据契约统一。

### 3. 回归测试 `tests/test_main.py`（新增 2 个）

- `test_main_catches_pipeline_exception_and_retries` — `run_pipeline` 持续抛 `AttributeError`，验证 main 捕获并重试到 `MAX_PIPELINE_ATTEMPTS` 次后 `sys.exit(1)`
- `test_main_retries_after_crash_then_succeeds` — 第一次崩溃第二次成功，验证重试后正常退出

### 4. `docs/TECH.md` 同步
