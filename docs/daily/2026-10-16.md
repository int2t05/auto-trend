### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +32,314 今日新增 · 275,082 总星数

> REA 是一个 MCP 服务器，把 AI Agent 接到逆向工程工具上，用来分析原生二进制、Electron/JS 应用、.NET 程序集和网站，在同一台机器上跑并给出证据链。

**亮点**

- 不重造反编译器，直接复用用户机器上已装的 Hopper、Ghidra 或 IDA，REA 只做编排和证据整理，省掉了重复的逆向引擎投入。
- 分析全部在本地执行，目标文件不出本机，这点对分析闭源商业软件和恶意样本的人很关键。

**核心功能**

- 通过 MCP（一种让 AI Agent 调用外部工具的协议）把 Ghidra、Hopper、IDA 当后端，Agent 直接拿到反编译伪代码、汇编、字符串、符号和函数调用引用，不用自己写脚本驱动这些工具。
- 静态 JS/Electron 分析不依赖任何原生反编译引擎：直接扔一个目录或 ASAR 包（Electron 打包后的归档文件），输出模块列表、import 关系、主进程与渲染进程的边界。
- 每条结论都附带证据和已知局限，CLI 和 MCP 走同一套流程，支持 --json 输出，方便塞进脚本或 CI。

**适用场景**: 三类人：想抄某个 App 里某个功能的产品/前端工程师；要搞清楚闭源 Electron 桌面应用怎么实现的开发者；分析固件、恶意样本的安全研究员。用法是让 Claude Code、Cursor、Codex 这类 Agent 自己去调查并给出实现。

**竞品对比**: 已有 Ghidra、IDA 各自的 MCP 插件和 mcp-ghidra 这类单点方案，但基本只管二进制。REA 的差异是一套 MCP 同时覆盖二进制、JS/Electron、.NET 和网站，并把'证据+局限'当默认输出。代价是对 IDA/Ghidra 的分析深度仍受后端限制。

**成熟度**: 早期项目，README 自己说'REA changes quickly'、更新频繁，API 和命令可能还会变；但官网、Discord、多语言文档和 showcase 都已齐备，社区在快速起来。

**趋势信号**: 2025 年 MCP 生态爆发，Agent 工具链从'帮我写代码'扩展到'帮我拆别人的二进制'，REA 正好卡在这个位置，加上 Electron 和闭源桌面应用分析需求一直很旺。

### [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)

 `Python` ⭐ +3,024 今日新增 · 69,429 总星数

> VoiceStudio 是一个完全本地运行的 ElevenLabs 开源替代品，把语音克隆、配音、听写、转录、有声书制作塞进一个 Electron 桌面应用，支持 646 种语言，数据不出本机。

**亮点**

- 把'本地优先'做成了默认路径而不是可选项：分析统计要用户明确同意才开，远程服务只是可选，模型权重和生成内容的授权边界在 Model Manager 里单独提示（附证据链接和未决审查点），这在语音克隆这类版权敏感领域是少见的做法
- 一个应用覆盖完整音频工作流：克隆→设计→配音→听写→有声书，不是单点工具。同步支持 watch folder（丢文件进目录自动处理）和可复用 recipe

**核心功能**

- 引擎可插拔：默认用 k2-fsa/OmniVoice，但整套架构把 TTS/ASR 模型抽象成可切换的 engine，用户能在应用里装不同本地模型（模型管理器），不被单一模型绑死
- 本地 API + MCP server：对外暴露 HTTP 接口和 Model Context Protocol，让 Claude Code、Cursor 这类 Agent 直接调用语音合成，不用自己写胶水代码
- 从 Tauri 迁移到 Electron：0.5.3 是最后一个 Tauri 版本，旧壳已删除。原因是需要本地 Python 后端 + Rust/Cargo 构建链太重，Electron 更适合打包 Python 运行时和跨平台分发
- 硬件自适应：NVIDIA 走 CUDA，Apple Silicon 走 Metal/MPS，没独显就装约 5GB 的 PyTorch CPU 小包降级跑，Windows on ARM 是 x64 Python 走模拟的试验状态

**适用场景**: 内容创作者、播客和有独立开发需求的团队：做视频多语言配音、批量生成有声书、给应用嵌入本地 TTS/ASR 而不想把音频传到云端 API。也适合对隐私敏感的行业（医疗、法律）做本地听写和转录。

**竞品对比**: 直接对标 ElevenLabs（云端、按量付费、音频出本机）；开源侧对手是 Coqui TTS、GPT-SoVITS、F5-TTS 这类单点模型仓库。最大差异是它是成品桌面应用+多引擎编排+Agent 接口，而不是一个需要自己写推理脚本的模型目录。

**成熟度**: 版本仍在 0.x（0.5.3 后刚切到 Electron 重构），API 和安装方式都可能变，但 CI、多语言文档、Discord、Docker/三平台安装包齐全，属于'能日常用但别指望稳定接口'的阶段。

**趋势信号**: ElevenLabs 等云语音服务持续涨价和版权争议，加上本地小模型（OmniVoice 等）质量追上来，'本地 ElevenLabs'这个叙事正好卡在点上；同时 README 里专门给 coding agent 写安装指南、提供 MCP 接口，踩中了 Agent 工具链的流量。

### [NationalSecurityAgency/ghidra](https://github.com/NationalSecurityAgency/ghidra)

 `Java` ⭐ +1,369 今日新增 · 88,955 总星数

> 美国国安局开源的逆向工程框架，能把编译好的二进制反汇编、反编译成类 C 代码并做脚本化分析。近期新版把运行环境抬到 JDK 25，并内置 PyGhidra 让 Python 直接调用它的 API，所以重新冲上趋势榜。

**亮点**

- NSA 把自己内部用了十几年的工具整体开源，连反编译器实现和指令集描述文件都放出来，这在国家级机构里很少见
- 自带共享项目仓库（Ghidra Server），多个分析师能同时对同一个二进制做标注、改函数名，解决团队逆向时注释和命名互相覆盖的问题

**核心功能**

- 反编译器把汇编还原成可读的伪 C 代码，支持 x86、ARM、MIPS、PowerPC 等大量指令集，以及 PE、ELF、Mach-O 等可执行格式
- 处理器指令集不写死在代码里，用自研的 SLEIGH 描述语言定义，加一款新芯片指令集只需写描述文件，不用改框架内核
- 支持无头（headless）命令行模式，配合 Java 或 Python（PyGhidra）脚本可批量跑分析，容易塞进 CI 或样本自动处理流水线

**适用场景**: 安全研究员和恶意软件分析师拿到没有源码的样本或固件时，用它看程序逻辑、找漏洞；CTF 选手比赛时逆向题目二进制；企业漏洞响应团队排查老旧闭源系统的安全问题。

**竞品对比**: 主要对手是商业的 IDA Pro 和开源的 radare2/rizin。Ghidra 免费、反编译质量接近 IDA，最大差异是脚本生态同时支持 Java 和 Python 且没有授权限制；IDA 的反编译体验仍略成熟但价格高，radare2 更轻量但上手更陡。

**成熟度**: 生产可用，正式版已迭代多年（版本号远超 1.0），文档齐、issue 活跃，NSA 内部和大量安全团队在用；但 README 自己提醒部分旧版本存在已知安全漏洞，需先查安全公告。

**趋势信号**: 新版把最低环境要求提到 JDK 25、Gradle 9.1，并在发行包里直接内置 PyGhidra，Python 用户不用再折腾插件就能调 Ghidra API，引发一波升级和讨论。

### [mksglu/context-mode](https://github.com/mksglu/context-mode)

 `TypeScript` ⭐ +904 今日新增 · 29,878 总星数

> MCP 服务器，把 AI 编程 agent 的工具输出挡在上下文外（省 98% token），再用 SQLite+FTS5 记住会话进度，压缩后能接着干。

**亮点**

- 刻意不做向量数据库。会话记忆走 SQLite FTS5 + BM25 全文检索，省掉嵌入模型和向量库的依赖与延迟，代价是只能关键词召回，语义模糊的查询会漏。
- 提出「Think in Code」：让模型写脚本去数、去算、去过滤，只 console.log 结果，而不是把 50 个文件读进上下文自己数。这条被当成所有 17 个客户端的强制范式。
- 明确拒绝管模型的说话风格。README 引用 Moonshot 的案例说激进简洁提示词会拉低编码/推理分数，所以路由只管数据去哪，不管模型怎么答。

**核心功能**

- 沙箱化工具输出：ctx_execute 等 6 个工具在沙箱里跑，只有结果回上下文。README 给的数字是 315KB 压到 5.4KB（98%），比如 47 次 Read 约 700KB 换成 1 次脚本执行 3.6KB。
- 会话记忆用 SQLite 存事件（文件改动、git 操作、任务、报错），压缩时不再把历史灌回上下文，而是索引进 FTS5 用 BM25 关键词检索按需取回，不走向量嵌入。不加 --continue 就立刻删掉上个会话数据。
- 用 hook 做路由强制：Claude Code 上注册 SessionStart、PreToolUse、PostToolUse、PreCompact、Stop 六个钩子，启动时注入路由指令，不往项目里写文件；没 hook 的平台要手动拷一份路由文件。

**适用场景**: 用 Claude Code、Cursor 等带 MCP 的 AI 编程 agent 的开发者。典型场景是让 agent 抓 Playwright 快照、拉 GitHub issue、读日志或大目录，这些原始数据几十 KB 一发就把上下文吃光；以及长会话被自动压缩后 agent 忘了改到哪个文件的团队。

**竞品对比**: 对标 Claude Code 自带的 auto-compact、Cline 的上下文管理，以及 mem0/Zep 这类向量记忆层。最大差异有两点：一是挡在工具输出进上下文之前（源头削减），而不只是事后压缩；二是记忆用 FTS5/BM25 而非向量检索，不引入嵌入模型。

**成熟度**: 可用但需留意：29.8k star、HN 第一、有 ctx_doctor 自检和 Discord，工程完整度不低；但用 ELv2 许可（非标准开源，禁止直接拿去做托管服务），README 里的企业 logo 墙无法核实，实际生产验证程度存疑。

**趋势信号**: 踩中当下 AI 编程 agent 上下文被打爆这个普遍痛点，又借 MCP 生态爆发和 Claude Code 插件市场上线的窗口冲上 HN 第一（570+ 分）。

> Rust 写的本地搜索引擎，一条命令索引任意文件夹，让 AI 用查询代替 grep 读文件，省下大量 token。

**亮点**

- 主推"参考编码"用法：先让 agent 下载并索引与当前任务最接近的开源仓库，查别人怎么解决再写自己的代码。受控实验（8 个任务、4 种语言、每组 16 次运行、用 claude -p 真实 token 计数）显示输出 token 比 grep 少 2.7 倍、比纯靠记忆少 26 倍，解决率都是 16/16，作者也承认模型已经背过的热门库上收益为零甚至为负
- 不发明新查询语言，直接复用 Elasticsearch 协议，等于白送一整批现成的客户端、仪表盘和 ES 生态工具，省掉用户迁移成本

**核心功能**

- autoindex 自动嗅探文件类型，给代码、文档、日志、PDF、SQLite、CSV 各建一份带类型的索引，不用写 schema，也不用配数据管道
- 默认走 BM25 词法检索，完全离线、不下载模型；神经向量检索是可选开关，开了要下约 90MB 模型，然后支持 BM25 + kNN + 混合排序
- HTTP API 兼容 Elasticsearch，拿现成的 ES 客户端就能连；项目跑 ES-YAML 兼容性测试，1366/1369 条通过
- 单个静态二进制，不带 JVM，附 MCP server，一条 xerj init 就能接进 Claude Code / Cursor，另有 /_memory 命名空间当 agent 记忆用
- 提供 xerj def 做定义跳转（返回 file:line + 函数签名），xerj gain 统计实际省下的 token，而不是估算

**适用场景**: 用 Claude Code、Cursor 写代码的开发者，索引公司内部私有仓库或冷门库，让 agent 查而不是盲读文件；也适合安全审计人员把日志、PDF、CSV 一次性索引后做 RAG 检索。

**竞品对比**: 和 ripgrep/grep 比是"检索结果"对"整文件灌进上下文"的区别，和 Sourcegraph、Zoekt 比是本地单机不依赖服务端；和 Elasticsearch、Meilisearch、Qdrant 比，最大差异是单静态二进制、无 JVM、免运维，且协议层面兼容 ES。

**成熟度**: 早期项目，但已有 CI、正式 Release、完整文档站和安全模型文档；默认 --insecure 模式关闭 TLS 和鉴权，只适合本机单人使用，别暴露到公网。

**趋势信号**: Claude Code、Cursor 这类编码 agent 目前主要靠 grep/sed 读文件烧 token，加上 MCP 工具生态和"上下文工程"正好是当下热点，XERJ 直接切进这个痛点并给出可量化的省 token 数据。

### [lightseekorg/tokenspeed](https://github.com/lightseekorg/tokenspeed)

 `Python` ⭐ +30 今日新增 · 2,544 总星数

> TokenSpeed 是面向 Agent 场景的 LLM 推理引擎，把控制面和执行面拆开：C++ 管调度、Python 跑模型，主打高吞吐和 Day-0 新模型支持。

**亮点**

- 控制面/执行面分离：正确性最要紧的调度部分用 C++ 加类型系统做静态保证，需要快速试错的部分留给 Python。这是它和 vLLM、TensorRT-LLM 最根本的架构差异，PyTorch 官方在收录它进生态时专门点了这一条。
- 非营利基金会（LightSeek）背书，NVIDIA 和 AMD 同时出人出力，定位是推理引擎里的中立派。不像 TensorRT-LLM 绑 NVIDIA、vLLM 有自己的商业公司，它更容易同时吃两家硬件，AMD MI355X 上跑 Kimi K3 就是例子。

**核心功能**

- 调度器把请求生命周期、KV cache 归属、计算与通信的 overlap 时序全部写成有限状态机（就是状态和跳转规则固定的流程图），控制面用 C++ 实现，靠类型系统在编译期就挡住 KV 资源被重复引用，而不是等到运行时才检查。
- 执行面用 Python 写，换模型、调算子不用重编译 C++，迭代快；kernel 被拆成独立插件子系统，有统一的注册表和选择机制、公开的移植 API，方便接不同加速器。
- 自带针对 Blackwell 优化的 MLA（Multi-head Latent Attention，DeepSeek 系模型用来把 KV cache 压小的注意力变体）实现，官方称是 agentic 场景下最快的之一；入口层用 SMG 集成的 AsyncLLM 降低 CPU 侧请求处理开销。

**适用场景**: 跑在线 Agent 产品的后端团队最需要它：coding agent、多轮工具调用、长上下文这类场景，既要单用户高 token/s（官方给了 GB300 上 685 tokens/s/用户的数据），又要高并发吞吐。另外是云厂商和模型公司，需要在 Kimi K3、Qwen3.8、GLM 5.3 Flash 等新模型发布当天就能上线推理。

**竞品对比**: 直接对标 vLLM 和 TensorRT-LLM。官方自己的说法是性能对齐 TensorRT-LLM、易用性对齐 vLLM，并在 Kimi K2.5 上放出了与 TensorRT-LLM 的 Pareto 曲线对比。最大差异是控制面/执行面分离的架构，以及中立身份带来的多硬件支持（NVIDIA GB300/B200 和 AMD MI355X 都有落地）。

**成熟度**: 早期项目，还没有 1.0 版本，API 可能变动；文档比较完整（有 Getting Started、模型 recipes、server 参数说明），也有 NVIDIA/AMD 官方博客和 Day-0 模型支持背书，但社区规模仍小，只有 2500 多 star，属于厂商推动多于用户自发的阶段。

**趋势信号**: 推理引擎的竞争焦点正从通用对话转向 Agent 工作负载（多轮、长上下文、单用户高 token/s），TokenSpeed 同期拿到 PyTorch 生态收录、NVIDIA 与 AMD 双方站台、多个前沿模型 Day-0 支持，最近又放出 Vera Rubin 上的 MLA 2 和 GB300 上的吞吐数据，所以持续被关注。

## 趋势观察

今天的热榜几乎被“给 AI Agent 打辅助”包场。共同点很清晰：大家不再只卷模型，而是卷 Agent 的外围设施。第一，MCP 成了事实标准。逆向工程、科研技能、编程工具都通过 MCP 接入 Agent，官方也下场做插件市场。第二，省 token 成了刚需。压缩日志、把工具输出挡在上下文外、用本地搜索代替 grep，都是在给上下文减负。第三，技能和方法论开始标准化。177 个科研技能包、开发方法论、跨工具插件层，都想做通用标准，不让 Agent 绑死在某一家。第四，多 Agent 协作和记忆在补课。组队、跨会话、跨机器联邦，说明单次对话不够用了。第五，本地和隐私优先。VoiceStudio 本地跑语音克隆，Rust 本地搜索，数据不出本机。第六，安全与逆向也在 AI 化。NSA 的 Ghidra 新版内置 Python API，AI Agent 直接接逆向工具。新闻热点上，Anthropic 官方插件目录、Agent Skills 标准改名，都指向同一件事：生态从野蛮生长转向收口。开发者现在拼的不是模型参数，而是谁能把工具、记忆、权限、成本管好。一句话，Agent 的“操作系统层”正在快速成形。
