### [google/ax](https://github.com/google/ax)

 `Go` ⭐ +1,543 今日新增 · 9,306 总星数

> Google 开源的 Agent 编排运行时，用 YAML 声明 Task/Workspace/Gateway/Model，在 K8s 上沙箱化批量跑 Agent 任务。

**亮点**

- 把 Agent 单独当一类工作负载处理：它不是无状态微服务，也不是跑完就退的批处理 Job，会攒状态、要严格隔离、可能死循环烧钱，所以四个原语是专门为这三件事设计的，而不是拿 K8s Job 硬套
- CLI 完全照抄 kubectl 的手感（apply/get/describe/watch/delete），还跟着 kubectx 走上下文、后台自动往控制面打隧道。用过 K8s 的人基本零学习成本

**核心功能**

- 四个声明式原语走 K8s 那套：Task 管沙箱执行、Workspace 预挂 Git 仓库和 MCP server、Gateway 管网络出口、Model 管用哪个 LLM 和凭据（从 K8s Secret 读），一条 ax apply 全部落下
- Gateway 做出口白名单，按 host 显式放行出站流量。默认网关 EGRESS-HOSTS 是 *，可以收窄到指定域名，用来防 Agent 乱调外部 API 把预算烧穿
- suspend/resume 走 checkpoint：空闲任务存盘暂停，恢复时从断点接着跑。沙箱底层是 Agent Substrate，带 CPU/内存限额，spec.debug 打开后能 ax ssh 进容器看现场

**适用场景**: 平台和基础设施团队，需要在集群里批量跑不受信任的 Agent 代码，比如让 Agent 自动改 Go 仓库代码、跑批量 code agent 任务。要的是隔离、限流、能进去看、别烧钱。

**竞品对比**: 和 LangGraph、CrewAI 这类单进程内的编排库不是一个层面，和 Temporal 也不同——那些不管沙箱隔离、网络出口和模型凭据。最像的参照物其实是 Kubernetes 本身，差别是多了 Gateway 出口管控和 suspend/resume 检查点。

**成熟度**: 早期项目，v1alpha1，README 自己挂了警告说稳定版前会有 breaking change；要跑起来得先有 K8s 集群、ko、容器镜像仓库、Redis 和 Agent Substrate 控制面，别急着上生产。

**趋势信号**: Google 官方下场占“Agent 跑在哪儿”这一层，一天涨 1500+ star。当前大家都在造 Agent，但沙箱、网络管控、多租户调度这层还缺标准方案，它直接套 K8s 的成熟范式切进来，自然被围观。

### [dream-num/univer](https://github.com/dream-num/univer)

 `TypeScript` ⭐ +1,142 今日新增 · 16,468 总星数

> Univer 是一个 TypeScript 写的开源 Office SDK，用 Canvas 自绘加插件内核，在浏览器和 Node.js 里跑同一套表格/文档/幻灯片引擎，现在主打给 AI Agent 当操作办公文件的后端。

**亮点**

- 渲染层自己重写：不依赖 DOM 表格，而是 canvas 直绘 + 自己的布局/滚动/选区体系，这是它能扛大表格、也能在 Node 端无界面跑的前提。
- 把办公套件当成给 Agent 用的 harness 来定位：同一份文件人和 Agent 都能改，Agent 生成的是真实带公式的工作簿而不是截图或纯文本，这是和纯文档解析库最本质的区别。

**核心功能**

- Canvas 渲染 + 自研公式引擎：整张表格用 canvas 逐帧画，不生成几十万个 DOM 节点，所以几十万单元格滚动不卡；公式引擎单独实现了公式解析、单元格依赖图和增量重算，改一个格子只重算受影响的链路。
- 插件内核 + 命令/服务总线：表格、文档、菜单、协同这些能力全是插件，插件之间靠 command 和 service 通信，可以只装自己需要的部分、懒加载或整体替换；不想挑就用 presets/ 里的预设包一次装齐。
- 同构设计（isomorphic）：浏览器 UI 和 Node.js headless 跑的是同一套代码，服务端不渲染界面也能打开工作簿、算公式、导出文件，再配一套统一的 Facade API（workbook/range/formula/document）前后端通用。
- 跨形态共享 runtime：表格、文档、看板、关系表共用一套存储和计算，网页上的控件和图表可以绑定到具体单元格，单元格一变页面跟着变（Univer Workspace 就是照这个思路做的开源样例）。

**适用场景**: 做 SaaS、内部工具或 BI 的团队，想在自家页面里嵌一个类似 Excel 的编辑区和公式计算，又不想用 OnlyOffice 那种整套成品。 做 AI Agent 的团队：把读写工作簿、算公式、生成报表做成 Agent 的工具或 MCP 服务，让 Agent 产出带公式和图表的文件再交给人工审核（官方已放出 CLI、OpenClaw、DeepSeek Harness 等集成）。

**竞品对比**: 对比 Luckysheet/x-spreadsheet，Univer 是持续维护的插件化内核、覆盖表格外的文档和看板，还支持 Node headless；对比 Handsontable/AG Grid，它不只做表格控件，还有公式引擎和多文档形态；对比 OnlyOffice/Collabora，它是可嵌入 SDK 而不是部署一整套服务；对比 SheetJS，它管编辑和计算，不只是解析文件。

**成熟度**: 中等成熟：核心开源、另有 Pro 收费分层，文档多语言齐全、Discord 社区活跃、release 和 CI 都在跑；但 AI Agent 方向的集成仓库（OpenClaw、WorkBuddy）自己标注为开发预览，接口仍会变动。

**趋势信号**: AI Agent 从写代码转向操作真实办公文件，MCP、agent harness、CLI 这套生态正在起来，官方顺势把定位从「表格 SDK」改成「AI Agent 的 Office Harness」，并一次放出多个 Agent 集成仓库，所以今天单日涨了 1100 多星。

### [browser-use/video-use](https://github.com/browser-use/video-use)

 `Python` ⭐ +746 今日新增 · 26,593 总星数

> browser-use 开源的视频剪辑 skill：素材丢进文件夹，Claude Code 读转写文本定剪辑点，ffmpeg 渲染成片。

**亮点**

- 把 browser-use 那套'给 LLM 结构化 DOM 而不是截图'的思路搬到视频：LLM 不'看'视频，而是'读'视频，画面只在需要时按需取一张。
- 渲染完不直接交付，而是对渲染结果在每个切点再跑一遍 timeline_view 自检，抓跳帧、爆音、字幕被遮，有问题就改再渲染，最多重试 3 次。动画叠加还能按条并行派子 agent，HyperFrames / Remotion / Manim / PIL 各管一个。

**核心功能**

- 用 ElevenLabs Scribe 做词级时间戳转写 + 说话人分离 + 音频事件（笑声/掌声/叹气），全部素材压成一个约 12KB 的 takes_packed.md 给 LLM 读。不喂视频帧——按 README 算，朴素做法 3 万帧 × 1500 token ≈ 4500 万 token 的噪声。
- timeline_view 只在决策点按需生成 PNG 合成图（胶片条 + 波形 + 词标签 + 静音间隙切点候选），专门用来判断模糊停顿、重拍取舍和切点是否合理。
- 决策结果落成 EDL（剪辑决策表，就是一份'从第几秒到第几秒、用哪条素材'的清单），再交给 ffmpeg 渲染：每个切点插 30ms 音频淡入淡出防爆音，字幕按 2 词大写分块烧录，配色走自定义 ffmpeg 链。

**适用场景**: 拍口播、访谈、教程、旅行 vlog 的创作者和小团队，素材一堆但不想在 Premiere 或剪映里手动对时间轴。已经装了 Claude Code / Codex 的开发者也能直接把它当 skill 用。

**竞品对比**: 对标 Descript、Opus Clip、剪映的自动剪辑，但那些要么是 GUI 手动操作，要么是固定模板批量出片。video-use 没有界面，靠对话按当前素材现定策略，而且是开源、跑在本地的 ffmpeg 管线。

**成熟度**: 早期项目，没有版本号，形态是 Claude Code skill，依赖 ElevenLabs API key 和本地 ffmpeg；有 browser-use 团队背书和 2.6 万 star，但生产稳定性还没被大规模验证。

**趋势信号**: Claude Code 的 skills / agent 生态正在爆发，browser-use 团队又把'agent 读结构化文本而非像素'的方法论挪到视频上，正好踩中 coding agent 急着找新落地场景的窗口。

### [agent-substrate/substrate](https://github.com/agent-substrate/substrate)

 `Go` ⭐ +558 今日新增 · 3,565 总星数

> Google 推出的 agent 执行运行时：把大量大部分时间空闲的 agent 当 actor，挂到少量 K8s worker 上，靠全状态快照实现亚秒级挂起恢复，8 个 pod 跑 250 个 agent。

**亮点**

- 思路是反着来的：不给每个 agent 留一个常驻容器，而是假设它们大部分时间闲着，靠挂起/恢复做超卖，把密度拉上去。这是把 serverless 的冷启动套路搬到了 agent 场景。
- 恢复的是完整状态（内存 + 文件系统），不是靠重放日志或从外部存储重建。所以 coding agent 睡一觉醒来，之前跑着的进程和磁盘改动都还在。

**核心功能**

- Actor/Worker 多路复用 + 全状态快照：赌 agent 大部分时间在等模型返回、处于空闲，于是把几千个 actor 挂到少量常驻 worker 上，挂起时把内存和文件系统整份快照存盘，恢复不到 500ms、单机每秒 500+ 次挂起恢复，官方 demo 用 8 个 pod 跑 250 个有状态 actor，超卖 30 倍。
- 底层直接复用 Kubernetes Pod 当 worker，自己补上 agent 专属的调度和控制面：atelet DaemonSet 跑在节点上管沙箱，atenet-router 按 HTTP header（ate-target-actor）把请求路由到具体 actor；沙箱用 microVM 或 gVisor 两种，内核和网络默认零信任隔离。数据面按 ate.dev/substrate-version 节点标签调度，避免新旧版本混跑。
- 框架无关：管的是标准 OCI 容器，所以 ADK、LangChain、Claude Code、Codex、MCP server 都能塞进去，不用改代码适配 SDK。
- 沙箱生命周期统一：microVM 和 gVisor 两种实现走同一套 create/destroy/suspend/resume 接口，换沙箱技术不用换上层逻辑。

**适用场景**: 适合要跑大量有状态 agent 的平台团队。比如给每个用户会话开一个持久 coding agent 沙箱的 IDE/云开发产品，或者把 MCP server 沙箱化常驻给多个模型复用。kagent（CNCF 沙箱项目）和 Google 的 Agent Executor 已经接进来当执行层。

**竞品对比**: 对标 E2B、Daytona、Modal Sandboxes、Cloudflare Sandbox SDK 这类 agent 沙箱。最大区别是它 K8s 原生、跑在你自己集群里，走 actor 多路复用加全状态快照，而不是一个沙箱一个容器；E2B 那类多是托管服务，密度和自托管能力是它的差异点。

**成熟度**: 早期项目，官方 README 明说 not ready for production、API 几乎一定会变，只支持最新和上一个 K8s 小版本，社区还在起步阶段。

**趋势信号**: Google Cloud 刚发布 Agent Executor 分布式 agent 运行时，kagent 等 CNCF 项目同步宣布接入，把「agent 运行时/沙箱」推成当下热点，这是 Google 在这个赛道上放出的基础设施拼图，所以一天涨 500 多星。

**成熟度**: v2 已稳定使用多年，v3 刚合并、输出格式有破坏性变更，依赖旧输出的下游脚本会挂；文档在 Read the Docs 上较完整，有 CI 和活跃 issue 区。

**趋势信号**: v3 分支刚合并进主干，CLI 结构和输出格式大改（issue #757 专门讨论迁移），老用户集中关注；加上间谍软件相关的新闻周期性推高这类工具的热度。

### [superdesigndev/treg](https://github.com/superdesigndev/treg)

 `Python` ⭐ +506 今日新增 · 2,804 总星数

> 把 3000+ 第三方 API 收进一个目录，Agent 用一个 token 按次付费调用，不用挨个注册供应商账号、也不用买月付订阅。

**亮点**

- 自己持有供应商账号并按次转售，把 $99–$139/月的订阅拆成几分钱一次，没账号的调用方直接用；但明确不做静默故障转移，同一能力有多个供应商时列出价格让用户自己选
- 按次计费的反面也做得很硬：没有公布价格的端点直接拒绝服务，而不是免费送出去，避免被当成免费代理刷

**核心功能**

 `TypeScript` ⭐ +87 今日新增 · 6,625 总星数

> BuilderIO 开源的 TypeScript 框架，用一套 action 同时给 Agent 当工具、给 React UI 当接口，省得为两边各写一套逻辑。

**亮点**

- 把'Agent 驱动 UI'反过来了：不是让模型去点按钮，而是让人和模型共用同一层 action，规避了 GUI Agent 点错、页面变了就崩的问题。
- 一个 action 天然生成 MCP/A2A 接口，等于顺手把自家的业务能力接进了 MCP 生态，这在同类前端框架里少见。

**核心功能**

- 能力只定义一次：用 Zod 写 schema 的 defineAction，同一个函数既被 Agent 当 tool 调用，也被 React 的 useActionQuery 调用，校验、权限、实现共用一份代码。
- Action 自动暴露成 HTTP、MCP、A2A、CLI 五种接口，不用为每种协议单独写适配层。
- Agent 不走 UI 点击，而是读取共享应用状态（当前页面、选中记录、活动视图）后直接调 action 层，数据在 UI 和 Agent 之间双向可见。
- 后端用 PostgreSQL，本地开发切成 PGlite（跑在 WASM 里的轻量 Postgres），可部署到任何兼容 Nitro 的托管环境。

**适用场景**: 做 AI 产品的前端和全栈团队，比如要给会议记录、演示文稿、邮件、数据分析这类知识工作场景加一个 Agent 副驾，又不希望 Agent 是个孤立聊天框、结果没法被人查看和修改。

**竞品对比**: 和 Vercel AI SDK、LangChain 比，这两者解决的是模型调用和编排，不管 UI 与后端能力复用；和 CopilotKit 比，CopilotKit 更偏向往已有 React 应用里塞一个 Agent，Agent-Native 要求从 action 层开始重建，耦合更紧但一致性更强。

**成熟度**: 早期项目，由 BuilderIO 团队维护，star 增长快但版本仍在 0.x 阶段，API 可能变动，生产使用需谨慎评估。

**趋势信号**: MCP 成为事实标准后，社区正在寻找'怎么把自家应用能力一次性接给 Agent 又接给前端'的统一写法，加上 BuilderIO 本身有 Builder.io/Qwik 的开发者基础，项目上线即被推到 trending。

### [harry7557558/spirula-studio](https://github.com/harry7557558/spirula-studio)

 `C++` ⭐ +69 今日新增 · 783 总星数

> 单文件跨平台 3DGS 训练器：用 Vulkan 跑通 N/A/I/A 显卡，内置 SfM 与 AI 抠图，8GB 显存能训 1000 万高斯。

**亮点**

- 把 SfM→训练→网格化→渲染整条链路塞进一个二进制，砍掉了 Python 虚拟环境和 COLMAP 两个最容易劝退新手的外挂依赖
- 训练默认起一个 HTTP viewer，云 GPU 上 ssh 做端口转发就能在浏览器实时看训练进度，不用配 Jupyter 或 TensorBoard

**核心功能**

- 训练后端用 Vulkan compute，一套代码跑 NVIDIA、AMD、Intel 和 Apple Silicon（Mac 上经 MoltenVK 转译），CUDA 只留作遗留分支；纯 C++ 打包成单个可执行文件，不依赖 Python/PyTorch
- 量化训练压显存：8GB 显存能塞下 1000 万个带全阶球谐（SH3，描述随视角变化的颜色）的高斯点
- 把 SfM、视频抽帧、AI 掩码都做进程序里——不用单独装 COLMAP；开启专利解码后 GPU 直接解 AVC/HEVC，抽帧比外调 ffmpeg 快约 15 倍；掩码走 SAM 2.1/3 权重按需下载
- 原生吃 360° 等距圆柱和鱼眼素材，不需要先做去畸变；用改造过的双边网格 + PPISP 做曝光/白平衡校正，减少偏色和压暗

**适用场景**: 3D 扫描、数字孪生方向的独立开发者和小团队。用手机或 360 相机拍一段视频，在 Windows/Mac 笔记本或租来的云 GPU 上直接出 splat 和带贴图网格，再导进 SuperSplat、UE 做后续处理。

**竞品对比**: 同类有 Brush（Rust + wgpu，也走跨厂商路线）、Postshot（仅 Windows + CUDA）、以及 nerfstudio/gsplat 这类 Python + PyTorch + COLMAP 组合。最大差异是它用 Vulkan 覆盖了 AMD/Intel/Apple 显卡，并且把 SfM 和视频抽帧一起内置，不是只做训练那一段。

**成熟度**: 有正式 Release 和多平台二进制、多语言界面，但基本是一人主导的快速迭代项目（近几月还在补 macOS、度量尺度、LoMa），建议先拿自己的数据跑通再用于生产。

**趋势信号**: 3DGS 工具链长期被 Python + CUDA 绑死，AMD/Intel/Apple 显卡用户基本被排除在外；这里用 Vulkan 打破了这个限制，又连续几个版本补上 360° 相机、度量尺度这些实际短板，正好撞上本地跑 3DGS 的需求。

### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +57 今日新增 · 50,013 总星数

> 给任意桌面软件自动生成命令行封装，让 AI Agent 用 shell 直接操控 CAD、Calibre、LibreOffice 这类 GUI 工具，输出 JSON，省掉为每个软件写 MCP server 的麻烦。

**亮点**

- 路线选择和 MCP 相反：不给每个软件写常驻 MCP server，而是生成一次性可调用的命令行，复用 shell 这个已经有几十年生态的通用接口，任何 agent 框架都能接
- 社区注册表 + 强制质量门槛：每个合并的 harness 要带单元测试和真实软件 E2E 证据（如 Calibre 41 个单测、Joplin 134 个测试基线），全仓 2461 个测试通过

**核心功能**

- 为每款软件生成一套 CLI harness（命令行外壳），同时输出 JSON 和人类可读文本，Agent 只要会调 shell 就能操作原本只能用鼠标点的软件，已覆盖 CAD、3D 场景、配音字幕、Calibre、LibreOffice、ArcGIS Pro、Obsidian 等 18 个 demo
- 带 preview / live preview / trajectory loop 三件套：Agent 先渲染预览看结果，再根据画面反馈改命令重跑，而不是盲发指令等失败
- 技能统一用 SKILL.md 描述并放在顶层 skills/ 目录，靠 `npx skills add HKUDS/CLI-Anything --skill <name>` 分发；CLI-Hub 做注册表，`pip install cli-anything-hub` + `cli-hub install <name>` 一键装

**适用场景**: 想让 Claude Code、Cursor 这类编码 Agent 自动改图、转文档、导字幕、批量处理 3D 模型的开发者，不用自己写胶水脚本 需要把内部工具（比如 ArcGIS Pro 制图、Rekordbox 曲库管理）接进 Agent 工作流的数据和运维团队，直接装现成 harness 或按模板自己提 PR

**竞品对比**: 对标 MCP（给模型接外部工具的标准协议）和 computer-use 类 GUI 自动化。MCP 每接一个软件要写一个 server、占上下文且要常驻进程；GUI 自动化靠截图点坐标，慢且不稳。CLI-Anything 走命令行，token 省、可脚本化、可测试，代价是只能操作本身有可编程接口的软件。

**成熟度**: 介于早期和生产之间：有 arXiv 技术报告、2461 个测试、Apache 2.0、多个第三方合并的 harness，但 skills 目录结构和 CLI-Hub 注册表格式近一个月还在改，接口可能变。

**趋势信号**: Anthropic 的 Agent Skills（SKILL.md）格式成了事实标准，这个项目随即把全部技能迁到 skills/ 目录并改用 npx skills add 分发，正好卡在 2026 年'Agent 怎么操作真实软件'这个最热的缺口上，加上 HKUDS 实验室自带流量。

## 趋势观察

这批项目指向同一件事：Agent 正在从演示品变成基础设施。大厂先动手。Google 和 AWS 把 Agent 运行时、编排、SDK 开源，K8s 沙箱、YAML 声明、长时任务、亚秒挂起都安排上。Anthropic 把投行和私募工作流做成可装插件。这说明 Agent 不再只是聊天，它要进生产环境。开发者这边，趋势是“别重写，先装技能”。给 Claude Code 配命令、MCP、hooks；把方法论打包成技能，逼 Agent 先写规格再写代码；用一套 action 同时服务 Agent 和 UI。更关键的是，Agent 开始伸手碰真实软件。GUI 自动化、API 聚合、代码知识图谱、Office SDK，都在降低它操作世界的门槛。垂直场景也在冒头：股票盯盘、制造业 ERP/MES、手机取证。风险同步到来。澳大利亚称 OpenAI Agent 入侵政府网站，首次把安全事件定性为 Agent 入侵。提示注入、越权、供应链安全被摆上台面。SBOM、基准审计、开源治理讨论变多。硬件侧，高通 X2 支持 Linux、GPU 虚拟化、单文件 3DGS 训练器，说明本地 AI 和 AI PC 还在往前拱。总结一句：Agent 从“能聊”走向“能干活、要治理”。生态不再比谁模型大，而是比谁把工具链、权限、场景和成本管得更顺。
