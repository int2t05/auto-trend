## 概览

今日共收录 **11** 个 GitHub Trending 项目。
主要语言分布：TypeScript(4)、Unknown(2)、CSS(1)、Python(1)、Rust(1)。

今天的榜单，十来个项目其实在干同一件事：给 AI 编程 Agent 打补丁。没人再造新模型，也没人从零写 Agent。大家都在 Agent 上面盖楼。设计规则包、技能库、配置外壳、开发方法论、统一托管台，全是外围。 原因很直白。模型能力已经拉平，Claude Code、Cursor、Codex、Grok 谁都能写代码。真正的差距跑到别处：页面丑不丑、需求问没问清、几个 Agent 会不会互相抢文件。所以「塑料味」「AI 味」被反复点名。生成能力不缺，缺的是品味和规矩。有人把设计流程写成 markdown，让模型照单执行；有人上 62 条离线规则抓模板味。这是把审美变成可执行的约束。 另一条线是碎片化。一个人手里同时养好几个 CLI Agent，就得有工作台管任务队列、隔离工作区、共享文件。一份配置要跨 7 个宿主复用，记忆和安全规则要打包带走。JetBrains 干脆把 Agent 包进一个带 Monaco 编辑器和 git worktree 的 IDE，大厂也认这个方向。连越狱提示词都被整理成可直接粘贴的合集，说明攻防在同步生长。 合起来看，这段时间的关键词不是「更强」，是「更顺手、更可控、更像人做的」。工具爆发之后进入整合期。谁能先把最后一公里磨平，谁就占住位置。

### [Nutlope/hallmark](https://github.com/Nutlope/hallmark)

 `CSS` ⭐ +2,830 今日新增 · 39,375 总星数

> 给 Claude Code、Cursor 等 AI 编程代理安装的设计技能：通过五十套主题，加上真实浏览器里的自动 lint 检测，让代理生成的页面不再呈现明显的 AI 生成风格。

**亮点**

- hero 区域（首屏主视觉区）先单独生成、渲染，再由无上下文的复审冷看一遍；通过之后才开始写页面其余部分。先用低成本验证最贵的一块，而不是整页做完再返工。
- 把“别做得像 AI”这种模糊要求转成可执行的 lint 规则和分级校验，而不是在提示词里写“请做得精致一点”。其中 755 张图片来自 Wikimedia Commons 的开放授权配图，只存元数据，用图时在页面上署名。

**核心功能**

- sloplint.mjs 调用 puppeteer-core 和真实 Chrome，在 8 种屏幕宽度下渲染页面，并逐条检查那些看起来像 AI 生成的设计特征：每个标题上方的小字、字距拉开的全大写标签、标题里只有一个彩色单词、页脚一律挂邮件订阅、hero 撑不满首屏。没有浏览器时降级为静态检查。
- 主题被当作“材质”处理，不是模板：50 个主题各是一个不超过 8KB 的单文件，只定义纸张质感、字体、配色、表面和组件，不规定页面结构和顺序。所以在同一个主题下，两次不同的 prompt 会得到两个不同的页面。
- 校验分为三层：Floor 会强制拦截（对比度、焦点、reduced motion、编造事实、手机布局崩坏）；Reflex 是可覆盖的默认习惯，代理要破必须先写明理由；Finish 只提示，不阻断发布。最后还有一个没有参与构建上下文的子代理进行独立复审。
- 执行 /hallmark redesign 时，先用 sloplint --before 记录下页面所有链接、表单字段、事件处理器和标题，改完后用 --kept 校验；只要丢失一个，就判定重设计失败，防止代理在重做样式时悄悄删掉埋点和表单逻辑。

**适用场景**: 适合用 Claude Code 或 Cursor 快速出营销页、落地页的独立开发者和两人小团队；也适合要重做已有站点样式、但又不能弄丢表单和埋点的前端——它可以用 redesign 或 audit 子命令单独处理指定路径。

**竞品对比**: 和 v0、Lovable、bolt.new 这类一句话建站工具正相反：它们生成快，但输出外观趋同，Hallmark 把“别撞脸”做成检查清单并硬性拦截。和 axe-core 这类无障碍 lint 也不是一回事，sloplint 检查的是设计风格上的特征，而不是 WCAG 合规。

**成熟度**: 已到 v2、MIT 协议、Together AI 出品，但本质上是技能脚本和规则集，主题与校验规则还在快速增补，当作生产力工具用没问题，别指望规则集稳定。

**趋势信号**: Anthropic 推出 Agent Skills 后，技能包生态在 2025 年底爆发；同时“AI 味设计”已经引发普遍反感，这个项目正好顺应这种情绪，一天涨 2800 星。

### [makecindy/cindy](https://github.com/makecindy/cindy)

 `TypeScript` ⭐ +1,465 今日新增 · 7,656 总星数

> 开源的跨设备 AI Agent 客户端：桌面和手机共用同一会话，直接接入你已有的 Claude Code / Codex 订阅或自己的 API key。

**亮点**

- 不租服务器：你自己的电脑就是后端，官方只做账号和会话同步的中转，省掉再自托管一套 agent 服务的运维
- agent 内核和外壳拆开卖：客户端免费开源、模型侧自带（订阅 / API key / 本地模型），只在官方托管服务上收费

**核心功能**

- pnpm monorepo，Electron 桌面端 + Expo/React Native 移动端共用 packages：auth、device-link、agent 编排、模型 provider 都是共享包，一套逻辑两端跑

- device-link 把本机当服务器：其他设备用同一账号连过来，复用那台机器上已配好的模型 provider（含订阅）和会话文件，但只开放项目目录，不做整盘同步

**竞品对比**: 对标 Happy Coder 这类给 Claude Code 补手机端的开源项目，以及 Claude Code、Codex 官方客户端；差异是它同时挂多个 agent 引擎，还自带手机远程桌面和 Skills/插件分发（SkillHub）。

**成熟度**: 早期项目，客户端 Apache-2.0 但后端闭源、托管服务收费，插件和 API 体系大概率还在变。

**趋势信号**: Claude Code 这类 agent 用量暴涨后，「离开电脑还能用手机接手同一会话」成了刚需，而开源侧正好缺一个既不锁模型也不锁设备的客户端，一天涨 1465 star 是这波需求在找出口。

### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +1,449 今日新增 · 90,908 总星数

> 给 AI 编程助手补一套「设计词汇表」：24 个命令加 62 条离线检测规则，专门抓 AI 生成前端那股模板味，让 Claude Code、Cursor 出的页面别千篇一律。

**亮点**

- 把「设计品味」拆成两层：确定性规则负责能机器判定的（字体、对比度、嵌套层级），LLM 只负责 critique 这种主观判断，硬检查部分零成本可离线
- 它不生成页面，只做审查和改造，所以能挂在任何已有 AI 编码工具上，而不是再造一个建站产品

**核心功能**

- 62 条确定性检测规则编译进一个 Rust 二进制，CLI 和浏览器扩展本地跑，不调 LLM、不要 API key，用来硬性识别 Inter 字体、紫蓝渐变、卡片套卡片、彩色底上放灰字这类 AI 套路
- 把产品事实固化成 PRODUCT.md（受众、场景、语气、约束）和 DESIGN.md（视觉系统），24 个命令共用同一份上下文，不用每次在 prompt 里重述
- 一套 skill 分发到 Claude Code、Cursor、Codex、Copilot、Gemini CLI 等 20 多个 harness，并给 Codex、Grok 写各自的原生 hook 清单（.codex/hooks.json、.grok/hooks/），靠编辑器钩子触发而不是靠人记得敲命令
- live 模式在浏览器里选中元素实时改样式变体，改完直接回写代码

**适用场景**: 用 Claude Code、Cursor 生成前端页面的独立开发者和小团队。典型流程是 AI 先把页面糊出来，再用 /impeccable critique 做 UX review、/impeccable polish 收尾、/impeccable audit 跑无障碍和响应式检查。

**竞品对比**: 直接对标 Anthropic 官方的 frontend-design skill（README 自己承认从这里起步），最大差异是官方版纯靠 prompt 指导，Impeccable 多了 Rust 规则引擎做可离线跑的硬检查；和 v0、Lovable 这类生成式建站工具不是一回事，那些负责出页面，它负责挑毛病。

**成熟度**: 装机量已经很大（9 万 star、VS Code 扩展已上架 Marketplace），但 24 个命令还在快速加，PRODUCT.md/DESIGN.md 这类文件格式和 hook 约定可能还会变，建议先在副项目里试。

**趋势信号**: AI 生成前端同质化成了公开吐槽点（「AI slop」），Anthropic 官方 frontend-design skill 又把这个品类带火，Impeccable 是踩在这波上做的增强版。

### [elayadesign/ai-design-skills](https://github.com/elayadesign/ai-design-skills)

 ⭐ +1,395 今日新增 · 9,870 总星数

> 给 Claude Code、Cursor 等 AI 编程工具用的落地页设计规则包。把设计流程和视觉参数写成 markdown，让模型照单执行，压住 AI 生成页面的那股塑料味。

**亮点**

- 设计变量（字体、颜色、间距、动效）全部集中在文件末尾一节。fork 仓库只改那一段，整个 skill 的行为跟着变——等于把提示词做成了可配置模板。
- 整个项目没有一行代码，全是 markdown 规则文件。门槛低到不需要懂编程，但也意味着效果完全取决于模型是否愿意遵守规则。

**核心功能**

- 把做落地页拆成固定流水线：先问 intake 问题（受众、目标、转化动作），再定页面结构，再写转化文案，最后套视觉系统。用检查清单压缩模型自由发挥的空间。
- 视觉系统给的是具体数值 token——字号阶梯、间距、圆角、动效时长，不是"现代简洁"这种形容词。模型照着填，不用自己编。
- 一个 skill 就是一个文件夹一份 SKILL.md。同一份文件分别丢进 .claude/skills、.cursor/rules、AGENTS.md、.windsurfrules、.clinerules，靠各家工具都读 markdown 规则这件事做跨工具复用，不写适配代码。

**适用场景**: 独立开发者、设计师、没有前端背景的产品同学，用 Claude Code 或 Cursor 从零拉一个营销落地页；小团队也能把自家设计规范固化成一个规则文件，全组共用。

**竞品对比**: 同类有它自己致谢的 Leonxlnx/taste-skill（本项目借了内容真实感和动效思路），以及 anthropics/skills 官方示例库和各类 awesome-claude-skills 清单。差异点是只做一个垂直品类、做深，且把设计参数抽成可改的单独一节；缺点是目前真的只有一个 skill。

**成熟度**: 早期项目，只有一个可用 skill，README 里写"more on the way"，没有版本号也没有测试。star 增速远超内容体量，先当模板参考、别当依赖。

**趋势信号**: Claude Code 带火的 Agent Skills（SKILL.md）格式在 2025 年底被 Cursor、Codex、Windsurf 陆续兼容，加上一堆非前端背景的人开始用 AI 直接生成落地页、又普遍嫌弃生成结果千篇一律，这类"喂品味"的规则包正好卡在这个空档上。

### [JetBrains/thinkrail](https://github.com/JetBrains/thinkrail)

 `TypeScript` ⭐ +1,204 今日新增 · 4,266 总星数

> JetBrains 孵化器出的 Agent 版 IDE：把 pi 编码代理包进一个自带 Monaco 编辑器、git worktree 隔离工作区和 SPEC 文档图谱的桌面/浏览器应用，让多个 AI 任务并行跑而不弄脏你的工作区。

**亮点**

- 隔离用 git worktree 而不是容器/沙箱：不隔离网络和文件系统，只隔离代码目录和分支，所以代理能直接用你本机的 gh、终端和环境变量，代价是安全性靠分支纪律而非沙箱
- 评审意见变成结构化上下文：在文件和 diff 上打锚点评论，直接作为一条消息发给聊天，代理按评论改；代理提 UI 改动时在聊天里渲染可评论的前后对比图

**核心功能**

- 每个工作区就是一个 git worktree（Git 的并行工作目录，同一仓库多份独立检出），自带分支和目录；PR 合并/关闭或闲置一周后工作区自动沉到项目侧栏的 Settled 货架，回来再激活
- 把项目意图写成一组互相连接的 SPEC.md 文件放在代码旁边，代理通过专门的 spec_* 工具读取、搜索、维护这张图，让上下文不随会话结束而丢失
- 不自己写代理循环，直接复用第三方 pi 代理：沿用你已有的 ~/.pi/agent 配置、pi 的登录方式、mcp.json 里的 MCP 服务器和 Agent Skills，只在外层做界面和工作区管理

**适用场景**: 适合已经用 pi、Claude Code 这类命令行代理写代码，但受不了在终端里看 diff、切分支、开 PR 的开发者。典型场景是同时丢几个任务给代理并行跑，各自在独立 worktree 里改，好的合、废的删。

**竞品对比**: 对手是 Cursor、Windsurf、Zed、Kiro、Claude Code 这些。最大差异是不绑定自家模型和账号——用 JetBrains AI 登录或接 pi 支持的任何 provider，且复用你已有的 pi 配置；另外并行任务靠 git worktree 实现，而不是靠多窗口或云端沙箱。

**成熟度**: 早期项目，JetBrains 孵化器出品，扩展系统还没做完（README 写的是「接下来加」），API 和界面都可能变，尝鲜可以、上生产要等。

**趋势信号**: JetBrains 亲自下场做「vibe coding」IDE，且是开源孵化项目，1204 颗日增星基本来自发布当天的品牌效应和社区对「大厂版 Cursor」的好奇。

### [affaan-m/ECC](https://github.com/affaan-m/ECC)

 `JavaScript` ⭐ +1,165 今日新增 · 291,076 总星数

> 给 Claude Code、Cursor 等 AI 编程 agent 加一层“外壳”：把技能、记忆、安全规则打包成插件，一份配置跨 7 个 agent 宿主复用，减少重复交代项目约定。

**亮点**

- 赌的是“模型能力趋同后，差距在 harness（agent 的外壳：提示编排、记忆、权限）而不是模型本身”，所以只做外壳不做模型
- 开源 MIT 永久免费 + 托管 GitHub App（Pro 19 美元/席/月跑私有仓库）双轨，靠订阅养一个维护者每周给 7 个宿主发版

**核心功能**

- 以插件形式（slug `ecc@ecc`）安装，同一套技能/记忆配置再适配 Codex、Opencode、Cursor 等共 7 个 agent 宿主，靠 npm 包 ecc-universal 统一分发，不用每个工具各配一遍
- “instincts” 层把反复出现的任务偏好（比如“改完先跑 lint”“别动 migrations 目录”）固化成规则，agent 下次遇到同类任务直接套，不用每次重读整份上下文
- 安全单独拆成 ecc-agentshield 包，对 agent 要执行的 shell 命令和文件操作做拦截审查，属于在 agent 跑偏之前就拦下来的护栏，不是事后扫描

 `TypeScript` ⭐ +777 今日新增 · 2,644 总星数

> 一个本地桌面应用，把 Codex、Claude Code、Grok、Cursor 等多个 AI 编程 Agent 装进各自的独立工作区和会话里，统一管理任务队列、文件共享和内嵌浏览器。现在火是因为各家 CLI Agent 集中发布，用户手里同时养好几个 Agent，缺一个统一托管的工作台。

**竞品对比**: 和 Anthropic 官方 skills、spec-kit、BMAD-METHOD 这类方案比，最大差别是不绑定单一 harness，同一个仓库适配十几家 CLI，且覆盖从需求访谈到 subagent 执行的全流程。

**成熟度**: 活跃维护、适配面很广，但本质是提示词和方法论集合，效果依赖模型对指令的遵循度，方法论本身谈不上版本稳定性。

**趋势信号**: 各家 CLI 的插件市场最近密集上线（Anthropic、OpenAI、xAI、Gemini 都有），一个仓库正好通吃所有市场，赶上 agent harness 生态爆发这波。

## 趋势观察

今天的榜单，十来个项目其实在干同一件事：给 AI 编程 Agent 打补丁。没人再造新模型，也没人从零写 Agent。大家都在 Agent 上面盖楼。设计规则包、技能库、配置外壳、开发方法论、统一托管台，全是外围。 原因很直白。模型能力已经拉平，Claude Code、Cursor、Codex、Grok 谁都能写代码。真正的差距跑到别处：页面丑不丑、需求问没问清、几个 Agent 会不会互相抢文件。所以「塑料味」「AI 味」被反复点名。生成能力不缺，缺的是品味和规矩。有人把设计流程写成 markdown，让模型照单执行；有人上 62 条离线规则抓模板味。这是把审美变成可执行的约束。 另一条线是碎片化。一个人手里同时养好几个 CLI Agent，就得有工作台管任务队列、隔离工作区、共享文件。一份配置要跨 7 个宿主复用，记忆和安全规则要打包带走。JetBrains 干脆把 Agent 包进一个带 Monaco 编辑器和 git worktree 的 IDE，大厂也认这个方向。连越狱提示词都被整理成可直接粘贴的合集，说明攻防在同步生长。 合起来看，这段时间的关键词不是「更强」，是「更顺手、更可控、更像人做的」。工具爆发之后进入整合期。谁能先把最后一公里磨平，谁就占住位置。
