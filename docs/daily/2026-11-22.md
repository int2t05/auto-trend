# GitHub Trending 日报 · 2026-11-22

## 概览

今日共收录 **16** 个 GitHub Trending 项目。
主要语言分布：Python(7)、TypeScript(4)、Shell(2)、HTML(1)、C++(1)。

今天这份榜单，一眼看过去全是“技能包”。漏洞挖掘打包成技能，开发流程打包成技能，画图表打包成技能，连 Google Stitch 的 UI 生成也打包成技能。共同点很直白：大家不再比谁的模型强，而是比谁能把一套做法塞进 Agent 手里，让它照着干。 第二层变化是，技能包覆盖的范围在扩大。以前只能包提示词，现在开始包 GUI 软件：给 CAD、LibreOffice、Obsidian 套一层命令行外壳，Agent 用纯文本就能操作，不用截图点鼠标。也开始包数据：Firecrawl 一个 API 喂干净的 Markdown，还出了 Rust 单二进制和免注册调用。Agent 的手和眼，正在被一块块补上。 第三层是平台抢位。Cursor 官方开源插件规范，“一个目录加一个 plugin.json”就能装；Google 把 Stitch 做成技能给 Claude Code、Cursor 调用。谁定下技能和插件的格式，谁就握住下一波入口。这不是技术问题，是生态站位问题。榜单里还有两个信号不该忽略。一是端侧和本地：Intel 的推理工具包把模型压到 CPU、GPU、NPU 上跑，MiniMind 用一张 3090、两小时、三块钱训出 64M 小模型，把全流程用原生 PyTorch 摊开给人看。二是“AI 写代码越多，烂摊子越多”开始有人收拾：OpenSRE 读 CI 日志、定位根因、直接提修复 PR，应用商店拒审原因也被做成提交前扫一遍的脚本。 连起来看，2024 年大家在卷模型，现在在卷“怎么用”。方法论、软件、数据、格式，全在被封装成 Agent 能直接吃下的零件。同时，本地小模型和自动修 bug 这两条线在提醒一件事：能力铺开之后，成本和可靠性才是真门槛。热闹归热闹，最后能留下的，是那些把零件拼成闭环的项目。

**适用场景**: 适合独立赏金猎人或小团队红队，在 HackerOne 等平台接了授权项目后，用 Claude Code 跑子域侦察、给攻击面排优先级、验证漏洞并写报告。

**竞品对比**: 和 PentestGPT 这类自动跑流程的 agent 不同，它不自己执行攻击链，只给 Claude 提供领域知识和判断标准；和 Nuclei 比，它不是模板扫描器，而是扫描前后的分析与研判层。

**成熟度**: 早期个人项目，没看到正式版本号，全靠 star 增长带动，技能质量参差，需要自己逐条核实后使用。

**趋势信号**: Claude Code 的 skills/插件生态刚开放，Agent Skills 格式又被多个 agent 工具同时支持，这类垂直领域技能包正好赶上标准化窗口期。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +1,006 今日新增 · 206,403 总星数

> Firecrawl 把网页抓取、爬站、搜索和 550+ 数据源打包成一个 API，给 AI Agent 提供干净的 Markdown 知识。新版推出 Rust 单二进制本地版和免注册 keyless 调用，门槛大幅降低。

**亮点**

- 本地抓取和云端抓取共用同一套 v2 API，只在能力上分层：单页抓不到时默认走云端兜底，并在结果里标 `"source": "firecrawl-cloud"`，也可以设 FIRECRAWL_CLOUD=off 全部留在本机
- 把“抓取”做成 MCP server 而不是让用户自己写工具函数，一条命令接进六种 AI 客户端，同时用 keyless 提供每月 1000 次免费额度，不用注册就能跑通

**核心功能**

- 本地版 Firecrawl Local 用 cargo 装成一个 Rust 二进制，不需要数据库、队列或容器，直接调用机器上已有的 Chrome/Chromium 渲染 JS 页面，PDF 和 Office 文档也在本地解析，无浏览器时静态页仍能抓，JS 页返回警告
- 本地 `serve` 命令在 3002 端口起一个兼容 Firecrawl v2 的 HTTP 服务，官方 Python/Node SDK 改个 api_url 就能指过来，本地路由不需要 API key
- `init` 命令自动探测 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 六种客户端，改配置前先备份，把本地注册成 MCP server（MCP 是让 AI 工具统一接入外部能力的协议），抓取类工具跑在本机，搜索和 Agent 类工具回落到云端
- 云端维护 550+ 数据源的知识库 Alexandria 和搜索引擎，抓取结果直接给 Markdown/结构化 JSON/截图，省 Agent 的 token；宣称覆盖 96% 网页、P95 延迟 3.4 秒

**适用场景**: 写 RAG 或 Agent 的后端和 AI 应用开发者，需要把文档站、竞品页面、PDF 喂给模型时用；以及用 Claude Code、Cursor 做开发、想让编辑器直接读网页内容的工程师。

**竞品对比**: 对比 Jina Reader、Crawl4AI、Apify、Exa：Jina 和 Crawl4AI 基本只做单页转 Markdown，Apify 偏爬虫市场，Exa 偏语义搜索；Firecrawl 的差异是把抓取、爬站、搜索和自建数据源合成一个 API，且本地跑和云上用同一份 SDK。

**成熟度**: 云服务已商业化多年、多语言 SDK 齐全可上生产；但这次主打的本 Rust 本地版是新东西，API 和行为还可能变。

**趋势信号**: MCP 生态今年成为 Agent 标配，叠加本次 Keyless 免注册上线和 Rust 单二进制本地版发布，让“给 Agent 接网页”从要配 key 变成两条命令的事。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +883 今日新增 · 323,873 总星数

> 把“问清需求→写规格→拆计划→子代理分工实现”这套开发流程做成可自动触发的技能包，让十几种编码代理按同一套方法干活。

**亮点**

- 卖的是“方法论”不是代码：核心产物是一堆约束 agent 行为的技能文本，靠插件市场分发，所以能同时铺到 17 种 harness，几乎零适配成本。
- 主 agent 只做计划与审阅，实际编码交给 subagent——等于给 LLM 流水线硬塞了一道 code review 环节，这是它敢让人放手跑几小时的关键。

**核心功能**

- 技能本身是文本/Shell 仓库，同一份内容通过各 harness 自己的插件机制分发——Claude Code 插件市场、Codex `/plugins`、`gemini extensions install`、`droid plugin marketplace`、`qwen extensions` 等，换代理只换一条安装命令。

- 强制流程约束：先逼出规格再写码，规格按人能读完的小段展示，然后产出实现计划，再由主 agent 派生 subagent 逐个任务执行并回审，全程要求真红/绿 TDD、YAGNI、DRY。

**适用场景**: 用 Claude Code、Cursor、Codex 的独立开发者和小团队，在需求模糊、又想让代理连续跑几小时不跑偏时用；也适合想把团队内部的 agent 产出规矩固化下来的工程组。

**竞品对比**: 对手是 GitHub 的 spec-kit、BMAD-METHOD，以及手写 CLAUDE.md / Cursor Rules 这类土办法。差别在两点：跨 harness 通用，且技能自动触发不靠人记得喊。但本质仍是提示词工程打包。

**成熟度**: 可日常用：17 种 harness 都有安装路径，作者还挂了商业支持入口；但核心是提示词和技能文本，行为会随各家代理版本漂移，没有稳定 API 可言。

**趋势信号**: Claude Code、Codex、Cursor 铺开之后，瓶颈从“模型会不会写代码”变成“会不会按流程走”，加上 Anthropic、OpenAI、xAI 最近陆续开放官方插件市场，这类技能包正好赶上分发渠道开闸；作者 Jesse Vincent（RT 和 Keyboardio 的作者）本身也带传播量。

 `Python` ⭐ +779 今日新增 · 14,624 总星数

> 一个 Qt 写的跨平台下载器，把 HTTP/BT/M3U8/YouTube/B站 等下载塞进一个 App，靠浏览器扩展嗅探链接并伪装浏览器 TLS 指纹绕过反爬。

**竞品对比**: 对比 Motrix、Gopeed、XDown 这类 aria2/多协议 GUI：Motrix 本质是 aria2 的壳，站点解析和浏览器嗅探弱；Gopeed 同为跨平台多协议但没做 TLS 指纹伪装和登录态传递。对比 IDM：IDM 只有 Windows 且收费，不支持 BT/M3U8 直播录制。

**成熟度**: 可日常使用：已有四平台签名安装包、Crowdin 翻译和 CLI 工具，但插件（Feature Packs）API 尚未公开，属于还在演进阶段。

**趋势信号**: 近期版本把 Android 端和插件系统补齐，加上国内用户对 B 站/YouTube 高画质下载和绕过反爬的刚需，被社区集中转发冲上 Trending。

### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +769 今日新增 · 62,238 总星数

> 给各种软件套一层命令行外壳，让 AI Agent 用纯文本就能操作 CAD、LibreOffice、Obsidian 这些 GUI 软件，不用截图点鼠标。

**亮点**

- 刻意不选 MCP，也不选截图方案；它把命令行当作 Agent 的接口：纯文本、行为确定、token 成本低、能管道组合，还能被 diff 和单元测试。2461 个测试就是这一取舍的代价与回报。
- 把“为软件写 harness”外包给社区：谁想要哪个软件被支持，就提交 issue 或 PR，CLI-Hub 充当应用商店，用 `pip install cli-anything-hub` 后一条命令安装。

**核心功能**

- 每个软件配一份手写的 CLI harness，用 Click 写子命令，直接调用软件自身的接口：LibreOffice 走 headless 转换、Obsidian 走 Local REST API、ArcGIS Pro 走 ArcPy、Rekordbox 走 SQLCipher 加密库。默认输出 JSON 供 Agent 解析，同时保留人类可读模式。
- 每个 CLI 都附带一份 SKILL.md（写给 LLM 看的使用说明），用 `npx skills add HKUDS/CLI-Anything --skill &lt;名字&gt;` 一条命令就能装进 Cursor、Claude Code 等客户端，工具和用法一起发布。
- 写操作有保护措施：Rekordbox 必须先备份才允许写库，XML/SVG/ODF/MLT 等格式解析统一走 defusedxml 防 XXE 注入，Sketch 的 token 文件做过路径穿越和软链接逃逸加固；仓库自称有 2461 个单元测试和端到端测试。

**适用场景**: 想让 Claude Code、Cursor 里的 Agent 批量改图纸、转文档、跑 n8n 工作流、整理 Obsidian 笔记库的开发者；以及不想为每个内部工具单独写一个 MCP server 的团队。

**竞品对比**: 对标 MCP（Model Context Protocol，给 Agent 接外部工具的标准协议）和各家的 computer-use（截图加模拟点击）。差别是：MCP 要服务方自己实现 server，覆盖不到桌面软件；computer-use 不用改造软件，但慢、贵、易出错；CLI-Anything 夹在中间，包一层现成命令行。

**成熟度**: 可以用，但质量参差不齐：Apache 2.0、有 arXiv 技术报告、社区 PR 几乎每天合并，不过 60 多个 harness 由不同人各写各的，覆盖面和稳定性不均。

**趋势信号**: Agent 正从聊天转向实际执行任务，MCP 覆盖不到桌面软件，恰好出现一个成本低的接入方式；项目冲到 trending 第一后又吸引更多人提 harness，形成正反馈。

**竞品对比**: 对标 Anthropic 的 Claude Skills 和 MCP 服务器目录。MCP 只解决「工具怎么接进来」，这里除了接工具还打包 prompt、技能和工作流，并且是 Cursor 官方维护加厂商自己写，质量下限更高，但绑死 Cursor 生态。

**成熟度**: 早期项目，规范和插件目录结构还在快速变动，部分插件明确标注 Beta，不适合当稳定依赖。

**趋势信号**: Cursor 推出插件市场，正好撞上 Claude Skills 带起的「agent 技能包」热潮，加上一天涨 260 星说明开发者在对标观望这个生态会不会成为下一个 MCP。

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +200 今日新增 · 11,978 总星数

> Intel 出品的推理部署工具包：把 PyTorch/TF/ONNX 等模型转成统一的 IR，再在 CPU、Intel GPU、NPU 上跑量化后的推理，主打端侧和本地跑大模型。

**亮点**

- 把 NPU 当成核心设备来支持。Intel Core Ultra 内置的 NPU 功耗低、可以常驻运行，OpenVINO 用同一套 API 同时覆盖 CPU、iGPU、dGPU、NPU，还支持把模型的不同层拆到不同设备上做异构执行。
- 同时兼容“传统 CV 模型”和“LLM/扩散模型”两条线：前者走 convert_model + compile_model，后者走独立的 openvino.genai 仓库和 GenAI API，不用为了跑大模型换一套框架。

**核心功能**

- 前端把 PyTorch、TensorFlow、ONNX、PaddlePaddle、JAX 的模型统一转成 OpenVINO IR（一种中间表示的计算图），之后部署不再需要原来的训练框架。同一个 IR 换设备只需改 compile_model 里的 device 字符串。
- 运行时按设备拆成插件：CPU 走 oneDNN 内核，Intel 核显和独显走 OpenCL 内核，Core Ultra 的 NPU 走单独 plugin。编译期做算子融合、常量折叠和布局转换，不是简单地逐层翻译。
- 配套 NNCF 做训练后量化，支持 INT8/INT4 权重量化，以及 AWQ、GPTQ 这类数据感知量化；模型体积和显存占用能降到原来的 1/4 左右，再用校准集补精度。
- GenAI API 里内置 continuous batching（请求动态拼批）和 KV cache 复用，用几行 Python 就能起一个本地 LLM 服务，不依赖 GPU。

**适用场景**: 适合在 Intel 笔记本、工控机、边缘盒子上做部署的工程师，例如 AI PC 应用开发者、工厂质检的视觉检测团队、零售门店的本地推理场景；他们手上通常是 PyTorch 模型加一台没有 NVIDIA 显卡的机器，需要把模型压小、跑快。

**竞品对比**: 和 ONNX Runtime 比，OpenVINO 只针对 Intel 硬件做深度调优，NPU 支持和 Intel GPU 内核更完整；和 NVIDIA TensorRT 生态不冲突，因为它是 Intel 平台的对应物；llama.cpp 更通用、跨平台更广，但在 Intel 平台上的吞吐和量化工具链不如 OpenVINO 完整。

**成熟度**: 生产可用。Intel 官方长期维护，2018 年至今持续按季度发版，文档、Notebook 示例、多语言 API（C++/Python/C/NodeJS）齐全，工业界已有大量部署案例。

**趋势信号**: AI PC 和 Intel Core Ultra 的 NPU 铺开，加上本地跑量化 LLM 的需求上涨，OpenVINO 成了“在没有独立显卡的 Intel 机器上跑模型”的默认选择；今天涨星大概率和新版本发布或 GenAI 管线更新有关。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +189 今日新增 · 32,777 总星数

> NGINX 官方开源主仓，C 写的 Web 服务器/反向代理/负载均衡器，靠事件驱动扛高并发。现在火是因为 F5 把开发主仓从 Mercurial 搬到了 GitHub，issue 和 PR 终于能在 GitHub 上直接提。

**亮点**

- 配置是纯文本指令，reload 时 master 读新配置再拉起新 worker、老 worker 处理完存量连接才退出，改配置不掉连接
- 把需要全局一致的状态（比如 limit_req 的客户端访问次数）塞进共享内存，让多进程不用加锁外部依赖也能统一限流

**核心功能**

- master/worker 多进程模型：master 只读配置、管 worker，worker 数量可按 CPU 核数自动设，每个 worker 用 epoll/kqueue 事件循环异步处理连接，一个进程扛上万连接，不用一连接一线程
- 模块分静态和动态两种：静态模块编译时烧进二进制，动态模块打成 .so 运行时按需加载，用 nginx -V 能看到当前二进制带了哪些静态模块
- 多个 worker 靠共享内存 zone 同步状态，限流计数、连接数、缓存索引都放这里，所以跨进程统计不用接 Redis 之类的外部存储

**适用场景**: 运维/SRE 拿它做 TLS 终止、反向代理、静态资源和灰度流量分发；Kubernetes 里常见的 ingress-nginx 也是基于它。中小团队一台机器顶住几万并发连接的场景最典型。

**竞品对比**: 和 Apache httpd 比，后者默认一连接一线程/进程，内存吃得多、C10K 场景吃亏；和 Caddy 比，Caddy 自动签 HTTPS 更省事但模块生态和调优深度不如 NGINX；和 HAProxy 比，HAProxy 只做代理不做静态文件和缓存；和 Envoy 比，Envoy 是 L7 服务网格方向、配置模型复杂、资源占用更高。

**成熟度**: 生产就绪程度极高，20 多年历史，主线版本 1.27.x，BSD-2 许可，全球大量企业在跑，文档和模块参考齐全。

**趋势信号**: F5 把 NGINX 的开发主仓和协作流程迁到 GitHub 官方组织，加上前段时间 NGINX 项目治理和人员的变动引发社区关注，开发者开始涌进来 star 和围观。

## 趋势观察

今天这份榜单，一眼看过去全是“技能包”。漏洞挖掘打包成技能，开发流程打包成技能，画图表打包成技能，连 Google Stitch 的 UI 生成也打包成技能。共同点很直白：大家不再比谁的模型强，而是比谁能把一套做法塞进 Agent 手里，让它照着干。 第二层变化是，技能包覆盖的范围在扩大。以前只能包提示词，现在开始包 GUI 软件：给 CAD、LibreOffice、Obsidian 套一层命令行外壳，Agent 用纯文本就能操作，不用截图点鼠标。也开始包数据：Firecrawl 一个 API 喂干净的 Markdown，还出了 Rust 单二进制和免注册调用。Agent 的手和眼，正在被一块块补上。 第三层是平台抢位。Cursor 官方开源插件规范，“一个目录加一个 plugin.json”就能装；Google 把 Stitch 做成技能给 Claude Code、Cursor 调用。谁定下技能和插件的格式，谁就握住下一波入口。这不是技术问题，是生态站位问题。榜单里还有两个信号不该忽略。一是端侧和本地：Intel 的推理工具包把模型压到 CPU、GPU、NPU 上跑，MiniMind 用一张 3090、两小时、三块钱训出 64M 小模型，把全流程用原生 PyTorch 摊开给人看。二是“AI 写代码越多，烂摊子越多”开始有人收拾：OpenSRE 读 CI 日志、定位根因、直接提修复 PR，应用商店拒审原因也被做成提交前扫一遍的脚本。 连起来看，2024 年大家在卷模型，现在在卷“怎么用”。方法论、软件、数据、格式，全在被封装成 Agent 能直接吃下的零件。同时，本地小模型和自动修 bug 这两条线在提醒一件事：能力铺开之后，成本和可靠性才是真门槛。热闹归热闹，最后能留下的，是那些把零件拼成闭环的项目。
