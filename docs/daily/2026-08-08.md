### [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

 `TypeScript` ⭐ +2,293 今日新增 · 6,671 总星数

> Prime Agent 是一个开源的编码和科研代理，基于递归语言模型（RLM）和持续记忆机制，能自我改进并长期自主运行。现在它因独特的自改进设计和 MIT 许可突然走红。

**亮点**

- 递归语言模型（RLM）把上下文当成变量，子代理像函数调用一样嵌入到持久化 REPL 中，这是目前主流 Agent 设计里少有的抽象
- 持续记忆（Continual Harness）允许代理把经验写成可导入的 Python 技能包，让工作模式跨会话复用，而不是每次从零开始

**核心功能**

- 持久化 IPython 作为内置工具，文件操作、shell 命令、子代理调用全通过代码完成，模型直接写 Python 来干活
- rlm(...) 函数可以派生出真实子代理并行或后台执行，结果以编程方式返回，支持代理之间互相通信和编排
- /refine 命令能基于当前轨迹做小步、有证据的自我改进，更新提示、记忆或技能描述，且不改动基础系统提示并支持回滚

**适用场景**: 软件工程师或 AI 研究员需要长时间无人值守的编码、重构或科研评估任务时使用，例如跑大规模测试、整理代码库或在后台执行多步骤自动化流程。

**竞品对比**: 和 Claude Code、OpenAI Codex 等编码代理比，最大差异是 RLM 编程模型和 /refine 自改进机制，而且完全开源（MIT），允许自托管和数据私有。

**成熟度**: 早期项目但工程较完整，有官方安装脚本、自动构建和文档；今日刚暴涨，API 可能还会调整。

**趋势信号**: Prime Intellect 是知名去中心化 AI 实验室，刚开源这个带自我改进能力的 agent，关联 PRIME-RL 强化学习项目和 verifiers，正好踩中编程 Agent 从助手向自主工人演进的行业热点。

### [cloudflare/computer](https://github.com/cloudflare/computer)

 `TypeScript` ⭐ +872 今日新增 · 5,793 总星数

> Cloudflare 出的虚拟文件系统，跑在 Durable Object 里，用 SQLite 当权威存储，给 AI agent 一个能读写文件和执行命令的工作区。预览版，API 不稳定。

**亮点**

- 文件系统本身就是一个 Durable Object，权威状态直接嵌入 Workers 运行时，天然分布式，不需要额外同步服务。
- FUSE 把 SQLite 状态投影成挂载点，agent 可以用标准 shell 工具操作文件，同时隔离容器保证安全。

**核心功能**

- 用 Durable Object 里的 SQLite 存文件系统状态，多个执行后端共享同一个权威工作区，没有第二个存储。
- 提供三种执行后端：容器（FUSE 挂载成真实文件系统，能跑任意 Linux 程序）、隔离 shell（just-bash）、隔离 JS（ECMAScript 模块），统一走 runtime.exec 一个入口。
- 容器后端用 capnweb RPC 和 FUSE 同步文件变更，元数据密集操作比真实磁盘快。

**适用场景**: 开发 AI agent 的开发者，需要在 Cloudflare Workers 上给 agent 提供文件读写、跑命令、执行代码的环境，比如让 agent 写文件、运行 pandoc 生成 PDF。

**竞品对比**: 跟 E2B 这类 sandbox 服务比，它把文件系统做成 Durable Object 的一部分，和执行后端解耦，后端可插拔，且原生集成 Cloudflare Workers。

**成熟度**: 预览项目，官方明确说不适合生产，API 不稳定，只能用来做实验和原型。

**趋势信号**: AI agent 正热，Cloudflare 亲自下场做 agent 的‘计算机’，给 Workers 生态补上执行环境这块关键拼图，所以一天涨了近千星。

**成熟度**: 项目本身是清单资源，无版本号，但结构稳定、有贡献指南和行为准则，维护活跃，可作为长期引用资料。

**趋势信号**: 近期欧洲多国对金融机构的KYC/AML监管趋严，且网上流传的“免费调查工具清单”需求激增，该repo因分类直达业务痛点而单日涨星超100。

### [unclebob/swarm-forge](https://github.com/unclebob/swarm-forge)

 `Clojure` ⭐ +81 今日新增 · 1,843 总星数

> 基于tmux的AI agent编排工具，用git worktree隔离多个agent，通过配置文件定义角色和流程，让多个AI代理协作完成编程任务。

**亮点**

- 用git分支管理整个工作流配置，分支即流程（two-pack/four-pack/six-pack），拉取分支就能用，无需额外安装
- 所有状态和脚本都本地化，通过caffeinate/systemd-inhibit防止主机休眠，确保长时间任务不中断

**核心功能**

- 用tmux会话+git worktree让每个agent在独立工作区并行工作，并通过共享脚本目录进行消息传递，避免互相干扰
- 通过swarmforge.conf定义拓扑，角色prompt和分层constitution.prompt控制行为，支持按角色指定claude/codex/copilot/grok等后端
- 用git分支承载不同复杂度工作流（two-pack/four-pack/six-pack），main只放共享脚本，运行时自动下载合并

**适用场景**: 开发者需要多个AI代理（如编码、审查、测试）协作完成项目，特别是想在自己机器上本地运行，不想依赖云端编排平台的场景。

**竞品对比**: 相比OpenAI Swarm等云端agent编排框架，SwarmForge完全本地运行，基于tmux和shell脚本，轻量且透明，更适合已有本地agent工具链的开发者。

**成熟度**: 早期项目，主分支仅作文档，可运行流程在独立分支上，版本未标注，API和配置可能变动。

**趋势信号**: 原因不明，可能是Uncle Bob（Robert C. Martin）的名人效应，或近期AI agent协作概念热度上升。

### [chenyme/grok2api](https://github.com/chenyme/grok2api)

 `Go` ⭐ +55 今日新增 · 7,146 总星数

> 多账户API网关，聚合Grok Build/Web/Console账户，暴露OpenAI和Anthropic兼容接口，解决官方API贵和风控问题。

**亮点**

- 按供应商域隔离出口流量（Build/Web/Console各自独立代理池），避免一个账户风控牵连全部
- 引入FlareSolverr处理浏览器验证，是同类网关中少见的反爬工程方案

**核心功能**

- 独立管理Grok Build、Web、Console三类账户池，自动同步配额和模型列表，支持批量导入导出
- 同时提供OpenAI Chat Completions和Anthropic Messages格式，兼容Codex、Claude Code等现有客户端
- 内置HTTP/SOCKS代理池和FlareSolverr（浏览器解锁工具），应对IP风控和验证码

**适用场景**: 开发者想用Grok模型但官方API昂贵或受限，通过该网关用自有多账户聚合，并接入现有OpenAI/Anthropic工具。

**竞品对比**: 相比one-api/new-api等通用LLM网关，它专攻Grok非官方协议，深度适配其OAuth/SSO和会话特性，但通用性较弱。

**成熟度**: 项目活跃但未发布正式版本，API可能变动，生产使用需谨慎。

**趋势信号**: Grok模型近期热度高且官方API限制多，社区通过这类非官方网关低成本接入，GitHub趋势榜因此上升。
