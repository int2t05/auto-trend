# GitHub Trending 日报 · 2026-11-03

## 概览

今日共收录 **15** 个 GitHub Trending 项目。
主要语言分布：Python(6)、TypeScript(3)、Rust(2)、Shell(2)、C(1)。

今天的榜单基本被同一件事占满：怎么把 AI agent 当团队来管。 一大半项目在给 agent 补基础设施。跨会话持久记忆、提示词技能包、把资深工程师的套路拆成小指令、用系统无障碍树让 agent 点桌面应用、MCP 直接抓网页、Rust 写的 worktree 工具方便同时开几个 agent。还有直接把 Claude Code 配成 49 人工作室，做成有预算和审批的"AI 员工后台"。这些解决的是同一个毛病：单开一个会话很惊艳，一开十几个就乱套。没有记忆，没有分工，没人拦着写烂代码。 另一个明确方向是本地推理往下压。FreeToken 把显卡、CPU、内存拼成一个池子，一张 24G 卡跑 290B 的 MoE。纯 C 引擎更狠，只把当前用到的专家留在内存，其余从磁盘按需读，8GB 内存也能跑几百 B。背景很直接：新开的开源大模型几乎全是 MoE，权重体积远超个人显存。 还有几个偏"可组合"的。Karpathy 用一个旋钮自动配好超参，100 美元练出 GPT-2 水平。不用训练，靠提示词加打分器搜参数，几十分钟去掉模型拒答。Kronos 把 K 线当语言预训练。思路一致：把门槛砍到普通人够得着。 合起来看，注意力正从"训模型"挪到"用模型干活"。agent 要记忆、要权限、要编排、要组织结构。接口要结构化，不能再靠截图猜坐标。模型这边拼的是能不能塞进你的机器。开发者生态正在从玩单次对话，转向搭一套能长期跑的系统。

### [pingdotgg/t3code](https://github.com/pingdotgg/t3code)

 `TypeScript` ⭐ +3,229 今日新增 · 42,512 总星数

> T3 Code 是一个开源的 agent 遥控器：在本机跑一个服务，用手机、网页或桌面端远程操控已登录的 Claude Code、Codex、Cursor 等 7 种 CLI，不用 API Key。

**亮点**

- 不自己写 agent 循环，只做控制层（作者叫它 agent harness control surface）：推理和工具调用仍交给各家 CLI，自己只负责会话管理、权限审批和多端同步。好处是任何一家 CLI 升级都不用跟着改模型层
- 远程优先且自托管：手机 App 直连你机器上的服务，代码和登录态不出自己的电脑。这也是它区别于 Cursor Glass 这类云端方案的核心取舍

**核心功能**

- 在本机起一个常驻服务（`t3 service install`），直接接管你电脑上已登录的 Claude Code、Codex、Cursor、Grok Build、OpenCode、Antigravity、fx 这 7 个 CLI，复用你已有的订阅额度，不去碰 API Key
- 一层适配层把 7 家 CLI 的会话统一成同一份状态，iOS、Android、Web、Electron 四端共用同一个后端，所以手机和桌面看到的会话是同一份
- 工程上走新工具链：构建用 Vite+（需要装全局 `vp` 命令），桌面端是 Electron，分发覆盖 winget、scoop、brew、deb、AUR、nixpkgs，`t3 update` 负责自更新

**适用场景**: 重度用 Claude Code / Codex 写代码的开发者。在工位上开好几个 agent 会话跑重构或修 bug，人离开电脑后用手机看一眼进度、批准权限、补一句指令，不用远程桌面。也支持外部 agent 通过 MCP 接进来。

**竞品对比**: README 自己点名对标 Codex 桌面版、Conductor、Claude Desktop 和 Cursor Glass。最大差异是开源、一次接 7 家 CLI、且原生支持手机远程；Conductor 基本只围绕 Claude Code，且是闭源 Mac 应用。

**成熟度**: 很早期，README 明说“very very early，expect bugs”，暂不接受大功能 PR，文档还只在 repo 里没有站点；但 App Store、Play 商店和多平台包管理器都已上架，说明分发链路是通的。

**趋势信号**: Theo（pingdotgg）本人的新项目发布日冲榜；更底层的推动力是 2025 年 Claude Code、Codex、Grok Build、Antigravity 等 CLI 一下子冒出七八个，用户既不想被锁死在一家，又都需要“人不在电脑前也能盯 agent”的遥控器。

### [vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)

 `Rust` ⭐ +2,275 今日新增 · 10,789 总星数

> Vercel Labs 出的桌面操作 CLI，让 AI agent 通过系统无障碍树读取和点击桌面应用，不靠截图和坐标匹配。视觉方案又贵又不稳，这个转向结构化控件树，所以现在火。

**亮点**

- 把「验证」这件事显式做进协议里：ref 属于某次快照，过期或歧义都直接报错而不是猜一个最像的目标，避免 agent 在错误元素上静默乱点
- 二进制自带与版本匹配的文档（agent-desktop skills get desktop / platform），agent 可以自己查当前平台的命令和限制，不用人去喂 prompt；输出统一 JSON envelope，错误里带 disposition.retry 告诉 agent 能不能重试

**核心功能**

- 走操作系统的无障碍树（macOS Accessibility、Windows UIAutomation、Linux AT-SPI）拿结构化的控件树 JSON，每个可操作元素带一个 ref 编号，agent 点 ref 就行，不用截图做像素匹配，也不调视觉模型
- 采用「快照-操作-再快照」的循环：ref 绑定快照 ID，UI 变了就返回 STALE_REF 或 AMBIGUOUS_TARGET，强制 agent 重新取快照再确认，把校验逻辑留在 agent 侧而不是工具里
- 默认 headless：通过无障碍 API 直接下发动作，不移动鼠标、不抢前台焦点，只有加 --headed 才用物理输入；每次 CLI 调用是独立进程，另有 C FFI 库（libagent_desktop_ffi）支持进程内调用，省掉反复起进程
- 给复杂应用做了分层快照：skeleton 模式先出粗粒度骨架，再用 --root 钻进某个子树，像 Slack 这种上千控件的界面不至于一次塞爆上下文

**适用场景**: 做 GUI agent 的团队，需要让 agent 操作非浏览器类桌面软件，比如 Finder 整理文件、Excel 填表、Slack 发消息、系统通知处理。适合在 Claude Code、Cursor 这类 harness 里挂成 skill，或通过 FFI 嵌进自己的 Rust/Python 程序。

**竞品对比**: 对比 Anthropic computer use、OpenAI Operator、UI-TARS 这类截图加坐标点击的方案，它不消耗视觉模型 token、结果确定可复现，但受限于各应用无障碍树的实现质量，冷门或自绘 UI 的软件可能读不出东西。对比 browser-use、Playwright MCP 只管浏览器，它覆盖整个桌面。

**成熟度**: Vercel Labs 实验项目，协议版本已到 2.6 但仍在快速迭代；key-down/key-up 等 4 个命令还没实现完，Linux 的 Wayland 和窗口管理能力明显弱于 macOS/Windows，Homebrew/Scoop 包还在提交中。

**趋势信号**: 2025 年 computer use 是 agent 主线，纯视觉方案成本高、点错就崩，社区正转向无障碍树这类结构化控制接口（browser-use、Playwright MCP 的走红是同一逻辑），Vercel Labs 把这条路从浏览器扩到整个桌面，踩中了这个转向。

### [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

 `TypeScript` ⭐ +1,803 今日新增 · 111,052 总星数

> 给 Claude Code 等编程 agent 做跨会话持久记忆：自动抓取会话里的工具调用，用 AI 压缩存档，下次会话按需注入相关上下文，省去重复交代项目背景。

**亮点**

- “文件就是协议”：不依赖宿主支持钩子，只要宿主会读 memory/log 下的 markdown 就能接上，所以能一次适配 Claude Code、OpenCode、T3 Code、Grok Bot 这么多家
- 存储层是可插拔的：可以走它自家托管的 CMEM Pro，也可以填自己的 OpenRouter / Gemini key，或者直接用 Anthropic 套餐，本地观察者要显式 `--provider host` 才开

**核心功能**

- 挂在宿主的 hook 上，每次 Read/Edit/Bash 这类工具调用都记成一条 observation，会话结束再用 LLM 压成语义摘要，而不是把原始聊天记录整段存下来
- 记忆检索走 MCP 工具：未来会话自己搜索历史记忆，命中才注入，不会一上来就把大段上下文塞进窗口
- 对没有 hook 能力的宿主（比如 Grok Bot）退化成监听 chat log 文件；把 decision、bugfix、security_alert 这类关键观察按 `- YYYY-MM-DD \[awareness\] …` 的格式追加进 memory/log/YYYY-MM.md，宿主启动时重读磁盘就算拿到了记忆

**适用场景**: 连着几天用 Claude Code / Codex / OpenCode 啃同一个仓库的开发者，隔天回来不想再解释一遍架构、约定和已经踩过的坑；几个人混用不同 agent 时，也想要一份共享的项目记忆。

**竞品对比**: 对比手写 CLAUDE.md / AGENTS.md：那是一次性静态文档，得人肉维护；对比 mem0、Letta 这类应用侧记忆库，它们面向自建 agent 的代码集成，而 claude-mem 是直接插进现成 IDE/CLI 的，靠 hook 自动采集、不用改 agent 代码。

**成熟度**: 版本已到 15.9.0，20 多种语言文档、有赞助商和商业托管服务，但迭代极快，安装流程默认引导你注册账号用托管记忆，在意隐私的得手动关掉 opt-in。

**趋势信号**: agent 记忆是当下最热的一块，它这波又刚铺开 Grok Bot、T3 Code、OpenCode 2 的多宿主支持并上线 CMEM Pro 托管服务（30 天免费试用），曝光直接拉满。

**趋势信号**: Claude Code 推出 subagents 和 Skills 之后，社区开始把整套研发流程写成 agent 角色，这类给 AI 装组织架构的模板在近期扎堆上榜，这个是其中角色划分和质检环节做得最细的一个。

### [mattpocock/skills](https://github.com/mattpocock/skills)

 `Shell` ⭐ +858 今日新增 · 310,517 总星数

> 把资深工程师的日常套路拆成可编辑的小提示词技能，装进 Claude Code、Codex 等编码代理，解决 agent 跑偏、啰嗦、写不出能跑的代码。

**亮点**

- 反框架立场：明确不做流程引擎，只给你能随手改的小提示词。针对的痛点就是 GSD/BMAD/Spec-Kit 这类方案接管流程之后，流程本身出 bug 你没法查。
- 用“共享词汇表”同时解决啰嗦和命名漂移：agent 拿到一份领域术语文档后，思考用的 token 更少，代码里的命名也更一致，会话开得越多收益越大。
- 装法跟着各家代理的原生插件市场走（claude-plugins-official、codex marketplace、copilot plugin），默认自动更新，不用自己 pull。

**核心功能**

- 每个技能就是一个纯文本 SKILL.md 提示词文件，放在 skills/engineering、skills/productivity 目录里，没有代码、没有流程引擎，改一行就能改行为；同一套文件经插件市场或 npx skills 分发到 Claude Code、Codex、GitHub Copilot、Gemini CLI 等不同代理。
- /setup-matt-pocock-skills 做一次性配置：问你用哪个 issue tracker（GitHub/GitLab/本地文件）、triage 打什么标签、文档存哪，后面 /triage 等技能直接读这份配置，不用每次重讲。
- /grill-with-docs 把三件事串起来：先让 agent 反过来追问你的需求（对齐），再把项目术语固化成 glossary 文档（共享词汇），最后把难解释的决策写成 ADR；配套的 /tdd 强制红-绿-重构循环，先写失败测试再动实现。
- /grill-with-docs 会纠正命名和表达方式，比如把“课程某个 section 里的 lesson 变成真实文件”压成项目术语“materialization cascade”，让 agent 少烧 token，变量和文件名也跟着统一。

**适用场景**: 用 Claude Code、Codex 写真实业务项目（不是一次性 demo）的独立开发者和中小团队，尤其是嫌 Spec-Kit、BMAD 太重、又想在多个代理之间来回切的人。

**竞品对比**: 对手是 GitHub Spec-Kit、BMAD-METHOD、GSD 这类自带流程和脚手架的框架，它们帮你管流程但也拿走控制权；这个仓库只是散装、可编辑、模型无关的提示词，最大差异是把控制权留给你，且装在各家原生插件市场里自动更新。

**成熟度**: 作者日常自用、文档和示例齐全、分发自带自动更新，但没有语义化版本号，技能文件的内容会随作者习惯变动，升级前最好先看 diff。

**趋势信号**: 踩中 Anthropic 推的 SKILL.md / Claude Skills 格式，加上 Claude Code、Codex、Copilot 的插件市场刚开放第三方源，作者 6 万订阅的 newsletter 一推就起量。

### [shiyu-coder/Kronos](https://github.com/shiyu-coder/Kronos)

 `Python` ⭐ +857 今日新增 · 46,114 总星数

> Kronos 是首个开源的金融 K 线基础模型，把 OHLCV 行情当成语言来预训练，让量化任务可以像调用大模型一样直接做预测。因 AAAI 2026 中稿重新引发关注。

**亮点**

- 关键取舍是不直接回归收盘价，而是把 K 线离散成 token 交给语言模型生成——这样天然能产出多条采样路径，直接反映金融预测的不确定性，避免了 MSE 回归那种虚假的确定感
- tokenizer 是独立可替换的组件，2k 上下文和 base 两个版本分开托管在 Hugging Face，模型和分词器解耦，方便单独替换

**核心功能**

- 两阶段架构：专用 tokenizer 先把连续的多维 K 线数据（开高低收量额）量化成分层离散 token，再用 decoder-only Transformer 在这些 token 上做自回归预训练——本质是把 K 线当文本词序列来建模
- 训练数据横跨 45 个全球交易所，专门针对金融数据高噪声的特点预训练，并非套用 TimesFM 那类通用时序模型
- KronosPredictor 封装了归一化、预测、反归一化三步；支持 T（温度）、top_p、sample_count 参数，一次能采样多条预测路径再平均，输出概率区间而不是单点
- 模型按参数量分档：4.1M / 24.7M / 102M 开源，499M 的 large 未放出，小档位单卡甚至 CPU 就能跑

**适用场景**: 量化研究员和交易团队做分钟级价格走势预测，比如拿 A 股 5 分钟 K 线预测未来 120 根；也可以作为信号模块嵌进已有因子回测流程，或用官方微调脚本适配自家标的和频率。

**竞品对比**: 和 TimesFM、Chronos、Moirai 这类通用时间序列基础模型比，Kronos 只吃金融 K 线、只做这一件事，且用离散 token 自回归生成而非连续值回归；和 FinGPT 那类金融文本大模型方向完全不同，它看的是行情数字不是新闻。

**成熟度**: 偏早期研究项目：论文 2025.08 上 arXiv，2025.11 才被 AAAI 2026 接收，微调脚本 8 月刚放出，最大模型未开源，没有版本号，API 仍可能变。

**趋势信号**: 2025.11.10 在 README 挂出 AAAI 2026 中稿消息，加上金融时序基础模型这个空白地带一直没开源对标物，消息被二次传播后拉了一波星。

### [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling)

 `Python` ⭐ +706 今日新增 · 93,346 总星数

> Scrapling 把 HTTP 请求、反检测浏览器、解析、并发爬虫放进一个 Python 库，还提供 MCP 服务让 AI agent 直接抓网页。

**亮点**

- 把通常要拼三套库的活（Scrapy 调度 + Playwright 渲染 + parsel 解析）收进一个包，选择器语法、Session 和导出格式统一，省掉跨库适配的麻烦。
- 解析层返回的元素对象自带指纹，长期跑的爬虫在目标站改版后不会直接失效；这比单纯提高抓取速度更有维护价值。

> FreeToken 是一个面向个人电脑的 MoE 推理引擎，把显卡、CPU 和内存合并成一个可弹性分配的资源池，让一张 24G 显卡也能运行 290B 级别的开源 MoE 大模型。最近一批开源大模型都采用 MoE 架构，权重体积远超个人显存，因此它受到关注。

- 把 CPU、GPU、主机内存和互连带宽视为一个整体来调度，核心是 q* 策略，判断依据是测出来的实时带宽，而非硬件型号。边缘设备带宽波动大，固定比例分片会不断遇到瓶颈

- 运行时显存重分配：专家缓存和 KV 内存的显存配额可以在不重启进程、不重载权重的情况下由引擎动态调整

**趋势信号**: 2025 年多 Agent 并行编码成了日常——Claude Code、Codex、Cursor Cloud、Gemini CLI 同时在线，社区里"一个人管 20 个终端"的痛点被反复吐槽，Paperclip 正好在这个节点把自己定位成管理层，加上 Cloud 候补名单和 Discord 拉新把热度顶了上来。

### [karpathy/nanochat](https://github.com/karpathy/nanochat)

 `Python` ⭐ +321 今日新增 · 60,037 总星数

> Karpathy 的全流程 LLM 训练实验架：只调一个 --depth 旋钮就自动配好全部超参，花约 100 美元、2 小时在 8xH100 上练出 GPT-2 水平的模型。

**亮点**

- 维护一个「time-to-GPT-2」排行榜，主指标是在 8xH100 上超过 GPT-2 1.6B CORE 分数（0.2565）所需的墙钟时间，社区提 PR 刷榜，目前从 168 小时（2019 年 OpenAI 原始训练）压到 1.65 小时
- 作者用 agent 跑「autoresearch」自动搜索超参，两轮分别把时间从 2.02 小时压到 1.80 和 1.65 小时，把调参过程本身做成了公开实验

**核心功能**

- 只暴露 --depth（Transformer 层数）一个旋钮，宽度、头数、学习率曲线、训练步数、weight decay 全按缩放律自动算出来，改一个整数就能练出整条 miniseries 模型（depth 26 ≈ GPT-2 水平）
- runs/speedrun.sh 一个脚本串完 tokenizer 训练、预训练、SFT、评测、CLI 推理，不用拼外部训练框架
- 评测指标用 DCLM CORE 分数加 val_bpb（按字节而非 token 算的验证损失，换词表也能直接比），再靠 fp8 和 1M token 的大 batch 把墙钟时间压下去
- 去掉 torchrun 就自动切成梯度累积单卡跑，结果基本一致，只是慢 8 倍

**适用场景**: 想亲手跑通 LLM 全流程的学生、研究者和做小规模消融实验的团队。典型用法是改一行代码、用 12 层小模型跑 5 分钟预训练，在 wandb 上看 val_bpb、CORE、MFU 判断这次改动有没有用。

**竞品对比**: 和 modded-nanogpt 比，后者只做预训练 speedrun，nanochat 把 tokenizer、SFT、评测、推理也包进来了；和 nanoGPT 比，多了缩放律自动配超参和完整评测链路；和 torchtitan、litgpt 这类工程化框架比，它是刻意写小、给人读懂和改的，不是拿来上生产的。

**成熟度**: 实验/教学性质，不是生产框架。主线还在高频改动，接口会变，榜单几乎每周刷新，但代码量小、有 DeepWiki 问答和 Discord 撑着，跑通门槛很低。

**趋势信号**: Karpathy 用 agent 自动刷自家 time-to-GPT-2 榜，几轮把训练成本压进 100 美元以内，加上「100 美元能买到的最好 ChatGPT」这个标题，社区跟着复现和提 PR。

### [max-sixty/worktrunk](https://github.com/max-sixty/worktrunk)

 `Rust` ⭐ +77 今日新增 · 10,154 总星数

> 用 Rust 写的 Git worktree 命令行工具，把建/切/删 worktree 简化成和切分支一样，专门服务同时跑多个 AI agent 的场景。

**亮点**

- 把 git worktree 的心智负担压到和分支同级：地址就是分支名，路径、端口（hash_port 模板过滤器给每个 worktree 分配唯一端口）都是算出来的，所以每个 worktree 能各跑一个 dev server 不撞车。
- 抓住「AI agent 需要干净工作目录 + 便宜的环境初始化」这个真痛点，用写时复制缓存解决问题，而不是靠 Docker 容器隔离那种重方案。

**核心功能**

- worktree 用分支名寻址，磁盘路径由配置模板算出来；切换目录靠 shell 集成（wt config shell install）实现真正的 cd，而不是起子进程，所以一条 wt switch feat 就到位。
- wt step copy-ignored 用文件系统级写时复制（reflink，支持 APFS/btrfs/XFS）把 target/、node_modules/ 共享给新 worktree，开十个 worktree 不用重新 install 或 build，磁盘也只占一份。
- wt switch -c -x claude 一步建 worktree 并 exec 指定命令；另有 create/pre-merge/post-merge 等生命周期 hooks，wt list --full 会并行拉取每个分支的 CI 状态和 LLM 生成的一句话摘要。

**适用场景**: 适合用 Claude Code、Codex、Cursor 这类能长时间无人值守跑任务的 agent 的开发者——同时开 5~10 个 agent，每个 agent 独占一个 worktree 互不踩踏，再配 Zellij/tmux 一个 tab 一个会话。

**竞品对比**: 对比原生 git worktree（起一个要敲三遍分支名再加 cd）、git-town（管分支流程但不管并行目录）、gwq 这类 Go 写的 worktree 管理器；差异在于它把 AI agent 周边全包了——COW 构建缓存、hooks、LLM commit message、wt switch pr:123 直接 checkout PR。

**成熟度**: 今年初才发布，不到一年，还在 0.x，基本是单一维护者（max-sixty，PRQL 作者）在推，日常用没问题但边缘 case 和命令行为可能还会变。

**趋势信号**: 2025 年起 Claude Code、Codex 能长时间无人值守，大家开始真的并行跑多个 agent，worktree 从冷门 git 功能变成刚需，而原生 UX 太烂——它正好卡在这个缺口上。

## 趋势观察

今天的榜单基本被同一件事占满：怎么把 AI agent 当团队来管。 一大半项目在给 agent 补基础设施。跨会话持久记忆、提示词技能包、把资深工程师的套路拆成小指令、用系统无障碍树让 agent 点桌面应用、MCP 直接抓网页、Rust 写的 worktree 工具方便同时开几个 agent。还有直接把 Claude Code 配成 49 人工作室，做成有预算和审批的"AI 员工后台"。这些解决的是同一个毛病：单开一个会话很惊艳，一开十几个就乱套。没有记忆，没有分工，没人拦着写烂代码。 另一个明确方向是本地推理往下压。FreeToken 把显卡、CPU、内存拼成一个池子，一张 24G 卡跑 290B 的 MoE。纯 C 引擎更狠，只把当前用到的专家留在内存，其余从磁盘按需读，8GB 内存也能跑几百 B。背景很直接：新开的开源大模型几乎全是 MoE，权重体积远超个人显存。 还有几个偏"可组合"的。Karpathy 用一个旋钮自动配好超参，100 美元练出 GPT-2 水平。不用训练，靠提示词加打分器搜参数，几十分钟去掉模型拒答。Kronos 把 K 线当语言预训练。思路一致：把门槛砍到普通人够得着。 合起来看，注意力正从"训模型"挪到"用模型干活"。agent 要记忆、要权限、要编排、要组织结构。接口要结构化，不能再靠截图猜坐标。模型这边拼的是能不能塞进你的机器。开发者生态正在从玩单次对话，转向搭一套能长期跑的系统。
