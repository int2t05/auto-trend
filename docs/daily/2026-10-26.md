### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,878 今日新增 · 47,230 总星数

> Cloudflare 开源的一个编码 Agent 技能包，让 Claude Code 这类 Agent 按六阶段流程做安全审计，产出带源码证据、经独立复核、符合 schema 的机器可读漏洞记录。

**亮点**

- 审计产物优先于报告：REPORT.md 等三份文档都是从已校验的记录派生出来的，不能手写，等于把“可信度”压在了 JSON 记录和 schema 上，而不是一段自然语言描述。
- 严重性必须落到影响（可能性 × 影响面），纵深防御少一层只算加固建议、不算漏洞；作者实测单次运行只覆盖重复运行总漏洞量的一半左右，所以整套流程就是按“多跑几轮累积”设计的。

**核心功能**

- 把审计过程写成结构化台账：coverage-ledger.json 记录架构、信任边界、输入面，猎手 Agent 按台账单元分派任务，再由 coverage critic 找没覆盖到的单元，避免“想到哪测到哪”。
- 发现者和验证者强制分离：每个候选漏洞交给一个全新的 Agent 专门去证伪，结论只有三档 —— confirmed（有完整源码调用链和可观测结果）、needs_validation（写清具体未解决的事实、不给严重级别）、rejected（记录被推翻的候选）。
- 两个零依赖 Node 校验器（validate-findings.cjs / validate-coverage-ledger.cjs）对着 report-schema.json 做校验，台账每次更新后、findings 写完和每次替换后都要重跑，schema 不合就不算数；多次运行是叠加的，复用旧台账只补缺口、只重验变更过的源码。

**适用场景**: 安全工程师或后端团队在自己的代码仓库里，让 Claude Code / 支持并行子 Agent 的编码 Agent 跑一遍审计，拿到可复核的漏洞清单；也适合开源维护者在上线前自查，或安全团队照着它搭自己的漏洞挖掘 harness。

**竞品对比**: 和 Semgrep、CodeQL 这类规则/查询驱动的静态扫描不同，它靠 LLM Agent 做跨文件语义推理，覆盖率来自台账而不是规则库，也不追求结果完全可复现；代价是更慢更贵，且跑目标代码时必须依赖 OS 级沙箱（断网、白名单环境、资源限额），否则只能停在 needs_validation。

**成熟度**: 早期项目，MIT 协议，无版本号，文档非常细（十几份按攻击面拆分的狩猎手册），但 API 和工作流仍可能调整。

**趋势信号**: Agent Skills 生态（skills.sh、npx skills add）刚起来，加上 Cloudflare 发博客说自家 fleet 级漏洞挖掘 harness 就是从这个 skill 长出来的，安全团队想直接抄一份当起点。

### [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)

 `Python` ⭐ +1,592 今日新增 · 87,193 总星数

> 把 ElevenLabs 的语音克隆、配音、听写搬到本地跑的桌面应用，覆盖 646 种语言，还提供 MCP 接口给 AI Agent 当语音工具。

**亮点**

- 走 GGUF 量化路线给 TTS 降门槛，而不是要求用户买大显存卡；多后端抽象让同一模型在 Metal、Vulkan、ROCm 上都能出声音，这是同类研究仓库普遍缺失的工程活。
- 把“让 AI Agent 帮你装”做成一等公民：仓库里有 agent.md 安装指南和 npx skills add 入口，Agent 自己检测硬件、问你要不要下模型、跑一次测试生成。

**核心功能**

- 默认引擎是 k2-fsa/OmniVoice，另有 CosyVoice 的 GGUF 量化版本；同一套界面下可在 CUDA、Apple Metal、Vulkan、ROCm、纯 CPU 之间切换。在 6700XT 这类消费级显卡上也能跑，不用 A100。
- 架构是 Electron 前端加独立 Python 推理后端（Bun 打包），引擎以插件形式接入，ASR 走 whisper.cpp；模型不随安装包分发，首次使用时按需下载，安装包因此只有几十 MB。
- 本地 HTTP API 加 MCP server，Claude Code、Cursor 这类 Agent 能直接把“合成一段语音”“转写这个文件”当作工具调用；配合 watch folder 和“recipe”做批量任务（如整本有声书）。

**适用场景**: 做视频或播客的内容创作者：需要给自己的视频配多语言音轨，又不想把素材上传到 ElevenLabs 云端的付费订阅用户。 企业和隐私敏感团队：会议转写、听写、内部培训音频本地生成，数据不出机器；开发者通过本地 API 把 TTS 接进自己的 Agent 流水线。

**竞品对比**: 对比 ElevenLabs：功能面重合（克隆、配音、多语言），最大差异是全部本地推理、无订阅、开源 AGPL。对比 XTTS-v2/Coqui、GPT-SoVITS、F5-TTS 这类研究仓库：那些只有 CLI 或 ComfyUI 节点，VoiceStudio 提供完整桌面 GUI、模型管理器和配音时间轴。

**成熟度**: 早期项目（0.5.x 版本），刚从 Tauri 迁到 Electron 且老用户需重装，Windows on ARM 明确标注实验性，API 和安装路径还会变。

**趋势信号**: 踩中两条线：一是本地优先、隐私不上云替代 ElevenLabs 的需求，二是 MCP/Agent 工具生态爆发，语音合成成了 Agent 的标配工具。

### [Nutlope/hallmark](https://github.com/Nutlope/hallmark)

 `CSS` ⭐ +1,317 今日新增 · 34,251 总星数

> 给 Claude Code、Cursor 等编码 Agent 加一层设计约束：48 套主题负责出页面，真实浏览器 lint 负责把「AI 味」挑出来重做，让生成的网页不像 AI 做的。

**亮点**

- 首屏单独先建，渲染后交给一个全新上下文的 subagent「冷眼」审，通过才做剩下的部分——不让同一个上下文自己夸自己。
- 不编内容：pre-flight 阶段只问一次真实素材（照片、截图、真实数字），照片库只有 755 张 Wikimedia Commons 的开放授权图，每张页面内署名，没有就空着而不是瞎编。

**核心功能**

- sloplint.mjs 用 puppeteer-core 在 8 种屏幕宽度下真实渲染页面，逐条检查具体毛病：标题上方的小标签、字距拉开的全大写标签、标题里只有一个词变色、整屏空卡片或全是照片、首屏撑不满屏、页尾必有邮件订阅、表单点了「谢谢」却没真发送。
- 闸门分三档：Floor（对比度、键盘焦点、prefers-reduced-motion、编造的事实、手机布局崩）直接不允许发布；Reflex（模型最容易掉进去的套路）允许带理由覆盖，但要写进记录；Finish 只是工艺提示，不拦发布。
- 主题是「材质」不是模板：48 个主题每个不超过 8KB、单独一个文件，只定义纸张/字体/配色/表面质感和组件样式，不规定页面结构和顺序；`theme.mjs deal` 按 prompt 发三张牌，`draw` 再按「这页要干什么」决定页面骨架。
- redesign 前先跑 `sloplint --before` 记下每个链接、表单字段、事件处理器和标题，改完用 `--kept` 校验一个都不能少，缺了就判失败。

**适用场景**: 独立开发者和小团队用 Claude Code / Cursor 赶落地页、定价页、产品官网时用，避免交出去的页面一眼被认出是 AI 生成；也用于对已有页面做 redesign 或只出报告的 audit。

**竞品对比**: 和 v0、Lovable、bolt.new 这类「一句话出 UI」的生成器不同，Hallmark 不自己出图，而是挂在你自己已有的 Agent 上当约束层加检查器；和 shadcn/Tailwind 模板也不同，它给的是材质而不是成品结构，重点是「拦住 AI 套路」而不是「给更多组件」。

**成熟度**: 已发 v2、npm 一行安装、四家 Agent 都有接入文档，但项目很新，主题目录和规则还在快速增删，适合尝鲜和小项目，关键产品页建议人工再过一遍。

**趋势信号**: Claude Code Skills / plugins 生态刚起来，加上大家对「AI 味」页面的审美疲劳正好撞在一起，成了第一个把「反 AI slop」做成可执行 lint 规则的项目。

### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +1,092 今日新增 · 87,957 总星数

> 给 AI 编程助手补上设计能力：1 个技能 + 24 条命令 + 62 条可离线跑的检测规则，专门治 AI 生成前端那股千篇一律的"模板味"。

**亮点**

- 把"设计审美"拆成可执行的部分和不可执行的部分：能机器判的 62 条规则交给确定性检测器（无需模型、零成本、可当 CI 卡点），剩下需要判断的交给 LLM 做 critique，避免用大模型去跑本就该写死的规则
- 安装时往 harness 里写 provider-native hook 清单（.claude、.codex、.grok 等），代码编辑时就触发检查，而不是等最后一次性让 AI"帮我优化一下设计"

**核心功能**

- 62 条确定性检测规则不调 LLM、不要 API key，纯本地静态跑，能直接判出"全站 Inter 字体、紫蓝渐变、卡片套卡片、彩色底上压灰字"这类 AI 通病，结果可复现、进 CI 也不花钱
- 给 AI 定了两套事实：PRODUCT.md 存受众、目标、约束、语气这类长期不变的产品真相，DESIGN.md 存视觉方向，两者分开存，避免模型把"这产品是给谁用的"和"按钮该圆还是方"混成一锅
- live 模式把浏览器当画布：/impeccable live 针对单个元素出变体，/impeccable generate 直接按元素名批量生成，不用人工在页面上点选；引擎是一个 Rust 自包含二进制，首次运行时下载到 ~/.impeccable/bin/，装完不依赖 Node

**适用场景**: 用 Claude Code、Cursor、Copilot、Codex 写前端页面/落地页的前端工程师和独立开发者——AI 代码能跑但长得像模板，需要一条命令做审计、收敛、打磨，或在已有的设计系统上做最终对齐。

**竞品对比**: 起点是 Anthropic 官方的 frontend-design skill，但那只是一段提示词、没有任何检查手段；Impeccable 的差异在于多了可离线执行的检测器和浏览器实时迭代回路。跟 shadcn、21st.dev 那类组件库不是一回事，它不给你组件，管的是你已有的代码长得好不好看。

**成熟度**: 工程上已经能日常用（Rust 单二进制、VS Code 插件上架、多 harness 安装脚本齐全），但命令集和 hook 机制改得还比较勤，升级后 Codex 等工具可能要重新批准 hook。

**趋势信号**: Claude Code、Cursor 这类助手大规模生成前端后，产出同质化成了公认问题，Anthropic 官方设计 skill 走红把这个话题推上台面，而 Impeccable 是第一个把它做成"带检测器可验证"的版本。

### [makecindy/cindy](https://github.com/makecindy/cindy)

 `TypeScript` ⭐ +675 今日新增 · 5,155 总星数

> Cindy 是一个开源桌面/移动端 AI Agent 客户端，把 Claude Code 和 Codex 等多个 harness 和模型混着用，在你本机真实文件和已登录应用上直接干活，开箱即用。

**亮点**

- 不是再造一个 Agent 框架，而是做一个“调度层”：把别人家的 harness 和模型当执行单元自由拼装，并保证工作区和记忆不中断。这个取舍省掉了自己训练和适配模型的成本，直接享受上游模型的迭代
- 客户端开源、后端闭源，但默认连官方云服务，开发者不用自建服务器就能登录自家账号调试；同时留了 Skip Sign-In 纯本地模式，不登录也能跑本地 Agent

**核心功能**

- 多 harness 混用：同一个任务里可以让 Claude Code 和 Codex 等不同 harness × 不同模型组合，分别负责规划、并行执行和评审，任务中途还能切换 harness 或模型，而工作区、记忆、技能、工具保持连续，不重开上下文
- Cindy 用 pnpm monorepo 组织，Electron 桌面端 + Expo/React Native 移动端共用 packages/* 里的认证、设备互联、Agent 编排、模型供应商等模块；claude-code、codex、ripgrep 这些二进制不提交到仓库，由 pnpm install 按平台下载，Android 平台工具下载时带 sha256 校验
- 支持和已有订阅不重复计费：已经付费的 Claude Code / Codex Coding Plan 可以直接授权接入，也可以用自家 API key 或本地模型；记忆、技能、定时任务、MCP 接入都跨 harness 共享

**适用场景**: 适合已经在用 Claude Code / Codex 写代码的开发者，以及想让 Agent 直接操作浏览器、电脑和手机处理日常任务的个人或小团队；可以接入 IM 和定时计划，让它在本地项目里自己跑周期任务并回报结果。

**竞品对比**: 和 Cursor、Claude Code 这类单一模型、单一 harness 的编码工具比，Cindy 的差异是模型和 harness 可热插拔、多 Agent 分工协作，而且不锁定单一厂商；和 OpenHands、AutoGPT 这类开源 Agent 框架比，它更偏成品桌面应用而不是开发者框架，但后端不开源，可定制范围受限于客户端。

**成熟度**: 早期项目，5k 星但后端不开源、插件市场和团队技能共享还在开发中，API 和功能会变。

**趋势信号**: 赶上了“多 harness 编排 + 复用已有 Coding Plan 订阅”这波需求：Claude Code 和 Codex 各自爆火后，用户手上订阅多、工具割裂，Cindy 主打一个客户端全接进来且不重复付费，顺势冲上 trending。

 `Rust` ⭐ +647 今日新增 · 11,830 总星数

**适用场景**: 买了实机的爱好者和学生用 robotctl 或手柄直接驱动、改行为；做机器人产品的团队可以抄它的守护进程拆分和 OTA 方案；研究者在 MuJoCo 里批量仿真测试策略再推到真机。

**竞品对比**: Petoi Bittle、Hiwonder 这类舵机机器狗跑的是写死的步态和遥控指令，microduck 跑端到端 RL 策略并开源了整条产品固件；比起 Unitree Go2 这类它更小更便宜，且固件不是黑盒。

**成熟度**: 面向在售硬件发布，有 CI、逐模块设计文档和可回滚的签名更新，算生产级；但仓库刚公开，接口和文档还在变。

**趋势信号**: Hugging Face 收编 Pollen Robotics 后开源 Reachy Mini 攒下的热度，现在把另一款在售机器人的完整固件也开源了，直接冲上 trending。

### [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents)

 `Python` ⭐ +381 今日新增 · 114,839 总星数

> 用多个 LLM 智能体分别扮演分析师、研究员、交易员和风控，模拟一家交易公司的投研决策流程，输出可回测的交易结论。最近发布了 v0.7.0。

**亮点**

- 多智能体的产出通过结构化输出强制交由特定的几个智能体（Research Manager、Trader、Portfolio Manager）完成，从而得到可程序解析的决策，避免自由聊天产生难以利用的文本
- 回测按每次决策之后的第一个收盘价打分，而不是按随意选定的价格，这样算出来的收益更接近真实执行

**核心功能**

- 回测做时点对齐（point-in-time）：每个分析日期只允许使用当天已经公开的数据，对 FRED 宏观数据、社交情绪、SEC EDGAR 财报都按披露时间过滤，避免用未来信息算收益
- 用 LangGraph 编排智能体图，支持检查点断点续跑；可以为不同模型层级分别配置不同的 provider，例如分析师用便宜模型、经理用强模型

**适用场景**: 量化研究员和 LLM 开发者拿它做投研流程自动化实验或多智能体协作研究：输入股票代码和日期，自动生成带辩论过程的研报和回测结果。不适合直接用于实盘下单。

**竞品对比**: 和 CrewAI、AutoGen 这类通用多智能体框架比，它的角色分工固定，并且自带金融数据源和回测；与 FinRobot、FinGPT 比，它的重点放在决策流程建模，并且有配套论文（arXiv 2412.20138）。

## 趋势观察

这批项目看下来，主线很清楚：Agent 不再只是聊天，开始直接上手干活。Cindy 直接在你本机的文件和已登录应用里操作，Claude Code、Codex 混着用。JetBrains 把编码 Agent 装进一个轻量 IDE，用 git worktree 隔开并行任务。都指向一件事：Agent 从对话框走进了工作台。 第二条线是给 Agent 立规矩。好几个项目专门治“AI 味”：48 套主题加真实浏览器 lint，把千篇一律的页面打回去重做；1 个技能配 62 条离线检测规则，专治模板腔。Cloudflare 的技能包让 Agent 按六阶段做安全审计，漏洞记录要带源码证据、要独立复核、要符合 schema。SEO 插件也是 26 个技能、19 个 agent 并行跑。共同点很直接：不满足于“能生成”，要“能验收”。 第三条线是拆包。技能包、MCP 接口、命令集，能力被打成可插拔的零件。ElevenLabs 的语音克隆搬本地跑，还留了 MCP 接口给 Agent 当工具。 第四条线是自持。本地跑模型、自己服务器部署 PaaS、自带模型 key，避免被平台绑定的意思很明确。 垂直行业也在被逐个改造：多个 LLM 扮演分析师、研究员、交易员和风控，模拟交易公司的投研流程；紫微斗数放出 67.5 万张命盘和 877 万段带出处的语料，算法确定、语料可查；连 25cm 的鸭子机器人固件都整套开源了。 一句话总结：热点已经不是“模型多强”，而是 Agent 怎么接进真实工作流、怎么被验收、怎么不绑在某家云上。开发者生态正从调 API，转向搭班子、定流程、留证据。
