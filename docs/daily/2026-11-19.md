### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +389 今日新增 · 60,025 总星数

> 把各种软件包一层带 JSON 输出的命令行，再配 SKILL.md 教 Agent 调用，让 Claude Code、Cursor 这类工具直接操作桌面软件，绕开 MCP 的部署成本。

**亮点**

- 刻意不走 MCP：不起常驻服务、不维护 tool schema，Agent 用现成的 shell 工具就能跑，报错时靠 --help 和退出码自己纠正，安装只需 pip 或 npx
- 带 preview / live preview / 轨迹回放，Agent 每改一步能看到中间产物（3D 场景、字幕、CAD 模型），不用等整条流程跑完才发现错

**核心功能**

- 每个软件一个用 Python Click 写的 CLI harness，子命令对应原软件的操作（LibreOffice 转文档、Calibre 管书库、3MF 改网格），同一条命令同时吐 JSON（给 Agent 解析）和人类可读文本，不改原软件源码
- 每个 CLI 自带一份 SKILL.md，用 `npx skills add HKUDS/CLI-Anything --skill &lt;name&gt; -g -y` 装进支持 Agent Skills 的客户端，Agent 靠读文档学命令，而不是靠注册 tool schema
- 解析不可信 XML/SVG/ODF/MLT/MusicXML/CSL 时统一走 defusedxml 防 XXE；Rekordbox 这类要写 SQLCipher 数据库的操作强制先备份再强写，Sketch 的 token 文件做了路径穿越和软链逃逸防护

**适用场景**: 想让 Claude Code、Cursor、OpenClaw 这类 agent 去操作本机软件的开发者——例如让 agent 批量转 LibreOffice 文档、整理 Calibre 书库、跑 Blender/CAD 出图、下载 Zoom 录制；也适合企业把内部系统包一层 CLI 挂进 CLI-Hub 给 agent 用。

**竞品对比**: 对比 MCP server 生态，CLI-Anything 不起服务、只生成命令行，部署和调试成本低一截；对比 computer-use 那类点屏幕的方案，它走确定性命令而不是点像素，结果可复现。

**成熟度**: 有 2400+ 测试、arXiv 技术报告和 Apache 2.0 许可，但仍是每天合 PR 的快速迭代期，各软件 harness 质量参差，上生产要先挑验证过的那几个。

**趋势信号**: Claude Code 的 Agent Skills 和 MCP 正被大量讨论，这个项目押的是“CLI 比 MCP 更省事”这条路线，又配上 CLI-Hub 分发和 60k star 的雪球效应，所以现在冲榜。

### [n8n-io/n8n](https://github.com/n8n-io/n8n)

 `TypeScript` ⭐ +325 今日新增 · 211,260 总星数

> n8n 是一个可自托管的可视化工作流自动化平台，把 AI Agent 能力直接做成画布节点。它想替代 Zapier 这类 SaaS 工具，但数据和模型都留在自己服务器上。最近 AI Agent 热度高，加上 SaaS 自动化工具涨价，它涨得很快。

**亮点**

- 采用 fair-code 授权：源码全部可见、可自托管，但禁止拿它做商业转售托管服务。这样既靠社区攒生态，又保住了云版本的生意
- 可视化画布和代码是同一套东西：每个工作流就是一份 JSON，能进 git 做版本管理，也能在节点里直接写 JS 补逻辑，不用在低代码和真代码之间二选一

**核心功能**

- 整套工作流由节点拼成，每个节点是独立的 npm 包（n8n-nodes-base 里有几百个），第三方可以自己写节点发布，不用改核心代码
- AI 能力用 LangChain.js 封装成画布节点：Agent、Memory、Vector Store、Tool 各是一个可拖拽的节点，换 OpenAI、Anthropic 或本地模型只改一个连接
- 代码节点能直接运行 JS 和 Python（Python 靠 Pyodide 在沙箱里运行），还能 import npm 包，可视化搞不定的逻辑就写一段代码插进去
- 大规模运行用队列模式：Redis + Bull 把主进程和 worker 拆开，多开 worker 横向扩容，失败的任务可以重试

**适用场景**: 适合不想把数据传给第三方 SaaS 的团队，比如金融、医疗公司的内部自动化流程；也适合做 AI 产品原型的开发者，用它快速接 CRM、数据库、Slack，串一个带人工审批的 Agent 流程，不用从零写编排代码。

**竞品对比**: 对手是 Zapier、Make（原 Integromat）这类 SaaS 自动化工具，以及 Dify、Coze 这类 AI 应用平台。最大的差别是 n8n 能完全自托管、数据不出内网，而且执行次数不按任务条数计费；比起 Dify，它的传统系统集成（1500+）多得多，AI 只是其中一块能力。

**成熟度**: 生产可用，已到 1.x 版本，有企业版和 RBAC、审计日志，社区和模板库都很成熟。

**趋势信号**: 2025 年 AI Agent 落地的需求集中爆发，n8n 把 LangChain 拆成节点给非算法岗使用，门槛一下降低；叠加 Zapier 等 SaaS 涨价、企业数据合规收紧，自托管方案被大量迁移，它的融资金额和发版频率也都在涨。

### [jquery/jquery](https://github.com/jquery/jquery)

 `JavaScript` ⭐ +266 今日新增 · 60,064 总星数

> jQuery 发布 4.0 大版本：删掉 IE 兼容代码和废弃 API，Deferred 对齐原生 Promise，支持 ESM 和按模块裁剪构建。

**亮点**

- 这是 2016 年 jQuery 3.0 之后第一个大版本，路线是纯减法：不加新功能，只清理历史包袱，把兼容层和废弃 API 一次性砍掉
- 同一份源码能裁出 slim、ESM、自定义子集三种形态，连选择器引擎都可以被原生 querySelectorAll 替代，只想做 DOM 操作和事件绑定的场景不用背整个库

**核心功能**

- 做减法为主：移除 IE 时代的兼容分支和一票废弃 API（jQuery.isArray、jQuery.trim、jQuery.parseJSON、jQuery.nodeName 等），改用 Array.isArray、Promise 等原生能力，让打包体积变小、代码更少被旧浏览器限制
- Deferred 对象改成符合 Promise/A+ 规范，.then 返回真正可链式、可被 await 的 promise，能和原生 Promise、async/await 混用，不再有 jQuery 自己的那套半吊子 Promise 语义
- 构建脚本支持 --exclude/--include 按模块裁剪：ajax、effects、event、offset 等都能去掉；去掉 selector 引擎后会换成基于浏览器 querySelectorAll 的轻量兜底实现，也能产出 ESM 版 jquery.module.js，具名导出 jQuery 和 $

**适用场景**: 维护老后台系统、WordPress 主题/插件、以及依赖大量第三方 jQuery 插件（轮播、表格、日期选择器）的团队，需要在不动现有页面的前提下升级到受支持的版本；3.x 已进入只修严重问题的状态，这批用户被迫排期迁移。

**竞品对比**: 和 React/Vue 不是同一层的东西，真正的替代者是原生 DOM API、fetch，以及 cash、Umbrella JS 这类精简克隆。jQuery 的差异点在于十几年积累的插件生态和老代码兼容性，cash 这些只覆盖了 API 子集，插件跑不起来。

**成熟度**: 非常成熟：20 年生产验证，文档和浏览器支持矩阵齐全，4.0.0 已正式发布；但 4.0 刚出，部分老插件是否兼容还需要实测。

**趋势信号**: jQuery 4.0.0 在 2026 年 1 月正式发布，同时官方宣布 3.x 只接收严重问题修复、1.x/2.x 彻底停止支持，逼着大批存量站点开始规划升级。

### [astral-sh/uv](https://github.com/astral-sh/uv)

 `Rust` ⭐ +258 今日新增 · 92,323 总星数

> 用 Rust 重写的 Python 包与项目管理器，一个二进制替代 pip、poetry、pyenv、virtualenv，装包快 10-100 倍。Python 生态正把它当默认安装入口，所以长期挂在趋势榜。

**亮点**

- 战略上做了 pip 兼容层而不是另起一套 CLI。现有 requirements.txt 工作流零改动就能迁移，这是它能在老项目里快速铺开的关键取舍；代价是要同时维护两套命令语义。
- 把"包管理"和"解释器管理"合到一个进程里：因为解释器由 uv 自己下载，创建虚拟环境不需要调用外部 python，环境创建从秒级降到毫秒级。

**核心功能**

- Rust 实现 + PubGrub 版本求解算法（一种把依赖约束当逻辑命题逐步推导的解析算法），加上全局缓存和硬链接安装：同一份包在磁盘上只存一份、只下载一次，装进虚拟环境时直接硬链接过去，不走复制。这是快 10-100 倍的主要来源，不靠并行下载。
- 统一锁文件（universal lockfile）：一次解析出覆盖所有操作系统和所有 Python 版本的 uv.lock，不用为 Linux/macOS/Windows 各跑一遍 lock。pip-tools 和 Poetry 都是按平台分别锁。
- 单二进制接管整条链路：自己下载并管理 CPython/PyPy（基于 python-build-standalone 的预编译解释器，相当于把 pyenv 的活干了），能跑带 PEP 723 内联依赖声明的单文件脚本，还提供 uv pip 这层 pip/pip-tools/virtualenv 的兼容命令。
- Cargo 风格的 workspace，多包仓库共享一个锁文件和虚拟环境，对应 Rust 开发者熟悉的组织方式。

**适用场景**: Python 后端和数据团队把 CI 里的 pip install 换成 uv pip sync，构建时间从几分钟压到几十秒；本地开发用 uv add/uv lock/uv sync 代替 Poetry。 需要频繁切换 Python 版本的开发者用 uv python install 3.12 3.13 和 uv python pin 顶替 pyenv；写一次性脚本的人用 PEP 723 在文件里声明依赖，直接 uv run 跑，不污染环境。

**竞品对比**: 对比 pip：没有锁文件和项目管理，但 uv 保留了 pip 兼容命令，迁移成本接近零。对比 Poetry/PDM：两者都是 Python 写的，启动和解析慢，Poetry 锁文件按平台分；uv 是静态二进制，冷启动快一个量级。对比 conda：不在同一生态，但抢的是"环境管理"这块心智。最大差异是速度加一个工具覆盖全链路。

**成熟度**: 生产可用：版本已接近 1.0，Astral 官方（Ruff 同一个团队）维护，文档完整，大量公司已在 CI 里使用。

**趋势信号**: uv 正从"更快的 pip"变成 Python 生态的默认安装入口：越来越多框架文档和教程直接写 uv 安装，加上临近 1.0 的稳定版节奏，持续带来新 star。

### [solidjs/solid](https://github.com/solidjs/solid)

 `TypeScript` ⭐ +40 今日新增 · 36,689 总星数

> SolidJS 2.0 重写：把响应式内核拆成独立包，JSX 直接编译成真实 DOM 操作，不做虚拟 DOM diff；同时加入异步、乐观更新原语，还随包发 LLM 提示文件。

**亮点**

- 彻底没有虚拟 DOM：编译产物直接持有 DOM 节点引用，状态变化只改对应那一个节点，省掉 diff 这一步

**核心功能**

- JSX 在构建期被编译成 template\(\)/insert\(\) 等真实 DOM 调用，组件函数只运行一次，更新粒度到单个表达式而不是整棵组件树重渲染
- 响应式原语抽成独立包 @solidjs/signals（signal/memo/effect/store），和渲染器解耦，配 @solidjs/web、@solidjs/universal 可换成非 DOM 目标
- 计算可以返回 Promise 或 AsyncIterable，用 &lt;Loading&gt; 做异步边界；更新默认在微任务里批量刷新，需要同步时调 flush\(\)
- 新增 createOptimistic / createOptimisticStore 和 action\(\) 结构化变更，把乐观 UI 做成框架原语而不是手写状态回滚
- 编译器换成基于 Oxc 的原生 JSX 编译器（@solidjs/compiler），Babel 插件降级为备选

**适用场景**: 面向嫌 React 重渲染开销大、又不想换 Svelte 语法的前端团队；典型场景是数据密集的仪表盘、低端设备上的交互页面，以及要用同一套组件同时输出 Web 和自定义渲染目标（如终端、Canvas）的项目。

- stitch::extract-static-html 会去抓本地跑着的 Web 应用页面，把 CSS 和图片内联成一个自包含 HTML 文件，再交给 Stitch 当设计输入——相当于给「已有代码、没有设计稿」的项目补一份可编辑稿
- stitch::react-components 和 react-native 把 Stitch 屏幕转成 React 组件或 RN StyleSheet，转换时做自动校验和 design token 一致性检查，还支持「同步到 Stitch 项目最新版本」的增量更新，不是一次性生成
- DESIGN.md 是设计系统的中间载体：extract-design-md 从源码里扫出设计规范写成 DESIGN.md，manage-design-system 再把它上传回 Stitch 应用成主题，设计和代码两头能对着改

**适用场景**: 前端团队和独立开发者：手上有 React 项目但设计稿丢了，想反向生成稿子做改版评审；或者反过来先用一句话让 Stitch 出几版移动端界面，再直接落成 React/React Native 代码。需要先配好 Stitch MCP 服务器和账号。

**竞品对比**: 对标的不是 Figma 官方 Dev Mode MCP 那种「从设计稿读数据」，也不是 v0、Builder.io Visual Copilot 那种绑定自家平台的出码，而是把设计稿生成和出码都做成可搬运的 skill，谁家 agent 都能挂。最大差异是设计源用的是 Google Stitch 而不是 Figma。

**成熟度**: 早期项目：本质是技能集合，没有版本号和稳定 API，skill 之间有互相依赖，README 自己都提示文档链接会跳错、OpenCode 要手工改目录名，上生产前得自己踩一遍。

**趋势信号**: Agent Skills 这个开放标准最近被 Codex 插件市场、Claude Code skills 等一批 coding agent 同时接纳，Google Labs 趁这个窗口把 Stitch 的设计能力做成 skill 分发，赶上了「设计→代码」这条链被 agent 接管的时间点。

### [NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator)

 `Python` ⭐ +312 今日新增 · 3,895 总星数

> NVIDIA 出的 AI Agent 技能评测框架。分三档检查技能包的规范、安全、重复度，以及技能对 agent 任务结果的实际影响，可以直接接进 CI。

**亮点**

- 把技能当作软件制品来做回归测试：同一套任务集分别在有技能和无技能的条件下各跑一遍，用通过率差值量化这个技能到底有没有用，而不是让模型给单次输出打个印象分。
- 先静态后动态的分层取舍：不需要花 token 的那一层先挡掉大部分低级问题，只有需要语义比对和真跑 agent 时才要求 NVIDIA Build key 和 Docker，因此小团队也能零成本接入。
- 除了被评测的对象，它自己也做成了一个技能，用 `npx skills add NVIDIA/SkillEvaluator` 装进 Claude Code，然后在对话里问一句就能跑。

**核心功能**

- 分三档执行：Tier 1 是纯静态检查，包含 500+ 条规则和检测模式，不需要 LLM key、Docker 或 GPU；Tier 2 用 embedding 做技能之间的语义重叠检测，并合成评测数据集；Tier 3 启动 Docker 跑真实 agent，对比“带技能”和“不带技能”两种跑法的任务通过率，算出 skill lift。
- Harness Check 按各家 agent 的真实加载规则做模拟：比如 Claude Code 不扫描 .agents/skills 目录，description 超过 1024 个 UTF-16 单元就会被截断。它直接输出一张表，说明 codex、claude-code、opencode、copilot-cli 等谁能加载、谁加载失败，并给出失败原因。
- 安全与代码完整性检查串联了现成扫描器：SkillSpector、Gitleaks、Bandit，Semgrep 可选，另外还有 PII、许可证、Unicode 同形字符、脚本 lint。`skillevaluator ci init` 会自动往你的仓库提交一个 setup PR，并带上 GitHub 或 GitLab 的复用模板。

**适用场景**: 适合给 Claude Code、Codex、Copilot CLI 写 Agent Skills 的团队和技能市场维护方。在 PR 阶段自动拦截这些情况：描述超长导致技能根本不被加载、捆绑文件里泄露密钥、两个技能语义重复、技能实际上没提升任务通过率。

**竞品对比**: promptfoo、LangSmith、DeepEval、Inspect AI 这些评的是模型或 prompt 的输出质量；SkillEvaluator 评的是技能包这个制品本身，包括规范、能否被加载、是否安全、是否和别的技能重复。针对 agentskills.io 规范做加载兼容检查的，目前基本没有同类。

**成熟度**: NVIDIA 官方维护，文档在 docs.nvidia.com，有 arXiv 论文和 PyPI 包，Tier 1 可以放心当 CI 卡口用；但整体仍是 0.x 早期，Tier 2/3 依赖 NVIDIA Build key 和 Docker，接口和评分可能随版本变动。

**趋势信号**: Anthropic 的 Agent Skills 规范让技能仓库数量快速增加，NVIDIA 把这项评测接入自己的 Verified Skills 认证管线，想要给生态定质检标准；再加上一键 CI 模板降低了接入门槛，正好处于技能数量爆发、质量却没人管的窗口期。

### [nvm-sh/nvm](https://github.com/nvm-sh/nvm)

 `Shell` ⭐ +237 今日新增 · 96,192 总星数

> 用纯 bash 脚本管理多个 Node 版本，按终端切换 PATH，没装 Node 也能一键装起来。多项目要锁不同 Node 版本时，它仍是默认选择。

**亮点**

- 刻意不做成二进制转发器，而是 shell 函数改 PATH。代价是不支持原生 Windows（只能走 WSL），换来零运行时依赖，且在 sh/dash/ksh/zsh/bash 上都能跑
- install.sh 会自己判断该写 ~/.bashrc 还是 ~/.zshrc 还是 ~/.profile；设 PROFILE=/dev/null 就不动配置，交给 oh-my-zsh 的 nvm 插件管，避免重复 source

**核心功能**

- 纯 POSIX shell 实现（一个 nvm.sh + 一个 install.sh），不依赖 Node/npm/Python，所以机器上还没有 Node 时也能 curl | bash 直接装
- 不装成可执行文件，而是把 $NVM_DIR/versions/node/vX/bin 前置进 PATH。切换只在当前终端会话生效，开两个窗口能同时跑 Node 20 和 Node 22，互不干扰
- 靠 .nvmrc 文件声明项目版本，再挂 shell hook（zsh 的 chpwd、bash 的 PROMPT_COMMAND）实现进目录自动 nvm use，省掉手动切版本
- nvm install --reinstall-packages-from=20 能把全局包从旧版本整批搬过去；NVM_NODEJS_ORG_MIRROR 可以换成国内镜像下载二进制

**适用场景**: 前端和 Node 后端开发者手上同时有几个项目，老项目卡在 Node 18、新项目要 Node 22，靠它在一个终端里切；CI 的 Docker 镜像里也常这么用：设 BASH_ENV 指向 profile，非交互 shell 里照样能 nvm install 固定版本。

**竞品对比**: 比 n（Rust/Go 写的二进制，装到 /usr/local 要 sudo，全机器只有一个版本）更隔离；比 fnm（Rust、启动快、原生支持 .nvmrc 自动切换）慢——每个新 shell 都要 source 一大坨 bash；比 volta（锁项目工具链全套）专注面更窄，但兼容性和踩坑文档最全。

**成熟度**: 生产可用，十几年的既成标准；版本号停在 v0.41.0 从没到 1.0，但 CI 测试矩阵覆盖多平台多 shell，文档连 Alpine、WSL、macOS 的坑都写了。

**趋势信号**: 近期发布 v0.41.0，又赶上 Node.js 大版本/LTS 切换，一批项目要同时锁几个 Node 版本，nvm 被重新翻出来查。

## 趋势观察

今天这份榜单，主角只有两个：Agent，和它的工具包。 Cursor 一次放出 40 多个插件，用一个 plugin.json 就把技能指令、CLI、SaaS 接口打包成 Agent 能直接调用的东西。Google Labs 把 Stitch 拆成 Agent Skills。NVIDIA 出了评测框架，专门检查技能包规不规范、安不安全、有没有用，还能接进 CI。还有给 Agent 加统一记忆和安全层的、给 Agent 装开发方法论的、把桌面软件裹成 JSON 命令行绕开 MCP 部署成本的。这些项目说的是同一件事：Agent 的技能，正在从随手写的提示词，变成有清单、有标准、有评测、有分发渠道的软件包。谁拿下插件市场，谁就是下一个应用商店。 MCP 索引仓库和自托管后端平台也在榜上，说明大家不想被单个厂商锁死，数据、模型、工具都想留在自己服务器上。n8n 涨得快，也是这个逻辑。 另一条线是工具链在重写。Rust 版的 Python 包管理器、用 bash 管 Node 版本、Svelte 5 用 runes 重做响应式、SolidJS 2.0 拆内核还顺手塞个 LLM 提示文件、jQuery 4.0 终于删掉 IE 兼容代码。老东西没死，是在换发动机。OpenVINO 火，是 AI PC 和本地推理真的来了。 还有个反差：一份纯前端的中国历史地图冲到榜首。满屏 Agent 里，它提醒大家，好项目不一定非得跟 AI 沾边。 一句话收尾：这一波不是模型变强了，是模型外面那层壳——技能规范、分发入口、评测、自托管——正在被迅速搭起来。
