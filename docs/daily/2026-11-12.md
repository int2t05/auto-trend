### [shadcn/improve](https://github.com/shadcn/improve)

 ⭐ +361 今日新增 · 11,170 总星数

> shadcn 出的 Agent 技能：用最贵的模型审计代码库并写出实施计划，交给便宜的模型照着执行。它只产出计划，不改代码，核心卖点是把 token 花在「想」而不是「干」上。

**亮点**

- 明确的「顾问/执行者」分层：贵模型只做读代码、判断优先级、写规格这类智力复利高的部分，写代码交给便宜模型。这个成本模型比单纯堆更强的 Agent 更贴近实际账单
- 计划里塞了机器可验证的验收门（命令 + 期望输出），执行者不需要自己判断「我做完了没」，也不需要理解全貌——这是让小模型能干成大活的真正关键
- 会读取仓库已有的 ADR / PRD / CONTEXT.md / DESIGN.md，把已经拍板的取舍当成既定前提，不再当成问题重提；同时保留「拒绝清单」，避免同一批误报反复出现

**核心功能**

- 审计阶段按 9 个类别（正确性、安全、性能、测试覆盖、技术债、依赖迁移、DX、文档、方向建议）并行开子 Agent 扫描，每条发现必须带 file:line 证据、影响面、工作量和置信度，不允许「泛泛而谈」的结论
- 有个「复核」环节：子 Agent 容易误报，所以顾问模型会把每条被引用的代码位置自己再读一遍，删掉假阳性、修正错误定位，并把被否掉的项连同理由记下来，下次不再重复提
- 计划按「最笨的可能的执行者」来写：上下文全部内联（精确路径、现状代码片段、仓库自己的 build/test/lint 命令），每一步附验证命令和期望输出，外加 out-of-scope 清单和 STOP 条件（情况不符就停下上报，别自由发挥）
- 每份计划盖上撰写时的 git commit，执行前做一次机械式的漂移检查；execute 会在独立的 git worktree 里跑便宜模型，然后像 tech lead 一样重跑所有 done 判据、核对改动范围，最多打回改 2 轮

**适用场景**: 适合已经在用 Claude Code / Cursor / Codex 等 Agent 的团队和个人开发者：中大型仓库想系统性清技术债、补测试、查安全问题，但不想让贵模型一步步写代码。也适合想用便宜模型（或本地小模型）批量干活的团队，先把活儿拆成可验证的工单再分发。

**竞品对比**: 和 GitHub spec-kit、BMAD、Taskmaster 这类「先写规格再实现」的工具有重合，也和 Claude Code 的 plan mode、Aider、Cursor 的 Agent 流程有交集。最大差异是它对模型能力做了显式的贵贱分层，并且把「评审执行结果、回写 backlog」做成了闭环命令（execute / reconcile / --issues），而不只是生成一份 markdown。

**成熟度**: 早期项目，刚发布就冲上 trending，作者是 shadcn（shadcn/ui 作者）有信誉背书；但因为只往 plans/ 目录写文件、不改源码，试错成本低，副作用可控。

**趋势信号**: 踩中两个当下热点：Agent Skills 格式（agentskills.io）正在被各家 Agent 采纳，以及团队对「贵模型跑 Agent 烧钱」的成本焦虑；再加上 shadcn 本人发布，自带分发。

### [GoogleChrome/modern-web-guidance-src](https://github.com/GoogleChrome/modern-web-guidance-src)

 `TypeScript` ⭐ +159 今日新增 · 2,005 总星数

> Chrome 团队把现代 Web API 的正确写法做成 Agent 技能包，用 CLI 按需注入编码助手的上下文，让 AI 少写老式臃肿 JS。最近 Agent Skills 概念走红，加上四大浏览器厂商联合背书，所以冲上热榜。

**亮点**

- 由 Chrome、Edge、Firefox、MDN 四个团队共同维护，指南不是单一浏览器的立场，跨浏览器兼容建议相对可信
- 把"给 Agent 补领域知识"做成可评测、可裁剪的内容工程，而不是堆一整本手册塞进 prompt，这是上下文管理上的实际取舍

**核心功能**

- 指南内容存成 Markdown，通过 `search` 语义检索和 `retrieve` 按 ID 取回，只把相关段落塞进 Agent 上下文窗口，不一次性灌满 prompt
- 用评测仪表盘反向裁剪内容：跑 eval 找出模型本来就会的知识直接删掉，只保留模型经常写错的 API 用法，用评测数据来控制 token 预算
- `legacy-scan` 子命令扫描本地代码库，定位过时写法（老式弹窗、手写 polyfill 等），给出对应的原生替代方案
- 覆盖 250 个平台特性，覆盖范围从 CSS 容器查询、oklch、subgrid，到 Popover API、锚点定位、View Transitions、scheduler.yield
- 每条特性都关联 web-features 的 Baseline 兼容数据，让 Agent 写"能用的地方用原生、不能用的地方加轻量 fallback"，而不是无脑堆 polyfill

**适用场景**: 用 Claude Code、Cursor、Copilot 写前端的开发者，尤其是接手老项目、想让 Agent 把 jQuery 时代代码换成原生 API 的团队；也适合制定前端规范的 Tech Lead 把指南固化进团队工作流。

**竞品对比**: 和 Context7 这类给 LLM 喂最新文档的 MCP 工具不同，它提供的是经过评测筛选的"实现范式"，并附带 legacy 代码扫描；MDN 是写给人读的参考文档，这份是写给编码 Agent 读的技能包。

**成熟度**: 早期项目，通过 `npx @latest` 安装、接口还可能有变动，虽有四大厂商背书和文档站，可以先在个人或试验性流程里用，不建议直接绑死生产流水线。

**趋势信号**: 2025 年底 Agent Skills 和上下文工程成为热点，Chrome 团队把"给编码 Agent 注入现代 Web 知识"做成标准技能包，正好赶上这波节奏。

### [openai/codex-security](https://github.com/openai/codex-security)

 `TypeScript` ⭐ +52 今日新增 · 11,938 总星数

> OpenAI 把 Codex 做成安全扫描 CLI 和 TypeScript SDK：扫仓库找漏洞，验证真假，直接出补丁，还能导出 SARIF 接入 CI。

**亮点**

- 核心取舍是拿 LLM agent 替代规则引擎：慢、贵、结果不完全确定，但换来了能读懂业务语义、能给修复代码，这是 Semgrep 那类工具做不到的。
- 扫描口径来自项目自己的 SECURITY.md 和威胁模型，而不是一套通用规则库，所以同一个工具在不同仓库关注点不一样。

**核心功能**

- 扫描分 Standard 和 Deep 两档：Deep 会重跑一遍 Standard 再合并去重，可用 --max-time 限制单次调查时长来控制 API 花销。
- 不只是报告漏洞：对候选发现做二次验证降误报，生成 patch，还能回头验证一个已有修复到底修没修好。
- 能读取仓库自己的 SECURITY.md 和保存的威胁模型当扫描上下文，并按源码和 Git 提交历史推断每个漏洞该派给谁修。
- 能导入第三方扫描器的结果，也能导出 SARIF/JSON/CSV，或推到 Linear、Jira、GitHub Issues，官方给了周更的 GitHub Action 示例。

**适用场景**: 安全工程师和平台团队把它放进 CI 做仓库周扫、PR 门槛检查；开发也可以直接在 Codex 会话里让 agent 扫自己仓库并顺手出补丁。

**竞品对比**: 对手是 Semgrep、Snyk Code、GitHub CodeQL 这类靠规则和数据流引擎的工具，它们快且结果稳定，但要人肉筛误报；Codex Security 用 LLM 推理加验证和出补丁，代价是慢和贵，反而可以把这些工具的 SARIF 结果吃进来做二次验证。

**成熟度**: 刚发布的新项目，文档齐全但明显是预览阶段：需要 Node 22.13+/Python 3.10+、要 API key，部分网络安全相关请求还要走 ChatGPT 的 Cyber access 白名单，上生产前得先小范围试。

**趋势信号**: AI 编程 agent 大量产码之后，安全审查成了瓶颈，加上 Anthropic 的 Claude 代码安全审查、GitHub Copilot Autofix 这一波竞争，OpenAI 直接把 Codex 做成 CLI 和 SDK 来占这块位置。

**成熟度**: 成熟稳定，6.7 万星、长期高频提交、CI 覆盖率与 Discord 社区齐全，但定位是教学示例，不建议直接搬进生产代码。

**趋势信号**: 没有单点事件，属于长期爬坡的教育类仓库，在面试准备季和 Hacktoberfest 这类开源贡献季会周期性多拿星。

**亮点**

- swizzle 能把任意组件的完整源码 eject 到项目里，底层 building block 也直接导出。等于说默认用 npm 包，真要改到底层就摊开源码自己维护，不用和上游 API 打架。

- 样式用 StyleX 在编译期生成原子 CSS，但对外只发预编译 CSS + 带类型的 React 组件。用的人不用装 StyleX 构建插件，不用配 PostCSS/Babel，想覆盖样式直接用 className 写 Tailwind、CSS Modules 或普通 CSS。

**适用场景**: 适合中大型 React 19 前端团队和内部设计系统团队：既要品牌定制、又不想被组件库的样式方案锁死；也适合已经在用 AI 编码助手生成界面、需要 agent 能准确查到组件 API 的团队。

**竞品对比**: 和 MUI、Ant Design 比，最大差别是主题走 CSS 变量、不用 wrapper 也不用深挖 theme override；和 shadcn/ui 比，shadcn 默认把源码复制进项目，Astryx 默认是正常发 npm 包、需要时才 swizzle。

**成熟度**: 公开版还在 Beta（版本低于 1.0），但内部已经跑了八年、13000+ 应用在用，文档、Storybook、沙箱都齐；公共 API 仍可能调整。

**趋势信号**: Meta 首次把内部最大的设计系统对外开源，而且直接打出 agent ready 的旗号，正好赶上 AI 编码助手大规模写前端这波；React 19 + StyleX 又都是 Meta 自家栈，顺手一起推。

### [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)

 `JavaScript` ⭐ +787 今日新增 · 116,164 总星数

> 它把资深工程师的开发流程——写规格、拆任务、TDD、评审、上线——打包成 25 个能被 AI 编码 Agent 自动加载的技能文件，一条 npx 命令装进 70+ 种 Agent。

**亮点**

- 把“流程”拆成按目录组织的技能包，Agent 按需加载单个技能文件，而不是把所有规则一次性放进上下文。这是 Anthropic Agent Skills 规范的核心取舍：用目录约定换取上下文节省，也让技能可以独立分发。
- README 自己披露了一个当前还没解决的关键问题：单独装某一个技能时，只会复制 skills/&lt;name&gt;/ 目录，仓库级的 references/ 共享检查清单不会一起带过去（issue #361）。这说明在多 Agent 生态里，“技能包如何跨平台移植”还没定论，作者选择直接说明，而不是掩饰。

**核心功能**

- 25 个技能全是纯 Markdown 文件（SKILL.md + YAML frontmatter 描述触发条件），Agent 按当前动作自动加载对应那一个。比如设计接口就触发 api-and-interface-design，写前端 UI 就触发 frontend-ui-engineering，不用手动 @。
- 9 个斜杠命令直接对齐开发流程的六个阶段：/spec 先写规格再写码、/plan 拆成小任务、/test 强制红-绿-重构、/review 按五个维度审、/webperf 先测再优化、/ship 上线。每个命令背后绑定一组技能，等于把流程固化成按钮。
- /build auto 把“生成计划”和“逐个任务实现”合并成一次审批后的自动执行：计划只批一次，之后每个任务仍然单独跑测试、单独 commit，遇到失败或高风险步骤自动停下来。它省掉的是任务之间的人工确认，而不是验证环节。
- 通过 Vercel 的 skills CLI（npx skills add）统一分发，一次装进 Claude Code、Cursor、Codex、Copilot、Gemini CLI、Cline、Windsurf、OpenCode 等 70+ 种 Agent；Claude Code 那边还额外支持插件市场安装。

**适用场景**: 用 Claude Code、Cursor 这类 AI 编码工具写业务代码的工程师。典型场景是：Agent 一上来就狂写代码、不写测试也不问需求。装上这套技能后，Agent 会被推着先出规格、再拆任务、每步跑测试，最后过一道评审门禁。 技术负责人或平台团队。他们想把团队的质量标准统一到每个成员使用的 AI Agent 里：用 /constraints 定义一次规则，所有 Agent 都按这个规则执行，不必每个人自己写 prompt。

**竞品对比**: 和 obra/superpowers、各种 awesome-claude-skills 清单比，大多数是零散的 prompt 片段或大杂烩列表；这套是有明确六阶段流程、能自动触发、带质量门禁的成套技能，且作者 Addy Osmani 是 Chrome 团队 Web 性能方向的人，/webperf 那部分是他的本行，不是临时拼凑的。与厂商官方 skills 相比，它更偏重“流程约束”，而非“工具封装”。

**成熟度**: 早期项目，还在 1.0 之前，存在已知缺陷（#361 的单技能安装不完整），但文档覆盖 8 种以上 Agent 的安装方式，Claude Code 插件市场已验证可用，社区提交和 issue 响应活跃。

**趋势信号**: 直接受益于 Anthropic 2025 年 10 月推出 Agent Skills 规范和 Claude Code 插件市场推广：开发者圈子正从“给 Agent 写 prompt”转向“给 Agent 装可分发技能包”，它是最早把这套理念做成完整工程流程体系的项目之一，加上 Addy Osmani 本人的关注度。

### [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)

 `Rust` ⭐ +708 今日新增 · 50,050 总星数

> Vercel Labs 出的 Rust CLI，给 AI agent 一个能用单条 shell 命令操控的浏览器：页面读成带 ref 的文本，点完再读，浏览器状态留在常驻 daemon 里。

**亮点**

- 故意把失败做实：click 遇到目标隐藏、禁用、在视口外、或被 cookie 横幅挡住时直接报错而不是返回成功，逼 agent 重新 snapshot 再试。这是专门防 LLM 幻觉式“我以为点到了”的设计
- 命令是一次性短调用，浏览器状态全留在 daemon 里（keep-alive），agent 不需要维持长连接、也不需要生成一整段 Playwright 脚本，单步失败不影响下一步

**核心功能**

- 页面不返回 HTML，返回可访问性树（浏览器给屏幕阅读器用的结构化页面描述）压成的紧凑文本，每个可交互元素挂一个 @e1 这样的 ref，agent 只需 click @e1，不用生成 CSS 选择器；导航或 DOM 变了就得重新 snapshot，ref 会失效
- Rust 写的 CLI 加一个后台常驻 daemon，首次命令时启动，通过 CDP（Chrome DevTools Protocol，Chrome 自带的调试接口）控制浏览器；每个 --session 独立 daemon 和独立浏览器，空闲一小时自动存状态再关掉
- 内置 skills 子命令：agent 跑 agent-browser skills get core 拉取和当前 CLI 版本绑定的操作说明，装到 agent 里的只是个薄壳 stub，所以文档永远不会比二进制旧；同时提供 agent-browser mcp 走 stdio 当 MCP server 用

**适用场景**: 写 coding agent / 终端 agent（Claude Code、Codex 这类）的人，需要 agent 自己去登录后台、填表单、抓登录后才能看的数据；也适合做端到端冒烟测试的 QA，直接用 shell 脚本串起来跑。

**竞品对比**: 同类有 Microsoft 的 playwright-mcp、browser-use、Stagehand。最大差异是它不做库也不只是 MCP：本质是个语言无关的 CLI + daemon，agent 用 shell 调用即可，且把快照压缩成 ref 文本而非整棵 a11y 树或坐标，省 token。

**成熟度**: Vercel Labs 实验项目，Apache-2.0，已有 npm/brew 和 macOS/Linux/Windows 原生二进制、完整文档站，但命令面很宽（trace、profiler、dashboard 都在内），API 仍可能变，别当稳定依赖。

**趋势信号**: 终端里的 coding agent（Claude Code、Codex CLI）这半年成为主流，它们能调的工具只有 shell，Vercel Labs 顺势把一个“shell 可调用的浏览器”做成标准件，同时接上 skills.sh 和 MCP 生态。

**竞品对比**: 同类有 mcp-home-assistant、hass-mcp 等第三方 MCP server，也有 HA 官方自带的 Assist/OpenAI Conversation 集成。差别是 ha-mcp 工具数量最多（87 个）且能写配置，官方 Assist 主要是语音助手对话，不负责改自动化。

## 趋势观察

今天的热榜几乎只有一个关键词：给 AI 打工。 Agent Skills 这个词正在刷屏，Chrome 团队把 Web API 的正确写法做成技能包，shadcn 把「贵模型规划、便宜模型执行」做成了产品，还有人把资深工程师的流程拆成 25 个技能文件，一条 npx 装进 70 多种 Agent。Meta 开源设计系统时，干脆把文档同时写给人和 AI 看。 一个共同判断正在成形：AI 编码的瓶颈不是生成代码，而是上下文和流程。所以大家忙着给 Agent 修路。Vercel 给浏览器套上一条 shell 命令，Home Assistant 把 87 个操作包成 MCP 工具，OpenAI 把 Codex 做成能扫漏洞、能出补丁的 CLI。工具不再面向人点鼠标，而是面向 Agent 调接口。 另一条线是「自己的东西自己管」。财务应用 Maybe 被社区接手做自托管，算法仓库继续靠分类和测试吃老本。开源正在从「给你代码」变成「给你一套能跑起来的能力」。 热闹归热闹，真正的分水岭还没到。技能包谁都能写，难的是验证：计划写完能不能落地，工具接上会不会出错。下一轮比拼，大概率不是谁的 Agent 更聪明，而是谁的工程约束更硬。
