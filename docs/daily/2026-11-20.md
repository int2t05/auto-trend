今日共收录 **16** 个 GitHub Trending 项目。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +825 今日新增 · 204,542 总星数

> Firecrawl 把网页抓成 LLM 能直接吃的 Markdown。现在多了 Rust 单文件本地版和一键 MCP 接入，抓不动的页面回落云端，还聚合了 550+ 数据源。

**亮点**

- 本地版和云端共用同一套 API 和 SDK，只在能力上分层（结构化 JSON、Interact、Agent 留给云端），迁移成本几乎为零，这是它区别于纯 SaaS 抓取服务的关键取舍
- Alexandria 把 550 多家数据提供商收敛到一个 API 后面，卖点从「抓网页」扩成「给 agent 喂知识」，顺便解决了纯爬虫覆盖不到的数据

**核心功能**

- 本地版是 cargo 装的一个 Rust 二进制，不要数据库、队列、容器；JS 渲染直接借用机器上已有的 Chrome/Chromium，PDF 和 Office 文档也在本地解析
- `firecrawl-local init` 自动探测 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 的配置文件，先备份再写入 MCP server 配置，重启后 agent 就能调 scrape/crawl/map
- 本地 `serve` 在 3002 端口复刻 v2 API，现有 SDK 改个 api_url 就能跑；本地渲染失败的页面自动转云端抓，结果里标 `source: firecrawl-cloud`，设 FIRECRAWL_CLOUD=off 可以彻底不出网

**适用场景**: 给 AI agent 或 RAG 管线找网页语料的开发者：在 Claude Code、Cursor 里让 agent 直接读文档站；或者数据不能出内网、需要自托管队列和 worker 的团队。

**竞品对比**: 同类有 Jina Reader、Crawl4AI、Apify、Tavily/Exa。最大差异是既能本地跑单二进制又能托管，API 和 SDK 完全一致；Alexandria 的多数据源聚合别家基本没有。

**成熟度**: 生产可用，v2 API 和 Python/Node SDK 已稳定，云端有付费用户和性能 benchmark；Local 是较新的组件，接口可能还有调整。

**趋势信号**: Claude Code、Cursor 这类 agent 工具普及后，MCP 成了事实标准，Firecrawl 顺势推本地 MCP 一键接入加 keyless 每月 1000 次免注册额度，正好卡在「给 agent 喂干净网页上下文」这个刚需上。

**适用场景**: 独立开发者或小团队用 Claude Code、Cursor 这类工具快速做完 App，准备提交 App Store 或 Google Play 前跑一遍扫描；也适合被拒后查原因、写申诉的产品和运营人员按清单逐条核对。

**竞品对比**: fastlane 的 precheck 只校验 iOS 的元数据和截图，AppFollow、Runway 偏发布后监控；这个覆盖 iOS + Android 双端、给的是可执行脚本加 AI agent 钩子，还额外管法规截止日期，差异在“给 agent 用”和“合规时效”。

**成熟度**: 早期项目，无版本号，主体是 Shell 脚本加文档，单作者维护；README 和 CI 都齐全，但规则要人工跟官方政策走，可能滞后。

**趋势信号**: AI 编码工具让随手做出来的 App 扎堆提交、拒审率上升，同时 EU AI Act 等合规截止日期临近，开发者需要一个提交前的自动拦截器。

- 暴露 aria2 兼容的 RPC 接口，第三方工具（如 AriaNg、命令行脚本）可以直接把它当 aria2 用；下载中途还能改 URL、请求头、代理而不丢进度

**适用场景**: 适合经常需要从 Bilibili、YouTube、HuggingFace、GitHub Release 拉资源的开发者、AI 模型玩家和内容搬运工；也适合想把 IDM + qBittorrent + N_m3u8DL 三件套合成一个的普通用户，Android 端还能录直播流。

**竞品对比**: 最直接的对手是 Gopeed（Go + Flutter，同样主打全协议跨平台），以及 IDM、Motrix、N_m3u8DL-RE 这类单点工具。差异在于它多了浏览器扩展嗅探 + 登录态透传，以及 aria2 RPC 兼容这个迁移钩子，能直接顶替老 aria2 前端。

**成熟度**: 基本可日常使用：四端都有签名安装包、文档站、Crowdin 翻译流程和 QQ/Discord 社区，但插件（Feature Packs）API 还没公开，说明扩展生态仍在定型期。

### [toeverything/AFFiNE](https://github.com/toeverything/AFFiNE)

 `TypeScript` ⭐ +182 今日新增 · 75,337 总星数

> AFFiNE 是开源的「Notion + Miro」二合一知识库：文档和无限画布共用一套 block 数据，本地优先、可自托管，最近靠 AI 功能和自托管需求重新上榜。

**亮点**

- 文档和画布不是两个功能拼在一起，而是同一份数据的两种视图——这是它和「Notion 里嵌一个白板插件」类方案最本质的区别
- 用 CRDT 做本地优先同步，把「离线可用」和「多人实时协作」这两个通常互斥的需求同时满足了，代价是数据模型和迁移会比纯云端方案复杂

**核心功能**

- 所有内容都是 block：同一棵 block 树既能以文档模式（像 Notion 的纵向排版）渲染，也能以无边界画布模式（像 Miro）渲染，富文本、便签、嵌入网页、数据库、形状、幻灯片都能拖到画布上，不用在两套数据之间同步
- 本地优先 + CRDT 协同：用 CRDT（一种让多人离线改同一份文档也能自动合并、不用服务器仲裁冲突的数据结构）做实时同步，数据先落本地磁盘，断网编辑后联网自动合并，同时支持 Web 和桌面端协作
- 编辑器内核拆成独立项目 BlockSuite，AFFiNE 只是它的一个上层应用；第三方可以基于 BlockSuite 自己搭编辑器，这也是他们做插件生态的铺垫

**适用场景**: 适合不想把笔记和资料交给 Notion/Miro 云端的个人和小团队，尤其是需要「写文档 + 画白板 + 排看板」在同一页面完成的场景；也适合有内网合规要求、要用 Docker 自建知识库的公司 IT/研发团队。

**竞品对比**: 对 Notion 是「开源 + 自托管 + 原生画布」，对 Miro 是「白板旁边就能写结构化文档」；另一个常被拿来比的是 AppFlowy（开源 Notion 替代，Rust + Flutter），但 AppFlowy 的画布能力弱，AFFiNE 主打的是两者合一。

**成熟度**: 主版本号仍在 0.x，桌面端日常可用、文档和自托管教程齐全、社区活跃，但数据模型和 API 还在演进，不建议在关键业务上单点依赖。

**趋势信号**: Notion、Miro 等闭源工具持续涨价并把 AI 功能放进付费墙，推动一波用户转向可自托管、数据留在本地的开源替代，AFFiNE 正好卡在这个位置上。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +73 今日新增 · 32,414 总星数

> 老牌 Web 服务器和反向代理的官方源码仓库，用多进程加事件驱动扛高并发，现在是获取 NGINX 官方代码的权威入口。

**亮点**

- 配置是一棵文本指令树，master 校验通过后平滑 reload：新 worker 起来接新连接，老 worker 把存量请求处理完再退出，全程不断连
- 用共享内存加 slab 分配器在多个 worker 之间共享状态，避免进程间加锁，这是它能在多核上横向扩展的关键

**核心功能**

- master 进程只读配置、管 worker，多个 worker 各自跑单线程事件循环（Linux 上用 epoll），一个连接一个状态机，不靠线程堆并发
- 模块分静态和动态两种：静态模块编译进二进制，动态模块是 .so 文件，运行时用 load_module 加载，加第三方模块不用重编整个 nginx
- worker 进程之间靠共享内存 zone 同步状态，限流计数、连接数、缓存索引都放在共享内存里，所以 limit_req 这类指令必须先定义一个 zone

**适用场景**: SRE 和运维拿它做 TLS 终结、反向代理和七层负载均衡；后端团队用它托管静态资源、做限流和缓存；K8s 集群里常作为 Ingress Controller 的底层。

**竞品对比**: 对手是 Caddy（自动申请 HTTPS 证书、配置更简单）、Envoy（xDS 动态下发配置，云原生场景常用）、Traefik（自动发现容器）。NGINX 胜在成熟度和模块生态，弱在配置是静态文件、改完要 reload，证书自动化也不如 Caddy 省事。

**成熟度**: 生产可用，全球装机量最大的 Web 服务器之一，稳定分支和 mainline 分支并行发布，文档完整。

**趋势信号**: 官方源码仓库从自建 Mercurial 迁到 GitHub 后成了唯一权威代码入口，主线版本又持续加 HTTP/3、QUIC 等新特性，star 自然往官方仓库集中。

> MiniMind 用 3 块钱 GPU 租金、2 小时在单张 3090 上从零训出 64M 小语言模型，全部训练代码用 PyTorch 原生手写，是给想搞懂 LLM 内部机制的人用的可复现教程。

**亮点**

- 故意放弃 transformers 的封装：连 LoRA、DPO 都手写，代价是代码量大、版本间不兼容，换来的是每个算法都能对着几十行代码看明白
- 把 MoE 从 shared expert 设计里拆掉，主线结构与 Qwen3-MoE 保持一致，让 200M 级别的玩具模型也能演示专家路由和负载均衡 loss

**核心功能**

- 预训练、SFT、LoRA、DPO、PPO/GRPO/CISPO、蒸馏全链路都自己实现，不用 transformers/trl/peft 的高层封装，只保留兼容接口，方便逐行读代码
- Tokenizer 用 BPE + ByteLevel 自训，词表里预留了 &lt;tool_call&gt;、&lt;tool_response&gt;、&lt;think&gt; 等标记位和 buffer token，Tool Call 和思考链直接从分词层面打通
- RLAIF 和 Agentic RL 把 rollout engine 解耦出来，生成后端可替换，支持多轮工具调用场景下的 GRPO / CISPO 训练；同时用 YaRN 做 RoPE 长文本外推
- 模型命名和结构对齐 Qwen3 / Qwen3-MoE 生态，Dense 64M、MoE 198M-A64M（激活 64M），因此能直接跑 llama.cpp、vllm、ollama 和 Llama-Factory

**适用场景**: 适合学生、转行工程师、高校教师，以及想在自己 3090/4090 上跑通全流程的小团队。典型用法：跟着仓库从 pretrain 训到 SFT，改写数据做垂直领域小模型（医疗、自我认知），或用自己训的模型给 Agent / Tool Call 流程做实验。

**竞品对比**: 同类有 Karpathy 的 nanoGPT（只覆盖 GPT 预训练）和 Stanford CS336 的 assignment。MiniMind 的差异在于覆盖 Pretrain→SFT→LoRA→RLHF→Agentic RL 全阶段，而且带中文数据和中文教程；代价是代码组织不如 nanoGPT 精炼。

**成熟度**: 教程型项目，67k star、迭代两年多、文档和训练曲线齐全，但每次大版本都明确声明不兼容旧模型权重，不适合直接上生产。

**趋势信号**: 2026-04-01 发布 minimind-3，结构换成对齐 Qwen3 生态，并新增原生 Agentic RL 训练脚本（GRPO/CISPO）和完整的 reasoning_content / tool_calls 推理接口，踩上了当下 Agent + 强化学习微调的热点。

## 趋势观察

今天这份榜单，几乎都在做同一件事：让 Agent 从会聊天变成会干活。 先看第一类，技能包。红队方法论、开发流程、画图品味、上架避坑手册，都被拆成一个个能加载的 skill 和插件。Agent 不用重新学，装上就能用。Cursor 干脆把插件做成官方规范，一个目录一个包，还能接 40 多个 SaaS。这说明生态开始分层：底层模型归模型，方法论归技能，各干各的。 第二类，给 Agent 装手脚。生成带测试的 CLI 封装，让 Agent 直接去点 CAD、3D、音频软件；Stitch 技能让代码和设计稿双向同步；Firecrawl 把网页变成模型能吃的 Markdown，还加了 MCP 接入。围墙花园被一根根打通，Agent 能碰的东西越来越多。 第三类，控制成本和控制风险。MiniMind 用 3 块钱、2 小时在单张 3090 上训出 64M 小模型；OpenVINO 让 LLM 直接在 AI PC 上跑；CI/CD Agent 和上架扫描脚本都强调自托管、自己的模型、代码不出门。大家不再盲目追大，开始算账、算合规、算授权范围。 连起来看：新闻热点从“模型多大”转向“Agent 怎么落地”。开发者生态在干三件事——把经验标准化，把接口统一化，把成本和安全捏在手里。MCP 这类协议正在变成事实标准，技能包成了新的分发单位。下一波竞争，不看谁模型大，看谁的 Agent 装得多、干得稳、管得住。
