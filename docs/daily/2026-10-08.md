### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +4,655 今日新增 · 17,072 总星数

> 把 Ghidra/Hopper、JADX、浏览器抓包统一成一个 MCP 服务，让 AI Agent 看中某个 App 的功能后，一路逆向到二进制并附上证据。

**亮点**

- 把入口定在'功能级逆向'而不是'整包反编译'：用户问的是'搜索是怎么实现的'，工具围绕这个问题去追调用链，而不是吐全量反汇编。
- 复用宿主环境做重活：原生分析用用户自己的 Hopper/Ghidra/IDA，Android 用 headless JADX，浏览器分析用本地 Chrome，样本不上传，全部本地跑。

**核心功能**

- 用 MCP（Model Context Protocol，让 AI Agent 调用外部工具的通用接口）把逆向工具挂给 Agent。它不自己写反汇编器，而是桥接用户已装的 Hopper、Ghidra 或 IDA，返回伪代码、汇编、字符串、符号和交叉引用。
- JS/Electron 走纯静态分析，不需要反汇编引擎：解开 ASAR 包，抽出模块、imports、source map、路由、IPC 通道和原生 addon 的对应关系。Android 则调 headless JADX，读出 Manifest、类、反编译方法和引用。
- 每条结论都带证据（命中的代码位置、引用）和局限说明，Agent 能顺着引用继续追问。设计上输出的是'这段功能怎么运作'，不是丢一堆汇编让模型自己猜。

**适用场景**: 独立开发者和产品团队看到别的 App（比如某 Electron 笔记软件的搜索）有个好功能，想让 Claude Code、Cursor 用 REA 查清实现方式再在自己项目里复刻一版；也适用于安全审计、竞品分析、接手无源码遗留系统的工程师。

**竞品对比**: GhidraMCP、IDA MCP 这类项目只包一个反汇编器。REA 用一个 MCP 同时覆盖原生二进制、JS/Electron、.NET 程序集、APK、网站和 HAR 抓包，并且强制输出证据链，这是最大差别。

**成熟度**: 早期项目，README 自己写着'REA changes quickly'并反复提醒更新，接口和 CLI 还在快速变动，暂不建议放进生产流程。

**趋势信号**: MCP 已被 Claude Code、Cursor、Codex、Gemini CLI 当默认插件协议，'npx xxx setup'一键接入的模式也跑通了，REA 正好踩在'把垂直专业工具塞给编码 Agent'这波上，一天涨 4600 星说明刚被集中传播。

### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5)

 `C++` ⭐ +2,716 今日新增 · 11,455 总星数

> AnyPS5 把 PS5 可执行文件重新链接成 Linux/Windows 原生程序，不放模拟器，让游戏直接在本机跑。走静态重编译路线，绕开 PS5 模拟器长期卡壳的难题。

**亮点**

- 遇到不支持或异常状态直接抛 std::runtime_error 并终止进程，不做容错降级。宁可崩掉也不静默跑出错误结果，方便快速定位兼容性问题
- 输入层用 SDL 统一映射手柄（含摇杆和扳机），键鼠走 anyps5-input.ini 配置文件，完全绕开 PS5 原生输入栈

**核心功能**

- relinker 把 PS5 可执行文件转成目标系统的原生格式（Linux 的 ELF / Windows 的 PE），不解释执行原指令，游戏代码直接跑在本地 CPU 上
- 用自己实现的 system prx 库替换 PS5 的系统共享库（prx 是 PS5 的动态链接库格式），游戏调用系统函数时直接落到这些原生实现上，而不是转发给模拟层
- shader recompiler 把 PS5 的 GPU 着色器翻译成 SPIR-V，可选接 Spirv-Tools 做校验，再交给 Vulkan 执行，等于把主机着色器转成 PC 显卡能吃的格式

**适用场景**: 想在 PC 上玩 PS5 游戏、又不想等模拟器成熟的玩家，以及做主机游戏保存和逆向的研究者、自制移植团队。

**竞品对比**: 和 RPCS3、PCSX2 这类模拟器路线完全不同：模拟器要模拟硬件行为、逐条处理指令，AnyPS5 是静态重链接，性能开销小得多。和 N64: Recompiled、Xenia 的重编译方向是一类思路，但目标平台是 PS5，且目前没有官方 SDK，全靠自己还原 prx 接口。

**成熟度**: 早期项目，兼容列表里能实际跑起来的游戏只有 Dreaming Sarah 一个，README 自己专门列了 TechnicalDebt 文档，别当日常工具用。

**趋势信号**: 静态重编译正成为主机游戏 PC 移植的替代路线（N64、Xbox 360 重编译项目之后），而 PS5 模拟器至今没有能跑的方案，这个项目刚好放出了能稳定 60fps 跑通游戏的 demo。

### [DuarteSantos8/openGym](https://github.com/DuarteSantos8/openGym)

 `JavaScript` ⭐ +1,493 今日新增 · 7,299 总星数

> openGym 是一个可以自己用 Docker 部署的健身记录应用，替代 Hevy/Strong 这类云订阅 App。训练计划、每组数据、体重照片都存在自己的服务器上，用 passkey 登录。今天暴涨 1493 星，赶上自托管替代订阅制 SaaS 的潮流。

**亮点**

- 可选 AI 教练跑在自己的服务器上，用自己填的 API key（Anthropic/OpenAI/Gemini/Ollama 都行），AI 只出草稿，每处改动都要用户点确认才生效；另有一个只读 MCP server，让 Claude Desktop 直接查自己的训练历史。
- 所有历史记录可以事后编辑，改完之后 PR（个人纪录）和统计会按修正后的历史重新计算，而不是留着错的旧纪录。

**核心功能**

- 多设备同步用字段级合并：两台设备同时改同一条训练记录时，按字段合并而不是整条覆盖，避免手机和电脑互相把对方的修改冲掉。

- 渐进超负荷规则引擎：支持线性加重、Greyskull LP、双渐进（先在次数区间内加次数，满了再加重量）。漏做的次数不会加重量，连续卡住自动触发 deload（减量周）。
- 肌群状态图分三种模式：本周训练容量落在哪、哪块肌肉还在恢复中、哪块已经荒废（detrained）；配合 1RM 估算曲线和 Poliquin/Thibaudeau/ATG 结构平衡比例。

**适用场景**: 有 NAS 或家庭服务器、会敲 docker compose 的健身爱好者，尤其是从 FitNotes、Strong、Hevy 想搬走数据的人。适合不想为记录深蹲重量每月付费、也不放心把体重和训练历史交给第三方的人。

**竞品对比**: 最接近的自托管竞品是 wger，但 wger 是传统 Django 表单风格，openGym 做成了可装到手机主屏的 PWA，并且有 passkey 登录、字段级同步和 AI 教练。和 Strong/Hevy 比，最大差异是数据在自己服务器上、无订阅无广告，代价是要自己配 HTTPS 才能用 passkey。

**成熟度**: 有 release 版本、CI 测试和覆盖率徽章、changelog、roadmap、Discord 社区、18 种语言和在线 demo，功能完整度不低，但基本是单人维护，且 passkey 登录要求自己配好 HTTPS 域名。

**趋势信号**: 和 Immich 替代 Google Photos 是同一条线：用户开始拒绝订阅制云健身 App 的数据锁定，加上 passkey 和 MCP/AI 教练这两个当下热门话题，很适合在 r/selfhosted 和 HN 上被推一波。

### [tester-army/e2e](https://github.com/tester-army/e2e)

 `TypeScript` ⭐ +1,390 今日新增 · 7,734 总星数

> TesterArmy 出的 AI 端到端测试框架：用自然语言描述目标让 agent 操作 App，再用定位器加断言校验结果；agent 步骤会被录下来，重跑直接回放不调模型。

**亮点**

- 录制回放 + 按需调模型：第一次跑用 agent 探索，之后当缓存用。既保留了 AI 的容错，又把每次 CI 的模型成本和不确定性压掉了——这是跟其他 AI 测试工具最大的分叉点。
- 把文档跟 npm 包一起发，放在 node_modules/e2e/docs，让 Claude Code、Cursor 这类编码 agent 能离线读到文档，明显是冲着 agent 写测试这个用法设计的。

**核心功能**

- Agent 步骤执行时把动作序列录下来，下一次运行直接确定性回放、不调用大模型，只有页面结构变了才重新调模型。纯 locator + 断言的测试完全不需要模型。
- Web 引擎包了一层 Playwright，覆盖 Chromium/Firefox/WebKit；移动端通过 agent-device 驱动 iOS 模拟器和 Android 模拟器。两边共用同一套 test/expect API，不用学两套写法。
- 把语义操作和断言交给 @e2e-dev/decision 的决策模型执行器，动作空间是有界的，减少 agent 在页面上乱点的概率；模型可自带（自己的订阅、API key 或本地模型）。

**适用场景**: 前端和移动端团队在 CI 里跑回归测试，Playwright/Cypress 的选择器一改版就挂，用自然语言描述业务目标更抗改版。 QA 工程师和不熟选择器的开发，想快速给结账、升级这类关键流程加一层端到端保障；React Native、SwiftUI、Jetpack Compose、Flutter 项目都有现成示例可抄。

**竞品对比**: 对比 Playwright、Cypress、Selenium 要手写选择器和断言；对比 Momentic、QA Wolf、Midscene.js 这类 AI 测试工具也做自然语言驱动，但 e2e 的差异是 replay 缓存不重复烧 token，且同一套 API 同时管 web 和移动端。

**成熟度**: 未到 1.0，官方 README 明确说 API 和配置可能在小版本间变动，属于迭代快、接口还可能改的早期项目。

**趋势信号**: AI agent 写/跑测试是当下最热的赛道之一，它又抢到了 npm 上极短且好记的包名 e2e，加上 Vite、Next.js、Expo、SwiftUI 等示例开箱即用，很容易被转发；单日 1390 star 更像是一波社交平台传播，具体触发事件不明。

### [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)

 `JavaScript` ⭐ +677 今日新增 · 102,981 总星数

> Addy Osmani 把资深工程师的工作流打包成 25 个 Markdown 技能 + 9 个斜杠命令，让 AI 编码 agent 按 spec→测试→评审→发布的流程干活，而不是每次自由发挥。

**亮点**

- 它不写任何运行时代码，纯粹是流程/提示词资产，所以能跨 70 多个 agent 复用，没有框架锁定问题——这在 agent 工具快速洗牌的当下是关键取舍。
- /build auto 的边界划得很清楚：自动化只吃掉'任务之间的手工步骤'，测试、逐个 commit、失败暂停这些验证动作一个都不省，属于对 agent 自主性的克制设计。

**核心功能**

- 全部内容就是 Markdown 写的 SKILL.md，分 25 个技能，按开发阶段（定义/计划/构建/验证/评审/发布）归类；agent 根据当前任务自动加载对应技能，比如设计 API 触发 api-and-interface-design，写 UI 触发 frontend-ui-engineering，不用手动切。
- 9 个斜杠命令一对一映射开发生命周期：/spec、/plan、/build、/test、/constraints、/review、/webperf、/code-simplify、/ship，每个命令自动拉起相关技能。
- /build auto 模式：计划批准一次后自动跑完全部任务，但每个任务仍走测试驱动、逐个提交，失败或高风险步骤会停下来等人，砍掉的是任务之间的点击而不是验证。

## 趋势观察

今天的热门项目指向同一件事：AI Agent 正在从会聊天，变成能干活。给它技能，给它记忆，给它电脑，给它规范和审计。MCP 把逆向工具、抓包、调试串成一个服务。技能集把需求拷问、术语表、流程图、代码评审打包成 Markdown。持久上下文让 Agent 跨会话记住做过什么。cmux 让多个 Agent 并行跑，终端变成调度台。Computer-Use 直接给 Agent 一台可操作的电脑。测试、安全审计、输出规范也在补。以前是 vibe coding，现在是给 Agent 立规矩、留证据、可回放。另一条线是硬核系统突破。PS5 可执行文件被静态重链接成原生程序，绕开模拟器。Epic 开源图形调试器，专治超大工程。这说明底层工具和逆向工程没有停，反而被 Agent 拉进工作流。openGym 暴涨，代表自托管替代订阅制 SaaS 还在继续。开发者的角色在变：少写一次性代码，多写技能、协议、评测和流水线。平台竞争也从模型转向生态。Claude Code、Codex 等成了入口，谁配套件多，谁留住人。接下来看两点：Agent 能不能稳定操作真实电脑；上下文和权限能不能管住。能管住，AI 才不是玩具，而是数字员工。
