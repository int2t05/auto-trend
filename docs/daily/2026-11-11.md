### [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)

 `JavaScript` ⭐ +465 今日新增 · 115,351 总星数

> 把资深工程师的研发流程（写规格、拆任务、TDD、评审、上线）打包成 25 个可安装技能，让 Claude Code、Cursor 等编码 Agent 按同一套规矩干活。

**亮点**

- 做的是「流程」而不是「知识」：不教 Agent 语法，而是用 spec→plan→build→test→review→ship 的顺序约束它，并内置质量门，比如合并前的五维评审、约束只定一次然后全局执行
- 只砍掉任务之间的人工点击，不砍验证：auto 模式下每个任务照样 TDD、单独 commit、失败即停，这是它敢叫「生产级」的关键取舍

**核心功能**

- 9 个斜杠命令对应研发生命周期六阶段（/spec /plan /build /test /review /ship），每个命令自动挂载对应技能；技能还会按上下文自动触发，比如设计接口时调 api-and-interface-design，写 UI 时调前端工程技能
- /build auto 模式下人只批一次计划，Agent 自己拆任务逐个实现，每个任务强制先写测试再写码、单独提交，遇到失败或高风险步骤会停下来等人
- 技能本体就是带 frontmatter 的 Markdown 文件（遵循 SKILL.md 约定），借 Vercel 的 npx skills CLI 一次装进 70+ 个 Agent，不绑定单一 IDE

**适用场景**: 用 Claude Code、Cursor、Codex 写业务代码的工程师和小团队，特别是被 Agent「不写规格直接开干、改完没测试」坑过的场景。也适合团队把代码评审标准、Web 性能预算这类规范固化成可复用技能。

**竞品对比**: 同类有 GitHub Spec Kit（规格驱动开发）、BMAD-METHOD（多角色 Agent 工作流）和大量 awesome-cursorrules 提示词合集。差别是它按生命周期组织成命令加技能，并通过 skills CLI 跨 70+ Agent 复用，不锁死在一个编辑器里。

**成熟度**: 偏早期但已能日常用：单人主导维护，结构还在调整（按单技能安装会缺共享 references 目录，issue #361 未闭环），多工具安装文档齐全，但没明确版本号和稳定性承诺。

**趋势信号**: Anthropic 的 SKILL.md 技能格式加上 Vercel skills CLI 正在变成跨 Agent 的事实标准，再叠加 Addy Osmani 本人的号召力，赶上了「从手写提示词转向安装技能包」这波转向。

### [tokio-rs/topcoat](https://github.com/tokio-rs/topcoat)

 `Rust` ⭐ +192 今日新增 · 6,942 总星数

> tokio 团队出的 Rust 全栈 Web 框架：服务端渲染 HTML，组件可直接查库，前端交互用 $\(\) 表达式自动编译成 JS，不用 wasm 也不用前端构建。当前处于早期实验阶段。

**亮点**

- 用「服务端渲染 + shard 局部替换」替代 wasm SPA：交互逻辑里类型安全的 Rust 子集被转译成 JS，复杂数据查询仍留在服务端，等于把 htmx 的思路和 Leptos 的响应式语法缝到了一起
- 框架出自 tokio-rs 组织，底层直接跑在 tokio 上，异步请求/DB 调用和组件渲染是同一套运行时，不需要在 sync/async 边界上折腾

**核心功能**

- 所有页面在服务端渲染，组件写成 async 函数直接查数据库，省掉前后端之间那层 API 层；需要局部刷新时用 #\[shard\] 标记组件，参数一变就在服务端重渲染并把新 HTML 换进页面
- $\(\) 表达式是类型检查过的 Rust：首次渲染时服务端算一次，同时被翻译成 JavaScript 发到浏览器，点击/输入这类交互直接在浏览器跑，不做 wasm 打包，也没有前端构建步骤
- 按目录结构推路由：app/posts/id.rs 自动映射到 /posts/{post_id}，文件名带下划线前缀的是布局不占 URL 段，不需要额外的路由配置文件或编译期代码生成
- asset! 宏在编译后的二进制里被扫描出来，把文件拷到本地资产目录并做内容哈希，配长缓存头；topcoat ui 命令把 shadcn 风格的 Tailwind 组件源码直接拷进项目，改起来没黑盒

**适用场景**: 适合已经用 Rust 写后端、又想少维护一套前端工程的团队，典型场景是内部管理后台、SaaS 产品的 CRUD 页面和带搜索过滤的列表页——这些地方不需要复杂 SPA 交互，但需要服务端直连数据库。

**竞品对比**: 对比 Axum/Actix，那些只是 HTTP 路由层，模板、资产、组件全要自己拼；对比 Leptos/Yew/Dioxus，那些走 wasm 路线，要打包、首屏体积大、还得处理服务端和 wasm 两套运行环境的差异。Topcoat 最大的差异是彻底不要 wasm 和前端构建。

**成熟度**: 早期实验项目，README 明说会有破坏性变更，版本低于 1.0，API 别指望稳定。

**趋势信号**: tokio-rs 官方组织亲自下场做全栈框架，加上 Rust Web 圈对 wasm 方案体积和复杂度不满的情绪在积累，这个「不要 wasm 的全栈」路线正好接上了这波讨论。

### [meta/astryx](https://github.com/meta/astryx)

 `TypeScript` ⭐ +3,108 今日新增 · 23,547 总星数

> Meta 把内部用了八年、支撑 13000+ 应用的设计系统开源了：150+ React 组件，换主题只改 CSS 变量，CLI 同时给人和 AI 助手查文档。

**亮点**

- 把「给 AI 用」当一等需求做：CLI 有专门的 docs 子命令供 agent 查文档，README 还专门建议写进 package.json script，避免 AI 直接调 CLI 时路径报错——这是按 agent 在终端里实际跑命令的行为倒推设计的
- 把性能和可覆盖性拆开：内部用 StyleX 编译换来零运行时样式，外部消费者完全不用碰 StyleX，主题走 CSS 变量、覆盖走 className，等于同时拿原子 CSS 的产物和普通 CSS 的可改性

**核心功能**

- 样式用 StyleX 编译（Meta 自家的原子化 CSS-in-JS，构建时生成静态 CSS、运行时零开销），但对使用者透明：直接引预构建 CSS，不装 Babel/PostCSS 插件；要覆盖样式就用 className 走 Tailwind 或普通 CSS
- 主题不是一套 ThemeProvider 配置，而是一组 CSS 自定义属性覆盖，改主题不动组件源码、不加包装层，设计师可以只靠 CSS 把组件改成品牌样式
- swizzle 命令能把任意组件的完整源码 eject 到项目里自己维护，底层 building block 也直接导出，避免顶层 API 锁死；CLI 提供 `astryx docs` 让 AI 助手在终端里查组件文档和 API 约定

**适用场景**: 适合已经有 React 19、多条产品线要统一 UI 的中大型前端团队，尤其是被 MUI/AntD 的样式方案绑住、想自己控主题的；也适合用 Cursor、Claude Code 这类 agent 写页面的团队，让 agent 按同一套文档和约定生成组件代码，而不是瞎编 API。

**竞品对比**: 对标 MUI、Ant Design 和 shadcn/ui。跟 shadcn 一样能 swizzle 出源码，但不强制你把组件代码搬进仓库；跟 MUI 比，换主题不用 ThemeProvider 包一层，也不带 emotion 运行时开销。

**成熟度**: Beta 阶段，core 和 cli 已上 npm，charts 只有 canary 标签；但底层是 Meta 内部八年、13000+ 应用验证过的代码，公开 API 仍可能调整。

**趋势信号**: 赶上 AI coding agent 全面铺开，大厂设计系统开始把「agent 可读」当卖点，加上 React 19 和 StyleX 生态刚成熟，Meta 挑这个时间点把内部最大设计系统放出来。

### [sherlock-project/sherlock](https://github.com/sherlock-project/sherlock)

 `Python` ⭐ +2,393 今日新增 · 109,378 总星数

> 一条命令跨 400+ 社交网站查用户名是否注册，给 OSINT 和安全自查用。

**亮点**

- 把每个站点的存在性判断做成可配置规则，新增或修复站点不用改 Python 代码，只改 JSON 数据
- 不做登录和官方 API，只靠公开页面状态码与错误文案推断，成本低但规则容易被站点改版打破

**核心功能**

- 用 data.json 维护 400+ 站点的 URL 模板、errorMsg/errorType、regexCheck 和自定义 headers，新增站点只改配置不改代码
- 并发发 GET 请求，按 HTTP 状态码或页面错误文案判断账号是否存在，支持 --timeout、代理和 Tor
- 结果可输出 CSV/Excel/JSON，支持多用户名批量、--print-all 显示未命中、--nsfw 过滤成人站点

**适用场景**: 安全研究员、反欺诈和品牌保护团队做 OSINT 排查时，用它快速查一个用户名在哪些平台注册；普通用户也可以查自己的用户名暴露面。

**竞品对比**: 同类的 Maigret 覆盖站点更多、还能抓取资料；WhatsMyName 偏浏览器端清单。Sherlock 只做存在性判断，胜在 CLI 简单、站点清单和社区体量大。

**成熟度**: 生产可用但结果不稳定：站点规则常因改版失效，需定期更新 data.json；版本低于 1.0，适合辅助排查，不适合当唯一证据。

**趋势信号**: 原因不明；近期没有明显大版本发布，热度更像 OSINT/隐私自查话题在安全社区被二次传播。

**亮点**

**核心功能**

- 技能格式极简：一个文件夹加一个 SKILL.md，YAML 头部只要求 name 和 description 两个字段，正文写指令、示例和脚本，不需要写任何框架代码或注册逻辑
- 渐进式加载（progressive disclosure）：启动时只把每个技能的 name 和 description 塞进上下文，判断命中后才读入完整 SKILL.md 和附带脚本，避免几十个技能一次性占满 token

- 分发和共用：既能通过 Claude Code 的 /plugin marketplace 安装，也能在 Claude.ai 上传，或通过 Skills API 调用；另有 spec/ 目录单独定义开放标准

**适用场景**: 想让 Claude 稳定地按公司模板出 PPT、写带品牌规范的文档、或者跑内部审批流程的团队。开发者照着现有技能改写自己的 SKILL.md，HR、法务、市场这类非工程角色也能拼出来。

**竞品对比**: 和 MCP 不是一类东西：MCP 解决“模型能调什么工具”，Skills 解决“模型知道怎么做事”，两者互补；和 Cursor 的 .cursorrules 或 GPTs 的自定义指令比，Skills 能附带可执行脚本和资源文件，并且按需加载、可打包分发，而不是每次全量塞进 prompt。

**成熟度**: 文档技能已在 Claude 生产环境验证，规范也已独立成站，但仓库自己标注为演示和教育用途，用前需自行测试。

**趋势信号**: Anthropic 把 Agent Skills 推成开放标准（agentskills.io），同期 Claude Code 插件市场上线支持一键安装，社区开始批量造技能，热度跟着生态一起涨。
