### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +54,679 今日新增 · 215,064 总星数

> REA 是一个 MCP 服务，把 Hopper、Ghidra、IDA 等逆向工具包成 AI Agent 能调的工具，让它能拆开二进制、Electron 应用和网站，看懂功能怎么实现，再照着写一份。

**亮点**

- 它把逆向工程这个高度依赖具体工具和脚本的活，抽象成一套统一的 MCP 接口：Agent 不需要会写 IDA Python 脚本，也能跨二进制、Electron、.NET、网站四种目标做分析。
- 设计上刻意不做'一句话结论'。返回结果必须带证据和未解部分，这是拿效率换可信度的取舍，主要防 LLM 在逆向场景里编造不存在的函数和调用链。

**核心功能**

- 用 MCP（模型上下文协议，一种让 AI 助手调用外部工具的通用接口）统一封装多种分析引擎：原生二进制走 Hopper/Ghidra/IDA，拿伪代码、汇编、字符串、符号和调用关系；JS/Electron 走静态分析，直接解 ASAR 包、模块依赖和渲染进程与主进程的边界，这条路径不需要反汇编引擎。
- 每条结论强制附证据和局限说明。Agent 拿到的是代码片段、引用位置和'哪些查不到'，而不是一段无法验证的总结，方便追问和继续追踪。
- 分析全程在本机跑，代码不上传；结果可以用 CLI 以 --json 输出，也能直接喂给 Agent，两条路走同一套工作流。

**适用场景**: 一是产品经理或前端工程师看到竞品 App 的某个功能想抄，用 Claude Code、Cursor、Codex 通过 REA 查清实现方式再在自己项目里重写；二是安全研究员和逆向工程师分析没有源码的 .NET 程序、固件或原生二进制，需要快速拿到调用图和伪代码。

**竞品对比**: 同领域已有很多单点方案，比如 Ghidra MCP、IDA Pro MCP，但基本只接一个引擎。REA 的差异是把原生二进制、JS/Electron、.NET 和网站放进同一套工具接口和证据格式。对比 Cursor、Claude 自带的代码理解，那边只能看有源码的项目，REA 面对的是没有源码的目标。

**成熟度**: 中等偏早的项目：已发 npm 包（rea-agents）、有 20 多种语言的 README 和 Discord 社区，但官方自己写明'REA changes quickly'，接口还在快速变动，别指望 API 稳定。

**趋势信号**: MCP 在 2025 年成了 Agent 接工具的事实标准，Claude Code、Cursor、Codex 都支持，REA 正好卡在这个接口红利上；加上'照着竞品功能抄一份'是开发者的高频刚需，把逆向工具接进 Agent 就成了顺理成章的事。

### [bilawalsidhu/gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view)

 `JavaScript` ⭐ +1,961 今日新增 · 55,701 总星数

> 把航班、船舶、卫星、地震、气象、公共摄像头这些公开数据叠到同一张三维地球上，在浏览器里本地运行，不填 API key 也能起步，还能用语音提问。

**亮点**

- 默认零 key 起步：所有基础数据源不注册账号就能跑，付费 key 只用来解锁高清影像和 Google 地点搜索，直接砍掉上手门槛，这是它能病毒式传播的关键设计

- 分享链接能序列化正在跟踪的单个目标，别人打开就是一个活的交接，而不是一张静态书签

- 多源公开信号图层化：ADS-B 航班应答机、AIS 船舶信标、TLE 卫星轨道根数、USGS 地震、GFS/ECMWF 气象、OSM 里的 ALPR（车牌识别摄像头）点位，每层都是独立可插拔模块，无 key 走 Esri 影像 + 免 key 地形，OSM 兜底

**适用场景**: 做 OSINT（公开来源情报）的研究者、记者、地理信息爱好者，想在一张地球上同时盯飞机、船、卫星和街边摄像头；也适合做演示视频或课堂讲解的人，比如回放尼泊尔 Bhote Koshi 洪水的淹没路径和前后对比影像。

**竞品对比**: Flightradar24、MarineTraffic、ADS-B Exchange 各自只覆盖一个领域且闭源要登录；CesiumJS 和 Google Earth Web 只有底图没有实时图层。它把航班+船+卫星+摄像头+气象叠在同一张地球上，代码可改，图层可自己加。

**趋势信号**: 2026 年 8 月开源发布后配套 YouTube 系列破 500 万播放、登顶 GitHub Trending，被 Brendan Eich 转发；正好撞上 OSINT 公开情报和「本地优先 + 语音 Agent」两波热度叠加。

### [lyogavin/airllm](https://github.com/lyogavin/airllm)

 `Jupyter Notebook` ⭐ +1,001 今日新增 · 38,441 总星数

> AirLLM 把大模型按层切成文件存到磁盘，推理时逐层送进 GPU，让单张 4GB 显卡跑 671B 甚至 2.8T 模型。

**亮点**

- 不做量化、不做蒸馏剪枝，靠"权重不常驻显存、按需从磁盘流式读"来绕开显存瓶颈，精度基本不丢，是拿速度换容量的极端取舍——本质是把 GPU 显存问题转成了磁盘 IO 问题。
- 训练也用了同一套思路：冻结的预训练权重逐层流过 GPU，只有适配器（adapter）常驻显存，于是 125B 能在 6GB 卡上微调，这条路和常见的 LoRA + 量化方案不太一样。

**核心功能**

- 逐层流式加载：首次运行把权重按层拆成独立文件，推理时一次只把一个层的权重拷进显存，显存占用约等于单层大小，所以 70B 能在 4GB 卡上跑起来，代价是每生成一个 token 都要全量读一遍磁盘。
- MoE 按专家路由流式加载：Kimi K3（2.8T）推理时只加载这个 token 真正路由到的专家，其余留在磁盘，官方实测端到端 3.72GB 显存；125B 的 Qwen3.8-Flash-Next 把 51B 的 n-gram 嵌入表用 mmap 放在主机内存，显存只占 5.95GB。
- 换速度的两种手段：一是块状量化（block-wise quantization，把权重分块再压）拿到最高 3 倍推理加速，二是预取，把下一层的磁盘读取和当前层的计算重叠起来，再快约 10%。

**适用场景**: 适合手里只有一张 4-8GB 消费卡（比如 RTX 3060 Ti、4090 空闲时）、但内存和 SSD 够大的个人开发者和学生，用来本地试跑 DeepSeek-V3、Qwen3-235B 这类超大开源模型，或者用低显存微调 125B 模型验证想法。不适合要高吞吐的线上服务。

**竞品对比**: 和 llama.cpp/GGUF 比，它不用量化也能跑，精度无损，但速度慢一个量级；和 DeepSpeed ZeRO-Inference、FlexGen 这类把权重卸载到 CPU/NVMe 的方案比，它更彻底，连 CPU 内存都不留权重，显存门槛压得更低，代价是磁盘吞吐成为硬上限。

**成熟度**: v3.0、Apache 2.0、有 PyPI 包和 Discord 社区、更新很勤，但文档主要靠 notebook，跑新模型要自己装 fork 版 transformers、备几百 GB 磁盘，属于能折腾不能直接上生产的阶段。

**趋势信号**: 2026 年 7 到 9 月连续加了 Kimi K3（2.8T）、Qwen3.8-Flash-Next（125B）支持和低显存训练，"2.8T 最大开源模型塞进 4GB 显卡"这个说法在社区里传播性极强，一天涨 1000 星。

### [mksglu/context-mode](https://github.com/mksglu/context-mode)

 `TypeScript` ⭐ +969 今日新增 · 28,410 总星数

> 给 AI 编程 agent 用的 MCP 插件：把工具原始输出挡在上下文窗口外，用 SQLite+FTS5 存会话记忆，今天冲上 Hacker News 第一。

**亮点**

- 刻意不管模型怎么写答案，只管道数据往哪走。README 明确反对"回答要简洁"这类提示词，理由是强推简短会拉低编码/推理 benchmark（引了 Moonshot AI kimi-k2.5 的 issue）。这跟一堆教模型少废话的插件是反着做的。
- 不带 --continue 启动就立刻删掉上次的会话数据，不留历史。相当于把"记忆"的默认值设成一次性。

**核心功能**

- 沙箱执行代替读数据：ctx_execute 让模型写一段 JS/Python 脚本在沙箱里跑，只把 console.log 的结果回传。README 里的例子是 47 次 Read（约 700KB）换成 1 次调用（3.6KB）。整体宣称 315KB 压到 5.4KB。
- 会话记忆用 SQLite 存事件（文件编辑、git 操作、任务、报错、用户决定），压缩对话时不做整段回灌，而是建 FTS5 全文索引，用 BM25 检索只捞相关的那几条事件回去。
- 部署形态是 MCP server + 6 个钩子（PreToolUse、PostToolUse、UserPromptSubmit、PreCompact、SessionStart、Stop），共 11 个 MCP 工具。SessionStart 钩子在运行时注入路由规则，不往项目里写文件；不支持钩子的平台要手动拷一份路由文件。覆盖 17 个客户端。

**适用场景**: 用 Claude Code、Cursor 等 agent 跑长任务的人：多文件重构、翻几十 MB 日志排查、批量看 GitHub issue。典型痛点是干半小时上下文被工具输出吃掉 40%。

**竞品对比**: 对手是 Anthropic 官方的 context editing / tool result clearing、mem0 和 Letta 这类记忆层、以及各种裁剪工具输出的 MCP 代理。最大差别：别人只裁剪输出，它让模型写脚本自己算；记忆部分按需检索而非回灌；而且不管模型文风。另注意许可是 ELv2，不是标准开源，不能拿它做托管服务。

**成熟度**: 有 HN 第一和企业团队使用背书、Discord 社区在跑，但 ELv2 许可 + 高速迭代，工具 API 还可能变，建议先小范围试点。

**趋势信号**: Hacker News 首页第一（570+ 分）带来一波流量；底层原因是 Claude Code / Cursor 用户普遍撞上 MCP 工具输出把上下文撑爆、compact 之后 agent 忘事这个当前最痛的问题。

### [vercel-labs/skills](https://github.com/vercel-labs/skills)

 `TypeScript` ⭐ +190 今日新增 · 34,664 总星数

> Vercel Labs 出的命令行工具，用 npx skills add owner/repo 一条命令把 Agent Skill（一份 SKILL.md 说明书）装进 Claude Code、Codex、Cursor 等 80 多个编码 Agent。它把散落各家、互不兼容的 skill 目录变成一个可复用的公共包。

**亮点**

- 把 skill 当 npm 包来管：owner/repo 寻址、私有源认证、软链接安装、全局/项目两种 scope，这套心智模型直接照搬包管理器，绕开了「每个 Agent 一套目录规范」的兼容地狱。
- 认证设计刻意保守——不执行 gh auth token、不把 GitHub CLI 凭证复制进自己的进程，只用 API 响应或退回认证过的 git clone，避免成为凭证明文流转的一环。

**核心功能**

- 一条命令打通 80+ 编码 Agent：同一份 skill 通过软链接（symlink）分发到各 Agent 各自的 skills 目录，改一处全生效，也可用 --copy 改成复制。装 project 级还是 -g 全局级可选。
- skill 源几乎不限：GitHub 简写、GitLab、Azure Repos、任意 git URL、本地路径、甚至一个直链下载 URL（单个 SKILL.md 或 zip/tar 包），下载限 10 MiB、解压限 25 MiB / 1000 文件，可用环境变量放宽。
- skills use 可以只借用不安装：把选中的 skill 渲染成一段 prompt 打到 stdout，管道喂给 claude，或者加 --agent 直接拉起某个 Agent 交互式开跑。
- 私有仓库复用你已有的 Git 认证链：先走 Git credential helper，失败再试 gh repo clone，最后退到 SSH；全程不读取、不拷贝 gh 存的 token 到 Node 进程里。

**适用场景**: 给已经在用 Claude Code / Codex / Cursor 写代码的开发者，尤其是团队里想把「前端设计规范」「代码审查清单」这类提示词做成共享资产的人。以前每人手工往 ~/.claude/skills 里拷文件，现在可以像依赖包一样 add、版本化、随项目提交到仓库让同事复用。CI 里也能用 --all -y 无交互批量装。

**竞品对比**: 最直接的「竞品」是各 Agent 自带的 skill/plugin 市场，比如 Claude Code 内置的插件安装，只能在自家生态用。skills 的差异点就是跨厂商中立：一份 SKILL.md 装到 80 多个 Agent。和 MCP 不是一层——MCP 接的是工具和数据，skills 装的是提示词和流程知识。

**成熟度**: Vercel Labs 官方产品、MIT 协议、npm 上可下，文档详尽但版本仍在 0.x 早期，API 和目录约定可能还会变。

**趋势信号**: Anthropic 推出 Claude Skills 后，「Agent 能力用 Markdown 文件打包」快速形成事实标准，各家 Agent 一拥而上但谁也不兼容；Vercel 以中立第三方身份做统一安装器，卡住了这个空档，加上 npx 零门槛，所以 star 涨得飞快。
