### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +1,046 今日新增 · 211,202 总星数

> Firecrawl 把网页抓成干净 markdown 喂给 AI Agent，现在出了单文件 Rust 版 Local，能本地跑、一条命令接进 Claude Code 和 Cursor。

**亮点**

- 同一套 API 有三种跑法：crates.io 单二进制、apps/api 自托管全套服务端、firecrawl.dev 云服务，代码不用改
- 把«抓页面»扩成«供给知识»：云端的 Alexandria 把 550+ 数据源和 search 接进同一个 API，Agent 不必只靠爬网页

**核心功能**

- Firecrawl Local 编译成单个 Rust 二进制（cargo install firecrawl-local），本地抓取不需要数据库、队列或容器，JS 页面直接复用你机器上已装的 Chrome/Chromium 渲染，PDF 和 Office 文档也在本地解析
- `firecrawl-local init` 自动探测 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 的配置文件，先备份再逐个写入 MCP server 配置；`serve` 在本机 3002 端口跑 Firecrawl v2 API，SDK 只改一个 api_url 就能连，本地路由不校验 API Key
- 本地优先、云端兜底：单页在本地渲染失败时会转给 Firecrawl Cloud 抓，结果里标 "source": "firecrawl-cloud"，设 FIRECRAWL_CLOUD=off 可完全断网隔离

**适用场景**: 给 Claude Code、Cursor 这类编码 Agent 或自建 RAG 管线喂网页和文档的开发者，需要抓文档站、竞品页面、PDF 手册转成 markdown，又不希望内容过第三方服务器时用它。

**竞品对比**: 和 Crawl4AI 比，Crawl4AI 是 Python 库、得自己管浏览器和并发；和 Jina Reader 比，后者只有托管接口没有本地部署。Firecrawl 的差异是本地二进制、自托管、云 API 三套共用一套接口，还叠了搜索和数据源。

**成熟度**: 生产可用，v2 API 已稳定，有 Python/Node SDK 和云服务商业验证；Local 是较新的 Rust 重写，细节功能仍在补齐。

**趋势信号**: Claude Code、Cursor 等本地 Agent 普及后 MCP 配置成了刚需，加上 Firecrawl Local 发布和 keyless 每月 1000 次免额度，直接把接入门槛压到一条命令。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +854 今日新增 · 327,785 总星数

> obra/superpowers 是一套给编码 Agent 用的开发方法论：把「先问需求→写规格→出计划→子 Agent 分工 TDD 实现」拆成可组合的 skill 文件，装进 Claude Code、Codex、Cursor 等十几家 CLI 后自动生效，让 Agent 别一上来就写代码。

**亮点**

- 把「方法论」而不是「工具」做成可分发插件——同一份技能内容通过各家官方 marketplaces 分发，等于把编码 Agent 的行为规范标准化了
- 用子 Agent + 干净上下文对抗长会话退化，这比把全部规则塞进一个大 CLAUDE.md 更抗上下文压缩

**核心功能**

- 技能就是一堆 Markdown 文件，每份带 description；启动时由 SessionStart 钩子注入一个 using-superpowers 引导技能，让模型在对话开头就知道要加载哪个技能，不用手动点名指令
- 子 Agent 驱动开发：把计划拆成单个任务派给独立子 Agent，每个子 Agent 拿干净上下文做一件事，主 Agent 检查 review 后再派下一个，避免长会话上下文腐烂，官方说能连续自主跑几小时不跑偏
- 一套仓库适配约 17 种 Agent 运行时（Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、OpenCode 等），靠各家的 plugin、extension 机制和兼容层发布：没有原生 skill 工具的运行时补一个兼容 Skill 工具，Pi 这类有 compaction 的还会在压缩后重新注入引导
- 规格和计划强制写成「水平差的初级工程师也能照着做」的粒度，并把红/绿 TDD、YAGNI、DRY 写死在流程里，而不是靠模型自觉

**适用场景**: 日常用 Claude Code / Codex / Cursor 写业务代码的开发者，尤其是接手不熟悉仓库、或者任务大到一次会话做不完的情况；团队想统一「Agent 怎么干活」的规范时也能用。

**竞品对比**: 和单文件 CLAUDE.md / .cursorrules、GitHub Spec Kit、BMAD-METHOD 这类方案比，它不是只给提示词或只做规格文档，而是覆盖「需求→规格→计划→实现」全流程，并且跨十几个 Agent CLI 通用。

**成熟度**: 已在多家官方插件市场上架、README 文档很细、还挂了商业支持邮箱，可用；但技能内容是快速迭代的方法论，行为可能随版本变化。

**趋势信号**: 2025 年底各家 Agent CLI 陆续上线官方插件/技能市场（Claude plugins、Codex plugins、Gemini extensions），技能包第一次有了统一分发渠道，加上作者 obra 在开发者圈的名气，这个仓库跟着起飞。

- orchestrate 插件把大任务分给三类并行的云 agent：planner 拆活、worker 干活、verifier 验收，中间靠结构化 handoff（把上下文按固定格式交接）串起来
- cli-for-agent 是一份给 agent 用的 CLI 设计规范：必须支持 flags、--help 里带可运行示例、能接管道、报错可读、幂等、支持 dry-run，让 agent 不会因为命令行为不一致而翻车

**适用场景**: 两类人会用到：一是销售、运营、招聘这类业务角色，在 Cursor 里让 agent 直接查 Salesforce 记录、翻 HubSpot 商机、读 Gmail 写草稿；二是工程团队，用 thermos、pstack 这类插件把 code review 和发布流程固化下来，全组跑同一套标准。

**竞品对比**: 直接对标 Claude Code 的 plugins/skills 体系和 MCP server 生态，也和 VS Code Copilot 的扩展市场抢同一块地。最大差别是 Cursor 把 SaaS 集成做成官方维护的第一方插件库，省掉了社区生态冷启动那一步。

**成熟度**: 早期阶段：仓库近 2 万星、有清单格式和脚手架，但插件规范刚发布，部分条目自带 Beta 标记，接口和目录结构还可能调整。

**趋势信号**: Cursor 正式推出插件市场并把规范开源，这是对 Claude Code 带火的 skills + MCP 扩展生态的直接跟进，官方一口气放出几十个集成制造了声量。

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +176 今日新增 · 12,865 总星数

> Intel 的开源推理部署工具包：把 PyTorch/TF/ONNX 模型转成 OpenVINO IR，在 x86 CPU、Intel 核显/独显和 NPU 上跑推理，自带 LLM 的 GenAI 接口。

**亮点**

- 用「一次转换、多处编译」的 IR + 插件架构，把硬件差异关在 runtime 里，模型侧代码完全不用改，这是它跟各家推理框架最大的结构差别
- 把 LLM 推理服务化能力（KV-cache 复用、连续批处理、投机解码）直接做进 GenAI API，而不是让用户自己拼 tokenizer 和采样循环

**核心功能**

- 多框架前端（PyTorch、TensorFlow、ONNX、PaddlePaddle、JAX/Flax）把模型转成统一的 OpenVINO IR，转换后就不再依赖原框架，部署机上不用装 PyTorch/TF
- 设备抽象层用插件实现，一份 IR 分别编译到 CPU（x86/ARM）、Intel 集显/独显、NPU，运行时按硬件挑算子实现，同一份代码换硬件不用改
- 配套 NNCF 做训练后量化，INT8/INT4 权重压缩，把 7B 级 LLM 压到能在消费级 CPU 和核显上跑；GenAI API 里封装了 KV-cache 和连续批处理（continuous batching）的推理流水线

**适用场景**: 在 Intel 硬件上做本地推理的开发者：AI PC 上做端侧聊天机器人、语音转写（Whisper），工厂产线用普通工控机做视觉质检，不想买 NVIDIA 卡又要跑模型的团队。

**竞品对比**: 对标 ONNX Runtime 和 TensorRT。差异是：OpenVINO 绑定 Intel 硬件栈（CPU/核显/NPU），只优化 Intel 平台；ONNX Runtime 覆盖面广但核显和 NPU 支持弱，TensorRT 只吃 NVIDIA 卡。llama.cpp 更轻但只针对 LLM 且量化策略更简单。

**成熟度**: 生产可用，Intel 官方长期维护，pip/conda/homebrew/npm 多通道分发，文档和 notebook 齐全，早有企业落地案例。

**趋势信号**: 大概率是新版本文档（链接已指向 2026 版）发布叠加 AI PC / Intel NPU 本地跑 LLM 的热度，让这个老项目重新冲上 trending。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +150 今日新增 · 33,573 总星数

> NGINX 官方源码仓库：一个 C 写的 Web 服务器/反向代理/负载均衡/API 网关，用事件驱动多进程模型扛住高并发。现在上热榜主要是官方仓库迁到 GitHub 后关注度回流，加上主线版本和安全补丁发布。

**亮点**

- 用多进程 + 单线程事件循环替代多线程，把并发成本压到每个连接几 KB 内存，这是它能长期占住入口层位置的核心取舍。
- 配置热加载做成了「新旧 worker 并存再平滑退出」，把「改配置」这个高频运维动作变成不影响在线请求的操作。
- 模块既可以编译期静态链接，也可以运行期 .so 动态加载，第三方模块（如 njs、各种第三方 filter）不用重新编整个 nginx。

**核心功能**

- master + 多个 worker 进程模型：worker 数量可写死或自动等于 CPU 核数，每个 worker 是单线程事件循环（Linux 下 epoll），不靠开线程扛并发，所以连接数上万时内存占用依然很平。
- 配置是纯文本指令树，改完执行 nginx -s reload 就行：master 读新配置、拉起新 worker、让旧 worker 处理完存量连接再退出，过程中不断连接、不掉请求。
- 模块分静态和动态两种：静态模块在 ./configure 时编译进二进制，动态模块是 .so 运行时加载；nginx -V 能看到当前二进制编进了哪些模块。
- 跨进程状态靠共享内存 zone：比如 limit_req_zone 把限流计数放在共享内存里，所有 worker 看到的是同一份计数，而不是各算各的。
- 反向代理、TLS 终止、负载均衡、内容缓存、限流都在同一份配置文件里组合，不用额外进程。
- 内存分配走自己的 pool（连接级内存池），一个请求结束整块释放，减少 malloc/free 和碎片。

**适用场景**: 运维/SRE 和后端团队拿它做入口层：TLS 终止、按路径分发到不同后端、静态资源缓存、接口限流、灰度切流。K8s 集群里通常通过 ingress-nginx 控制器间接使用它。

**竞品对比**: 常被拿来和 Caddy、Envoy、HAProxy、Traefik 比。最大差异是 NGINX 配置是静态文本、没有控制面 API，动态改配置要么 reload 要么上 OpenResty/njs；Caddy 主打自动签证书和极简配置，Envoy 主打 xDS 动态下发、面向服务网格，NGINX 胜在成熟度、模块生态和运维人员熟悉度。

**成熟度**: 生产可用，20 年以上历史，BSD-2 许可，主线 1.29.x / 稳定 1.28.x，文档和模块参考齐全，F5 提供商业版和支持。

**趋势信号**: 官方源码仓库从 Mercurial 迁到 GitHub 后社区关注持续回流，叠加近期主线版本更新和 Rift 系列安全漏洞补丁发布，把仓库重新推上热榜。

## 趋势观察

这批项目凑在一起，指向一件事：大家不再比谁的模型强，开始比谁给 Agent 装的东西多。 最明显的是 SKILL.md、plugin.json 这类「技能清单」成了新标准。漏洞赏金方法论、开发流程、画图、搜索、Stitch 出设计稿、App Store 拒审规则，全被打包成技能包塞进 Claude Code 和 Cursor。Agent 不再是聊天框，而是被接上 CAD、Obsidian、Burp 的一双手。MCP 则成了通用接口，谁都来插一下。 第二个共同点是「先立规矩再干活」。superpowers 那套先问需求、写规格、再让子 Agent 分工 TDD，说明社区开始操心 Agent 一上来就乱写代码的毛病。 第三是往本地走。Firecrawl 出单文件 Rust 版，OpenSRE 自托管、用自己的模型，Notion+Miro 的替代品本地优先。大家不想再交订阅费，也不想把数据交出去。 还有一条暗线：把大模型拆开给人看。3090 上两小时训 64M 小模型，从预训练到 GRPO 全流程手写，教学需求在涨。 热闹背后是两个变化。一是分发渠道变了，编辑器插件位和技能目录就是新的应用商店，谁先占住谁定标准。二是开发者生态在分层，上面是模型厂，中间是 Cursor、Claude Code 这些壳，下面是一堆做垂直技能的个体户。 短期看，技能包会先泛滥再收敛，重复造轮子的要死一批。真正站得住的，是攥着独家数据或独家流程的，比如那 681 份漏洞报告、那套审核规则。至于 NGINX 回榜和 OpenVINO，是老基础设施在新叙事里重新露脸，不新鲜，但一直是底座。
