### [vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)

 `Rust` ⭐ +2,470 今日新增 · 15,713 总星数

> Vercel Labs 出的桌面操作 CLI：不截图，改为读取系统无障碍树，把界面转成带 ref 的 JSON，让 AI Agent 直接点击和输入，支持 macOS、Windows、Linux。

**亮点**

- 内部没有模型：只输出 JSON 结果报文，判断、重试、验证全在调用方 Agent 里，所以能搭配任意模型，也能被普通脚本直接调用；错误信息里还带 disposition.retry 字段，告诉调用方这次失败重试是否安全。
- Rust 编写的核心通过 PlatformAdapter trait 统一抽象，每个平台编译一个 crate，同一套命令在三种系统上共用；发布包还内置与版本对齐的技能文本（skills get desktop/platform），Agent 使用前先读规则，避免提示词和新版命令对不上。

**核心功能**

- 不截图也不做像素匹配，直接调用系统无障碍 API（macOS 的 AX、Windows 的 UI Automation、Linux 的 AT-SPI），把窗口读成 JSON 树，每个可操作元素带一个 ref，并标出可执行的动作（Click、SetValue 等）。
- ref 与 snapshot_id 绑定（形如 @s8f3k2p9:e8），界面一旦变化就返回 STALE_REF 或 AMBIGUOUS_TARGET，强制 Agent 重新快照再确认，形成“看，做，再看”的闭环，避免 Agent 在假想的 UI 状态上连续误操作。
- 默认无头运行：通过 ref 操作时走无障碍 API，不移动鼠标也不抢焦点，只有加 --headed 才用真实键鼠；同一套命令还能以 MCP 工具形式跑在 stdio 上（desktop_snapshot、desktop_click 等），MCP 客户端和脚本都能直接调用。

**适用场景**: 适合让 Agent 操作 Slack、Finder、Excel、内部管理系统这类桌面软件的团队，比如做 RPA、UI 自动化测试和后台办公流程；也适合接入 Cursor、Claude Desktop 等支持 MCP 的 Agent 客户端。

**竞品对比**: 对比 Anthropic computer use、OpenAI Operator、pyautogui 这类截图加坐标的方案，它不消耗视觉 token，也不需要多模态模型，但只对暴露无障碍树的 App 有效，Canvas 自绘界面和游戏基本没法用；纯浏览器场景下 Playwright MCP 更成熟。

**成熟度**: Vercel Labs 的实验项目，版本号还没到 1.0，API 和命令集可能变动；文档和错误码写得比较全，但没有商业支持承诺。

**趋势信号**: computer use 是当下 Agent 落地的热点，截图方案又贵又不稳，Vercel Labs 用无障碍树给出低成本替代路径，赶上了 MCP 生态扩散期，单日涨 2470 星。

### [NVIDIA/auto-ontology](https://github.com/NVIDIA/auto-ontology)

 `Python` ⭐ +2,050 今日新增 · 5,727 总星数

> 英伟达开源的语义本体层：从企业元数据自动生成知识图谱，把指标定义和血缘喂给 Agent，让自然语言转 SQL 不再是黑盒猜测。

**亮点**

- 取舍很明确：不追求“什么都能查”，而是用已认证的本体定义去约束生成，宁可查不出来也不给错数——这跟主流 text-to-SQL 拼命提高召回率的思路相反
- 把人工纠错回灌进本体，问得越多共享上下文越准，等于把每次修正沉淀成资产而不是一次性对话

**核心功能**

- 先做一次“语义编译”把本体建好，也就是把表、字段、指标定义、join 路径预先算成图谱；之后 Agent 提问时直接查图谱定位到具体的表和 join，不用每次现场猜 schema
- 回答强制带三样东西：生成的 SQL、走过的本体节点、数据来源血缘，人可以拿 SQL 回源库对数，错了能定位到是哪一步理解偏了
- 模型按角色拆成四路配置（reasoning 主力做 NL2SQL、non-reasoning 轻量模型只抽实体、embed 做向量、rerank 重排），每路一套 endpoint/key/model 环境变量，能单独换便宜模型压成本
- 对外只暴露 MCP / CLI / API 三种口子，本体本身不绑定 Agent 框架，任何 harness 都能接
- 本体存在 Postgres + pgvector 里，和它描述的 catalog 同库，省掉再维护一套向量库

**适用场景**: 面向数据平台/BI 团队：仓库里有几百张表、指标口径在各系统对不上、业务方天天问“上季度某产品在某州的收入是多少”却不敢信 AI 给的数。也适合正在搭 Agent 的开发者，通过 MCP 把可信数据上下文挂到自己的 agent 上。

**竞品对比**: 对标 dbt Semantic Layer、Cube、AtScale 这类语义层，以及 WrenAI、Vanna 这类开源 text-to-SQL。最大差异是它从现有元数据自动生成本体并原生走 MCP 输出，不是让你手写 YAML 模型；但它自带一套 Next.js 全栈应用，比纯库重得多。

**成熟度**: 早期项目：明确写着暂不接受外部贡献，跑起来必须申请 NVIDIA API key，版本号未到 1.0，API 和部署方式都可能变。

**趋势信号**: 单日 2050 星，基本是英伟达官方发布带动的——配套 Nemotron 模型和 MCP 生态一起推，正好踩在“Agent 能查库但数不敢信”这个当下最痛的点上。

### [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling)

 `Python` ⭐ +2,005 今日新增 · 96,961 总星数

> 一个 Python 库打通抓取全流程：HTTP 请求、隐身浏览器、解析、并发爬虫，还内置 MCP 服务让 AI Agent 直接调用。抓网页不用再拼 Scrapy+Playwright+BeautifulSoup 三件套。

**亮点**

- 把 MCP server 和 Agent Skill 做进抓取库本身，Agent 调用一次就完成'打开页面→剥掉导航广告→输出正文'，省掉自己拼 requests + BeautifulSoup 的一堆胶水代码
- 对付 Cloudflare Turnstile/Interstitial 靠的是在 C++ 层打补丁的 Firefox（Camoufox），改的是浏览器指纹本身，不是只在页面里注入 JS 改 UA

**核心功能**

- 三种抓取器共用一套解析 API：Fetcher 走快速 HTTP，DynamicFetcher 用 Playwright 渲染 JS，StealthyFetcher 基于改造版 Firefox（Camoufox）在底层改指纹；同一份 CSS/XPath 选择器代码在三者间通用，换抓取方式不用重写解析逻辑
- 自适应选择器：给元素存指纹（标签、属性、文本、层级），站点改版后按相似度重新定位同一个元素，减少爬虫因 DOM 变动直接失效
- Spider 内置代理轮换、AutoThrottle 自适应限速、失败重试、断点续爬（pause/resume）和 JSON/JSONL/CSV/XML 导出，整体异步并发跑

**适用场景**: 数据工程和增长团队做价格监控、竞品采集、批量线索抓取；以及给 AI Agent 做联网工具的人——在 Claude、Cursor 里通过 MCP 让模型自己抓页面并转成干净 Markdown。

**竞品对比**: 对标 Scrapy + scrapy-playwright + parsel 的组合：Scrapy 只管爬，浏览器渲染要装插件，解析另找库，三者 API 不统一；Scrapling 一个包一套 API 全包，还多出自适应选择器和 MCP。Apify 的 Crawlee 是同类，但生态偏 JS/TS，Python 侧不如它完整。

**成熟度**: 版本仍在 0.x，API 可能变动；但 CI 测试、ReadTheDocs 文档、10 种语言 README、Docker 镜像和 Discord 社区都在，中小规模生产可用。

**趋势信号**: 最近加了 MCP server 和 Agent Skill，还上架了 ClawHub/OpenClaw 技能市场，正好踩中 AI Agent 需要'自己上网抓数据'这波需求，单日 2000 星主要来自这里。

### [JiaFeiMiao-K-Cat/DiscImageStudio](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio)

 `C#` ⭐ +1,778 今日新增 · 6,816 总星数

> 用普通刻录机在 CD/DVD/BD 盘面上烧出肉眼可见的图案：把图片编码进光盘物理层（EFM/NRZI、ECC），跨平台 .NET 10 实现，带 WPF 图形界面和 CLI。

**亮点**

- 自带拍照标定流程：拍一张刻好的盘，估计内外半径和轨距的三次分布曲线，再反投影回去修正。README 里有校准前后实拍对比——恒定轨距时径向十字线明显弯曲，校准后接近直线

**核心功能**

- DVD 的做法是反解物理层：在 NRZI/EFMPlus 通道域做约束求解，让生成的数据同时满足 3T–14T 游程规则、纠错码和扰码，读出来就是一张黑白图（数据本身是合法的 DVD 镜像）

- 蓝光用 17PP 调制 + 3T/6T 映射 + ECC 簇，生成单层 25G 的 UDF 2.01 ISO；即时刻录走 MMC 顺序写入，边算边烧不落盘

**适用场景**: 想在可刻录盘上做盘面图案的收藏党和实体介质爱好者、做小批量实体唱片/周边的独立音乐人、以及研究光盘物理编码的工程师。用一台普通 DVD 刻录机加空白 Verbatim 盘就能出图，不需要 LightScribe 那种专用硬件。

**竞品对比**: 对标 LightScribe / LabelFlash 和 Yamaha 的 DiscT@2：前两者要专用刻录机和带涂层的盘，且只画标签面；DiscT@2 只在 CD-R 数据区边缘画一小条。这个用任意刻录机、任意盘，整面出图。

**成熟度**: 功能可用但仍偏早期：文档和物理模型复核写得很足，还有确定性自检回归，不过桌面端只支持 Windows，即时刻录明确标注实验性、实盘验证覆盖有限，建议先用可报废的盘试。

**趋势信号**: 时机上赶上了 .NET 10 发布窗口，加上实体光盘回潮的话题，README 里校准前后的实拍对比图在社交平台被转发，一天涨 1778 星。

### [mattpocock/skills](https://github.com/mattpocock/skills)

 `Shell` ⭐ +1,379 今日新增 · 313,719 总星数

> Matt Pocock 把自己 .agents 目录里天天用的 AI 编码 agent 技能（一堆 SKILL.md 提示词）开源出来，解决 agent 不懂需求、话太多、写出的代码跑不通这三类老毛病。

**亮点**

- 刻意做成小块可组合，而不是像 BMAD、Spec-Kit 那样接管整个流程；作者的理由是流程一旦被框架吃掉，流程本身出 bug 你没法修。
- 把领域驱动设计里的 ubiquitous language（团队和业务方说同一套词）搬到人机对话上：术语表既减少 agent 啰嗦，又让命名一致、检索更快，是这套东西里最实用的一招。

**核心功能**

- 技能全是纯 markdown 的 SKILL.md 文件，不写代码不搞 DSL，装进 agent 目录就生效，改起来跟改笔记一样。分发走两条路：Claude Code、Codex、Copilot、Gemini CLI 各自的插件市场自动更新，或用 npx skills 把可编辑文件拷进项目手改。
- 用一次性的 /setup-matt-pocock-skills 交互式配置，问你要用哪个 issue tracker（GitHub、GitLab、本地文件或你自己描述）、triage 时打什么标签、文档存哪，后续 /triage 等技能按这套约定跑。
- 核心手法是“共享语言”：/grill-with-docs 先让 agent 反问你需求，把项目黑话整理成术语表加 ADR（架构决策记录），之后变量、函数、文件名统一用这套词，agent 读代码和思考都省 token。

**适用场景**: 日常用 Claude Code、Codex 或 Cursor 写真实业务代码的工程师——开工前想让 agent 先把需求问清楚、重构时想要红-绿-重构的 TDD 节奏、手上 backlog 需要按标签批量 triage 的人。

**竞品对比**: 对比 BMAD-METHOD、GitHub Spec-Kit、GSD 这类重型流程框架，差异在“不夺权”：那边给你固定阶段和产物模板，这边只给你几个可随手改的提示词，不锁模型也不锁 IDE。对比 awesome-claude-code 之类技能合集，它胜在作者本人实战验证加统一的设计思路。

**成熟度**: 能用但不是软件意义上的稳定版：本质是提示词文本，没有语义化版本，内容会随作者习惯和模型升级频繁变，好在装了随时能改、删掉也没副作用。

**趋势信号**: 2025 年底 Claude Code、Codex、Copilot 相继上线插件与 skills 机制，agent 技能从复制粘贴提示词变成可安装分发的包；加上作者 6 万人 newsletter 的分发力，这套“反重型框架”的轻量方案正好踩在大家对 Spec-Kit 式流程疲劳的节点上。

### [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

 `TypeScript` ⭐ +1,172 今日新增 · 113,080 总星数

> 给编码 Agent 加持久记忆：自动录下会话里的每次工具调用，用 LLM 压成摘要，下次开新会话时把相关部分塞回 context。解决 Agent 关掉就失忆的问题。

**亮点**

- 不存原始对话记录，只存 LLM 压缩后的“观察”，把存储和注入成本压到原始 transcript 的一小部分——这是它能长期挂着而不炸 context 的核心决策。

- 靠宿主 IDE/CLI 的 hook 自动采集会话中每一次工具调用（读文件、改代码、跑命令），不用人手动记笔记；会话结束交给 LLM 压成结构化的“观察”条目，分决策、修 bug、安全告警几类。
- 记忆按天追加到纯文本的 memory/log/YYYY-MM.md，下一次会话启动时按相关性挑选注入，而不是把历史对话整段塞回去——注入量可控，这是它省 token 的关键取舍。

- 做了一层跨 Agent 适配：有 hook 的（Claude Code、Codex、Copilot、OpenCode）挂 hook，没 hook 的（Grok Bot）退化成一件事——监听聊天日志文件的变化。同一套记忆格式对上多家客户端。

**适用场景**: 每天用 Claude Code / Codex 写代码的开发者：昨天让 Agent 摸清的那个 20 个文件的模块，今天开新会话不用重新解释一遍。 团队想给多个 Agent 客户端（Claude Code + OpenCode + Copilot）共用一份项目记忆，避免每个工具各记一套。

**竞品对比**: 同类有 mem0、Letta（原 MemGPT）、Cipher、basic-memory，以及最土的手写 CLAUDE.md。最大差异是它不做通用记忆层，直接绑在编码 Agent 的 hook 上做无感采集，开箱即用；代价是深度耦合各家客户端的 hook 接口。

**成熟度**: 版本已到 15.9.0，多语言文档齐全、适配了十来个 Agent 客户端，可用；但发版节奏极快、API 和配置项常变，且核心记忆能力绑了商业托管服务（CMEM Pro，30 天试用后回落），介意依赖的要留意。

**趋势信号**: 编码 Agent 普及后“每次新开会话都从零开始”成了最普遍的抱怨，而它最近连续跟进了 OpenCode 2、T3 Code、Grok Bot 等一批新冒出来的 Agent 客户端，踩中了这波客户端碎片化的窗口。

### [floci-io/floci](https://github.com/floci-io/floci)

 `Java` ⭐ +1,090 今日新增 · 29,816 总星数

> 一个用 Java 写的本地 AWS 模拟器，跑在 4566 端口，换掉 LocalStack 镜像就能用，MIT 免费、无账号无功能锁，用来在本地和 CI 里跑 S3、DynamoDB、Lambda 等。

**亮点**

- 定位是“假 AWS 端点”而不是代理：任何已发布 region 和 partition 都接受，凭据填任意非空值就行，默认不做鉴权，省掉本地配 IAM 的一堆配置。
- 同一套设计拆成四个仓库覆盖 AWS/Azure/GCP/OCI，端口 4566/4577/4588/4599 对齐，多云端测试能共用一套工具链。

**核心功能**

- 所有服务共用 4566 一个端口，靠请求里的服务标识分流；端口和 LocalStack 完全一致，只改镜像名、不动 AWS_ENDPOINT_URL 和代码就能迁移。
- 对保真度要求高的服务（如 Lambda）直接开真 Docker 容器执行，而不是返回写死的假响应；代价是必须挂载 /var/run/docker.sock。

> Horizon 是一个开源的 AI 新闻雷达：它自动抓取你订阅的信息源，由大模型筛选、打分并改写，每天生成中英双语简报，并以静态网页的形式发布。现在火，是因为它同时支持接入多种模型，还能用 GitHub Actions 零成本运行。

**亮点**

- 这个项目用自己每天产出的简报支撑自己的站点（dogfooding）：Daily workflow 跑完就部署，等于一个每天自动更新的活 demo，你能先去官网看效果再决定要不要用
- 全流程没有常驻服务：纯 CI + 静态托管，运行成本接近 0，也不会因为你忘记维护服务器而停摆

**核心功能**

- 模型适配层统一走 OpenAI 兼容接口：Claude、GPT、Gemini、DeepSeek、豆包、MiniMax 可以随时切换，也能接 Ollama 跑本地模型，因此不会绑定某一家 API 或某一种计费方式
- 靠 GitHub Actions 定时触发（仓库自带 Daily workflow），抓取、调用模型、生成 Markdown、构建并部署到 GitHub Pages 全在 CI 里完成，不用买服务器，也不用维护数据库
- 一份输入同时产出中英文两版简报，通过 prompt 层面的双语文案控制，而不是跑两遍流程
- 信息源以 RSS/Atom 为主，仓库开着「sources welcome」入口，靠 PR 众包扩充源列表

**适用场景**: 适合每天要追某个垂直领域（AI、前端、量化、生物医药）动态的开发者、研究员和投研人员：把常看的博客、公众号 RSS、arXiv 订阅填进配置，第二天早上直接读一份已经去重、排序、写好的双语摘要，不用自己刷十几个站点。

**竞品对比**: 对标的方案是 Feedly AI 或 Inoreader 这类带 AI 摘要的 RSS 阅读器，以及 Follow（RSSHub 生态的阅读器）。最大差异是：Horizon 不做信息流，只交付一份已经写完的成稿；模型能自己换，数据也不进入别人的服务器。相比手写 RSS + ChatGPT 的脚本，它把定时调度、去重、双语排版和发布都打包好了。

**成熟度**: 有独立文档站、双语 README、Trendshift 和 HelloGitHub 的推荐，1.2 万星说明社区关注度不错，但本质仍是个人主导项目，接口和配置格式可能随版本调整，建议先在 GitHub Actions 里试跑再长期依赖。

**趋势信号**: 近期同时出现在 Trendshift 日榜和 HelloGitHub 推荐位（README 里挂着这两个徽章），叠加「多模型可切换 + 一键 Action 部署」这个组合正好契合 2025 年个人 AI 信息助理的需求，因此带来了一波集中曝光。

### [MichaelCade/90DaysOfDevOps](https://github.com/MichaelCade/90DaysOfDevOps)

 `Shell` ⭐ +97 今日新增 · 30,600 总星数

> 一份按天打卡的 DevOps 学习路线图，从 2022 年起每年一个主题（DevOps、DevSecOps、社区分享），已积累 110k 字正文加 91 场 YouTube 社区分享，全部免费开源。

**亮点**

- 刻意做成必须按顺序学的固定课表，避免常见『收藏了一堆链接但学不完』的收藏夹 Github 项目困境，降低选择难度。
- 作者自己公开从零学习的记录，不假装自己是专家，这种『边学边写』的做法反而让新手更愿意跟着学，也让资深读者愿意来纠错。

**核心功能**

- 按年份分卷的线性课表：2022 年 90 天基础（原则、流程、工具），2023 年 DevSecOps，2024 年社区版 91 场分享；每年一个 2022.md、2023.md、2024.md 索引页，把读者按顺序推进课程，不让人自己选择学什么。
- 内容是正文加视频的双轨形式：每天一篇 Markdown 笔记，配合 YouTube 上的社区分享会话，读不下去时可以直接看录像。
- 靠 PR 做社区维护：不同语言的读者提交翻译和勘误，作者按贡献者反馈修改内容，作者本人不单独把关，把内容质量交给社区评审。
- 采用 CC BY-NC-SA 4.0 许可，允许转载和修改，但禁止商用；作者明确声明不接受厂商赞助，工具全部是免费或开源软件。

**适用场景**: 面向想转行做运维、SRE 或云原生的人，从零开始按天完成入门学习；也适合团队新人当入职培训大纲，或培训讲师当免费课程素材。

**竞品对比**: 和 roadmap.sh 相比：roadmap.sh 给的是知识地图，节点之间没有顺序，也不告诉你先学哪个；这个项目给的是有先后顺序的天数课表。和 KodeKloud、A Cloud Guru 相比：那些是付费实验环境，这个项目只有文档和视频，没有动手实验的沙箱环境。

**成熟度**: 内容类项目，账号已稳定维护 3 年以上、30k star；但能否继续更新，取决于作者是否还会推出 2025 版，新版发布没有固定节奏。

**趋势信号**: 原因不明——它不是代码库，没有版本发布，可能因为跨年学习计划季被推荐，或出现在某份 DevOps 学习清单里；没有可查的具体事件。

## 趋势观察

今天这份榜单，一半项目都在干同一件事：给 AI 编码 Agent 打地基。 Worktrunk 解决多个 Agent 并行跑任务时互相踩文件。持久记忆项目解决 Agent 一关就失忆。Vercel 的桌面 CLI 不截图，改读系统无障碍树，让 Agent 真的能点、能输入。Spec Kit 把「先写规格再写代码」做成斜杠命令。Garry Tan 的 23 个命令，把写代码拆成 CEO、设计、评审、QA 的流水线。这不是模型变强了，是大家发现模型再强，工程护栏不补上就是白费。 第二个共同点：上下文不再靠猜。英伟达开源语义本体层，把指标定义和血缘喂给 Agent，自然语言转 SQL 才有据可依。抓取库内置 MCP，技能包先报价再生成，MCP 正在变成 Agent 和外部世界之间的统一接口。 第三，自主控制的意识起来了。Java 写的本地 AWS 模拟器直接替掉 LocalStack，代码评审机器人主打自托管、自带 API Key，Horizon 用 GitHub Actions 零成本跑。开发者不想把数据和账单交出去。 也有相反的方向。一边是所有人往 Agent 流水线上不断添加工具，另一边有人用纯 C99 在单核 CPU 上跑 2.78 万亿参数模型，8 GB 内存，不用 GPU。还有拿刻录机在光盘上烧图案的。这才是开源社区一贯的样子：主流叙事越热，越有人往反方向走。 一句话：开发者生态已经从「看模型能干什么」，进入「怎么把模型管起来」。规范、记忆、权限、成本，这些不引人注目的词，正在变成真正的竞争点。
