### [vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)

 `Rust` ⭐ +3,791 今日新增 · 13,349 总星数

> Vercel Labs 出的桌面版 computer use 工具：走操作系统无障碍树读界面并操作，不截图不猜坐标，给 AI agent 提供 CLI 和 MCP 接口。

**亮点**

- 工具内部没有模型：CLI 只负责「看」和「做」，决策循环留在调用方 agent 里。所以不绑定任何 LLM 厂商，也不额外烧推理 token
- 二进制里打包了跟版本匹配的用法文档（skills get desktop / platform），agent 自己读，不用往 prompt 里塞会过期的说明

**核心功能**

- 直接调系统无障碍 API 读界面——macOS 用 AX API、Windows 用 UI Automation、Linux 用 AT-SPI，把窗口树转成带 ref 的 JSON，每个可操作元素一个 ref，agent 按 ref 点击/输入，全程不截图、不做像素匹配
- ref 自带 snapshot_id（如 @s8f3k2p9:e8），界面一变就返回 STALE_REF 或 AMBIGUOUS_TARGET，逼 agent 走「操作→重新快照→校验」的闭环，防止盲点；裸 @e8 直接报错
- 默认 headless，事件直接注入目标控件，不移动鼠标不抢焦点，加 --headed 才用物理输入；同一份 Rust core 通过 PlatformAdapter trait 按平台编译，另有 C FFI 供进程内调用

**适用场景**: 想让 agent 直接操作桌面软件的团队：自动填 ERP/CRM 表单、批量整理 Finder/资源管理器文件、跑桌面端 UI 回归测试。接入方式是 Claude Code、Cursor 这类支持 MCP 的 harness，跑 agent-desktop mcp 即可。

**竞品对比**: 和 Anthropic Computer Use、OpenAI Operator、OmniParser 这类截图+视觉定位方案比，它不猜坐标，拿的是元素语义和可用动作列表，省 token 也稳；和 Playwright（只管浏览器）、pywinauto/Appium（单平台、无 agent 接口）比，它跨三平台且输出专为 agent 设计。短板是无障碍树覆盖差的 app（自绘 UI、游戏、部分 Electron 应用）会抓不到元素。

**成熟度**: 文档站、npm、Homebrew、GitHub Release 原生包都齐了，但仍是 Vercel Labs 实验产品，部分命令和平台能力标注为「拒绝执行」，API 可能变动。

**趋势信号**: computer use agent 正热，但截图方案又贵又不稳；Vercel Labs 此时放出无障碍树路线并自带 MCP server，正好赶上 Claude Code、Cursor 等 MCP 生态爆发。

### [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling)

 `Python` ⭐ +1,658 今日新增 · 95,271 总星数

> Scrapling 是一个 Python 爬虫框架，把单次请求、JS 渲染、反爬浏览器、解析和并发爬取装进一个库，并额外提供 MCP 服务器让 AI Agent 直接调用它抓网页。

**亮点**

- 解析层同时给 CSS、XPath、文本和正则四种选择器，并且和 fetcher 层解耦：同一套选择器代码，换成普通 HTTP 还是隐身浏览器都不用改
- 把 MCP server 和 Agent Skill 做成一等公民，还上架了 OpenClaw 的 skill 市场。等于把爬虫框架直接改造成 Agent 的一个工具，而不只是给人用的库

**核心功能**

- 自适应元素追踪：网站改版、class 名或 DOM 结构变了之后，能按元素特征在页面上重新定位原来的目标，不用每次手改选择器
- 自带隐身浏览器 fetcher，处理 Cloudflare Turnstile/Interstitial 这类人机校验，还能在后台捕获页面发出的 XHR/API 请求，直接拿到数据接口而不是解析 HTML
- Spider 支持并发、代理轮换、失败重试、AutoThrottle（自动降速避免被封）、断点续爬和流式输出，结果可直接导出 JSON/JSONL/CSV/XML 或干净的 Markdown

**适用场景**: 数据采集工程师和做 RAG/AI Agent 的开发者。前者用它替换 Scrapy+Playwright 两套东西搭爬虫；后者通过 MCP 让 Claude 之类的 Agent 自己去浏览网页、把整站抓成 Markdown 喂进知识库。

**竞品对比**: 对比 Scrapy：Scrapy 强在调度和中间件生态，但不带浏览器和反爬；Scrapling 一个库全包。对比 Crawl4AI：后者主打给 LLM 输出 Markdown；Scrapling 的差异是隐身浏览器加上自适应选择器，更偏工程化的反爬和数据抽取。

**成熟度**: 已有 PyPI 包、Docker 镜像、CI 测试和 10 种语言的文档，Discord 社区在运营，能直接上生产；但迭代很快，小版本之间 API 可能变。

**趋势信号**: 赶上 AI Agent 抓网页这波需求：新加的 MCP server、Agent Skill 和 OpenClaw 上架，让它在 Claude/Agent 生态里被反复推荐。

 `Shell` ⭐ +1,164 今日新增 · 311,757 总星数

> Matt Pocock 开源了自己 .agents 目录里的编码 Agent 技能包（SKILL.md 提示词文件），教 Claude Code、Codex、Copilot 这些 Agent 按"先问清需求、再写失败测试、最后改代码"的正经路子干活，而不是靠感觉写代码。

**亮点**

- 明确反"流程框架"路线：GSD、BMAD、Spec-Kit 是接管你的整个研发流程，它是给你几个能拆能改的小提示词，出问题你能直接读文件改，不用跟框架黑盒较劲

**核心功能**

- 技能全是纯 Markdown 的 SKILL.md，不写代码只写流程；体量小、可读可改，作者明说"随便 hack 成你自己的"，且不绑定模型，Claude、GPT、Gemini 都能跑

- 装一次 /setup-matt-pocock-skills，它会问你用哪家 issue tracker（GitHub、GitLab、本地文件）、triage 时打什么标签、文档存哪，把后续技能接到你现有工作流上，而不是另起一套

**适用场景**: 天天用 Claude Code / Codex / Cursor 写真实项目的前端和全栈工程师。典型场景：需求还模糊时先 grill 一轮对齐，再把 ticket 丢给 /triage 分类，然后 /tdd 一步步实现，避免 Agent 一把梭出个没法 review 的大 PR。

**竞品对比**: 对手是 BMAD、GSD、Spec-Kit 这类重型 Agent 工作流框架，以及社区零散的 awesome-prompts 合集。最大差异是它不做框架、不做编排，只给可编辑的 Markdown 技能，且按 Claude Code、Codex、Copilot、Gemini CLI 各自的插件市场分别提供安装命令。

**成熟度**: 早期但已是作者日常自用并配了自动更新的插件市场和 newsletter，文档和安装说明写得比多数同类项目细；版本号和向后兼容性没承诺，技能随时会改。

**趋势信号**: Claude Code 插件市场、Codex 和 Copilot 的 plugin marketplace 刚铺开，Agent 技能（skills）正在成为跨工具的通用分发格式，作者本人又是 TypeScript 教育圈大 V（60k 订阅），一发就被大量转推。

### [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

**亮点**

- 一个安装器适配多个宿主：自动找每个 IDE 的配置目录、注册原生插件、没有 hook 就降级成文件监听，同一份记忆跨 Claude Code / OpenCode / T3 Code / Gemini 复用

**核心功能**

- 挂在宿主的 hook 上自动抓每次工具调用（读文件、跑命令、改代码），不用人手动记笔记；对没有 hook 的宿主（如 Grok Bot）改成监听聊天日志文件落盘
- 把抓到的操作交给模型压成语义摘要，打上 decision / bugfix / security_alert / sensitive 等类型标签，按日期追加进 memory/log/YYYY-MM.md 纯文本日志

**适用场景**: 同一仓库上同时用 Claude Code、OpenCode、Codex 的开发者——换会话、换工具、隔天回来都不用重述项目背景；做长周期重构或追老 bug 时，让 Agent 记得上次为什么这么改。

**竞品对比**: 对比 CLAUDE.md、Cursor rules 这类手写规则文件，它是自动采集、不用人维护；对比 mem0、Letta\(MemGPT\)、basic-memory 这类通用记忆层，它绑定编码 Agent 的 hook 和工具调用事件，颗粒度是'改了哪个文件、跑了什么命令'而不是聊天内容。

**成熟度**: 版本已到 15.9.0，文档覆盖 30 种语言、安装器做得比较完整，生产可用；但默认托管记忆是商业服务（30 天试用后可能转付费），不想付钱得自己配 OpenRouter/Gemini key。

**趋势信号**: 2026 年编码 Agent 从单工具变成 Claude Code + Codex + OpenCode 混用，各家上下文窗口仍不够，'跨会话不丢记忆'成了共同缺口；项目近期又补了 Grok Bot、T3 Code 等新宿主适配，正好赶上这波。

### [JustVugg/colibri](https://github.com/JustVugg/colibri)

 `C` ⭐ +802 今日新增 · 47,397 总星数

> 纯 C 写的 MoE 推理引擎，把专家按热度分放显存、内存和 NVMe，9.9GB 常驻内存跑起 744B 模型，没有大显存也能本地推理。

**亮点**

- 思路是“显存不够就分层”，不是“显存不够就降位宽”：权重不整体压到更低精度，而是靠专家换入换出解决，代价变成磁盘随机读带宽，精度不损失
- 一个模型家族一个 C 文件、直接吃现成 GGUF——放弃通用推理框架的抽象层，换零依赖、可交叉编译、在任何有编译器的机器上自举

**核心功能**

- 按 token 激活频率把 MoE 专家分三级：经常用的常驻 GPU 显存（CUDA/Vulkan），次热门的放在 RAM，冷门专家按需从 NVMe 流式读入，用换入换出换显存——示例里 744B int4 模型常驻只占 9.9GB、32 秒起来
- 纯 C 实现，每个模型家族一个独立源文件（GLM、Kimi、DeepSeek、Qwen、OLMoE 等共 13 个引擎），不依赖 PyTorch/Python 运行时；同一份 GGUF 权重不转换，直接在 CPU、Vulkan、CUDA 三套后端上跑
- 安装器先探测 RAM、剩余磁盘、CPU 和 GPU，用“常驻部分 + 最小专家缓存必须塞进内存”倒推能跑哪个模型；缺编译器就下预编译二进制，模型下载支持断点续传；跑起来后同时提供 OpenAI 兼容 /v1 和 Anthropic 兼容接口，外加 MCP server 供 AI 助手调用

**适用场景**: 手上只有 8–16GB 内存的笔记本或单卡工作站、又不想把数据发到云上的个人开发者和中小团队。典型用法是把本地模型接到 Cline、Cursor 这类 IDE 助手或内部 Agent，用 OpenAI 兼容地址直接替换云端 API。

**竞品对比**: 对手是 llama.cpp / Ollama 和 ktransformers：前者靠 mmap 让操作系统页缓存被动换页管理专家，后者做 CPU+GPU 算子级卸载但框架重、依赖 Python。colibri 最大差异是自己实现显式的 GPU/内存/NVMe 三级专家缓存调度，全 C、无 Python 运行时。

**成熟度**: 版本已到 v2.1.0，安装器和多语言文档比较完整，但 13 个模型引擎意味着大量手写适配代码，公开的测试覆盖和 issue 响应数据看不到，先按实验性方案评估。

**趋势信号**: 开源 MoE 模型参数冲到几百 B，消费级硬件彻底装不下，“本地跑大模型”的痛点集中爆发；但 README 点名的 GLM-5.3、Kimi K3、DeepSeek V4 等版本号看起来都还没公开发布，热度里可能掺了占位和炒作。

### [p-e-w/heretic](https://github.com/p-e-w/heretic)

 `Python` ⭐ +701 今日新增 · 38,983 总星数

> 不用训练就能改开源大模型的行为：自动搜出一组权重消融参数，把拒答、废话、谄媚这些毛病压下去，单张 3090 半小时搞定。

**亮点**

- 把「消融」从一次性的手工手术变成了带目标函数的黑盒优化问题：以前要人工挑方向、挑层、挑系数，现在只描述想要什么（用 scorer 打分），参数交给 TPE 搜
- 用 KL 散度作为副目标做约束，显式控制「改得多狠」和「模型别退化」之间的取舍，这是它比其他 abliteration 脚本更容易保持 MMLU/GSM8K 成绩的关键

**核心功能**

- 用 Optuna 的 TPE 贝叶斯优化在消融参数空间里搜索，目标函数是「拒答关键词命中率尽量低 + 与原始模型的 KL 散度尽量小」，也就是既要去审查又要防止模型变傻，参数不靠人手调
- 默认的 Arbitrary-Rank Ablation（ARA）不再只沿单个方向向量做 rank-1 消融，而是在权重上做任意秩的子空间消融，并对各层加一个可调的权重核，自由度比以前的手工 abliteration 高很多
- scorer 和 modifier 都是插件：写一个继承 Scorer 的类实现 get_score 就能定义新目标，路径可以写成模块名或 path.py:ClassName，不用改包源码。官方已带拒答率、KL 散度、去废话、去幽默、去谄媚几套配置
