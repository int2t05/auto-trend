# GitHub Trending 日报 · 2026-11-14

## 概览

今日共收录 **12** 个 GitHub Trending 项目。
主要语言分布：TypeScript(4)、Go(2)、Python(2)、C++(1)、Rust(1)。

今天这批项目有个很明显的共同点：大家不再比谁的模型会写代码，而是在比谁能把 Agent 塞进真实的工作流程里，还让人放心。 第一类是给 Agent 补基础设施。阿里开源代码审查 CLI，把选文件、配规则这类确定性活儿交给流水线，LLM 只做动态判断，图的就是评论准、省 token。OpenAI 亲自下场做安全扫描，扫仓库、验漏洞、出带证据的补丁。Chrome 联手 Edge、Firefox、MDN 发技能包，直接往编码助手的上下文里塞现代 Web API，让它别再用十年前的老写法。Chrome DevTools 也出了 MCP 服务器，Agent 改完前端能自己开真浏览器验证。这些动作说明，大厂开始抢的不是模型，而是 Agent 的接口标准和工作流入口。 第二类是人和 Agent 的协作界面。有项目专门做本地浏览器审阅层，Agent 出的计划、diff 直接在网页上标注回灌。多 Agent 并行时，人的审阅成了瓶颈，这个位置正被工具填上。Block 那个用 Nostr 统一人和 Agent 身份的做法，也是同一个思路。 第三类是自托管替代付费 SaaS。监控工具一条 docker run 就跑，Maybe Finance 被社区接手继续做，Tailscale 把数据面拆成不用账号、不用 root 的 netcat。省钱、可控、能自己改，是这批人的共同诉求。 还有一类是垂直场景的流水线。股票分析、散户交易复盘，都把流程拆成技能和 YAML 工作流，强调不喊单、可复盘。 总的看，热点从「模型能力」转向了「可靠交付」。关键词是省 token、可验证、留证据、能复盘。开发者生态正在围绕 Agent 干活这件事，重新搭一遍水电煤。

### [tailscale/tailcat](https://github.com/tailscale/tailcat)

 `Go` ⭐ +256 今日新增 · 9,568 总星数

> Tailscale 官方把自家 magicsock 数据面拆出来做成 netcat：两端靠一个短地址带外交换连接信息，DERP 引导加 NAT 打洞，WireGuard 端到端加密，不用账号、不用 root。

**亮点**

- 把'控制面'降级成一次人工复制粘贴：短地址同时承载身份公钥和打洞引导信息，等价于把协调服务器换成了聊天软件，换来零账号、零配置、零基础设施
- 内置 SSH 服务端直接用本地 authorized_keys、命令行里的公钥行或 GitHub 的 user.keys 做认证，并明确拒绝 command=、from= 这些它实现不了的选项，避免给人错误的安全预期

**核心功能**

- 复用 Tailscale 的 magicsock：先用 DERP 中继完成握手和 NAT 打洞，打通就升级成点对点 UDP，打不通自动退回 DERP 中继，全程 WireGuard 加密
- 砍掉控制面：连接元数据（对端公钥、DERP 引导信息等）编码进一个短地址字符串，用户自己贴到聊天窗口或邮件里传给对方，没有协调服务器和账号体系
- 纯用户态：不改路由表、不改 DNS、不要 root、不要 Tailscale 账号，单个二进制覆盖 Linux/macOS/Windows/BSD，还能编译成 WebAssembly 在浏览器里收发文件和文本，和 CLI 互通
- CLI 把隧道包装成日常用法：serve/forward/browse/ssh，端口映射支持 5555:10.2.200.213:5555 这种把内网另一台机器的端口代理出来，不用开 exit-node 暴露整个网段

**适用场景**: 运维和开发临时把内网端口、跳板机 SSH、局域网里安卓设备的 adb 端口给远端的同事用；也适合没有管理员权限、装不了 Tailscale 客户端的机器，或 CI 里两台机器之间传文件。

**竞品对比**: 和 ngrok 比，打洞成功时流量是端到端直连、不经过厂商服务器，也不用注册账号；和 croc、magic-wormhole 的短码思路接近，但它是通用 TCP 通道加端口转发，不只是传文件；和 Tailscale 本身比，少了身份管理、ACL 和 DNS，全靠人工传地址。

**成熟度**: Tailscale 官方出品，deb/rpm/brew/scoop/snap/nix/AUR/conda 打包齐全，但仍是早期项目，浏览器端只能走 DERP 中继，WebRTC 直连还没做（issue #4），API 可能变。

**趋势信号**: 官方用'Tailscale without Tailscale'这个梗发布，把自家数据面单独拿出来做通用工具，还顺手给了个能在浏览器直接试的 WASM demo，当天就能玩起来，所以被大量转发。

### [Likely7/Veyra-NRVideo](https://github.com/Likely7/Veyra-NRVideo)

 `C++` ⭐ +256 今日新增 · 1,713 总星数

> Windows 上的实时 GPU 视频增强播放器：本地视频、采集卡、PS5/Xbox/Moonlight 串流都能接入，在显卡上直接完成超分、降噪、补帧和 HDR。

**亮点**

- 播放器、采集、增强、录制都放在一个应用里：同一套效果链既能用于本地视频，也能用于采集卡和 Moonlight/Sunshine 串流，省去了 madVR + OBS + 录制软件来回切换的麻烦
- 把 madVR 那类滤镜图变成了可视化节点编辑：每个降噪层可以单独调整参数，节点之间可以真正连成执行链，还能保存成会话和预设以复用

**核心功能**

- 整条处理链都留在显存中：DirectX 12 把播放器帧、WGC 屏幕或采集卡帧直接送入 GPU，超分→降噪→补帧→HDR 依次在显卡上执行，不回到 CPU 中转
- 超分和降噪使用现成推理模型，不自行训练：可调用 RTX Video SR（RTX20~50 系）、AMD lmxxf / RedDuke 降噪模型，或 DLSS / XeSS / FSR；还支持二次超分后再降采样到目标分辨率，并在启动前检查显存占用预算
- 补帧用去重加锚点插值的方式实现：容忍稀疏噪声的全帧去重、平滑运动锚点、可选的 VFG 调节，自适应 VSync 最多等待 3ms，避免帧队列堆积造成卡顿
- 降噪做成可叠加的层，每层有独立的强度、颜色和时序稳定参数，还能用节点图连接多条超分链路；效果设置会与导出录制共用

**适用场景**: 适合手上有 PS5 / Xbox / 采集卡、想把 1080p60 的画面实时拉到 4K 或补到 120 帧的玩家和主播；也适合想修老片、做实时降噪加放大，又不想折腾 madVR + mpv 配置文件的人，处理完可直接录成带音轨的 MP4/MKV。

**竞品对比**: 对比 madVR/mpv，它的画面处理效果未必更细腻，但界面操作更简单，并且增加了采集和串流输入；对比 Lossless Scaling，它不只处理游戏窗口，而是处理整条视频流；对比 Topaz Video AI，它主打实时处理，并非离线精品修复。

**成熟度**: 已发布到 2.1.6，2.1.x 版本连续迭代，发布非常密集，累计下载量超过 10 万，提供中文、英文、日文文档和 Wiki；但核心推理模型依赖第三方，ANR 运行时不随安装包分发，README 标题明显夸大，建议当作“能用但需要试错”的工具，不要按生产软件对待。

**趋势信号**: 标题直接借用了 GTA6 和“DLSS 5”两个热门词（PS5 GTA6 跑 120FPS），又赶上 2.1.x 连续发布补帧和双超分功能，被玩家社区转发，推上了趋势榜。

### [alibaba/open-code-review](https://github.com/alibaba/open-code-review)

 `Go` ⭐ +215 今日新增 · 50,826 总星数

> 阿里把内部用了两年、几万开发者用过的 AI 代码审查 CLI 开源了：确定性流水线负责选文件、配规则、定位评论，LLM Agent 只负责动态决策，主打评论准、省 token。

**亮点**

- 明确取舍：主动放弃召回率，只报高置信度的真缺陷。官方 AACR-Bench（50 个开源仓库、200 个真实 PR、10 种语言、1505 条人工标注）上，同模型下 F1 和精确率高于 Claude Code，token 只花约 1/9，代价是漏报更多
- 架构上把“必须正确”的部分从模型手里拿回来：文件选择、规则匹配、评论定位全是代码保证，prompt 只用于动态检索和判断，等于给 LLM 套了硬约束

**核心功能**

- 确定性流水线先做三件“不能错”的事：挑出该审的文件、按特征用模板引擎匹配规则、把相关文件打包成一个评审单元（比如 message_en.properties 和 message_zh.properties 绑在一起），每个包是一个独立上下文的子 Agent 并发跑，大 changeset 不会漏文件
- 评论的定位和内容由独立的“定位模块 + 反思模块”二次校正，不靠 LLM 直接吐行号，减少报错位置漂移
- 内置多语言缺陷规则集（NPE、线程安全、XSS、SQL 注入），Agent 能读完整文件、搜代码库、翻其他改动文件补上下文，接口兼容 OpenAI 和 Anthropic，也能挂在 Claude Code / Codex / Cursor / Kimi Code 里跑

**适用场景**: 适合中大型研发团队的 PR 审查和 CI 门禁——后端、基础架构团队在几十上百个文件的合并请求上跑它，减少人工过一遍假警报的时间；也支持 `ocr scan` 全文件扫描，用来审计不熟悉的代码库。

**竞品对比**: 对标 Claude Code + Skills、CodeRabbit、Cursor BugBot、GitHub Copilot code review 这类方案。最大差异是它把“确定性工程 + Agent”做成显式架构，而不是纯 prompt 驱动，宣称更少误报和更低 token 成本；但召回率不如通用 Agent，属于精度优先路线。

**成熟度**: 阿里内部跑过两年、服务数万开发者，OpenSSF Gold 认证，开源版刚放出，npm 版本号和 API 可能仍在调整。

**趋势信号**: Claude Code、Codex 这类通用 Agent 今年成了主流，团队想拿它做 code review 但被漏文件、位置漂移、成本高劝退，阿里正好在这个节点把内部验证过的“工程约束版”开源出来。

### [backnotprop/plannotator](https://github.com/backnotprop/plannotator)

 `TypeScript` ⭐ +108 今日新增 · 10,559 总星数

> 给 AI 编码 agent 做的本地浏览器审阅层：agent 出的计划、HTML、diff 直接在网页里标注评论，一键回灌给 agent。多 agent 并行时人的审阅成了瓶颈，它正好补这个位置。

**亮点**

- 反馈是闭环的：你在页面上标的行内注释会直接回灌成 agent 下一轮的输入，而不是导出个文件让你自己贴回去，省掉最容易出错的那一步
- Inbox 的非阻塞设计：agent 问完问题不用挂着 session 等你，回复异步送回原来那个会话，等于把 agent 的等待时间从人的响应时间里摘出去

**核心功能**

- 通过各家 agent 的 hooks / 插件 / 斜杠命令接入（Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、Pi），agent 一产出 plan 就自动弹浏览器审阅页，不用手动复制粘贴到别处
- Inbox 把多个 agent 的提问、文件、待审内容收进一个本地收件箱：agent 发完消息就继续干活，不阻塞等回复，你回完的内容作为它下一轮输入送回去；Claude Code / Pi / OpenCode 走自家插件，其他 agent 通过 `plannotator inbox mcp` 这个 MCP 服务接入
- 代码审阅做了 VCS 后端抽象，同一套 diff 界面能吃 Git 未提交改动、GitHub PR、GitLab MR、GitButler 工作区/stack/分支层、Jujutsu\(jj\)、Perforce，也能直接吃一个静态 unified diff 文件
- HTML artifact 是真渲染出来再标注（`--render-html`），不是先转成 markdown 再标，所以交互式原型、报表这类东西能按原样看

**适用场景**: 同时开好几个 Claude Code / Codex / Gemini CLI 会话的开发者：一边让 agent 写代码，一边在浏览器里批注计划文档和 PR diff，评论直接变成 agent 的下一轮指令。也适合要 review 同事 PR 但不想在 GitHub 网页里来回切的人。

**竞品对比**: 对比 Claude Code / Codex 终端里自带的 plan 审批和 diff 确认（只能在终端里 y/n，注释很别扭），以及 GitHub PR 网页评论、Cursor 的逐块接受 diff——Plannotator 的差异是跨 agent、跨版本控制系统，且标注粒度高、结果还能回灌给 agent。

**成熟度**: 可以用起来了：一万多星、官方站点和文档齐全、接了十来种 agent，但 Inbox 这类模块刚上线，命令和接口还在快速变。

**趋势信号**: 多 agent 并行写代码变成常态后人成了瓶颈，社区正好缺一个"统一收件箱 + 审阅层"，它新发的 Inbox 加上一口气覆盖几乎所有主流 CLI agent，踩在这个点上。

### [block/buzz](https://github.com/block/buzz)

 `Rust` ⭐ +97 今日新增 · 37,355 总星数

> Block 开源的自托管协作空间：人和 AI Agent 用同一套 Nostr 签名事件与身份，消息、代码补丁、CI、审批、搜索都在同一条日志里。

**亮点**

- 用一个事件日志当唯一底座，把聊天、forge、CI、发布、搜索压成一套 substrate（底层），代价是所有东西都得先建模成事件，做不了特例。
- 自托管默认一个 relay 对应一个社区；多租户托管时共享 Postgres、Redis、对象存储，但把租户边界定义在 URL 语义上，而不是靠后端隔离来兜底。

**核心功能**

- 整个工作区就是一个 Nostr 中继：聊天消息、表情、工作流步骤、代码评审、git 事件全部是同一个日志里的签名事件，人和 Agent 用同构密钥对，所以搜索和审计不用做系统间对接。Nostr 中继可以理解成一个只追加、按公钥签名的消息服务器。
- Agent 用独立密钥对和独立频道成员身份做隔离，靠身份而不是权限开关——把 Agent 拉进频道跟拉一个同事进来是同一个操作，它做的事也自然留下自己的审计痕迹。
- git 走 NIP-34（把补丁、仓库公告、CI 状态编码成 Nostr 事件的标准），开一个 feature 分支等于开一个频道，补丁、CI 结果、首轮评审、合并决策都落在同一个房间里。
- buzz-cli 是 JSON 输入 / JSON 输出的 Agent 优先接口，配 ACP harness 接 Goose、Codex、Claude Code；工作流是 YAML，支持 message / reaction / schedule / webhook 四种触发。

**适用场景**: 适合想把 Slack、GitHub、CI 面板、发布工具、搜索合成一个自托管地方的小团队和开源项目维护者，尤其是想让 Agent 真能翻半年历史、提补丁、跑首轮评审的组织；也适合在意数据主权、要自己跑 relay 的团队。

**竞品对比**: 对比 Slack/Discord 加 bot、GitHub 加 Actions、Matrix/Element：最大差异是 Agent 不是外挂 bot，而是和人类同身份的事件作者，聊天、补丁、CI、审批进同一个索引。但 Slack 的生态和 GitHub 的 forge 成熟度短期追不上。

**成熟度**: 早期但能跑：relay、桌面端、频道、搜索、CLI、YAML 工作流已可用，移动端和审批门还在接，README 自己列了“强观点、代码未写”清单，API 可能还会变。

**趋势信号**: Block（Jack Dorsey 那家）亲自开源并推自托管 relay，正好接上 Dorsey 一直在讲的 Nostr 去中心化叙事，加上“Agent 是成员不是 bot”这个说法踩中了当下 Agent 工具的注意力。

### [louislam/uptime-kuma](https://github.com/louislam/uptime-kuma)

 `JavaScript` ⭐ +71 今日新增 · 93,956 总星数

> 自托管的网站与服务监控工具，一条 docker run 就能跑起来，用来替代 UptimeRobot 这类付费 SaaS。

**亮点**

- 单进程单容器 + SQLite 的部署取舍：放弃水平扩展，换来树莓派上一条命令就能跑，这是它传播开的主因
- 状态页可以绑定自定义域名，一个实例同时对外提供多个项目各自的公开状态页

**核心功能**

- 前端 Vue 3 + 后端 Node，心跳结果走 WebSocket 推给浏览器，仪表盘实时变化，不用 REST 轮询
- 探测类型覆盖 HTTP/关键词匹配/JSON 查询/TCP/Ping/DNS/WebSocket/Docker 容器/Steam 服务器；还有 Push 反向监控——外部定时任务主动打请求进来，超时没收到就报警
- 内置 90+ 通知渠道（Telegram、Discord、Slack、SMTP 邮件、Gotify 等），每个渠道是独立配置组件；所有心跳和配置存本地 SQLite，不依赖 MySQL/Redis

**适用场景**: 个人开发者和小运维团队监控自己的 VPS、NAS、家庭服务器和 side project，挂一个公开状态页给客户或同事看；也常被拿来当定时任务的心跳看门狗（cron 没跑就告警）。

**竞品对比**: 和 UptimeRobot 比是开源自托管的免费替代，不受免费版 5 分钟检测间隔限制；和 Gatus 比有图形界面、不用手写 YAML；和 Zabbix、Prometheus+Alertmanager 比轻量得多，但没有指标长期存储和告警分级。

**成熟度**: 2.x 正式版已发布，Docker 镜像有正式版本号，生产可用；但主要靠作者一人维护，PR 积压较多。

**趋势信号**: 长期处于 beta 的 2.0 正式版上线（Docker 镜像已打 :2 标签），老用户批量迁移升级带来一波关注。

### [tradermonty/claude-trading-skills](https://github.com/tradermonty/claude-trading-skills)

 `Python` ⭐ +69 今日新增 · 4,297 总星数

> 把盘面检查、风控、选股、仓位、复盘拆成 Claude Skills 和 YAML 工作流，帮没时间的散户把交易流程走完。不喊单、不自动下单，只留下一套可复盘的决策记录。

**亮点**

- 定位很克制：明确说不外包买卖决策、不做信号服务，输出是“检查清单和流程状态”，而非“买这只”。这在 AI 炒股类项目里很少见，可信度也更高
- 把工作流做成机器可读的 YAML manifest，每个流程序列（先跑哪个技能、经过哪个决策门、产出什么文件）都能被校验器和文档共同引用，同一套东西既能给人看，也能给 Claude 执行

**核心功能**

- 每个技能是一个 skills/&lt;name&gt;/SKILL.md 加辅助脚本，skills-index.yaml 是唯一权威索引，workflows/*.yaml 用 --strict-workflows 校验器检查引用的技能是否存在，避免文档和实际脱节

## 趋势观察

今天这批项目有个很明显的共同点：大家不再比谁的模型会写代码，而是在比谁能把 Agent 塞进真实的工作流程里，还让人放心。 第一类是给 Agent 补基础设施。阿里开源代码审查 CLI，把选文件、配规则这类确定性活儿交给流水线，LLM 只做动态判断，图的就是评论准、省 token。OpenAI 亲自下场做安全扫描，扫仓库、验漏洞、出带证据的补丁。Chrome 联手 Edge、Firefox、MDN 发技能包，直接往编码助手的上下文里塞现代 Web API，让它别再用十年前的老写法。Chrome DevTools 也出了 MCP 服务器，Agent 改完前端能自己开真浏览器验证。这些动作说明，大厂开始抢的不是模型，而是 Agent 的接口标准和工作流入口。 第二类是人和 Agent 的协作界面。有项目专门做本地浏览器审阅层，Agent 出的计划、diff 直接在网页上标注回灌。多 Agent 并行时，人的审阅成了瓶颈，这个位置正被工具填上。Block 那个用 Nostr 统一人和 Agent 身份的做法，也是同一个思路。 第三类是自托管替代付费 SaaS。监控工具一条 docker run 就跑，Maybe Finance 被社区接手继续做，Tailscale 把数据面拆成不用账号、不用 root 的 netcat。省钱、可控、能自己改，是这批人的共同诉求。 还有一类是垂直场景的流水线。股票分析、散户交易复盘，都把流程拆成技能和 YAML 工作流，强调不喊单、可复盘。 总的看，热点从「模型能力」转向了「可靠交付」。关键词是省 token、可验证、留证据、能复盘。开发者生态正在围绕 Agent 干活这件事，重新搭一遍水电煤。
