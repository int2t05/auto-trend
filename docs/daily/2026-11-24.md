### [elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)

 `Python` ⭐ +2,029 今日新增 · 20,450 总星数

> 把 84 个 Claude Code 技能打成 Bug 猎人知识包，含 681 份公开漏洞报告的检测模式，说一句测试目标就自动加载对应打法。

**亮点**

- 没有规则引擎也没扫描器，纯靠模型读 markdown 来执行，所以加一条攻击手法只是加一个文件，不用改代码。
- 技能里硬编码了纪律约束：OOS 驳回话术、PII 打码、证据脱敏，这些合规动作直接写进知识包里，防止模型越界乱打。

**核心功能**

- 知识全部写成 markdown 的 SKILL.md，靠话题关键词自动触发加载，不用手动点名调用；同一份知识层一键拷进 Claude Code、Codex CLI、OpenCode、Hermes、AntiGravity 五个 agent 的 skills 目录。
- 681 份 HackerOne 公开报告提炼成 58 个 hunt-* 技能，每个漏洞类别给出检测特征、payload、WAF 绕过表和漏洞串联模板，其中 433 条标了原始报告出处可回溯。
- 接 Burp MCP 读代理流量、接 HackerOne MCP 查项目范围和重复报告，把「读公开报告」变成「对真实流量动手」；再用 7-Question Gate 加 VRT（漏洞评级分类法）把发现分成真漏洞、重复、范围外三档。
- 覆盖 M365/Entra、Okta、vCenter、SharePoint、SSL VPN 设备等外网设备的 2024–2026 CVE 链条和拿到凭据后的横向升级路径。

**适用场景**: 众测/SRC 安全研究员和企业红队在授权项目中用它做资产搜集、攻击面排序、漏洞验证和报告撰写；也适合做外部攻击面评估的团队对着 M365、Okta、vCenter 这类边界设备查已知 CVE 链。

**竞品对比**: 和 Nuclei 模板、Metasploit 不是一类——那两个会自己发请求或打利用，这个只给 agent 装知识不替代工具；相比 PentestGPT 那种单一大 prompt，它按需加载 84 个技能，能省 context 也更细。

**成熟度**: 早期快速迭代，文档齐（安装、用法、技能目录都有），但技能内容仍在频繁改动，别当成稳定 API。

**趋势信号**: Claude Code 插件市场加上 SKILL.md 变成跨 harness 的通用格式，这类「给 agent 装专业知识包」的项目正好踩在风口，作者又用 681 份公开报告做了可审计的数据背书。

### [XiaoYouChR/Ghost-Downloader-3](https://github.com/XiaoYouChR/Ghost-Downloader-3)

 `Python` ⭐ +1,087 今日新增 · 16,838 总星数

> 一个用 Qt 写的跨平台下载器，HTTP、磁力、BT、M3U8、DASH 和 B 站、YouTube 解析都塞进同一个界面，还带浏览器嗅探和 Android 端。

**亮点**

- 浏览器扩展把页面上的媒体全部列出来，点一下就交给桌面端下载，并且把浏览器的登录态/Cookie 一起带过去，所以会员内容不用重新登录
- 弱网是它主打的场景：自动测带宽决定分几块，而不是固定线程数硬拉，README 里直接写「好网络下谁都快，考验的是烂网络」

**核心功能**

- 分块下载采用预分配文件加各线程按偏移直接写盘，不做最后拼接，省掉下载完成后的一次整文件拷贝（这是 IDM 的做法，多数 Python 下载器靠临时分片再 merge）
- 发请求时套用真实浏览器的 TLS 指纹（握手中的加密套件、扩展顺序等特征，即 JA3/JA4），让 Cloudflare 这类反爬以为是 Chrome，而不是 Python 客户端
- 基于 Qt/PySide6 一套代码发布 Windows、macOS、Linux、Android 四个平台；Android 上做成系统级录制服务，可直接录直播 M3U8 并在后台继续下载
- 暴露 aria2 兼容的 JSON-RPC 接口，AriaNg 等现成第三方前端能直接接管任务；任务跑着的时候还能改 URL、请求头、代理而不丢进度

**适用场景**: 适合受够了 IDM 只支持 Windows、迅雷限速、yt-dlp 只有命令行的人：比如要批量下载 B 站合集和多 P、从 HuggingFace 拉大模型权重、在浏览器里看到能播的视频就想存下来，或者在 Android 手机上录一场直播。

**竞品对比**: 对比 Motrix（aria2 套壳，只做 HTTP/BT，早已停更）、IDM（Windows 独占、无 BT/直播）、yt-dlp（命令行、不碰 BT）、迅雷（限速和会员墙），差异在于同一个 GUI 里同时覆盖通用协议加站点专用解析，还跨到移动端。

**成熟度**: 已有四平台正式安装包、代码签名、Crowdin 翻译和 AUR 包，可日常使用；但插件系统（Feature Packs）的公开 API 还在稳定中，扩展生态暂时别指望。

**趋势信号**: 很可能是新版本把 Android 端和直播流录制补齐、加上 B 站/YouTube 解析做得比之前完整，在 IDM 无 Linux/macOS 版、Motrix 停更的空档里被社区推上来。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +924 今日新增 · 208,317 总星数

> 把网页变成 LLM 能吃的 markdown 和结构化数据。新推出单二进制本地版，一条命令接进 Claude Code、Cursor 等 MCP 客户端，不用数据库和容器。

**亮点**

- 本地优先、云端兜底的混合路由：能用本机浏览器解决的就地解决，搞不定的才走云，并在返回结果里标明来源，用户能一眼看出数据从哪来
- 把产品从「网页抓取 API」扩成「知识基础设施」：云侧加了搜索和 Alexandria 的 550+ 数据源，从抓网页升级到查数据，Agent 一次调用能拿到更广的知识

**核心功能**

- 本地版是单个 Rust 二进制（cargo install firecrawl-local），不带数据库、队列和容器；JS 页面直接复用你机器上已装的 Chrome/Chromium 渲染，PDF 和 Office 文档也在本地解析
- `firecrawl-local init` 自动扫描本机的 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 配置文件，逐个写入 MCP server，改之前先把原文件备份
- `serve` 在本机 3002 端口跑完整的 Firecrawl v2 API，SDK 只改 api_url 就能从云切到自托管，本地路由不要 API key；本地抓不动的单页默认回落到云，结果里标 `source: firecrawl-cloud`，设 FIRECRAWL_CLOUD=off 可强制全本地

**适用场景**: 做 RAG 和 Agent 的开发者需要给模型喂网页、文档内容；以及不愿意把内部资料和抓取内容发到第三方 SaaS 的团队，在私有环境里跑爬虫和 MCP 工具。

**竞品对比**: 同类有 Crawl4AI（Python 自托管）、Jina Reader、Apify/ScrapingBee（托管抓取）、Exa/Tavily（搜索 API）。最大差别是它把自托管做成了 Rust 单二进制并自带 MCP 自动接入，本地和云共用同一套 v2 API，云侧还额外挂了 550+ 数据源。

**成熟度**: 云服务已有大量商用流量和公开 benchmark，SDK、文档齐全；本地版是较新的 Rust 实现，属于新组件但整体 API 已稳定在 v2。

**趋势信号**: MCP 和 Agent 生态正热，这次把本地运行做成单二进制、一条命令自动注册到各家 AI 客户端，再叠加免登录的 keyless 免费额度，直接把 star 拉起来了。

### [zhouxiaoka/autoclip](https://github.com/zhouxiaoka/autoclip)

 `Python` ⭐ +907 今日新增 · 14,928 总星数

> 把长视频和直播回放放在本机剪成竖屏短视频，自动挑高光、加字幕封面文案，一条链接一键出片。

**亮点**

- 它没有云端上传队列，也不收月费，代价是会占用本机的 CPU 和 GPU。因此它做了两个取舍：一是无损裁剪，避免重复编码；二是只让 LLM 读取转写文本，不对视频逐帧判断。
- 高光检测按内容类型分成两套策略：说话类内容依靠转写文本，游戏类内容依靠视觉和 OCR；它还为 8 秒以上的独立操作片段单独设置预算，不采用一套固定阈值处理所有内容。

**核心功能**

- 桌面端用 Tauri 外壳搭配 Python 处理管线，剪辑和渲染都在本机用 ffmpeg 完成，素材不上传；模型可以填自己的 API key，也可以接 Ollama / LM Studio 使用本地模型运行。
- 语音转写使用 Whisper 或 SenseVoice 并生成带时间戳的字幕，再由 LLM 在转写文本上挑选高光片段。它只根据文字判断，不扫描视频像素，因此能大幅节省算力。
- 通过 OBS WebSocket（4455 端口）连接，下播后自动拉取录像，再用 ffmpeg -c copy 做无损裁剪，不重新编码；游戏类内容改用视觉识别和 OCR，并针对 8 秒以上的独立片段设置识别预算上限，防止成本失控。

**适用场景**: 播客、访谈、课程作者和游戏主播，加上 MCN 的剪辑运营，会把一场 1 小时直播或长视频拆成几十条 9:16 切片，批量生成字幕、封面和标题，并发布到抖音、小红书、Shorts、Reels。

**竞品对比**: 与 Opus Clip、Klap、Vizard 这类云端 SaaS 相比，AutoClip 按分钟收费并要求先上传素材；AutoClip 是 MIT 协议的本地桌面版，免费且素材不出本机，但没有 SaaS 那套模板库和团队协作。开源侧的 FunClip、ClipsAI 多为命令行脚本，AutoClip 则提供了完整的 GUI 和发布链路。

**成熟度**: 版本已到 1.6，13 种语言的界面和文档齐全，也提供了演示样片；但模型需要自己提供 key，或依靠本机算力运行，切出来的片段仍需人工复核，还不适合当作全自动流水线。

**趋势信号**: v1.6 刚加入 OBS、Twitch、Kick、Discord 等 6 个直播回放源，直接满足主播下播后快速生成切片的需求；同时它跟上了本地模型（Ollama）和 MCP 这两项当前热门趋势。

### [obra/superpowers](https://github.com/obra/superpowers)

**核心功能**

- 技能库本体是纯 Markdown 加 Shell 安装脚本，靠各 harness 的 SessionStart 钩子注入一个 using-superpowers 引导技能，不用改 Agent 源码就能让技能自动触发，用户不用手敲命令
- 强制流程：Agent 先反问你要做什么、逼出规格 → 把设计切成能一口气读完的小块让你签字 → 生成一份“没项目上下文、不爱测试的初级工程师也能照做”的实施计划，硬性要求 red/green TDD、YAGNI、DRY
- 一份技能多端分发：Claude Code、Codex App/CLI、Cursor、Gemini CLI、GitHub Copilot CLI、Devin CLI、Factory Droid、Grok Build、Kimi Code、OpenCode、Pi、Qwen Code、Muse 等各有独立安装命令，同一仓库同一套技能内容

**适用场景**: 用 Claude Code、Cursor、Codex 写代码的个人开发者和团队。想让 Agent 自主跑一两个小时还不跑偏、又不想每次手写长 prompt 约束流程的场景，尤其是从零起新功能或重构。

**竞品对比**: 同类有 BMAD-METHOD、各种 .cursorrules / AGENTS.md 模板，以及 Claude Code 自带的 subagents。最大差异是 Superpowers 靠钩子自动触发技能而不是让用户手动调用，并且同一套技能铺到了十几个 Agent 工具里。

**成熟度**: 有官方插件市场上架和商业支持入口，多平台安装文档齐全；但本质是一堆 prompt 和技能文件，跨 harness 行为不一致（比如 Hermes 会话压缩后会丢掉引导），稳定性跟着底层 Agent 工具走。

**趋势信号**: 2025 到 2026 年各家 Agent 工具集体上线插件/技能市场（Anthropic 官方插件市场、OpenAI Codex 插件市场、Gemini extensions、xAI 市场），Superpowers 第一时间跟进铺货，正好吃到“Agent 技能”这波红利。

### [jingyaogong/minimind](https://github.com/jingyaogong/minimind)

 `Python` ⭐ +828 今日新增 · 69,845 总星数

> 花 3 块钱、2 小时，在单张 3090 上从零训出 64M 小模型；从预训练到 Agentic RL 的全链路代码都手写开源，当作 LLM 入门教材。

**亮点**

- 刻意不使用高层框架：DPO、GRPO、CISPO、MoE 负载均衡 loss、KV-Cache 全部手写，十几行 transformers 能跑完的流程被拆成能逐行读懂的代码
- 把结构对齐到 Qwen3 生态，权重可以直接放进 llama.cpp / vllm / ollama / Llama-Factory，因此即使模型很小，也能完整验证“训练→导出→部署→接 OpenAI API 兼容客户端”这条真实链路
- 成本压到极限：README 明确说明“2 小时”是单卡 3090 跑完 SFT 一个 epoch 的实测时间，“3 块钱”是对应时段的 GPU 租用费，个人完全能复现

**核心功能**

- 模型结构对齐 Qwen3 / Qwen3-MoE：Dense 64M、MoE 198M-A64M，去掉 shared expert；训练代码全部用原生 PyTorch 实现，不调用 transformers / trl / peft 的高层抽象
- 训练流程覆盖 Pretrain → SFT → LoRA → DPO → PPO/GRPO/CISPO → 多轮 Tool Use 的 Agentic RL；RLAIF 的 rollout engine 做了后端解耦，可更换生成后端
- Tokenizer 用 BPE + ByteLevel 自行训练，在词表中加入 &lt;tool_call&gt;/&lt;tool_response&gt;/&lt;think&gt; 标记；思考能力由 chat_template 加 open_thinking 开关控制，不再需要单独 train_reason.py
- 支持 DDP / DeepSpeed 多卡、wandb / swanlab 可视化、断点续训（跨 GPU 数恢复），以及用 YaRN 做 RoPE 长文本外推，并在 C-Eval、C-MMLU、OpenBookQA 上跑评测

**适用场景**: 想看懂 LLM 内部机制的在校学生、转行工程师和算法面试备考者，可拿它当可跑通的教程；独立开发者想在自己业务数据（医疗、客服自我认知）上微调一个能塞进 llama.cpp / ollama 的小模型时也用得上。

**竞品对比**: 和 karpathy 的 nanoGPT 比，nanoGPT 只有预训练、结构是 GPT-2、偏英文；和 SmolLM / TinyLlama 比，那两个只发权重不发极简训练代码。MiniMind 是少数把预训练、SFT、LoRA、DPO、PPO/GRPO、Tool Use 全链路、中文数据和原生实现打包在一起的项目。

**成熟度**: 69.8k star、持续迭代两年多，Apache 2.0 完全免费，工程完整度可以当教学参考；但定位是入门教材，64M 模型别指望上生产。

**趋势信号**: 2026-04-01 发布 minimind-3，结构转向 Qwen3 / Qwen3-MoE，并新增原生 Agentic RL 脚本 train_agent.py（多轮 Tool Use 场景下的 GRPO / CISPO），正好赶上“小模型 + 智能体强化学习”这波热度，加上 3 块钱的成本容易被转发。

### [mvanhorn/last30days-skill](https://github.com/mvanhorn/last30days-skill)

 `Python` ⭐ +797 今日新增 · 73,736 总星数

> 给 AI Agent 的调研技能：并行搜 Reddit、X、HN、Polymarket 等 20 多个平台近 30 天内容，按真实互动量打分后合成一份简报，补上 Google 搜不到的一手讨论。

**亮点**

- 核心取舍是「不做数据平台，只做会话桥接」：各家平台都是围墙花园、没有统一 API，它就让用户自带 key 和已登录的浏览器会话，把一个 Agent 同时接进十几个平台，这是别人绕不过去的地方
- 把预测市场赔率当成事实置信度：讲某个传闻时直接在同一段下面标 Polymarket 的概率和变化幅度，等于给每条结论配一个「有多少人愿意为它下注」

**核心功能**

- 做成 Agent「技能」而不是独立 App：仓库只提供 SKILL.md 命令规格和采集管道，推理交给 Claude Code、Codex、Cursor、Gemini CLI 等宿主，安装方式是 `/plugin install` 或 `npx skills add`，不自己造 agent 框架也不训模型
- 每个平台一个采集器（`*-pp-cli` 子进程）：有 API key 就调官方接口，没有就复用用户自己的浏览器登录会话来抓，把关掉鉴权的 Reddit 顶楼评论、X 帖子、YouTube 完整字幕、GitHub PR 合并率、Polymarket 赔率都拉回来

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +184 今日新增 · 12,359 总星数

> 英特尔开源的一套 AI 推理部署工具，把 PyTorch/TF/ONNX 模型转成自家 IR 并针对 Intel CPU、核显、NPU 做量化和编译加速。现在火是因为 AI PC 和本地跑 LLM 的需求起来了，它是不靠 NVIDIA 显卡也能跑模型的主力方案。

**亮点**

- 两段式设计：转换和编译分开，模型先转成 IR 存盘，运行时按目标设备现场编译，所以部署包不带 PyTorch，也不吃 Python 环境
- 把 NPU 当一等公民而不是附属品，GenAI pipeline 里 LLM 的 prefill 和 decode 可以落到笔记本 NPU 上跑，功耗比纯 CPU 低一截

**核心功能**

- 离线把 PyTorch/TensorFlow/ONNX/PaddlePaddle/JAX 模型转成内部 IR（中间表示，一种与框架无关的模型格式），转换时做算子融合、常量折叠和精度校准，部署端不再需要装原框架
- 配套 NNCF 做训练后量化（PTQ，模型跑几批校准数据就把 FP32 权重压成 INT8/INT4），把 LLM 和大视觉模型塞进消费级 CPU 和核显
- 同一份模型换设备只改一个字符串（'CPU'/'GPU'/'NPU'），runtime 底下分别走 x86/ARM 的 oneDNN、Intel 核显独显、以及酷睿 Ultra 的 NPU；GenAI API 另外封装了 KV cache 复用和 continuous batching（连续批处理，把多个请求拼一批喂给模型）

**适用场景**: 做本地 AI PC 软件的开发者想在客户没独显的笔记本上跑 LLM 或 Whisper；工厂/零售的边缘盒子、工控机做视觉检测，只有 Intel CPU 没有 GPU 的团队；以及想在自己电脑上离线跑开源模型的个人。

**竞品对比**: 对标 NVIDIA TensorRT、ONNX Runtime 和 llama.cpp。最大差异是它押注 Intel CPU/核显/NPU 这条没独显也能跑的路线，TensorRT 则完全绑 NVIDIA 显卡；相比 ONNX Runtime 它对自家硬件调得更深，相比 llama.cpp 它覆盖的不只是 LLM，还有检测、分割、语音这些传统模型和完整 C++ 部署链路。

**成熟度**: 成熟可上生产：英特尔官方维护多年，版本号已到 2026 年线，文档齐全，PyPI/npm/conda/brew 都有包，企业用户不少。

**趋势信号**: AI PC 概念落地加上酷睿 Ultra 的 NPU 铺开，配合 2026 新版本文档和 GenAI 对本地 LLM 的支持，让"不靠 NVIDIA 显卡跑模型"这件事重新被讨论。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +174 今日新增 · 33,111 总星数

> NGINX 官方开源仓库，C 写的 Web 服务器/反向代理/负载均衡器，靠事件驱动多进程模型扛高并发，是绝大多数站点入口的那一层。

**亮点**

- 配置文件是声明式的、按请求处理阶段（rewrite/access/content 等）分阶段执行，改配置只需 reload：master 校验新配置后平滑拉起新 worker、旧 worker 处理完存量连接再退，不断连
- 把并发模型压到「进程数≈CPU 核数」这一档，把复杂度从线程锁转移到共享内存和事件回调上，这是它能用很小内存吃很高连接数的根本原因

**核心功能**

- master 进程只负责读配置、管 worker，worker 进程用 epoll/kqueue 事件循环处理连接，不搞一连接一线程，所以几万个并发连接内存也不炸
- worker 之间不共享堆内存，状态靠共享内存 zone 传递——限流计数、缓存索引、upstream 健康状态都放在共享内存里，多进程才能看到同一份数据
- 功能全拆成模块，分静态模块（编译进二进制）和动态模块（.so 运行时加载），nginx -V 能查出当前二进制编进了哪些模块，第三方模块不用重编主程序

**适用场景**: SRE/运维和 backend 团队把它放在最前面做 TLS 终止、反向代理、七层负载均衡和静态资源缓存；K8s 里的 ingress-nginx 也是基于它，前端静态站点、API 网关分流都是典型场景。

**竞品对比**: 对比 Caddy 是自动 HTTPS、配置更短但生态和调优经验少；对比 Envoy/Traefik 是云原生动态配置（xDS/服务发现）能力强，NGINX 改 upstream 基本得 reload 或上 OpenResty/njs；对比 HAProxy 是负载均衡算法和观测更专精。NGINX 的差异点是静态文件与 TLS 性能、模块生态和二十年积累的配置范例。

**成熟度**: 生产可用，二十多年历史，BSD-2 协议，stable/mainline 双轨发布，F5 提供商业支持和企业版。

**趋势信号**: 原因不明；可能和主线版本持续发布、以及官方源码从 Mercurial 迁到 GitHub 后曝光度变高有关。
