### [bilawalsidhu/gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view)

 `JavaScript` ⭐ +2,265 今日新增 · 30,485 总星数

> 浏览器里的开源 3D 地球仪，实时叠加航班、船舶、卫星、地震和公开摄像头等真实数据，本地运行、图层可自由扩展。

**亮点**

- 免 key 起步：不注册、不填任何密钥就能看到航班、军机、卫星、地震、摄像头和火箭发射，付费 key 只当画质和搜索的升级项，在应用内 POWER UP 面板粘贴即可。密钥写入 .env 前先设成仅属主可读，macOS 下还能直接从 Keychain 读。
- 相机、滤镜、图层和正在追踪的目标全部序列化进 URL，打开链接等于接手同一个实时目标，而不是收藏一张静态截图。

**核心功能**

- 用 Cesium 当 3D 渲染底座，卫星影像走 Esri/Google、地形走 Cesium ion，没有 key 时自动回退 OSM，照样能看航班、卫星、地震和摄像头；每条数据线各自是一个独立模块，可单独开关和替换。
- 用 GLSL 写屏幕后处理滤镜做传感器观感：CRT、夜视 NVG、热成像 FLIR、黑白 Noir 都是在同一张渲染结果上换 shader，不用重画场景。
- 目标物体按距离切 LOD：远处只画一个图标，镜头靠近后换成按机型对应的真实 3D 模型（787、ATR-72、Citation、Bell 206、MQ-9）。

**适用场景**: 做 OSINT 的情报分析者、跑航空或海事选题的记者、要录演示视频的创作者。在一张地球上同时看多个公开数据源，点中一架飞机就能切进驾驶舱视角，还能一键跳到离它最近的公开摄像头。

**竞品对比**: Flightradar24、MarineTraffic 各自只覆盖航班或船舶，也不让你加图层；Palantir Gotham 这类 GEOINT 平台闭源且昂贵。差别在于它开源、在本地浏览器跑、把多源叠在同一张地球上，图层是能自己写的模块。

**成熟度**: 偏早期：没有版本号，更新很频繁，图层接口还可能改；但 CI、npm run doctor 自检、上手文档和跨平台一键安装都齐了，开箱能跑。

**趋势信号**: 作者同名的 God's Eye View YouTube 系列已积累 500 万+ 播放，这次把之前闭源的 WorldView 开源，视频观众直接变成 star，冲上 GitHub Trending 日榜和周榜第一。

### [p1neappleXpress/OpenFlux](https://github.com/p1neappleXpress/OpenFlux)

 `Go` ⭐ +355 今日新增 · 1,436 总星数

> 把 TCP 包塞进 Yandex Docs 光标消息或 MAX 的 WebRTC 通道里传输的隧道工具，本地开 SOCKS5，出口节点用 gvisor 用户态栈还原流量，用于研究受限网络下的隐蔽信道。

**亮点**

- 不自己发明加密协议，而是寄生在第三方云服务的正常功能上：协作文档的光标消息、IM 的数据通道，流量在平台看来就是正常业务流量，不依赖自建中转 IP 的隐蔽性。
- 出口节点把网络栈搬进 gvisor 用户态，代价是要处理内核乱回 RST 的问题；README 明确说 -m owner --uid-owner 匹配不生效，因为 RST 是无属主 socket 的内核生成的——这个取舍和解释写得比多数同类项目清楚。

**核心功能**

- 传输层做成 Transport 接口，可插拔：现有两个后端，一个把数据编码进 Yandex Docs 的协作光标位置消息，一个走 MAX 即时通讯的 WebRTC DataChannel，加新后端只要实现接口并在 main.go 的 switch 里注册。
- 出口节点不用内核 socket，而是用 gvisor 用户态网络栈自己收发 TCP，因此内核看到来自隧道的回包时没有对应 socket，会发 RST 把连接打断；解法是只对隧道专用出口 IP 做 iptables DROP RST，避免全局 DROP 让所有关闭端口变成“filtered”并影响主机其他连接。
- 客户端侧就是个 SOCKS5 服务（默认 :1080），浏览器直接填代理即可；iOS 端通过 cgo 把 Go 编译成静态库 liboflux.a，再用 Network Extension 做成系统级 VPN，Android 单独用 NDK 构建客户端二进制。

**适用场景**: 面向需要研究网络封锁与隐蔽信道的安全研究员、以及身处俄语区强管控网络的普通用户。典型流程是：租一台 Linux VPS 当出口节点跑 --exit-node，本地跑 --client 起 SOCKS5，然后在浏览器或系统里设代理。

**竞品对比**: 和 Xray/v2ray、Shadowsocks、Tor 这类方案最大的区别是：它们都在自建协议和自建中转服务器上做伪装，而 OpenFlux 直接借用 Yandex Docs、MAX 这些平台的现成信道，不需要自己的落地 IP 隐蔽。代价是依赖第三方平台规则、速率受平台限制，MAX 传输还可能封号且封禁会在停用后持续。

**成熟度**: 早期项目，无版本号，作者自己把 MAX 传输标为 experimental，README 大段是免责声明和封号警告，只适合实验环境。

**趋势信号**: 俄语区强管控下用户寻找绕过手段，而 MAX 是俄政府力推的本土通讯软件、Yandex Docs 也是本地常用工具，把这两者当信道正好踩在当下俄语社区关注点上；加上 iOS TestFlight 客户端刚补齐，一天涨了 355 星。

- 用文件系统的 reflink 而不是拷贝或软链接来共享构建缓存——软链接会让构建工具写穿到源目录，拷贝又太慢，reflink 是这里唯一不牺牲正确性的做法。

**核心功能**

- worktree 用分支名寻址，磁盘路径由可配置模板算出来。`wt switch -c -x claude feat` 一条命令就完成建分支、建 worktree、进目录、启动 Claude，而原生 git 要三行。
- `wt step copy-ignored` 用 reflink（写时复制，文件系统层面只复制指针不搬数据）在 APFS/btrfs/XFS 上共享 `target/`、`node_modules/` 这类构建产物，十个 worktree 不用各自重新构建一遍。
- Hooks 挂在 create/pre-merge/post-merge 等生命周期上，模板里可用 `hash_port` 给每个 worktree 分配唯一端口跑独立 dev server；`wt list --full` 还能显示每个分支的 CI 状态和 LLM 生成的变更摘要。

**适用场景**: ['一个人同时开 5-10 个 Claude Code / Codex 会话跑长任务的开发者——每个 Agent 一个 worktree 互不干扰，出问题直接 `wt remove` 清掉。', '需要频繁切 PR 或分支做 review、跑测试的工程师，`wt switch pr:123` 直接跳到 PR 分支，配合 `wt merge` 一条命令完成 squash、rebase、合并、清理。']

**竞品对比**: ['和原生 `git worktree` 比，它把三行命令压成一行并加了 hooks、LLM commit、合并流程；和 Conductor、gwq 这类工具比，它坚持纯 CLI、不绑定某个编辑器，并且明确围绕『并行 Agent』而不是『并行分支』设计。']

**成熟度**: 早期项目，年初才发布，但文档站、CI、Codecov、Homebrew/Cargo 安装都齐全，作者响应积极，命令名和配置格式后续仍可能调整。

**趋势信号**: 2026 年自主编码 Agent 能长时间无人值守跑任务，开发者开始同时管理多个 Agent，而 git worktree 是天然的隔离手段却 UX 很差，这个工具正好卡在这个缺口上，作者也公开称它已成为最流行的 worktree 管理器。
