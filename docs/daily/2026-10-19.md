### [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)

 `Python` ⭐ +2,232 今日新增 · 53,911 总星数

> 一个跑在本地的 AI 求职框架，基于 Claude Code 的斜杠命令完成搜岗、岗位匹配打分、改简历、写求职信、面试准备。作者被裁员后自己用它投了 69 份简历拿到 offer，开源后爆火。

**亮点**

- 不是 SaaS 而是「fork 走自己用」的仓库：所有数据（姓名、履历、期望薪资）写在你能看到的 tracked 文件里，AI 只在本机跑，简历不出本地。作者还专门警告公开 fork 会泄露个人信息，给了用私有仓库 + upstream 的做法
- 把「求职方法论」写成给 Agent 的评估标准和写作规范（结构化匹配打分、前瞻式求职信框架、可选薪资对标），而不是写成一堆 prompt 模板，换语言换国家时方法论仍可用

**核心功能**

- 用 Claude Code 的斜杠命令把求职拆成流水线：/setup 建档、/scrape 抓岗、/rank 批量打分、/apply 投递、/interview 面试准备，每一步的产物落到本地文件，下一步直接读
- 简历和求职信用 LaTeX 模板生成并编译成 PDF（简历走 lualatex，求职信走 xelatex 因为 cover.cls 依赖 fontspec），改内容不改排版
- 「起草—审稿」双 Agent 循环：一个 Agent 写简历和求职信，另一个 Agent 按固定评估标准挑毛病，反复修改后才输出终稿
- 投递前做 ATS 可解析性检查：用 pypdf 抽取 PDF 文本，检查关键词是否被机器读到，没有 pypdf 就退回 Poppler pdftotext，两者都没有则降级成人工关键词核对
- 每个招聘网站是一个独立的 skill CLI（放在 .agents/skills/*/cli/ 下，TypeScript + Bun），安装脚本自动发现并 bun install，所以新增站点不用改主流程

**适用场景**: 正在找工作的个人用户，尤其是技术岗求职者：本地有 Claude Code 订阅，想批量筛岗位、针对每个 JD 定制简历和求职信，而不是每投一家手动改一遍。当前抓岗模块只覆盖丹麦站点（Jobindex、Jobnet、Akademikernes Jobbank），其他地区要自己换 portal skill。

**竞品对比**: 和 Teal、Simplify、Jobscan 这类在线求职工具比，最大差异是数据留在本地、流程可改、不订阅 SaaS；和直接用 ChatGPT 改简历比，它把搜岗、打分、生成、审稿串成了可重复执行的固定流水线，而不是每次重新对话。

**成熟度**: 早期项目，靠作者个人求职案例验证（69 投 20 面 1 offer），有 CI 和完整安装文档，但强依赖 Claude Code 付费订阅 + LaTeX 环境，站点覆盖仅丹麦，API 和目录结构仍可能变动。

**趋势信号**: 2025 年底科技业裁员潮下「AI 帮我找工作」的需求集中爆发，加上 Claude Code 的 skills/斜杠命令生态成熟，这类「把 Agent 工作流打包成可 fork 仓库」的项目正好踩中两个热点。

### [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)

 `Python` ⭐ +2,082 今日新增 · 75,864 总星数

> 全本地跑的开源 ElevenLabs 替代品：语音克隆、设计音色、视频配音、听写、转写、做有声书一站打包，覆盖 646 种语言，还带本地 API 和 MCP，能在自己的显卡上跑。

**亮点**

- 从 Tauri 整体迁到 Electron，0.5.3 是最后一个 Tauri 版本，旧壳和旧 UI 入口直接删掉、不兼容——团队宁肯吃一次迁移成本，也要把桌面端和 Web UI 合成一套代码
- 把「本地跑语音模型」的门槛压到一条 curl 命令：安装脚本做硬件检测、按需下载模型、保留用户已有项目和模型，还写了给 agent 读的安装文档，让 Claude Code 帮你装

**核心功能**

- 默认 TTS 引擎用 k2-fsa/OmniVoice，但引擎可换：模型管理页里能装、能切别的引擎，装机脚本按硬件自动装对应 PyTorch 构建（NVIDIA 走 CUDA、Apple Silicon 走 MPS、没独显装约 5GB 的 CPU 小包）
- 桌面端是 Electron，后端是独立的 Python 进程，前端只通过本地 HTTP API 说话。所以同一套后端能同时被桌面 App、手机伴侣（预览中）和 agent 复用，不是把模型塞进 UI 进程里
- 内置 MCP server 和本地 API，Claude Code、Codex、Cursor 这类编码 agent 可以直接调它合成和转写；另外有 watch folder 和可复用的 recipe 来做批量任务（有声书、多集配音）

**适用场景**: 做 YouTube/B 站多语言配音的创作者、批量生产有声书的工作室，以及不想把原始录音传到 ElevenLabs 的用户；还有想给自己 agent 接一条本地语音输出链路的开发者。

**竞品对比**: 对上 ElevenLabs，核心差异是数据不出机器、没有按字符计费；对 GPT-SoVITS、F5-TTS、Coqui 这些开源 TTS 项目，它是全家桶——克隆、配音、转写、批量、桌面 UI、API/MCP 都预先接好了，代价是 AGPL-3.0 协议和更重的依赖体量。

**成熟度**: 还在 0.x 版本，桌面壳刚经历一次大版本重写，API 和安装方式可能变；但安装脚本、排障文档、引擎指南和 benchmark 都写得比较全，属于日常能用、不建议直接进生产的阶段。

**趋势信号**: 赶上了开源本地语音替代 ElevenLabs 这波热度，加上 Electron 重写版刚落地、自带 MCP 能被 Claude Code / Cursor 一键接入，正好卡在 agent 需要语音输出这个时间点上。

### [anomalyco/opencode](https://github.com/anomalyco/opencode)

 `TypeScript` ⭐ +1,414 今日新增 · 216,802 总星数

> 开源的终端 AI 编程 Agent，不锁定某一家模型，用 build/plan 两个 Agent 分工，v2 版本和桌面端刚发布，所以冲上趋势榜。

**亮点**

- 把 Agent 做成 server + 客户端两层，同一套后端能同时喂给终端 TUI、桌面端和编辑器插件，不用为每个界面重写一遍逻辑。
- 把“先看再改”做成了产品默认流程：plan Agent 靠权限规则硬性禁止写文件，而不是靠 prompt 里写一句“请不要修改”。

**核心功能**

- 前后端拆开：TUI 只是前端，真正干活的是本地跑的一个 server 进程。两者通过 HTTP/SSE 通信，因此你可以从另一台机器连过来接管同一个会话。
- 模型无关：底层走 AI SDK 接多家 provider，换模型只改配置，不像 Claude Code 那样锁死 Anthropic。
- 内置 build 和 plan 两个 Agent，按 Tab 切换。plan 是只读的，默认拒绝改文件，跑 bash 命令前要请求授权，适合先摸清陌生代码库再动手。

**适用场景**: 常驻终端的后端/全栈工程师，尤其是要 ssh 到远程机器上改代码、或者团队想接自建模型网关/私有部署模型的情况；也可给不想把代码传给闭源厂商的团队用。

**竞品对比**: 对手是 Claude Code、OpenAI Codex CLI、Aider。最大差异是开源 + 不绑模型 + 自带 TUI 界面，Claude Code 只认 Anthropic 模型，Aider 更偏 git 提交式的老派 CLI 交互。

**成熟度**: 能用但仍在快速迭代，分发渠道已经很全（npm/brew/pacman/nix/mise），桌面端刚进 beta，接口可能还会变。

**趋势信号**: Claude Code 把“终端里跑 Agent”这个用法带火之后，大家开始找不锁模型的开源替代；加上 opencode 刚从 sst 独立成 anomalyco 并发了 v2 和桌面端 beta，一波关注集中爆发。

### [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official)

 `Python` ⭐ +1,175 今日新增 · 42,827 总星数

> Anthropic 官方维护的 Claude Code 插件市场，一条命令装插件，把 MCP 服务、斜杠命令、子代理和技能打包分发。

**亮点**

- 外部插件用固定 commit sha 的 git-subdir 拉取，不用分支引用，上架后内容不会悄悄变，可复现、可审计。
- 内/外两个目录分开（/plugins 是 Anthropic 自己写的，/external_plugins 是第三方的），审核只管准入门槛，README 明确写官方不控制也不验证插件里的 MCP 服务和文件——信任责任交给用户。

**核心功能**

- 插件是一个标准目录包：plugin.json 元数据 + 可选 .mcp.json（MCP 服务器配置）、commands/（斜杠命令）、agents/（子代理定义）、skills/（SKILL.md 技能），一个包把五种扩展点一起分发。
- 插件名是只读 slug，改名不能直接改，要在 marketplace.json 的 renames 映射里登记，客户端下次同步时自动把旧名重写成新名，避免用户已装的插件报 plugin-not-found。
- 支持 strict:false 的“技能捆绑”：源仓库没有 plugin.json 时，用 git-subdir + 固定 commit sha 指向若干含 SKILL.md 的目录，注册成 &lt;插件名&gt;:&lt;技能名&gt;，纯技能仓库不用改造就能上架。

**适用场景**: Claude Code 的日常用户想快速装现成能力（比如某个 MCP 服务、某个代码审查 agent）；第三方工具厂商想把自己的服务塞进 Claude Code 的分发入口，就走 external_plugins 提交表单。

**竞品对比**: 和 mcp.so、Smithery、Glama 这类 MCP 服务索引站，以及 awesome-claude-code 这类清单比，最大差异是它跟客户端打通：不是在网页上找链接再手动配，而是 /plugin install 直接在 Claude Code 内装，还带改名迁移机制。

**成熟度**: 早期项目，目录刚开放第三方提交，插件数量和审核流程都在起步，官方明确说不验证插件内容，生产使用需自行审查。

**趋势信号**: Claude Code 插件市场刚开放外部提交，加上 Agent Skills 这波生态热度，官方目录成了默认分发入口，一天涨 1175 星是被插件系统整体发布带起来的。

### [stablyai/orca](https://github.com/stablyai/orca)

 `TypeScript` ⭐ +1,146 今日新增 · 96,980 总星数

> 把 Claude Code、Codex 等多个编码 agent 并行跑在一个工作台里，每个占一个独立 git worktree，桌面、手机、远程都能管。agent 从单线程变多线程，缺的就是这层编排。

**亮点**

- 不自建模型代理，直接用你自己的 Claude / Codex 订阅跑，还带账号热切换和 rate-limit 重置时间的用量面板——绕开 API 计费，这是它能留住重度用户的关键
- 反向控制：CLI + Computer Use 让 agent 能操作宿主 IDE 本身，形成 agent 驱动 agent 的循环，而不是把 agent 关在一个只读的聊天框里

**核心功能**

- 一条 prompt 分发给多个 agent，每个 agent 起一个独立 git worktree 做隔离，跑完对比 diff 再合入胜出的那个分支，互不污染工作区
- 内嵌 Chromium 窗口做 Design Mode：点页面上的任意 UI 元素，把这个节点的 HTML、CSS 和裁剪后的截图直接拼进 agent 的 prompt，省掉手写"第几行样式不对"
- 终端用 WebGL 渲染（对标 Ghostty），滚动缓冲落盘，重启 app 后历史还在；SSH 模式把 worktree 放到远程大机器上跑，自带断线重连和端口转发
- 提供 orca CLI（worktree create / snapshot / click / fill），把 IDE 的操作面暴露成命令，agent 可以反过来自己开 worktree、点按钮、填表单

**适用场景**: 主要给同时用 Claude Code、Codex、OpenCode 的重度个人开发者：一个需求开三五个 agent 并行试，挑最好的合并。也适合手上只有笔记本、需要 SSH 到远程机器跑 agent 的人，以及想在地铁上用手机盯 agent 进度、发 follow-up 的人。

**竞品对比**: 同类有 Conductor、Crystal（也是多 worktree 并行跑 Claude Code），以及 Cursor、Zed 这类只带单 agent 面板的编辑器。Orca 的差异是覆盖最全：桌面 + iOS/Android + SSH 远程 + 内嵌浏览器取 DOM，别人通常只做其中一块。

**成熟度**: 迭代极快、几乎每日发版，桌面三平台和 iOS App Store 都已上线、有 Discord 社区，属于可日常重度使用的早期产品，但 CLI 和 API 仍在变，不适合团队做标准化依赖。

**趋势信号**: Claude Code、Codex 全面 CLI 化，加上订阅制给了个人大量额度，大家开始同时开好几个 agent 并行干活，编排层因此成了刚需；移动 companion app 上架 App Store 也直接带来了这波曝光。

### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +589 今日新增 · 54,727 总星数

> 把各种软件（CAD、LibreOffice、Calibre、n8n 等）包装成命令行工具，让 AI Agent 能直接调用，配套 CLI-Hub 注册表一键安装。

**亮点**

- 用 CLI 而不是 MCP server 做 Agent 接口：不需要给每个软件起一个常驻服务进程，命令天然可管道组合、可脚本化，返回的 JSON 也省 token
- 注册表众包模式：社区提交某个软件的 CLI 适配层，审核合并后即可被 cli-hub install，覆盖速度取决于 PR 数量，而非官方自己从头支持全部软件

**核心功能**

- 每个 CLI 同时提供两种输出：JSON 给 Agent 解析，人类可读文本给终端用户；底层用 Click 构建命令树，pytest 覆盖 2461 个用例含 E2E
- 自带 CLI-Hub 注册表，执行 pip install cli-anything-hub 后，用 cli-hub install &lt;name&gt; 像装 npm 包一样安装社区写好的软件适配层；每个适配层配 SKILL.md，可用 npx skills add 装进 Claude Code、Cursor 的技能目录
- “预览→执行→回看”循环：Agent 先跑命令拿中间产物或预览图，再改参数重跑，CAD 建模、3D 场景、字幕都是这么迭代出来的
- 安全侧有具体取舍：XML/SVG/ODF/MusicXML 等不受信输入统一走 defusedxml 解析，Sketch 的 token 文件做路径穿越和软链逃逸防护，Rekordbox 的 SQLCipher 写入强制先备份

**适用场景**: 用 Claude Code、Cursor 的开发者需要批量改 CAD 图纸、转 LibreOffice 文档、整理 Calibre 书库、操作 Joplin 笔记或 n8n 流程时，让 Agent 调这些 CLI，而不是自己点鼠标。

**竞品对比**: 对手是 MCP server 生态和 computer-use 类 GUI Agent（Anthropic computer use、OpenAI Operator 那种看截图点坐标的）。最大差异是不要求软件提供 API，也不需要视觉模型去点按钮，靠命令行加 JSON 输出打通。

**成熟度**: Apache 2.0 + arXiv 技术报告 + 每天在合 PR，但各软件适配层来自社区提交，质量参差，用之前先看对应目录的测试和 issue 状态。

**趋势信号**: Agent 产品正从“能聊”转向“能干活”，MCP 之后大家普遍在找让 Agent 操作桌面软件的通用方案；这个项目正好踩在这一点上，又刚上线 CLI-Hub 注册表、一键装技能和多语言文档，传播起来了。

### [ruvnet/ruflo](https://github.com/ruvnet/ruflo)

 `TypeScript` ⭐ +513 今日新增 · 76,647 总星数

> Ruflo 是套在 Claude Code / Codex 外面的 agent 外壳，用 MCP 和插件把上百个 agent、向量记忆、跨机联邦通信注入进去，让多个 agent 分工协作跑长任务。

**亮点**

- 分发方式是 Claude Code 插件市场（/plugin marketplace add ruvnet/ruflo），mods 直接在 Claude Code 进程里跑，权限跟着你的账号走；这是把 harness 做成寄生层，并非另起一个框架。
- 联邦（federation）设计：多台机器上的 agent 之间能通信但控制数据不外泄，思路是把记忆和协调留在本地节点，只交换必要信号。

**核心功能**

- 用一个 MCP server 暴露 314 个工具，还提供 26 个 CLI 命令，Claude Code 和 Codex 这类支持 MCP 的客户端都能接入；它自身不是独立运行时。
- 靠 Claude Code 的 hooks 做自动路由：装完 npx ruflo init 后照常写代码，后台自动决定任务该派给哪个 agent、要不要调用 swarm，用户不用手点工具。
- 记忆层接的是 RuVector：本地向量检索 + 轨迹对比学习（把跑成功的执行路径和失败的做对比来更新），官方说这部分检索和更新不需要调 LLM。

**适用场景**: 已经在用 Claude Code 或 Codex 做开发的工程师，想跑那种要拆成调研、写码、测试、审查多步的长任务；也适合想给团队统一 agent 配置、看 token 花费和任务轨迹的技术负责人。

**竞品对比**: 横向是 CrewAI、AutoGen、LangGraph 这类 Python 多 agent 编排框架，纵向是和 Claude Code 自带的 subagent / Task 工具比。最大差别是它不做独立运行时，寄生在现有 CLI 客户端里，靠 hooks + MCP 注入能力，学习成本主要落在配置上而不是改代码。

**成熟度**: 已迭代到 v3、有正式 npm 包和插件市场分发，但 README 里自绘的下载计数器、以及“original agent harness”这类说法营销味重，具体能力建议自己跑一遍再信。

## 趋势观察

今天这份榜单，基本是一张“给 AI Agent 修路”的施工图。共同点很清楚：大家不再比谁的模型更聪明，而是比谁给 agent 配的脚手架更顺手。 第一条线是插件化和官方下场。Anthropic 自己开插件市场，一条命令装齐 MCP、斜杠命令、子代理；Cursor 出了 plugin.json 规范；Google 把 Android 开发规范写成 SKILL.md 发给所有人。以前是社区自己摸，现在是厂商定标准，生态从野路子进入铺轨阶段。 第二条线是记忆和编排。共享长期记忆服务、把 Claude Code 和 Codex 塞进同一工作台各占一个 git worktree、Ruflo 往外壳里注入上百个 agent，都在解决同一件事：agent 从单线程变多线程，人脑管不过来了。缺的不是模型，是调度台。 第三条线是接口改造。把 CAD、LibreOffice、Calibre 包成命令行让 agent 直接调用，看着枯燥，杠杆却最大。软件不会为 agent 重写一遍，那就给 agent 装一只手。 第四条线是本地化。全本地语音克隆、本地视频修复、小显存也能跑大模型的节点图引擎，清一色强调自托管。算力贵、隐私敏感、订阅疲劳，三件事一起把需求推回本地。 最出圈的反而是一个求职框架：作者被裁后自己投了 69 份简历拿到 offer，然后开源。这说明普通人已经在拿 agent 处理自己的真麻烦，不再只是玩 demo。 合起来看：模型能力正在变成背景噪音，真正的新闻在接口、记忆、编排和本地部署这几层。谁把这些路修平，谁就拿到下一批开发者。
