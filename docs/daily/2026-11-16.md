# GitHub Trending 日报 · 2026-11-16

## 概览

今日共收录 **12** 个 GitHub Trending 项目。
主要语言分布：TypeScript(6)、Python(3)、Go(2)、C++(1)。

这批项目看着分散，说的其实是同一件事：模型不再是主角，把它接进工作流才是。一半的项目在给 Agent 修管道。MCP 统一接口，事件协议统一前后端，Chrome 直接把 DevTools 包成 MCP 服务器。各家都在抢着定标准，让 Agent 能真正动手。另一半在把经验打包成 Skills：漏洞打法、前端最佳实践、交易风控，全变成 SKILL.md，装进 Claude Code、Cursor。大家想明白了，与其反复提示，不如把流程固化成可安装的零件。再往下是干活的基础设施。腾讯用 SOP 串联十个 CLI，阿里把内部评审工具开源，还有人给 Agent 加弹窗审阅。共同点很清楚：要沙箱，要人工审批，要可回滚。人不再卡在流程里，但关键节点还得点头。底座也在补。零依赖 C 张量库支持 4bit 格式，离线推理正往手机和浏览器里挤。NVIDIA 开始做技能评测，这是个明确信号：行业从「能不能做」转向「到底有没有用」。一句话总结，大厂把内部工具往外开源，开发者把 Agent 当同事而不是玩具。真正热闹的不是模型，是模型周围那一圈工程。

### [google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills)

**亮点**

- 本身不是 SDK，而是'给 Agent 的说明书'：真正调设计 API 的是远端 Stitch MCP server，仓库只负责定义工作流和提示词，所以能跨客户端复用

- 做双向转换：extract-design-md 扫前端源码抽出设计 token 写成 DESIGN.md，code-to-design 再配合 extract-static-html（把 CSS 和图片内联成单文件 HTML）上传回 Stitch 项目

**适用场景**: 前端团队或个人开发者用 Google Stitch 出完设计稿后要落地成 React、Vite dashboard、shadcn/ui 代码；反过来也用于把已有 React/Vue 老项目导进 Stitch 统一设计系统。

**竞品对比**: 和 v0、Lovable、Figma 的 Dev Mode MCP 比，最大差别是不绑定客户端：遵循 agentskills.io 开放标准，Claude Code、Cursor、Codex 装的是同一套技能；Figma 那条路则锁死在自家 MCP 和付费席位里。

**成熟度**: 早期项目，Google Labs 实验性质，前置依赖 Stitch MCP 和账号配置，技能之间还有互相依赖，接口和技能命名都可能变。

**趋势信号**: Agent Skills（SKILL.md）开放标准正在 Claude Code、Cursor、Codex 之间快速扩散，同时 Google 刚把 Stitch 的 MCP 和 Antigravity 放出来，开发者正缺'能给 Agent 装的能力包'。

### [NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator)

 `Python` ⭐ +122 今日新增 · 1,939 总星数

> NVIDIA 的 AI Agent 技能评测框架：先做安全与格式检查，再用嵌入查重，最后在沙箱里跑带技能/不带技能的对照实验，量化技能到底有没有用。

**亮点**

- 被测对象是 skill 文件本身而不是 agent 输出：同一个任务跑两遍（带技能/不带技能），直接给出技能的边际贡献，而不是笼统的模型跑分
- 自己也做成一个 skill 分发（npx skills add），装进 agent 后可以直接问“我的技能行不行”，把评测入口塞进开发者的日常对话里

**核心功能**

- 三层流水线可拆开单独跑：Tier1 静态校验加安全扫描（内置 SkillSpector、Gitleaks，Semgrep 可选），Tier2 用嵌入向量算技能之间的语义重叠，Tier3 在 Docker 沙箱里跑 agent 对照实验
- 没有 API Key 也能出分：静态检查给出确定性评分（示例 86.2/100，默认及格线 70），CI 里靠退出码卡 PR，`skillevaluator ci init` 会直接提一个配置 PR
- Tier3 用 autopilot 造评测集：从 evals/EVAL.md、--prompt 任务文件或已保留的 trace 生成合成用例，再对比带技能与不带技能两次运行的行为差异

**适用场景**: 写 Claude Code、Codex 技能的开发者和做内部技能库/技能市场的平台团队。在 PR 里挂 CI 卡质量分和重复度，上线前跑沙箱实验确认技能真能提升任务成功率，安全团队用它查 skill 文件里的提示注入和危险命令。

**竞品对比**: 对比 promptfoo、DeepEval、Inspect AI 这类偏输出评测的工具，它评的是 skill 这个产物的静态质量、安全风险和跨技能重复，这几个维度竞品基本不覆盖；但沙箱跑 agent 那块反而是复用 Harbor，不比专门做 agent eval 的框架强。

**成熟度**: PyPI 上还是 0.9.x，API 可能变；但有 NVIDIA 背书、arXiv 论文、docs.nvidia.com 文档和 GitHub/GitLab CI 模板，工程完整度高于一般早期项目。

**趋势信号**: Agent Skills 规范（agentskills.io）和 Claude Code 技能生态刚铺开，第三方技能没有准入标准，NVIDIA 借 Verified Skills 流水线、开发者博客和配套直播推了这一波。

**亮点**

- 报告可审计性做成了卖点——433 条模式单独标注来源报告编号，安全从业者能自己判断某条 payload 是否适用于当前目标，而不是盲信 AI。
- 技能本身是纯 Markdown 文件，没有运行时依赖，因此跨 harness 移植的成本几乎为零，只换目录路径。

**核心功能**

- 技能靠语义匹配自动加载，无需按名字调用：每个 skill 是一份 SKILL.md，里面写了技能描述和适用场景；Claude 根据你说的“我在测什么”来挑选要加载哪几个技能，而不是靠 slash command 手动点名。

- 企业外围攻击矩阵覆盖 M365/Entra、Okta、vCenter、SharePoint、SSL VPN（Cisco/Fortinet/Citrix/Palo Alto/Pulse/SonicWall/F5）2024–2026 的 CVE 链，以及拿到凭据后的横向提权（IMDS、STS AssumeRole、跨账号 confused deputy）。
- 通过 Burp MCP 把 Burp Suite 作为 MCP server 接入，Agent 能直接读改请求包，而不只是输出文本建议。
- install 脚本按各 harness 的约定路径分发 skill 文件（~/.claude、~/.agents、~/.hermes、~/.gemini），同一套知识层可跑在 Claude Code、Codex CLI、OpenCode 等五个终端上。

**适用场景**: 适合做 SRC/漏洞众测的独立研究者、外包渗透测试团队和做外部红队初始访问的人。典型流程是：给出一个在范围内的域名，让它跑子域枚举（subfinder + crt.sh）、存活探测和指纹识别，按攻击面排序后直接进入 GraphQL introspection 或 OAuth redirect_uri 这类具体方向；最后按 H1/Bugcrowd VRT 口径生成报告并脱敏证据。

**竞品对比**: 和 PentestGPT 这类“给 LLM 套一个自主推理循环去跑渗透”的项目不同，它不接管流程，只提供知识和路由，执行仍由操作者驱动。和 PayloadsAllTheThings 这类静态 payload 仓库比，它多了按目标自动挑技能和组合链的能力。

**成熟度**: 仍在早期迭代（版本号为 v2，技能数从 82 涨到 83），但已在授权红队和 DVWA/Juice Shop 等靶场跑过；文档齐全，community 活跃度靠 star 增长而非 issue 反馈验证。

**趋势信号**: Claude Code 刚上线 plugin marketplace 和跨工具的 Agent Skills 格式，安全圈正好在试“把专家打法固化成技能包”，它踩在这个时间点上，一装即用。

### [ggml-org/ggml](https://github.com/ggml-org/ggml)

 `C++` ⭐ +43 今日新增 · 15,993 总星数

> 一个零依赖的 C 张量库，让大模型能在笔记本、手机、浏览器上离线跑。它是 llama.cpp、Ollama 的算力底座，最近因为支持 MXFP4/NVFP4 这类 4bit 微缩放格式再次上榜。

**亮点**

- 计算图和后端解耦的设计：先构图再执行，后端实现一组固定的算子接口就能接入，所以新硬件适配的工程量是“写 kernel”，不用改上层模型代码。
- 把量化做进 kernel 内层而不是先反量化成 fp16 权重，省的是内存带宽而不是算力。大模型推理本来就是内存带宽瓶颈，这一手让 7B 模型能塞进 8G 内存的笔记本。
- 主仓库刻意保持精简：核心改动要求提到 llama.cpp 那边发 PR，借 llama.cpp 的 CI 和用户量做测试，避免自己维护一套庞大的测试矩阵。

**核心功能**

- 运行时零内存分配：启动时按计算图一次性算好内存池大小并分配，推理过程中不再出现 malloc，避免堆碎片和分配抖动，这是端侧跑大模型时延迟稳定的前提。
- 2~8 位整数量化加 MXFP4/NVFP4 微缩放格式：每 32 个权重共享一个缩放因子，用 4bit 存数值，反量化直接塞进矩阵乘法的内层循环，边解压边用 FMA 累加，权重只从内存读一遍。
- 手写 SIMD kernel 覆盖 x86 的 AVX2/AVX512、ARM 的 NEON/SVE、RISC-V 的 RVV，再加 CUDA/Metal/Vulkan/SYCL 后端；模型先建成计算图，执行时按设备切后端，同一份模型代码不用改就能从 CPU 切到 GPU、NPU。
- GGUF 单文件同时装权重、超参和 tokenizer，拷一个文件就能跑，不用配 Python 环境或依赖树。

**适用场景**: 想在本地或端侧跑 LLM、语音识别的人：llama.cpp、whisper.cpp、Ollama、LM Studio 全都基于它；还有做边缘硬件和 NPU 的厂商，靠它给自家芯片写后端，让模型能在没有 Python、没有 CUDA 的设备上跑起来。

**竞品对比**: 对比 PyTorch/ATen，ggml 不追求算子齐全和自动微分，只做推理，代价是零依赖、编译出来几 MB、能在裸机和浏览器里跑；对比 ONNX Runtime、MNN、ncnn 这些推理框架，它多了 GGUF 这个事实标准的模型分发格式和 2~8bit 量化工具链；对比苹果的 MLX，它跨平台而不锁死在 Apple Silicon。

**成熟度**: 核心代码已经很稳定：llama.cpp 生态里的 Ollama、LM Studio 都在用，生产验证充分；但作为独立库版本号仍在 v0.x，API 频繁重构，官方明确说核心改动要走 llama.cpp 提 PR，第三方直接当依赖用要小心升级破坏。

**趋势信号**: OpenAI 用 MXFP4 量化发布 gpt-oss，llama.cpp 靠 ggml 的 MXFP4 kernel 当天就能跑；同时 NVIDIA Blackwell 原生支持 NVFP4，ggml 成了少数几个能吃下这些新 4bit 格式的推理内核，热度跟着回来。

### [GoogleChrome/modern-web-guidance-src](https://github.com/GoogleChrome/modern-web-guidance-src)

 `TypeScript` ⭐ +1,219 今日新增 · 7,447 总星数

> Chrome 联合 Edge、Firefox、MDN 做的一套「前端最佳实践技能包」，通过 CLI 把最新 Web API 指南按需塞进编码 Agent 的上下文，让 AI 别再生成 jQuery、重 polyfill 那套老代码。

**亮点**

- 把「文档」重做成「技能」：不是让模型读 MDN，而是人工校准成一篇篇带 ID 的 markdown 指南，由 CLI 精确投喂，控制上下文成本。
- 用评测结果当内容筛选器——哪些知识模型已经掌握就删掉，这在文档类项目里不常见，等于给知识库做了 token 预算管理。

**核心功能**

- CLI 只有三个动作：search 按自然语言找指南 ID、retrieve 取全文、legacy-scan 扫代码里的过时写法。Agent 只把命中的那一篇拉进上下文，不用整包文档撑爆 token。
- 每条指南挂 web-features 的 feature ID 和浏览器兼容数据，并强制写「降级回退」方案，引导模型用特性检测 + 轻量回退，而不是上来就引 polyfill 或老库。
- 内容靠评测反向裁剪：建了公开的 eval dashboard，跑模型生成代码的打分，把「模型本来就会」的低价值条目删掉，只留真正需要补的 250 个新特性（容器查询、Anchor Positioning、Popover、View Transitions、scheduler.yield 等）。

**适用场景**: 前端团队在用 Claude Code、Cursor、Copilot 写页面时接入，避免 AI 生成手写 div 弹窗、自制 tooltip、几十 KB 的 polyfill；也能用 legacy-scan 扫存量项目，列出该换成原生 API 的地方。

**竞品对比**: 和 Context7、llms.txt 这类「把文档抓下来喂给模型」的方案不同：那些是通用文档搬运，量大但没筛选；这套是浏览器厂商亲自写、按评测裁剪过的处方，还多一个扫旧代码的 legacy-scan。对手更像是 Cursor Rules 和 Claude Code Skills 里各团队自己手写的规范。

**成熟度**: 早期项目，刚开源不久、版本未到 1.0，CLI 和指南内容都在快速迭代；但已有 Chrome、Edge、Firefox、MDN 四方共管，贡献与治理文档齐全，可以先在团队里试用。

**趋势信号**: 2025 年下半年 coding agent 大爆发，Claude Code Skills、MCP、llms.txt 这波「让 Agent 读对东西」的生态起来，Chrome 拉上另外两家浏览器和 MDN 抢先占住「前端该用什么 API」这个入口。

**竞品对比**: 和 Luckysheet（同作者旧作，维护基本停了）、x-spreadsheet 比，架构重写且覆盖表格+文档+幻灯片；和 Handsontable、AG Grid 比，后者是表格组件，Univer 卖的是带公式引擎和协作的整套 Office 底座；和 OnlyOffice 比，它是可嵌入 SDK 而不是成品办公套件。

**成熟度**: 核心引擎活跃迭代、文档八种语言齐全，但协作、文件导入导出和 AI 扩展是商业授权，上生产前要算清授权成本和功能边界。

**趋势信号**: README 整个改写成 "Build your own AI office"，配套放出 AI SDK、CLI、agent 集成和 Univer Workspace 参考应用，正好踩在 agent 需要操作表格文档这波需求上。

### [backnotprop/plannotator](https://github.com/backnotprop/plannotator)

 `TypeScript` ⭐ +866 今日新增 · 12,042 总星数

> 给 AI 编程 Agent 加一层本地浏览器审阅界面：Agent 出计划、改完代码或提问时自动弹窗，你批注完一键回灌会话。多 Agent 并行时人不再卡住流程。

**亮点**

- 核心取舍是把审阅做成"异步队列"而不是"阻塞式确认"：Agent 提问后立刻释放，人什么时候有空什么时候答，答案还能精确回到发起提问的那个会话
- 批注数据落在本地共享目录，浏览器 UI 和终端 TUI 共用一份，等于把"审阅记录"当成跨工具的一等公民而不是某个界面的临时状态

**核心功能**

- 接入方式用的是各家 CLI 自己的 hook/plugin 机制，而不是包一层终端：Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、Pi 等 10 多个都适配了，Agent 一产出 plan 就自动打开本地页面，批注作为下一轮消息回给同一个会话
- 代码审阅把多种版本控制抽象成同一套 side-by-side diff 界面：Git 未提交改动、GitButler 工作区/堆栈、Jujutsu、Perforce、GitHub PR、GitLab MR 都能评，评论直接变成 Agent 的修改指令

## 趋势观察

这批项目看着分散，说的其实是同一件事：模型不再是主角，把它接进工作流才是。一半的项目在给 Agent 修管道。MCP 统一接口，事件协议统一前后端，Chrome 直接把 DevTools 包成 MCP 服务器。各家都在抢着定标准，让 Agent 能真正动手。另一半在把经验打包成 Skills：漏洞打法、前端最佳实践、交易风控，全变成 SKILL.md，装进 Claude Code、Cursor。大家想明白了，与其反复提示，不如把流程固化成可安装的零件。再往下是干活的基础设施。腾讯用 SOP 串联十个 CLI，阿里把内部评审工具开源，还有人给 Agent 加弹窗审阅。共同点很清楚：要沙箱，要人工审批，要可回滚。人不再卡在流程里，但关键节点还得点头。底座也在补。零依赖 C 张量库支持 4bit 格式，离线推理正往手机和浏览器里挤。NVIDIA 开始做技能评测，这是个明确信号：行业从「能不能做」转向「到底有没有用」。一句话总结，大厂把内部工具往外开源，开发者把 Agent 当同事而不是玩具。真正热闹的不是模型，是模型周围那一圈工程。
