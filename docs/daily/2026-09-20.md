### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,428 今日新增 · 18,184 总星数

> Cloudflare 开源的 coding-agent 技能包，用六个阶段加互相证伪的子 agent 做安全审计，产出带源码证据、机器可读的 findings.json。

**亮点**

- 用「覆盖账本 + 交叉证伪」替代了传统的「让模型直接吐漏洞列表」。核心不是模型多强，而是把审计过程变成可校验的证据链：每个攻击面单元记进 ledger，每条发现必须有源码追溯，换一个全新 agent 来推翻它。
- 安全边界写得很硬：需要 OS 级沙箱（禁外网、白名单环境变量、资源限额、只允许写临时目录）才会真正编译和执行目标代码，没有沙箱就不跑，相关线索一律降级成 needs_validation。这是防止审计 agent 自己被执行恶意代码的实用取舍。

**核心功能**

- 把审计拆成六阶段流水线：侦察建 architecture.md 和 coverage-ledger.json（攻击面清单）→ 按清单单元派隔离的 hunter → 候选验证 → 写 findings.json → 独立复核 → 出报告。每一步都要过 validate-coverage-ledger.cjs / validate-findings.cjs 这两个零依赖 Node 脚本，findings.json 必须符合 report-schema.json。
- 对抗式验证：找到漏洞的 agent 和验证它的 agent 不是同一个，验证 agent 的任务是尽力证伪（disprove）。最终结论只有三种——confirmed（有完整调用链和可观测结果）、needs_validation（有明确未决事实、不给严重级别）、rejected（被证伪），逼着 agent 拿证据说话而不是凭感觉报高危。
- 攻击面分类写死在十几个 Markdown 提示词里：内存安全与二进制、AI/LLM 提示注入、Web 协议与认证、客户端 DOM 注入、供应链与发布、云与 IAM、RPC 与消息队列、资源耗尽、多租户数据隔离、桌面与本地 IPC 等。针对不同目标加载不同狩猎类，不靠一套通用 prompt 打天下。
- 支持增量：重复跑同一仓库是在旧 ledger 和 findings 上叠加，用旧账本定位没覆盖的缺口，重验源码变过的部分，不把上一轮未决的条目当成已覆盖。官方说单次跑只能找到重复跑总发现量的大约一半。

**适用场景**: 安全工程师和研发团队用 Claude Code 这类支持并行子 agent 的编码助手，对自己或客户的代码库做审计和渗透测试，输出可直接进 issue 系统或报告的机器可读结果。开源维护者和做合规审计的团队也能用来做周期性的重复扫描。

**竞品对比**: 和 Semgrep、CodeQL 这类基于规则/查询语言的 SAST 比，它没有固定规则库，靠多 agent 按攻击面清单狩猎并互相证伪，能覆盖业务逻辑和认证协议这类规则写不出来的问题，但更慢更贵、结果不稳定。和半成品 LLM 找漏洞 prompt 比，差别在于它有覆盖账本、结构化 schema 和独立验证，不是一次性输出。

**成熟度**: 刚开源的新项目（MIT，无版本号），18k star 里 2.4k 是单日涨的，明显是发布当天爆火；README 说它是 Cloudflare 内部漏洞挖掘 harness 的单仓库起点、经过实战，但作为公开 skill 的提示词和流程大概率还会大改。

**趋势信号**: Cloudflare 刚发博客《Build your own vulnerability harness》把这个内部系统亮出来，同时 Anthropic 的 Agent Skills 生态（skills.sh CLI、SKILL.md 格式）正在快速铺开，两个热点撞在一起，加上「AI 自动挖漏洞」最近本来就是安全圈最热的题目。

### [trycua/cua](https://github.com/trycua/cua)

 `HTML` ⭐ +1,018 今日新增 · 25,249 总星数

> Cua 给 AI Agent 配了一台能真正操作的电脑：开源桌面驱动、云端隔离桌面集群、苹果芯片上的本地虚拟机，外加评估基准和小模型，让 Agent 在代码、API 和图形界面之间自由切换。

**亮点**

- 不跟模型绑定：自带 agent 和模型都行，Cua 只负责"电脑"和操作工具，驱动层同时提供 CLI、MCP 和类型化 SDK 三种接入方式
- Cua Bench 能把 Agent 操作过程导出成轨迹（trajectory），直接当训练数据和评测集用，形成了"环境—执行—评估—数据"的闭环

**核心功能**

- Cua Driver 在 macOS/Windows/Linux 上做原生应用操作，支持"后台投递"——不抢鼠标、不抢窗口焦点就能点按钮、填表单（前提是系统和应用支持）
- Cua-S1 是专门做"System 1"决策的小模型：不解码 token 生成文字，而是直接对结构化界面元素打分，判断某个字段该填什么值、某个元素要不要动
- Lume 在 Apple Silicon 上用苹果原生虚拟化框架跑 macOS/Linux 虚拟机，本地就能开一台干净的桌面临时环境
- Fleets 用池化方式预置云端 Linux 桌面，代码从池里领一台，通过同一套 Sandbox SDK 执行命令、截图、操作应用，本地沙箱和云沙箱 API 一致

**适用场景**: 做 computer-use Agent 的团队——比如用 Claude Code、Cursor、Codex 接 MCP 来驱动桌面软件的开发者，需要批量跑任务做训练数据或回归评测的算法工程师，以及要隔离环境跑自动化测试的 QA。

**竞品对比**: 和 Browserbase、E2B、Daytona 这类沙箱比，Cua 多了原生桌面应用操作和 macOS 本地虚拟机；和 pyautogui、Appium 这些老式自动化库比，它的后台投递不抢焦点，且是为 LLM Agent 设计的。

**成熟度**: 热度很高（25k star，单日 +1000），Driver 和 Fleets 可用，但 Cua-S1 明确标注是早期源码研究版、权重另放 Hugging Face，API 可能还会变。

**趋势信号**: Claude Computer Use、OpenAI Operator 把 computer-use 带火之后，社区缺一套开源、能接 MCP 直接插进 Claude Code/Cursor 的桌面操作底座，Cua 这次主推的 Fleets 云桌面集群正好补上这块。

### [affaan-m/ECC](https://github.com/affaan-m/ECC)

 `JavaScript` ⭐ +826 今日新增 · 263,889 总星数

> ECC 是一套跨 AI 编程客户端（Claude Code、Codex、Cursor、Opencode 等 7 种）的 Agent 增强层，统一提供技能、记忆、安全拦截和先调研后改代码的工作流，省得你为每家工具各配一套规则。

**亮点**

- 把自己定位成 'agent harness 的操作系统'——不抢客户端的位置，而是插在客户端和模型之间，统一管记忆、技能和安全，客户端换了你也不用重配
- 把安全能力拆成独立的 npm 包 ecc-agentshield 单独发版，而不是塞进主插件里，这样即使用户不用整套 ECC 也能只装安全层

**核心功能**

- 跨 harness 兼容层：同一套插件（npm 包 ecc-universal）适配 Claude Code、Codex、Cursor、Opencode 等 7 个客户端，配置写一次到处能用，不用给每家重复维护 rules 和 memory 文件
- instincts + memory 机制：把会话里验证过的做法沉淀成可复用的行为规则，跨会话保留，减少每次开新对话都要重新解释项目背景的重复劳动
- ecc-agentshield 安全层：单独发 npm 包，在 agent 真正执行命令/改文件前做拦截和审查，防止 AI 误删文件、乱跑 shell、泄漏密钥这类事故
- research-first 工作流：强制 agent 先去查证（文档、代码、搜索结果）再动手改，降低瞎猜 API、编造函数名的情况

**适用场景**: 日常用 Claude Code / Codex CLI / Cursor 写代码的开发者，尤其是同时在 2-3 个客户端之间切换的人，不想每家各写一份 CLAUDE.md、rules、mcp 配置。团队里给 agent 加一层安全闸门、避免它直接跑危险命令的场景也适用。

**竞品对比**: 对手主要是各客户端自带的配置体系（Claude Code 的 CLAUDE.md/skills、Cursor 的 rules）和社区框架如 SuperClaude、claude-flow。最大差异是它不绑死一家客户端，一套配置覆盖 7 种 harness，而多数同类项目只服务 Claude Code。

**成熟度**: 已商业化运营：有 npm 包、GitHub App、Discord、14 语言文档、$19/seat/月 的 Pro 付费档，但核心只由一名维护者每周发版，且 26 万 star 这个量级明显需要自己再核实一下真实活跃度，接入生产前建议先小范围试。

**趋势信号**: 现在 AI 编程客户端在混战（Claude Code、Codex CLI、Cursor、Opencode 各占一块），用户不想被单一工具锁死，加上 agent 乱执行命令的安全事故越来越多，跨客户端的统一增强层正好踩在这两个痛点上。

### [anthropics/claude-code](https://github.com/anthropics/claude-code)

 `TypeScript` ⭐ +419 今日新增 · 147,202 总星数

> Anthropic 官方终端 AI 编程代理的仓库，用自然语言让 Claude 读代码、改文件、跑命令、走 git 流程；这个 GitHub 仓库本身主要是 issue 反馈区和插件集合，不包含 CLI 源码。

**亮点**

- 反直觉的取舍：别人都在做代码库预索引，它偏不做，靠模型现场搜索。好处是零配置、代码改了不用重建索引，坏处是大仓库里搜索慢、token 消耗高
- 扩展全走配置而不是 UI：CLAUDE.md 管记忆、hooks 管自动化、MCP 管外部工具、subagents 管并行，全部是文件+命令行，天然能进版本控制和 CI

**核心功能**

- 不做代码库向量索引，改成让模型自己用 grep/glob/读文件按需搜索（agentic search），省掉索引构建和失效维护，代价是每次任务都要重新探索一遍仓库
- CLAUDE.md 项目记忆文件 + /init 扫描生成，团队把构建命令、代码规范、目录约定写进去，等于给 agent 一份常驻上下文，不用每次重复交代
- hooks 机制：在 PreToolUse / PostToolUse 等节点挂 shell 命令，比如改完文件自动跑 prettier、lint 或测试，失败就把错误喂回模型重试
- 支持 MCP（Model Context Protocol，一套让模型接外部工具的标准协议）连接数据库、Jira、Figma 等，还支持 subagent 开独立上下文窗口并行干活

## 趋势观察

今天的热榜基本围着 Agent 转。一边是「给 Agent 配装备」：ECC 想统一七家客户端的技能和记忆，Addy Osmani 把开发流程拆成技能包，Cloudflare 拿六个阶段加互相证伪做安全审计，Anthropic 直接给金融行业发模板。另一边是「让 Agent 有手有脚」：Cua 给它一台真电脑，BuilderIO 和 Vercel 让它和 UI 共用一套工具与状态。共同点很清楚：大家不再只比谁家模型强，而是比谁的 Agent 更能干活、更安全、更能复用。开发者生态正从「写提示词」转向「搭基建」——技能、编排、断点续跑、审计证据、缓存字段，全是工程活。MCP 成了焦点，也成了靶子。有人骂它设计就错了，有人实测它重复拉工具列表，还有人喊要在 Agent 和工具之间加一层确定性策略，让授权不再交给 LLM。吵归吵，方向一致：Agent 接工具这层得管住。另外，自托管明显变热。文档、开发环境、GPU 训练、行情看板，都在往自己机器上搬。配上「确定性内核加不确定外壳」那篇博客，再加上 PE 收购诊所、AI 安全监管俘获这类新闻，能看出一条主线：大家既想要 AI 的能力，又不想把控制权全交出去。工具在变强，信任在被重新定价。
