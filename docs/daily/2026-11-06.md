### [NVIDIA/auto-ontology](https://github.com/NVIDIA/auto-ontology)

 `Python` ⭐ +2,679 今日新增 · 7,856 总星数

> NVIDIA 开源的企业语义层：把元数据建成知识图谱，Agent 生成 SQL 前先统一指标定义，回答自带 SQL 和出处。

**亮点**

- 带反馈回写：人工确认过的修正会折回本体，同一个问题第二次问就更准，语义层从静态文档变成会被使用数据喂大的东西
- 模型按角色拆成三件套（ENDPOINT / API_KEY / MODEL）：reasoning、non-reasoning、embed、rerank 各一套，实体抽取走轻模型、问答走重模型，弱项字段自动回落到 DEFAULT_MODELS

**核心功能**

- 先从元数据生成企业本体（实体、指标、关系），问题里的 revenue、product、state 这类词先被解析成本体里的认证术语，再沿关系自动推出 join 路径，而不是让 LLM 自己猜怎么连表
- 生成的 SQL 要拿认证定义和数据血缘过一遍校验，答案连同 SQL 和执行步骤一起返回，能拿结果回原库对数
- 本体、数据目录、向量都放在同一个 Postgres + pgvector 里；对外同时开 MCP、CLI、REST API 三种口，任何 Agent 框架都能接

**适用场景**: 数据平台或分析团队，在给 Claude Code、Cursor 这类 Agent 接内部数仓时用。前提是有人先把口径定下来，Agent 查数才不会把营收算错；已经用 dbt 或 Cube 维护语义模型的团队，可以让 Agent 复用同一套定义。

**竞品对比**: 正面撞 dbt Semantic Layer、Cube、AtScale 这类商业语义层，以及 WrenAI、Dataherald 这类开源 text-to-SQL。差别是它把「校验 + 血缘」做成了生成 SQL 前的强制门槛，并且原生走 MCP 给 Agent 用；代价是默认推理绑在 NVIDIA NIM 端点上。

**成熟度**: 刚开源，官方明确不接受外部 PR，API 还会变；有 Helm 和 Docker Compose、有完整 Web UI，但种子数据脚本放在另一个仓库，目前适合跑 demo，别急着上生产。

**趋势信号**: NVIDIA 亲自下场开源「Agent 上下文层」，正好赶上语义层成为 2026 年共识、MCP 变成事实标准，一天 2600+ star 是发布日的集中曝光。

### [vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)

 `Rust` ⭐ +2,173 今日新增 · 17,305 总星数

> Vercel Labs 出的桌面操作 CLI：让 AI 读系统无障碍树来点按钮、填表单，不截图不比像素，还能直接当 MCP 工具接进任意 agent。

**亮点**

- 工具里不内置模型，只做"看—点—再看"的哑执行器，循环逻辑留给调用方 agent。这样换模型、换策略都不用动工具，也不会把工具和某家模型绑死
- 二进制自带和版本匹配的 skill 说明书（agent-desktop skills get desktop / platform），agent 第一次用自己读文档，不用人写 prompt 教它怎么点

**核心功能**

- 不靠截图和像素匹配，直接读 macOS 的 AX API、Windows 的 UI Automation、Linux 的 AT-SPI，把整个窗口转成 JSON 树，每个可操作元素带一个 ref（如 @s8f3k2p9:e8），点它就行
- ref 绑定快照 id：UI 一变就返回 STALE_REF 或 AMBIGUOUS_TARGET，强制 agent 重拍快照；错误里还带 disposition.retry 字段，告诉 agent 这次失败能不能安全重试
- Rust 写核心，通过 PlatformAdapter trait 在编译期选平台 crate，CLI 和 C 库共用同一套逻辑；动作默认走无障碍 API（headless），不移动鼠标、不抢焦点，加 --headed 才用物理输入

**适用场景**: 想让 agent 操作真实桌面软件的人：比如让 Claude Code、Cursor 里的 agent 打开 Excel 导报表、在 Slack 翻历史消息、走只有图形界面没有 API 的老系统（ERP、银行客户端、医疗软件）做 RPA；也适合 QA 写端到端测试。

**竞品对比**: 对手是 Anthropic Computer Use、OpenAI CUA、微软 UFO 这类截图 + 坐标方案，以及只做浏览器的 browser-use / Playwright。最大差别是不吃图像：token 少、定位准、可复现，但只对有无障碍树的应用有效，自绘 UI、游戏、Canvas 应用基本没辙。

**成熟度**: Vercel Labs 实验项目，CLI 接口已成型、文档站点完整、npm/brew 都能装，但仍在 Labs 阶段，60 个命令里有 4 个（key-down 等）还是占位拒跑，API 可能变。

**趋势信号**: computer use 正从截图方案往结构化无障碍树上转（更便宜更稳），加上 MCP 生态爆发，一条 mcpServers 配置就能接进 Claude/Cursor，Vercel Labs 的品牌又自带流量。

**核心功能**

- 技能本体就是一个 SKILL.md 纯文本文件，不含任何代码，同一份内容通过 Claude Code 插件市场、Codex marketplace、Copilot 插件源、Gemini CLI 的 skills install 或 npx skills@latest add 分发到 5 家以上 agent，不锁模型也不锁编辑器。

**适用场景**: 用 Claude Code、Codex、Cursor、Copilot 写真实业务代码的工程师，尤其是被 agent 输出啰嗦、改错方向、写完不跑测试折腾过的人。适合在已有仓库里补一套可复用的工作流，而不是从零生成项目。

**竞品对比**: 对手是 BMAD、GitHub Spec-Kit、GSD 这类重型 agent 流程框架，它们定义完整阶段和角色但侵入性强、排他；这套技能的差异是可拆、可改、无流程绑定，代价是依赖你自己知道该在什么时候调哪个技能。

**成熟度**: 文档和安装引导写得比多数同类项目细，覆盖主流 agent 且多数能自动更新，但本质是作者个人日常配置的集合，内容随他习惯漂移，API 层面不算稳定。

**趋势信号**: Claude Code、Codex、Copilot 最近陆续上线插件/技能市场，社区正从『抄提示词』转向『装技能包』，这个仓库刚好是最早一批以插件形式分发的个人技能集，加上作者 6 万人 newsletter 引流。

### [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling)

 `Python` ⭐ +1,655 今日新增 · 98,320 总星数

> Scrapling 是一个 Python 爬虫框架，把 HTTP 请求、隐身浏览器、解析、并发爬取和 AI Agent 接入合并到一个库中，省去了在 requests、Playwright、Scrapy 之间来回切换的工作。目前在 Trending 上出现，主要因为它推出了 MCP server 和 Agent Skill。

**亮点**

- 用同一套 CSS/XPath 选择器 API 覆盖整个流程：单次请求、渲染页面、全站爬取都使用同一个写法，学习成本比 Scrapy + Playwright 两套体系低。
- 把爬虫做成 MCP 工具，让 AI Agent 直接调用：Agent 自己决定抓哪个 URL、取哪些字段，省去为每个站点编写爬虫。

**核心功能**

- 自适应元素定位：抓取每个元素时保存其 DOM 位置、文本、属性等特征；网站改版后，如果选择器失效，就按这些特征重新匹配到原来的元素，以减少重新编写解析代码。
- 隐身浏览器模式：修改浏览器指纹，并直接处理 Cloudflare Turnstile 和 Interstitial 验证页；同时能捕获页面背后发出的 XHR/fetch API 请求，改用直接请求接口代替渲染整页。
- 基于 async 的 Spider 架构：支持代理轮换、失败重试、AutoThrottle 自适应限速、断点续爬（暂停后可从上次状态继续），结果可直接导出 JSON/JSONL/CSV/XML 或干净的 Markdown。
- 自带 MCP server 和 Agent Skill：Claude 这类 AI Agent 可以直接调用它的浏览、抓取能力，不需要自己编写爬虫代码。

**适用场景**: 需要批量采集网页的数据工程师和分析师，例如价格监控、舆情抓取、给 RAG 或微调准备语料。也适合只想在终端临时抓一个页面的开发者，以及在 AI Agent 里需要实时联网取数的场景。

**竞品对比**: 与 Scrapy 相比，Scrapling 内置了隐身浏览器和 JavaScript 渲染，而 Scrapy 需要自行接入；与 Crawl4AI、Firecrawl 相比，它更侧重完整爬虫能力（代理轮换、断点续爬、限速），不只是把页面转成 Markdown；与 Playwright + BeautifulSoup 手动组合相比，它更省配置。

**成熟度**: 文档、CI、Docker 镜像、多语言 README、Discord 社区都已具备，属于可用的成长期项目，但版本迭代快，接口仍可能变动。

**趋势信号**: 2025 年到现在，AI Agent 联网取数需求爆发；它通过适配 MCP server、Agent Skill、OpenClaw Skill 三套 Agent 生态，直接进入了这波流量。

### [JiaFeiMiao-K-Cat/DiscImageStudio](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio)

 `C#` ⭐ +984 今日新增 · 7,458 总星数

> 把一张图片变成符合 CD/DVD/单层 BD-R 物理层约束的数据流，用普通刻录机烧进普通空白盘，盘面就会显出肉眼可见的图案。不依赖 LightScribe 这类专用硬件。

**亮点**

- 思路上的关键在于逆向利用刻录物理层：普通刻录软件追求数据正确，这个项目反过来，把数据位流当作像素来解，用求解器挑出烧出来最亮或最暗的位流组合。
- 即时流式刻录不在硬盘上生成完整镜像，这对 25GB 蓝光很关键；这样既省下几十 GB 临时空间，也缩短总耗时。

**核心功能**

- DVD 引擎是个约束求解器：它把图像转成满足 DVD 物理层规则的 NRZI 通道位流，并处理 ECMA-267 规定的 ECC 块、EFMPlus 8/16 调制和扰码，让 pit 和 land 的分布正好呈现出需要的灰度图案，而不仅仅是数据合法。
- CD 走的是另一条路：只输出 0D 和 AA 两种字节组成的音轨，这两种字节经 EFM 编码后 pit 长度不同，反射率也不同，因此形成两级灰度；导出 WAV+CUE 或 RAW，交给 cdrecord 或 ImgBurn 烧录。
- 蓝光部分用 17PP 调制、ECC 簇和 3T/6T 长度映射，把图案映射到单层 25GB BD-R 上，还能顺便写 UDF 2.01 文件系统，让盘上既有图案，也有能读出来的文件。
- 标定用手机拍摄光盘照片，估计内外半径和轨距分布，再用三次多项式拟合轨距随半径的变化；因为刻录机如果按恒定轨距生成图案，径向线条会弯成弧。
- .NET 10 做核心，WPF 图形界面和跨平台 CLI 共用同一套引擎；即时烧录直接走 Windows 自带的 IMAPI2，一边生成一边写入，不在硬盘上生成完整镜像。

**适用场景**: 给做实体介质创作的人、光盘收藏玩家、做演示物料或礼物的人用：在 Win 上用 GUI 排版并导出 ISO，或插上刻录机直接烧；Linux/macOS 用户用 CLI 生成镜像，再拿 cdrecord 或 ImgBurn 烧。

**竞品对比**: 直接对手是 LightScribe 和 LabelFlash，它们必须在支持该技术的专用刻录机上加专用盘片才能烧盘面图案；这个项目换成任何普通 CD/DVD/BD 刻录机加普通空白盘，差别是硬件门槛基本归零，代价是图案只有黑白两级，且要按盘片手工标定。

**成熟度**: 属于早期项目：即时烧录被明确标为实验性，蓝光只支持单层 25GB，Linux/macOS 的 CLI 也是实验状态，文档和自检很全，但真实盘片验证的覆盖面还窄。

**趋势信号**: 单日涨近千星，多半是实拍盘面效果图在社交平台传开，加上光盘刻录这个小众圈子本来就对物理层面玩法敏感；具体触发事件不明。

### [floci-io/floci](https://github.com/floci-io/floci)

 `Java` ⭐ +779 今日新增 · 30,595 总星数

> Floci 是一个用 Java 写的本地 AWS 模拟器，一条 docker compose up 就能让 S3、DynamoDB、Lambda 等服务跑在本机 4566 端口，不需要 AWS 账号也不用付费解锁功能，是 LocalStack 的免费替代品。

**亮点**

- 命名策略是「直接当 LocalStack 用」：README 里专门提供迁移章节，用户只需把镜像名从 localstack/localstack 改成 floci/floci 就能继续用，降低替换成本
- 控制台以 sidecar 形式按需拉起、可插拔，并把「连得上 Floci」作为健康检查条件，于是控制台不需要自己知道 Floci 的地址，也不需要额外暴露端口

**核心功能**

- 所有 AWS 服务共用一个端点 http://localhost:4566，SDK、CLI、Terraform、CDK、OpenTofu 只需改 AWS_ENDPOINT_URL 这一个环境变量，凭证随便填非空值即可，代码不用改
- 对保真度要求高的服务（如 Lambda）真正启动 Docker 容器来运行，不再只是返回假响应，测试结果更接近真实云端
- Web 控制台按需启动：访问 /_floci/ui 时才去拉控制台镜像，作为 sidecar 容器挂在 Floci 的 Docker 网络上，把 Floci 自己可达的地址注入成 AWS_ENDPOINT_URL，控制台日志会写入本地的 CloudWatch Logs；控制台可换成第三方，只要实现「监听 PORT、提供 /api/health、连 AWS_ENDPOINT_URL」这份约定即可
- 支持 Testcontainers，测试代码里可以直接把 Floci 容器当作依赖启动

**适用场景**: 后端和平台工程师在本地开发、跑集成测试、配 CI 流水线时用它，替代真实 AWS 账号：写 Terraform/CDK 的团队可以本地 plan+apply 验证，Lambda 开发者能在本机调试函数，CI 里则用来跑不需要联网和密钥的端到端测试。

**竞品对比**: 主要竞品是 LocalStack：LocalStack 近年版权把不少服务和功能放进了付费版，还需要 auth token，而 Floci 是 MIT 许可，无账号、无功能门槛，能直接换镜像。跟 Moto 的区别是 Moto 是进程内的 Python mock 库，Floci 是独立容器，且对 Lambda 这类服务会起真实容器。

**成熟度**: 仍处于早期（镜像版本 0.7.x），仓库从 hectorvent/floci 改名迁移到 floci-io/floci，旧镜像不再更新，API 和配置项可能还会变，但 3 万 star 说明已经过一批用户实际验证。

**趋势信号**: LocalStack 把越来越多能力收到付费墙后面、社区对 auth token 和功能限制的不满积累已久，Floci 正好卡在这个时间点以「免费、无账号、换镜像即用」的姿态接住了迁移需求。

**成熟度**: Vercel Labs 实验项目，有完整文档站和 npm/Homebrew 多平台预编译包，但属于 LABS 标，API 和命令可能变，不建议无脑上生产。

**趋势信号**: MCP 之外，Agent 工具正在往 CLI + skills 这波转向，Vercel 借 skills.sh 推自己的标准，同时赶上 Playwright MCP、browser-use 带火的 Agent 浏览器赛道。

### [lz4/lz4](https://github.com/lz4/lz4)

 `C` ⭐ +23 今日新增 · 12,465 总星数

> 老牌无损压缩库 LZ4 更新基准：单核解压 4.9 GB/s，接近内存带宽，压缩率约 2.1。适合压缩不是瓶颈、解压速度才是瓶颈的场景。

**亮点**

- 把"解压速度"当成唯一硬指标来设计格式：宁可牺牲压缩率，也不在解压路径上加 Huffman/FSE 这类熵编码阶段。这让它比 zstd 快 3 倍，但压缩率也只有 2.1 对 2.9。
- 库用 BSD-2、命令行工具用 GPL-2.0 的双授权，商业闭源产品能直接嵌库而不被传染，这是它比很多同类压缩库更容易进大厂代码库的原因之一。

**核心功能**

- 解压端不做熵编码：块格式里只有"字面量拷贝 + 回溯匹配拷贝"两种指令，解压就是查偏移再 memcpy，所以单核能跑到 4950 MB/s，是 Snappy（1350 MB/s）的 3.6 倍。
- 同一套解压器配两档压缩器：默认档 770 MB/s 压出 2.11 倍，LZ4_HC -9 只用 40 MB/s 就换来 2.72 倍，但两者解压速度一样（约 4800 MB/s）。加压缩成本不影响读端。
- 一个 acceleration 整数直接调压缩率/速度的权衡，不用换算法、不用换格式；另支持字典压缩，只取字典末尾 64 KB，能直接吃 zstd 的字典训练器产物，专治几百字节小包压不动的问题。

**适用场景**: 数据库和消息队列的块压缩（Kafka、ClickHouse、RocksDB、Cassandra 都内置它）、Linux 内核 zram 和文件系统透明压缩、游戏资源包与容器镜像层。用户是写存储引擎或做数据管道、被解压 CPU 开销卡住的工程师。

**竞品对比**: 对比 Snappy：压缩率几乎一样（2.11 对 2.09），但解压快 3.6 倍，Google 自己也在往 LZ4 迁。对比 zstd：zstd 默认档压缩率高 37%（2.9 对 2.1），但解压只有 1570 MB/s。LZ4 占的是"压缩率够用、解压最快"那一格，两者是互补不是替代。

**成熟度**: 生产就绪，v1.11.0 版本，十几年历史，几乎所有 Linux 发行版和主流数据库都内置，API 早已冻结。

**趋势信号**: 原因不明。这是 1.2 万 star 的老基础设施项目，每天 23 star 属于常态曝光而不是爆红；近期唯一动作是 v1.11.0 版本和 README 里的基准表刷新。

## 趋势观察

今天热榜几乎被同一件事占满：大家都在给 AI Agent 写说明书。 Matt Pocock 开源了自己的技能包，Garry Tan 开源了 23 个斜杠命令，把 AI 拆成 CEO、设计、评审、QA 几个角色；Google 把 GCP 认证、GKE 排障写成 SKILL.md，一条 npx 装进去；Scenario 教 Agent 出图出视频；还有人直接打包 6 个技能做成合集。格式高度一致：Markdown、小份、可改、装进 Claude Code 或 Cursor 就能用。 第二个共同点是 MCP。Scrapling 靠 MCP server 和 Agent Skill 冲上榜单；Vercel 的命令行浏览器和桌面操作 CLI 都能直接当 MCP 工具挂进任意 Agent。接口统一后，工具开始互相拼装。 第三，大厂下场定规矩。NVIDIA 做企业语义层，Agent 写 SQL 前先对齐指标口径；微软开源语音模型家族，量化后纯 CPU 跑。以前是社区教模型怎么用工具，现在官方亲自写套路，让模型照着走，而不是瞎猜。 也有专补基础设施的：给 git worktree 包一层，让多个 Agent 并行改代码不打架；浏览器状态留在后台守护进程，每步只发一条短命令，省掉反复启动的开销。 几点感受。技能包正在变成新的分发形态，像当年的 npm 包，只不过内容是“怎么干活”。Agent 的瓶颈不在模型，在流程和口径。谁能把行业 know-how 写成模型读得懂的指令，谁就占住位置。另外榜上还混着 LZ4 单核解压 4.9 GB/s、把图片烧进普通光盘这种硬核项目，说明生态没被 AI 淹掉，AI 只是长在了老地基上。
