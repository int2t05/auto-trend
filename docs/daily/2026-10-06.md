# GitHub Trending 日报 · 2026-10-06

## 概览

今日共收录 **13** 个 GitHub Trending 项目。
主要语言分布：TypeScript(4)、Python(3)、JavaScript(2)、C++(2)、Shell(1)。

这批项目指向同一个方向：AI Agent 正在变成新的操作系统。测试、CAD 建模、剪视频，全被做成 Agent 插件。Claude Code、Cursor、Codex 成了统一入口，围绕它们做工具就能冲上 Trending。今天排第一的正是个 AI 测试 agent，用自然语言写目标，跑通后录成回放，下次不再烧模型算力，直接打 Playwright、Cypress 维护 locator 的痛点。

第二是补短板。Agent 没记性，就有人做跨会话记忆，压缩历史再注入；Agent 没眼睛，就有人做免费联网工具，让它读推特、Reddit、B站、小红书，不付 API 费。记忆和联网，是 agent 落地绕不过的两块砖。

第三，开发者开始算账。T3 Code 远程操控本机 agent，复用现有订阅额度，不另配 Key。能白嫖就白嫖，成本意识上来了。

自托管和隐私依然很硬。健身记录放自己服务器，DNS 拦截用 2 美元 ESP32 搞定，Cloudflare 干脆把内部 AI 工作台开源，每人跑一份实例。数据攥在自己手里，这个诉求没退过。

还有一条暗线：绕开主流。AnyPS5 不跑模拟器，靠重链接把 PS5 程序变成原生程序；Stremio 用统一协议聚合片源。不跟大厂走，自己找路。

总体看，生态正从 demo 转向日常工具链。记忆、联网、省钱、自托管，是这轮四个关键词。

### [DuarteSantos8/openGym](https://github.com/DuarteSantos8/openGym)

 `JavaScript` ⭐ +1,433 今日新增 · 4,512 总星数

> 自托管健身与体重记录应用：Docker 一键部署、passkey 登录、1324 个动作库，能从 Strong/Hevy/FitNotes 导入数据，训练记录留在自己服务器上。

**亮点**

- AI 相关功能（AI 教练、MCP server）全部默认关闭，跑在自己服务器、用自己填的 API key（Anthropic/OpenAI/Gemini/Ollama 都行），且 AI 给的改动必须人工确认才生效——把'要 AI'和'数据不出门'这两个冲突需求拆开处理。
- 上传自定义动作媒体的位置信息在设备端就剥掉了，不经服务器；加上 17 种语言（含从右到左的阿拉伯语）连动作名称和说明都翻译了。

**核心功能**

- 多设备同步是合并（merge）不是覆盖：两台设备同时编辑同一条记录不会互相冲掉，配合 WebAuthn passkey（用 Face ID/指纹代替密码）登录，新设备靠一次性验证码或二维码配对。
- 肌肉状态图分三种模式看：练到的容量、还在恢复的、已经退练的，各自映射到人体图上；再叠加每个动作的估算 1RM 曲线和结构性平衡比（Poliquin/Thibaudeau/ATG 这几套力量训练界的肌群比例标准）。
- 进度规则可配置到单个动作：线性加重、Greyskull LP、双进阶（在设定次数区间内先加次数再加重量）或加时长；没完成的次数不加重量，连续停滞自动触发减载（deload）。
- 数据进出都走现成格式：直接导入 FitNotes/Strong/Hevy 的 CSV 或 API key、Apple Health 体重导出，导出统一是一个 JSON；另外带一个只读的本地 MCP server，让 Claude Desktop 之类助手查你的训练历史。

**适用场景**: 适合有 NAS、VPS 或家用服务器、又不想把训练数据交给订阅制 App 的健身者，尤其是一直用 Strong/Hevy/FitNotes 但担心数据被锁的人；也适合带几个学员的教练，用多 profile 加邀请制管理后台分开记。

**竞品对比**: 跟 Strong、Hevy、FitNotes 比，最大差别是这些 App 数据在厂商云上、功能绑订阅，而 openGym 是 Docker 起在自己机器上、可 fork；跟同为自托管的 wger 比，它多了 passkey 登录、离线 PWA、从上面这几款 App 的导入通道，以及恢复/退练视角的肌肉图。

**成熟度**: 文档和测试齐全——有 CI 测试徽章、覆盖率、changelog、roadmap，自托管指南覆盖 Cloudflare Tunnel/Caddy/Traefik/nginx 和 Kubernetes，还有在线 demo 和 Android APK；但由个人维护、未见企业用户验证，属于可用但建议先备份数据的阶段。

**趋势信号**: 赶上两股潮流叠加：一是'自托管、数据归自己'的反订阅情绪，二是它把 MCP server 和自带 API key 的 AI 教练做进了健身记录里，正好蹭上 2025 年 MCP 生态爆发的热度，一天涨 1400+ 星大概率是 HN/Reddit 上被推了一把。

### [tester-army/e2e](https://github.com/tester-army/e2e)

 `TypeScript` ⭐ +1,398 今日新增 · 5,131 总星数

> 用自然语言描述测试目标，AI agent 驱动 web 和移动端 App 完成操作，首次跑通后录成回放、下次不再调模型。目标是降低 Playwright/Cypress 里维护 locator 和脚本的成本。上线即冲上 GitHub Trending 第一。

**亮点**

- 把 LLM 放在'首次探索'而不是'每次执行'的位置——录下来回放。这一招同时解决了 AI 测试两个老大难：跑一次烧一次 token，以及同一个用例每次结果可能不一样。
- 文档跟着 npm 包一起发，放在 node_modules/e2e/docs 里，coding agent 可以离线读全量文档。这是明确为'AI 写测试'这个用法做的工程取舍，不是顺手打包。

**核心功能**

- 自然语言步骤和代码断言写在同一个测试文件：先 agent.act('upgrade the workspace to Pro') 让模型自己找路径操作，再用 expect(screen.getByRole('status')) 这种传统 locator 做确定性断言，AI 的灵活性和传统断言的稳定兼得。
- 录播机制：带 agent 的步骤跑通时会把动作序列记录下来，下一次运行直接回放、不调用模型；只有 App 变了才重新问模型。没有 agent 步骤的测试完全不碰模型，等于把 LLM 成本压到首次探索。
- 引擎可插拔：web 端底层就是 Playwright，驱动 Chromium/Firefox/WebKit；移动端走 agent-device 驱动 iOS 模拟器和 Android 模拟器；一套测试 API 覆盖两端，另外还有 kernel 托管浏览器和 EAS 托管模拟器可以直接跑在云端。

**适用场景**: 有 web 或移动端产品、想在 CI 里跑端到端回归的团队。前端和 QA 不用再逐条写和修 selector，写清楚目标就行；也适合让 Claude Code、Cursor 这类 coding agent 直接读 npm 包里自带的文档来生成测试。

**竞品对比**: 对标 Playwright、Cypress、Appium、Maestro，最大差异是自然语言步骤和代码断言在同一个文件、且能回放不反复烧 token；对标 Momentic、QA Wolf、Octomind 这类 AI 测试 SaaS，差异是开源、Apache-2.0，模型可以自带 key、订阅或本地模型。

**成熟度**: 未到 1.0，README 明确写了 API 和配置在 minor 版本之间还会变；文档和 examples（Vite/Next.js/Expo/SwiftUI）比较完整，但尚无企业生产验证的公开信息。

**趋势信号**: 单日涨 1398 星、README 里直接挂着'GitHub Trending Repository of the Day'徽章，更像是一波发布上榜带来的滚雪球；踩中的则是当下 'AI agent 替人写和维护 e2e 测试' 这波热度。

### [Panniantong/Agent-Reach](https://github.com/Panniantong/Agent-Reach)

 `Python` ⭐ +1,155 今日新增 · 92,108 总星数

> 给 AI Agent 一键装上联网能力的命令行工具，让 Agent 能读推特、Reddit、YouTube、B站、小红书，全部走免费路径不付 API 费。

**亮点**

- 把「接入方式迟早会失效」当成第一性问题来设计——多后端路由 + agent-reach doctor 全链路体检，把平台风控带来的维护成本从用户转移到维护者自己身上。
- 自身不写抓取逻辑，而是把 yt-dlp、gh CLI、Jina Reader、Exa MCP、各类第三方 MCP server 包一层统一 CLI，重点是选型、装配和体检，而不是重造轮子。

**核心功能**

- 每个平台做「首选 + 备选」多后端路由：哪个接入方式被平台封了自动切下一个，用户不用改配置。README 里给的实例是 yt-dlp 被 B站风控封死，直接切到 bili-cli，用户零操作。
- 登录态不自己存密码，走本地 Chrome 已有会话（CDP 协议，即用调试端口遥控浏览器），Cookie 只留在本机、不外传；小红书这类也明确不替用户登录。
- 安装方式本身是给 Agent 读的 Markdown 脚本：人只复制一句「帮我安装 Agent Reach + URL」，Agent 自己装 CLI、查 Node/gh/mcporter 缺失项、按需写 SKILL.md 到 skills 目录。默认只体检，加 --system 才动系统包。

**适用场景**: 用 Claude Code、OpenClaw、Cursor 的开发者做竞品调研、用户反馈收集，或者运营想批量看推特评价、小红书口碑、B站教程字幕、Reddit 帖子，但不想买 Twitter API、也不想给每个平台各写一个爬虫。

**竞品对比**: Jina Reader 只解决读网页，Firecrawl、BrowserAct、CoreClaw 解决网页抓取，twitter-mcp、xiaohongshu-mcp 各管一个平台。Agent Reach 的差异是不自己抓，而是把这些零散工具聚合成一个 CLI，加上跨平台的故障自动切换和诊断。

**成熟度**: 没有正式版本号，MIT 协议，有英日韩多语言文档和多家赞助商，但本质是第三方工具的聚合层，平台风控一变就可能某条渠道失效，属可用但易碎的早期阶段。

**趋势信号**: Claude Code、OpenClaw 这类能跑 shell 的 Agent 普及后，「给 Agent 喂外部数据」成了刚需，而 Twitter 等 API 收费、各平台风控越来越严，这个项目正好卡在这个缺口上，README 里还连续标注 2026-06 平台封禁事件，说明它在紧跟平台变化更新。

### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5)

 `C++` ⭐ +997 今日新增 · 5,125 总星数

> AnyPS5 把 PS5 可执行文件转成 Linux/Windows 原生程序，靠重链接和重写系统库实现，全程不跑模拟器。是 PS5 游戏移植与保存方向上一条和主流模拟器完全不同的技术路线。

**亮点**

- 走静态重编译加重链接，而不是模拟器：不改游戏逻辑，直接把二进制改造成原生程序，省掉模拟器的指令翻译和系统调用模拟开销，理论上性能更接近原生
- 把系统库函数覆盖率和着色器覆盖率做成徽章和进度图挂在 README 里，还单独写了技术债文档，等于公开承认哪些没做完

**核心功能**

- relinker（重链接器）把 PS5 可执行文件直接转成目标系统的原生二进制格式，同时用重写的 PRX 库顶替 PS5 系统动态库（PRX 相当于 PS5 上的 DLL），让程序按原生方式动态链接，不需要解释执行或独立运行时进程
- shader 重编译器把 PS5 着色器翻译成 SPIR-V，构建时可选 Spirv-Tools 做校验，再由 Vulkan 驱动执行，绕开了模拟 GPU 指令这条路
- 遇到未实现或异常状态直接抛 std::runtime_error 并把 what() 打到 stderr 后终止进程，宁可崩也不静默出错，方便暴露还没覆盖到的系统库函数
- 手柄走 SDL 映射（含摇杆和扳机），键鼠通过 anyps5-input.ini 配置

**适用场景**: 想在 PC 上跑 PS5 独占游戏、或者做游戏保存/互操作性研究的玩家和开发者。目前实测能玩的只有 2D 平台跳跃游戏 Dreaming Sarah，在 GTX 1050 Ti + i5-7500 上稳定 60 帧。

**竞品对比**: 对比 shadPS4、Kyty 这类 PS4/PS5 模拟器，最大区别是 AnyPS5 不做指令模拟、不用单独运行时进程，而是直接改二进制并原生链接；代价是必须一个个实现 PS5 系统库，眼下兼容游戏列表只有一款 2D 小游戏，远不如模拟器成熟。

**成熟度**: 早期项目，官方兼容列表仅一款 2D 游戏通过验证，README 自带技术债文档，还没到日常可用的程度。

**趋势信号**: PS5 模拟与静态重编译最近是社区热点（shadPS4 带起关注度），而“不用模拟器、直接把主机游戏编成原生程序”这条 N64 重编译式的路线正被大量转发，所以一天涨了近千星。

**成熟度**: 早期项目：AGPLv3，README 全是 demo 视频和赞助商位，看不到版本号、测试或 CI 说明，流程和工具接口都可能随时变。

**趋势信号**: 编码 agent 生态正热、Veo/可灵等视频生成模型价格快速下降，两个条件第一次同时凑齐，让「agent 自己拍片」从演示变成了几百块能跑通的事。

### [caddyserver/caddy](https://github.com/caddyserver/caddy)

 `Go` ⭐ +515 今日新增 · 77,247 总星数

> Caddy 是 Go 写的 Web 服务器，给所有站点默认自动签发和续期 TLS 证书，支持 HTTP/1.1、HTTP/2、HTTP/3。省掉手工配证书和 reload 的麻烦，一条命令就能把域名跑成 HTTPS。

**亮点**

- 多 CA 兜底加集群协调：一个域名可同时配多个 ACME 签发机构，某家挂了自动切换；多个 Caddy 实例能协同管理证书，避免几十台机器同时去申请同一张证书触发限流。
- 证书出问题不拖垮服务：TLS/OCSP/证书相关的失败会降级处理，服务器保持在线，而不是证书一过期整站 502。

**核心功能**

- 默认自动 HTTPS：内置 CertMagic 库，自动向 Let's Encrypt / ZeroSSL 申领证书、续期、处理 OCSP；内网域名和 IP 地址用本地自建 CA 签发，配置文件里不用出现任何证书路径。
- 配置可以热更新：原生 JSON 配置配一个 REST API，改配置无需重启进程也不断连接；不想写 JSON 可以用 Caddyfile，或者写 config adapter 把别的格式翻译成 Caddy 的 JSON。
- 模块化插件架构：HTTP 处理、TLS、日志、存储、DNS 挑战各自是可注册的 Go 模块，用 xcaddy 在编译期挑插件，产物是静态二进制，连 libc 都不依赖。

**适用场景**: 适合个人开发者、小团队和内部平台给一堆域名或内网 IP 快速上 HTTPS，不想每年折腾证书续期。也常被拿来当反向代理或 API 网关，放在 Docker/K8s 服务前面统一收流量。

**竞品对比**: 对比 Nginx，不用手写证书配置和 reload，配置行数少一大截，代价是 Go 运行时内存占用更高，纯静态文件的超高并发场景 Nginx 仍更省资源。对比 Traefik，Caddy 不绑定容器编排，可以当传统 Web 服务器单独用。

**成熟度**: 生产可用，已在海量请求和数百万张证书上验证，v2 稳定多年，官方文档和社区论坛都成熟。

**趋势信号**: Caddy 2.10 加入了加密 ClientHello（ECH，把 TLS 握手里的域名也加密）和 ACME profiles 支持；同时 Let's Encrypt 在推短期证书，手工续期越来越不现实，默认自动 HTTPS 的价值被重新放大。

 `C++` ⭐ +196 今日新增 · 1,494 总星数

> 用 2 美元的 ESP32-C3 做 Pi-hole 式 DNS 广告拦截：把 537k 域名压成 40 位 FNV-1a 哈希排序存进 flash 二分查找，只用约 50KB RAM，10ms 出结果。

**亮点**

- 核心取舍是只存哈希、不存原始域名：牺牲了可读性（没法从 flash 里反查被屏蔽的具体域名）和极低概率的误杀，换来内存占用从 MB 级掉到 50KB，于是不需要 PSRAM、芯片成本从约 8 美元降到 2 美元。作者论证这套做法在带 PSRAM 的大芯片上同样更省，C3 只是把差距拉得最明显。
- 4MB flash 上的分区取舍被明确摆出来：要支持固件 OTA 就得留两个 app 分区，blocklist 只剩约 1.3MB、上限约 25 万域名；而 53.7 万条的极限列表只能用单 app 分区、放弃固件 OTA。用户在 partitions.csv 里自己选。

- UDP DNS 服务器做 sinkhole：命中就回 0.0.0.0，未命中就转发给上游解析器再把回复中继回来。查一个域名时还会连带查它的各级父域后缀，所以屏蔽主域就等于屏蔽所有子域。
- 构建脚本 build_blocklist.py 能吃 hosts 文件、纯域名列表、AdGuard/Adblock 的 ||domain^ 规则，@@ 规则做白名单；GitHub Actions 每周一自动重建一份默认 blocklist.bin 并发到固定下载 URL，设备开个定时任务自己拉取更新。

**适用场景**: 想在不额外开一台树莓派/常开主机的情况下给全家网络拦广告的家庭用户和折腾党。插在路由器背面的 USB 口上供电，局域网里所有设备改一下 DNS 指向它就行。

## 趋势观察

这批项目指向同一个方向：AI Agent 正在变成新的操作系统。测试、CAD 建模、剪视频，全被做成 Agent 插件。Claude Code、Cursor、Codex 成了统一入口，围绕它们做工具就能冲上 Trending。今天排第一的正是个 AI 测试 agent，用自然语言写目标，跑通后录成回放，下次不再烧模型算力，直接打 Playwright、Cypress 维护 locator 的痛点。

第二是补短板。Agent 没记性，就有人做跨会话记忆，压缩历史再注入；Agent 没眼睛，就有人做免费联网工具，让它读推特、Reddit、B站、小红书，不付 API 费。记忆和联网，是 agent 落地绕不过的两块砖。

第三，开发者开始算账。T3 Code 远程操控本机 agent，复用现有订阅额度，不另配 Key。能白嫖就白嫖，成本意识上来了。

自托管和隐私依然很硬。健身记录放自己服务器，DNS 拦截用 2 美元 ESP32 搞定，Cloudflare 干脆把内部 AI 工作台开源，每人跑一份实例。数据攥在自己手里，这个诉求没退过。

还有一条暗线：绕开主流。AnyPS5 不跑模拟器，靠重链接把 PS5 程序变成原生程序；Stremio 用统一协议聚合片源。不跟大厂走，自己找路。

总体看，生态正从 demo 转向日常工具链。记忆、联网、省钱、自托管，是这轮四个关键词。
