### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,979 今日新增 · 39,933 总星数

> Cloudflare 开源了内部漏洞挖掘 harness 的起点：它是一个 agent skill，用六个阶段编排多个相互隔离的子 agent 做代码安全审计，结论分三档并用 JSON Schema 校验。

**亮点**

- 多次运行是叠加的：读上一次的覆盖账本和结论，只补没覆盖的攻击面、只重验改过的源码，不把过期证据当已覆盖。官方说单次运行大约只找到重复运行总漏洞量的一半，这条设计直接针对 LLM 审计漏报。
- 要求 OS 级沙箱（断外网、白名单环境、资源限额、只写指定 scratch 目录）才允许跑目标代码；没有沙箱就把线索停在 needs_validation，不执行。这是把'别让审计 agent 被待审代码打穿'写进了流程。

**核心功能**

- 六阶段流水线：侦察写 architecture.md 和 coverage-ledger.json → 按账本单元分派猎人 → 候选交给新的验证者 → 输出 findings.json → 独立复核源码声明 → 生成 REPORT.md；每一步的产物都是文件，可追溯。
- 对抗式验证：负责验证的 agent 不是找到漏洞的那个 agent，它的任务是证伪。漏洞有完整源码溯源和有界实测结果才算 confirmed；只要有一个事实没落实就降为 needs_validation，且不给严重级别。
- 两个零依赖 Node 校验器（validate-findings.cjs、validate-coverage-ledger.cjs）配合 report-schema.json，用来限制 agent 输出的格式；每次覆盖账本更新、每次复核替换结论后都重跑一次。
- 按攻击面拆的 prompt 库：内存安全与二进制、LLM prompt 注入、Web 协议与认证、客户端、供应链、云与部署、RPC、资源耗尽、多租户数据隔离、桌面与移动端各一份，按目标类型挑用。

**适用场景**: 安全工程师或后端团队在合并前对单个仓库做一轮审计，用 Claude Code 这类支持子 agent 的 coding agent 跑，产出 findings.json 和 REPORT.md 直接进修复流程。也适合给内部平台团队当自建漏洞挖掘流程的模板。

**竞品对比**: 和 Semgrep、CodeQL 这类靠规则加数据流分析的 SAST 不同，它不做静态扫描，靠多 agent 分工和证伪流程控制漏报误报；和 Xbow 等商业 AI 渗透测试产品比，它是开源的流程模板，不含扫描引擎。

**成熟度**: 早期项目，没有版本号，只有流程文档和两个校验脚本的测试；可以当辅助审计用，不适合直接当 CI 门禁。

**趋势信号**: Cloudflare 在官方博客公开了全公司用的漏洞挖掘 harness，并把这个 skill 作为单仓库起点开源；又刚好赶上 coding agent 的 Skills 生态（skills.sh、npx skills add）起步，一天涨了近 3000 星。

### [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)

 `JavaScript` ⭐ +1,948 今日新增 · 173,787 总星数

> Ponytail 是一套给 AI 编码 agent 用的规则包（skill）：先让它在仓库里找现成组件和原生能力，找不到才写新代码，同时不许省掉校验、错误处理和安全检查。

**亮点**

- 规则里写死“只写任务需要的代码”，但明确列出不准砍的四项：校验、错误处理、安全、无障碍。这样模型不会把“省 token”理解成删掉检查，安全类 6 个任务 30 次跑全过
- 用对照基准自证而不是喊口号：39 个任务（含一个真实 FastAPI + React 仓库），同模型有/无 skill 各跑 5 次，同时报告“注入 bug 的检出率”这种反向指标（66% vs 46%），防止出现只删代码、不写测试的假优化

**核心功能**

- 以提示词和斜杠命令的形式插进 20 种 agent（Claude Code 等），不改模型也不改运行时；agent 动手前先检索仓库已有的组件，比如要日期选择器就复用仓库里的 Input 组件并加上浏览器原生 type=date，而不是安装一个日期库、手写整套日历
- `/ponytail-review` 做的是变更影响分析，不只读 diff，还会去读被改字段在别处被谁引用。基准里它抓到一个真实问题：有人重命名字段后，没被改动的 src/routes/feed.js 里的 Atom 订阅每次请求都会崩
- `/ponytail-audit` 先给仓库建图（入口在哪、数据怎么流、预期多大负载），再按严重程度排序输出，直接告诉你先修第几条，而不是只列可以删的代码
- Claude Code 里有一条常驻状态带（band），靠 hooks 统计当前任务的 token、花费、agent 耗时、代码复用率和最近一次改完测试是否通过

**适用场景**: 日常用 Claude Code、Cursor、Codex 这类 agent 写业务代码的工程师和团队。典型场景是：让 agent 加个小功能，它却装了新依赖、写了几百行；或者 agent 改完一个字段名就提交，没人跑测试。

**竞品对比**: 跟手写 CLAUDE.md / .cursorrules、以及各类 agent 提示词模板比，差别是它带斜杠命令、生成后自检和公开对照基准，还给出成本和复用率的量化数字；跟 Aider、Codex 这类 agent 本体不是一层，它是挂在上面的插件。

**成熟度**: 版本已到 5.3，有 npm 包、MIT 协议、多语言 README 和公开 benchmark 目录，可用；但本质是提示词层，效果强依赖具体模型版本和仓库结构，模型一升级就可能要重调。

**趋势信号**: agent 编码的 token 账单在这两年成了团队真实成本，加上 Claude Code 的 skills 机制开放后大家开始比谁家的规则包更省，v5 重写并放出对照基准正好踩在这一点上。

### [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)

 `Python` ⭐ +1,408 今日新增 · 133,180 总星数

> 把代码、文档、SQL、PDF 转成可查询的知识图谱，代码用 tree-sitter 本地解析，不建向量库，帮 Claude Code 这类助手少扫文件、少烧 token。

**亮点**

- 把“贵的”和“便宜的”分开：结构化代码用本地解析器零成本啃完，只把 PDF、图片这类非结构化内容推给大模型，token 花在刀刃上。
- 产物是三个可落盘文件——可点击的力导向图 graph.html、摘要 GRAPH_REPORT.md、全量 graph.json——图建一次反复查，不用每次重新扫仓库。

**核心功能**

- 代码部分用 tree-sitter 做 AST 解析，纯本地、确定性，不调用任何 LLM——代码不出机器，也不花 token；只有文档、PDF、图片、视频才交给助手模型或自备 API key 做语义抽取。
- 每条边都打标签：EXTRACTED 表示源码里明写的（import、调用、定义），INFERRED 表示由 graphify 自己推出来的（跨文件调用链）。用户能分清哪些是读到的、哪些是猜的。
- 不用 embedding、不建向量库，图直接落盘成 graph.json（带 schema_version 和 graphify_version），查询走图遍历：explain 看一个节点的所有连接，path 求两点最短路径，另带社区检测给节点上色。

**适用场景**: 接手陌生大仓库的后端工程师，在 Claude Code / Cursor 里改一个 SQL schema 或接口前，先问图谱“改这个会牵连到哪些调用方”；也适合 monorepo 团队日常排查跨文件依赖，替代反复 grep 和让模型重读文件。

**竞品对比**: 同领域有 Aider 的 repo map（同样基于 tree-sitter 做仓库摘要）、Cursor/Sourcegraph 的向量索引式代码 RAG。最大差异是它明确不做向量检索，答的是“A 到 B 怎么连”这种路径问题，且每条边能追溯到是读到的还是推出来的。

**成熟度**: 已到 v8，有 PyPI 包、CI、独立文档站、多语言 README 和 Discord，YC S26 背书，生产可用；但非代码模态的效果取决于所接模型，且核心能力向商业版 Graphify Cloud 引流。

**趋势信号**: AI 编程助手的上下文成本成了当下最现实的痛点，加上 Claude Code / Cursor 的 skill 插件生态刚起来，再叠加 YC S26 和 v8 发布的社区曝光。

### [supabase/supabase](https://github.com/supabase/supabase)

 `TypeScript` ⭐ +693 今日新增 · 113,560 总星数

> 开源 Firebase 替代品：一个 Postgres 数据库同时提供数据库、登录鉴权、自动生成 API、实时订阅、文件存储和向量检索，省掉自己搭后端。

**亮点**

- 核心思路是“不自己造轮子”：数据库用 Postgres、API 用 PostgREST、鉴权用 GoTrue、文件用 S3，团队主要精力花在把这些开源件拼起来和做控制台，而不是重写基础设施。
- 所有权限判断都统一到 Postgres RLS 这一层，REST、GraphQL、Realtime、Storage 共用同一套策略，避免了多套权限系统容易产生的规则不一致。

**核心功能**

- PostgREST 直接把 Postgres 表结构翻译成 REST 接口，权限靠数据库的 RLS（行级安全策略，写在表上的过滤规则）控制，鉴权逻辑不用写进业务代码。
- Realtime 是独立的 Elixir 服务，订阅 Postgres 的逻辑复制槽（WAL 变更流），把增删改变成 JSON 经 WebSocket 推给客户端，并对每个订阅者检查 RLS 权限。
- 客户端拆成 postgrest-js / auth-js / realtime-js / storage-js / functions-js 等独立小包，每个只对接一个外部系统，可以单独用，不用整个 Supabase SDK。
- Storage 服务把文件本体放 S3，权限元数据留在 Postgres，跟数据库走同一套 RLS 规则；pg_graphql 扩展则把同一个库再暴露成 GraphQL。
- 向量检索直接用 pgvector 扩展，embeddings 和业务表放在同一个库里，不需要额外维护一套向量数据库。
- 整体用 Envoy 做边缘代理，Envoy 在这里是服务网关，负责路由和限流，各组件（PostgREST、GoTrue、Realtime、Storage）拼装成一个平台。

**适用场景**: 适合前端或全栈独立开发者、小型创业团队做 MVP：不想自己写登录、CRUD 接口和 WebSocket 推送，直接用 supabase-js 接 Next.js / Flutter 应用；也适合做 RAG 的 AI 应用，用 pgvector 存 embedding 并配合 RLS 做多租户数据隔离。

**竞品对比**: 对 Firebase 是开源 + SQL + 可自托管，不会被绑死在 Google 的 NoSQL 上；对 Neon、PlanetScale 这类只提供托管数据库的服务，它把鉴权、API、实时推送、存储一并打包；对 Appwrite、PocketBase 这类开源 BaaS，差别在于底层是真正的 Postgres，能直接用 SQL、扩展和 pgvector。

**成熟度**: 生产可用：11 万星、大量企业在用，有自托管方案和完整文档；但组件多、自托管编排复杂，客户端库仍在 2.x 阶段，自托管升级需要自己承担运维成本。

**趋势信号**: 项目定位已从“开源 Firebase”改成“Postgres 开发平台”，加上 pgvector 让 Postgres 直接当向量库用，这一轮 AI 应用和 RAG 的建站需求把它重新推上热榜。

 `Python` ⭐ +303 今日新增 · 31,728 总星数

> Anthropic 官方开源 11 个按岗位划分的 Claude 插件，把销售、财务、法务等岗位的流程和工具连接写成 markdown 加 JSON，装进 Cowork 或 Claude Code 就能直接干活。

**亮点**

**竞品对比**: 对标 OpenAI 的 GPTs 和 Custom Instructions、微软 Copilot 的 agent，以及 Glean 这类企业搜索产品。最大差异是它完全文件化、可 fork、可提 PR，走后市场而不是黑盒商店；但代价是强绑定 Claude 生态，连接器深度也不如 Glean、Zapier 这些做了多年的集成平台。

**成熟度**: 刚开源几天，星数暴涨但还没有版本号和社区治理沉淀，目录结构和字段定义可能还会变；好在全是 markdown，重构迁移成本低，且有 Anthropic 官方维护。

**趋势信号**: Claude Cowork 刚上线，Anthropic 同步把内部的 11 个插件一次性开源，配合 Claude Code 新增的 plugin marketplace 命令，等于官方亲自给生态铺了一层“岗位模板”，赶上 agent 从“通用助手”转向“按角色定制”的节点。

### [php/php-src](https://github.com/php/php-src)

 `C` ⭐ +287 今日新增 · 41,265 总星数

> PHP 官方解释器源码仓库。PHP 8.5 刚发布，带管道操作符、array_first/array_last 等新语法，是观察这门语言演进方向的一手来源。

**亮点**

- 共享 nothing 的请求模型：每个请求独立起止，状态不跨请求保留，配合 PHP-FPM 进程池，天然避开内存泄漏和长驻进程的状态污染；代价是常驻缓存只能靠 OPcache 共享内存
- 语言变更强制走 RFC + 核心开发者投票（wiki.php.net/rfc），新特性先投票再实现，破坏性改动必须经过一轮 deprecation，因此十几年前的代码大多还能跑

**核心功能**

- Zend 引擎先把 PHP 源码编译成 opcode，再由 OPcache 缓存在共享内存里复用，省去每次请求重新解析；JIT 再把热点路径编译成机器码
- PHP 8.4 引入属性钩子（property hooks）：在属性声明上直接写 get/set 逻辑，不用再手写 getter/setter 方法，同时支持非对称可见性（public 读、private 写）
- PHP 8.5 新增管道操作符 |&gt;，把左值当参数传给右侧函数，取代嵌套调用；闭包和一等公民可调用对象现在能写进常量表达式和属性默认值
- 扩展安装改用 PIE（PHP Installer for Extensions），按 composer 包的方式装 C 扩展，逐步替代老的 PECL

**适用场景**: PHP 后端开发者和运维。日常跑 Laravel、Symfony、WordPress 的团队，关注 8.5 升级带来的语法变化和废弃项，以及 PHP-FPM + OPcache 的部署调优；写 C 扩展的人也会直接看这个仓库。

**竞品对比**: 对手是 Node.js、Python\(Django/FastAPI\)、Go、Java Spring。最大差异在部署模型：PHP 每个请求重新起一个干净上下文，OPcache 预热后启动开销接近零；Go/Java 是常驻进程，得自己处理内存与并发状态。

**成熟度**: 生产就绪，30 年老项目，当前稳定版 PHP 8.5，全球大量网站实际运行，测试套件和文档齐全。

**趋势信号**: PHP 8.5 正式版在 2025 年 11 月发布，管道操作符等语法变更让仓库短期内被大量围观。

### [fastapi/fastapi](https://github.com/fastapi/fastapi)

 `Python` ⭐ +101 今日新增 · 103,876 总星数

> FastAPI 是用 Python 类型注解声明接口的 Web 框架，自动完成参数校验、依赖注入和 OpenAPI 文档生成，是当前 Python 写后端 API 的主流选择。

**亮点**

- 把接口文档当成副产品：不用手写 Swagger YAML，路由一注册，/docs 和 /openapi.json 就自动是准确的最新版，前端可以直接拿来生成 SDK
- 一套类型声明同时干三件事——校验、序列化、文档，避免 Flask/Django 里序列化器、表单校验、文档三份定义各写一遍还容易不同步

**核心功能**

- 路由函数的类型注解（Pydantic 模型）直接当校验器用：请求体、查询参数、路径参数、响应模型都从函数签名推导，运行时校验失败自动返回 422，同时生成 JSON Schema
- 底层用 Starlette 做 ASGI 异步框架、Pydantic 做数据校验，所以能跑 async/await 并发，官方对标 NodeJS 和 Go 的吞吐，而不是 Flask 的同步 WSGI 模型
- 依赖注入系统 Depends 用函数签名声明依赖（数据库连接、鉴权、分页参数），支持子依赖和 yield 清理逻辑，鉴权、事务这类横切逻辑写一次全站复用

**适用场景**: Python 后端工程师和算法团队建 REST/gRPC 网关、模型推理服务。微软 ML 服务、Uber 的 Ludwig 预测服务、Netflix 的 Dispatch 告警编排、Cisco 的内部自动化平台都在用。

**竞品对比**: 对比 Flask 是同步 WSGI 且校验和文档要自己装插件；对比 Django REST Framework 有 ORM 和 admin 但样板代码多、异步支持晚；对比 Litestar/Sanic 生态和文档成熟度、star 数差一个量级。FastAPI 的差异点是把标准类型注解变成框架契约，学 Pydantic 就等于学会半个框架。

**成熟度**: 生产可用：GitHub 10 万+ star、Pydantic v2 已稳定、测试覆盖率拉满、有微软/Netflix/Uber 等公开生产案例，版本号仍是 0.1xx 但 API 早已事实稳定。

**趋势信号**: 2025 年底官方发布了 FastAPI 迷你纪录片，加上同一团队推出托管服务 FastAPI Cloud（本 README 的 Keystone 赞助位），带来一波关注回流。

## 趋势观察

今天的榜单基本被"给 AI 编码助手打补丁"这件事占满了。Anthropic 出了 11 个按岗位分的插件，销售、财务、法务装进去就能干活；Ponytail 管住 agent 别乱造轮子，还逼它别省掉校验和安全检查；Cloudflare 干脆把内部的漏洞审计拆成六个阶段、多个互相隔离的子 agent 跑。方向很一致：大家不再纠结模型能不能写代码，开始琢磨怎么让它少烧 token、少犯错、别偷工减料。 另一条线是上下文管理。把代码、文档、SQL、PDF 转成知识图谱，绕开向量库，就是为了让助手少扫文件。这跟"技能包""规则包"是一回事，都是在给模型省算力、给结果上保险。 还有几个老面孔提醒我们底座没变。PHP 8.5 带着管道操作符发了新版，还在稳稳迭代。FastAPI 依然是 Python 后端的默认答案。Firebase 的开源替代把数据库、鉴权、存储、向量检索塞进一个 Postgres。连 PCL 这种 Minecraft 启动器把源码同步到 GitHub，都能引来一波关注，说明开发者生态还有很接地气的一面。 一句话：AI 正从"能干活"走向"可靠地干活"，围绕它的配置、规则、审计和上下文管理，正在长成一门正经的工程活。
