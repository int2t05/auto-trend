### [HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)

**亮点**

- 不是纯向量 RAG：直接复用 HKUDS 自家 LightRAG 的图谱检索栈，并提供检索对比，能在同一份资料上切换策略看效果。

**核心功能**

- 用内置 LightRAG 把教材、笔记、网页索引成实体-关系图，检索时图和向量一起走，跨文档找知识点不靠单段相似度。
- 嵌入索引支持断点续跑（resumable embedding checkpoints），并记录索引由哪个解析器/模型构建，换 PDF 解析器或重建库时能对账，不用整库重算。
- 辅导记忆做有界窗口，学习路径改动要审核，测评按组生成；长周期跟学不会把上下文无限堆大，错题和进度能落到学习日志。

**适用场景**: 自学者/大学生把课程 PDF、Office 讲义、Kiwix 离线百科导入，生成学习路径、题库和视频课；教师或培训机构可拿它搭私有课程知识库和测评系统。

**竞品对比**: 对标 NotebookLM、ChatGPT Projects 和 Khanmigo：NotebookLM 强在资料问答和音频概览，DeepTutor 多了学习路径、分组测评和长期导师记忆；和 Open WebUI+RAG 插件比，它把 LightRAG 图谱和课程工作流做进同一个产品。

**成熟度**: 已到 v1.7.0，Apache 2.0，发版很密、文档多语言、社区活跃，可自部署试用；但功能面很宽，生产前要按自己的资料规模压测索引和解析。

**趋势信号**: 刚发 v1.7.0：模块化安装降低部署门槛，视频课和块笔记把 AI 家教从问答扩成课程产品，HKUDS 在 LightRAG 上的口碑又带来传播。

### [elayadesign/ai-design-skills](https://github.com/elayadesign/ai-design-skills)

 ⭐ +2,139 今日新增 · 11,377 总星数

> 一个给 AI 编程工具用的「设计技能」文件集合，目前就一个：教 Claude Code / Cursor 从零做出有设计感的落地页。现在火是因为 Anthropic 刚推 Agent Skills、SKILL.md 成了跨工具的通用规则格式。

**核心功能**

- 技能本身就是一份 SKILL.md 纯 markdown，按各家约定分别落到 .claude/skills/、.cursor/rules/、AGENTS.md、.windsurfrules、.clinerules 或直接塞进 system prompt，一套内容六种装法
- landing-page-design 不是让你「生成个页面」，而是先反问需求（intake questions），再定页面结构、写转化文案，最后才套字体/间距/圆角/动效这一整套视觉 token
- 所有设计取值（字体、颜色、间距、动效）集中在文件末尾一节，fork 后只改这一节，前面的规则和流程自动跟着变

**竞品对比**: 和 Leonxlnx/taste-skill（本项目的灵感来源，README 里已注明）思路接近，都是给 AI 灌设计规则；和 v0、Lovable 这类直接出页面的生成器比，它不产页面，产的是约束模型决策的说明书；和 shadcn/ui + Tailwind 模板比，它不给代码组件，给的是流程和取值。

**成熟度**: 早期项目：1.1 万星但只有一个技能、一个 SKILL.md，作者自己写「More on the way」，API 和文件结构都可能变。

**趋势信号**: Anthropic 推出 Agent Skills 后 SKILL.md 成了跨工具的通用格式，加上大家普遍抱怨 AI 生成的落地页长得一模一样，这个仓库正好踩在「技能格式」和「AI 审美」两个热点上；单日 2139 星也说明它是被某个大 V 或榜单带火的。

### [Nutlope/hallmark](https://github.com/Nutlope/hallmark)

 `CSS` ⭐ +2,110 今日新增 · 41,001 总星数

> Together AI 出的设计 skill，装进 Claude Code/Cursor/Codex 后，生成页面前先发主题、生成后用浏览器 linter 抓"AI 味"，专治 AI 做的落地页全都长一个样。

**亮点**

- 把 hero 单独先建出来、单独渲染、交给一个全新上下文的 subagent 冷评，通过后才允许写页面剩余部分，避免模型一边生成一边给自己打高分
- 把"品味"落成可执行检查：不是再给模型一段风格提示词，而是先发主题物料 + 用浏览器实测，最后才由审查 agent 拍板

**核心功能**

- sloplint.mjs 用 puppeteer-core + 真实 Chrome 在 8 种视口宽度下渲染页面，检测具体的机器味特征：每个标题上方那行小 eyebrow 字、字距拉开的全大写小标签、标题里只有一个词变色、满屏空占位框或只有图没有内容、首屏高出屏幕一截、页脚固定挂一个邮件订阅框、点了提交只弹"谢谢"却没真发请求
- 50 个主题每个都是 references/themes/ 下不超过 8KB 的单文件"材质"（纸感、字体、配色、表面处理、组件、纹理）配一张成品图；它只定义材质不定义结构，一次构建只读一个文件，所以同一主题两次生成的页面排布不同
- 门槛分三级：Floor（对比度、焦点、reduced motion、编造事实、手机布局崩坏）一律不许发版；Reflex 是模型默认会犯的套路，允许带理由在案驳回；Finish 只做提示不拦发布
- 重设计有回归保护：sloplint --before 先把页面所有链接、表单字段、事件处理器、标题记下来，改完 --kept 检查少一个就报失败，避免 AI 改版把功能接线路由一起删了

**适用场景**: 用 Claude Code、Cursor 快速搭落地页/产品站的独立开发者和早期创业团队；以及要重做已有页面、但必须保住原有链接和表单提交逻辑的前端。跑 `/hallmark redesign &lt;path&gt;` 或 `/hallmark audit &lt;path&gt;`。

**竞品对比**: 同领域有 Anthropic 官方 frontend-design 插件、pbakaus/impeccable、taste-skill、Kami，这些主要是塞给模型一段审美提示词加示例；Hallmark 的主要差异是多了一个能独立跑的浏览器 linter 和"主题即材质"的固定物料库，好坏可以机器验，不靠模型自觉。

**成熟度**: v2，四万多 star 但热度刚起来，本质是 skill 集合而非运行库，风险主要是主题目录和门槛规则还会变。

**趋势信号**: 2025 下半年 Claude Code/Codex 的 skill 与插件生态集中爆发，同时"AI 生成的落地页千篇一律"成了公开吐槽点，这个反套路 skill 正好卡在这个话题上，加上作者 Nutlope（Hassan El Mghari）本身在 AI 工具圈影响力大。

### [hmjz100/LinkSwift](https://github.com/hmjz100/LinkSwift)

 `JavaScript` ⭐ +1,616 今日新增 · 35,386 总星数

> 一个油猴脚本，在百度、阿里、夸克、123 等 9 家网盘的网页里，用各家的公开 API 换出文件的真实下载直链，再推给 IDM / Aria2 / ABDM 去下载。免去必须安装官方客户端这一步。

**亮点**

- 不做浏览器里的下载器，只负责拿直链 + 推任务，把实际传输交给 IDM/Aria2 这类成熟客户端，绕开浏览器单线程下载的限制
- README 明确写了不破解限速、只用服务商公开接口，主动和'加速下载''限速破解'这类宣传切割——这是这类脚本少见的合规姿态

**核心功能**

- 脚本注入网盘网页，调用各家网盘自己的公开 API 把分享页里的文件换成带签名的直链（dlink），再拼成 cURL 命令、Aria2 任务或直接推送到 IDM / ABDM 客户端
- 百度网盘从 BDUSS Cookie 改成 AccessToken 鉴权，用户不用把长期登录凭证交给第三方脚本
- 自己实现了多块分片的多线程下载和进度条，并且给直链做缓存，避免同一文件重复请求签名 URL
- 代码是单文件 userscript，无后端、无服务器，逻辑全跑在浏览器里，兼容 Chrome ≥76 和 Edge ≥88

**适用场景**: 主要用户是 Linux / Android 上没有官方网盘客户端的，或者嫌官方客户端限速又不想开会员的人。典型场景：从夸克、123、阿里云盘的公开分享页批量下载大文件，把链接扔给 NAS 上的 Aria2 或 PC 上的 IDM 跑。

**竞品对比**: 直接对位油小猴的【网盘直链下载助手】（syhyz1990/baiduyun），本项目的差异是开源可查、覆盖 9 家网盘（原版更少），并多了 IDM/Aria2/ABDM 推送和多线程分块下载。同类还有各种'XX 网盘会员青春版'油猴脚本，但多数只做单一网盘。

**成熟度**: v1.1.3 正式版 + v1.1.4 测试版，单人维护但更新日志很密；由于依赖各网盘前端和接口，网盘一改版就可能失效，需要跟着修。功能可用，但别指望 API 稳定。

**趋势信号**: README 首页就在提醒'GreasyFork 上黑产刷子导致无法及时更新，建议换个源覆盖安装'——用户被从 GreasyFork 挤到 GitHub 直装；叠加 1.1.4 刚加光鸭云盘、适配 123 云盘改版，两个因素一起把它推上了趋势榜。

 ⭐ +1,477 今日新增 · 7,472 总星数

> 一个把 32 份完整系统提示词按模型归档的仓库，覆盖 Claude、Gemini、GLM、DeepSeek、Kimi 等 26+ 模型，给出可直接粘贴的越狱或人格设定文本，一天涨 1477 星。

- 针对不同 harness 的指令优先级下手——比如把 Grok 的配置塞进 `&lt;CFG&gt;` 配置字段而不是对话里，利用的是「系统级配置比用户消息权重高」这个机制

**核心功能**

- 一个模型一个文件，主张「完整可粘贴、不给摘要」——同时给出 AGENTS.md 工作区规则、Ollama Modelfile（`FROM` + `SYSTEM` 块）、Grok `&lt;CFG&gt;` 配置槽三种落地形态，把对话级提示词和常驻配置分开处理

**适用场景**: 做提示注入防御的红队和安全研究员，可以拿它当攻击语料库，测自家过滤规则和指令层级能不能扛住；普通用户则会拿它在本地 Ollama 或 coding agent 里换一套说话方式。

**竞品对比**: 同类有 Pliny 的 L1B3RT4S（偏一次性越狱 payload）和 asgeirtj/system_prompts_leaks（专扒厂商原始系统提示词、不做改写）。这个仓库的差异是强调完整可粘贴，并且把 AGENTS.md、Modelfile 这类非对话指令面也纳入了。

**成熟度**: 早期项目，无版本号、无许可证说明；清单里 GLM-5.3、DeepSeek V4、Qwen 3.8、Gemini 4 Argon、Kimi K3 等型号对不上公开版本，真实性没法验证，加上提示词随厂商更新几天就失效，只能当参考资料，不能当依赖。

**趋势信号**: coding agent 普及让 AGENTS.md 成了新的常驻指令入口，同时 OpenCode Zen 一批匿名免费「stealth model」（Big Pickle、Space Bunny 之类）上线，大家想弄清它们背后是谁的模型、系统提示词怎么写的，需求集中爆发。

### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +1,472 今日新增 · 93,319 总星数

> 给 Claude Code、Cursor 等编码 Agent 装一套设计词汇加检查器：24 个命令改设计，62 条规则抓「AI 味」，还能在 Agent 说完工之前把问题拦下来。

**亮点**

- 把「设计品味」拆成可调用的动词表：bolder/quieter/distill/typeset/layout/overdrive 各配一份专用 playbook，并且要求只指向一个窄目标（比如「bolder the pricing cards」）。作者的经验是：单页细看比整页扫一遍有效得多，这个取舍直接写进了命令设计。
- 检测器故意不用 LLM：规则确定、可复现、能进 CI、能按值 ignore（比如「Inter 是品牌字体」）或按文件注释关掉单条规则。省掉了 LLM 评审自己也不稳定的问题。

**核心功能**

- 62 条确定性规则检测「AI slop」：纯规则，不调 LLM，不需要 API key，可离线跑。能点名 Inter 字体、紫到蓝渐变、卡片套卡片、彩底灰字、每个标题上方一个圆角方块图标这些跨模型反复出现的套路，也能抓内边距挤、标题层级跳级这类基础问题。
- 设计 hook 嵌进 Agent 的编辑流程：Agent 每改一个 UI 文件就扫一次，结果在它宣布完成之前回灌给模型，让它自己改。支持 Claude Code、Cursor、Codex、GitHub Copilot、Grok Build、Hermes Agent，安装器会自动配好。
- 检测器本体是 Rust，走 npx 分发：CLI 支持扫目录、扫 URL（用你本机装的 Chrome/Edge 渲染，才能查对比度和过小字号）、`--json` 输出、`--github` 直接出 Actions 注解，退出码 2 表示有问题，能塞进 CI。
- init 读代码生成 PRODUCT.md，document 生成 DESIGN.md，后面每条命令都读这两份文件；改完的品牌色、字体、语气不会每次都被 Agent 忘掉。live 模式在 dev server 上盖一层 overlay，点选元素切变体，选中后写回源码，支持 Vite/Next/SvelteKit/Astro/Nuxt。

**适用场景**: 用 Claude Code 或 Cursor 批量出落地页、SaaS 后台、营销页的独立开发者和前端小团队。痛点是 Agent 生成的东西千篇一律，人又懒得逐页挑毛病，想在上线前跑一遍 critique/audit，或在 Agent 每次改完自动拦一道。

**竞品对比**: 可访问性和性能这块和 Lighthouse、axe-core 有重叠，但这两者不管「所有 AI 生成的页面长得一样」。和 v0、Lovable 这类生成式设计工具比，它不替你生成，只在 Agent 已有产出上纠偏。真正差异是它卡在 Agent 循环内部这个位置，目前暂无直接竞品。

**成熟度**: 文档站、CLI、Chrome 扩展、案例研究都齐了，但项目很新，24 个命令还在增删（craft 已降级成别名），API 和命令名可能变，建议先在非核心项目上试。

**趋势信号**: 2025 年底 Claude Code Skills / Agent 插件生态集中爆发，同时「AI 做的网页全是一个味」被大量吐槽，这个项目正好卡在两个话题的交叉点上。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +1,095 今日新增 · 307,639 总星数

> 把一套开发方法论拆成可自动触发的 Agent 技能包，装进任意编程 CLI，逼模型先写规格、再按 TDD 小步实现。

**亮点**

- 显式处理上下文压缩：Pi 在 compaction 后重新注入引导技能，Hermes 没有 post-compaction 钩子就直说会失效、建议开新会话——这种把 harness 差异写在文档里的做法比假装通用更实在

**核心功能**

- 技能本体是一堆 SKILL.md 提示词文件，不是可执行代码。每个技能限定一个场景（路由、动画、原生模块、SDK 升级、EAS 打包），Agent 按任务描述自动挑对应文件加载，避免每次都把整套 Expo 文档塞进上下文。
- 分两层：免费的框架技能（Expo Router、Reanimated 动画、原生模块、Web 迁原生）和付费的 EAS 服务技能（构建提交、OTA 更新、CI 工作流）。每个服务类技能开头都写明要花多少钱、套餐限制在哪，不让 Agent 偷偷把用户带进付费流程。
- 配了 Expo MCP Server 补上「能动手」的一半：按需读最新文档、用 npx expo install 装版本兼容的依赖、触发并监控 EAS 构建、拉 TestFlight 崩溃数据、在模拟器里截图。技能负责「怎么做」，MCP 负责「真去做」。
- 用 hooks 思路做入口路由：expo-overview 是总闸，请求模糊时先加载它再分发到具体技能；实验性 API（如 Modules API 2.0 宏迁移）单独放 expo-experiments 插件，API 稳定后再并回主包。

**适用场景**: 用 Cursor / Claude Code / Codex 写 React Native 应用的开发者，尤其是从 Web 转过来的人。典型场景：让 Agent 搭一个带 Tab 和 Modal 的 Expo Router 页面、写 PR 预览构建的 EAS Workflow、把老项目升到新 SDK 时不被依赖冲突坑。

**竞品对比**: 跟直接用 Expo 官方文档 + 通用 LLM 比，差别是 Agent 不用猜版本约束和 EAS 套餐边界；跟其他框架厂商出的 skills 比，Expo 这套把免费开源技能和付费 EAS 技能明确分开，还带成本提示，这点少见。但本质上仍是文档的提示词封装，不是新工具。

**成熟度**: 官方维护、MIT 协议、配套 MCP 和插件市场通道齐全，可以用；但技能内容随 Expo SDK 版本滚动，实验性 API 那组随时会变或下线。

**趋势信号**: Anthropic 推的 Agent Skills / SKILL.md 格式在 2025 年底成了跨工具的事实标准，skills.sh 这类分发站起来了，Expo 是第一批把官方技能同时铺进 Claude Code 和 Codex 插件市场的框架厂商。

## 趋势观察

今天这份榜单，一眼看上去不像在追新模型，倒像在给 Agent 修路、给 Agent 立规矩。 最集中的一类是「技能包」。Anthropic 刚推 Agent Skills，SKILL.md 就成了跨工具的通用格式，于是设计技能、TDD 技能包、Expo 官方技能包一夜之间全冒出来。大家在写同一种文件：告诉编码 Agent 该按什么规矩干活。 第二类是「管住 Agent」。有人把 pi 塞进 Monaco，用 git worktree 隔离并行任务，用 SPEC.md 存长期项目记忆，让 vibe coding 也有分支和评审。有人做了 62 条规则的设计检查器，专门在 Agent 说「完工」之前抓「AI 味」。共同点很直白：AI 写代码快了，人开始补流程。 第三类是「记忆和容器」。Macro 用一张双向图把邮件、文档、任务、Agent、CRM 串起来，团队和 AI 共用一份记忆；HKUDS 的导师用 LightRAG 记住你的学习路径；还有人把 Codex、Claude、Grok 塞进同一个桌面工作台，各给独立工作区和队列。Agent 不再是一个聊天框，而是工作区里的一个工位。 还有两个信号值得记一笔。一是本地优先、自带订阅：Cindy 把电脑变服务器，手机接着跑同一会话；网盘直链脚本绕开官方客户端。用户不愿意为一个壳再付一次钱。二是提示词本身成了资产，26+ 模型的系统提示词被整理归档，一天涨一千多星。 ESP32 用 WiFi 信号反推呼吸心率，是唯一的硬件异类，但思路一致：数据留在本地。 一句话收束：模型能力还在涨，但这两天的热闹几乎全在模型外面——规格、技能、检查、记忆、并发。Agent 正在长出属于自己的软件工程，谁把这套流程做顺，谁就拿到下一轮的入口。
