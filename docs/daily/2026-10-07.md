### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +2,956 今日新增 · 10,411 总星数

> REA 是一个 MCP 服务器，把 Hopper/Ghidra/IDA 和 JS/Electron 静态分析接进 AI Agent，让它能逆向没有源码的 App 和二进制，并给出证据。

**亮点**

- 把「不确定性」做成一等公民：结论必须附证据和未知项，限制了 Agent 逆向时张口就来的毛病，结论可以人工核对。
- 引擎选择策略刻意不做 fallback——多引擎可用时必须人工指定并锁定到会话结束，保证同一份分析结果可复现，而不是这次用 Ghidra 下次用 Hopper。
- setup 会先把改动的路径列出来、备份已有配置，装 Hopper 单独走一次授权，避免工具直接改坏用户的 Agent 配置。

**核心功能**

- 一个 MCP server 统一封装 Hopper、Ghidra、IDA 三个反汇编引擎，Agent 只调一套工具，不用为每个引擎各写一遍对接；同时覆盖 JS/Electron 应用、.NET 程序集和网站。
- 静态 JS/Electron 分析不依赖反汇编器：直接读解包后的应用目录或 ASAR 包，重建调用图，全程不执行目标程序，也不需要 Hopper/Ghidra。
- 每条结论强制带 Evidence、limitations、unknowns 三类字段；多个引擎都能处理同一目标时拒绝自动挑一个，直接报 capability_unavailable + ambiguous，要求显式传 --provider，会话内锁定该引擎且不回退。

**适用场景**: 适合两类人：一是想抄某个 App 里某个功能的产品和独立开发者，用 Claude Code、Cursor、Codex 这类 Agent 直接问「这个功能怎么实现的」；二是安全研究、恶意样本分析、以及需要审计闭源 Electron 客户端的团队。

**竞品对比**: 同领域已有 ida-pro-mcp、GhidraMCP 这类项目，但它们基本只绑一个引擎、只处理原生二进制。REA 的差别是引擎无关 + 覆盖非原生目标（JS/Electron、.NET、网站），并且输出格式里带证据和限制说明。

**成熟度**: 偏早期，npm 包 + CI + 多语言文档 + Discord 都有，README 详细，但项目发布时间短、迭代快，MCP 接口和 CLI 参数可能还会变。

**趋势信号**: 2025 年 MCP 生态爆发，Agent 工具正从「写代码、查文件」往逆向闭源软件这种硬场景扩，REA 刚好把 Ghidra/Hopper/IDA 一次性接进来，占住了这个位置。

### [tester-army/e2e](https://github.com/tester-army/e2e)

 `TypeScript` ⭐ +1,725 今日新增 · 6,581 总星数

> 面向 Web 和移动端的 E2E 测试框架：用自然语言让 AI Agent 驱动应用，再用选择器断言验收，首次跑完后的步骤会被记录下来，之后直接回放、不再调模型。

**亮点**

- 录制-回放式的 Agent 步骤是核心取舍：AI 只在界面变化时介入，所以测试可以按 PR 频率跑而不用每次烧 token，绕开了 AI 测试工具成本不可控的老问题。
- 不写 agent 步骤的测试完全不需要模型，团队可以逐步把 AI 引入个别脆弱用例，而不是整套测试都依赖 LLM。
- npm 包里直接附带全部文档到 node_modules/e2e/docs，方便 Claude Code、Cursor 这类编码 Agent 离线读取并自动写测试。

**核心功能**

- Agent 步骤第一次执行时记录完整操作序列，下次运行直接回放、零模型调用，只有应用发生变化才重新让模型规划——把不确定的 LLM 调用压成一次性成本。
- 同一份测试文件里混用 AI 步骤和确定性定位器断言（如 expect(screen.getByRole('status'))），AI 负责跑到目标状态，断言负责判定通过与否，避免纯 AI 测试结果无法裁决。
- Web 引擎底层就是 Playwright，跑 Chromium/Firefox/WebKit；移动端通过 agent-device 驱动 iOS 模拟器和 Android 模拟器，两端共用同一套 test/expect API。
- @e2e-dev/decision 把语义操作和断言限制在有限决策模型里执行，不是让模型在页面上随便点。

**适用场景**: 前端和 QA 团队把登录、下单、升级套餐这类多步流程放进每次 PR 的 CI；React Native/Expo 或 SwiftUI 团队想用一套测试同时覆盖 Web 和 iOS/Android，不想维护 Playwright + Appium 两套栈。模型可自带（订阅、API key 或本地模型）。

**竞品对比**: 对 Playwright/Cypress 这类纯选择器方案，差异是多了自然语言步骤且 UI 改动时能自愈；对 Appium/Maestro/Detox 这类移动端工具，差异是同一套 API 覆盖 Web 和移动端。相比 Octomind、QA Wolf、Momentic 等云端 AI 测试服务，它是开源 Apache-2.0，模型可自带、不强制托管。

**成熟度**: 未到 1.0，作者明确说明 API 和配置在 minor 版本间仍可能变动；文档、示例（Vite/Next.js/Expo/SwiftUI）和 Discord 都有，但还不适合直接押上关键生产流程。

**趋势信号**: 2025 年 AI Agent 写测试、跑测试成为热点话题，它把「自然语言步骤 + 缓存回放」做成了能塞进 CI 的落地形态，加上当天集中曝光（项目页/榜单/社区转发）带动单日 1725 star。

### [DuarteSantos8/openGym](https://github.com/DuarteSantos8/openGym)

 `JavaScript` ⭐ +1,419 今日新增 · 5,979 总星数

> openGym 是一个自托管的健身与体重记录 App，一条 docker compose up 跑在自己服务器上，passkey 登录、离线可用，还能算肌肉疲劳和去训练，并把 Hevy/Strong/FitNotes 的数据导入进来。

**亮点**

- 登录用 WebAuthn passkey（Face ID / 指纹），没有中心账号服务器，数据就是一个你能直接拷走的文件夹；自己上传的动作用片会在设备端先剥掉定位信息再传上去
- AI 教练和 MCP server 都默认关闭，跑在自己的服务器、用自己填的 key（支持 Anthropic、OpenAI、Gemini 或本地 Ollama），而且 AI 提的每个改动都要你逐条批准，不自动写进训练记录

**核心功能**

- 按组数、重量、时间给每块肌肉建疲劳与恢复模型，在人体图上用三种模式显示：训练量落在哪、哪块还在恢复、哪块已经很久没练——多数健身 App 只统计总量，不做恢复度建模
- 多设备同步是合并而不是覆盖：两台设备同时改同一次训练时按字段合并（类似 CRDT 的思路），不会后写的把先写的冲掉
- 预置 1324 个带动作动画演示的练习，可按人体图部位浏览、按你手上有的器械筛选，还内置 Push/Pull/Legs、5×5 等四套可直接编辑的起始计划
- 进阶规则做得比较细：支持线性、Greyskull LP、在某个次数区间内双进阶、加时间这几种，漏做的次数不加重量、卡住了自动触发 deload，每个目标重量都会说明为什么是这个数

**适用场景**: 会用 Docker 的健身爱好者或程序员，不想把训练记录交给 Hevy/Strong 这类订阅制云服务，于是在家里的 NAS 或 VPS 上跑一个，家里几个人各建一个 profile；从 Hevy、Strong、FitNotes 导出的 CSV 或 Hevy 的 API key 直接导进来接着记。

**竞品对比**: 商业侧对标 Strong、Hevy、FitNotes，开源侧对标 wger。openGym 的差异是体验更像现代消费级 App——PWA 可装到主屏、离线可用、passkey 登录、动作带动画演示，而 wger 更像后台管理风格；同时官方直接支持 Hevy/Strong 导入，迁出商业 App 的成本很低。

**成熟度**: 有正式 release、CHANGELOG、amd64/arm64 的 Docker 镜像、自托管文档和在线 demo，加上 Discord 社区，属于能自己部署就用的程度，但迭代很快、功能面还在扩张，接口偶尔会动。

**趋势信号**: 赶上 self-hosted 和「我的数据我做主」这波风潮——大家对订阅制健身 App 涨价、跑路、数据拿不回来已经不耐烦，而它又刚好带了 AI 教练和 MCP server 这两个当下最热的关键词。

### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5)

 `C++` ⭐ +949 今日新增 · 6,977 总星数

> 把 PS5 可执行文件重新链接成 Linux/Windows 原生程序，不靠模拟器，而是用自研系统库替换。已有 2D 游戏跑到 60fps。

**亮点**

- 碰到不支持或意外的状态，直接 throw std::runtime_error，把 what() 打到 stderr 后终止进程。宁可崩也不猜行为，避免模拟器常见的静默出错、游戏跑着跑着数据坏掉。
- 着色器不走自定义 IR 也不生成 GLSL，直接出 SPIR-V，少一层翻译、少一个中间表示要维护。

**核心功能**

- Relinker 把 PS5 的 ELF 转成目标系统的原生格式（ELF/COFF），再和项目自己用 C++ 实现的系统 PRX 库动态链接。不启动虚拟机，也没有单独的运行时进程。
- 兼容性靠人肉补 API：core/libs/prx 里逐个声明并实现 PS5 系统函数，README 用徽章显示函数覆盖率。也就是说每多一个游戏能跑，背后是一批系统函数被重新实现。
- 着色器重编译器把 PS5 的 GPU 着色器翻成 SPIR-V，构建时可选接 Spirv-Tools 校验输出是否合法，直接对接 Vulkan。

**适用场景**: 想在自己 PC 上跑自有 PS5 游戏的玩家（Linux 和 Windows 都行），以及做游戏保存、需要研究 PS5 系统 API 调用的逆向工程师。

**竞品对比**: 和 shadPS4、Kyty 这类 PS4/PS5 模拟器不同，AnyPS5 不做指令级模拟，走的是 Wine 那条路：重写系统 API，让原生二进制直接跑。差异是性能损耗小，代价是兼容性完全依赖逐函数补齐，目前只验证了一个 2D 游戏。

**成熟度**: 早期项目，只有一个验证过的 2D 游戏，作者自己在仓库里列了技术债文档，API 和兼容性都不稳定。

**趋势信号**: 跟 shadPS4 带火的 PS4/PS5 游戏上 PC 话题有关，加上“重链接而不是模拟”这条反直觉路线在社区传播，一天涨了近千星。

- 把 DDD 里的 ubiquitous language（团队和业务方共用的统一术语表）搬到人和 agent 之间，不只是让对话更短，还让命名一致、代码库对 agent 更好导航、思考时更省 token。

**核心功能**

- /grill-with-docs 在写代码前让 agent 反过来盘问需求，把澄清出来的领域术语沉淀成一份共享词汇表（原来叫 CONTEXT.md），之后 agent 用同一套词命名变量、函数和文件——README 举的例子是把「课程某小节被赋予文件系统位置」压缩成「materialization cascade」。
- 技能就是纯 Markdown 文件，不绑模型也不绑 agent：用 npx skills 装就复制进仓库让你随便改，用 Claude Code 插件市场装就是只读订阅、跟着 marketplace 的版本走，官方明确说别两个都装。
- /setup-matt-pocock-skills 每个仓库跑一次，问清用哪个 issue tracker（GitHub、GitLab、本地文件或你自己描述）、triage 时打哪些标签、文档存哪，后面的 /triage 等技能按这份配置执行。

**适用场景**: 适合用 Claude Code、Codex 写真实项目的工程师——不是做一次性 demo，而是被 agent 写偏、输出啰嗦、缺测试反馈循环困扰的人；团队已经用 GitHub/GitLab issue 流转的话可以直接接上 /triage。

**竞品对比**: 对比 GitHub Spec-Kit、BMAD-METHOD 这类全流程框架，最大差别是它不接管流程，只提供可改的小技能文件；对比 obra/superpowers 之类技能合集，它更强调共享词汇表和 ADR 决策记录的沉淀。

**成熟度**: 早期但已在作者日常使用：纯 Shell/Markdown 无版本号，有 CHANGELOG 和约 6 万人订阅的 newsletter，技能格式可能随各 agent 的规范变动。

**趋势信号**: Claude Code 官方插件市场上线、agent skills 格式正被多家 agent 当通用标准，同时社区对「vibe coding」产出的代码质量不满在升温，它正好踩在这两个点上。

### [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)

 `Shell` ⭐ +623 今日新增 · 157,969 总星数

> 一批按岗位划分的 AI Agent 人设提示词库（前端、后端、运维、安全等），配脚本一键装进 Claude Code、Cursor、Codex 等 15+ 工具。趁各家 AI 编程工具都支持子 Agent 的窗口期火了。

- 有配套原生桌面应用（macOS/Linux/Windows，支持 brew cask 安装），能浏览全部名册并一键装进目标工具、自动更新，把"clone 仓库再复制文件"这一步彻底去掉了。

**核心功能**

- 内容本体是 Markdown 写的 Agent 定义文件，每份含身份人设、工作流程、交付物代码示例和成功指标，不是通用提示词模板
- scripts/convert.sh 把同一份源文件转换成各家工具的原生格式（Claude Code subagents、Cursor rules、Copilot、Aider、Windsurf、Gemini CLI 等），install.sh 再按 --tool/--division/--agent 参数做选择性安装

- installer 会检测 OpenCode 当前约 119 个 Agent 的注册上限，超了会提前警告并建议用 --division 拆着装

**适用场景**: 用 Claude Code / Cursor / Codex 写代码的开发者，希望切换"前端模式""运维模式"时拿到结构化的角色提示，而不是每次自己写一大段 prompt。团队也可以把工程、安全几条线单独装进各自环境。 给非工程角色（Reddit 社区运营、文案、现实检查员等）用同一套框架描述工作流程的人，可直接抄这些人设文件当模板。

**竞品对比**: 同类是 wshobson/agents、VoltAgent/awesome-claude-code-subagents 这类 Claude Code 子 Agent 合集，以及各家 awesome-cursor-rules。差别在于它做了跨工具转换层和 runbook 班组机制，别人基本只针对单一工具、且靠手动复制。

**成熟度**: 可用但不重：无版本号、无测试，本质是 Markdown 内容库加 Shell 脚本；已有桌面应用和 brew cask 分发，MIT 协议，问题在于单个人设质量参差，需要自己筛。

**趋势信号**: Claude Code 子 Agent、Cursor rules、各类 Agent Skills 标准轮番铺开，开发者手里工具太多、配置格式互不兼容，这个项目正好卡在"一份内容喂所有工具"的痛点上；加上最近上线了桌面应用并登上 Reddit，带来一波集中 Star。

**亮点**

- 自带本地 MCP 服务器（cadgen mcp）和 viewer，模型在对话框里以可旋转卡片呈现，agent 能读到你选中的视图

**成熟度**: 早期项目，cadgen 版本 0.7.15 未到 1.0，API 可能变动，但已有 PyPI 发布、CI 测试、Discord 社区和多 agent 适配。

**趋势信号**: Claude Code、Codex 的插件目录/skills.sh 生态刚铺开，把 CAD 这类垂直专业工具接进 agent 正是这波插件化的直接受益点，一天涨 600+ 星。

 `JavaScript` ⭐ +616 今日新增 · 77,849 总星数

> 给 AI 编程助手装的设计规范包：24 条命令加 60 条不用大模型的检测规则，专治 AI 生成前端千篇一律的毛病。

**亮点**

- 把「AI 设计」拆成一套可执行的动词命令（bolder、quieter、distill、harden、colorize），人和模型有共同词汇，不用每次重新描述想要什么感觉。
- 确定性规则不经过模型这一层，意味着可以进 CI、进编辑器 hook、零延迟零成本复现，这是纯提示词方案做不到的。
- live / generate 模式在真实浏览器里点元素出变体，直接看效果改，不用描述给模型听。

**核心功能**

- 60 条确定性检测规则，CLI 和浏览器扩展在本地跑，不调 LLM、不要 API key。像 ESLint 一样查设计问题：灰字压彩底、纯黑不调色、卡片套卡片、圆角图标块乱用。结果可复现，能挂进 hook 在写代码时实时报错。
- 能用规则算的用规则，算不出来的（视觉层级、情绪传达）交给 LLM critique。两条腿分开，省 token 也省得模型胡判。
- 一条 npx impeccable install 把 skill、24 条命令和各家原生的 hook 清单写进 Claude Code、Cursor、Codex、Copilot、Grok、Gemini CLI 等目录。运行时是同一个自包含二进制，Node 只是安装壳，不装 Node 也能用 Git submodule 或插件方式跑。
- 状态分文件存：PRODUCT.md 记产品硬事实（受众、目标、操作场景、约束、语气），DESIGN.md 记视觉方向。两件事分开，后面的命令不会把产品事实当成风格随便改。

**适用场景**: 用 Claude Code、Cursor 生成前端页面的前端工程师和独立开发者，尤其是搭 SaaS 后台、落地页、营销站时嫌 AI 出图太模板化的人。团队里也当设计评审用：/impeccable audit 查 a11y 和响应式，/polish 上线前收尾，/harden 补错误态和文案溢出。

**竞品对比**: 起点是 Anthropic 的 frontend-design skill（一段提示词指导），Impeccable 在它之上加了 60 条确定性规则、24 条命令和多 harness 的 hook 安装。和 v0、Lovable 这类生成式工具也不同：它不生成页面，只约束你已有的 AI 助手别把界面做土。

**成熟度**: 早期项目，README 没给版本号，命令和安装流程在快速迭代；文档站齐全、支持的 harness 很多，但各家 hook 要手动信任批准，有摩擦。

**趋势信号**: Anthropic 的 frontend-design skill 先火了一波，加上社区对「AI 味」前端（Inter 字体、紫蓝渐变、卡片套卡片）的吐槽集中爆发，这个项目正好把反 AI 味做成了能一键安装的工具。

### [deepseek-ai/DeepGEMM](https://github.com/deepseek-ai/DeepGEMM)

 `Cuda` ⭐ +199 今日新增 · 8,780 总星数

> DeepSeek 开源的 GPU 张量核心算子库，把 FP8/FP4 GEMM、融合 MoE、稀疏索引打分等大模型核心计算收进一套 CUDA 代码，安装时不用编译。

**亮点**

- 刻意不用 CUTLASS 的模板和 CuTe 代数，只保留少量核心 kernel 函数，代码量小到能通读，但性能仍追平或超过专家手调库（H800 上跑到 1550 TFLOPS）
- 为 DeepSeek V3.2 的 lightning indexer 单独写了 MQA 打分 kernel（算 relu(q·k) 再按权重求和），SM100 上直接用 MXFP4/MXFP8 加打包 UE8M0 缩放因子

**核心功能**

- DeepJIT：所有 kernel 在运行时用 NVRTC 现编现用，pip 安装不需要 nvcc、不用等几十分钟编译，配套一个低 CPU 开销的 JIT C++ 模块（Python 侧调用几乎不占 CPU）
- Mega MoE：把 EP dispatch、linear1/linear2、SwiGLU、EP combine 融成一个 mega-kernel，靠对称内存让 NVLink 通信和 tensor core 计算重叠，而不是先通信完再算
- MoE 分组 GEMM 只切 M 轴（N、K 必须固定），训练/预填用 contiguous 连续布局，解码用 masked 掩码布局——这样开 CUDA Graph 时 CPU 不知道每个专家收多少 token 也能正确算
- SM90 只支持 NT 一种内存布局，SM100 支持 NT/TN/NN/TT 全部四种；缩放因子格式也不一样，SM90 用 FP32，SM100 用 4 个 UE8M0 打包进一个 torch.int

**适用场景**: 自研或部署 MoE 大模型的团队，尤其是做推理框架的工程师（vLLM、SGLang 这类），需要在 H800/H100/B200 上把专家层的 FP8 矩阵乘和 all-to-all 通信同时压到硬件极限。也适合想学 NVIDIA kernel 优化的人当教材读。

**竞品对比**: 主要对手是 NVIDIA 官方 CUTLASS 和 OpenAI 的 Triton。CUTLASS 通用但要啃模板、编译慢；Triton 好写但极致性能难抠。DeepGEMM 走的是「少量核心 kernel + 运行时 JIT」，换来更快编译和 MoE 专属的融合算子。

**成熟度**: 生产可用：DeepSeek 自家 V3/V3.2 的训练和推理在跑，已从 NVIDIA 扩到昇腾（DeepGEMM-Ascend），但 API 仍频繁变动，PR 里常有破坏性改动。

**趋势信号**: 2026.09.30 一口气发了昇腾版 DeepGEMM-Ascend 和一批新优化（含 locality domain），加上 DeepSeek V3.2 稀疏注意力带火的 indexer 打分 kernel，正好撞上国产 GPU 适配这个热点。

## 趋势观察

今天这份榜单，几乎全是给 AI Agent 加装的配件。技能包、人设库、上下文记忆、图表工具、设计规范，本质是同一个动作：把能力塞进 Claude Code、Codex 这些编码助手里。各家刚开放子 Agent 和插件市场，谁先占住标准，谁就说话有分量。

第二条线是让 Agent 真去干活，而不是陪聊。自然语言驱动 E2E 测试、生成 3D 模型并下单打印、接入逆向工具分析没有源码的程序——AI 的手从编辑器伸进了车间和二进制。

有意思的是另一头在往回拽。有人写技能包逼 Agent 先给结论、别寒暄；有人用 60 条不用大模型的规则，治前端生成物千篇一律。大家开始烦 AI 的啰嗦和套路，就用规则把它按回地面。

还有个省钱信号：测试跑完一遍就回放、不再调模型，检测靠本地规则，健身 App 自托管、离线可用。把模型用量和隐私收回自己手里，正在变成共识。

底层也没歇着。DeepSeek 开源 FP8、FP4 算子库，有人把 PS5 程序重链接成原生 PC 程序跑到 60 帧。上层疯狂加插件，下层死抠性能，两头一起推。
