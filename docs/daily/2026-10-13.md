### [lyogavin/airllm](https://github.com/lyogavin/airllm)

 `Jupyter Notebook` ⭐ +879 今日新增 · 37,757 总星数

> 把大模型按层切成文件存盘、逐层搬进显存，让 70B 甚至 2.8T 模型在 4GB 显卡上跑起来，现在还支持 6GB 微调，新模型一发布就适配。

**亮点**

- 把'显存不够'重新定义成'磁盘和 PCIe 带宽够不够'——不用量化、蒸馏、裁剪也能跑，代价是速度换内存。
- 同一套思路也用在训练上：冻结权重逐层流式读入，LoRA 适配器常驻显存，Qwen3.8-Flash-Next（125B）在 6GB 上能训。

**核心功能**

- 逐层流式加载：权重按层分片存盘，每次只把一层搬进显存，算完立刻释放，显存占用只跟最大一层的大小挂钩，跟总参数量无关。
- 块状量化压缩（block-wise quantization，把权重切成小块分别缩放再压成低精度）把权重变小，减少磁盘读取量，官方称推理最多提速 3 倍，因为瓶颈是 IO 不是算力。
- 对 MoE 模型按专家流式加载：Kimi K3（2.8T）每个 token 只路由到少数几个专家，那就只加载这几个专家；Qwen3.8-Flash-Next 的 51B n-gram 词表用 mmap 映在主机内存里，64GB 内存足够。
- 预先取下一层的数据来盖住加载耗时的空档（prefetching），官方说约 10% 提速。

**适用场景**: 适合手上一张 4GB~12GB 消费卡（RTX 3060 Ti、4090）的个人开发者和学生，想本地跑 DeepSeek-V3、Qwen3-235B 试试效果或做小规模 LoRA 微调。不适合要高并发、低延迟的线上推理服务。

**竞品对比**: llama.cpp/GGUF 靠量化把整个模型塞进内存或显存，内存不够就崩；AirLLM 不做量化、逐层从磁盘流式读，能跑远超本机内存的模型，但慢得多。和 HuggingFace accelerate 的 device_map offload 思路相近，多了 MoE 按专家流式和训练支持。

**成熟度**: 37.7k star、有 PyPI 包和 v3.0 版本，但推理速度慢、依赖特定 transformers/flash-attn 版本（README 里专门提醒 CUDA 12 构建和 4.56.x 版本），属可玩可试级别，不建议直接上生产。

**趋势信号**: 开源模型规模一路狂飙（Kimi K3 2.8T、Qwen3.8-Flash-Next 125B MoE），消费级显卡显存却原地踏步，而该项目总在新模型发布后一两周内就跟上适配，最近还加了训练支持。

### [Alishahryar1/free-claude-code](https://github.com/Alishahryar1/free-claude-code)

 `Python` ⭐ +626 今日新增 · 59,503 总星数

**竞品对比**: 跟 LiteLLM、OpenRouter、one-api/new-api 这类 LLM 网关/聚合器同类。最大差别是它专做'编程 Agent 反代'：内置 11 种 Agent 的启动命令（fcc-claude、fcc-codex 等）和一份免费额度目录，而前者是通用 API 网关，不管你怎么把 Agent 接上去。

**成熟度**: 热度很高（近 6 万星）且有 pytest/ruff/ty 的 CI，但本质依赖第三方免费额度的可用性，随时可能因 provider 收紧政策失效，属于能用但要自己承担风险的项目。

**趋势信号**: Claude Code、Codex 这类 Agent 用量费钱，而多家厂商（NVIDIA NIM、DeepSeek、xAI 等）在抢着发免费额度，社区就想把它们串起来白嫖；这次新增浏览器原生 Codex 会话和 Whisper 语音输入，进一步扩大了能用的入口。

### [mksglu/context-mode](https://github.com/mksglu/context-mode)

 `TypeScript` ⭐ +246 今日新增 · 27,545 总星数

> 给 AI 编程助手做上下文窗口瘦身的 MCP 服务器：把工具返回的原始数据挡在上下文外、用 SQLite 存会话记忆，覆盖 17 个客户端。当下 Agent 上下文爆满是普遍痛点，所以冲上 HN 第一。

**亮点**

- 明确不做「让模型少说话」的提示词约束。作者认为强制简洁会拉低编码和推理基准（引用了 Moonshot AI 关于 kimi-k2.5 的 issue），所以路由只管数据去哪，不管模型最后怎么组织语言——这跟一堆「魔法 system prompt」类工具的思路正好相反。
- 记忆检索用 FTS5 + BM25 做按需召回，而不是压缩后全量回灌上下文。这是把「会话记忆」当搜索引擎做，而不是当聊天记录做。

**核心功能**

- 沙箱工具拦截 MCP 返回结果：Playwright 快照、GitHub issue、访问日志这类原始数据不直接进上下文，先在沙箱里处理，只回传摘要，例子是 315KB 压到 5.4KB（98% 降幅）。
- 会话记忆落 SQLite，但压缩（compact）后不把历史全量塞回去，而是把文件编辑、git 操作、任务、报错事件索引进 FTS5，需要时用 BM25 检索相关性最高的事件，让模型从断点接着干。不传 --continue 就直接删库，保证新会话是干净状态。
- 「Think in Code」范式：不让模型把 50 个文件读进上下文来数函数，而是让它写一段脚本跑完只 console.log 结果——47 次 Read 换 1 次 ctx_execute，700KB 变 3.6KB。
- 通过 MCP 协议 + 平台 hook 强制路由：Claude Code 走插件市场全自动，靠 SessionStart hook 在运行时注入路由指令、不往项目里写文件；不支持 hook 的平台只能手动拷一份路由文件。注册 11 个 MCP 工具（6 个沙箱 + 5 个运维元工具）。

**适用场景**: 重度使用 Claude Code / Cursor 的开发者：跑 Playwright 抓页面、拉一堆 GitHub issue、读日志时，上下文半小时就掉 40%，这个项目就是给这类长会话用的。 多平台混用的团队：有人在 Claude Code、有人在 OpenClaw 网关、有人在别的 MCP 客户端，需要统一一套上下文节省和记忆续接规则。

**竞品对比**: 对标的是 Claude Code 自带的 /compact 和内置上下文管理，以及 mem0、Letta(MemGPT) 这类 Agent 记忆层。最大差异：它不只管记忆，还从源头上把 MCP 工具输出截流，并且把 17 个平台的客户端都纳入同一套路由；mem0 那类只解决「记住什么」，不解决「工具返回的数据一开始就别进来」。

**成熟度**: 生产可用但授权需注意：2.7 万 star、HN 第一、README 称微软/谷歌/Meta 等团队在用，但用的是 ELv2 许可（源码可见、非标准开源，不能拿去做竞品托管服务）。

**趋势信号**: MCP 生态铺开一年后，「每次工具调用都把原始数据灌进上下文」成了公认的 Agent 头号浪费，加上 Anthropic 自己也在推 context engineering 和 compaction，这个项目正好卡在这个时间点被顶上 HN 首页（570+ 分）。

### [open-webui/open-webui](https://github.com/open-webui/open-webui)

 `Python` ⭐ +157 今日新增 · 155,310 总星数

> 自托管 AI 聊天平台，一个界面同时接 Ollama 本地模型和任意 OpenAI 兼容 API，把 ChatGPT 式体验搬进企业内网，最近补上了 Agent 终端和 MCP 工具接入。

**亮点**

- 插件不是一个大而全的 hook，而是按数据流位置切成 Filter/Pipe/Action/Tool/Skill 五类，写插件的人不用猜自己在哪一层，也方便做审批流和限流。
- 新增的 Open Terminal 给 Agent 一个真终端和文件系统去跑多步任务（分析数据、执行脚本、改错、产出文件），企业版按用户给隔离容器并限资源——这是从聊天框往 Agent 沙箱走的一步。

**核心功能**

- 后端 FastAPI + 前端 Svelte，模型接入层做成了 provider 无关：同一个 URL 配置项指向 Ollama、LMStudio、vLLM、GroqCloud、OpenRouter 都能跑，界面不变。
- 本地 RAG 用 BM25 + 向量混合检索再加重排序（不是纯向量），文档解析走 Tika、Docling、PaddleOCR 等外部引擎，向量库可选 9 种（ChromaDB、PGVector、Qdrant、Milvus、Elasticsearch、Oracle 23ai 等）。
- 插件分五类，职责写死：Filter 改请求/响应、Pipe 把外部服务伪装成模型、Action 给消息加按钮、Tool 给模型调用、Skill 注入能力；外部工具通过 MCP/MCPO/OpenAPI 服务器接进来。
- 企业部署细节到位：Redis 存 session + WebSocket 实现多 worker 多节点挂负载均衡，LDAP/AD、OAuth 信任头登录、SCIM 2.0 自动开户（Okta/Azure AD/Google Workspace），OpenTelemetry 出 traces/metrics/logs。

**适用场景**: 企业内部平台团队（金融、医疗、法务这类数据不能出内网的行业）给员工搭私有 ChatGPT，统一计费和用量统计；个人开发者在本地跑 Ollama 想要个比命令行好用的前端。

**竞品对比**: 同赛道有 LibreChat、AnythingLLM、LobeChat。Open WebUI 的差异是功能覆盖最全且企业特性最厚（SCIM 2.0、LDAP、OTel、Redis 水平扩展），LibreChat 更偏轻量多模型，AnythingLLM 更偏文档 RAG 单点。

**成熟度**: 生产可用，155k star、有商业企业版和完整文档，社区（Discord）活跃，企业身份/可观测性/水平扩展都齐了。

**趋势信号**: MCP 成为工具接入事实标准后它很快跟进（MCP/MCPO），又补上 Open Terminal 的 Agent 执行能力，正好踩在企业想要自托管 AI 平台、不想把数据交给公有云的时间点上。

### [microsoft/BitNet](https://github.com/microsoft/BitNet)

 `C++` ⭐ +97 今日新增 · 41,021 总星数

> 微软官方的 1-bit LLM 推理框架，把权重压成三值（-1/0/1）用查表代替乘法，让 100B 模型在单颗 CPU 上跑到 5-7 token/s。

**亮点**

- 核心取舍是「训练时就接受三值权重」，换来推理端彻底省掉乘法器和大量权重访存。官方数据：x86 CPU 提速 2.37x–6.17x、能耗降 71.9%–82.2%；ARM 提速 1.37x–5.07x、能耗降 55.4%–70.0%
- 2026 年 7 月把它从「聊天 LLM 推理器」扩成了通用 1-bit 推理底座：新发的 VibeASR.cpp 用同一套 I2_S kernel 在 CPU 上做实时多语言语音识别，RTF < 1

**核心功能**

- 权重只有 -1、0、1 三种取值，矩阵乘法被改写为「查表 + 累加」（LUT），前向几乎不做浮点乘，I2_S 格式下每个权重只占 2 bit
- 手写 x86（AVX2）和 ARM（NEON）SIMD kernel，多线程分块（tiling）参数可配，官方称相比原实现又提速 1.15x–2.1x
- 推理无损：1.58-bit 前向结果和全精度一致，因为三值特性来自模型训练阶段，而不是推理时临时量化

**适用场景**: 想在笔记本、手机、树莓派或没有 GPU 的内网服务器上跑大模型的人。也适合做检索的场景——刚发的 BitNet-embedding 0.6B/270M 就是给 CPU 上的向量化用的。

**竞品对比**: 最直接的对比是 llama.cpp / ggml 的 Q4 量化。差别在于：llama.cpp 是把全精度模型压小，跑起来仍要做整数乘；BitNet 的模型天生三值，推理端可以完全不用乘法。代价是只能用 BitNet 训练出来的模型，普通 LLaMA 权重跑不了。

**成熟度**: 生产可用：1.0 版本、微软官方维护、MIT 协议，有 arXiv 技术报告、Hugging Face 模型和在线 demo，CPU/GPU 两条路径都已落地。

**趋势信号**: 七月连发两个 1-bit embedding 模型（0.6B/270M）和基于 BitNet I2_S 的实时 ASR 引擎，把 1-bit 推理从 LLM 聊天扩到 embedding 和语音，正好撞上「本地/边缘 CPU 推理」这波热度。

## 趋势观察

今天的榜单，几乎全是给 AI Agent 打下手的基础设施。MCP 成了事实标准:逆向工具、绘图技能、会话记忆,都封装成 MCP 服务器塞进 Claude Code、Cursor。Agent 不再是聊天框,而是能拆二进制、能画图、能连内网的工具人。

第二条线是省钱和降门槛。上下文爆满是普遍痛点,所以有窗口瘦身的 MCP 服务器,把原始数据挡在上下文外,用 SQLite 存记忆,直接冲上 HN 第一。推理侧更狠:1-bit 三值权重、按层切分搬进显存,4GB 显卡跑 70B,单颗 CPU 跑 100B。还有本地代理把 11 种 Agent 的请求转发到 61 家免费模型商,一个月 13 亿 token。

第三条线是自托管和企业内网。自托管聊天平台一个界面同时接 Ollama 和 OpenAI 兼容 API,把 ChatGPT 式体验搬进公司内部。

共同信号很清楚:模型能力在贬值,工程能力在升值。谁能管好上下文、压住成本、接住私有数据,谁就有位置。开发者生态正从调 API 写应用,转向给 Agent 造零件。
