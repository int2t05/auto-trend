## 概览

今日共收录 **16** 个 GitHub Trending 项目。
主要语言分布：Python(7)、TypeScript(4)、Shell(2)、HTML(1)、C(1)。

今天这份榜单，大半是“给 Agent 装技能”的活儿。Claude Code 有红队测试包，Cursor 有官方插件规范，还有画图技能、检索技能、设计技能。Cursor 干脆把自己从 IDE 变成了插件市场。意思很明确：Agent 不只是聊天框，它正在变成平台，技能就是插件，谁定标准谁收租。第二个信号是 MCP。Firecrawl Local 装完自动注册成 MCP server，Google Stitch 也走 MCP。这协议正在变成 Agent 连接各类工具的通用接口，抓网页、做设计、连 SaaS 都从这儿进。第三，Agent 开始进入真实工程环节。CI 一挂自动读日志、推理根因并推送修复分支，App 提交前先拦截拒审原因，漏洞检测按 CVE 攻击链走。不再只是演示，而是实际承担工程任务。还有一种趋势是避免被云服务绑定：3 块钱用 3090 训完小模型，AFFiNE 数据存本地，Intel 工具链让 AI PC 本地跑 LLM，CLI agent 可自托管。本地、便宜、自己掌控，成了卖点。另外，给 Blender、CAD 套命令行让 Agent 敲命令，把网站转成干净 Markdown 喂给 Agent，都在解决同一个问题：Agent 操作外部工具和获取输入的能力还不够顺畅，需要有人做衔接工具。一句话，热点从“模型多强”转到了“Agent 怎么用”。开发者忙着给 Agent 装插件、接入标准、补短板。生态正从拼模型转向拼工程化，插件市场和 MCP 是这一轮的主战场。

### [elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)

 `Python` ⭐ +1,716 今日新增 · 18,436 总星数

> 把 83 个众测/红队技能打包成 Claude Code 插件，装完 Claude 就按你的测试目标自动加载漏洞检测套路、CVE 攻击链和报告规范。

**亮点**

- 定位是“提示层”不是“执行框架”：不自己造扫描器，把领域知识和流程约束塞进已有 Agent，工具还是 subfinder、httpx、Burp 那一套，判断交给模型

**核心功能**

- 知识全是 Markdown 写的 SKILL.md，模型靠读描述自己决定加载哪个技能，不用记命令名；同一份文件复制到 ~/.claude/skills、~/.agents/skills、~/.hermes/skills、~/.gemini/config/skills 就能给 Claude Code、Codex CLI、OpenCode、AntiGravity 共用
- 把 681 份公开的 HackerOne 披露报告拆成按 24 个漏洞类别组织的检测模式、payload 表、绕过表和利用链模板，其中 433 条单独标了报告出处可以逐条回查
- 通过 MCP 接 Burp Suite 和 HackerOne API：一个把代理流量和重放结果喂进上下文，另一个用来查历史重复报告、拉项目 scope，减少报重复单
- 带企业边界攻击矩阵：M365/Entra、Okta、vCenter、SharePoint（含 ToolShell）、Cisco/Fortinet/Citrix/Palo Alto 等 SSL VPN 的 2024–2026 CVE 链和拿到凭据后的横向路径

**适用场景**: 接单的独立白帽和甲方红队做外部打点的人用。典型流程是在 HackerOne 项目里先跑子域枚举和指纹，排出攻击面优先级，再按 GraphQL introspection、OAuth redirect_uri、IDOR 这些类别逐个验，最后过一遍三查七问式的有效性校验再报单。

**竞品对比**: 和 PentestGPT、CAI 这类自成闭环的自动化渗透 Agent 不同，它不接管工具调用，只做知识和流程层，必须搭在现成的编码 Agent 上跑；和 Nuclei 模板库比，那边是正则和 DSL 硬匹配，这边靠 LLM 读语义做判断。

**成熟度**: 早期项目：没有版本号、基本单人维护，内容是文档加安装脚本，出错顶多给出错误建议而不是搞坏环境，适合当辅助参考，不能当唯一依据。

**趋势信号**: Claude Code 的 skills 和插件市场刚开放，安全圈正试着把众测老手的经验打包成 Agent 可加载的知识库，叠加 SharePoint ToolShell 这类边界设备 CVE 集中爆发，红队对“现成攻击链”的需求被拉起来了。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +915 今日新增 · 207,295 总星数

> 把网站变成干净 Markdown 喂给 AI Agent。这次新增 Firecrawl Local：一条 cargo install 装上的 Rust 单二进制，本机抓取并自动注册成 MCP server，抓不动的页面回退云端。

**亮点**

- 本地优先 + 云端兜底的路由设计：单页在本地加载失败时自动改由 Firecrawl Cloud 抓，结果里标 source: firecrawl-cloud，设 FIRECRAWL_CLOUD=off 可彻底断云，兼顾覆盖率和数据不出本机
- 同一个 API 契约同时跑在本地二进制、自托管服务和云上，用户从本地迁到云只是换个 base URL，不用改代码

**核心功能**

- Firecrawl Local 用 Rust 写成单个二进制，自带 scrape/crawl/map，不需要数据库、队列或容器；PDF 和 Office 文档也在本机解析，不传云
- JS 渲染复用本机已装的 Chrome/Chromium，而不是打包一个浏览器，所以体积小；没装浏览器时降级成静态抓取，并在结果里给 warning
- firecrawl-local serve 在 localhost:3002 复刻 Firecrawl v2 API，本地路由不需要 API key，现有 Python/Node SDK 只改 api_url 就能跑
- firecrawl-local init 自动探测 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 六种客户端，写 MCP 配置前先备份原文件

**适用场景**: 给 Claude Code、Cursor 里写 Agent 的开发者：让它能读文档站、竞品页面、PDF，不用自己拼 Playwright + 解析器 + 向量库 需要批量把站点文档转成 Markdown 语料做 RAG 的团队，一条 firecrawl-local crawl --out ./pages 就能按页落盘

**竞品对比**: 对比 Jina Reader（只做单页转 Markdown）、Crawl4AI（Python 库，得自己搭和维护浏览器）、Apify（偏爬虫平台）、Tavily/Exa（只给搜索），Firecrawl 把抓取、爬站、搜索、MCP 打包成一套 API，还多了本地跑 + 云端兜底这条路径。

**成熟度**: 生产可用：有商业云服务、自托管方案和多语言 SDK，文档和社区都齐全；但 Local 是新拆出来的组件，命令和默认行为还可能调整。

**趋势信号**: MCP 客户端今年集中铺开，Firecrawl 把抓取做成一条命令装好的本地 MCP server，再叠上每月 1000 次免注册的 keyless 额度，Agent 开发者接入成本几乎为零。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +788 今日新增 · 324,421 总星数

> 给编码 Agent 装一套开发方法论：先问清需求、写规格、拆计划，再派子代理按 TDD 逐任务实现，一次适配 18 种 Agent 工具。

**亮点**

- 反着来：Agent 被要求先别写代码，而是回头问你到底想做什么，把“需求澄清”变成强制的第一步，避免一上来就生成一堆跑不通的代码。
- 一份技能库吃下 18 个 harness 的原生插件机制，不绑定单一厂商；同时用 SessionStart 钩子解决“技能装了但不触发”这个 agent 插件最常见的失效点。

**核心功能**

- 技能本体是 Markdown，靠各宿主自带的插件市场分发：Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、Kimi Code、Qwen Code 等 18 家各装一份；另外塞了一个 bootstrap 技能，在会话开始和上下文压缩之后重新注入，保证技能真会被触发，而不是装完就被忽略。
- 流程被拆成可组合技能：brainstorm 逼出需求 → 分段展示规格让你读得下去 → 出实现计划 → subagent-driven development，每个工程任务派一个子代理去做，主代理检查它的产出再放行，所以能连续自主跑几个小时不偏离计划。
- 计划模板硬性要求 red/green TDD、YAGNI、DRY，并规定粒度要细到“没品味、没项目上下文、不爱写测试的初级工程师也能照做”——用提示词约束替代代码检查。
- 明确处理了各宿主的差异：比如 Hermes 没有压缩后钩子，文档直接写明长会话会丢 bootstrap、要重开会话，而不是假装都能用。

**适用场景**: 用 Claude Code / Codex / Cursor 写真实业务代码的独立开发者和中小团队，尤其是需求一开始说不清、又想让 Agent 长跑几小时不跑偏、事后还要有规格和计划文档可查的场景。

**竞品对比**: 和 CLAUDE.md / .cursorrules 这类静态规则文件比，它不止是提示词，而是带状态的多阶段流程；和 GitHub Spec Kit、BMAD-METHOD 比，它不止产出规格文档，还把规格→计划→子代理执行→审查做成自动触发的闭环，而且同一份技能能横跨各家 Agent。

**成熟度**: 方法论型早期项目，本体就是 Shell 安装脚本加 Markdown 技能，没有传统 API 破坏问题，但技能内容和流程还在快速迭代；安装面铺得很广，已开出企业支持邮箱。

**趋势信号**: Claude Code、Codex、Gemini CLI、Copilot CLI 等接连上线官方插件市场，“Agent Skills”正变成跨工具的通用分发格式，Superpowers 恰好赶在这波入口开放的节点上一次覆盖全部。

**趋势信号**: 2026 年 Agent 工具链正从"人人写 MCP"转向"给 Agent 一套 CLI"，HKUDS 靠 CLI-Hub 一键安装和技能包格式快速铺量，加上新出的技术报告一起把热度顶起来。

- 多进程 + 单线程事件循环的取舍：不用多线程锁，靠 worker 之间几乎不共享可变状态来避免锁竞争,代价是跨 worker 的共享数据必须显式放进共享内存 zone
- 配置 reload 的平滑切换机制：新旧 worker 并存一段时间，老 worker 排空存量连接后自己退出，不用重启进程也不掉连接

**核心功能**

- master 进程只负责读配置和管理，多个 worker 进程各自用 epoll（Linux）/kqueue（BSD）做事件驱动处理请求，worker 数可配成 auto 跟 CPU 核数对齐，避免一个连接占一个线程
- 进程间靠共享内存 zone 同步状态：限流计数（limit_req_zone）、缓存索引、连接统计都放共享内存里，所以多个 worker 看到的是同一份数据，不用走进程间通信
- 模块化拆分，模块能静态编译进二进制也能做成 dynamic module 运行时加载，用 nginx -V 可以查当前二进制带哪些静态模块
- 配置是纯文本指令式，reload 时先启新 worker 接管新连接、旧 worker 处理完存量连接再退出，做到不丢连接的热更新

**适用场景**: SRE/运维和 backend 工程师拿来放在应用前面做反向代理、TLS 终止、静态文件服务、灰度分流和限流；K8s 集群里 ingress-nginx 也是它。做秒杀、大促这种突发流量场景时用来挡在前面。

**竞品对比**: 对比 Apache httpd，nginx 在 C10K 这类大量空闲长连接场景内存占用低得多；对比 Caddy，Caddy 自动申请续期 HTTPS 证书更省事，nginx 要自己配 certbot；对比 Envoy，Envoy 支持 xDS 动态下发配置，nginx 改配置基本要 reload。nginx 的优势是静态资源和反向代理这块打磨了二十年，资料和第三方模块最多。

**成熟度**: 生产就绪，20 多年历史，BSD-2 协议，全世界大量高流量站点在跑，F5 提供商业支持和企业版。

**趋势信号**: 2024 年官方代码从 Mercurial 迁到 GitHub，这个仓库成了 nginx 唯一的官方源码入口，加上主线版（1.29.x）持续发版和安全补丁，star 一直往这聚。

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +158 今日新增 · 12,160 总星数

> 英特尔开源的 AI 推理部署工具链，把 PyTorch、TF、ONNX 模型转成统一格式，跑在 Intel CPU、GPU、NPU 上。现在本地跑 LLM 的 AI PC 需求起来，它跟着火了。

**亮点**

- 不做通用编译器，只死磕 Intel 自家硬件：AI PC 上的 NPU 是它独占的加速路径，ONNX Runtime 那边 NPU 支持薄得多。
- 转换和推理分两层：convert_model 生成与硬件无关的 IR，compile_model 才做设备相关的图优化和算子融合，所以换个硬件不用重新转模型。

**核心功能**

- 自带模型前端解析器，直接读 PyTorch FX 计算图、TensorFlow GraphDef、ONNX 的 protobuf，转成自家 IR 后运行时不需要原框架。
- NNCF 做训练后量化，LLM 权重能压到 INT4（分组量化 + 数据感知的 AWQ/GPTQ 类算法），显存/内存占用降一半以上。
- 插件式后端：CPU 插件底层用 oneDNN，吃 AVX-512 和 AMX 指令；GPU 插件走 OpenCL；NPU 插件对接 Intel VPU 驱动，同一份 IR 换设备只改一个字符串。
- GenAI API 里内置 continuous batching、paged attention 的 KV cache 和投机解码，不用自己写 LLM 服务调度。

**适用场景**: 学生和嵌入式工程师在只有核显或 NPU 的笔记本、工控机上跑 YOLO、Whisper、7B 量化模型；企业做视觉质检、缺陷检测这类边缘推理，用 OpenVINO Model Server 部署到产线设备。

**竞品对比**: 对标 ONNX Runtime、NVIDIA TensorRT 和 llama.cpp。TensorRT 只吃 NVIDIA 卡；ONNX Runtime 跨平台广但每家硬件都浅；OpenVINO 只做 Intel，但对 Intel CPU/GPU/NPU 的算子覆盖和量化工具链更深。

**成熟度**: 生产可用，有正式年份版本号和完整文档，英特尔企业级支持，社区多年活跃。

**趋势信号**: AI PC 概念落地，酷睿 Ultra 的 NPU 要靠它才能跑本地大模型，英特尔近期推 GenAI API 和 LLM 推理示例，带来这波涨星。

## 趋势观察

今天这份榜单，大半是“给 Agent 装技能”的活儿。Claude Code 有红队测试包，Cursor 有官方插件规范，还有画图技能、检索技能、设计技能。Cursor 干脆把自己从 IDE 变成了插件市场。意思很明确：Agent 不只是聊天框，它正在变成平台，技能就是插件，谁定标准谁收租。第二个信号是 MCP。Firecrawl Local 装完自动注册成 MCP server，Google Stitch 也走 MCP。这协议正在变成 Agent 连接各类工具的通用接口，抓网页、做设计、连 SaaS 都从这儿进。第三，Agent 开始进入真实工程环节。CI 一挂自动读日志、推理根因并推送修复分支，App 提交前先拦截拒审原因，漏洞检测按 CVE 攻击链走。不再只是演示，而是实际承担工程任务。还有一种趋势是避免被云服务绑定：3 块钱用 3090 训完小模型，AFFiNE 数据存本地，Intel 工具链让 AI PC 本地跑 LLM，CLI agent 可自托管。本地、便宜、自己掌控，成了卖点。另外，给 Blender、CAD 套命令行让 Agent 敲命令，把网站转成干净 Markdown 喂给 Agent，都在解决同一个问题：Agent 操作外部工具和获取输入的能力还不够顺畅，需要有人做衔接工具。一句话，热点从“模型多强”转到了“Agent 怎么用”。开发者忙着给 Agent 装插件、接入标准、补短板。生态正从拼模型转向拼工程化，插件市场和 MCP 是这一轮的主战场。
