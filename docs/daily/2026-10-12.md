### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +25,599 今日新增 · 116,905 总星数

> 一个 MCP 服务器，把 Hopper/Ghidra/IDA 的二进制分析能力接进 Claude Code 等 AI Agent，让模型直接看懂某个功能在原生代码、Electron、.NET 里是怎么实现的。

**亮点**

- 把工程重心从'造工具'挪到'编排工具 + 统一证据格式'：MCP tool catalog 是自动生成的（见 docs/mcp-contracts.md），跨原生二进制、JS/Electron、.NET、WASM、网站输出同一套带证据的结构化结果
- 全程本地跑，静态 JS 分析甚至不需要装任何反汇编器；只有原生分析才按需调用本机已有的 Hopper/Ghidra/IDA

**核心功能**

- 不自研反汇编引擎，而是给 Hopper、Ghidra、IDA 三家都写了适配层，通过统一的 MCP 契约暴露工具，用户手上有哪个就用哪个（Ghidra 免费也能跑）
- Go 二进制走内置静态解析：直接读 ELF/PE/thin Mach-O 里的 Go buildinfo，拿到编译器版本、依赖模块、replace 指令和编译参数，不用装 Go 工具链
- 每条结论强制附带证据（命中的函数、字符串、调用引用）和明确的未知项一起回给模型，目的是压住 Agent 在逆向场景里最爱犯的'编造'问题
- JS/Electron 静态分析可独立运行：解析应用目录或 ASAR 包，输出模块列表、import 依赖图、Electron 主进程/渲染进程边界，不需要任何原生分析引擎

**适用场景**: 两类人：一是想复刻竞品某个功能的开发者，让 Agent 去扒别人的 Electron 应用或桌面软件，看完证据再写自己的实现；二是安全研究员和逆向工程师，在 Claude Code、Cursor、Codex 里用自然语言驱动 Ghidra/IDA，省掉手工翻反汇编的时间。因为是全本地执行，处理私有二进制时不用上传到云端。

**竞品对比**: 同赛道已有 GhidraMCP、ida-pro-mcp、r2ai 等，但基本都绑定单一工具、单一目标格式。REA 的差别是一个 MCP 覆盖原生二进制/JS/Electron/.NET/WASM/网站，且不强制你买 IDA。

**成熟度**: 已发 npm 包、有 19 种语言 README 和 Discord 社区，但官方自己写明'更新很快、新版本包含大量修复'，API 可能变动，生产使用建议锁版本。

**趋势信号**: MCP 在 2025 年成了 Agent 接工具的事实标准，加上编码 Agent 普及，'用 Agent 做逆向'（vibe reversing）正从小圈子玩法变成主流需求，这个项目踩的正是这波。

### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5)

 `C++` ⭐ +3,952 今日新增 · 30,787 总星数

> 把 PS5 可执行文件重新链接成 Linux/Windows 原生程序，不做 CPU 模拟也不要独立运行时，靠重写系统库和着色器转 SPIR-V 让游戏直接跑在 PC 上。

**亮点**

- 彻底放弃模拟器路线：没有 CPU 模拟、没有独立模拟进程，游戏线程就是宿主线程，换取更低开销，代价是兼容性必须靠一个个补 API 堆出来
- 把“缺失的库函数”做成显式崩溃而不是悄悄降级，等于用崩溃日志驱动兼容性开发流程

**核心功能**

- relinker 把 PS5 可执行文件转成目标平台原生格式（静态重编译），不解释指令、不做 JIT，CPU 侧几乎无模拟开销
- 重写 PS5 的 prx 系统库（相当于主机上的动态链接库），用原生实现顶替原库调用；着色器重编译器把 PS5 shader 转成 SPIR-V，并用 Spirv-Tools 校验，走 Vulkan 路线
- 碰到未实现的调用直接抛 std::runtime_error、打印 what() 到 stderr 后退出，不做静默兜底，方便靠崩溃点定位缺哪个库函数

**适用场景**: 想在没有 PS5 的 PC 上跑主机游戏的玩家和做互操作性/游戏保存研究的开发者；也是学静态重编译、主机库重实现（类似 N64/Xbox 360 重编译项目）的人拿来读代码的样本

**竞品对比**: 和 shadPS4、RPCS3 这类模拟器不同，它不做 CPU 指令翻译层；和同为静态重编译的 N64 recomp、Xbox 360 重编译项目比，它针对 PS5 且自带完整 shader 到 SPIR-V 的重编译链。

**成熟度**: 早期项目，验证过的游戏只有 Dreaming Sarah 一款 2D 小游戏，API 和模块划分大概率还会大改；文档比较齐（含架构和技术债说明）。

**趋势信号**: PS4/PS5 模拟是近期热点（shadPS4 等），而“静态重编译取代模拟器”这条路线在 N64、Xbox 360 项目上刚被验证可行，这个项目把它搬到 PS5 上，加上 3 万星量级的突然曝光带来一波关注。

**成熟度**: 早期项目，文档还堆在 _develop 目录下，README 连版本号都没写，API 和文件格式大概率还会变，不建议直接接进生产流程。

 `JavaScript` ⭐ +886 今日新增 · 52,117 总星数

> 浏览器里跑的"间谍卫星"地球仪：把航班、船舶、卫星、地震、气象、摄像头等公开数据叠在同一个 3D 地球上，本地运行、语音操控、代码可查。

**亮点**

- 定位很反直觉：视觉上做成"不该给普通人看的驾驶舱"，但数据全部来自公开源、代码全部可审——把一个纯视觉噱头变成了可验证的开放情报工具。
- 每个数据层拆成独立模块并允许自带数据源，同时用 URL 序列化追踪目标，等于把"看一个地球"变成"交接一个正在移动的目标"。

**核心功能**

- 把多路公开数据流并到同一个 Cesium 3D 地球上：ADS-B 航班、AIS 船舶、TLE 卫星轨道、USGS 地震、GFS/ECMWF 气象、OSM 里标注的 ALPR（车牌识别摄像头）点位，每层是独立模块，可单独开关和替换数据源。
- 无密钥启动：默认走 Esri 卫星影像 + 免密钥地形，Esri 挂了就回退 OSM；航班、卫星、地震、公共摄像头、火箭发射都不用 key，只有想要照片级 3D 才需要 Cesium ion 或 Google Maps 的 key。
- 用 GLSL 后处理着色器在正常地球上覆盖传感器观感（CRT、NVG 夜视、FLIR 热成像、Noir、雪景），再叠一层屏幕空间检测框和 ID，做出"军用 HUD"的视觉效果，但底层还是普通的 3D 地球渲染管线。
- 实时语音 AI agent 直接驱动相机和查询：用一句话让地球飞到指定坐标、追踪某个目标、统计并排序卫星/数据中心/大坝，回答里还会说明这条数据源是不是过期或走了降级方案。
- 分享链接把相机位姿、样式、图层和当前追踪目标一起序列化进 URL，别人打开就是同一个实时画面，被追踪的目标是交接而不是书签。

**适用场景**: OSINT 分析师、记者、应急/救援人员，以及航空航运爱好者。典型场景：追一架具体航班或一艘船的实时位置、查某颗卫星什么时候过顶、复现尼泊尔 Bhote Koshi 洪水灾情做报道素材，或者录一段"驾驶舱第一视角"的演示视频。

**竞品对比**: 和 Flightradar24、MarineTraffic 这类单领域追踪站比，它把航班、船舶、卫星、地震、气象、摄像头压进同一个可编程地球，而不是各开一个网页；和 Google Earth、Cesium 这类纯地球引擎比，它自带数据管道、语音控制和军用 HUD 风格的呈现层。最大差异是免密钥起步 + 本地部署 + 图层可自换。

**成熟度**: 早期但已能日常使用：有 CI、doctor 自检脚本、Pinokio 一键安装和跨平台测试，文档完整；但强依赖第三方公开数据源，接口一变功能就空——README 明确说旧版本因为 OSM Overpass 拒绝查询，Traffic、Mapped Installations、ALPR 三层直接变空白，需要更新才恢复。

**趋势信号**: YouTube 上同名的 God's Eye View 视频系列（自称 500 万+ 播放）先爆，然后作者把项目开源，配合"公开数据拼出间谍卫星体验"的话题性和语音 AI agent 控制，8 月冲上 GitHub Trending 日榜和周榜第一。

### [lyogavin/airllm](https://github.com/lyogavin/airllm)

 `Jupyter Notebook` ⭐ +548 今日新增 · 36,710 总星数

> AirLLM 把大模型按层拆开存盘，推理时只把当前层搬进 GPU，让 70B 模型在单张 4GB 显卡上跑起来，最近还加了小显存微调支持。

**亮点**

- 核心取舍是拿磁盘和内存换显存：不再要求显存装得下整个模型，只要装得下最大的一层就行。代价是每生成一个 token 都要把权重从磁盘重搬一遍，所以它是'能跑'而非'跑得快'。
- MoE 模型做逐专家加载，而不是逐层加载，把稀疏路由当成省显存的抓手，这比单纯调小 batch 或降精度的思路省得多。

**核心功能**

- 分层流式加载：模型按 transformer 层切分存到磁盘，推理时一次只把一层读进显存，占用等于最大单层体积，而不是整个模型大小。
- 块级量化（block-wise quantization）压缩权重，官方称最多提速 3 倍、精度损失近乎可忽略；再配合预取，一边算当前层一边预读下一层，用计算掩盖磁盘 IO，README 说约 10% 提速。
- MoE 按专家流式：只加载 token 实际路由到的专家而不是整层，这是 Kimi K3（2.8T）能压到 3.72GB 显存的关键；n-gram embedding 大表则用 file-map 放在主机内存里。
- 训练也走同样思路：冻结权重逐层流式读入，只把 adapter 常驻 GPU，所以 125B 模型能在 6GB 显卡上微调。

**适用场景**: 只有一张消费级显卡（RTX 3060/3090/4090）或 Mac 的个人开发者、学生、研究员，想拿 DeepSeek-V3、Kimi K3 这类几百 B 到 T 级开源模型跑离线实验、批处理问答，或用 LoRA 在小显存上微调大模型。

**竞品对比**: llama.cpp 靠 GGUF 量化加部分层 offload 到 CPU，速度明显更快，但前提是模型能压进可用显存+内存；Accelerate 的 device_map 只能把层拆到多张卡或多个设备。AirLLM 的差异点是不量化也能跑，显存门槛可以低到比单层还小，代价是慢很多，两者适合的场景不同。

**成熟度**: Apache 2.0，36.7k stars，PyPI 有包可 pip 安装，更新频繁（2026 年还在持续接新模型和训练功能），但推理吞吐低、官方未给生产级性能承诺，属于实验和个人本地使用阶段，不建议直接做线上高并发服务。

**趋势信号**: 开源模型越做越大（Kimi K3 2.8T、DeepSeek-V3 671B），显卡显存和价格却卡着个人开发者；AirLLM 最新加了小显存训练支持——125B 模型在 6GB 显卡上微调，正好戳中'一张消费卡跑大模型'这个当下最热的需求。

### [chrislgarry/Apollo-11](https://github.com/chrislgarry/Apollo-11)

 `Assembly` ⭐ +466 今日新增 · 74,389 总星数

> 1969 年阿波罗 11 号制导计算机的原始汇编源码归档，由 Virtual AGC 和 MIT 博物馆从纸质扫描件逐行转录，公共领域。它是登月代码的唯一开源原档。

**核心功能**

- 两份完整程序、约 3.6 万行 AGC 汇编：Comanche 055 跑指令舱、Luminary 099 跑登月舱，覆盖制导、导航、推力器控制、交会雷达、键盘显示等模块，可用 yaYUL 汇编器还原成 AGC 机器码。
- 在 15 位字长、36K 字只读绳存 + 2K 字 RAM 的约束下写成：没有调用栈，返回地址靠 Q 寄存器加自修改指令（直接改写跳转指令的地址字段）实现；矩阵和向量运算交给 Interpreter 虚拟指令集跑，用解释执行换代码密度。
- 仓库本身是校勘工程，不是代码托管：Comanche055 和 Luminary099 各开一个 milestone 记录转录存疑处，任何人都能对着 MIT 博物馆的原始扫描件逐行提 PR 修正。
- 连硬件都算上：程序烧在 Raytheon 手工编织的 core rope 只读存储器里，靠铜线穿过磁环来记录 0 和 1，所以代码发布即固化，改一行要重织。

**适用场景**: 航天史和计算机史课程的师生、做 AGC 模拟器或 FPGA 复刻的爱好者（配合 Virtual AGC 工具链），以及想研究极端内存受限下实时系统怎么写的嵌入式工程师。

**竞品对比**: 和 Virtual AGC（rburkey2005/virtualagc）是互补关系：那边提供 AGC 模拟器和可运行的汇编工具链，这边只放源码原档，README 里也直接把编译需求指向它。没有同量级的竞争项目。

**成熟度**: 只读归档，源码属公共领域且 1969 年即冻结，不存在版本迭代风险，维护工作只剩校对和翻译。

**趋势信号**: 没有明确的触发事件，属于社交平台周期性考古转发——'人类登月用的代码长这样'这个话题一被翻出来就会连带涨星。

### [pytorch/pytorch](https://github.com/pytorch/pytorch)

 `Python` ⭐ +315 今日新增 · 104,617 总星数

> PyTorch 是 Meta 主推的深度学习框架，把 NumPy 式的张量计算搬到 GPU 上，并用动态图自动求导让模型随时改结构。如今它已是 AI 训练的事实标准，热度长期在线。

**亮点**

- 动态计算图是它当年跟 TensorFlow 1.x 静态图拉开差距的关键：定义即执行，改网络结构不用重编译，研究和调试体验直接好一个档次
- 生态锁定效应强：Hugging Face、vLLM、PyTorch Lightning、torchvision 等几乎整条 AI 工具链都围绕它构建，换框架成本极高

**核心功能**

- 基于磁带式（tape-based）的反向模式自动求导，每跑一次前向就记录一遍计算过程，网络结构可在运行时任意改，调试时栈信息直接指到你写的那一行
- 张量可放在 CPU 或 GPU 上，底层接 Intel MKL、cuDNN、NCCL 等加速库，还自研了 GPU 显存分配器来减少碎片、支持更大模型
- Python 优先：不是给 C++ 框架套壳，新算子可以直接用 Python 或 NumPy/SciPy 写，需要性能时再用 C++/CUDA 扩展 API 无胶水代码接入

**适用场景**: 做深度学习研究和落地的工程师、研究员、学生。常见场景：用 torch.nn 搭 Transformer/CNN 训练模型、用 DataLoader 做数据管道、在单卡或多卡 GPU 上跑训练，再导出部署。Hugging Face 上的绝大多数模型默认就是 PyTorch 实现。

**竞品对比**: 主要对手是 Google 的 TensorFlow/JAX。TensorFlow 静态图部署成熟但在研究中用得少；JAX 在函数式、可组合变换（jit/vmap/grad）上更优雅、在 TPU 上更强，但生态和上手门槛不如 PyTorch。整体上 PyTorch 占学术和工业训练的主流。

**成熟度**: 非常成熟，生产可用。发布早已过 2.x 版本，有 Meta 等大厂和整个 AI 社区在维护，CI 状态公开在 hud.pytorch.org，文档、教程、社区规模都是顶级。

**趋势信号**: 大模型训练与推理持续升温，PyTorch 作为底座被反复访问；再加上近期版本持续补充编译加速（torch.compile）、FP8/低精度训练和对国产/异构 GPU（ROCm、Intel GPU、Jetson）的支持，热度自然长期居前。

## 趋势观察

这些项目看似分散，其实指向同一条线：AI 正在从“聊天”变成“干活的手”。MCP 把 IDA、Ghidra 接进 Claude Code，AI 能直接读二进制；给编程助手加画图技能，说明 Agent 的工具箱越来越专业。另一边，AirLLM 让 70B 模型塞进 4GB 显存，PyTorch 继续当训练底座，说明大家不再只堆大模型，而是拼谁能把模型跑得又小又稳。PS5 游戏重链接到 PC、阿波罗源码归档，则代表逆向工程和数字保存进入新阶段：老代码、闭源平台都在被重新打开。浏览器里的“间谍卫星”地球仪，把航班、船舶、卫星、地震全叠进 3D 地球，本地运行、语音操控，这是 OSINT 和可视化民主化。Rust 创作引擎把 AI 生成与手工编辑放同一条流程，说明创作者要的是可控，不是一键生成。总结一句：热点从“模型多大”转向“模型能接多少工具、跑多省、落多深”。开发者生态也在变：MCP 成接口标准，本地优先、开源可查、跨端复用成默认选项。新闻里 AI 热度还在，但真正被讨论的是权限、成本、数据主权和可复现性。这波趋势不会只停在演示，它会继续往专业软件、游戏、地理情报和创作工具里钻。
