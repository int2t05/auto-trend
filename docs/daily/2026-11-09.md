### [sherlock-project/sherlock](https://github.com/sherlock-project/sherlock)

 `Python` ⭐ +2,373 今日新增 · 104,736 总星数

> 一个命令行工具，输入用户名就并发去几百个社交网站探测该账号是否存在，输出命中清单。OSINT 和渗透测试做信息收集时的常用第一步。

**亮点**

- 核心取舍是"声明式规则 + 单次请求"：不做页面解析、不做登录态，判定全靠配置文件里的 errorType，准确率完全取决于社区对站点规则的维护质量
- 站点清单是纯数据文件，社区提 PR 加站点的门槛极低，这也是它能滚到几百个站点的原因

**核心功能**

- 把每个站点的探测规则写进 data.json：URL 模板、一个已知存在的示例用户名、以及判定"不存在"的方式（HTTP 状态码 / 页面里的错误文案 / 重定向后的最终 URL），新增站点只改配置不改代码
- 用 concurrent.futures 线程池并发发请求（--threads 可调），几百个站点几秒跑完；每个请求只做一次 GET 看状态码或关键字，不登录、不抓正文，所以开销极低
- 支持 --proxy 和 --tor（走 SOCKS）绕开限流，结果可导出 CSV / XLSX / JSON；--site 限定站点、--nsfw 排除成人站、--browse 直接打开命中的主页

**适用场景**: OSINT 调查员、记者核查账号、渗透测试的信息收集阶段，用它把目标用户名在 GitHub、Reddit、Instagram 等站的注册情况一次性铺开，再手工筛。普通用户也常用来查自己的用户名被哪些站占了。

**竞品对比**: 同领域有 maigret（Python，站点更多、能从已确认账号递归挖关联账号并出可视化报告）和 WhatsMyName（社区维护的站点清单 + 网页版）。sherlock 胜在知名度、装完即用的 CLI 体验和 10 万+ star 带来的教程覆盖，但站点数量和判定逻辑的更新不如 maigret 激进。

**成熟度**: 0.x 版本、无稳定 API 契约，但已被大量 OSINT 教程和安全工具链引用，日常可用；站点规则靠社区 PR，个别站点会因改版失效。

**趋势信号**: 没有明确的新版本或事件驱动，更像是 OSINT/隐私自查话题回暖把它推回趋势榜。

### [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot)

 `TypeScript` ⭐ +1,439 今日新增 · 18,750 总星数

> 开源的 Grok Bot 替代品：一个桌面聊天应用，通讯录里每个 bot 都是本机真实运行的 agent，各自有模型、电脑和已连接的应用。

**亮点**

- 产品形态上的取舍：不做“一个大助手”，做成通讯录。每个 bot 有独立人格、独立对话记忆、独立模型和独立电脑，会话之间互不污染，这比共用一个长上下文的单 agent 方案更接近真实分工。
- 数据在本地，凭证复用现有登录：既不用重新注册，也不用把 API key 交给第三方，这一点直接决定了它能否作为那些闭源产品的替代。
- 安全边界由运行时按平台认证，并不只是一个开关：宿主控制只在 macOS 和 Ubuntu Xorg 开放，Wayland 默认关闭，说明权限模型被明确设计成“默认不给”。

**核心功能**

- 本地 harness 服务监听 127.0.0.1，统一托管所有 agent 子进程；直接调用你机器上已登录的 claude / codex / grok CLI，不经过代理，也不需要注册新账号；在设置里可以把引擎指向自定义的 CLI 二进制。
- 每个 bot 可选择三种执行环境：云端 Linux 桌面、隔离的本地 VM，或者在明确同意后使用宿主电脑本身；其中宿主控制按平台逐项认证，在 Ubuntu Wayland 下直接禁用（issue #345 未解决），在 Xorg 下可用。
- 通过 Composio 连接 500+ 应用，涉及敏感操作时会弹出审批卡片，由你放行；所有对话记录、密钥和事件都保存在 ~/.openmausbot 本地目录，不存云端。

**适用场景**: 适合已经订阅 Claude / ChatGPT / Grok、想要“一个 bot 管一件事”的人：比如让一个 bot 盯着邮件，让另一个 bot 运行脚本跑 CI，再由第三个 bot 整理文档，它们各自使用各自登录的账号。也适合不想把数据交给 Meta、OpenAI、Manus 云端机器的开发者和隐私敏感团队。

**竞品对比**: 直接竞争对象是 xAI 的 Grok Bot、Meta Muse、OpenAI dots、Manus 的 Cue；这些全是闭源产品，只支持单一模型，电脑和数据都在厂商那边。OpenMausBot 的差异是支持任意模型混搭、使用你自己的机器和订阅、数据留在本地，代价是要自己安装 Electron 应用并配置 CLI。

**成熟度**: 有 macOS 签名公证的 dmg、Windows 安装包和 Ubuntu deb，三平台都在发布，但 Wayland 上的宿主控制还卡在 issue #345，平台相关功能明显仍在逐个补齐，适合尝鲜和小规模自用，团队核心流程慎用。

**趋势信号**: 2026 年头七周，Grok Bot、Meta Muse、OpenAI dots、Cue by Manus 接连发布，全是闭源且数据留在厂商云端的个人 agent 产品，社区正在集体寻找开源替代，这个项目正好填补了这个空缺。

### [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)

 `Rust` ⭐ +815 今日新增 · 47,885 总星数

> Vercel Labs 出的 Rust 命令行浏览器，让 AI Agent 一次一条 shell 命令地开网页、读页面、点元素。页面以无障碍树文本返回，元素带 @e1 引用，省 token 也好定位。

**亮点**

- 点击失败会真的报错，而不是返回成功：目标被遮罩、禁用、在视口外、被 cookie 弹窗盖住都会失败，逼 Agent 先处理遮挡再重新 snapshot，避免 Agent 在假成功上继续瞎走
- 默认浏览器是 Chrome for Testing，但可以用 --engine 换成 Lightpanda、Obscura，用 --cdp / --auto-connect 接管已有的 Chrome，或转到 Browserbase、Browserless、Kernel 等云浏览器；同一个 CLI 接口覆盖本地和云端

**核心功能**

- snapshot 把页面转成无障碍树（浏览器给屏幕阅读器用的语义结构），每个可交互元素给一个 @e1 这样的引用；Agent 只需读纯文本再点引用，不用解析整页 HTML，也不用截图做视觉定位
- 后台常驻一个 daemon（后台进程），通过 Chrome DevTools Protocol 控制浏览器；浏览器在命令之间不关闭，所以每一步只是发一条短命令，省掉每次冷启浏览器的几秒；空闲一小时自动存状态退出，每个 --session 独立一个 daemon 和浏览器
- skills 子命令随 CLI 版本一起发布，装进 Agent 的只是一个瘦桩，真正指令要跑 agent-browser skills get core 现取，保证 Agent 看到的命令说明和本机装的版本一致，不会因为提示词过期而调错参数

**适用场景**: 写代码的 Agent（Claude Code、Cursor 之类）需要通过 shell 跑端到端验证、登录后台抓数据、点表单提交、复现前端 bug；也适合 QA 把手工点击流程写成脚本，用 diff 命令对比改版前后页面。

**竞品对比**: 对比 Playwright/Puppeteer：那两个是给人写代码的完整 API，Agent 用要么装 Playwright MCP 包装，要么自己生成代码；agent-browser 直接把动作做成一条条 shell 命令 + 文本快照，Agent 不需要写代码。对比 browser-use、Stagehand：那两家是 Python/TS 库内嵌 LLM 循环，agent-browser 是语言无关的 CLI + daemon，任何能跑 shell 的 Agent 都能接。

**成熟度**: Vercel Labs 实验项目，文档站和 macOS/Linux/Windows 原生二进制都齐了，但命令集和 skills 仍在快速变，接入前最好锁版本。

**趋势信号**: 编码 Agent 普遍通过 shell 调外部工具、MCP 成为标准接入口，加上 WebMCP 这类让网页直接暴露工具给 Agent 的提案正在推，Vercel 顺势把浏览器压成一条命令并自带分发技能，赶上了 Agent 需要真浏览器这一步。

### [anthropics/skills](https://github.com/anthropics/skills)

 `Python` ⭐ +792 今日新增 · 189,921 总星数

> Anthropic 把 Claude 的 Agent Skills 机制开源：每个技能就是一个装有 SKILL.md 的文件夹，Claude 按需加载。它还放出了自家产品在用的 docx/pdf/pptx/xlsx 文档技能源码，让开发者照着写自己的。

**亮点**

**核心功能**

- 技能就是一个文件夹 + 一个 SKILL.md，YAML frontmatter 只要求 name 和 description 两个字段，正文写指令、示例和规范；不用写代码、不用注册函数，Claude 匹配到描述才去读正文，平时不占上下文

- 把整个仓库注册成 Claude Code 插件市场（/plugin marketplace add anthropics/skills），一条命令装 document-skills 或 example-skills；同时 ./spec 目录给出 Agent Skills 规范，./template 给空白模板

**适用场景**: 想让 Claude 按公司品牌规范出 PPT/Word、按固定流程跑数据分析的企业团队；以及在 Claude Code 里把重复操作（测试 Web 应用、生成 MCP server）固化成可复用技能的开发者。

**竞品对比**: 和 MCP 不冲突：MCP 给模型接工具和数据源，Skills 给模型灌流程和领域知识，官方文档也把两者并列。比起 OpenAI 的 GPTs/自定义指令或 Cursor rules，最大差别是同一份技能文件能跨产品复用，而且规范开放到 agentskills.io，别人也能实现。

**成熟度**: 参考/示例仓库，没有版本号，官方明确写『仅供演示和教育用途』，接口和目录结构可能变；但四个文档技能是 Claude 生产环境在用的代码，参考价值高，自己上生产前必须逐项测。

**趋势信号**: Anthropic 正把 Skills 从自家功能推成开放标准（agentskills.io），同时接进 Claude Code 插件市场，Notion 等伙伴开始出技能包，生态刚起量所以关注度集中爆发。

### [ranxianglei/billion-context](https://github.com/ranxianglei/billion-context)

 `TypeScript` ⭐ +460 今日新增 · 5,388 总星数

> 一个插在 AI 编程 agent 和模型 API 之间的上下文压缩插件：把已消费的对话压成分层摘要，让一个会话跑几十天、几百亿 token 也不爆窗口，同时省约 5 倍 token。

**亮点**

- README 挂了一篇自写的论文，给的是真生产数据：4.5 个月、三台机器、17.4 万次模型调用、187.6 亿输入 token，20 万 token 窗口零溢出，最长单会话 8584–12049 次调用
- 第三方 benchmark（1500 条，LongMemEval-S / ContextBench / MemoryAgentBench）里跟 full context 和三种 RAG（bm25、embedding、embedding-rerank）硬碰：ContextBench 第一，LongMemEval-S 比最强 RAG 高 16.6%，1.48M token 压测 100% 存活

**核心功能**

- 直接改写 Anthropic/OpenAI 的流式返回（SSE），插在 agent 和模型 API 中间做代理，agent 侧零改动，npm 装完配个 base_url 就能用
- 训练无关的分层增量压缩：模型自己判断哪些内容该压、什么时候压，逐层生成高保真摘要，不是按长度硬截断，压缩结果可回溯
- 专门保前缀缓存：靠稳定的前缀让会话保持 95–97% 的 prefix-cache 命中率，压缩本身只吃掉 ≤2% 的 token，避免省了上下文却把缓存优惠全弄丢

**适用场景**: 用 Claude Code、Codex CLI、Gemini CLI 这类工具长时间连续开发的程序员。典型场景是一个大仓库重构或连续几天调试，不想每几小时就被迫开新会话丢上下文，也不想被 token 账单打穿。

**竞品对比**: 主要对手是各宿主自带的 summarizer 和 RAG 记忆方案。最大差异：RAG 是检索回填、容易丢细节且打断前缀缓存，它是原地分层压缩，保留缓存命中率，且压缩时机交给模型判断而非固定阈值。

**成熟度**: 版本 0.1.x，属于早期，但已有近 19B token 的生产规模数据和第三方评测，文档算完整，API 仍可能变。

**趋势信号**: 2025 年 Claude Code / Codex CLI 一类长会话 agent 成为主流工作方式，上下文窗口和 token 成本变成真痛点，而 prefix cache 又是厂商降费的核心机制，这个项目正好卡在'压缩上下文还能不破坏缓存'这个缝上，README 一口气列了 30 多个 CLI 适配也是社区自发扩散的信号。

### [dsx-ai-factory/nvke](https://github.com/dsx-ai-factory/nvke)

 `Go` ⭐ +345 今日新增 · 938 总星数

> NVKE 让平台团队在自己的 GPU 裸金属机器上运行一套类似 EKS 的管理平面，按需为客户创建独立的 Kubernetes 集群，每个集群都有自己的控制面、etcd 和节点池。

**亮点**

- 把"构建"和"部署"切开：节点镜像和组件由配套项目 NVKR 用固定输入构建并签名，产出物存进 registry，NVKE 只负责部署，因此可追溯性靠构建链保证，而不是靠运行时
- 二进制拆成 9 个（agent、controller、nvkectl、management-engine、tenant-api、operator-api 等），把租户侧 API 和运维侧 API 分成两个进程，方便划出多租户的安全边界

**核心功能**

- 走 Cluster API + 自研的 CAPNICo provider：管理平面不直接操作机器，而是向 NVIDIA Infra Controller \(NICo\) 申请裸金属服务器，所申请的服务器装好系统后直接成为工作集群的节点
- 节点加入集群前必须先用主板 TPM 做 SPIFFE/SPIRE 认证，验证通过后才下发 join 凭证；因为裸金属没有云厂商的 instance identity，只能靠硬件证明自己的身份
- `nvkectl` 先用一个临时的 seed 集群自举出管理集群，之后由管理平面持续按需生产客户集群，官方把它定位成"Kubernetes 集群工厂"，而非某个发行版

**适用场景**: 适合自建 GPU 机房的 AI 基础设施团队和平台工程团队：买了一批 8 卡机，要给内部算法组或外部客户按需开隔离的 K8s 集群跑训练、推理。想先评估的人可以用本地 quickstart，在模拟机器上跑通，不需要真 GPU。

**竞品对比**: 同类的自建裸金属 K8s 方案有 Cluster API + Metal3、Canonical MAAS + Charmed Kubernetes、SUSE Rancher/RKE2，NVIDIA 自己还有 BCM。最大差别是 NVKE 只认 NICo 一家基础设施 provider，装机、镜像、节点认证全绑在 NVIDIA 生态里，不是通用方案。

**成熟度**: Preview 阶段，官方明确不建议上生产：默认关闭 API 认证并使用明文 HTTP，管理面不能自升级、没有备份恢复流程，API 和行为还会变。

**趋势信号**: 云上 GPU 又贵又约不到，团队开始自己买整机，想要一个"私有版 EKS"来把闲置的 8 卡机管起来；加上本地 quickstart 不用真 GPU 就能跑通，降低了围观和上手门槛。

### [google-deepmind/mujoco](https://github.com/google-deepmind/mujoco)

 `C++` ⭐ +41 今日新增 · 16,571 总星数

> DeepMind 维护的通用物理引擎，专攻多关节机器人和接触仿真；MJX 版本让它能上 GPU/TPU 并行训练，赶上具身智能热潮。

**亮点**

- 模型用 MJCF（自家 XML 格式）描述，加载时编译成扁平的 C 结构体数组；仿真器只读这些预分配数组，所以 C API 轻、Python/Unity/WASM 都能薄封装。
- 同一套物理模型同时有原生 C 版和 JAX 版 MJX，CPU 上跑实时仿真，GPU/TPU 上跑万级并行环境，不用换模型格式。

**核心功能**

- C 核心 + XML 编译器预分配所有运行时内存，仿真循环里不动态分配，单步计算快且可预测，适合实时控制。
- MJX 用 JAX 重写物理步，能在 GPU/TPU 上批量并行 rollout，并支持对物理仿真自动求导，直接用解析梯度训练策略。
- 接触模型用软约束和凸优化求解接触力，通过 solref/solimp 参数调接触软硬，能模拟足式机器人落地、抓取这类复杂接触。

**适用场景**: 机器人学习和控制研究者用 Python/dm_control 搭足式、机械臂、人形环境跑强化学习；生物力学和动画团队用它做关节受力与接触仿真。

**竞品对比**: 和 PyBullet 比，MuJoCo 的接触求解更稳更准，MJCF 生态成熟；和 NVIDIA Isaac Sim/Isaac Lab 比，它不拼照片级渲染和大场景，胜在轻量、CPU 单核快、MJX 可微。

**成熟度**: 生产可用，3.x 按月发版、文档和 Python/Unity/WASM 绑定齐全，机器人学习社区大量使用；MJX 部分仍在快速迭代。

**趋势信号**: 具身智能和人形机器人升温，大家要在 GPU 上批量跑物理仿真训练 VLA/强化学习策略，MJX 正好把 MuJoCo 从 CPU 仿真器变成可微并行训练后端。

### [anthropics/claude-quickstarts](https://github.com/anthropics/claude-quickstarts)

 `Python` ⭐ +32 今日新增 · 19,594 总星数

> Anthropic 官方示例库，覆盖电脑操作、浏览器自动化、托管 Agent，教开发者把 Claude API 拼成能部署的应用。

**亮点**

- Daily Brief 把「源读不到」和「今天没内容」分开报：每个来源单独存书签，再用账本防重复推送，抓取失败的源明确标成不可读，不假装平静——这是无人值守定时任务最容易翻车的地方。
- MCP Server 用一个 `wait_for_idle` 工具把会话事件流压成一次请求/响应，Claude Desktop 这种只会一问一答的客户端也能驱动长任务；再加 agent 白名单，限制拿到 bearer token 的人能碰哪些 agent。

**核心功能**

- 电脑操作和浏览器的「最小示例」都不套现成库：直接手写 VNC（RFB 远程桌面协议）和 CDP（Chrome 调试协议）驱动，管一个桌面或一个 Chromium 标签页就能跑，还附带一个不调模型的离线测试脚本，用来单独验证驱动逻辑。
- 托管 Agent 的整套部署写成文件，用 `ant apply` 一次下发：agent、运行环境、两个记忆存储、凭证 vault、cron 定时任务。偏好存储设成只读，状态存储设成读写，两个分开。
- 知识库示例把一批文档一次性提取、消解冲突、合并成带版本号的记忆 wiki，每条事实留出处；之后反复回答分析师提问时比每次翻原始文档便宜。
- computer-use 最佳实践那份示例把省钱的招数摊开写：显式工具定义、图片按需裁剪缩放、prompt caching、服务端压缩上下文、批量工具调用、沙箱 shell、轨迹录制。

**适用场景**: 想把 Claude 接进 Slack、Linear、Sentry 的团队可以直接抄这几个桥接示例；在评估电脑操作、浏览器自动化的开发者拿它当参考实现。典型场景是运维排障、金融数据分析、文档审阅这类需要看屏幕或翻一堆文件的活。

**竞品对比**: 对比 OpenAI Cookbook、LangChain/LangGraph 的模板，最大差别是这些示例深度依赖 Claude 的独有能力：Managed Agents 会话、event_deltas 流式、vault 按位置注入凭证、prompt caching，换成别家框架没法照搬。

**成熟度**: 官方维护、1.9 万 star，但定位就是示例代码，部分项目 README 明说不是生产代码；工具集接口带日期（如 computer_toolset_20260801），说明还会变，接口可能随时调整。

**趋势信号**: Anthropic 刚推 Managed Agents（托管 Agent 会话）和 2026-08 版 computer/browser toolset，配套发了电脑操作最佳实践博客，开发者涌进来找能直接跑的参考实现。

## 趋势观察

这批项目基本围绕一件事：把 AI Agent 从演示做成能干活的软件。 先看工具层。Vercel 出了 Rust 写的命令行浏览器，让 agent 一条命令开网页、读无障碍树，省 token 也好点按钮。那个上下文压缩插件更直接，把对话压成分层摘要，一个会话跑几十天、几百亿 token 不爆窗口，还能省五倍左右 token。加上 Anthropic 开源的 Agent Skills，技能就是装 SKILL.md 的文件夹，按需加载，连自家在用的 docx、pdf、pptx、xlsx 源码都放出来了。Agent 现在有了手脚、有了记忆、有了技能包。 再看底座。NVKE 让平台团队在裸金属 GPU 上开 Kubernetes 管理平面，给客户一人一套独立集群，控制面、etcd、节点池都分开。DeepMind 的 MuJoCo 配 MJX 上 GPU/TPU 并行，冲着具身智能去。算力和物理仿真都在往 agent 训练上靠。 应用端也有意思。开源的 Grok Bot 替代品，通讯录里每个 bot 都是本机真跑的 agent，各有模型、电脑和连接的应用。Meta 把用了八年、支撑 13000+ 应用的设计系统开源，150 多个组件，命令行工具直接让 AI 编程助手读文档。 共同的信号很清楚。大厂在拿开源换开发者，Anthropic、Meta、Vercel、DeepMind 都是这个套路。开源的东西越来越“给 AI 读”：文档、技能、无障碍树，全是给 agent 准备的接口。Agent 不再是聊天框，是要装进系统、接管工具、能长跑不歇的那种东西。谁先把工具链和记忆做扎实，谁就先落地。
