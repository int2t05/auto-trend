### [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)

 `Python` ⭐ +3,856 今日新增 · 57,891 总星数

> 把 Claude Code 变成求职流水线：抓招聘网站、评岗位匹配度、用 LaTeX 生成定制简历和求职信、准备面试。全在本机跑，fork 下来就是自己的。

**亮点**

- 整个求职流程落在自己的 git 仓库里，简历是 LaTeX 源码，每投一个岗位的改动都能 diff 出来；对比 SaaS 简历工具是上传 docx、改完就丢
- 作者把'fork 是公开的'这个坑写进 README 显眼处：`/setup` 会把姓名、联系方式、薪资期望写进 tracked 文件，所以私人使用应该建私有仓库、把原仓库挂成 upstream，而不是直接 fork

**核心功能**

- 每个招聘门户封成一个独立小 CLI（`.agents/skills/*/cli/` 下用 Bun + TypeScript 写），`install_portal_clis.py` 自动扫描目录批量 `bun install`，新增门户不用改核心；带 install 阶段生命周期脚本的包会被跳过并报告，防供应链投毒
- 起草-评审双代理：先出定制 CV 和求职信，再由 reviewer agent 按固定评估标准挑毛病、改一轮。CV 用 lualatex 编译，求职信走 xelatex，因为 `cover.cls` 依赖 fontspec
- `/apply` 里带 ATS 可解析性检查：用 pypdf 抽 PDF 文本（没有就退回 pdftotext，再没有就降级成人工看关键词），确认简历投进去机器读得到关键词
- `/scrape` 跨多个门户抓岗位后去重、按 fit 打分排序；岗位太多时用 `/rank` 批量打分成 shortlist，避免一条条看
- `/setup` 支持三种建档方式，能直接读 `documents/` 里的 CV PDF、LinkedIn 导出、证书；文档模式幂等，资料越加越多可以反复重跑

**适用场景**: 适合正在大量投岗的求职者，尤其是技术岗和转行者：每天刷 Jobindex、Jobnet 这类门户，一个岗位改一版简历和求职信太费时间。默认门户是丹麦市场，换成本地招聘站要自己写或换 skill；核心的匹配评估和写作流程跟语言、国家无关。

**竞品对比**: 和 Simplify、Teal、Jobscan、Rezi 这些在线求职/简历工具比，最大差别是数据不出本机、流程可改源码。那些 SaaS 主打一键自动填表和 ATS 关键词打分，这个是把抓取、匹配、写、评审整条链交给 Claude Code 的代理来跑，简历成品是能编译的 LaTeX。

**成熟度**: 能用但偏早期：有 CI、SETUP.md/AGENTS.md 文档齐全、有社区 fork 和演示视频，不过基本是单人维护，命令和目录结构还在演进，不建议当稳定依赖。

**趋势信号**: Claude Code 的 skills/命令工作流这一波正热，加上作者'69 份定制申请、20 次一面、最后靠它拿到 AI 工程师 offer'的真实背书和社区视频演示，把'AI 求职'这个刚需场景点着了。

### [stablyai/orca](https://github.com/stablyai/orca)

 `TypeScript` ⭐ +1,590 今日新增 · 98,531 总星数

> 把 Claude Code、Codex 等命令行编程 agent 装进一个桌面 IDE，每个跑在独立 git worktree 里并行，结果对比后择优合并，手机上也能远程盯进度。用你自己的订阅账号跑，不用 API key。

**亮点**

- 把「盯着 agent」这件事从桌面解绑：移动端 app 不做编辑，只做完成通知 + 发后续指令，等于给长任务加了个遥控器
- Agent 能通过 CLI 操作 Orca 自己的 GUI（snapshot/click/fill），本质是把 Electron 应用本身变成一个可被 agent 调用的工具，绕开只靠终端交互的限制

**核心功能**

- 隔离用 git worktree 而不是 Docker：一条 prompt 可同时分发给 5 个 agent，每个在独立 worktree 改代码，最后并排看 diff、merge 赢的那个，省掉容器启动和依赖重装
- 内置 Ghostty 级终端，WebGL 渲染，支持无限分屏，scrollback 重启后不丢；SSH worktree 让 agent 跑在远端大机器上，本地只做 UI，带自动重连和端口转发
- Design Mode：在真实 Chromium 窗口里点任意 UI 元素，自动抓 HTML、CSS 和裁好的截图塞进 agent prompt；CLI 反向提供 snapshot/click/fill，让 agent 反过来操作 Orca 界面

**适用场景**: 适合同时养着好几个 CLI agent 的独立开发者和小团队：一个人开 4-5 个 Claude Code / Codex 任务并行跑重构、修 bug、写测试，用手机推送看哪个先跑完。也适合把重活丢到 SSH 远程服务器上跑，本地笔记本只留界面。

**竞品对比**: 对比 Conductor、Crystal、Claude Squad 这类 worktree 编排工具，以及 Cursor/Windsurf 这类单 agent IDE，最大差异是不绑定模型厂商（任何终端里能跑的 CLI agent 都行），并且自带终端 + 移动端 + 远程运行时，是一整套而不是一个插件。

**成熟度**: 有 macOS/Windows/Linux 三平台正式版、iOS 上架、Discord 社区和日更 changelog，但作者自己说功能列表永远追不上发布速度，API 和界面仍在高频变动。

**趋势信号**: Claude Code、Codex CLI、OpenCode 等多个命令行 agent 同时爆发，开发者普遍在并行跑好几个，缺一个统一调度台；同时它支持直接用个人订阅额度跑 agent，绕开 API 按 token 计费，正好卡在这个时间点。

### [anomalyco/opencode](https://github.com/anomalyco/opencode)

 `TypeScript` ⭐ +1,311 今日新增 · 218,005 总星数

> OpenCode 是一个开源、不绑定模型厂商的终端 AI 编码代理，可在命令行里完成改代码、跑命令、查代码库等任务；v2 和桌面版 beta 刚刚推出，成为 Claude Code、Codex CLI 之外的开源替代。

**亮点**

- 把代理拆成“只读计划”和“可写执行”两种模式，通过切换代理来限制风险，而不是靠 prompt 约束模型自觉，这是权限层面的硬限制。
- TUI 不做成单体，而是作为本地服务的客户端，为桌面 App、远程连接和多前端复用保留了扩展空间。

**核心功能**

- 客户端/服务端分离：核心以本地服务形式运行，终端 TUI 只是一个前端，因此可以接桌面 App，也能从其他终端或远程接入同一个会话。
- 内置两个代理并做权限隔离：build 有全部权限；plan 只读，默认拒绝改文件，执行 bash 前先征求同意，适合先读陌生代码库再动手。
- 接入真实语言服务器（LSP）获取类型错误和诊断信息，而不只是用 grep 搜文本，改完 Java、TS 这类强类型项目时能自己发现编译错误。
- 安装方式覆盖 npm、bun、Homebrew、pacman、mise、Nix，并支持 XDG 目录和自定义安装路径，方便在 CI 和容器里固定版本。

**适用场景**: 适合习惯在终端里工作的后端、全栈工程师，以及想自选模型（本地模型或公司内部网关）而不被厂商锁定的团队；典型流程是：用 /plan 读代码库 → 切到 /build 改代码 → 跑测试。

**竞品对比**: 与 Claude Code（闭源且只跑 Anthropic 模型）、OpenAI Codex CLI、Gemini CLI 相比，最大差异是模型无关；与 Aider、Cline 相比，它更像一个完整的代理运行时（含 LSP、子代理、权限模型），而不是单纯的代码补丁工具。

**成熟度**: 已到 v2 并有多种包管理器分发和 24 种语言文档，但桌面 App 仍标 BETA，接口和配置格式仍有变动风险。

**趋势信号**: 2025 年 Claude Code、Codex CLI、Gemini CLI 把“终端编码代理”变成主流形态，社区对开源、可换模型的替代品需求集中爆发；OpenCode v2 和桌面版 beta 恰好在这个时间点发布。

### [Comfy-Org/ComfyUI](https://github.com/Comfy-Org/ComfyUI)

 `Python` ⭐ +1,011 今日新增 · 139,948 总星数

> 开源的节点式扩散模型执行引擎，把图像、视频、3D、音频的生成流程拆成节点连线，在本地跑。新模型发布当天基本就能用上。

**亮点**

- 节点图不只是界面，它本身就是执行计划：引擎先做依赖分析再调度，能跳过没变的节点，这和写脚本一次性跑完推理是两回事
- 开源模型和闭源模型混在同一张图里：Partner Nodes 直接调 Nano Banana、Seedance、Hunyuan3D 这些闭源 API，和本地模型串着用
- App Mode 把复杂的节点图包成一个只有几个输入框的简易界面，给不懂节点的人用

**核心功能**

- 异步权重流式加载：模型权重分块从内存或硬盘送进显存，边算边加载，4GB 显存加 8GB 内存就能跑很大的视频生成模型
- 按图做部分重跑：改一个参数只重算下游受影响的节点，上游结果直接复用，不用整条流程从头跑一遍
- 工作流存成 JSON，生成的图片和视频里还内嵌了完整图结构和随机种子，文件拖回界面就能复现同一张图
- 模型加载拆得很细：checkpoint、扩散模型、VAE、文本编码器、LoRA、ControlNet、放大器可以分开装、分开换

**适用场景**: 视觉创作者和 AI 小工作室用来做电商图、短视频、游戏美术，把一套调好的生成流水线反复复用；开发者用它的本地 HTTP API 把生成能力接进自己的产品后端。

**竞品对比**: 对比 Automatic1111 WebUI（表单式、基本只做图像、更新慢）和 HuggingFace Diffusers（写代码的 Python 库），ComfyUI 的差异是节点图加显存调度，小显存也能跑视频模型，而且新模型适配几乎最快。

**成熟度**: 生产可用：版本 0.7.x、每周发版，桌面版和付费云都已上线，有大量商业工作室在用；但主版本更新经常把第三方自定义节点搞坏。

**趋势信号**: Flux.2、Qwen-Image、Wan 2.2、HunyuanVideo 1.5 这批开源模型近期密集发布，ComfyUI 基本是第一个能跑起来的工作流，每出一个新模型就带一波 star。

### [akitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory)

 `Rust` ⭐ +666 今日新增 · 11,505 总星数

> 给 AI 编程 Agent 做长期记忆的开源工具：用 hook 静默记录会话，存成 git 里的 markdown wiki，让 Claude Code、Codex、Cursor 等 20 多个 Agent 共享同一份上下文并互相交接。

**亮点**

- 把“记忆”做成纯文件系统加 git 版本链：删了也能 restore-page 找回，人工可以直接用 grep 或 Obsidian 改，宣称的写入上限约 700/s 是实测出来的而不是估的
- 可选的“dream”后台整理是唯一用 LLM 的路径，默认关闭，只在空闲时把一簇冷笔记重写成整页，人一回来就取消，且必须先通过 recall eval 才可能变成默认行为

**核心功能**

- 真相源是 git 仓库里的普通 .md 文件，数据库只是可随时重建的派生索引，因此不需要维护向量库；检索时把全文、实体、链接和可选向量融合成一个排序结果
- 跨 Agent 交接走带 owner 的类型化 handoff 协议，每次交接只能被领取一次；`ai-memory run` 还能给下一个 Agent 一份临时的本地投影，让它读到上一个 Agent 的可见历史，服务端只收 harness 名和 session id，不收 transcript 路径和内容
- 默认零 LLM 调用：生命周期 hook 采集到的是清洗过的结构化 observation，会话结束时汇总成 wiki 页；记忆按访问加权衰减（打开、搜索、链接命中都算使用），冷数据压缩成文件路径、错误码、决策这类硬事实，近重复合并、疑似矛盾打标，全程不调 API

**适用场景**: 适合同时用 Claude Code、Codex、Cursor 等多个编程 Agent 的开发者，或需要在台式机和笔记本之间接力、把会话交给同事继续的人。典型场景是一个任务做到一半换工具，下一个 Agent 不用重新问架构、试过的失败方案和待定问题。

**竞品对比**: 对比 Claude Code 自带 memory、Cursor memories：那些记忆锁在单一工具和单台机器上，换 Agent 就断。对比 mem0、Letta、Zep 这类 agent memory 框架：它们走抽取原子事实加向量库的路线，每条都要模型参与；ai-memory 反过来，默认不烧 token，形态是你能直接读的 markdown。

**成熟度**: 已有正式 release、CI 校验的支持矩阵和 ARCHITECTURE 文档，自带多用户鉴权和审计日志；但迭代很快，原生 Windows 仍是实验状态，属于可自用但生产部署要跟版本。

**趋势信号**: 2025 年底到 2026 年初，Claude Code、Codex、Cursor、Gemini CLI 同时流行，“换 Agent 就丢上下文”成了真实痛点；作者 Fabio Akita 本身有大量受众，配合新版本发布和网站上线，一天冲到 666 星。

### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +606 今日新增 · 55,367 总星数

> 把 Blender、LibreOffice、CAD、Calibre 等软件包成命令行工具并输出 JSON，让 Claude Code、Cursor 这类 Agent 直接调 shell 操作真实软件，不用截图点鼠标。

**亮点**

- 路线选择很明确：不做 GUI 截图点击（computer-use），而是给每个软件补一层命令行壳。理由是对 Agent 来说 shell + JSON 比像素更省 token、更可复现、更好写测试
- 项目本体其实是个注册表 + 贡献流程，不是一个库。CLI-Hub 收社区 PR，每个 harness 要过单测和真实软件的 E2E 才合，2,461 个测试是这么攒出来的

**核心功能**

- 每个软件的 harness 是一个 Click 写的 Python CLI，同一份代码同时输出 JSON（给 Agent 解析）和人类可读文本（给人调试），避免维护两套接口
- 分发单位是 SKILL.md：`npx skills add HKUDS/CLI-Anything --skill &lt;name&gt; -g -y` 一行把技能装进 Claude Code / Cursor 的 skill 目录，再配 `pip install cli-anything-hub` + `cli-hub install &lt;name&gt;` 管版本
- 带预览闭环：Agent 执行命令生成产物（CAD、3D 场景、图表、字幕）后，能读回预览图或文件再改，形成 preview → 执行 → 检查的 trajectory 循环
- 安全上做了取舍：XML/SVG/ODF/MusicXML 等不可信输入统一走 defusedxml，Sketch 的 token 文件防路径穿越和符号链接逃逸，因为 Agent 读到的内容本身可能是恶意的

**适用场景**: 用 Claude Code / Cursor 的开发者，想让 Agent 真的产出 CAD 图纸、3D 场景、视频字幕、图表，而不是只改代码文件 自动化团队要批量驱动 LibreOffice 转文档、Calibre 管书库元数据、Joplin/Obsidian 同步笔记、Rekordbox 改曲库，走脚本比开 GUI 稳

**竞品对比**: 对比 MCP server（把软件包成 MCP 工具）和 Open Interpreter / computer-use 那类截图点击方案：MCP 要每个客户端支持协议、工具描述占上下文，computer-use 慢且易错；CLI-Anything 走最原始的 stdin/stdout，任何能跑 shell 的 Agent 都能用。代价是每个软件都得有人写一遍壳。

**成熟度**: 未到 1.0，核心价值在社区注册表，几十个 harness 质量参差，部分有单测+真实软件 E2E、部分只是薄封装，选之前要看具体那个 CLI 的测试和最近提交。

**趋势信号**: Agent 客户端（Claude Code、Cursor、OpenClaw 等）已普及，缺的是'能给 Agent 用的软件接口'，项目刚好踩中这个空档；加上 arXiv 技术报告、CLI-Hub 注册表上线和 18 个 demo 集中放出，一天涨 600 星。

### [ruvnet/ruflo](https://github.com/ruvnet/ruflo)

 `TypeScript` ⭐ +564 今日新增 · 77,324 总星数

> Ruflo 是套在 Claude Code / Codex 外面的 agent 执行层（harness），给它们加 swarm 编排、跨会话记忆和多机联邦。现在火是因为 Claude Code 刚上插件市场，它第一时间接入并改名抢「原始 harness」名号。

**亮点**

- 定位是 harness 不是框架：不自建 agent 循环，寄生在 Claude Code / Codex 上做插件和 MCP 扩展，换模型或换宿主工具时逻辑不用重写
- Swarm 路由是闭环的：Router → Swarm → Agents → Memory，做完的任务经验回灌给路由器当下一轮的派活依据，不是一次性编排

**核心功能**

- 以 MCP 服务器形式把 300+ 工具、20+ CLI 命令暴露给 Claude Code 和 Codex，装完插件后靠 hooks 在后台自动路由任务，用户照常写代码不用学新命令
- 记忆层用 RuVector 做本地向量检索，配合「轨迹对比学习」——把同一条任务的成功/失败执行路径做对比微调，官方说检索和对比更新这一步不需要调 LLM
- 联邦（federation）模式：不同机器上的 agent 能互相通信协作，但带权限和数据隔离，目的是多机 swarm 时不把数据泄出去

**适用场景**: 已经在用 Claude Code 或 Codex 的开发者和小团队，想让多个 agent 分工跑长任务、跨会话记住项目上下文，或者企业想给 agent 加权限护栏和审计。不写代码的人基本用不上。
