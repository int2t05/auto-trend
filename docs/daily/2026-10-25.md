### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,264 今日新增 · 44,958 总星数

> 把编码 Agent 变成安全审计员：六阶段流程、覆盖台账、独立证伪复核，产出可机器校验的漏洞记录。

**亮点**

- 用 coverage-ledger.json 把「查过哪些入口」变成可校验的数据，而不是听模型自己说查完了——审计里最容易糊弄的就是覆盖度，这一步直接堵住
- 发现者和验证者强制分离，材料级替换还要再过一次独立验证，照搬人工渗透测试的双人复核；并且明确承认「不跑就证明不了」，没有 OS 级沙箱（断网、白名单环境、资源限额）就把结论自动降级为 needs_validation

**核心功能**

- 审计拆成六阶段（侦察→按覆盖清单派 hunter→候选验证→结构化输出→独立复核→出报告），中间产物是 architecture.md、coverage-ledger.json、findings.json，用 JSON Schema + 两个零依赖 Node 脚本卡格式
- 每个候选漏洞交给一个没参与发现的 agent 专门去证伪，结论分三档：confirmed 必须有完整源码链路和可复现结果，needs_validation 必须写清未解决的具体事实且不给严重级别，rejected 记录被证伪的候选
- 按目标类型准备了 10+ 套攻击面提示词——内存安全/二进制、LLM 提示注入与工具调用、HTTP 请求走私与鉴权、前端 DOM 与 postMessage、供应链与发布签名、云与 IaC、RPC 与消息队列、资源耗尽、多租户数据隔离、桌面/移动本地 IPC，侦察阶段先分类再派对应的 hunter
- coverage-ledger 当工作队列用，同一仓库重复跑是累加的：拿上次的台账找缺口、只重验证改动过的源码，不把过期或没结论的条目算成已覆盖

**适用场景**: 安全工程师和研发在发版前对自家仓库做一轮审计；开源维护者接手陌生代码库想快速摸清信任边界；安全研究团队拿它当批量跑仓库的起点，替代纯人工的渗透测试前筛。

**竞品对比**: 和 Semgrep、CodeQL、Snyk 这类规则+数据流扫描器不是一回事：它没有扫描引擎，靠 LLM 读代码加沙箱实跑验证，漏报低但慢且贵。对比直接对 Claude/Codex 说「帮我审计」，多了覆盖台账和独立证伪两层约束，代价同样明显。

**成熟度**: 早期项目：主体是一堆 Markdown 提示词加两个校验脚本，没有版本号，刚开源就被博客带火；方法论成熟但结果强依赖模型能力和沙箱配置，建议先拿小仓库和低风险目标试跑。

**趋势信号**: Cloudflare 在《Build your own vulnerability harness》博客里点名这就是其内部漏洞挖掘系统演化前的单仓库原型并开源，同时 skills.sh 这类 Agent Skill 分发渠道正在流行，一天涨两千多星。

### [NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell)

 `Rust` ⭐ +896 今日新增 · 19,569 总星数

> NVIDIA 开源的 Agent 安全运行时：给自主 AI Agent 一个受策略约束的沙箱，能读写文件、装包、调 API、用凭证，但碰不到你的数据和网络。0.1.0 刚发稳定版。

**亮点**

- 把"策略变更前先证明会多开什么权限"当成一等公民，用形式化验证做 diff 审阅，这在 Agent 沙箱里少见——多数方案只做事后审计或运行时拦截
- 网络出口是逐连接鉴权 + 凭证注入点绑端点，等于把"Agent 能不能用这把钥匙"和"钥匙能开哪扇门"拆成两件事分别管

**核心功能**

- 内核级强制：每个 Agent 跑在独立沙箱里，文件访问和系统调用由内核控制点拦截，每条出网连接在离开沙箱前先过一遍策略检查，不是靠 Agent 自觉
- 策略变更做形式化验证：新策略生效前用 prover 算出它会新开哪些口子（比如能拿凭证访问新主机、调用新 API 方法），高风险变更挂起等人工审
- 凭证代持：Agent 全程看不到真实密钥，OpenShell 只在发往白名单端点的请求上把凭证注入进去，泄了沙箱也拿不到 key
- 网关 + supervisor + 沙箱三层控制面，K8s 上用 Helm 部署网关，要求 CNI 必须真的执行 NetworkPolicy

**适用场景**: 要把编码 Agent（如 OpenCode、Claude Code 类）接到公司内网、私有仓库、数据库的生产团队；以及平台工程师在 K8s 上给一批 Agent 统一发凭证和网络白名单，又不想把 root 权限交出去。

**竞品对比**: 对标的是一类方案：E2B、Daytona、Modal 这类 Agent 沙箱，以及 gVisor/Firecracker 这类通用隔离层，还有 Anthropic 的 sandbox-runtime。最大差别是 OpenShell 把"策略形式化验证 + 凭证代持"做进主流程，而不只是给个隔离容器；代价是绑定自己的网关和策略 DSL，迁移成本不低。

**成熟度**: 早期项目（0.1.x），API 和策略格式还可能变，但 NVIDIA 背书、文档齐全、Python/TS/Go/Rust 四套 SDK 和 Helm chart 都有，不是玩具。

**趋势信号**: 0.1.0 稳定版发布带来固定发布节奏和新隔离原语，叠加今年 Agent 从 demo 走向带真实凭证的生产环境、提示注入和供应链投毒事件频发，安全运行时正好卡在这个窗口上。

### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +619 今日新增 · 86,571 总星数

> 给 AI 编码代理补上设计规范：24 条斜杠命令和 62 条确定性检测规则，专门解决 AI 生成前端“Inter 字体 + 紫蓝渐变 + 卡片套卡片”这种千篇一律的模板感。

**亮点**

- 把“设计品味”转成可逐条检查的反模式清单：不用 Inter 和系统默认字体、不在彩色背景上放灰字、不用纯黑纯灰（必须带色偏）、卡片不套卡片、不用弹跳缓动。模型有具体规则可依，不用只靠一句“做得好看点”自行发挥
- `live` 模式在真实浏览器里点选元素直接迭代变体，`generate` 连点选都省了，按元素名批量出方案；修改落在真实 DOM 上，不用每次靠文字描述再让模型猜

**核心功能**

- 用 62 条确定性检测规则检查设计问题，Rust 编译成单个可执行文件在本地运行，既不需要 LLM，也不需要 API key；CLI 和浏览器扩展共用同一套规则
- 产品事实写入 PRODUCT.md（受众、场景、约束、语气），视觉方向写入 DESIGN.md，两份分开存，防止模型把“卖给谁”和“用什么颜色”混为一谈
- 一个 skill 通过各家 hook manifest 安装到 Claude Code、Cursor、Codex、Copilot、Gemini CLI 等 13+ 个 harness，编辑时自动触发，不用每次手动贴提示词

**适用场景**: 适合拿 Claude Code 或 Cursor 快速搭 MVP 落地页、后台界面的独立开发者和小团队。上线前跑一遍 `audit`（可访问性、响应式、性能）或 `polish`（对齐设计系统），省掉人工逐像素检查设计稿的步骤。

**竞品对比**: 起点是 Anthropic 官方的 frontend-design skill，那个只是一次性提示词。Impeccable 多了三层：24 条可复用命令、跨会话持久保存的 PRODUCT.md、以及完全不调 LLM 的确定性规则检查 + 浏览器实时迭代。

**成熟度**: 生产可用：有 npx 安装器、官网文档、VS Code Marketplace 扩展和十余家 harness 适配，8.6 万星；但命令行为会随底层模型版本调整，不建议当稳定 API 依赖。

**趋势信号**: AI 生成前端越来越像同一套 SaaS 模板，这已经引起很多人的反感；Anthropic 的 frontend-design skill 又带动了“给 agent 装 skill”的潮流，大家开始给 coding agent 补设计这类偏软的能力。

### [makecindy/cindy](https://github.com/makecindy/cindy)

 `TypeScript` ⭐ +477 今日新增 · 4,197 总星数

> Cindy 是一个开源的桌面 AI Agent 客户端，把 Claude Code 和 Codex 当作可替换的执行引擎，在本地真实文件和已登录应用上执行任务。它最近热度上升，是因为已经订阅 Claude Code/Codex 的用户希望跨工具复用额度，并让多个 Agent 协作完成任务。

**亮点**

- 没有自己从零实现 Agent 循环，而是把别人已经成熟的 CLI Agent 当作可替换的插件来用，因此省去了最难的模型调用与工具调用部分；同时允许用户直接授权已有的 Claude Code/Codex 订阅，避免重复付费，这是它最关键的获客设计。
- 客户端在 Apache-2.0 下开源，但云端后端放在另一个私有仓库里，所以“开源”覆盖的是桌面端和移动端外壳与编排层，而托管服务本身是收费的闭源产品。

**核心功能**

- 把 Claude Code 和 Codex 这两个现成 CLI Agent 抽象成可插拔 harness（把模型与执行环境封装在一起的一层）：同一个任务运行到一半就能更换 harness 或模型，工作区和会话上下文不会中断。
- 支持“异构多 Agent 编排”（内部代号 Orca）：同一个任务可以由不同 harness×模型 组合的 Agent 分别负责规划、并行执行和审阅，对应文档在 docs/dev-rules/ 里。
- 记忆和技能保存在客户端层，因此可以跨 harness 复用：你纠正过一次的内容，换到 Codex 或 Claude Code 里仍然有效；MCP 用来把内部工具接入这一层。
- pnpm monorepo 共享代码：Electron 桌面端和 Expo/React Native 移动端共享 auth、device-link、agent 编排、模型供应商等 packages；claude-code、codex、ripgrep 二进制在安装时按平台下载，Android platform-tools 固定版本并做 sha256 校验。

**适用场景**: 对象是已经为 Claude Code 或 Codex 付费的开发者，以及想让非工程同事用自然语言操作本地文件和浏览器的团队。典型场景包括：在本地仓库里派发任务、通过 IM 或定时任务触发固定流程、用 MCP 接入公司内部系统。

**竞品对比**: 和 Cursor、Claude Code、Codex CLI 这类绑定单一 harness 的工具不同，Cindy 是套在外面的编排外壳，可以混搭多个 harness 与模型；和 OpenHands、Goose 这类自建 Agent 循环的开源项目相比，它不自己造 Agent，而是复用现成 CLI。

**成熟度**: 早期项目：客户端开源但后端闭源，插件市场和技能共享仍标注为 in the making，文档偏内部工程规则（AGENTS.md、dev-rules），外部贡献者的上手路径不完整。

**趋势信号**: Claude Code 和 Codex 的订阅制普及后，用户想“一次付费、多个 Agent 共用”，而 Cindy 直接复用已有订阅，因此契合了这波需求；同时 Electron 桌面 Agent 加上多 Agent 编排正是当下的热点。

### [Nutlope/hallmark](https://github.com/Nutlope/hallmark)

 `CSS` ⭐ +455 今日新增 · 32,336 总星数

> 给 Claude Code、Cursor 这类编码 agent 用的设计 skill：按页面用途生成网页，再用真实浏览器 lint 掉那些一眼就能看出 AI 生成痕迹的设计问题。

**亮点**

- 先只做 hero 第一屏，渲染出来冷读一遍再往下写，避免整页写完才发现整体风格已经偏了
- 最后交给一个全新上下文的 reviewer 子 agent 审，构建者不能自己给自己打分；重设计还先跑 sloplint --before 记下所有链接、字段、事件处理和标题，改完用 --kept 校验，少一个就判失败

**核心功能**

- sloplint.mjs 用 puppeteer-core 拉起真实 Chrome，按 8 个宽度渲染页面并逐项检查：每个标题上方都挂一条小字 eyebrow、全大写加字距的标签、标题里塞一个彩色词、整页空框或只有图片、hero 溢出首屏、页尾必放一个邮件订阅框、点提交却什么都不发的假表单
- 规则分三档：Floor 是硬性要求，不通过就不允许交付（对比度、键盘焦点、reduced-motion、编造的数据、手机布局崩）；Reflex 是模型默认会犯的毛病，允许写明理由后推翻；Finish 只做细节打磨，不拦发布
- 48 个主题各是一个不超过 8KB 的文件和一张成品截图，只定义材质（纸感、字体、配色、表面、纹理和自带组件），不规定页面内容与顺序，一次构建只读一个主题

**适用场景**: 独立开发者、小团队前端用 Claude Code 或 Cursor 赶落地页、产品官网、预约页时用它，尤其是页面被吐槽“一眼 AI 生成”的场景；也用于对已有页面做重设计前的审计。

**竞品对比**: 和 v0、Lovable、Bolt 这类托管式生成器不同，Hallmark 是装进你本地 agent 的 skill，代码不出本地；相比 shadcn、Tailwind 模板给的是组件，它给的是材质和可执行的检查规则；相比 Anthropic 官方 frontend-design skill，多了真实浏览器渲染检查和重设计回归测试。

**成熟度**: v2 已发布，采用 MIT 许可，支持 5 个 harness，主题目录和文档都很完整；但本质上是提示词加检查脚本的组合，不是稳定库，模型换代行为会变，建议先在单页上试。

**趋势信号**: Anthropic 推出 Skills 后，agent skill 生态在 2025 下半年爆发，同时“AI 味网页”（标题上小字加紫色渐变）成了众矢之的，v2 一次放出 48 套主题正好踩中这个情绪。

**趋势信号**: Claude Code 改装原生二进制、版本号一路小步快跑，新用户涌入速度远超官方文档的消化能力，这类「周末上手攻略」正好接住这批人。

## 趋势观察

这批项目看下来，最明显的一条线是：编码 Agent 正在从「能跑」走向「能管」。 以前大家比谁的 Agent 会写代码，现在比谁能让 Agent 别乱来。NVIDIA 直接开源了一个受策略约束的沙箱，Agent 能读文件、装包、调 API，但碰不到你的数据和网络。另一边有人把编码 Agent 改造成安全审计员，六阶段流程加独立证伪复核。这说明一个事：企业开始认真担心 Agent 的权限边界了，安全从「事后补」变成「事前关笼子」。 第二条线是配套产业在疯长。AWS 官方把 MCP 服务器、技能包、插件打包好，让 Claude Code、Cursor 这些助手直接查文档、调 API、部署。还有教程仓库手把手教你怎么编排 agent、hooks、MCP，因为官方文档只会罗列功能，不讲怎么组合。Cindy 更进一步，把 Claude Code 和 Codex 当成可替换的执行引擎，本质是让已付费的用户跨工具复用额度、多 Agent 协作。工具正在被「零件化」。 第三条线挺有意思：开始有人专门治「AI 味」。两个项目都在解决 AI 生成前端千篇一律的问题——Inter 字体、紫蓝渐变、卡片套卡片。一个用真实浏览器 lint，一个上 24 条命令加 62 条确定性规则。这说明 AI 生成的东西量大到一眼能认出来了，审美和规范成了新刚需。 机器人那边，Pollen 的迷你机器鸭用 Rust 跑 50Hz 控制循环、强化学习驱动 15 个舵机，还带签名更新和失败回滚——还是那套工程化思路，落到物理世界。 至于电子书索引仓库能火，靠的不是代码，是资源量和 GitHub Pages 的零成本分发。 把这几条拼起来看：Agent 生态正在从「炫能力」转向「建规矩」。沙箱、审计、设计规范、可替换引擎、签名回滚，全是基础设施活。开发者不再只问 Agent 能干什么，开始问它出错时谁兜底。
