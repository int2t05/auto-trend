### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,716 今日新增 · 42,429 总星数

> Cloudflare 把内部漏洞挖掘流水线的起点开源成一个 Agent 技能：分六个阶段审计代码，每条漏洞结论都要另一个 Agent 独立反驳验证，最后输出通过 schema 校验的机器可读结果。

**亮点**

- 跨次运行会累加：复用上一次的账本和 findings 去补缺口、只复验改动过的源码，官方说单次运行大约只能找到重复运行总找到量的一半，等于把“多跑几遍”做成了流程。
- 按目标类型拆了 10 份攻击面提示库（内存安全与内核、LLM 提示注入、HTTP 协议与认证、客户端 DOM、供应链与发布、IAM 与容器、RPC 与消息队列、资源耗尽、租户隔离与数据生命周期、桌面移动与本地 IPC），而不是一套通用 prompt 打所有仓库。
- 没有禁用外网、限制资源、只允许写 scratch 目录的 OS 级沙箱时，它不执行目标的构建、浏览器、模糊测试，结论只能停在 needs_validation，这是少见地把“跑不动就别下结论”写进规则。

**核心功能**

- 用覆盖账本（coverage-ledger.json）把审计拆成可枚举的单元，每个单元派一个隔离的 hunter 子 Agent 去查，再由 coverage critic 找漏区，避免重复扫描同一片代码，也避免整块代码没人管。
- 查找和验证强制分离：每个候选漏洞交给一个全新的 verifier 去“证伪”，只有拿到完整源码调用链、且有可观测边界的才标 confirmed；被推翻的进 rejected，事实没查清的进 needs_validation 且不准给严重等级。
- 产物用两个零依赖 Node 脚本（validate-findings.cjs / validate-coverage-ledger.cjs）按 JSON Schema 校验，阶段 4 和每次阶段 5 替换记录后都要重跑一遍，防止模型自己编字段。

**适用场景**: 适合安全工程师或后端团队在合并前对中大仓库做一次渗透式审计，也适合把 Claude Code 这类支持子 Agent 的编码 Agent 挂进 CI 前的检查流程；典型场景是查越权、缓存投毒、提示注入、租户数据串号这类规则扫描器抓不到的逻辑漏洞。

**竞品对比**: 和 Semgrep、CodeQL、Snyk Code 这类靠规则和数据流分析的静态扫描不同，它让 LLM 去找需要理解业务语义的逻辑漏洞，代价是结果没法定量复现、跑一次成本高；和 Anthropic 官方 /security-review 命令比，多了覆盖账本、独立验证器和 JSON 产物这三层约束。

**成熟度**: 本质是提示词加两个小校验脚本的 skill，没有版本号也没说明测试覆盖，文档很细（含反模式、沙箱要求、目录规范），但效果强依赖宿主 Agent 和沙箱质量，暂时别当成合规审计证据用。

**趋势信号**: Cloudflare 把自己漏洞挖掘流水线的起点开源，正好撞上 Agent Skills 生态爆发和 AI 自动找漏洞（XBOW 一类）的热度，加上 Cloudflare 官方博客背书，几天内冲到 4 万星。

### [NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell)

 `Rust` ⭐ +1,119 今日新增 · 18,908 总星数

> NVIDIA 开源的 AI Agent 沙箱运行时：内核级限制文件、系统调用和网络，凭据只在批准的端点注入，0.1.0 起进入稳定发版节奏。

**亮点**

- 把「改策略」当成「改代码」来管：先形式化验证算权限 diff 再合并，而不是让人肉 review 一堆 YAML
- 凭据从沙箱里彻底移出，改成网关按目标端点注入，等于把密钥泄露面从 Agent 进程缩到网关一处

**核心功能**

- 每个 Agent 跑在独立沙箱里，靠内核控制（文件访问 + 系统调用过滤）强制策略，出沙箱的每条网络连接先过策略检查再放行，不靠应用层自觉
- 策略改动用形式化验证预演：提交前先算出生效后会新开哪些权限（例如能用凭据访问新主机、调用新 API 方法），有风险就挂起等人工审批
- Agent 拿不到真凭据，网关在请求发往白名单端点时才把密钥贴上去，所以即使被 prompt injection 骗了也偷不走 key
- 架构分 gateway（控制面，管沙箱/策略/凭据）+ supervisor + sandbox 三层，K8s 里用 Helm 装，网络隔离交给 CNI 的 NetworkPolicy

**适用场景**: 平台或安全团队想让编码 Agent（README 里用 OpenCode 演示）在内网或 CI 里读仓库、装依赖、调外部 API，但公司不允许它碰生产凭据和内网机器；也适合做 Agent 产品的团队做多租户隔离。

**竞品对比**: 和 E2B、Daytona 这类「托管跑代码沙箱」不同，也和 gVisor、Kata、Firecracker 这类纯隔离内核不同：OpenShell 卖的是策略和凭据治理，隔离层是它自己拼的，可自托管在自己机器上。

**成熟度**: 0.1.x 早期项目，API 还会变，但 NVIDIA 官方文档、四语言 SDK、Helm 和 Brev 一键部署都已就位，不是玩具。

**趋势信号**: 0.1.0 刚发布并宣布稳定发版节奏、新增隔离原语和扩展面，正好撞上社区对 Agent 拿到 shell 和凭据后失控的担忧，加上 NVIDIA 招牌自带流量。

### [php/php-src](https://github.com/php/php-src)

 `C` ⭐ +716 今日新增 · 41,594 总星数

> PHP 官方解释器源码仓，Zend 引擎加 opcache/JIT 的完整实现。PHP 8.5 正式版刚发布，一天涨 716 星，是老牌语言换新版带来的关注。

**亮点**

- 无共享的请求模型：每个 php-fpm worker 一次只处理一个请求，请求结束把内存池整个清空，所以普通业务代码不用操心内存泄漏
- opcache 把编译结果落在共享内存里，多个 worker 跨进程复用同一份 opcode，让 PHP 的“每次请求重新编译”代价基本消失

**核心功能**

- Zend 虚拟机先编译成 opcode，再由 opcache 缓存、JIT 把热代码转成 x86/ARM 机器码，省掉每次请求的重复解析
- 内存靠引用计数即时释放，配一个循环垃圾回收器专门处理对象互相引用的死循环，请求结束整段内存直接丢弃
- 词法分析器用 re2c 生成、语法分析器用 bison 生成，改 PHP 语法要动 .re/.y 文件再重新生成 C 代码，不是手写解析器
- 自带 run-tests.php 测试框架，make test 默认并行跑 10 个进程，同时接入了 OSS-Fuzz 做持续模糊测试

**适用场景**: 中小团队和独立开发者做 Web 站点、API 后台，典型组合是 nginx + php-fpm 跑 WordPress、Laravel、Symfony。要改语言行为或写 C 扩展的人才会直接碰这个仓库。

**竞品对比**: 和 Node.js 比，PHP 不用自己搭进程管理和事件循环，php-fpm 直接按请求分发到多进程；和 Python/FastAPI 比，内置函数库和 FastCGI 集成开箱即用。差异点是它不做常驻内存，靠每请求隔离换稳定性，代价是没有进程内缓存和长连接状态。

**成熟度**: 生产可用，二十多年历史，PHP 8.5 已正式发布，文档和测试套件都很完整。

**趋势信号**: PHP 8.5 正式版发布，带来管道操作符 |&gt;、#\[\\NoDiscard\] 属性、array_first/array_last 等新特性，社区集中讨论把主仓库顶上了趋势榜。

**竞品对比**: 和 OpenAI 的 GPTs、Zapier 的 AI 自动化比，最大差异是绑定 MCP 协议 + 命令行/桌面双端，产物是文件化的 skill 和 command，可版本管理、可 fork；和 LangChain、CrewAI 这类 Agent 框架比，它不提供编排代码，只给领域知识和接口声明，上手门槛低但也没法做复杂逻辑。

**成熟度**: 刚开源的新项目，无版本号，官方维护文档完整，但插件本身是通用模板，实际用起来必须自己改。

**趋势信号**: Anthropic 刚推出 Cowork（面向非程序员的 Agent 产品）并开放插件市场，这个仓库就是市场里的官方插件集合首次开源，加上 Claude Code 也支持同一套插件安装命令，两个入口一起带量。

### [OpenBMB/VoxCPM](https://github.com/OpenBMB/VoxCPM)

 `Python` ⭐ +150 今日新增 · 40,339 总星数

> OpenBMB 开源的无分词器 TTS：把文本直接转成连续语音表示，2B 模型支持 30 种语言、文字描述造音色、可控克隆和 48kHz 输出，Apache-2.0 可商用。

**亮点**

- Voice Design：只给一句自然语言描述（性别、年龄、语气、情绪、语速）就能凭空造出一个声音，不需要任何参考音频，把配音选角变成写 prompt
- 可控克隆把“音色”和“风格”拆开：参考音频锁音色，另一段风格指令单独调情绪和语速，克隆时不用重录参考

**核心功能**

- 不做离散音频分词（tokenizer），直接用扩散自回归模型生成连续语音表征，省掉“音频先量化成码本再还原”这一步带来的音质损失
- AudioVAE V2 采用不对称编解码：编码端只吃 16kHz 参考音频，解码端直接吐 48kHz，超分内置在声码器里，不用外挂升采样器
- 推理只需 10 步扩散 + CFG=2.0，4090 上 RTF 约 0.3；接 vLLM-Omni（带 PagedAttention 和 OpenAI 兼容接口）能压到 0.13，另有 llama.cpp-omni 端侧版本
- 底座是 MiniCPM-4，用 200 万小时多语种数据训练，支持 30 种语言和四川话、粤语、闽南语等 9 种中文方言，不用打语言标签

**适用场景**: 有声书、播客、短视频配音团队需要批量生成多语种人声，又不想按字符付云端 TTS 费用；游戏和客服团队用“文字描述造音色”快速试角色声线，再用短参考音频做可控克隆。

**竞品对比**: 对标 CosyVoice 2/3、F5-TTS、Fish Speech、IndexTTS 这类开源 TTS。最大差异是彻底不用离散音频 token，且把 48kHz 超分塞进声码器内部，多数竞品还是“tokenizer + 声码器”两段式、输出 24kHz 左右。

**成熟度**: 生产可用：Apache-2.0 商用授权、ReadTheDocs 文档、HF/ModelScope 权重、arXiv 技术报告齐全，还有官方 vLLM-Omni 服务和端侧 llama.cpp 移植。

**趋势信号**: 2026.04 发布 VoxCPM2 大版本（2B、30 语言、Voice Design、48kHz），加上前代 1.5 在 2025.12 拿过 GitHub Trending 第一，社区热度直接续上了。

### [nodejs/node](https://github.com/nodejs/node)

 `JavaScript` ⭐ +66 今日新增 · 122,933 总星数

> Node.js 是跑 JavaScript 的服务端运行时，把 V8 引擎和异步 I/O 包起来，让 JS 能写后端和命令行工具。这次上热榜是因为它改了发布节奏：改成每年一个大版本、每个大版本都进 LTS。

**亮点**

- 发布节奏从“半年一版、只有偶数版进 LTS”改成“每年 4 月一版、所有大版本都进 LTS”，总支持期 36 个月。好处是版本号可预测、奇数版不再是一次性试验品
- 治理上走开放模式，TSC\(技术指导委员会\) 投票决策，OpenJS 基金会托底。这让它不是某家公司说改就改的项目，企业敢押注

**核心功能**

- 底层是 V8 编译执行 JS，配 libuv 做事件循环和跨平台异步 I/O，所以单线程也能扛住大量并发连接，这是它能写高并发服务端的根本原因
- 四条发布线分工明确：Alpha\(10 月切分支，允许 breaking change\)、Current\(4 月转正，禁 breaking change\)、LTS\(只收在 Alpha/Current 待满两周的补丁\)、Nightly\(每天自动打包、不测试\)，避免生产环境被不稳定的 API 变更打到
- 发布前用 CITGM 把 npm 上的下游热门包挨个跑一遍回归，二进制包配 SHA256 校验 + 发布者 PGP 签名，下载后可验真

**适用场景**: 写后端 API、CLI 工具、BFF 层的团队，以及 webpack/Vite/ESLint 这类前端工具链的作者——这些工具本身就是跑在 Node 上的。运维和 SRE 关心的是选哪个 LTS 版本、什么时候必须升级。

**竞品对比**: 主要对手是 Deno 和 Bun。Deno 默认不给文件和网络权限，安全模型更严；Bun 换用 JavaScriptCore 引擎，主打启动快和自带打包/测试。Node 的差异点是 npm 生态体量和 LTS 的长期稳定承诺——大量现有库只能在 Node 上跑。

**成熟度**: 生产就绪，LTS 提供 30 个月支持，全球企业大规模验证过；早期版本 API 会变，别上生产。

**趋势信号**: 社区在讨论新的发布节奏改革——改成每年一个大版本、全部转 LTS，这个变动直接影响所有团队的升级计划，所以被刷上趋势。
