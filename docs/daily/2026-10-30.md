### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +2,870 今日新增 · 95,799 总星数

> 给编程 Agent 装一套设计词库和 62 条静态检查规则，把“做得高级点”变成具体命令，出货前拦下 AI 味界面。

**亮点**

- 先写上下文再改代码：`init` 生成 PRODUCT.md（给谁用、要干什么、约束），`document` 把现有视觉系统抓成 DESIGN.md，之后每条命令都读这两个文件，模型不用每次猜项目调性
- live 模式在 dev server 上盖一层 overlay，点页面元素后热换变体，选中的写回源码；兼容 Vite/Next/SvelteKit/Astro/Nuxt/纯 HTML，靠框架自己的 HMR 预览，且只改本地 checkout

**核心功能**

- 24 个斜杠命令把模糊审美拆成具体动作（bolder/quieter/distill/typeset/layout/overdrive），每个命令配一份只针对这一种改动的 playbook，并要求指定目标（如 `/impeccable bolder the pricing cards`），避免 Agent 整页乱改
- 62 条确定性规则做“AI 味”检测，纯规则匹配不调 LLM、不要 API key：扫 JSX/TSX 源码只能跑模式类规则（紫蓝渐变、Inter 字体、卡片套卡片、跳级标题），对比度不足、字号过小这类必须看渲染结果，所以 CLI 要指向 URL（`npx impeccable detect http://localhost:5173`），用本机 Chrome/Edge 渲染后判定
- Agent 编辑钩子：接在 Claude Code / Cursor / Codex / Copilot 上，UI 文件一被改就自动扫一遍，把问题回灌给 Agent 让它修完再收工；同一套规则也能进 CI（`--github` 输出 Actions 注释，退出码 2 = 有问题）或 Chrome 扩展在任何页面上叠层显示

**适用场景**: 用 Claude Code、Cursor、Codex 快速搭前端的产品团队和独立开发者：手里已有一个页面或组件想改好，就逐块跑 critique/polish/harden；设计系统团队则把 detector 挂到 CI，防止 AI 生成的代码把品牌规范带偏。

**竞品对比**: 和 v0、Lovable 这类“从零生成页面”的工具路子相反，它主要审已有界面并逐组件迭代；和 ESLint/stylelint 比，后者管代码规范不管视觉，它查的是视觉套路和可用性问题。暂时没有功能完全对位的竞品。

**成熟度**: 星数极高、官网文档和 Chrome 扩展都齐，但命令集还在调整（`craft` 已标为废弃别名），命令名和行为可能变，建议先在单个组件上试用。

**趋势信号**: AI 生成前端高度同质化（Inter 字体、紫蓝渐变、卡片套卡片）已成公开吐槽点，同时 Claude Code / Cursor 刚开放 skill 与 hook 机制，这类“给 Agent 塞领域知识包 + 事后检查”的形态正好踩在风口上。

### [HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)

 `Python` ⭐ +1,930 今日新增 · 50,636 总星数

> 港大数据智能实验室开源的 AI 家教：把教材、PDF、网页做成知识库，按每个学生的水平和历史生成学习路径、出题、讲题。刚发 v1.7.0，赶上 AI 教育这波热度。

**亮点**

- 把"辅导能力"做成可安装的 skill 插件，配套 EduHub 社区仓库，用户可以自己写技能包分享，像给家教装扩展。
- 索引文件会记录"是哪个解析器、哪个 embedding 模型建的"，模型换了就强制重建，避免用旧索引配新模型导致检索结果悄悄变差。

**核心功能**

- 知识库用同团队的 LightRAG 搭：先把文档抽成"实体—关系"图谱再检索，回答能定位到原文段落、图表和公式，不是单纯的向量切片匹配。
- 学习者记忆单独建模：聊天记录、答题对错、错题都写进个人画像，但做了长度上限截断（bounded tutoring memory），防止上下文越滚越大拖垮推理。
- 多模态走原生接口：PDF 里的图直接喂视觉模型，朗读和视频讲解用 Gemini 原生语音合成；还支持导入 Kiwix 离线包，断网也能查维基百科当资料源。

**适用场景**: 自学者把教材、论文、网课资料丢进去，让它按自己进度出题讲解；学校或培训机构用它搭内部课程库，给学生做统一的知识库问答和测验。

**竞品对比**: 对比 Khanmigo、NotebookLM：Khanmigo 绑定可汗课程且闭源，NotebookLM 只做资料问答没有学习路径和长期学情跟踪。DeepTutor 的差异是开源可自部署 + 图谱 RAG + 跨会话的学习者建模。

**成熟度**: 已到 v1.7.0，Apache 2.0，有 arXiv 论文和 Discord/飞书/微信群，但发版极勤（几天一个 minor），接口和配置项还在变，适合自部署尝鲜，生产接入要锁版本。

**趋势信号**: HKUDS 是 LightRAG 的原班团队，本身自带流量；叠加 v1.7.0 刚发布（模块化安装、块状笔记、视频讲解）和 AI Tutor 赛道正热，一天涨近 2000 星。

### [elayadesign/ai-design-skills](https://github.com/elayadesign/ai-design-skills)

 ⭐ +1,187 今日新增 · 12,420 总星数

**亮点**

- 它不做工具，也不写一行代码，只发布 markdown。跟着各家工具的 rules 文件约定走，哪家生态起来都能直接复用，没有集成成本。
- 把“设计品味”抽成一块可编辑的参数区，用户改参数而不是改指令，降低了调 prompt 的门槛。

**核心功能**

- 每个技能就是一个文件夹，核心是一份 SKILL.md。同一份文件能放进 .claude/skills、.cursor/rules、AGENTS.md、.windsurfrules、.clinerules 五种位置，不用为每个工具重写一遍。
- landing-page-design 把建站拆成固定步骤：先问需求（intake questions），再定页面结构，然后写转化文案，最后给一整套视觉系统（字体、间距、圆角、动效）。等于把“设计”变成模型能按顺序执行的任务清单。
- 字体、颜色、间距、动效这些设计取值全部集中在文件底部一节。改这一节就换掉整套风格，上面的规则自动跟着走，不用逐条改 prompt。

**适用场景**: 适合没有设计背景的独立开发者、后端工程师，在 Cursor 或 Claude Code 里快速做出一个看上去不像“AI 生成”的产品落地页；也适合设计团队拿它当统一的 prompt 基线。

**竞品对比**: 直接前身是 Leonxlnx/taste-skill，本项目的文案真实感和动效思路就是从那里改的；同领域还有 superdesign、v0 这类直接出 UI 的产品。最大差别是它不生成界面也不带编辑器，只发一份提示词规则，模型和工具随便换。

**成熟度**: 极早期，只有一个技能，没有版本号，文档写得清楚但内容很薄，12k star 主要是热度而非验证。

**趋势信号**: Claude Code 的 Agent Skills（SKILL.md）格式在 2025 年底被多家编码工具陆续兼容，同时“AI 做的落地页长得都一样”被大量吐槽，这个设计规则包正好卡在这个空档。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +1,034 今日新增 · 308,791 总星数

> 一套塞进编码 agent 的软件开发方法论：先逼出 spec 和实现计划，再派子 agent 按红绿 TDD 逐条做完。做成插件，一份仓库适配 17 种 agent 工具。

**亮点**

- 不发布框架和 SDK，只发布 Markdown 指令加一段引导语，把「方法论」本身做成可分发、可上架的插件。
- subagent 分工闭环：主 agent 只负责拆任务和评审，子 agent 埋头干活，所以能连续自主跑几个小时不跑偏。
- 用「写给人读」的规格切段审查卡住 agent 的自由发挥，把质量控制点前移到写代码之前。

**核心功能**

- 方法论拆成一堆可组合的 Markdown skill 文件，靠一个 using-superpowers 引导 skill 在会话开始和上下文压缩后自动注入，agent 自己触发对应流程，用户不用背命令。
- 强流程：先反问需求逼出 spec，再分小段让人读完确认，然后产出「水平一般的初级工程师也能照做」的实现计划，最后派 subagent 逐任务执行、主 agent 审子 agent 的产出，强调真红/绿 TDD、YAGNI、DRY。
- 一套 skill 同时打进 17 个 harness（Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、Qwen、Kimi、Grok、Devin、Droid、OpenCode、Pi、Muse…），每个都走各家自己的 plugin/hook/extension 机制单独安装，Pi 和 Muse 用原生 SessionStart hook，Hermes 没有压缩后钩子就直接在文档里写明长会话会丢引导。

**适用场景**: 日常用 Claude Code、Cursor、Codex 写代码的开发者和小团队，想强制 agent「先设计再动手」，避免一次对话就狂奔出没人敢维护的代码；企业里要统一团队 agent 工作流时也会用。

**竞品对比**: 对比 AGENTS.md/CLAUDE.md 这类一次性规则文件、GitHub 的 spec-kit、BMAD-METHOD：规则文件全靠模型自觉遵守，Superpowers 用自动触发的 skill 加子 agent 执行循环把流程真正跑起来，而且同一份仓库能装进 17 个 harness。

**成熟度**: 迭代快、跨 17 个 harness 维护成本高，已有商业支持渠道，算生产可用，但上游工具每次改插件机制都得跟着修。

**趋势信号**: Anthropic 把 Agent Skills 推成通用格式后，Claude Code、Codex、Cursor、Gemini 等接连开官方插件市场，Superpowers 正好卡在「第一个把整套开发方法论打包成跨平台 skill 插件并全量上架」的位置。

**亮点**

- 安全模型是明确的取舍——首次启动点一次同意后，agent 以 danger-full-access + approvalPolicy: never 运行，读写文件、跑命令、上网、控浏览器都不再逐次确认。README 直接把这条写成警告，让你只跑信得过的任务
- Computer Use 做成独立子进程 cua-driver，由 OpenBot 启动后交给每个 provider 用，不绑死某一家，也不塞进 Electron 主进程

**核心功能**

- 用 ACP（Agent Client Protocol，一个让宿主程序用统一接口驱动不同 AI 编码 agent 的协议）接入 Grok CLI、OpenCode、Gemini、Cursor CLI、Cline；Codex 走官方 App Server，Claude 走 Claude Code。同一个界面里切 provider，还能自定义 OpenAI 兼容端点和本地 Ollama/LM Studio
- 每个 agent 一个独立本地工作区和独立会话，消息走 FIFO 队列，可暂停、恢复、取消；队列写入磁盘，进程崩溃后接着跑。另外每个 agent 单独监控上下文占用，线程快撑满模型窗口前自动压缩历史
- agent 之间能互发消息、回复、传文件；共享频道聊天里有唯一的 task owner 负责派活，支持 Stop/Resume/Reassign/Archive。内置一个持久化浏览器给 agent 打开和操作，Computer Use 则通过 release 里的 cua-driver 独立子进程实现（截屏 + 模拟鼠标键盘）

**适用场景**: 同时开着好几个编码 agent 的个人开发者，用它替代一堆终端标签页；也适合想把 agent 常驻跑在 VPS 上的团队——有 systemd 安装脚本、Docker 镜像和 Nix flake，能通过 iPhone App 或 openbot.run 网页远程接入。

**竞品对比**: 同类有 Conductor、Vibe Kanban、Claude Squad、Crystal，它们基本绑死 Claude Code、围绕 git worktree 并行跑任务；OpenBot 的差异是多 provider（含 Grok/Gemini/Cursor/Cline）+ 完整桌面 App + 内置浏览器 + 可自托管成服务器。也可以对比 Zed 编辑器里的 ACP agent 面板，但那是编辑器内嵌，不是独立工作区。

**成熟度**: 早期项目：README 自称 development preview，agent 免确认全权限运行，许可证是 PolyForm Noncommercial（非商业），API 和安全模型都可能变，别拿它碰生产数据。

**趋势信号**: 近几个月 Codex CLI、Grok CLI、Gemini CLI、Cursor CLI、Cline 扎堆发布，开发者手上同时有好几个 agent，缺一个统一托管的壳——这波单日 709 星大概率是发布推广带来的。

### [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

 `TypeScript` ⭐ +336 今日新增 · 105,017 总星数

> 给编码 Agent 加持久记忆：用 hook 抓每次会话的工具调用，AI 压缩成摘要，下次会话自动注入相关上下文。解决跨会话失忆。

**亮点**

- 把「记忆从哪来」抽成 provider 层：本地 observer、自己的 OpenRouter/Gemini key、Anthropic 套餐、托管 CMEM Pro 都能切。安装时选，不绑死一个模型
- 多宿主适配不走统一协议，而是让安装器去探测每个 IDE 开了哪些 provider，再把原生插件分别注册进各自的 home 目录。像 T3 Code 这类能自动识别

**核心功能**

- 靠宿主自带的 hook 自动录下会话里的工具调用，不需要人手动记笔记；碰上没有 hook 的宿主（如 Grok Bot），就改成盯它的聊天日志文件
- 把原始记录交给模型压缩成语义摘要，下个会话再通过 MCP 搜索工具按需取回相关内容，而不是把整段历史塞进 context

**成熟度**: 版本已到 15.7.0，README 翻了 30 多种语言，接入宿主一大堆，但同时带托管付费档和 30 天试用，迭代极快，别指望接口不变。

**趋势信号**: Claude Code、Codex、Cursor 这类 CLI Agent 铺开之后，跨会话失忆成了所有人共同的痛点。Claude Code 的 hook 机制刚好让「自动采集」变得可行，作者又把同一套记忆层快速复制到十几个 Agent 上，赶上这波热度。

### [CopilotKit/OpenBot](https://github.com/CopilotKit/OpenBot)

 `TypeScript` ⭐ +247 今日新增 · 8,292 总星数

> CopilotKit 开源的"AI 同事"平台：每个 agent 分到一台独立容器电脑（浏览器、文件、工具），所有动作先审批后执行并留审计，跑在你自己机器上。

**亮点**

- 判定发生在动作之前而不是只做事后日志：gateway 在工具真正执行前给出 allow/deny，拒绝时把触发的那条规则名回给用户
- 刻意做成"可 clone 的模板"而不是 SaaS：所有 workspace 都是 private、不发 npm 包、没有托管版，你把 examples/ 下的租户包换成自己的 coworker 就跑起来；模型 key 由管理员填，加密存储且不写日志

**核心功能**

- 每个 Bot 一个独立 Docker 容器，容器内自带 Chromium、独立登录态和工作区，由 supervisor 拉起——agent 的浏览器和文件操作被关在这台"电脑"里，碰不到别的东西
- 所有工具调用（浏览器、文件、MCP server、UI 组件）统一进一个 gateway：先解析目标，再按你的策略判定 allow/deny，往 PostgreSQL 写一条审计记录，然后才真正执行；拒绝时直接告诉用户是哪条规则拦的
- 以 AG-UI 协议（agent 与前端交互的开放协议）作为接入层，LangGraph、Mastra、CrewAI、Pydantic AI、Google ADK 或手写的 agent 都以同样方式接进来，治理逻辑挂在协议上，不绑框架

**适用场景**: 适合要把 agent 放进内网、又怕它乱动数据和系统的大公司 IT/安全团队。典型场景是让 agent 自己开浏览器查系统、读工单、写文档，同时每一步留痕；仓库里的 fintech 示例就包括拿差旅报销单比对政策、把会议纪要转成待办、on-call 交接、客户反馈归类。

**竞品对比**: 和 OpenHands 这类"给 agent 一台沙箱电脑"的开源项目重叠，也和 Dify/n8n 这类自托管 agent 平台、以及 README 自己点名的 ChatGPT/Claude/Grok 有交集。差异点是不绑 agent 框架（靠 AG-UI）、每个 coworker 独占一个容器、工具调用强制过策略网关并落审计行。

**成熟度**: Beta 阶段，作者自己说"这是模板不是产品"，依赖 CopilotKit Intelligence 项目和 license（有免费额度），还要求 Bun 1.4+（部分测试在 1.3 上会挂），API 和目录结构预计会变。

**趋势信号**: CopilotKit 借 AG-UI 协议和企业自托管 AI 同事这波需求发布 OpenBot，正好撞上各家都在做 computer-use agent、企业又开始要求私有部署和审计留痕的时间点。

## 趋势观察

今天这份榜单有个明显的共性：没人再比谁的模型聪明了，大家都在给编码 agent 补配套。 一半项目在做“托管”。把 Claude、Codex、Grok 这些 CLI 塞进独立虚拟机、独立工作区，统一管队列、管文件，还让它们互相通信。有人干脆把它们包成聊天软件里的多个 bot，各带人格和记忆，数据留在本地。说白了，各家 CLI 最近扎堆发布，工具碎了一地，中间层的机会就来了。 另一半在做“规矩”。以前跟 AI 说句“做得高级点”就完了，现在得写成 SKILL.md、AGENTS.md，配 62 条静态检查规则，出货前把那股 AI 味拦下来。还有项目把 TDD 流程、spec 先行、49 人工作室的角色分工，全固化进目录结构。提示词工程正在变成流程工程。 几个信号值得记。跨工具通用格式在成形，一份仓库能适配 17 种 agent 工具，一个 SKILL.md 到处跑。持久记忆被单独拎出来做，靠 hook 抓会话、压成摘要再回注，解决跨会话失忆。本地化和审计写进产品里，直接对着闭源 SaaS 打。教育那头也有动静，港大的 AI 家教把教材做成知识库，按人出路径。 一句话：模型能力外溢之后，注意力和钱正在往 agent 的调度、记忆、规范和治理上挪。谁能把这些碎工具缝成一套能交付的流程，谁就占住位置。
