### [google/ax](https://github.com/google/ax)

 `Go` ⭐ +2,305 今日新增 · 7,880 总星数

> Google 开源的 Go 语言 agent 编排运行时,把 agent 任务当 K8s 式声明式工作负载来管:沙箱隔离、预挂仓库、锁出站网络、可暂停恢复。

**亮点**

- Gateway 默认只放开你列出的出站主机。agent 调模型 API 和工具服务器都走这条路,能挡住 agent 死循环刷 API 烧钱——这是 agent 相比普通微服务最容易失控的地方。
- 把 agent 状态检查点做进 suspend/resume。agent 会持续积累状态,既不是无状态微服务也不是跑完就退的批处理,所以能存下状态、暂停再续跑是它的核心取舍。

**核心功能**

- 四个声明式原语,全写成 ax.io/v1alpha1 YAML 一次 apply:Task(任务加 CPU/内存限制)、Workspace(启动前预挂 Git 仓库、MCP server、skill 包,让 agent 一上来就是热的)、Gateway(出站流量锁到显式 host 白名单)、Model(指定平台用哪个 LLM,凭据从 K8s secret 取)。
- CLI 走 gRPC 控制面,动作和 kubectl 一样:apply/get/describe/watch/delete,外加 agent 专属动词 ax ssh(进运行中的沙箱看它在干嘛)、suspend/resume(检查点 actor 状态后暂停,再精确恢复)。
- 控制面部署在 K8s 上(用 ko 构建镜像,Redis 存状态),沙箱执行交给 Agent Substrate;atenet 路由器负责让你从集群内、笔记本或 gRPC 客户端连到运行中的 task。

**适用场景**: 平台和基础设施工程师,要在集群里同时跑几千个不受信任的 agent。典型流程:agent 克隆仓库改 Go 代码、调 MCP 工具、打模型 API,团队需要卡住每个 agent 的 CPU/内存和能访问的外网域名,还要能随时 ssh 进去看或把它暂停掉。

**竞品对比**: 和 E2B、Daytona 这类沙箱 SDK 比,AX 管的是整个集群的调度和声明式生命周期,不只是创建单个沙箱。和直接拿裸 K8s 跑 agent 比,它多了模型凭据、MCP 预热、出站网络围栏、状态检查点这些 agent 专属的东西。

**成熟度**: 早期项目,API 是 v1alpha1,README 自己警告稳定版之前会有重大破坏性改动;还要自备 K8s 集群和 Agent Substrate 才能跑起来。

**趋势信号**: Google 官方下场做 agent 运行时,正好撞上 MCP 生态铺开、agent 数量变多管不住的窗口,社区缺一层把 agent 当集群工作负载来调度的东西,一天涨 2300 星是这个需求的直接反映。

### [agent-substrate/substrate](https://github.com/agent-substrate/substrate)

 `Go` ⭐ +245 今日新增 · 3,068 总星数

> Google 开源的 Agent 运行环境：把大量大部分时间在空闲的 Agent 实例多路复用到少量 worker 上，靠内存+文件系统快照做亚秒级挂起恢复，实现高密度沙箱托管。

**亮点**

- 不自己造一套调度和编排，而是把 Kubernetes 当底座——Pod、HPA 这些直接复用，只在上面加 Agent 专属的调度和低延迟路由。好处是 agent 运行、推理、训练能共用同一套基础设施做整体优化。
- 刻意做「低观点」系统：它不管你是不是 AI Agent，只管容器的创建、销毁、挂起、恢复和流量路由。状态存在快照里而不是进程里，所以换机器不用重建，恢复后接着用。

**核心功能**

- Actor/Worker 复用模型：把几百上千个有状态 Agent（叫 actor）映射到少量常驻 worker 上，赌的是 Agent 大部分时间在等模型返回、处于空闲，靠这个做超卖。官方 demo 是 250 个有状态 actor 跑在 8 个物理 pod 上，约 30 倍超分。
- 全状态挂起/恢复：冻结时把内存和文件系统一起快照下来，恢复只要不到 500ms，单机每秒能做 500 次以上挂起/恢复，actor 可以直接「传送」到池子里任意一台 worker 上接着跑。
- 隔离层用 gVisor 和 microVM，管的是标准 OCI 容器，所以对 Agent 框架无感；上层套 Kubernetes，靠 atelet DaemonSet 管 worker、atenet-router 按 header 路由流量到指定 actor，worker 版本用节点 label 卡住。

**适用场景**: 跑大量有状态编码 Agent 会话的团队，比如同时开几百个 Claude Code、Codex 环境并保留文件系统状态；也适合把 MCP 工具服务器做成常驻沙箱，以及 RL 训练里需要成千上万并发 agent 环境的场景。kagent 这类 K8s 原生 Agent 框架的用户是直接目标。

**竞品对比**: 对标 E2B、Modal、Daytona 这类 Agent 沙箱方案，它们基本是一会话一沙箱、用完即弃；Substrate 的重点是把空闲 actor 超卖到共享 worker 池，并深度绑定 Kubernetes，更适合已经有大集群、想自建而非买托管服务的团队。

**成熟度**: 早期项目，README 明确写了不适合生产、API 几乎一定会变，连 Google 官方支持产品都不算，目前只适合尝鲜和内部试点。

**趋势信号**: 和 Google 最近推的 Agent Executor（google/ax）以及 CNCF kagent 接入直接相关，Agent 沙箱基础设施正是当下各家抢着做的赛道，Google 用自家 gVisor 加 K8s 入场所以关注度集中。

### [superdesigndev/treg](https://github.com/superdesigndev/treg)

 `Python` ⭐ +230 今日新增 · 2,309 总星数

> treg 是给 AI Agent 用的「工具版 OpenRouter」：一个 base URL 加一个 token，就能调用 3000+ 个第三方接口（SEO、社媒、爬虫、人物公司信息等），按次计费，不用逐个注册厂商账号。

**亮点**

- 不做模型路由、只做工具路由，并且自己持有 Semrush、Crunchbase、Apollo 这些 $99-$139/月的订阅账号来转售按次调用，绕开注册墙和邀请制 API
- 同一个 token 同时覆盖外部目录接口和团队私有工具，私有 key 优先、不计费，等于把「公共工具市场 + 企业密钥管理」合成一层
- 配了 Claude Code 插件市场、Claude.ai Connector 和 MiniMax 插件市场三条分发路径，装完不带 token 也能自动引导完成登录和 mcp install

**核心功能**

- 代理只做转发不改写请求（relays, never models），认证在服务端注入，调用方永远不持有厂商 key，所以上游 API 改了也不用客户端改代码
- 四级凭证阶梯：团队自己注册的工具 > 团队存的密钥（走虚拟工具注入）> 已验证的公开免密路由（免费）> 用 treg 自己的账号代付（扣团队预付费余额），自带 key 永远优先且不计费
- 一次请求可绑多个密钥（bindings），比如同时注入 OAuth bearer 和 developer-token 头；CLI 类型工具直接把密钥注入到 stripe/gh/vercel 这类厂商二进制里跑
- 余额不足返回 HTTP 402，body 里带 balance_micro、estimated_cost_micro、topup_url，Agent 不用读自然语言就能自己决定充值
- MCP 服务分两个面：/mcp/v2/ 只暴露精选目录接口，且把读调用和写调用分开，好让 Claude 拿到准确的安全信号；/mcp/ 则开放团队自有工具和导入的 skills
- strict_query 校验：标记为 strict 的接口会拒绝未声明或重复的 query 参数、不支持的值和请求体

**适用场景**: 适合做 Agent 产品的团队和个人开发者：需要在产品里接一堆第三方数据源（找邮箱、查外链、抓 TikTok 数据、生成语音），又不想一家家开户、按月订阅。也适合企业把内部 API、OAuth 连接和 SKILL.md 统一注册一次，让全团队的 Agent 共用，密钥不出服务器。

**竞品对比**: 和 Composio、Arcade.dev、Smithery 这类工具接入/MCP 注册表比，最大差别是 treg 自己承担厂商账号和账单、按调用次数收费，而不是只帮你管 OAuth；和 OpenRouter 比，它路由的是工具不是模型，但借用了「一个 key 打通全部」的模式。

**成熟度**: 早期项目，仓库刚起来（约 2300 星），有托管服务和自部署文档，但没有版本号和企业落地案例，API 和计费规则还可能变。

**趋势信号**: MCP 在 2025 年成了 Agent 接工具的事实标准，Claude Code 插件市场又刚开放，大家对「工具从哪来、密钥怎么管」的需求集中爆发，treg 正好卡在这个位置，所以一天涨 230 星。

## 趋势观察

今天的热榜只有一个主角：Agent 的周边。

Google 一口气开源了两个跑 Agent 的底座，一个把空闲实例多路复用做高密度沙箱，一个把任务当 K8s 工作负载管。Anthropic 给出金融业十个工作流的参考实现。再加上 Claude Code 模板库、工具版 OpenRouter、Office SDK、对话剪视频的 video-use，一条从「跑起来」到「接进来」的链路正在成型。模型本身不再是新闻，谁的 Agent 更稳、更快装进项目才是。

另一条线是信任。五角大楼罕见承认过度依赖 AI 导致导弹误击学校；DEX 检测器顺手扒出某头部池子三分之二成交量是三个钱包自买自卖；SAML 被批几乎无法正确实现。Agent 越自动，出错和造假的代价就越直接。所以那篇讲幂等、降级、可见性、快速恢复的复盘，反而是当下最像刚需的内容。

还有零星的老东西复活：Rust 重写 VFP 编译成 wasm，TypeScript 直编原生 App。监管那边也在拉扯，Waymo 转身做公交接驳，澳洲要立法让用户关掉推荐算法。

一句话总结：所有人都在给 Agent 修路，但刹车还没装好。
