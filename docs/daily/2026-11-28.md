今天的热榜，一半是在给 AI Agent 装零件。技能包、插件、CLI 封装、MCP 接口，都在做同一件事：把 Agent 从“会聊天”改造成“能干活”。 趋势有几条很明确。第一，标准正在抢跑。Agent Skills、MCP、Cursor 的官方 manifest，都想让同一套东西在 Claude Code、Cursor、Codex 上通用。谁定接口，谁就先占位。第二，大厂开始把自家能力拆开，供 Agent 调用。Google 把 Stitch 的设计能力做成技能，Intel 把推理工具箱摊开，Firecrawl 直接给个 Rust 单二进制，不要数据库也不要容器。第三，开发者不再迷信大模型。3 块钱、单卡 3090、两小时训完的教程能被顶上来，说明大家关心的是能不能读懂、跑得起、改得动。本地优先、可自托管、免部署，都是同一个思路。 还有一条不显眼但重要：Agent 开始承担风险检查和修复。漏洞赏金技能包把 681 份公开报告整理成可复用的打法；App Store 拒审清单在上传命令执行前就拦下来；OpenSRE 自己读日志、提假设、定位根因，直接推修复 PR 等人审。除了往前冲，也开始管风险。 一句话：这波热闹不在模型变强，而在 Agent 的手脚和工具链被补齐了。

### [elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)

 `Python` ⭐ +1,608 今日新增 · 26,472 总星数

> 给 Claude Code 等 AI agent 装的漏洞赏金「技能包」：85 个技能、58 个 hunt-* 分类，把 681 份公开披露报告整理成可复用的打法。现在火是因为 Claude Code 插件市场刚开、Agent Skills 成了跨工具标准。

**亮点**

- 用「已披露报告」当少样本知识库，而不是让模型自由发挥：先给定真实报告里的模式再让它推理，输出更贴近实际能拿赏金的思路，同时用引用标注压住幻觉。
- 内置「出报告前先自我否证」的环节：7-Question Gate 追问这个洞到底能不能利用、VRT 映射定严重性、OOS 驳斥话术、PII 脱敏。同类工具基本只管打，不管提交质量。
- 把 2024–2026 的企业边界链写进技能：M365/Entra、Okta、vCenter、SSL-VPN 设备、SharePoint（ToolShell）、云 IAM，以及拿到凭据之后的横向升级路径。

**核心功能**

- 把 681 份 HackerOne 公开报告拆成 24 个漏洞类、58 个 hunt-* 技能，每个技能带检测点、payload、WAF 绕过表、链式利用模板；其中 433 条标了原始报告出处，可以逐条回查，避免模型胡编。
- 靠 SKILL.md 里写的 description 做语义匹配自动加载：用户只说「在测 acme.com，跑 recon 排一下攻击面」，相关技能就自己挂上，不用记命令名，模型也不会一次塞进 85 个技能撑爆上下文。
- 通过 MCP 接两个外部系统：Burp Suite（拿真实代理流量）和 HackerOne API（查自己提交过的报告、搜重复、读 program scope），把范围数据和实际请求喂给模型，而不是让它凭空猜。
- 一份 SKILL.md 用安装脚本复制到 5 个 agent 的技能目录（Claude Code / OpenCode / Codex CLI / Hermes / AntiGravity），知识层通用，斜杠命令和 hunt 流程只留 Claude Code。

**适用场景**: 独立漏洞赏金猎人和小团队红队，在 HackerOne/Bugcrowd 的授权项目或 DVWA、Juice Shop 这类练习靶场上，走「recon → 排攻击面 → 按漏洞类打 → 写报告」这条流程。也适合刚开始做赏金、需要照着成熟套路走一遍的人。

**竞品对比**: 和 PentestGPT 这类「让 agent 自己跑扫描」的工具不同，它不执行攻击，只给 agent 灌打法知识和范围纪律；和 Payloads All The Things、HackTricks 这类静态知识库比，它的内容按技能组织、能被 agent 按场景自动调用，还带报告引用和 Burp/HackerOne 数据接入。

**成熟度**: 早期内容型项目，装上能用，但技能正确性靠作者人工整理、没有回归测试；当「懂行的副驾」用可以，别当自动化扫描器，且只在授权范围内跑。

**趋势信号**: Claude Code 插件市场 2025 年 10 月刚上线、Agent Skills 被多个 agent 工具采纳成通用格式，正好赶上「给 agent 装专业知识包」这波；再叠加 SharePoint ToolShell 等企业边界漏洞在 2025 年持续被利用，红队向的技能包需求被拉高。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +922 今日新增 · 328,547 总星数

> 给编码 Agent 装一套开发方法论：先访谈需求出规格，再拆计划，派子 Agent 分头实现并互审，兼容十几种 CLI。

**亮点**

- bootstrap 提示词在 SessionStart 注入，上下文压缩后再注入一次——专门解决长会话被压缩后 Agent 忘掉方法论的问题。Hermes 没有压缩后钩子，作者直接在文档里承认这种会话会失效，让你重开会话
- 把“先想清楚再动手”做成了默认行为：Agent 看到你要建东西时不会直接写代码，而是先问清楚目标、分块确认设计，再派子 Agent 执行

**核心功能**

- 技能包就是一批带 description 的 Markdown 提示词，Agent 按描述自己匹配触发，不用手动敲斜杠命令
- 子 Agent 驱动开发：每个任务丢给一个上下文干净的 subagent 去写，主 Agent 验收、review 后再放行下一个任务，避免长会话里上下文越滚越脏
- 同一份技能打包成 17 种 harness 的插件格式：Claude 插件市场、Gemini extension、Cursor /add-plugin、Codex/Grok/Copilot 官方市场，装法不同但内容同源
- 流程强制先出 spec 再写码：需求访谈→分块给你签字→出实施计划（明确要求红绿 TDD、YAGNI、DRY），签字后才允许动代码

**适用场景**: 用 Claude Code、Codex、Cursor、Gemini CLI 这类工具跑几小时长任务的开发者，尤其是想让 agent 自主推进又怕它跑偏的人；团队也可以拿它当统一的开发流程模板。

**竞品对比**: 对手是手写 AGENTS.md/CLAUDE.md 规则、GitHub spec-kit、BMAD-METHOD 这类方法论提示词包。最大差异是不绑单一工具，靠各家插件市场一次性铺到十几个 CLI，而且技能自动触发、不需要你记得去调用。

**成熟度**: 已经有商业支持邮箱和多 harness 官方市场上架，说明不是玩具；但本质仍是提示词工程，不同 harness 行为不一致，API 和技能内容还在快速调整。

**趋势信号**: 编码 Agent CLI 集体开放插件市场（Claude、Codex、Cursor、Copilot、Gemini、Grok、Kimi、Qwen），加上长任务和子 Agent 编排成了当下焦点，一个仓库全适配自然被顶上来。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +822 今日新增 · 211,861 总星数

> Firecrawl 把网页抓取成干净 markdown 喂给 AI Agent，现在新增 Rust 单二进制本地版和 MCP 一键接入，无需数据库和容器，云版再补搜索和 550+ 数据源。

**亮点**

- 本地跑抓取但把搜索和 Alexandria 回落到云，结果里用 `source: firecrawl-cloud` 标出来源，用户能一眼看出哪条数据出了本机；不想连云就 `FIRECRAWL_CLOUD=off` 全本地
- Keyless 模式：MCP、CLI、API 不注册不填 key 每月 1000 credits，把试用摩擦降到几乎为零，这是拉新的主要手段

**核心功能**

- 本地版用 Rust 写成单个二进制，自带抓取/爬取/站点地图功能，不需要数据库、队列或 Docker，一条 cargo install 就能跑
- JS 渲染复用本机已装的 Chrome/Chromium，PDF 和 Office 文档也在本地解析；没有浏览器时静态页照跑，需要渲染的页面会返回 warning 而不是报错
- `firecrawl-local init` 会自动扫出 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 的配置文件，先备份再写入 MCP server 条目
- `serve` 在本机 3002 端口起一个兼容 Firecrawl v2 的 API，官方 SDK 只改 api_url 就能指过来，本地路由不需要 API key

**适用场景**: 给写 Agent 的开发者用：Cursor/Claude Code 里让模型直接读文档站、竞品页面或 PDF；也可自托管给需要数据不出内网的团队做 RAG 语料抓取。

**竞品对比**: 同类有 Jina Reader（只做单页转 markdown）、Crawl4AI（Python 库，要自己搭环境）、Apify/Browserbase（偏托管浏览器和爬虫平台）。Firecrawl 的差异是同一套 API 既能本地单机跑又能切云，且直接铺到 MCP 客户端里。

**成熟度**: 成熟，v2 API 稳定、云服务商业化运营、社区和贡献者规模大，自托管路径文档齐全，生产可用。

**趋势信号**: MCP 成了 Agent 接工具的事实标准，各家客户端都在抢数据入口，Firecrawl 用 Rust 本地版 + 免注册 keyless 正好卡在这个窗口。

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +151 今日新增 · 12,979 总星数

> Intel 开源的推理部署工具箱，把 PyTorch/TF/ONNX 等模型转成统一中间格式，再在 Intel CPU、核显、独显和 NPU 上跑，主打端侧和 AI PC 上的本地推理。

**亮点**

- 真正把 NPU 当一等公民：不只是 CPU/GPU，Intel 的 NPU 有独立的编译路径，这是很多推理框架还没跟上的部分
- 同一套 IR 跨 CPU、iGPU、dGPU、NPU 部署，硬件换代不用重写推理代码，靠 core.compile_model\(model, 'NPU'\) 这种一行切换

**核心功能**

- 模型转换走 ov.convert_model：把 PyTorch、TensorFlow、ONNX、PaddlePaddle、JAX 的模型直接读成 OpenVINO IR（一种内部的算子图格式），部署时不再需要原框架和 Python 训练环境
- 运行时按设备做图级优化：算子融合、常量折叠、内存复用，再针对 CPU（x86/ARM）、Intel 核显/独显、NPU 分别生成执行代码，同一份 IR 换个设备名就能跑
- 配套 NNCF 做训练后量化，支持 INT8 和 LLM 常用的 4-bit 权重压缩，把大模型塞进笔记本内存；GenAI 子项目提供带 KV-cache 和连续批处理的 LLM 文本生成流水线
- 通过 Optimum Intel 直接吃 Hugging Face Hub 上的 transformers 和 diffusers 模型，一行 from_pretrained 就能换后端

**适用场景**: 做 AI PC 和边缘设备的开发者——在搭载 Intel Core Ultra 的笔记本上用 NPU 跑本地大模型、Whisper 语音转写；工业视觉团队在无 GPU 的 x86 工控机上部署 YOLO 质检模型；也在需要 C++/C 接口嵌进现有产线软件的场景里用。

**竞品对比**: 对 ONNX Runtime 是直接竞争，两者都能跑 ONNX，但 OpenVINO 对 Intel 硬件的调优更细，尤其是核显和 NPU；对 NVIDIA 的 TensorRT 是错位竞争，TensorRT 只吃 N 卡，OpenVINO 主打没有独显的 x86 机器；对 llama.cpp 这类纯 LLM 推理器，OpenVINO 覆盖面更广（视觉、语音、传统模型都管）。

**成熟度**: 生产可用，Intel 官方长期维护，版本已到 2026.0，文档、Notebook 示例、多语言 API 齐全，企业落地案例多。

**趋势信号**: AI PC 铺开后 Intel Core Ultra 的 NPU 成了标配硬件，开发者要找能真正调用 NPU 的推理栈，加上文档已切到 2026 版本、GenAI 子项目补上了 LLM 支持，关注度被抬起来。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +146 今日新增 · 33,701 总星数

> NGINX 官方开源仓库，一个 C 写的高性能 Web 服务器/反向代理/负载均衡器。它解决的是「一台机器扛住海量并发连接」的问题，现在是运维和网关的默认基础设施。

**亮点**

- 进程模型和事件模型的取舍很克制：不用多线程加锁去榨性能，而是用多 worker 加共享内存，把并发问题挡在架构层外面，所以十几年来单机稳定性一直在线。
- 配置即接口：所有能力通过文本配置里的 directive 暴露，模块决定可用指令集，这套设计让它能被 Ansible、Helm、各种 Ingress Controller 用模板批量生成，生态才铺得开。

**核心功能**

- 事件驱动的多进程模型：一个 master 进程管配置和 worker 生命周期，多个 worker 各自跑一个异步非阻塞事件循环（Linux 上是 epoll，BSD 上是 kqueue），单个 worker 能同时挂住上万条连接，不需要一连接一线程。
- 模块化拆分：核心功能全在模块里，静态模块编译期链接进二进制，动态模块编译后靠 load_module 在配置里按需加载，第三方模块（如 lua、brotli）不用重新编译整个 nginx。
- 用共享内存 zone 跨 worker 同步状态：限流计数、连接数、缓存索引都放在共享内存段里，所以 limit_req 能对同一个客户端在所有 worker 上统一计数，而不是各算各的。
- 配置热加载：nginx -s reload 时 master 重新解析配置、拉起新 worker、让老 worker 处理完存量连接再退出，连接不中断，配置也不会写坏就全崩。

**适用场景**: SRE 和运维拿它做入口层：TLS 终止、静态资源服务、反向代理后端服务、做限流和缓存。K8s 里 ingress-nginx 是它最常见的用法，传统机房则常放在 HAProxy/LVS 后面当七层网关。

**竞品对比**: 对手是 Caddy（自带自动申请 HTTPS 证书，配置只有几行但性能与模块生态不如它）、Envoy（云原生 L7 代理，靠 xDS 做动态配置，更适合服务网格，但学习成本高）、Traefik（自动发现容器服务）。最大差异是 NGINX 配置是静态文件、改动靠 reload，动态能力弱，但性能、模块数量和运维人员的熟悉度仍是优势。

**成熟度**: 生产就绪，十几年大规模验证，BSD-2 协议，stable（1.28）和 mainline（1.29）双轨发布，文档完整，F5 提供商业支持。

**趋势信号**: 官方开发仓库从 Mercurial 迁到 GitHub 后，代码、issue 和 PR 都集中到这里，加上主线版本持续更新（HTTP/3、新指令），开发者顺手 star 的多了。

## 趋势观察

今天的热榜，一半是在给 AI Agent 装零件。技能包、插件、CLI 封装、MCP 接口，都在做同一件事：把 Agent 从“会聊天”改造成“能干活”。 趋势有几条很明确。第一，标准正在抢跑。Agent Skills、MCP、Cursor 的官方 manifest，都想让同一套东西在 Claude Code、Cursor、Codex 上通用。谁定接口，谁就先占位。第二，大厂开始把自家能力拆开，供 Agent 调用。Google 把 Stitch 的设计能力做成技能，Intel 把推理工具箱摊开，Firecrawl 直接给个 Rust 单二进制，不要数据库也不要容器。第三，开发者不再迷信大模型。3 块钱、单卡 3090、两小时训完的教程能被顶上来，说明大家关心的是能不能读懂、跑得起、改得动。本地优先、可自托管、免部署，都是同一个思路。 还有一条不显眼但重要：Agent 开始承担风险检查和修复。漏洞赏金技能包把 681 份公开报告整理成可复用的打法；App Store 拒审清单在上传命令执行前就拦下来；OpenSRE 自己读日志、提假设、定位根因，直接推修复 PR 等人审。除了往前冲，也开始管风险。 一句话：这波热闹不在模型变强，而在 Agent 的手脚和工具链被补齐了。
