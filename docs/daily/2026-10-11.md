### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +25,793 今日新增 · 78,163 总星数

> 把 Hopper/Ghidra/IDA 等逆向工具包装成 MCP 服务，让 AI Agent 直接分析二进制、Electron 应用和 EVM 字节码，看懂别人的功能再自己实现。

**亮点**

- 不自己造反汇编引擎，直接复用用户已有的 Hopper/Ghidra/IDA 授权和安装，setup 时可选择代装 Hopper，绕开了自研引擎的成本和许可问题
- setup 不只注册 MCP server，还会往 Agent 里写入配套的逆向工作流指令，让 Agent 知道按什么步骤追问和验证，而不只是拿到一堆工具

**核心功能**

- MCP 协议接入，把用户已装的 Hopper、Ghidra 或 IDA 当后端 provider 调用，自己不实现反汇编器；而 JS/Electron 静态分析完全不需要这些引擎
- JS/Electron 分析输出模块、import、source map、路由和 IPC 边界；原生二进制输出伪代码、汇编、字符串、符号、调用与引用
- 每条结论都附带证据和已知局限（evidence + limitations），Agent 能分清哪些是实测结果、哪些是推测
- 同一套能力也能脱离 Agent 用 CLI 跑：ELF 节/段布局靠 pwntools，EVM 字节码推断 dispatch selector、字节偏移和参数可变性，Linux 崩溃记录还原每个线程的寄存器和信号

**适用场景**: 想抄竞品功能的产品和工程团队：在 Claude Code、Codex、Cursor、Gemini CLI 里让 Agent 调 REA 分析目标 App，拿到实现思路后直接写进自己项目。也适合做安全研究和漏洞分析的人。

**竞品对比**: 对比 GhidraMCP、IDA Pro MCP 这类单后端封装——那些只能把一个反汇编器接给一个 Agent；REA 是多后端抽象层加统一证据格式，一份接口横跨原生二进制、JS/Electron、EVM 字节码和崩溃转储。

**成熟度**: 早期项目，有 CI 和 19 种语言的文档、Discord 社区，但官方明说版本变化快，CLI 和 API 可能随时调整，不建议直接依赖。

**趋势信号**: MCP 已经成了 Agent 接外部工具的事实标准，加上终端 Agent 普及，'让 Agent 自己逆向'成了新玩法，同类的 Ghidra/IDA MCP 封装最近集中冒头；不过一天涨 2.5 万星、占总星数近三分之一，这个增速更像爆款传播而非正常增长。

### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5)

 `C++` ⭐ +5,805 今日新增 · 27,423 总星数

> 把 PS5 可执行文件重新链接成 Linux/Windows 原生程序：不做硬件模拟，靠自己重写的 PS5 系统库加着色器转 SPIR-V，让游戏直接在 PC 上跑。

**亮点**

- 遇到未实现或没见过的状态直接抛 std::runtime_error，把 what() 打到 stderr 后结束进程。宁可崩溃也不猜一个返回值继续跑，避免出现静默的错误行为。
- 用回链接（relink）+ 系统库重实现替代指令级模拟：省掉了模拟 CPU/GPU 的开销，代价是每个系统函数都得手写。

**核心功能**

- relinker 把 PS5 可执行文件转换成目标平台的原生格式（ELF/PE），游戏二进制直接链接到本地重写的系统库，没有虚拟机、没有额外的运行时进程。
- core/libs/prx 逐个重写 PS5 系统库（PRX 类似 Windows 的 DLL，是 PS5 上以动态库形式提供的系统模块），进度按已声明的函数比例公开上报。
- 着色器重编译器把 PS5 GPU 的着色器翻译成 SPIR-V（Vulkan 用的跨平台图形中间格式），并在开启 ANYPS5_ENABLE_SPIRV_TOOLS 时用 Spirv-Tools 校验输出是否合法。

**适用场景**: 想在自己 Windows/Linux 电脑上玩 PS5 游戏的人，以及做游戏保存（preservation）和互操作性研究的开发者。目前实测能跑的只有 Dreaming Sarah 这类 2D 小游戏，GTX 1050 Ti / i5-7500 上稳定 60fps。

**竞品对比**: 和 shadPS4、RPCS3 这类模拟器方向完全不同：那些是模拟主机硬件和系统调用，AnyPS5 是把游戏二进制改造成原生程序。好处是性能接近原生，坏处是兼容游戏数量少得多，系统库要一个个补齐。

**成熟度**: 早期项目，仅验证了极少数游戏，仓库自己列了 TechnicalDebt 文档，兼容性和接口都不稳定，不建议普通用户指望它当日常工具。

**趋势信号**: PS5 兼容/模拟圈热度正高，而这是少见的『零模拟、纯重链接』路线，本身就是个话题点；单日近 6000 星的脉冲大概率来自某次外部曝光，仓库里没写具体原因。

### [storytold/artcraft](https://github.com/storytold/artcraft)

**亮点**

- 服务端和桌面客户端放同一个 Rust 仓库，等于把「云端算力」和「本地算力」当成同一个引擎的两种部署形态，而不是两套代码。
- README 里写「Turning memes into dreams」，说明团队是从做社区梗图/短视频工具起家，现在把同一套引擎转向严肃创作工具，属于产品线升级而不是从零起盘。

**核心功能**

- 一个 Rust monorepo 里同时产出「API 服务」和「可下载客户端」两条产品线，核心逻辑只写一遍，桌面端和服务端共用同一套引擎代码，不是前端 + Python 脚本的拼盘。

**竞品对比**: 和 ComfyUI 比，ComfyUI 是 Python 写的节点式 Stable Diffusion 前端，靠社区节点生态堆功能，装起来麻烦；ArtCraft 用 Rust 写底层，更像一个能直接装机分发的成品。和 Adobe Firefly、Runway 比，差异是本地跑 + 流程可控，而不是云端按次调用。

**成熟度**: 早期项目，今天单日暴涨 3200 star 属于典型发布日传播，正式版本号和 API 稳定性还没验证，不建议直接压生产流程。

**趋势信号**: 今天单日 3222 star，是典型的团队新作发布日病毒式传播；叠上 Rust + 生成式媒体这波热度，以及 Storyteller 本身已有的社区用户基础。

**亮点**

**成熟度**: 官方维护、文档清楚，但形态还早期——插件没有版本号、目录 schema 可能变，实质是 markdown 提示词集合，翻车风险低但实际效果取决于底层模型和各家 MCP 连接器的成熟度。

**趋势信号**: 赶上 Claude Cowork 上线推广期，加上 Anthropic 官方亲自开源一个「岗位插件市场」，等于在给 MCP 生态做示范——证明这套协议不只是给程序员接工具用的。

### [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master)

 `Python` ⭐ +461 今日新增 · 59,696 总星数

> PPT Master 把文档或一个主题交给 AI，直接生成可编辑的原生 PPTX——带母版、原生形状、真图表和动画，工作流跑在你自己的 AI 工具里，数据不出本机。

**亮点**

- 把 PowerPoint 本身当渲染后端，自己只负责'内容 → OOXML 原生对象'的映射，靠这个避开了同类工具导出图片后没法编辑的通病。
- README 里排满了 Kimi、PackyCode、APIKEY.FAN、RunAPI、APIMart 的邀请返佣链接——项目靠 LLM API 中转商的联盟分成养活，这是个很直白的开源变现样本。

**核心功能**

- 输出的是真正的 PPTX 原生对象：用幻灯片母版、原生形状和绑了数据的图表/表格，而不是把每页渲染成图片或纯文本框贴上去，所以生成完还能在 PowerPoint 里改字、改数、调动画。过渡和 Morph 动画也走 PowerPoint 原生能力。
- 它不是独立 App，而是一套跑在 Claude Code、Codex、Kimi 这类 Agent 工具里的工作流：Agent 读你本地的 PDF/DOCX/网页，在本机生成文件，因此不绑某一家模型、资料不往第三方平台传。
- 生成分两步走：先把内容梳理成有论证结构的叙事骨架，再做版式和视觉设计，不是让模型一上来就堆排版。同时支持吃进你自己的 .pptx 模板复用母版版式，并能把演讲者备注用 TTS 转成音频旁白。

**适用场景**: 适合需要按公司固定模板出正式 deck 的人：咨询/投行分析师、企业市场部和财务做季度汇报、技术讲师把论文或长 PDF 转成讲解稿。也适合不想把内部资料上传到在线 PPT 生成 SaaS 的团队。

**竞品对比**: 和 Gamma、AiPPT、讯飞智文比，那些在线工具导出常是图片或受限编辑，PPT Master 走原生 OOXML 对象并复用你自己的母版；开源侧 Presenton 偏自托管一键生成、Slidev 是 Markdown 转静态网页，都不强调 PowerPoint 原生母版和动画深度。

**成熟度**: MIT 协议、近 6 万星、示例页和赞助商齐全，属于可用状态；但它本质是跑在别人 Agent 上的工作流而非库，没有 API 稳定性包袱，实际产出质量高度依赖你接的模型和模板。

**趋势信号**: Agent Skills 这类'把工作流塞进 AI 编程工具'的用法正在起飞，加上 Kimi K3（主打百万 token 上下文和原生视觉）刚发布并赞助了本项目，'长文档直接出可编辑 PPT'正好踩在这波点上。

> 把 Karpathy 对 LLM 写代码毛病的吐槽变成一份 CLAUDE.md，用四条纪律约束 Claude Code 和 Cursor，减少乱猜、过度设计和无关改动。

**亮点**

- 只用一个提示词文件，不加依赖、不改代码、不换工具，靠行为约束减少 Agent 乱假设、过度抽象和顺手改无关代码，可和现有项目规范共存。
- 直接引用 Karpathy 的观点把“目标驱动执行”落成测试优先循环：给成功标准，让 LLM 自己迭代验证，而不是每一步都靠人下命令。

**核心功能**

- 一份 CLAUDE.md 拆出四条可执行原则：先想后写、简单优先、外科手术式改动、目标驱动执行，每条都写清具体行为和判断标准，比如“200 行能压到 50 行就重写”“每个改动行都要能追溯到用户请求”。
- 支持两种安装：Claude Code 插件市场全局安装（/plugin marketplace add forrestchang/andrej-karpathy-skills，再 /plugin install andrej-karpathy-skills@karpathy-skills），或直接把 CLAUDE.md 追加到单项目；还提交了 .cursor/rules/karpathy-guidelines.mdc，让 Cursor 项目规则复用同一套约束。
- 把命令式任务转成可验证目标：不写“加验证”，改写“先写无效输入测试再让测试通过”；不写“修 bug”，改写“先写复现测试再修”，让 Agent 靠测试循环自己收敛。

**适用场景**: 用 Claude Code 或 Cursor 写代码的开发者与团队，在让 Agent 做多步重构、加功能、修 bug 时使用；也适合把规则合并进项目 CLAUDE.md，统一团队里 Agent 的改动纪律。

**竞品对比**: 和 Cursor Rules、Awesome Cursor Rules、各类 Claude Code 插件同类；最大差异是只聚焦 Karpathy 点名的四个编码坑，单文件、可追加到现有 CLAUDE.md，还附带 Cursor 规则，不绑定单一编辑器。

**成熟度**: 单文件提示词项目，MIT 许可，安装方式清楚，但效果随模型和项目变化，属可用但不保证生产一致性的早期方案。

**趋势信号**: Karpathy 发推批评 LLM 乱假设、过度设计、乱改代码，Claude Code 插件市场又让提示词类 skill 一键安装，社区顺势把推文做成可复用的 CLAUDE.md 并快速传播。

### [mksglu/context-mode](https://github.com/mksglu/context-mode)

 `TypeScript` ⭐ +178 今日新增 · 26,421 总星数

> context-mode 是一个 MCP 服务器，把 AI 编程助手读取的原始工具输出（Playwright 快照、日志、GitHub issue）挡在上下文窗口外，只把压缩后的结果喂给模型，号称能省 98% 的 token，同时用 SQLite 记住会话进度。

**亮点**

- 思想转变：把 LLM 当代码生成器而不是数据处理器。不读数据进上下文，而是写脚本在沙箱里处理，只回传结果，这一步理论上能带来 100 倍级别的上下文节省。
- 反潮流的一个取舍：明确拒绝在路由层里塞『回答要简短』这类的 prompt 约束，理由是过度的简洁提示会拉低编码和推理 benchmark（引用了 Moonshot 关于 kimi-k2.5 的 issue），只管道数据流向、不管道模型怎么说话。
- 会话隔离做得比较狠：不用 --continue 的话，上一个会话的 SQLite 数据立刻删除，避免陈旧记忆污染新任务。

**核心功能**

- 沙箱化工具输出：MCP 工具调用（如 Playwright 快照 56KB、20 条 GitHub issue 59KB）先落到沙箱里过滤，只把结果回传，README 里给的例子是 315KB 压到 5.4KB。
- 会话记忆用 SQLite 存事件（文件改动、git 操作、任务、错误），再建 FTS5 全文索引，压缩对话后用 BM25 相关性检索按需取回，而不是把历史一股脑塞回上下文。
- 『Think in Code』路由：不让模型把 50 个文件读进上下文再数函数，而是让模型写一段脚本去算、只 console.log 结果，一次 ctx_execute 顶十次 Read 调用。
- 跨 17 个平台的 hooks 强制路由：在 Claude Code 等支持 hook 的客户端注册 PreToolUse/PostToolUse/PreCompact/SessionStart 等 6 个钩子，运行时注入路由指令，不往项目里写文件。

**适用场景**: 重度用 Claude Code、Cursor、Codex 等编码 Agent 的开发者：跑 Playwright 截图、翻几十个 GitHub issue、查 access log 时，上下文半小时就被吃掉 40%，用它把这些脏数据挡在外面。 长会话的团队项目：对话被 compact 后 Agent 常忘记在改哪个文件、任务做到哪一步，它靠 SQLite + FTS5 把进度留住，恢复会话时只取相关片段。

**竞品对比**: 同一层级的对手是各家客户端自带的上下文压缩（Claude Code 的 /compact、Cursor 的上下文管理）和通用 MCP 记忆方案（如 mem0、各类 memory MCP server）。最大区别是它做在 MCP + hooks 这一层而非模型侧，且对 17 个平台都适配；但这也意味着它依赖客户端的 hook 能力，非 hook 平台要手动拷一次路由文件。

**成熟度**: 已上 Hacker News 第一（570+ points），有 npm/Discord/Marketplace 完整配套和 ctx-doctor 自检工具，README 挂了一堆大厂 logo，但采用 ELv2 许可证（非标准开源，商用有限制），版本未到 1.0，属于快速演进期。

**趋势信号**: 2025 年 AI 编码 Agent 全面铺开后，上下文窗口被工具原始输出吃满成了最普遍的痛点，加上 MCP 协议成为事实标准，把优化做在 MCP 层正好卡在生态爆发的位置，所以能一天涨 178 星、冲上 HN 榜首。

### [pytorch/pytorch](https://github.com/pytorch/pytorch)

 `Python` ⭐ +84 今日新增 · 104,190 总星数

> GPU 加速的张量计算库兼深度学习框架，用 tape 式自动微分兼顾灵活性和速度，是当下大模型训练与微调的事实标准底座。

**亮点**

- Python First 不是给 C++ 框架套一层壳：autograd、nn 模块直接长在 Python 运行时上，报错栈能指到用户自己那行代码，而不是框架内部的 C++ 图层
- 走的是 eager 优先 + 渐进编译路线：先让代码能跑能调试，需要性能时再局部 torch.compile，而不是像 JAX 那样一开始就要求纯函数式和静态 shape

**核心功能**

- torch.compile：把 Python 模型捕获成 FX 计算图，再交给 TorchInductor 生成 Triton（GPU）或 C++ 内核，不用自己写 CUDA 就能接近手写内核的速度；图捕获失败就自动回退 eager 执行
- 基于 tape 的反向模式自动微分：前向跑的时候记录算子，反向按记录回放，计算图每轮迭代重建，所以 if/while 这类动态控制流和变长输入直接支持
- 自带缓存式显存分配器（caching allocator）：一次性向驱动申请大块显存再切分复用，减少 cudaMalloc 调用和碎片；多卡训练靠 NCCL + DDP 做梯度同步

**适用场景**: 做模型的研究员和算法工程师：从 HuggingFace 上拉模型做微调、用 torchtitan 做预训练、写自定义层和 loss。用完导出到 vLLM、TensorRT 或 ExecuTorch 上做线上推理。

**竞品对比**: 对比 TensorFlow（现在主推 Keras 3）和 JAX：JAX 靠 XLA 编译、静态 shape 友好但调试和动态控制流绕；TF 生态重心已转向多后端。PyTorch 的差异点是动态图调试体验好，且 HuggingFace、vLLM、torchtitan 这些周边生态基本都先支持它。

**成熟度**: 生产就绪，2.x 系列持续维护，工业界训练和推理的主力框架，文档和社区响应都很成熟。

**趋势信号**: 84 stars/天 对 10 万星项目属于日常基线流量而非突增，近期关注主要来自大模型训练栈（torchtitan、torchao 量化）和 Blackwell、ROCm、Intel XPU 等新硬件后端的适配推进。

## 趋势观察

今天这份榜单指向一件事：AI Agent 正在从会聊天变成能干活。MCP 是最明显的信号。逆向工具、浏览器快照、图表绘制、岗位技能，都做成 MCP 或技能包，直接塞给 Agent。Agent 不再只生成代码，还能看二进制、翻日志、画图、做 PPT、跑流程。第二个信号是上下文变贵，大家开始省着用。context-mode 把原始输出挡在窗口外，只喂压缩结果，还用 SQLite 记进度。Karpathy 的吐槽变成 CLAUDE.md，Matt Pocock 做跨 Agent 技能包，都是在给 AI 编程立规矩：少乱猜，少啰嗦，少改无关代码。第三个信号是可控和本地优先。Storyteller 要可复现，PPT Master 要原生 PPTX 且数据不出本机，画图技能输出单个 HTML+SVG，PS5 重链接绕开模拟器直接跑 PC。开源项目不再只追模型参数，而是追工作流、工具链和交付物。底座也没消失。Flutter、TensorFlow、PyTorch、HuggingFace 还在榜上，说明跨端 UI、训练部署、模型加载仍是刚需。但新闻热点已经转向 Agent 周边：协议、插件、技能、记忆和约束。开发者生态正在把提示词、领域知识和工具调用工程化。谁能把 Agent 管住、用好、接进现有工作流，谁就拿到下一波效率红利。这个方向已经很清楚，接下来拼的是细节和可靠性。
