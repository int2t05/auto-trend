### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,085 今日新增 · 66,017 总星数

> Cloudflare 开源的安全审计 skill，把 coding agent 变成审计员：六阶段流程找漏洞，负责找和负责验的不是同一个 agent，只输出可复核的结构化结论。

**亮点**

- 靠角色隔离压误报：发现者永远不当验证者，候选漏洞必须被新 agent 正面推翻过才算数，而不是让模型自己说'这看着像漏洞'
- 多轮累加而非重复跑：复用上一轮的台账和 findings，只补缺口、重验改动过的源码，官方测试里单轮大约只找到重复跑能覆盖的一半漏洞

**核心功能**

- 六阶段流水线：侦察阶段先产出 architecture.md 和 coverage-ledger.json（覆盖台账，列出所有攻击面单元），再按台账单元分派 hunter，并用 coverage critic 专门找漏掉的攻击面，避免 agent 东一榔头西一棒子翻文件
- 对抗式验证 + 三档结论：每个候选漏洞交给全新 verifier 去证伪，最终结论再由另一个独立 agent 复核源码；认定分 confirmed / needs_validation / rejected，needs_validation 强制不带 severity，防止 agent 编造危害等级
- 零依赖 Node 校验脚本：validate-findings.cjs 和 validate-coverage-ledger.cjs 对着 report-schema.json 校验 findings.json 和台账，Phase 4 和 Phase 5 每次替换后都跑，字段不合规直接卡住
- 攻击类别拆成 9 份提示词文件，按目标类型选用：内存安全/二进制、LLM 提示注入与工具调用、Web 协议与鉴权、客户端 DOM、供应链与发布签名、云 IAM 与容器、RPC 与消息队列、资源耗尽、多租户数据隔离

**适用场景**: 安全工程师人手不够时先跑一轮全量初筛，把结果喂给渗透测试或 SDL 流程做 triage；开源维护者上线前自查鉴权、供应链、多租户隔离这些平时没人看的角落。

**竞品对比**: 和 Semgrep、CodeQL、Snyk Code 不是一类东西：那些是规则/查询驱动的确定性扫描，只覆盖预先写好的模式；这套靠 agent 推理去找没见过的漏洞类别，代价是结果不确定、必须人工复核，不能顶替 SAST 卡在 CI 里。

**成熟度**: 早期项目，没有版本号，本质是提示词 + 校验脚本的组合，产出质量高度依赖所用模型，官方自己承认单轮覆盖率只有一半左右。

**趋势信号**: Cloudflare 博客公开了内部漏洞挖掘 harness 的做法，顺手把这套 harness 的起点开源成 skill，正好撞上 Claude Skills、skills.sh 这类 agent 技能生态刚起步。

### [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot)

 `TypeScript` ⭐ +1,955 今日新增 · 17,271 总星数

> 开源版 Grok Bot：在一个聊天应用里管理一队 AI agent，每个 bot 直接在你机器上运行 Claude / Codex / Grok CLI，各带独立模型、独立虚拟机和独立应用授权，数据留本地。

**亮点**

- 把多 agent 编排做成通讯录：界面就是一个 Telegram 式聊天应用，侧边栏每个联系人都是一个活着的 agent，各自有独立线程记忆、独立模型和独立电脑。用户不需要学习 workflow 编排，像跟人聊天一样。
- 安全边界按平台分级认证，未认证的平台就关掉功能，比如 Wayland 的 host control 因为一个未解决的 issue 直接禁用，而不是“尽力支持”后留下隐患。这个取舍比多数同类项目严谨。

**核心功能**

- 每个 bot 实际上运行你本机已安装的 claude / codex / grok 命令行工具，复用你现有的登录和订阅，不经过中间代理；在 Settings → Engines 里可以改成指向自定义的 CLI 二进制文件（自编译版本或包装脚本）。
- 本地只启动一个小型 harness 服务，监听 127.0.0.1，统一管理所有 agent 子进程；会话记录、密钥、事件全部写入 ~/.openmausbot 目录，不上传云端。
- 执行环境分为三档：云端 Linux 桌面、隔离的本地虚拟机、以及直接操作你本机（需要显式授权）。最后一档目前只在 macOS 和 Ubuntu Xorg 上通过验证，Wayland 因为 issue #345 未解决而直接关闭该功能。
- 第三方应用接入使用 Composio 的 500+ 集成，走 OAuth 授权而非存密码；敏感操作会弹出审批卡，等人点确认。
- 技术栈是 Electron + React 19 + TypeScript（strict）桌面应用，macOS 是签名并公证的 .dmg，另有 Windows x64 安装包和 Ubuntu 24.04 的 .deb / AppImage。

**适用场景**: 适合已经有 Claude、ChatGPT 或 Grok 订阅、又不想再注册新账号的开发者，以及独立工作者。他们在桌面端让几个 bot 分工：一个写代码跑测试，一个查资料，一个操作 GitHub、Notion、Slack 这类 SaaS，关键时刻点确认卡片来审批。

**竞品对比**: 直接对标 Grok Bot、Meta Muse、OpenAI dots、Cue by Manus 这几款闭源个人 agent：它们通常绑定单一模型、跑在厂商云虚拟机上、还要指定套餐或邀请码。OpenMausBot 的差异是每个 bot 可以配不同模型、用你自己已有的登录、数据落在本地 ~/.openmausbot，并且是 Apache 2.0。

**成熟度**: 早期项目，但分发做得比较正规（签名公证的安装包、多平台构建）；功能上还有明显缺口，比如 Wayland 下的本机控制仍被禁用，API 和交互可能还会变。

**趋势信号**: 2026 年头七周里，Grok Bot、Meta Muse、OpenAI dots、Cue by Manus 四款闭源个人 agent 产品接连发布，并且都把模型、电脑和数据留在厂商一侧，开源替代位置空着，这个项目正好赶上这个缺口。

### [sherlock-project/sherlock](https://github.com/sherlock-project/sherlock)

 `Python` ⭐ +1,766 今日新增 · 101,035 总星数

> 输入一个用户名，它就并发去 400+ 社交网站查这个账号存不存在。用于 OSINT 信息收集和个人数字足迹自查。近期突破 10 万 star。

**亮点**

- 数据和代码彻底分离。400 多个站点的判定逻辑都是配置，社区贡献新站点只需提一个改 JSON 的 PR，这是它能长期维护住站点库的关键。
- 内置 Tor 和代理支持（--tor / --proxy）。批量探测几百个站点时不会把真实 IP 暴露给所有目标。
- 结果可直接导出 CSV / XLSX，方便接到后续的表格分析流程里。

**核心功能**

- 站点规则全写在 data.json 里：每个站点写清 URL 模板（用 {} 占位用户名）、判定方式、以及用户名格式正则。加新站点只改 JSON，不碰代码。
- 三种判断账号不存在的方式：HTTP 状态码（如 404）、页面里出现指定错误文案的正则、或请求被重定向到别的地址。有的站点还会误报，靠三条互补来降低。
- 用 asyncio + aiohttp 并发发请求，配合可配置超时和重试；站点多的时候几十秒跑完一轮，还会用每个站点的正则先筛掉明显不合法的用户名，省掉无效请求。

**适用场景**: 安全研究员和红队做目标信息收集时，用一条命令把某个用户名在各平台的账号全捞出来；普通用户也可以拿它查自己旧用户名在哪些站注册过，再挨个去注销。

**竞品对比**: 同领域有 WhatsMyName（同类用户名枚举，以 Web 端和 JSON 清单为主）和 Maigret（从 sherlock fork 出来，站点更多，还会抓页面上的用户名、全名等额外信息）。sherlock 的差异是更轻、纯 CLI、无多余依赖；要更多情报就得上 Maigret。

**成熟度**: 已到 0.15.x，10 万 star，长期有人维护，生产可用；但站点规则依赖各平台页面结构，平台一改版就会失效，得跟着更新数据文件。

**趋势信号**: star 数刚破 10 万这个里程碑，加上 OSINT 和“查自己数字足迹”的话题在社交平台上被反复传播，带来一波集中关注。

### [zed-industries/zed](https://github.com/zed-industries/zed)

 `Rust` ⭐ +1,114 今日新增 · 94,347 总星数

> 用 Rust 和自研 GPU 渲染框架重写代码编辑器，摆脱 Electron 卡顿；内置多人协作与 AI agent 编辑，由 Atom、Tree-sitter 作者打造。

**亮点**

- UI 层自己重写（GPUI）而非套壳 Web，把编辑器输入延迟压到接近原生，这是与 VS Code 最本质的区别
- 协作编辑是内核级能力而不是插件，文本合并、光标同步、冲突处理都由 CRDT 在底层完成

**核心功能**

- 自研 GPUI 框架把界面直接渲染到 GPU（Metal/Vulkan/DirectX），绕开 Electron 的 Web 渲染路径，大文件滚动和输入延迟明显更低
- 多人实时协同编辑做进内核，用 CRDT（无冲突复制数据类型）自动合并多人对同一文件的并发修改，不依赖外挂插件
- 用 Tree-sitter 做增量语法解析，改一个字符只重解析受影响的语法片段，语法高亮、折叠、跳转都基于这棵语法树

**适用场景**: 面向嫌 VS Code 卡顿、内存占用高的开发者，尤其在大仓库、大文件场景；需要远程结对编程或多人同时改一份代码的团队也会用。

**竞品对比**: 对比 VS Code（Electron + Web 技术栈）启动更快、内存更低、滚动更顺；对比 JetBrains 系启动更轻，但插件生态远不如前两者成熟；对 Neovim 是原生 GUI + 开箱即用协作。

**成熟度**: 已发布稳定版，macOS/Linux/Windows 均有安装包，由 Zed Industries 商业公司维护，提交频繁、社区规模大。

**趋势信号**: Zed 近期推 Agentic Editing 和 ACP（Agent Client Protocol，让外部 AI agent 接入编辑器的协议），可接 Claude Code、Gemini CLI 等；叠加 Windows 正式支持，带来这波 star 增长。

### [mattpocock/skills](https://github.com/mattpocock/skills)

 `Shell` ⭐ +1,100 今日新增 · 317,908 总星数

> Matt Pocock 把自己 .agents 目录里天天用的 AI 编码技能包开源了：一套小而可改的 SKILL.md 流程文件，装进 Claude Code / Codex / Copilot 等 agent 里，治「agent 干错活、话太多、代码跑不通」三个毛病。赶上各家 CLI 都开始支持插件市场，一键就能装。

**亮点**

- 明确反「流程框架」路线：BMAD、Spec-Kit、GSD 这类方案把整个开发流程接管过去，出问题难调试；这里只给小块可组合的技能，控制权留在人手里
- 把领域驱动设计里的「统一语言」搬给 AI：让 agent 先说「materialization cascade」而不是 20 个字的啰嗦描述，顺带让变量、函数、文件名一致，省 token 也让代码库更好导航

**核心功能**

- 技能就是一堆 markdown 流程文件（SKILL.md），不写代码、不封装框架，用户直接改文本就能定制，也能跨模型跨 agent 用
- 用 /grill-me、/grill-with-docs 让 agent 反过来追问需求，同时生成项目术语表（CONTEXT.md）和 ADR 决策记录，靠统一词汇压缩 agent 的输出长度和命名漂移
- /tdd 强制红-绿-重构：先写失败测试再改代码，配合静态类型和浏览器访问构成反馈回路；/setup-matt-pocock-skills 一次性问清 issue 追踪器、triage 用的 label、文档存放路径
- 按 agent 分别给出安装命令：Claude Code / Codex / Copilot 走各自 plugin marketplace 自动更新，Gemini CLI 和 cursor/windsurf/opencode 等走 npx skills 手动装

**适用场景**: 适合已经用 Claude Code、Codex、Cursor 写真实项目、但被「agent 自作主张改一堆文件」折磨的工程师。典型流程：开工前 /grill-with-docs 对齐需求并沉淀术语表，写码时 /tdd 推进，维护期用 /triage 按 label 分诊 GitHub/GitLab issue。

**竞品对比**: 对手是 BMAD、GitHub Spec-Kit、GSD 这类「重型 agent 工作流框架」，以及 SuperClaude、awesome-claude-code 这类提示词合集。最大差异是不接管流程、不改你的仓库结构，文件小到可以随手 fork 改写，代价是没有统一编排，得自己挑技能组合。

**成熟度**: 作者是 Total TypeScript 的 Matt Pocock，文档和安装路径写得很细，但内容是不断迭代的提示词而非有版本号的库，会跟着各家 agent 的插件规范变，按「可用的日常工具」看待而非稳定依赖。

**趋势信号**: Claude Code、Codex、Copilot CLI 近几个月陆续上线 plugin marketplace / skills 安装机制，agent 技能从散落 Gist 变成可分发的标准包，这个仓库正好是第一批按新规范打包、又一个自带 6 万 newsletter 订阅者的作者发的。

### [google/skills](https://github.com/google/skills)

 `Python` ⭐ +443 今日新增 · 23,513 总星数

> Google 官方把云产品文档和排障流程做成 Agent Skills 包，一条 npx 命令装进 Claude Code / Gemini CLI，让 agent 照着官方流程干活。

**亮点**

- 把云厂商最佳实践做成可安装的 agent 依赖，而不是网页文档。技能随仓库更新，agent 读到的是 Google 当前维护的流程，不会用过时的教程幻觉出命令

- 每个技能是一个目录，含 SKILL.md（带 frontmatter 的说明文件）+ 脚本和参考文件，遵循 agentskills.io 规范；agent 启动时只读一行描述，命中任务才展开全文，避免把几十万字文档塞进上下文
- 用 npm 生态分发知识：npx skills add google/skills 交互式选技能、选目标 agent、选项目级还是全局安装；npx skills update 批量升级并清理已废弃技能，让"提示词"像依赖一样可版本化
- 内容不是 API 文档搬运，而是按任务编排的端到端 runbook：GKE Node NotReady 排查、TPU MXLA 训练卡死分析、AlloyDB 混合检索选型、Gemini API 迁移 AI Studio 到 Agent Platform，每步带具体命令和判断分支

**适用场景**: 用 Claude Code、Gemini CLI、Cursor 的 SRE 和平台工程师，在配 GKE 集群、调 TPU 训练、搭 RAG 或做 GCP 上云架构选型时，让 agent 直接按 Google 自己的排障路径执行，而不是靠模型凭记忆猜 gcloud 参数。

**竞品对比**: 和 AWS 的 MCP servers、Azure MCP Server 路线不同：那些是把云 API 包成工具让模型去调，Google 这里是给模型一套流程和命令。差异是从"能调接口"变成"知道先查什么、再改什么"。

**成熟度**: Google 官方维护、技能数量多，但没有版本号、部分技能标注 Public Preview，属于快速迭代阶段，技能内容和目录结构都可能变。

**趋势信号**: Anthropic 推出 Agent Skills 规范后各家 agent 客户端陆续支持，skills.sh 这类注册表随之出现，Google 是第一个把整条云产品线打包成官方技能的厂商，踩在"给 agent 装知识"这个点上。

### [anthropics/skills](https://github.com/anthropics/skills)

 `Python` ⭐ +390 今日新增 · 188,925 总星数

> Anthropic 把 Claude 的 Agent Skills 官方实现开源了：每个技能就是一个带 SKILL.md 的文件夹，模型按需加载。还顺手放出了 Claude 文档能力背后的 docx/pdf/pptx/xlsx 四个生产技能，让开发者照着写自己的。

**亮点**

- 把「教模型做事」从一次性 prompt 变成可版本管理、可分发、可复用的文件资产，模型只在需要时读对应文件夹，这是个绕过上下文膨胀的实用设计
- 直接把生产环境在用的文档技能开源。这相当于把内部实现细节交出来当教学样本，比自己写一堆「最佳实践」文档有用得多

**核心功能**

- 技能的最小单位是一个文件夹加一个 SKILL.md，YAML frontmatter 只要求 name 和 description 两个字段，其余是给模型看的 Markdown 指令、脚本和资源文件，模型按需加载，不常驻上下文
- 开源了 Claude 产品里真实在跑的 docx / pdf / pptx / xlsx 四个文档技能（Apache 2.0），不是玩具 demo，是复杂技能的参考实现，比如 PDF 表单字段提取就是靠这类技能做的

- 把 StyleX 藏在编译产物之后——内部拿到原子 CSS 的体积和确定性，外部用户零迁移成本，这跟多数 CSS-in-JS 设计系统要求你接入其运行时/Build 插件是反着来的。

**核心功能**

- 样式用 StyleX（Meta 自家的编译期原子 CSS 库）编写，但发布的是预编译 CSS：使用者不用装 StyleX、不用配 Babel/PostCSS 插件，想覆盖样式直接传 className 用 Tailwind、CSS Modules 或纯 CSS 都行。
- 主题就是一组 CSS 自定义属性覆盖，换肤、改品牌色不用包装组件或 fork 源码；需要深入定制时用 swizzle 命令把某个组件的完整源码导出到项目里自己改。
- CLI 内置 `astryx docs` 子命令，把组件文档、模板、codemod 做成可查询的机器入口，并建议全局装一次，让任意目录下的 AI 助手都能拿到同一份组件参考。
- 组件的内部积木（hooks、子部件）直接导出，不锁在顶层封闭 API 后面，可以按任意层级组合。

**适用场景**: 适合有多个产品线、需要统一视觉和可访问性的中大型前端团队搭中后台；也适合用 Cursor、Claude Code 这类 agent 写 React 界面的开发者，让 AI 按固定约定生成组件而不是编造 prop。

**竞品对比**: 对标 MUI、Ant Design、Chakra UI、shadcn/ui。差异点是无样式锁定加面向 agent 的 CLI；但生态、第三方扩展和中文文档远不如 MUI/AntD，且硬性要求 React 19，存量项目升级成本不低。

**成熟度**: Beta 阶段，npm 包还在 1.0 之前，API 可能调整；但代码本身在 Meta 内部跑了 8 年、13,000+ 应用，稳定性和可访问性有底子，开源社区刚起步。

**趋势信号**: Meta 首次把内部最大设计系统对外开源，加上'agents 和人用同一套工具'的定位，正好撞上 2025 年 AI 编码助手大规模落地的节点。

## 趋势观察

今天的榜单就一个关键词：给 agent 发工作手册。 Anthropic 把 Agent Skills 官方实现开源了。一个技能就是一个带 SKILL.md 的文件夹，模型按需加载。这条线一开，别人马上跟上。Google 把云产品文档和排障流程打包成技能，一条 npx 装进 Claude Code。Cloudflare 做安全审计技能，六阶段流程，找漏洞的和验漏洞的还不是同一个 agent。Matt Pocock 把自己天天用的技能包也放了出来。Vercel 干脆写了个 Rust 命令行浏览器，让 agent 一条条敲 shell 命令读网页，读无障碍树，比截图省 token。 共同点很清楚：大家不再比谁的模型更聪明，开始比谁给 agent 配的说明书更靠谱。文档正在变成接口，流程正在变成代码。 第二个信号是分工。不是一个万能 agent 干所有活，而是一队各有模型、各有虚拟机、各有授权的 bot。质量靠角色隔离，不靠提示词祈祷。 第三，Rust 又赢一轮。Ruff 一个二进制替掉三个 Python 工具，快 10 到 100 倍。Tailwind v4 引擎用 Rust 重写。新编辑器也是 Rust 加自研 GPU 渲染，就是要甩掉 Electron。 还有一条暗线：绕开云。三星家电走局域网直连，不要账号。bot 数据留本地。上下文压缩把长对话折叠成分层摘要，100K 窗口跑月级会话，token 省五倍。省钱，也少依赖。 开发者生态正在从“写应用”转向“写 agent 能干活的说明书”。谁把流程、文档、权限理清楚，谁的 agent 就少犯错。这股风才刚开始。
