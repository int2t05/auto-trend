### [sherlock-project/sherlock](https://github.com/sherlock-project/sherlock)

 `Python` ⭐ +2,372 今日新增 · 102,216 总星数

> Sherlock 用同一个用户名批量排查 400+ 社交站点是否存在对应账号，适合 OSINT 和账号侦察，今天因 GitHub Trending 曝光走热。

**亮点**

- 每个站点带已占用/未占用样本用户名，CI 能自动发现站点改版导致检测规则失效。
- 数据驱动站点库加软 404 文案匹配，比单纯看状态码更抗站点改版。

**核心功能**

- 站点规则放在 JSON 里：每个站点配置 URL 模板、探测 URL、errorType（按状态码或错误文案判断）、regexCheck 和自定义 headers，加站点不用改核心代码。
- 用线程池并发请求多个站点，支持 --timeout、--proxy、--tor，单个站点超时或限流不影响整体扫描。
- 检测不只看 HTTP 200：能匹配页面错误文案识别“软 404”，并用 username_claimed/unclaimed 样本用户名做站点规则自检。

**适用场景**: 安全研究员、红队和渗透测试人员在信息收集阶段用同一用户名扫多平台；记者、反欺诈和品牌保护人员也用它核实账号是否同一人所有。

**竞品对比**: 同领域有 Maigret、Blackbird、Nexfil。Sherlock 知名度和站点库更大、CLI 简单；Maigret 站点更多，还支持递归搜索和更丰富的报告。

**成熟度**: 成熟但仍是 0.x 版本，站点规则靠社区维护，适合调查类使用，不适合当稳定 API 嵌入生产。

**趋势信号**: 原因不明：今天新增 2372 星，但未见近期重大版本或事件，可能是 GitHub Trending 曝光和 OSINT 话题传播带动。

### [meta/astryx](https://github.com/meta/astryx)

 `TypeScript` ⭐ +863 今日新增 · 15,399 总星数

> Meta 把内部用了 8 年、支撑 13000+ 应用的设计系统 Astryx 开源了：150+ React 19 组件，用 StyleX 写样式但外面还能用 Tailwind 覆盖，CLI 和文档专门为 AI 编程助手设计。

**亮点**

- 把内部设计系统的"约定"当成产品来做：所有组件的命名、prop、组合规则统一，并且明确说这样做的目的是让 AI 能预测没见过的组件怎么用——这是把 AI 可读性当成 API 设计约束，不只是加个 MCP server
- StyleX 的取舍很实在：内部用它拿到编译期原子 CSS 和类型安全，对外却把编译产物直接发成 CSS，把工具链成本转嫁给库作者而不是使用者

**核心功能**

- 样式用 StyleX 原子化编译生成，但以预构建 CSS 形式交付，使用方不用装 Babel/PostCSS 插件；覆盖样式直接传 className，Tailwind、CSS Modules、普通 CSS 都能用，不会被样式方案绑死
- 主题就是一组 CSS 自定义属性的覆盖，设计师改变量就能换品牌，不用 fork 组件源码或包一层 wrapper；官方给了 7 套现成主题（neutral、matcha、y2k 等）
- CLI 把组件文档、模板、脚手架、codemod 打包成命令（如 astryx docs、astryx component --list），AI 助手和人都读同一份参考；swizzle 命令能把某个组件的完整源码弹出到项目里自己改

**适用场景**: 中大型前端团队（尤其是已经用 React 19 的产品组）需要一个能改品牌、又不想被某个样式库锁死的组件库时用它；另外适合已经在用 Cursor、Claude Code 这类 AI 助手写页面的团队，因为 CLI 给 agent 提供了固定的查文档入口。

**竞品对比**: 对标的不是 shadcn/ui（源码复制模式），更像 MUI、Chakra、Ant Design 这类完整设计系统。最大差异是两点：主题靠 CSS 变量而非 JS theme 对象，覆盖样式不绑定自家方案；以及把 CLI + 文档当成 agent 接口来设计——MUI 和 Ant Design 目前都没有做到这个程度。

**成熟度**: 处于 Beta 阶段，公开 API 可能还会变；但内核在 Meta 内部跑了 8 年、覆盖 13000+ 应用，组件成熟度远高于版本号给人的印象。

**趋势信号**: Meta 刚把它从内部系统开源出来（带 facebook.com 的资源和 atmeta.com 文档站），加上"agent ready"正好踩在 2025 年各家都在给 AI 编程助手做组件库接口的节点上。

### [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)

 `Rust` ⭐ +812 今日新增 · 47,309 总星数

> Vercel Labs 出的浏览器自动化命令行工具，用 Rust 写成。把网页转成带编号的无障碍树文本喂给 AI agent，agent 一条命令一步操作，浏览器全程不关。

**亮点**

- 统一了「快照-操作-再快照」的循环：把页面状态做成可编号的短文本，操作靠引用定位，这是给 LLM 而不是给人用的接口，跟 Playwright 选择器那套思路不同
- 一个 Rust 单二进制按平台分发（npm 按 host 挑二进制，也有 Homebrew），同时能换引擎：默认 Chrome for Testing，也能接 Lightpanda、iOS 模拟器里的 Mobile Safari，或 Browserbase 这类云浏览器

**核心功能**

- 用无障碍树生成 snapshot，每个元素带 @e1 这种引用编号，agent 只读这一小段文本就能点击，不用解析整页 HTML，省 token 也省推理步数
- 首次命令拉起后台常驻 daemon，通过 Chrome DevTools Protocol 控制浏览器；浏览器在命令之间保持打开，每个 --session 一个独立 daemon，闲置一小时先存状态再退出
- 点击目标被遮挡、隐藏、禁用或在视口外时直接报错退出，不返回假的成功，逼 agent 重新拍快照再试
- 技能包和 CLI 版本一起发版：装到 agent 里的是个薄壳，运行时去拉 `skills get core`，保证说明书和实际命令对得上；另外自带 `mcp` 子命令起 MCP server

**适用场景**: 写 coding agent、自动化测试或网页抓取的团队。只要 agent 能跑 shell 命令（Claude Code、Cursor、Codex 这类），就能让它开页面、填表单、点按钮、截图、导 PDF。

**竞品对比**: 对标 Playwright MCP 和 browser-use。Playwright MCP 是 MCP 协议 + 选择器，browser-use 是 Python 库绑死自己的 agent 框架；agent-browser 是 CLI + daemon，任何能执行 shell 的 agent 都能接，不挑框架。

**成熟度**: Vercel Labs 实验项目，命令面已经很广、文档分章节写全，但 Labs 标签意味着 API 和命令可能随时调整，别当稳定接口用。

**趋势信号**: Claude Skills / skills.sh 生态刚铺开，加上 MCP 热度，Vercel Labs 同时押了 skills 和 MCP 两条路，赶上了 agent 需要「手」的这波需求。

### [ranxianglei/billion-context](https://github.com/ranxianglei/billion-context)

 `TypeScript` ⭐ +460 今日新增 · 4,911 总星数

> 一个插在 coding agent 和模型 API 之间的上下文压缩插件：把长会话按模型自己的判断压成分层摘要，让 10 万 token 窗口也能跑几天，token 省约 5 倍。

**亮点**

- 把上下文管理从 agent 内部搬到 API 代理层，和具体客户端解耦，一次适配 20+ 个 CLI/IDE agent，这是它能同时支持这么多工具的原因
- 把 prefix cache 命中率当成压缩质量的约束条件——很多压缩方案只看信息保留，它反过来要求压缩动作不能破坏前缀稳定性，否则省下的 token 全被缓存未命中吃掉

**核心功能**

- 作为透明代理放在 agent 和模型 API 之间，直接重写 Anthropic/OpenAI 的流式响应来压缩，客户端（Claude Code、Codex、Gemini CLI、Qwen Code 等 20 多个）不用改代码，一套 acp-kernel 全适配
- 压缩的时机和内容交给模型决定，生成多代分层摘要（hierarchical，一代套一代），不是到阈值就硬截断；训练-free，不需要微调任何模型
- 压缩策略要给 prefix cache 让路：健康会话的前缀缓存命中率保持 95–97%，压缩本身开销 ≤2%，并用 /acp、/acp-cache 命令查缓存归因，把缓存命中率当第一指标而不是 token 数

**适用场景**: 适合连着几天用 Claude Code / Codex 做大重构、长链路 debug 的开发者，按 token 付费又想避免反复 /compact 丢上下文；也适合拿 DeepSeek、Qwen 这类便宜模型配小窗口跑长任务的团队。

**竞品对比**: 对标的是 Claude Code 自带的 /compact 摘要、Cline 等 agent 内置的上下文管理，以及 bm25/embedding/embedding-rerank 这类 RAG 记忆方案（mem0、Zep 同类）。最大差异是不检索片段，而是让模型自己写可增量更新的分层摘要，且不像 RAG 那样每次重排前缀、破坏缓存；作者自测 LongMemEval-S 上 79.20% 比最好的 RAG 62.60% 高 16.6 个点。

**成熟度**: v0.1.x 早期版本，API 可能还会变，但已公开 4.5 个月、18.76B token、17 万次调用的生产数据和第三方基准，文档和中文 README 完整，社区有多个 QQ 群。

**趋势信号**: 长会话的 token 账单和窗口上限成了 coding agent 眼下最痛的点，各家内置 compaction 效果一般、RAG 记忆又破坏缓存，这个项目正好在 Claude Code / Codex 生态爆发的当口给出代理层解法，还顺手放了一份论文和 1500 条第三方评测。

### [dsx-ai-factory/nvke](https://github.com/dsx-ai-factory/nvke)

- Preview 阶段故意砍掉管理面自升级/自扩缩/备份恢复，先把"创建—扩缩—升级—换节点"这条工作负载集群生命周期闭环做出来

**核心功能**

- 自举建集群：先用一个临时 seed 集群拉起管理集群，管理面再通过 Cluster API + 自研 CAPNICo provider 向 NVIDIA Infra Controller（NICo，管裸金属机器的组件）申请 GPU 机器，拼成多个独立工作负载集群，每个集群有自己的 apiserver、etcd 和节点池

**适用场景**: 手里有 GPU 裸金属机房的平台团队或 GPU 云服务商：给内部算法团队或外部客户开 GPU 训练/推理集群，客户拿自己的 kubeconfig 用 kubectl 干活，运维方只管管理面。

**竞品对比**: 最接近的是 SAP Gardener（同样是元集群管一堆租户控制面）和自己拿 Cluster API 拼方案。差异在于它绑死 NVIDIA NICo 做 GPU 裸金属供给，节点入网走 TPM 证明，不是通用 IaaS 适配。

**成熟度**: Preview 早期项目，README 明说别上生产：API 默认无鉴权、明文 HTTP、管理面不能升级也不能备份恢复，API 和行为都可能变。

**趋势信号**: 踩在 NVIDIA DSX AI 工厂叙事上——GPU 不再只是卖卡，持有裸金属的一方想自己开"GPU 托管 K8s"卖容量，这类管理面就成了必需件。

### [anthropics/claude-quickstarts](https://github.com/anthropics/claude-quickstarts)

**亮点**

- MCP Server 示例把 Sessions API 包成 9 个工具，其中一个 `wait_for_idle` 把会话事件流压成一次同步请求/响应，让 Claude Desktop 或 Claude Code 能直接操作工作区里已有的 agent，并用白名单限制 bearer token 能碰到的范围

**核心功能**

- 电脑操作和浏览器操作的最小示例自己实现了协议驱动：一个直接手写 VNC 的 RFB 协议控制桌面，一个直接走 Chrome DevTools Protocol 控制单个标签页，都不套 Playwright 或 VNC 库，方便看清接口本身
- 《Computer Use Best Practices》示范了让电脑操作 agent 更省钱更可靠的做法：截图按需缩放和历史裁剪、prompt caching、服务端上下文压缩（compaction）、批量工具调用、沙箱 shell、完整轨迹录制
- Managed Agents 示例用声明式文件部署：`ant apply` 一份配置就定义好 agent、运行环境、两个 memory store、凭据 vault 和 cron 定时任务；聊天侧用 `event_deltas` 逐 token 推流，vault 凭据按 `injection_location` 注入到指定请求位置

**适用场景**: 面向准备接 Claude API 的开发者，拿来抄结构做具体东西：企业客服知识库机器人、财报数据分析、浏览器自动化表单填写、在 CI 里定时跑 Sentry 告警分诊、每工作日把 Slack 和 PR 汇总成一条简报。

**竞品对比**: 对标 OpenAI Cookbook、LangChain/LlamaIndex 的模板和 Vercel AI SDK 示例。差异是它只服务 Claude 自家新接口（computer/browser toolset、prompt caching、Managed Agents 会话），新 API 的可用示例往往只有这里有。

**成熟度**: 官方参考代码，多个子项目自己写明“不是生产代码”，适合学接口和抄架构，不适合直接上线。

**趋势信号**: 仓库新塞进一整批 Managed Agents 示例，加上带日期版本号的 `computer_toolset_20260801`／`browser_toolset_20260801` 工具接口，说明 Anthropic 刚发布托管智能体和新的电脑/浏览器工具协议，开发者涌进来抄接入代码。

### [google-deepmind/mujoco](https://github.com/google-deepmind/mujoco)

 `C++` ⭐ +26 今日新增 · 16,206 总星数

> DeepMind 维护的通用物理引擎，专门算多关节结构和接触，是机器人强化学习仿真的主力工具；MJX 分支用 JAX 重写后能上 GPU 批量并行训练。

**亮点**

- 把物理引擎写成 C 库加 XML 模型描述，Python、C#、JS/WASM 都只是薄绑定层，同一份模型在桌面、浏览器、Unity 里跑出来的结果一致
- 提供多线程 rollout 模块，一次调用并行展开多条轨迹，省掉自己写多进程采样池的活

**核心功能**

- 模型先由内置 XML 编译器一次性编译成预分配好的低层数据结构，仿真运行时不再申请内存，每一步只做纯计算，这是它跑得快的主因
- MJX 是用 JAX 重写的分支，跑在 XLA 上，能在 GPU/TPU 上同时并行几千个环境，并且整个物理步可自动求导，用解析梯度直接训练运动策略
- 接触用软约束（把碰撞当成可轻微穿透的弹簧约束来求解）而不是硬约束，所以数值更稳，抓取、足式落地这类接触频繁的场景不容易炸

**适用场景**: 做具身智能和机器人的算法团队，用 pip install mujoco 或在 Unity 里搭 Gym 风格环境，训四足/人形行走、机械臂抓取策略；生物力学和图形动画的人也用它算关节受力。

**竞品对比**: 对手是 PyBullet（免费好装但接触求解精度差，跑出来的策略迁移到真机常翻车）和 NVIDIA Isaac Gym/Isaac Lab（GPU 上更快，但绑死 NVIDIA 显卡和它那套生态）。MuJoCo 的差异点是接触仿真精度高，现在靠 MJX 把 GPU 批量并行这块补上了。

**成熟度**: 生产可用，3.x 版本按月发版，DeepMind 全职维护，文档和 Colab 教程齐全，学术论文和工业机器人团队都在用。

**趋势信号**: 人形机器人和具身智能这波热度带动，加上 MJX 让它在 GPU 上批量训练成为现实；不过今天只涨 26 星，属于长期基本盘热度而非突发事件。

## 趋势观察

今天这批项目，没几个在比模型谁更聪明，都在比谁能把活干完。共同点很明显：给 agent 修路。 一是上下文和记忆有人管了。那个压缩插件插在 agent 和模型 API 中间，把长会话按模型自己的判断压成分层摘要，10 万 token 窗口能跑几天，token 省大约 5 倍。这是真痛点，不是概念。 二是「怎么干活」开始有格式了。Anthropic 的 SKILL.md 加跨厂商规范，Meta 把用了 8 年的 Astryx 开源、CLI 和文档专门为 AI 编程助手写，Vercel 把网页转成带编号的无障碍树直接喂给 agent。大家都在给 AI 定接口，谁的格式先被采用，谁就先占位。 三是算力持有方想自己当云厂商。NVIDIA 这套 GPU 裸金属托管 K8s，让手里有卡的人按需发独立集群，每个带自己的控制面和 etcd。卖卡不如卖平台。 四是数据主权往回走。Grok Bot 类产品把模型、虚拟机、密钥全留在本机，通讯录里一排 bot，各干各的。企业还是不放心把东西交出去。 另外 Sherlock 这种批量查 400 多个站点账号的 OSINT 工具上榜，说明安全侦察也是刚需。 一句话：新闻里还在聊模型参数，开发者已经在铺管道、定规范、抢入口。谁能把 agent 的上下文、技能、执行环境这三件事捏到一块，下一轮就轮到谁说话。
