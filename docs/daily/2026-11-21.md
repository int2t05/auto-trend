# GitHub Trending 日报 · 2026-11-21

## 概览

今日共收录 **16** 个 GitHub Trending 项目。
主要语言分布：Python(7)、TypeScript(4)、Shell(2)、HTML(1)、C(1)。

今天这批热榜，几乎不是在造模型，而是在给 Agent 装手脚。第一类最扎眼：一堆「技能包」。渗透测试方法论、先问需求再写代码的开发流程、一句话出图表、并行搜十几个平台的简报，全被打包成 skill 文件。装进 Claude Code、Cursor、Codex，Agent 就多会一门手艺。第二类是接口。网页抓取工具直接注册成 MCP 服务器，Google 的设计工具也走 Stitch MCP，Cursor 官方插件让 Agent 连上 Gmail、Salesforce、GitHub。MCP 正在变成 Agent 接外部系统的通用插座。第三类是「让 Agent 真去干活」。CLI-Hub 给只有图形界面的软件套一层命令行，Agent 敲命令，不用截图点鼠标。CI/CD Agent 自动读失败日志、定位根因、提修复 PR。App 上架合规扫描器在提交前拦漏项。这是从「聊天」到「上手」的明显转折。另一条线是本地和便宜。MiniMind 用单卡 3090、约 3 块钱跑通完整训练链路，学原理用。Intel 把推理搬到自家 CPU、GPU、NPU，蹭 AI PC 的风。Ghost-Downloader 和 AutoClip 都主打本地、开源、替代收费 SaaS。合起来看，开发者生态的重心在挪：模型不再是主角，围绕 Agent 的「技能层、接口层、工具层」成了新的兵家必争之地。谁能把真实工作流拆成 Agent 能调用的干净接口，谁就先拿到下一波。热闹归热闹，这些技能包和插件最后拼的还是稳不稳、接得对不对。Agent 生态刚搭起脚手架，真正耐用的那一层还没定。

### [elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)

 `Python` ⭐ +1,622 今日新增 · 14,721 总星数

> 把 83 个渗透测试技能、681 份已公开的 HackerOne 漏洞报告模式和 15 个斜杠命令打包成 Claude Code 技能包，按话题自动加载，让 Claude 在授权范围内按红队方法论干活。

**亮点**

- 这里做的是知识与判断层，不是攻击执行层。skill 只提供方法论、检查清单和绕过思路，实际发包还是交给 subfinder、httpx、Burp 这些成熟工具，避免让大模型直接乱发请求。
- 用「7-Question Gate」和 VRT 分类做误报收敛：每条疑似漏洞先过一遍固定问题清单，再映射到 Bugcrowd VRT 严重性等级；这比让模型直接判断“这是高危”要可复现得多。

**核心功能**

- 58 个 hunt-* 技能按漏洞类型拆分，每类写成检测思路、payload、WAF 绕过表和利用链模板；你只要用自然语言说明正在测试的目标，Claude 就会自动匹配并加载对应技能，不用点名调用。
- 这些模式从 681 份已披露的 HackerOne 报告里提炼，其中 433 条单独标注了原始报告出处，可以回溯核对，目的是压低模型凭空编造漏洞的概率。
- 通过 MCP 接入真实工具：HackerOne MCP 拉取你账号下的私有项目范围，防止越界扫描；Burp MCP 把抓到的请求转给 Burp Suite 做拦截和重放。另有 cbh CLI（用 pipx 安装）和 hunt 目录脚手架，用来管理每次测试的产物。
- 四个层叠加：方法论层负责定流程，hunt-* 负责 web 漏洞，企业边界层负责 M365/Entra、Okta、vCenter、SSL VPN 设备的 CVE 链，交付层负责把漏洞报告写出。技能按 SKILL.md 格式写，同一份技能能同时安装到 Claude Code、OpenCode、Codex CLI、Hermes、Google AntiGravity 五个 agent 环境。

**适用场景**: 面向漏洞赏金猎人、外部红队和做 web 渗透的安全工程师：在授权的 HackerOne 项目或企业外部资产上做侦察、排序攻击面、找链式漏洞、写报告；也可以在 DVWA、Juice Shop 这类靶场练手。

**竞品对比**: 和 PentestGPT、hackingbuddyGPT 这类端到端自动渗透 Agent 不同，它不自己跑扫描循环，是给 Claude Code 挂载的领域知识插件。和 Burp、Nuclei 不是替代关系：那些是执行工具，它是让 agent 知道该在什么场景用哪把工具、怎么串成利用链。

**成熟度**: 早期偏成熟：安装脚本（macOS/Linux/Windows）、使用文档、可搜索技能目录、多 harness 指南都齐，但还没有正式版本号、单人维护，技能内容和斜杠命令接口可能继续变化；README 里的演示记录也标注为示意，不是真实会话。

**趋势信号**: Claude Code 的 Skills 机制刚开放不久，把垂直领域方法论打包成 skill 是目前最容易先落地的一类玩法；安全攻防又是社区公认的高关注场景，加上 AI 辅助挖洞在 HackerOne 上正被激烈讨论，热度被推高。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +1,241 今日新增 · 205,523 总星数

> 把网页抓成干净 Markdown 喂给 AI Agent 的工具。现在新增了本地单文件 Rust 版本，能一条命令注册成 MCP 服务器，给 Claude Code、Cursor 这些客户端直接提供抓取能力。

**亮点**

- 本地优先加云端兜底：默认在本机抓，本机加载不了的页面才回落到 Firecrawl Cloud，并在结果里标 `"source": "firecrawl-cloud"`，设置 `FIRECRAWL_CLOUD=off` 可以彻底切断外发
- 同一个 API 三种运行方式（本地二进制、自托管全量服务、云），本地模式复用系统浏览器，不用像其他方案那样打包一份 Chromium 镜像

**核心功能**

- Firecrawl Local 用 Rust 编译成一个二进制文件，不需要数据库、消息队列或 Docker；它直接调用本机已装的 Chrome/Chromium 渲染 JS 页面，没有浏览器时静态页面仍能抓，PDF 和 Office 文档也在本地解析
- `firecrawl-local init` 会扫描本机上的 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 的配置文件，逐个备份后写入 MCP server 配置，一次把这些客户端全部接上
- `firecrawl-local serve` 在本机 3002 端口起一个兼容 Firecrawl v2 的 HTTP API，本地路由免 API key，官方 Python/Node SDK 只要把 api_url 指过来就能直接运行
- 云端负责本地做不到的部分：搜索和 Alexandria（把 550+ 数据源统一到一个接口，用来补充抓网页之外的知识）走 Firecrawl Cloud，未登录也能用但限速

**适用场景**: 做 RAG 和 Agent 的开发者，需要把文档站、竞品网站批量抓成 Markdown 丢进向量库。另一类是给 Cursor、Claude Code 加联网抓取能力，但公司规定不能把内网 URL 发到第三方云服务的团队。

**竞品对比**: 对比 Jina Reader、Crawl4AI、Apify：Jina 只有托管接口，Crawl4AI 是 Python 库、要自己管浏览器进程，Apify 是托管的 Actor 市场。Firecrawl 的差异是同一套 API 既能本地单文件运行，也能自托管，还能直接当 MCP 服务器接入各种 Agent 客户端。

**成熟度**: 生产可用：20 万 star，有商业云服务、SDK 和基准测试支撑。但 Local 的 Rust 组件是新的，命令和配置细节还可能变。

**趋势信号**: 核心原因是 MCP：`init` 一条命令就把抓取能力塞进 Claude Code、Cursor 等客户端，直接受益于 MCP 生态这波爆发和 Agent 对实时网页数据的需求；同期推出免注册的 keyless 额度和 Alexandria，也在拉新。

### [XiaoYouChR/Ghost-Downloader-3](https://github.com/XiaoYouChR/Ghost-Downloader-3)

 `Python` ⭐ +1,082 今日新增 · 13,942 总星数

> Ghost-Downloader-3 是一个用 Python + Qt 写的跨平台下载器，把 HTTP、BT、M3U8、YouTube/B站解析、浏览器嗅探塞进一个原生客户端，主打下载协议集成和弱网提速。

**亮点**

- 没有采用 Electron + aria2 的常见组合，而是用 PySide6 自己实现多线程下载内核，Windows/macOS/Linux/Android 四个平台共用一套 Python 代码出安装包
- 任务状态可以完整序列化，下载过程中允许修改 URL、请求头、代理而不丢进度，这一点大部分下载器做不到

**核心功能**

- 分块后直接写入预先分配好的文件偏移位置，块下完就保存到磁盘，不用最后再拼一遍临时文件，省掉一次全量磁盘读写；分块数量根据实时带宽自动调整
- 请求时模仿真实浏览器的 TLS 指纹（ClientHello 里的加密套件、扩展顺序等特征），让 Cloudflare 这类反爬服务把它当成普通 Chrome
- 一套下载内核同时处理 HTTP/HTTPS、Magnet/BT、FTP、M3U8、MPEG-DASH、eD2k，再叠加站点解析层：YouTube/B站可选清晰度、字幕、多P、片段截取，GitHub/HuggingFace 走镜像加速
- 暴露 aria2 兼容的 JSON-RPC 接口，Motrix、AriaNg 这类现成前端可以直接连上来控制任务

**适用场景**: 适合经常下载大文件、BT 资源、网课和视频素材的人：普通用户拿它替代 IDM 或迅雷，B站/YouTube 内容创作者批量拉素材，Android 用户还能后台录 M3U8 直播流。

**竞品对比**: 和 IDM 比，IDM 只支持 Windows 且收费，协议也只覆盖 HTTP/FTP；和 Motrix、Aria2 生态比，它们主要依赖 aria2 作为下载后端，不负责解析站点，而 Ghost-Downloader-3 自带内核和站点解析；和 yt-dlp 比，它提供图形界面、BT 和普通文件下载。

**成熟度**: 已经到第 3 代，四个平台都有正式安装包，有 Crowdin 翻译、Discord/QQ 群和命令行工具，可以日常使用；但插件 API 还没公开，接口仍在变动。

**趋势信号**: 大概率是近期版本更新把浏览器嗅探、B站/YouTube 解析和 Android 录播组合到一起，因此被推荐上榜；具体触发事件不明。

### [zhouxiaoka/autoclip](https://github.com/zhouxiaoka/autoclip)

 `Python` ⭐ +979 今日新增 · 12,368 总星数

> AutoClip 是一个开源的桌面 AI 剪辑工具：贴入一个视频链接，它就能把播客、访谈、课程这类长视频自动切成竖版短视频，并同时生成字幕、封面和发布文案。它的火点在于用开源、本地渲染的方式，替代 Opus Clip 这类按订阅收费的剪辑 SaaS。

**亮点**

- 把“链接输入、成片输出”当作唯一主路径，中间不要求用户先做时间轴或关键帧操作，剪辑决策（选段、裁切、字幕断句）全部交给模型和规则；需要改时再进编辑器，降低首次使用门槛
- 以 MCP server 的形式分发剪辑能力，所以除了给人用的桌面版，还能被 Agent 当工具调用；在“AI 自动出片”这个方向，它比纯 GUI 工具多了一个可编程接口

**核心功能**

- 整条流程放在本机跑：Tauri 做桌面壳，Python 做后端，抓取视频链接、把语音转成文字（ASR）、用大模型挑选高光片段、竖版裁切、用 ffmpeg 渲染成片；只有 ASR 和大模型走云端并按 token 计费，视频文件不离开本地磁盘
- 面向成片效果的处理，而不是简单截取：字幕按平台的安全区重新分页（避免一句字幕被裁成两行），竖版裁切按人物取景来跟踪主体，而不是直接用画面中心裁剪
- 同一套核心提供了三个入口：桌面 GUI、CLI 和 MCP server（通过 Model Context Protocol 对接 Agent，让 Claude 这类助手直接调用剪辑能力）；批量的长视频走队列排队渲染

**适用场景**: 播客主、访谈类 UP 主、课程讲师和做矩阵号的运营团队需要把 1 小时的素材批量拆成十几条短视频，分别发到抖音、小红书、TikTok、Shorts 和 Reels；不想为每个片段支付 SaaS 订阅费，或者素材涉及版权、不愿上传到第三方云的人。

**竞品对比**: 对手是 Opus Clip、Klap、Vizard、2short.ai 和剪映的图文成片。最大差异是开源、本地渲染、免费且可被 Agent 调用；闭源 SaaS 的优势在于成片模型的调优和云端算力，AutoClip 的成片质量更依赖你接入的模型。

**成熟度**: 偏早期但能用的程度：MIT 协议、8 种语言 README、release 更新频繁，但字幕分页和长视频队列这类基础问题最近才修，输出格式和接口还会变，不建议直接压在生产流水线上。

**趋势信号**: 赶上了两个风口：一是播客、访谈切片做矩阵号的刚需，二是 MCP 生态爆发，让“剪辑工具”能作为 Agent 工具链的一环被分发；同时它直接对应 Opus Clip 的付费点，开源替代的叙事很容易在 Trending 上被转发。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +890 今日新增 · 322,999 总星数

> 一套给编码 Agent 用的开发方法论，打包成可组合的 skill 文件，装进 Claude Code、Codex、Cursor 等 17 种工具里，让 Agent 先问清需求、写完计划再动手。

**亮点**

- 不自己做 Agent 运行时，而是寄生在各家 harness 的 plugin/skill 机制上。结果是它能同时出现在 Anthropic、OpenAI、xAI 的官方插件市场里，这在同类工具里很少见。
- 把「计划好不好」的验收标准写死成一句话：一个没项目背景、不写测试的初级工程师能不能照着执行。这个标准直接决定了计划要多细，比泛泛说「清晰的计划」有用。

**核心功能**

- 整套东西就是 Shell 脚本 + Markdown 技能文件，不写自己的运行时。安装完全借用各家工具自带的插件市场（Claude 的 /plugin、Codex 的 /plugins、gemini extensions install、copilot plugin marketplace 等），同一份技能仓库适配 17 个 harness。
- 靠一个叫 using-superpowers 的引导技能，在会话启动的 SessionStart hook 里注入，上下文被压缩后再注入一次，因此技能会自动触发，用户不用手动喊。Hermes 没有压缩后的 hook，长会话就会失效，README 里直接说明了这个坑。
- 流程是硬的不是建议：先逼问出 spec，再分段展示给你确认，然后生成一份「给没上下文、没品味、不爱写测试的初级工程师也能照着做」的实现计划，最后起子 Agent 逐个任务执行、互相 review，强调真正的 red/green TDD 和 YAGNI/DRY。

**适用场景**: 日常用 Claude Code、Cursor、Codex 写代码的开发者，特别是想让 Agent 连续自主跑几个小时任务的团队。典型场景是 Agent 一上来就乱写代码、跑偏、不写测试，需要有人给它立规矩。

**竞品对比**: 对手是 BMAD-METHOD、GitHub spec-kit，以及各工具自带的 plan mode 和手写的 CLAUDE.md/AGENTS.md。最大差别是两件事：不绑定单一工具（spec-kit 绑 Copilot，BMAD 主要绑 Claude Code），以及流程是强制执行而不是给你一份规则文档自己遵守。

**成熟度**: 早期项目，靠 Markdown 技能驱动、没有版本号可参考，但已被多家官方插件市场收录并提供商业支持邮箱；上下文压缩后技能失效这类边界问题还靠文档提醒而非自动修复。

**趋势信号**: 赶上 Agent Skills 和插件市场这一波：Anthropic 推 Skills、OpenAI 和 xAI 接连开放插件市场，作者 obra（Jesse Vincent，RT 和 K-9 Mail 的作者）本身有号召力，加上大家被「Agent 乱写代码」折磨够了。

### [mjmirza/app-store-compliance](https://github.com/mjmirza/app-store-compliance)

 `Shell` ⭐ +869 今日新增 · 2,917 总星数

> 把 App Store / Google Play 拒审规则做成 Shell 扫描器加 AI 编码工具钩子，在提交前拦住隐私清单、权限声明这类高频漏项。

**亮点**

- 思路不是做一套 lint 规则让人记得跑，而是挂进 AI agent 的工具调用钩子，让上传命令直接执行不了——把合规从"人自觉"变成"跑不通"
- 全部用 Shell + Markdown 实现，零依赖、不装东西、不改你的代码，clone 下来一秒能扫，这也是它能塞进十几个不同编辑器钩子体系的前提

**核心功能**

- 扫描器是纯 Shell 脚本，读取 Info.plist 的用途字符串（NSCameraUsageDescription 等）、PrivacyInfo.xcprivacy 隐私清单、AndroidManifest 权限声明，命中就打印文件名和行号，并在最后一行输出 BLOCKED / CLEAR / NOT CHECKED 的结论，可直接作为脚本的判断条件
- 把 117 条拒审模式逐条对应到 Apple 审核条款编号和 Google Play 政策条目，每条下面附一行 fix 提示，一条一行的拒审邮件能直接对上是哪条规则
- install.sh 把同一个检查写成各工具的 hook：Claude Code、Codex CLI、Gemini CLI、Cursor、Copilot、Grok、Qwen、Kimi 等十余个工具各自的钩子机制，agent 一旦要跑上传命令就被拦下；Expo 托管项目没有原生目录时降级读 app.json / app.config 检查用途字符串

**适用场景**: 独立开发者和小团队在提审前自查，尤其是让 Claude Code / Codex 代跑 fastlane 上传的人。不写代码的产品或运营也能照预提交 checklist 手工走一遍。

**竞品对比**: fastlane 的 precheck 只查商店元数据（标题、描述、截图），不看你代码里实际调了哪些隐私 API；MobSF 这类偏安全漏洞扫描。它是少数直接查源码隐私声明与法规截止日期的。

**成熟度**: 早期项目，无 1.0 版本号，基本单人维护，规则准确性靠社区 PR 补，建议当检查清单用而非唯一依据。

**趋势信号**: AI 编码 agent 开始直接替人执行上传命令，社区需要一个能在工具调用前硬拦的钩子；同时 EU AI Act、DSA、各州年龄法的合规截止日期集中在 2025-2026 年落地。

> MiniMind 用 PyTorch 原生代码从零实现 64M 小模型的完整训练链路（预训练→SFT→LoRA→DPO→GRPO→Tool Use），单卡 3090 两小时、约 3 元就能跑通，适合学 LLM 内部原理。

**成熟度**: 官方仓库但规范很新，部分插件仍标 Beta，多数插件只有一行描述、缺详细文档，属早期阶段，清单格式和 SDK 接口都可能变动。

**趋势信号**: Cursor 正在把插件市场做成自己的 Agent 扩展标准，抢在 Claude Code skills 和 MCP 之上定义分发格式，今天涨星大概率是插件市场开放、官方批量上线第三方连接器带来的。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +246 今日新增 · 32,620 总星数

> NGINX 官方开源仓库：老牌 Web 服务器兼反向代理，用多进程加事件驱动扛住高并发连接。

**亮点**

- 配置是纯文本指令，reload 时不掐断连接：新 worker 按新配置起来，老 worker 把手上的请求处理完再退，线上改配置不掉连接
- 用多进程加共享内存绕开操作系统进程/线程模型的限制，进程崩一个不影响其他，也不需要锁住整个请求处理流程

**核心功能**

- master-worker 多进程模型：master 只负责读配置、管进程，worker 数按 CPU 核数起，每个 worker 单线程跑 epoll/kqueue 事件循环，因此不用为每个连接开线程
- 共享内存区（shared memory zone）：限流计数、缓存索引、连接状态放在共享内存里，多个 worker 进程读到的是同一份数据，这是限流能全局限流的前提
- 静态模块在编译期编译进二进制，动态模块用 load_module 运行时加载，nginx -V 可以列出当前二进制带了哪些静态模块，决定你能用哪些指令

**适用场景**: 运维/SRE 和 backend 工程师用它做站点入口：TLS 终止、按路径反代到后端服务、多台上游做负载均衡、静态资源缓存和按 IP 限流。也常见于 K8s Ingress Controller 的底层实现。

**竞品对比**: 对比 Apache httpd 的每连接一线程/进程模型，NGINX 在同等内存下能扛的连接数高一个量级；对比 Caddy 缺自动申请续期证书，得自己配 certbot；对比 Envoy/Traefik 缺现代服务发现和细粒度 L7 治理，动态配置要靠 reload 或第三方模块。

**成熟度**: 极其成熟，mainline 已到 1.29.x，BSD-2 协议，二十多年生产验证，文档和社区都是顶级，可以直接上生产。

**趋势信号**: NGINX 把开发主仓从 Mercurial 迁到了 GitHub，官方仓库成了唯一可信的源码入口；加上主线版本持续发安全补丁，运维和打包的人开始直接盯这个仓库，star 随之上涨。

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +217 今日新增 · 11,834 总星数

> Intel 开源的推理部署工具，把 PyTorch/TF/ONNX 模型转成自家 IR 再量化，让没有 NVIDIA 显卡的 Intel CPU/GPU/NPU 也能高效跑模型。搭上 AI PC 本地跑 LLM 的热潮。

**亮点**

- 走「先转 IR 再针对设备生成 kernel」的两段式路线，同一个模型不改代码就能在 CPU/GPU/NPU 之间切换，换硬件不用重训也不用改推理代码
- 把 Hugging Face 生态接进来（Optimum Intel），transformers/diffusers 的模型能直接转换部署，不用先手工导 ONNX

**核心功能**

- 模型转换到自家 IR：直接接收 PyTorch/TF/ONNX/PaddlePaddle/JAX 模型对象，转成 OpenVINO 中间表示，中间做算子融合、常量折叠、布局变换，部署时彻底脱离原训练框架
- NNCF 训练后量化：INT8/INT4 权重量化加激活值校准，LLM 走分组 INT4，权重和 KV cache 一起压，让 7B 级模型能塞进消费级笔记本内存
- 一套 API 打通 CPU\(x86/ARM\)、Intel 核显/独显、NPU，编译模型时按目标设备选 kernel 并做异构切分；上层还有 GenAI API 提供 continuous batching、KV cache 复用这些 LLM 服务套路

**适用场景**: 给在 Intel 笔记本、工控机、边缘盒子上做本地 AI 的开发者用：AI PC 上跑本地 LLM 对话、门店里用 Whisper 做离线语音转写、产线相机做实时质检。典型用户是想省掉 NVIDIA 显卡成本的算法工程和 ISV。

**竞品对比**: 比 ONNX Runtime 对 Intel NPU 和核显的调度更深、量化工具链更完整，但只在 Intel 硬件上才划算；比 TensorRT 不绑 NVIDIA 卡；比 llama.cpp 能吃的模型格式多得多，不只 LLM。

**成熟度**: 生产可用：Intel 官方长期维护，PyPI/npm/conda/brew 多渠道发版，文档和 Notebook 教程齐全，已有大量边缘产品在用。

**趋势信号**: AI PC 换机潮下 Intel Core Ultra 的 NPU 需要软件栈落地，OpenVINO 更新到 2026 版本并强化 GenAI API，让 LLM 和扩散模型能直接在笔记本 NPU 上跑。

## 趋势观察

今天这批热榜，几乎不是在造模型，而是在给 Agent 装手脚。第一类最扎眼：一堆「技能包」。渗透测试方法论、先问需求再写代码的开发流程、一句话出图表、并行搜十几个平台的简报，全被打包成 skill 文件。装进 Claude Code、Cursor、Codex，Agent 就多会一门手艺。第二类是接口。网页抓取工具直接注册成 MCP 服务器，Google 的设计工具也走 Stitch MCP，Cursor 官方插件让 Agent 连上 Gmail、Salesforce、GitHub。MCP 正在变成 Agent 接外部系统的通用插座。第三类是「让 Agent 真去干活」。CLI-Hub 给只有图形界面的软件套一层命令行，Agent 敲命令，不用截图点鼠标。CI/CD Agent 自动读失败日志、定位根因、提修复 PR。App 上架合规扫描器在提交前拦漏项。这是从「聊天」到「上手」的明显转折。另一条线是本地和便宜。MiniMind 用单卡 3090、约 3 块钱跑通完整训练链路，学原理用。Intel 把推理搬到自家 CPU、GPU、NPU，蹭 AI PC 的风。Ghost-Downloader 和 AutoClip 都主打本地、开源、替代收费 SaaS。合起来看，开发者生态的重心在挪：模型不再是主角，围绕 Agent 的「技能层、接口层、工具层」成了新的兵家必争之地。谁能把真实工作流拆成 Agent 能调用的干净接口，谁就先拿到下一波。热闹归热闹，这些技能包和插件最后拼的还是稳不稳、接得对不对。Agent 生态刚搭起脚手架，真正耐用的那一层还没定。
