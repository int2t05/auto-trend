### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +2,300 今日新增 · 97,318 总星数

> 给编码 Agent 加一套设计词汇：24 个斜杠命令 + 62 条纯规则检测器，专门解决 AI 生成页面千篇一律的问题。

**亮点**

- 把「做得好看点」这种模糊指令拆成一组可命名的动作词（bolder、quieter、polish、harden），每个词对应一份针对该动作预写的 playbook，并且强制你指定目标元素——单个 section 精修胜过整页扫一眼
- detector 做成纯规则、可离线、退出码有语义（2 = 有问题，1 = 扫不了），所以同一套规则能塞进 agent 的 hook（改完 UI 文件立刻回灌结果）、CLI、GitHub Actions 注解和 Chrome 扩展四个入口

**核心功能**

- 62 条确定性规则的「AI slop 检测器」，完全不调 LLM、不要 API key：扫源码（JSX/TSX）只跑模式规则，扫 URL 时才跑需要渲染的规则（对比度、过小字号），用你本机的 Chrome/Edge 渲染
- 24 个斜杠命令按用途分组：steer（bolder/quieter/distill/typeset）、review（critique 按可用性启发式打分并排序修复优先级，audit 出 P0-P3 的技术质量报告）、finish（polish/harden/adapt/optimize）、live（浏览器内点选元素换变体）
- 把项目上下文写成文件再复用：init 读代码后只问推断不出来的东西，生成 PRODUCT.md；document 把现有视觉体系写进 DESIGN.md，后续每个命令都读这两份文件，避免每次重新解释品牌

**适用场景**: 用 Claude Code、Cursor、Codex 写前端页面的开发者和设计工程师。典型流程是让 agent 生成落地页或后台界面后，跑一遍 critique 和 audit 把可用性、无障碍、响应式问题挑出来；或者在 CI 里跑 detect，防止 AI 生成的样式回退混进主干。

**竞品对比**: 和 stylelint、ESLint 只查代码规范不同，它查的是渲染后的设计模式（紫蓝渐变、卡片套卡片、每段标题上的圆角图标）；和 Lighthouse、axe-core 比，它把设计套路和 a11y、性能混在一个 P0-P3 排序里给。最大差异是它不改你的模型，只是套在现有 agent 上的一层命令和检查。

**成熟度**: 文档站、Chrome 商店扩展、20 多个 agent 客户端适配都已就位，但命令集还在动（craft 已降级成普通构建请求的别名），适合当辅助审查用，别当唯一把关。

**趋势信号**: 「AI slop」正好成了今年的公共吐槽点——大家受够了 agent 默认吐出的 Inter 字体加紫蓝渐变，而这个项目一次接入了 20 个 agent 客户端，赶上了这波情绪。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +1,259 今日新增 · 309,546 总星数

> 一套写给编程 Agent 的软件开发方法论：把「先问清需求、再出计划、最后派子 Agent 按 TDD 做」固化成可自动触发的技能包，一键装进 Claude Code、Codex、Cursor 等十几种 CLI。

**亮点**

- 把人的决策点前置：Agent 看到你在搭东西时不直接写代码，而是先退回来问你要解决什么，设计分块确认后才动手。这跟主流「给个 prompt 就开干」的做法是反的
- 子 Agent 分工 + 主 Agent 审查的循环，本质是用架构换上下文长度，避免长任务跑到后面忘了原始 spec

**核心功能**

- 技能以 Markdown 指令 + Shell 脚本的形式组织，靠 SessionStart 钩子在会话开始时注入 using-superpowers 引导语，上下文被压缩（compaction）后再注入一次，所以技能是自动触发的，用户不用记命令、也不用每次手动点名
- 工作流分三段：先反向追问出 spec，把 spec 切成一次能读完的小块让你逐段签字，再产出一份「没品味的初级工程师也能照做」的实施计划；计划里强制红/绿 TDD、YAGNI、DRY
- 执行阶段用子 Agent 驱动开发（subagent-driven development）：每个工程任务派一个子 Agent 去做，主 Agent 审阅它的产出再决定下一步，主上下文不被单个任务的细节塞爆，因此能连续自主跑几个小时不偏离计划
- 同一个仓库适配 17 种 harness（Claude Code、Codex App/CLI、Cursor、Gemini CLI、Copilot CLI、Devin CLI、Factory Droid、Kimi Code、Qwen Code、OpenCode、Grok、Muse、Pi 等），各家插件机制不同就各写一套安装入口和兼容层

**适用场景**: 日常用 Claude Code、Codex 或 Cursor 写代码的工程师，想让 Agent 从「问一句改一个文件」升级成从需求澄清一路做到实现和测试。也适合想把 TDD、评审、计划流程固化进 Agent 的技术团队，省得每个人自己维护一份 CLAUDE.md 或 rules 文件。

**竞品对比**: 对标 BMAD-METHOD、GitHub 的 spec-kit 这类规范驱动开发工具，以及散落在各仓库里的 CLAUDE.md / .cursorrules 手写指令。最大差异是它一套内容同时铺到 17 家 harness 的官方或第三方插件市场，并且覆盖从需求到测试的完整流程，不只是一份 prompt 模板。

**成熟度**: 已有 Anthropic、OpenAI、xAI 官方插件市场上架和不少企业用户咨询，但作者是单人维护（obra / Jesse Vincent），方法论类项目技能措辞迭代频繁，跟进前建议锁定版本。

**趋势信号**: 各家 CLI 今年陆续开放插件市场（Claude、Codex、Grok 官方 marketplace），一个方法论能一键装进所有主流 Agent，正好卡在 spec-driven development 这波讨论最热的时候。

### [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

 `TypeScript` ⭐ +1,140 今日新增 · 106,596 总星数

> 给编程 Agent 做跨会话记忆：自动录下每轮工具调用，用 AI 压成摘要，下次会话再把相关片段喂回去。现在火是因为 Claude Code 等 Agent 生态爆发，长任务断档成了普遍痛点。

**亮点**

- 分层记忆设计：原始日志 → AI 压缩观察 → 按需检索注入，三层分离，避免把整段对话历史硬塞进上下文窗口。
- 对没有 hook 能力的宿主用"盯 chat log 文件"兜底，用最土的办法把兼容性铺到十几个 Agent 上，这是它能覆盖这么广的关键取舍。

**核心功能**

- 会话中抓取工具调用日志，结束后交给 AI 压缩成带标签的"观察"（决策/修复/安全告警/敏感操作），只存摘要不存原始 transcript，下次按相关性注入，省 token
- 靠宿主 hook 挂进 Claude Code、Codex、OpenCode、T3 Code 等；对没有 hook 的宿主（如 Grok Bot）退化成轮询 chat log 文件抓取
- 提供 MCP 搜索工具，让 Agent 自己按需查历史记忆，而不是每次开场就整包塞进上下文
- 安装器自动探测各 IDE 的配置目录，把原生插件和 hook 注册进去，一条 npx 命令搞定多宿主

**适用场景**: 长期用 Claude Code / Codex 写同一个项目的开发者：隔天回来接着改，Agent 不用再从头问"这个仓库怎么跑、上次那个 bug 修到哪了"。 多人或长周期任务里，把"为什么这么改"的决策记录留存下来，方便换会话、换 Agent、换机器后继续。

**竞品对比**: 同类有 mem0、Zep、Letta（MemGPT）这类通用 Agent 记忆层，还有 Claude Code 自带的 CLAUDE.md 手写记忆。claude-mem 的差别是走宿主的 hook 自动采集，不需要 Agent 主动调 API 去存，也不靠人肉维护 Markdown。

**成熟度**: 版本已到 15.7.0，多语言文档齐全，有托管服务和付费订阅，算是商业化了；但强依赖各宿主的 hook/插件接口，宿主一改版就可能挂，装机后要留意版本匹配。

**趋势信号**: Agent 记忆是当下最热的赛道之一，而这个项目近期一口气扩到 OpenCode、T3 Code、Antigravity CLI、Grok Bot 等一大批新宿主，又挂着 Vercel OSS 计划和 Trendshift 曝光，正好赶上 Claude Code 生态扩张的窗口。

### [pingdotgg/t3code](https://github.com/pingdotgg/t3code)

 `TypeScript` ⭐ +930 今日新增 · 32,980 总星数

> 在本机起一个常驻服务，接管你已装好的 Claude Code、Codex、Cursor 等命令行 Agent，用手机、网页或桌面端远程查看进度、批准权限、发指令。

**亮点**

- 路线选择是“套壳而非重写”：不自己造 Agent 循环，只做多厂商 CLI 的统一遥控层。好处是上游模型和工具一升级自动吃到，代价是行为受各家 CLI 的接口约束。
- 远程访问靠你自己机器上的服务，不走中心化云中转，隐私和延迟都比把会话托管到第三方要好。

**核心功能**

- 不重新实现 Agent，只做控制层：直接调用你本机已登录的 Codex CLI、Claude Code、Cursor CLI、Grok、OpenCode，复用它们的订阅和权限模型，不涉及转发 API Key。

**趋势信号**: 一家做了两年的闭源 SaaS 突然开源核心代码（Rust + SolidJS 全栈），撞上当下“Agent 需要统一上下文和记忆、别再靠 MCP 拼工具”的讨论热度，加上 README 里直接引 Linear“issue tracking is dead”开怼，话题度高。

### [expo/skills](https://github.com/expo/skills)

 `Shell` ⭐ +38 今日新增 · 3,924 总星数

> Expo 官方出的 Agent 技能包。把 Expo/EAS 的搭建、升级、构建、调试流程写成一个个 SKILL.md，喂给 Cursor、Claude Code 等编码 Agent，让它别瞎写 React Native 代码。

**亮点**

- 官方主动在技能里标注"这一步要花钱"，把付费服务的成本提示写进 Agent 可读的说明，防止 Agent 自动帮你开出一堆 EAS 构建账单——很少见的设计
- 不堆一份大文档，而是拆成按需加载的技能文件加 MCP 工具调用，把"知识"和"执行"分开管

**核心功能**

- 技能按场景拆成单个 SKILL.md（expo-router、expo-animation、eas-update 等 20 多个），Agent 按任务描述只加载相关那几个，不把整份文档塞进上下文
- 分三组：开源 SDK 技能免费、EAS 付费服务技能开头必须写成本和套餐限制、未定 API 单独放 expo-experiments 插件，避免 Agent 推荐用不了的实验特性
- 双分发通道：Claude Code/Codex 走官方插件市场自动更新并捆绑 Expo MCP 配置，其他 Agent 用 `npx skills add expo/skills --skill '*'` 把文件落到项目根目录
- 和 Expo MCP server 分工：技能只教流程，MCP 真干活——按需拉最新文档、用 `npx expo install` 装兼容版本、触发并监控 EAS 构建、拉 TestFlight 崩溃数据、远程模拟器截图

**适用场景**: 面向用 Cursor、Claude Code、Windsurf 写 React Native/Expo 的开发者。典型场景是从零搭路由结构、把 Next.js 网页迁成原生 App、升级 Expo SDK、配 EAS Build/Update 的 CI 流程。

**竞品对比**: 对比社区流传的 .cursorrules、各种 awesome-cursor-rules 合集，以及 Anthropic skills 生态里的第三方技能包：差异是 Expo 官方维护、跟 SDK 版本同步更新，并且带 MCP 能真的执行命令，不只是贴规则。

**成熟度**: 早期项目，装有 experimental 分组说明部分技能还会改，但官方维护、MIT 协议、插件市场上线，日常用问题不大。

**趋势信号**: 2025 年底 Agent Skills 和 skills.sh 分发生态起来，Expo 是最早出官方技能包的主流框架团队之一，跟着这波生态热度涨星。

## 趋势观察

看完这批项目，一个感觉特别明显：大家不再比谁的模型强，而是在给 Agent 补基础设施。第一件大事是记忆。跨会话记忆、Macro 的双向图、JetBrains 的 SPEC.md、AI 家教的长期记忆，都在解决同一个问题——Agent 干长活会断片，记不住上一轮干了啥。第二件是技能包成了新的分发格式。SKILL.md 满天飞：Anthropic 官方出手，Expo 官方出手，Matt Pocock 把自己天天用的指令也开源了。本质都是教 Agent 别瞎写、别啰嗦、别不测试、别千篇一律。第三个信号是权限和审计。AI 同事的工具调用要先过网关审批、再写审计记录；开源 Grok Bot 每个联系人有独立授权；还有人做远程服务，用手机批准 Agent 的权限。说明 Agent 已经能自己动手了，现在缺的是管住它的缰绳。还有个值得注意的：巨头开始下场。Expo、JetBrains、Anthropic 都亲自发官方包，agentic IDE 进入混战。底层也在变，Lightpanda 干脆绕开 Chromium，用 Zig 重写只为 AI 服务的无头浏览器。整体看，新闻热点正从“模型能聊”转向“Agent 能干长活”，开发者生态的重心也跟着移到了记忆、技能、权限、远程控制这些配套件上，而且普遍强调本地自托管、数据留在自己机器里。这股风不是炒概念，是真在填坑。
