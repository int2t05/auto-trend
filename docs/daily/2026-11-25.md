### [elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)

 `Python` ⭐ +1,826 今日新增 · 21,999 总星数

> 把 84 个 Claude Code 技能打包成“漏洞挖掘助手”，塞进 681 份已公开的 HackerOne 报告提炼的检测套路和企业 VPN/身份平台 CVE 链，让 Claude 自动按话题加载对应打法。它现在火是因为 Claude Code 技能/插件生态刚起来，安全圈在找“AI 直接上手打靶”。

**核心功能**

- 知识库是 681 份已披露 HackerOne 报告压缩成 24 类漏洞的检测模式，其中 433 条逐条标注了报告出处，做成可审计的 SKILL.md 文件

**适用场景**: 适合做众测的独立白帽和红队外网打点人员：接到 HackerOne 项目或授权外网评估后，用它跑子域枚举、技术指纹、按面排序，再针对 GraphQL 内省、OAuth redirect_uri、IDOR 这类常见坑出 payload 和验证步骤。

**竞品对比**: 和 PentestGPT、HackingBuddyGPT 这类学术向的 LLM 渗透 Agent 相比，它不自己做自主循环，而是寄生在 Claude Code 上吃现成的工具调用和 MCP 生态；和 Nuclei 模板库相比，它是给模型看的判断逻辑，不是给扫描器跑的规则。

**成熟度**: 早期偏实战项目，靠 star 快速起量，文档齐全但 API/技能目录仍在频繁变动，且实际效果高度依赖模型本身，企业环境需自行评估合规风险。

**趋势信号**: Claude Code 的 Skills/插件市场刚开放，加上 AI 辅助渗透从“论文 demo”转向“能装能用的技能包”，赶上这波工具化红利。

### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +1,074 今日新增 · 65,167 总星数

> 港大 HKUDS 团队把各种软件（CAD、Calibre、LibreOffice、Obsidian 等）包成命令行工具，让 AI Agent 用最熟悉的 shell 就能操作，不用截图点击。

**亮点**

- 绕开 MCP 和截图点击这两条路：MCP 要每个 App 常驻一个 server、工具描述占满上下文，GUI Agent 靠截图点击又慢又脆；改成 CLI 后 Agent 用 shell 管道组合，token 便宜、可脚本化、可复现
- 把「让软件变得对 Agent 可用」这件事拆成社区可并行贡献的单元：一个人写一个 App 的 harness，PR 合并进注册表后就能被所有 Agent 客户端安装，形成软件适配层的众包网络

**核心功能**

- 每个软件对应一个用 Python click 写的 CLI 封装，底层调用软件自身的 API、文件格式或自动化接口；输出同时提供 JSON（给 Agent 解析）和人读文本（给人看），一次命令两用
- 技能化分发：每个 CLI 配一份 SKILL.md，用 `npx skills add HKUDS/CLI-Anything --skill &lt;名字&gt;` 直接装进 Claude Code、Cursor 等客户端；CLI-Hub 当注册中心，`cli-hub install &lt;name&gt;` 一键装
- Agent 闭环设计：跑命令 → 看预览图/日志 → 修正再跑（README 里的 preview / live preview / trajectory loop），用来生成 CAD 图、3D 场景、字幕这类看得见的产物
- 安全上做了取舍：不可信 XML/SVG/ODF 走 defusedxml 解析，Sketch 的 token 文件防路径穿越和软链逃逸，Rekordbox 写 SQLCipher 前强制备份

**适用场景**: 已经在用 Claude Code / Cursor 这类终端 Agent 的开发者，想让 Agent 直接操作本机的专业软件——批量改 Calibre 书库元数据、用 LibreOffice 无头转文档格式、自动写 Obsidian 笔记、给 Rekordbox 曲库打标签。

**竞品对比**: 对标 MCP server 生态（如各家官方 MCP）和 computer-use / GUI 自动化方案（Anthropic computer use、Open Interpreter）。最大差异是把接口降级成纯文本 CLI 而非结构化协议或像素输入，代价是每个 App 都得有人手写适配层。

**成熟度**: 社区热度很高（6.5 万星、2461 个测试、有 arXiv 技术报告、Apache 2.0），但各 App harness 由社区分散贡献，质量参差，部分还是提案状态，生产使用前得逐个验证。

**趋势信号**: 2026 年 5 月密集合并了 Calibre、Rekordbox、3MF、Joplin 等一批 harness 并上线 CLI-Hub 注册中心，正好赶上「Agent 直接操作本机软件」这波需求，以及开发者对 MCP 生态膨胀的疲劳。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +1,003 今日新增 · 326,102 总星数

> 给编码 Agent 装上的一套开发方法论：先问清需求、写规格、出计划，再派子代理逐个任务实现并审查。跨 17 种 Agent 工具通用，现在火是因为各家插件市场刚起来。

**亮点**

- 子代理驱动开发：主代理只负责拆任务和验收，子代理干活、另一个代理审查，能连续自主跑几小时不偏离计划——这是把'长任务不跑偏'当工程问题解，而不是靠更长的 prompt。
- 借宿主工具的钩子做技能引导，而不是自己搞一套运行时。代价是要为每种 harness 各写一份安装文档和适配（Pi、Muse 用原生技能，Hermes 缺钩子就退化），收益是零依赖、装完即用。

**核心功能**

- 用 harness 的 SessionStart 钩子注入一个 using-superpowers 引导技能，上下文被压缩后再注入一次，所以技能是自动触发的，用户不用手打 prompt；Hermes 没有压缩后钩子，作者直接在文档里说明这个坑
- 把流程拆成可组合的 markdown 技能：先追问真实意图 → 把需求规格分段给你确认（每段短到能读完）→ 生成一份'没品味、没项目上下文、不爱写测试的初级工程师也能照做'的实施计划 → 子代理逐任务执行并互查
- 同一个仓库适配 17 种工具（Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、Qwen Code、Kimi、Devin、Grok 等），每种给对应的 marketplace 清单和安装命令，本质是同一套技能文本做多份打包
- 计划模板里硬性写入红/绿 TDD、YAGNI、DRY，把'要不要先写测试'从模型自由发挥变成流程约束

**适用场景**: 日常用 Claude Code / Cursor / Codex 写中大型功能的开发者，受够了 Agent 一上来就乱写代码、改到一半跑偏；装完后让它先出规格和计划再审。 想让团队里几个人的 Agent 行为一致的工程团队，把流程固化成技能而不是每人自己维护 CLAUDE.md 或规则文件。

**竞品对比**: 同类有 GitHub 的 spec-kit、BMAD-METHOD，以及各家自带的 plan mode 和 CLAUDE.md/AGENTS.md 规则文件。最大差异是跨工具通用、靠钩子自动触发，不用每次手工贴流程 prompt；代价是技能格式跟着各家 harness 走，适配维护量大。

**成熟度**: 可用但仍在快速迭代：已进 Anthropic、OpenAI、xAI 的官方插件市场，harness 覆盖很全，但技能格式随宿主工具变动，API 层面不算稳定。

**趋势信号**: Anthropic 推出 Agent Skills 后，Codex、Cursor、Grok 等陆续开放插件/扩展市场，Superpowers 正好卡在'技能标准化 + 一份技能多工具复用'这个窗口上被推上来。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +991 今日新增 · 209,296 总星数

> Firecrawl 把网页抓取、搜索和 550+ 数据源统一成一个 API，供 AI Agent 使用。新版本增加了本地单文件二进制和 MCP 自动接入，因此再次登上热榜。

**亮点**

- 本地优先 + 云端回退的混合架构：默认本地抓，抓不动才静默走云端，用 FIRECRAWL_CLOUD=off 可强制全本地，兼顾隐私和覆盖率
- 把 MCP 注册做成一键 init，不用手写 JSON 配置，这相当于把“接入”这一步从文档搬进了 CLI

**核心功能**

- Firecrawl Local 用 Rust 编成一个可执行文件（cargo install 安装），无需数据库、队列或容器，抓取、爬取、map 全在本机运行，PDF 和 Office 文档也在本地解析
- 需要 JavaScript 的页面直接复用你机器上已装的 Chrome/Chromium 渲染，不额外安装无头浏览器；如果没有浏览器，静态页照样能抓，只是需要浏览器渲染的页面会返回警告
- 在 localhost:3002 上启动一份 Firecrawl v2 API，官方 SDK 只需把 api_url 指向本机，就能原样跑通，本地路由不需要 API Key；本机打不开的单页会默认交给云端处理，并在结果里标记 source: firecrawl-cloud
- 执行 `firecrawl-local init` 会自动扫描 Claude Code、Cursor、Windsurf、Gemini CLI、Codex 的配置文件，先把原文件备份，再把 Firecrawl 注册成 MCP server

**适用场景**: 适合正在做 AI Agent、RAG 或知识库的开发者：需要把网页转成干净的 markdown 喂给 Claude Code、Cursor 这类工具，又不想把内网或敏感页面发到第三方云服务的场景。

**竞品对比**: 对比 Crawl4AI、Jina Reader、ScrapingBee、Apify：Crawl4AI 是 Python 库、要自己管浏览器；Jina Reader 只做单页转 markdown；Firecrawl 的差异在于同时提供本地二进制、云端 API、MCP 接入和 Alexandria 的 550+ 数据源，还兼容自家 SDK 的即插即用。

**成熟度**: 生产可用，已有 v2 API、多语言 SDK、商业云服务和自托管部署，社区和文档都成熟。

**趋势信号**: MCP 在 2025 年成为 Agent 工具接入的事实标准，加上 Firecrawl Local 用 Rust 单二进制发布并配合 Keyless 每月 1000 次免费额度，直接降低了 Agent 抓网页的门槛。

### [mjmirza/app-store-compliance](https://github.com/mjmirza/app-store-compliance)

 `Shell` ⭐ +928 今日新增 · 6,097 总星数

> 一个开源的 App 上架前自检工具：用 Shell 脚本扫 iOS/Android 工程，按 124 条真实拒绝原因提前报警，并附法规截止日期表和 AI 编码工具钩子。

**亮点**

- 态度罕见地老实：README 里反复写扫描只能证明代码里没有已知风险，CLEAR 不等于过审，账户配置、商店文案这些机器看不见的部分单独列成人工清单要求记进 .app-review-readiness.json
- 把合规工具做成 Agent 钩子而不是又一个网站或 CI 服务，零安装零配置，蹭上了 2025 年 AI 编码工具普遍支持 hook 的这波能力

**核心功能**

- 纯 bash 静态扫描，不改代码不装依赖：直接读 Info.plist 用途字符串、PrivacyInfo.xcprivacy、AndroidManifest.xml 权限、Expo 的 app.json，命中就输出 \[CRITICAL\] 并给出文件:行号和 fix 行，最后一行给 BLOCKED / CLEAR / NOT CHECKED 结论
- 一条 install.sh 把扫描挂成 AI 编码工具的 pre-submit hook：Claude Code、Codex CLI、Gemini CLI、Cursor、Copilot、OpenCode 都支持，Agent 执行上传 App Store Connect / Google Play 的命令前先跑一遍，命中严重项就拦下来
- 规则包带 60 天保鲜期检查（输出 Rule pack STALE 提示 git pull），外加 112 条法规截止日期表（EU AI Act、DSA、COPPA、各州年龄法），每条结论都挂 Apple/Google 官方链接，不自己编条款号

**适用场景**: 主要给独立开发者和 2-5 人小团队：用 Cursor / Claude Code 快速做出 App，第一次提审不知道隐私清单和演示账号怎么写。也适合被拒过一次、想照着 playbook 写申诉信的人，以及不写代码但负责提审的产品/运营照清单逐条核对。

 `C++` ⭐ +185 今日新增 · 12,538 总星数

> Intel 开源的推理部署工具箱，把 PyTorch/TF/ONNX 等模型转成自家 IR 格式，再针对 Intel CPU、核显和 NPU 做量化与加速，主要用来在本地和边缘设备上跑视觉、语音和 LLM。

**亮点**

- 转换一次、多设备复用：同一份 IR 可以在 CPU、GPU、NPU 之间切换，NPU 跑不动的算子自动落到 CPU，这个回退机制是它能在碎片化 Intel 硬件上落地的关键
- 把量化工具 NNCF 和 Hugging Face 生态打通，主流开源模型基本能开箱转成 INT4 上 NPU，省掉了自己写量化脚本和算子适配的活

**核心功能**

- 模型转换器直接吃 PyTorch、TensorFlow、ONNX、PaddlePaddle、JAX 的模型，转成 OpenVINO IR（一种中间表示格式，转换完就不再依赖原框架），再用 core.compile_model 按目标设备编译
- NNCF 做训练后量化，把权重和激活压到 INT8/INT4；配合 Optimum Intel 一条命令把 Hugging Face 上的模型转成低精度版本，主要省内存、提吞吐
- 设备插件架构：CPU、Intel 核显/独显、NPU 各是一个插件，编译时按设备能力切分算子图，遇到 NPU 不支持的算子自动回退到 CPU 执行，不至于整模型跑不起来
- 单独的 GenAI API（openvino.genai 仓库）封装了 LLM 流水线：KV cache 管理、连续批处理、投机解码这些推理侧优化不用自己写

**适用场景**: 在 Intel 笔记本、工控机、边缘盒子上做本地部署的算法工程师和集成商，典型场景是工业质检的视觉模型、Whisper 语音转写、以及用 Core Ultra 的 NPU 跑本地大模型助手。

**竞品对比**: 对标 ONNX Runtime 和 NVIDIA TensorRT。ONNX Runtime 跨厂商更中立、覆盖面广；TensorRT 只在 N 卡上跑但性能更极致。OpenVINO 的差异点是只押注 Intel 硬件，把核显和 NPU 这两块别人不太管的算力用起来。LLM 场景下和 llama.cpp 也有重叠，后者更轻、更通用，OpenVINO 强在量化与 NPU 加速。

**成熟度**: 生产可用，Intel 官方维护多年，版本已排到 2026.x，C++/Python/C/NodeJS 多语言包齐全、pip/conda/brew/npm 都能装，文档和 Notebook 教程完整。

**趋势信号**: AI PC 和端侧推理这波热度推动的：Intel Core Ultra 的 NPU 要靠它才能用起来，加上 2026 版本文档和 GenAI API 对本地 LLM 的支持，让它在“不联网跑大模型”的需求里被反复提起。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +158 今日新增 · 33,283 总星数

> NGINX 官方开源仓库：C 写的 Web 服务器/反向代理/负载均衡器，靠事件驱动多进程模型扛高并发。老牌项目，近期上 GitHub 官方镜像带来星标回流。

**亮点**

- 用少量 worker 进程 + 非阻塞事件循环替代线程池，把并发成本从"每连接一个栈"降到"每连接一点状态"，这是它能扛 C10K 的根本原因
- reload 用新老 worker 并存再优雅退出的方式做配置热更新，不需要重启进程、也不丢在途请求

**核心功能**

- master/worker 多进程 + 事件驱动（Linux 用 epoll、BSD 用 kqueue），单 worker 用非阻塞 IO 处理上万连接，不靠一请求一线程
- 多 worker 通过共享内存 zone 同步状态，限流（limit_req_zone）、连接计数、缓存索引都放在共享内存里，所以各进程看到的是同一份计数
- 配置是声明式文本指令，master 进程读配置、校验语法，reload 时先起新 worker、再让老 worker 处理完存量请求退出，不断连接
- 模块分静态和动态两种：静态在 configure 阶段编进二进制，动态模块（.so）可运行时加载，nginx -V 能看编进去了哪些

**适用场景**: SRE/运维和后端团队用来做入口层：TLS 终止、七层反向代理、多台上游负载均衡、静态资源和 API 响应缓存、按 IP/Key 限流。K8s 里常以 Ingress Controller 形式出现。

**竞品对比**: 对手是 Caddy（自动签 HTTPS、配置更简单）、Envoy（xDS 动态配置、服务网格原生）、Traefik（容器自动发现）、HAProxy（纯负载均衡更强）。NGINX 的差异是模块生态和部署惯性最大、配置最成熟，但没有原生的动态配置下发和服务发现，改配置得靠 reload 或第三方控制面。

**成熟度**: 生产可用，二十多年验证，stable/mainline 双轨发版，BSD-2 许可，文档齐全。

**趋势信号**: 原因不明——没有明显的新版本或社区事件，猜测是官方仓库迁到 GitHub 后持续被搜索到，加上最近 mainline 发版/安全公告带来的短期关注。

## 趋势观察

今天这份榜单有个很明显的共同点：大家都在给 AI Agent 配装备。一边是 Claude Code、Cursor 这些工具刚开放插件和技能市场，另一边开发者立刻把技能打包上架。安全打靶、绘图、搜索、读设计稿、写 CI 修复，全是“让 Agent 直接干活”的模块。 第二个趋势是 Agent 的操作方式在变。以前是截图加点击，现在流行让模型走命令行。港大把一堆软件包成 CLI，Firecrawl 加 MCP 自动接入，思路一样：给 Agent 一个它最熟的 shell，比教它看屏幕靠谱。 第三，本地化和低成本成了卖点。3090 两小时三块钱训小模型，Intel 工具箱在本地 CPU 和 NPU 上跑推理，AutoClip 在本机剪视频。大家不想什么都往云上送。 还有一层是方法论开始沉淀。那个跨 17 种工具的开发流程，先问需求、写规格、再派子代理实现，说明光有工具不够，得教 Agent 怎么做事。MCP、plugin.json 这些规范正在变成事实标准。 总的来说，开发者生态正从“模型能聊天”转向“模型能接活”。谁能把工具、规范、流程三样配齐，谁就先跑起来。热度不在模型本身，而在模型外面那层脚手架。
