### [Alishahryar1/free-claude-code](https://github.com/Alishahryar1/free-claude-code)

 `Python` ⭐ +415 今日新增 · 69,526 总星数

> 一个本地代理，把 Claude Code、Codex 等 12 种编码 Agent 接到 61 家模型供应商上，聚合每月 13 亿免费 token，绕开订阅费。

**亮点**

- 核心思路不是"造一个更好的 Agent"，而是把 Agent 和模型之间那层协议当成可替换的插槽——这让它天然能跟着新出的免费模型（如 NVIDIA NIM 的 Nemotron、Gemini Flash Lite）快速扩容
- 把"免费额度能不能用"这个不确定问题，用多 key 轮换 + 多供应商 fallback + token 压缩硬做成工程问题，这是它和普通 API 转发脚本的最大区别

**核心功能**

- 在本地起一个 OpenAI 兼容端点（默认 http://127.0.0.1:8082/v1），把各 Agent 的请求翻译成目标供应商格式，同时保留原生流式输出、工具调用和交错思考（模型在回答里穿插推理块），不是简单换个 base URL
- 用 RTK + Headroom 两个工具压上下文，官方宣称最多省 90% token——本质是把重复的仓库上下文和历史对话做压缩与复用，让免费额度能撑更久
- 做了完整的容错层：自动重试、可配置限流和并发数、模型/供应商自动降级、多 API key 轮换。一个请求失败后会按序打到下一个供应商，而不是直接报错
- harness（客户端）和 provider（模型来源）解耦成两层适配，12 个客户端 × 61 个供应商的组合靠两个适配层维护，一条命令 fcc-claude / fcc-codex 就能起对应 Agent

**适用场景**: 不想掏 20~200 美元月费、但已经习惯 Claude Code 工作流的个人开发者和学生。典型场景是在终端、VS Code/JetBrains 里写代码，或者在外面用 Discord/Telegram 给 Agent 发语音指令让它跑任务。

**竞品对比**: 同领域有 LiteLLM（模型网关）、OpenRouter（聚合 API）、musistudio/claude-code-router、以及 Cline 自带的供应商切换。FCC 的差异是它不满足于协议转换，还把免费额度聚合、token 压缩、多客户端入口（含手机语音）和容错捆绑成一整套，装上就能跑。

**成熟度**: 工程化程度不低——有 pytest CI、ty 类型检查、ruff 格式化、Windows/macOS 桌面安装包和 Admin UI；但它整个价值建立在供应商的免费额度政策上，随时可能被限流或封禁，别放到生产关键路径，作者自己也声明与 Anthropic 无关。

**趋势信号**: Claude Code 和 Codex 的用量限制持续收紧、订阅价格不低，同期 NVIDIA NIM、Gemini Flash Lite 等放出大额免费额度，加上 OpenClaw 带起的个人 Agent 热潮，几件事叠在一起把这个项目推了上去。

### [CopilotKit/OpenBot](https://github.com/CopilotKit/OpenBot)

 `TypeScript` ⭐ +298 今日新增 · 11,833 总星数

> OpenBot 是 CopilotKit 开源的自托管「AI 同事」工作台：每个 Bot 分到一台隔离的虚拟电脑（浏览器、文件、工具），动作执行前要审批、执行后留审计。现在火是因为企业想把 computer-use agent 落到实处，又不想把数据和权限交给第三方。

**亮点**

- 核心卖点不是「agent 多聪明」而是「agent 的动作可治理」：把审批点卡在工具执行之前而不是之后，这是企业敢让 agent 碰浏览器和文件系统的前提
- 主动跟 agent 运行时解耦：agent 可以继续跑在 Bedrock AgentCore、Google Agent Platform、Microsoft Foundry 上，OpenBot 只当工作台和权限层，避免被绑定死在某个 agent 框架里

**核心功能**

- 每个 Bot 跑在独立 Docker 容器里，自带浏览器、文件系统和工具集，互不串号；桌面端是把前端和这套容器后端打包成一个双击即用的 App，Mac 的 .dmg 已公证、Windows 安装包已签名
- 接 AG-UI 协议当「智能体和界面之间的标准插头」：Claude Agent SDK、LangGraph、CrewAI、Google ADK 等框架通过一个 AG-UI endpoint 接进来，前端和后端可以各自升级，工具侧走 MCP
- 工具调用做成「事前审批 + 事后留痕」两道闸：策略层在动作真正执行前拦下等人点确认，执行后写入审计日志，配合公司登录、角色和工具权限做团队级管控
- 模型层不绑定：OpenAI、Claude、Gemini 或任何 OpenAI 兼容端点都能换，可以继续用自己已有的模型供应商关系

**适用场景**: 适合想给非工程岗位（运营、客服、财务、猎头）配「数字同事」但又过不了安全和合规评审的公司——比如让 Bot 自己开浏览器查资料、填表单、导出文件，员工在关键一步点批准，IT 事后能查到它到底点了什么。也适合已经有一堆 LangGraph/CrewAI agent、缺一个统一前端和权限层的小团队。

**竞品对比**: 对手是 OpenAI Operator/Computer Use、Anthropic 的 computer use、Manus、Browser Use、OpenHands 这类「给 agent 一台电脑」的方案。最大差异是 OpenBot 主打自托管 + 模型自选 + 企业审批审计，而且不自己造 agent，用 AG-UI 把别家的 agent 接进来当同事；代价是它本身不提供最强的操作能力，能力上限取决于你接进来的 agent。

**成熟度**: 处在「能自己装着玩」到「企业可用」之间：有签名安装包、K8s 部署文档和 MIT 模板，但 Business 版（SSO、审计、权限）还挂在 early access 排队，接口和策略模型可能还会改。

**趋势信号**: 踩中了两条线：一是 computer-use agent 从 demo 走向「企业敢不敢放权」的落地期，二是 CopilotKit 刚拿 A 轮、正借 AG-UI 协议做生态推广，开源仓库本身就是最好的获客入口（顺手把 Business 版 early access 摆在 README 第一屏）。

### [ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp)

 `C++` ⭐ +176 今日新增 · 134,707 总星数

> llama.cpp 是用 C/C++ 写的本地大模型推理引擎，把模型量化成 1.5~8bit，让普通 CPU、Mac、各类显卡都能跑 LLM 和视觉模型。最近新增 llama cli 和 llama serve 统一命令，并支持一行脚本安装，降低了上手门槛。

**亮点**

- 不依赖任何第三方库的纯 C/C++ 实现，编译出来就是一个二进制文件，可以直接放进手机、树莓派、路由器这类跑不了 Python 环境的设备
- 用 GBNF 语法约束解码：给模型套一份语法规则，让它只能输出符合 JSON、正则或函数调用格式的内容，把结构化输出这件事从提示词层面下移到推理层解决

**核心功能**

- 自研 ggml 张量库做底层计算，再配上手写 CUDA kernel 和 Metal/ARM NEON 优化，CPU、NVIDIA、AMD、Apple Silicon、昇腾 NPU、Intel GPU 都能运行；一个代码库支持 19 种后端，不用装 Python 或 PyTorch
- 实现 1.5~8bit 整数量化（即把模型权重压成低精度整数来省显存），配合 k-quant 分块量化，让 70B 模型能在显存不够的机器上跑
- CPU+GPU 混合推理：把部分层放显存、部分层放内存，模型比显存大也能跑，只是会慢些
- GGUF 单文件格式打包权重、分词器和元数据，llama-server 对外提供 OpenAI 兼容的 REST 接口，已有工具只要改 base_url 就能接入

**适用场景**: 需要在本地或私有环境跑模型的开发者和团队，比如笔记本上做原型验证的算法工程师、要数据不出内网的金融或医疗团队，以及用它当推理后端做桌面 AI 应用的开发者。Ollama、LM Studio、llamafile 底层都是它。

**竞品对比**: 和 vLLM 比，vLLM 靠 PagedAttention 主打服务端高吞吐，但要求 NVIDIA GPU，而 llama.cpp 的优势是跑在几乎任何硬件上，包括纯 CPU 和消费级设备。Ollama 其实是基于 llama.cpp 封装的易用外壳，底层推理还是它；mlx 只服务 Apple Silicon。

**成熟度**: 生产可用：13 万 star，每日 nightly 构建，维护者几十人，代码被 Ollama、LM Studio 等产品大规模验证，只是版本号还在 v0.x，API 偶有变动。

**趋势信号**: 最近把入口统一成 llama cli 和 llama serve 两条命令，上线 llama.app 一行脚本安装和内置 Web UI，还把 Qwen3.5-0.8B 这类小模型当成默认示例，上手成本比过去从源码编译低了一个档次。

### [nvm-sh/nvm](https://github.com/nvm-sh/nvm)

 `Shell` ⭐ +63 今日新增 · 96,057 总星数

> nvm 是一个用纯 shell 写的 Node.js 版本管理器，一条命令即可切换 Node 版本、隔离各项目依赖。Node 24 转 LTS、Node 20 临近停止维护，多版本并存需求上升，它因此重新受到关注。

**亮点**

- 架构上它不是一个可执行程序，而是一个被 source 进 shell 的函数集合。这是它必须“污染” shell 环境（改 PATH）的唯一办法，代价是无法直接在脚本或非交互 shell 里调用，Docker 场景要额外配 BASH_ENV
- 版本目录就是普通文件夹，切换只做 PATH 拼接，不做软链替换或二进制分发，因此多 shell 会话天然互不干扰——这是 fnm、volta 用软链/shim 方案后要额外解决的问题

**核心功能**

- 用纯 POSIX shell 脚本实现，不依赖 Node 自身或任何编译产物，sh/dash/ksh/zsh/bash 都能运行，安装就是把仓库 clone 到 ~/.nvm 再 source 进当前 shell
- 切换版本不改全局软链，而是把 ~/.nvm/versions/node/vX/bin 前插到当前 shell 的 PATH，所以两个终端能同时跑不同 Node 版本，切换零等待
- 支持 .nvmrc 文件 + shell hook，cd 进目录自动 nvm use；nvm install --reinstall-packages-from=20 可把全局 npm 包迁移到新版本，避免重装全局 CLI
- 支持 NVM_NODEJS_ORG_MIRROR 镜像和离线安装（二进制预下载到缓存目录），国内网络和 CI 内网都能用

**适用场景**: 维护 npm 库或 SDK 的开发者，需要同时验证 Node 20/22/24 的兼容性；以及 CI 流水线里给不同仓库指定不同 Node 版本的前端/Node 后端团队。

**竞品对比**: 主要对手是 fnm（Rust 单二进制）和 Volta（锁定项目工具链），它们启动快、支持 Windows 原生；nvm 慢在每次开 shell 都要 source 几百行脚本，但胜在零依赖、POSIX 通用、CI 里几乎预装，生态惯性极强。

**成熟度**: 生产可用：已十年以上、96k star，是事实标准，但版本号仍停在 v0.41.0（从未发 1.0），README 明确提示 API 可能变动。

**趋势信号**: Node 24 已转 LTS、Node 20 临近 EOL，大量项目同时要在这几个大版本间来回切；叠加 v0.41.0 新版本发布带来的首页曝光。

### [nodejs/node](https://github.com/nodejs/node)

 `JavaScript` ⭐ +62 今日新增 · 123,649 总星数

> Node.js 官方仓库，基于 V8 和 libuv 的 JS 运行时。最近改了发布节奏：从 Node 27 起每年 4 月发布一个大版本，而且所有大版本都会进入 LTS。

**亮点**

- 发布模型被彻底重做：新大版本每年 4 月从 main 切分支，先发 6 个月 Alpha（允许 semver-major 变更），转 Current 后再过 6 个月转 LTS，每个大版本都有 36 个月生命周期。以前是半年一发、只有偶数版本进 LTS
- 分发包带 PGP 签名的 SHASUMS256.txt.asc，keyring 单独放在 nodejs/release-keys 仓库，下载后可以用 gpgv + shasum 校验二进制是否被篡改

**核心功能**

- 底层用 V8 执行 JS，用 libuv 做事件循环，网络和文件 I/O 走非阻塞回调，单线程就能处理大量并发连接
- 内置了不少工具链：node:test 测试运行器、TypeScript 类型剥离（--experimental-strip-types，只删除类型不做类型检查）、单文件可执行程序 SEA，很多项目不用再装 ts-node、jest、pkg

> TensorFold 是一个用 Zig 写的 LLM 推理引擎，直接读取 checkpoint 并在 Metal/CUDA/Vulkan 上运行，不依赖 Python 或 MLX，装个二进制就能起 OpenAI 兼容服务。
