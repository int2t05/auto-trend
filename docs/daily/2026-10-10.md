# GitHub Trending 日报 · 2026-10-10

## 概览

今日共收录 **11** 个 GitHub Trending 项目。
主要语言分布：Python(3)、TypeScript(1)、C++(1)、Rust(1)、HTML(1)。

今天这份榜单，主线很清楚：大家都在给 AI Agent 造零件和说明书。

一半项目是“技能包”。Matt Pocock 的 SKILL.md、资深工程师流程打包、SwiftUI 经验、绘图技能，本质都是把人的隐性经验写成 AI 能读的文件。Anthropic 更直接，按岗位发插件，销售、法务、财务各一套。竞争点从“模型多强”转向“经验怎么喂进去”，格式也在收敛：markdown 加 MCP。

另一半是落地和降本。阿里开源内部用了两年的代码审查工具，评论精确到行，同模型下 token 只要 Claude Code 的九分之一；LiteLLM 把网关核心换成 Rust，拼高并发低延迟。企业开始算账了，不再只是尝鲜。

逆向工程那块很扎眼。REA 让 Agent 用 Ghidra 读无源码应用，PS5 游戏被重链接成原生程序。AI 正从“能写代码”走到“能看懂别人的代码”，黑盒在被拆开。

再往外看，LingBot-Map 一次前向就算出 3D 结构，ArtCraft 单日涨三千七百星。开源项目在往 Agent 底座上靠，谁提供被 Agent 调用的能力，谁就吃到流量。

一句话：Agent 不缺脑子，缺的是手脚、规矩和账本。今年拼的是谁把这三样配齐。

### [morluto/rea](https://github.com/morluto/rea)

 `TypeScript` ⭐ +14,927 今日新增 · 52,733 总星数

> REA 把 Hopper、Ghidra、Electron 拆包等逆向工具通过 MCP 接给 AI Agent，让它看懂无源码应用的功能并照着实现。

**亮点**

- 不自己造反编译器，而是复用你本机已装的 Hopper/Ghidra/IDA——分析能力直接继承成熟工具，REA 只做调度和把结果整理成 Agent 能消化的格式，省掉了重建反编译器的巨大成本。
- MCP 和 CLI 走同一套 workflow 实现，Agent 和人手动在终端跑的是同一条链路，输出格式一致，方便脚本化、快照对比和结果复现。

**核心功能**

- 用 MCP（Model Context Protocol，让 Agent 调用外部工具的标准协议）统一封装多类逆向后端：原生二进制走 Hopper/Ghidra/IDA 桥接，JS/Electron 走静态解析，另支持 .NET 程序集、EVM 字节码、ELF 布局和 Linux 崩溃记录，Agent 用同一套接口调用。
- 静态分析 JS/Electron 时不需要任何反编译引擎，只靠 Node.js：直接解析 ASAR 包，输出模块、import 依赖、source map、路由、IPC 边界和原生插件调用关系。
- 所有结论都附带证据和局限（代码位置、引用、不确定项），Agent 拿到的是可追溯的定位信息，而不是一段没出处的解释，方便它继续追问或验证。
- setup 命令会改写 Claude Code、Codex、Cursor、Gemini CLI、Grok Build 等 Agent 的配置文件，注入 MCP server 和配套的 workflow 提示词，并备份原配置。

**适用场景**: 想复刻竞品某个功能但没有源码的客户端/前端开发者，直接在 Claude Code 或 Cursor 里让 Agent 分析目标应用；安全研究员和 CTF 选手用它做二进制和 EVM 的快速摸底；排查 Electron 应用 IPC 行为或崩溃的人也能用。

**竞品对比**: 和 Ghidra MCP、IDA MCP 这类单点插件比，REA 不止给某个反编译器套个 MCP 壳，而是横跨二进制、Electron、.NET、EVM、网站；和直接让 Claude Code 读源码比，它处理的是完全没有源码的目标。

**成熟度**: 迭代很快的早期到中期项目，README 自己提示版本变动频繁、要常更新，文档和多语言 README 齐全，建议锁版本后再用于生产。

**趋势信号**: MCP 已经成为 Agent 接外部工具的事实标准，Claude Code、Cursor 这类工具又刚普及，'让 Agent 自己去做逆向'这个缺口正好被填上；同时项目铺了 19 种语言的 README 和 Trendshift 徽章，明显在做集中社区推广。

### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5)

 `C++` ⭐ +5,868 今日新增 · 23,181 总星数

> 把 PS5 可执行文件重链接成 Linux/Windows 原生程序，重写系统库让游戏直接跑，不靠模拟器、不额外起运行时进程。

**亮点**

- 换了一条路：不模拟 CPU/GPU，而是重链接二进制 + 手写系统库实现，所以没有模拟器的指令翻译开销。README 里 Dreaming Sarah 这种 2D 游戏在 GTX 1050 Ti / i5-7500 上能稳 60fps。
- 项目自带技术债文档和系统库覆盖率徽章，把"还有多少函数没实现"公开成进度条，这种做法在同类项目里不多见。

**核心功能**

- relinker（重链接器）把 PS5 可执行文件转成目标平台的原生格式，PS5 的系统 prx 库（主机上的系统动态库）用 C++ 重写成原生 .so/.dll，游戏直接动态链接上去，不做指令级翻译。
- 着色器重编译器把 PS5 的 GPU 着色器翻译成 SPIR-V（Vulkan 用的中间字节码），并在开启 ANYPS5_ENABLE_SPIRV_TOOLS 时用 Spirv-Tools 校验结果，把翻译错误挡在运行前。
- 遇到不支持或没覆盖到的状态直接抛 std::runtime_error，把 what() 打到 stderr 后结束进程，不静默降级——兼容到什么程度一眼能看出来，代价是容错差。

**适用场景**: 跑在 PC 上玩 PS5 独占游戏的玩家，以及做主机逆向、游戏保存和兼容层研究的开发者。输入用 SDL 手柄，键鼠可以写 anyps5-input.ini 配置。

**竞品对比**: 对手是 shadPS4、Kyty 这类 PS4/PS5 模拟器，以及 RPCS3 的模拟路线。最大区别是不模拟硬件，游戏跑的是原生指令；代价是每少一个系统函数就得手动重写，兼容性推进速度比模拟器慢得多。

**成熟度**: 早期项目，兼容列表里通过验证的游戏极少（目前主要是一个 2D 平台游戏），但文档齐全、含技术债说明，GPLv2 授权。

**趋势信号**: PS5 模拟/越狱话题当下正热（shadPS4 等），而"不写模拟器、直接重链接成原生程序"是条明显不同的新路子，一天涨近 6000 star 有传播效应加成。

**竞品对比**: 同类是 ComfyUI、InvokeAI 这类节点式生成工作流工具；最大差别是 ArtCraft 用 Rust 写核心并编译成桌面客户端，跑在本地而不是 Python + 浏览器。

**成熟度**: 早期项目，README 目前基本只有一张 ASCII 画和文档链接，技术细节还压在 _develop/ 里，API 大概率不稳定，不建议上生产。

**趋势信号**: 单日 3752 星、占总星数三成，是典型的开源首发爆量曲线——Storyteller 团队（做 meme 和短视频生成的那家）把内部 Rust 引擎开源，正好撞上「本地可控生成」这波热度。

### [mattpocock/skills](https://github.com/mattpocock/skills)

 `Shell` ⭐ +1,687 今日新增 · 283,103 总星数

> Matt Pocock 把自用的 Agent 技能开源：一组可插拔的 SKILL.md 命令，治 AI 编码跑偏、啰嗦、不写测试，跨 Claude Code / Codex / Copilot / Gemini CLI 通用。

**亮点**

- 路线和主流「AI 全流程框架」相反：不做流程管家，只给十几条互相独立、可组合的小技能，你随时能改能删，框架出 bug 时不会被卡住
- 把「共享语言」当成核心杠杆：先和 Agent 对齐一套项目术语表，之后变量名、文件名、思考用词都统一，改一个词能让 Agent 少啰嗦、省 token、也更好在代码库里导航

**核心功能**

- /grill-me 和 /grill-with-docs 在写代码前让 Agent 反过来追问你需求细节做对齐；后者还边问边产出项目术语表（CONTEXT.md 那类 glossary）和 ADR 架构决策记录，让 Agent 和你说同一套黑话
- /tdd 强制红-绿-重构循环：Agent 必须先写一个跑不通的测试，再改代码把它跑通，把「有没有反馈」变成硬约束而不是建议
- 纯 Markdown + Shell 实现，装法是接进各家 Agent 的原生插件市场（claude plugin install / codex plugin / copilot plugin / gemini skills install），或用 npx skills 把可编辑的 SKILL.md 直接拷进项目手动改；不绑定任何模型

**适用场景**: 日常用 Claude Code、Codex、Copilot 写真实业务代码的工程师，特别是 TypeScript/前端项目；以及想让团队统一 AI 编码流程、已经把 issue 挂在 GitHub 或 GitLab 上、需要用标签做 triage 的团队。

**竞品对比**: 直接对标 GitHub Spec-Kit、BMAD、GSD。差别是那几家要接管整个流程（spec → plan → tasks），这个是十几条独立小技能，装哪个、改哪个由你定，而且同一套技能能跨多家 Agent 复用。

**成熟度**: 无版本号、靠插件市场自动更新的个人技能集合，文档和使用说明写得挺细、有约 6 万人订阅的 newsletter，但本质是作者自己的工作流，别指望稳定的对外 API。

**趋势信号**: Anthropic 推 Agent Skills 标准、Claude Code 插件市场上线后，各家 CLI Agent 陆续支持 SKILL.md，Matt Pocock 借着 TypeScript 圈的影响力和 6 万订阅把这波「给 Agent 配可复用技能包」的热度接住了。

> Anthropic 官方开源 11 个按岗位划分的插件，让 Claude Cowork/Claude Code 变成销售、法务、财务等角色的专用助手，纯 markdown 配置，通过 MCP 接入企业现有工具。

**亮点**

**核心功能**

- 11 个插件按职能拆分（销售、法务、财务、数据、客服、市场、产品、企业搜索、生物研发等），每个插件固定四件套：plugin.json 清单、.mcp.json 工具连接配置、commands/ 斜杠命令、skills/ 领域知识，全是 markdown 和 JSON，没有一行可执行代码，也没有构建步骤

**适用场景**: 销售、法务、财务、PM、市场、客服这类非工程岗位的知识工作者，用 Claude Cowork 做客户调研、合同审查、对账关账、写 spec、写文案这类日常活儿。也适合想让全团队用同一套流程和术语的团队负责人，把公司自己的工具栈和规范写进插件文件共享。

**竞品对比**: 对标 OpenAI 的 Custom GPTs 和市面上的 Agent 模板。最大差别是文件化和协议开放：GPTs 是在 ChatGPT 界面里点出来的配置，锁在平台内；这套是能进 Git 做版本管理的文件，走开放的 MCP 协议，且同一份插件在 Cowork 和 Claude Code 两个产品里都能跑。

**成熟度**: 刚开源，没有公开版本号，但由 Anthropic 官方维护、内容全是不含执行逻辑的 markdown，实际风险主要在插件质量参差，基本都要按自己公司情况改写才能用。

**趋势信号**: Claude Cowork 新发布，Anthropic 顺势开源官方插件库给新平台补生态位，同时把 MCP 从开发者工具推向普通知识工作者。

### [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)

 `JavaScript` ⭐ +436 今日新增 · 104,149 总星数

> 把资深工程师的研发流程（需求→计划→编码→测试→评审→上线）打包成 AI 代理能直接读的 SKILL.md 技能文件，让 Claude Code、Cursor 等 70+ 工具有章法地干活。

**亮点**

- 把"流程"和"技能"分成两层：斜杠命令只管阶段顺序和卡点，技能文件管具体怎么做，两者解耦后可以只装自己需要的那几个技能。
- /build auto 的取舍很明确——去掉的是人在任务之间点"下一步"的动作，不是验证：每个任务仍强制测试先行、单独提交，失败或高风险时暂停等人工介入。

**核心功能**

- 把开发生命周期拆成 9 个斜杠命令（/spec /plan /build /test /constraints /review /webperf /code-simplify /ship），每个命令按需加载对应技能文件，而不是把所有提示词一次性塞进上下文，省 token 也更可控。
- 技能用统一的 SKILL.md 目录格式，通过 vercel-labs/skills CLI 分发，一条 npx skills add 能装进 70+ 种代理（Claude Code、Cursor、Codex、Copilot、Gemini CLI、Windsurf、OpenCode 等），换工具不用重写提示词。
- 支持按上下文自动触发技能：设计 API 自动上 api-and-interface-design，写前端自动上 frontend-ui-engineering；/build auto 先出计划、人审批一次后逐任务测试并单独提交，出错或遇到高风险步骤会停。

**适用场景**: 日常用 Claude Code、Cursor、Codex 写真实项目的开发者和中小团队。想在 agent 里固定住测试先行、代码评审、性能先测量这些习惯，又不想每次手写长提示词或维护一堆 Cursor Rules / 子代理配置。

**竞品对比**: 对比 Anthropic 官方 Skills、obra/superpowers 这类技能库，以及各家 Cursor Rules / Claude 子代理配置，最大差异是不绑定单一工具，靠统一的 SKILL.md 格式加 CLI 一次装到 70+ 代理，并且覆盖从 spec 到 ship 的完整链路而不是零散技巧。

**成熟度**: README 自称 production-grade，但本体是一堆 markdown 提示词，仓库自己还挂着 #361（单技能安装会丢 references/ 目录）这类移植问题，格式也跟着各家代理规范在变，属于快速迭代期，别指望接口长期稳定。

**趋势信号**: Anthropic 推 Agent Skills 格式、Vercel 出了 skills 安装 CLI 之后，"用技能文件管住 agent 行为"成了社区新共识，叠加 Addy Osmani 在 Chrome/前端圈的知名度，这个合集顺势被推上趋势榜。

### [alibaba/open-code-review](https://github.com/alibaba/open-code-review)

 `Go` ⭐ +326 今日新增 · 45,457 总星数

> 阿里把内部用了两年、数万开发者验证过的 AI 代码审查工具开源了。它用确定性流水线加 LLM Agent 的混合架构，评论精确到行，同模型下 token 消耗约为 Claude Code 的九分之一。

**亮点**

- 思路是反过来的：不是让 Agent 什么都干，而是把「必须正确」的步骤用工程逻辑锁死，只把「需要判断」的步骤留给模型。作者认为纯语言驱动的 Skill 架构缺少硬约束，才会出现漏审、行号漂移、质量随 prompt 波动
- 明确做了精度优先的取舍——Recall 故意低于通用 Agent，换来更高的 Precision 和 F1，理由是漏报比误报便宜（误报要人工逐条 triage）。这个取舍在项目里是写明的，不是意外

**核心功能**

- 混合架构：文件筛选、文件打包、规则匹配、评论定位这些不能出错的环节交给确定性代码，只有动态决策和上下文检索交给 LLM Agent。规则匹配用模板引擎而不是自然语言 prompt，输出更稳定
- 相关文件自动打包成一个审查单元（比如 message_en.properties 和 message_zh.properties 绑在一起），每个包跑独立 sub-agent、上下文隔离，天然支持并发，大 changeset 不会漏文件
- 两个独立后处理模块负责评论定位和评论反思，专门修 AI 反馈常见的行号漂移和内容跑偏；Agent 本身带工具调用，能读完整文件、搜代码库、看其他改动文件补上下文
- 内置多语言规则集，覆盖 NPE、线程安全、XSS、SQL 注入这类确定性问题，不依赖模型自己想起来

**适用场景**: 研发团队在 CI 里接 GitHub/GitLab 的 PR 流水线，让机器先跑一遍行级评论，人工 reviewer 只处理真问题，减少误报噪音。也适合接手老代码库时用 ocr scan 对整文件做审计，没有 diff 也能审。 适配 Claude Code、Codex、Cursor、Kimi Code 等 Agent，模型端点走 OpenAI/Anthropic 兼容协议，想换模型只改配置。

**竞品对比**: 对手是 Claude Code / Codex 这类通用 Agent 加 Skills 的玩法，以及 CodeRabbit、Qodo 这些商业 AI review 工具。最大差异是它用一个公开可复现的 benchmark（AACR-Bench：50 个仓库、200 个真实 PR、10 种语言、80+ 资深工程师标注的 1505 条 ground truth）证明同模型下 token 只花约九分之一、精度更高，而通用 Agent 只能靠体感。

**成熟度**: 生产就绪。阿里内部跑了两年、服务数万开发者，拿到 OpenSSF Gold 认证，已发 npm 包，GitHub 45k star，多语言文档齐全。

**趋势信号**: AI 代码审查正是当下热点，但通用 Agent 做 review 的漏审、行号漂移、token 烧钱问题已经被大量吐槽，阿里这时把内部打磨两年、带公开 benchmark 和 OpenSSF Gold 背书的工具开源，正好卡在「大家试过通用方案但不满意」的节点上。

### [Robbyant/lingbot-map](https://github.com/Robbyant/lingbot-map)

 `Python` ⭐ +110 今日新增 · 17,798 总星数

> LingBot-Map 是一个流式 3D 重建的「前馈式」基础模型：喂进一段视频，一次前向就算出相机位姿和 3D 结构，518×378 分辨率下约 20 FPS，能扛住 1 万帧以上的长序列。ECCV 2026 最佳论文候选。

**亮点**

- 用「锚点上下文 + 轨迹记忆」在流式推理里做漂移修正，绕开了传统 SLAM 的后端全局优化和回环检测——代价是精度依赖模型本身而不是几何优化。
- 把 LLM 推理里的分页 KV 缓存（FlashInfer）直接搬到 3D 重建的时序注意力上，这是让「上万帧流式」在工程上跑得起来的关键取舍。

**核心功能**

- Geometric Context Transformer 把三件事塞进一个流式框架：坐标定位、密集几何线索、长距离漂移修正；靠 anchor context（锚点上下文）、pose-reference window（位姿参考窗口）、trajectory memory（轨迹记忆）三个机制实现，不依赖传统的回环检测做全局优化。
- 注意力用 paged KV cache（分页 KV 缓存）——这是从 LLM 推理搬过来的技术，把历史帧的键值缓存分页管理，FlashInfer 后端跑长序列显存不爆，518×378 下稳定 20 FPS，超过 10,000 帧不崩。
- 前馈式单次推理：不做 per-scene 迭代优化，不像 COLMAP 或 SLAM 那样退出建图流程；同时发布了 KITTI、Oxford Spires、TUM-D、7-scenes、ETH3D 等 9 个数据集的评测脚本。

**适用场景**: 做机器人、无人机、AR/VR 的团队需要边走边实时建图，又不想上重型 SLAM 系统；以及研究流式 3D 重建、拿视频做长序列场景重建的科研人员。

**竞品对比**: 同类有 DUSt3R / MASt3R / VGGT（离线、一次前向做多视图重建，不看时序），以及 CUT3R / Spann3R（做流式但长序列会漂移）。LingBot-Map 的差异点是：单次前向 + 长序列不漂移 + 20 FPS 三者同时满足。传统方案 ORB-SLAM3 靠回环检测，精度高但流程重、场景泛化差。

**成熟度**: 研究项目阶段：Apache-2.0 授权，HuggingFace/ModelScope 权重和 9 个 benchmark 脚本齐全，但仍在修 FlashInfer 和 SDPA 的 KV cache bug，接口可能变动，暂不建议直接上生产。

**趋势信号**: 挂着 ECCV 2026 最佳论文候选的名头，最近接连放出 2.5 万帧长视频 demo、评测 benchmark 和推理加速（--compile），正好赶上「3D 基础模型 + 流式重建」这波热度。

> LiteLLM 是一个开源 AI 网关，用 OpenAI 格式统一调用 100+ 家大模型（OpenAI、Anthropic、Bedrock、VertexAI 等），带成本统计、虚拟密钥、限流和负载均衡。最近把网关核心换成 Rust，主打高并发低延迟。

**亮点**

- 网关和 SDK 分离：库就那么用 import litellm，服务化就起 proxy，同一套配置两边跑，不用为部署模式写两遍代码
- 把 A2A 协议也纳进来了，不只代理模型调用，还能调 LangGraph、Vertex AI Agent Engine 等远端 Agent，试图做模型+Agent 的统一入口

**核心功能**

- 统一适配层：把 100+ 家模型的请求/响应/错误类型全翻译成 OpenAI 的 chat/completions 格式，换模型只改 model 字符串，不动业务代码
- 网关核心用 Rust 重写，官方基准是 1k RPS 下 P95 延迟 8ms；Python 侧保留 SDK 和代理配置层，还拆出无额外依赖的 litellm-core 独立发行包
- 内置虚拟密钥 + 花费追踪 + 限流 + 守卫栏（guardrails）+ 负载均衡，按 key/团队/模型维度记账和限流，另有管理后台看用量

**适用场景**: 需要同时接多家模型的团队：AI 应用后端、平台工程团队、做 LLM 中台的公司在 LiteLLM 网关后挂各家 API，统一发 key、统一记账、做故障切换；也有人在 LangGraph、OpenHands 这类 Agent 框架里当模型调用层。

**竞品对比**: 同领域有 Portkey、Kong AI Gateway、Cloudflare AI Gateway、OpenRouter（托管版）。LiteLLM 最大的差异是开源可自托管 + Python 生态贴合度最高，而且 provider 覆盖数量最多；Portkey 更偏可观测性，OpenRouter 是托管服务不能自建。

**成熟度**: 生产可用，60k star、YC W23 出身，Stripe、Netflix 等公司在用，有企业版和托管代理；但网关核心刚从 Python 转 Rust，属于进行中的重构，升级时要注意版本兼容。

**趋势信号**: 多模型混用成为常态、各家 Agent 框架都在找统一模型入口，加上这次把网关核心换成 Rust 的性能重写和瘦身版 litellm-core 发行包，正好踩在企业自建 AI 网关的需求上。

**趋势信号**: Agent Skills 格式刚被 Claude Code 插件市场和多个 AI 编码工具接受，正变成跨助手的事实标准；加上作者在 Swift 圈的影响力，一条 npx 命令就能装完。

## 趋势观察

今天这份榜单，主线很清楚：大家都在给 AI Agent 造零件和说明书。

一半项目是“技能包”。Matt Pocock 的 SKILL.md、资深工程师流程打包、SwiftUI 经验、绘图技能，本质都是把人的隐性经验写成 AI 能读的文件。Anthropic 更直接，按岗位发插件，销售、法务、财务各一套。竞争点从“模型多强”转向“经验怎么喂进去”，格式也在收敛：markdown 加 MCP。

另一半是落地和降本。阿里开源内部用了两年的代码审查工具，评论精确到行，同模型下 token 只要 Claude Code 的九分之一；LiteLLM 把网关核心换成 Rust，拼高并发低延迟。企业开始算账了，不再只是尝鲜。

逆向工程那块很扎眼。REA 让 Agent 用 Ghidra 读无源码应用，PS5 游戏被重链接成原生程序。AI 正从“能写代码”走到“能看懂别人的代码”，黑盒在被拆开。

再往外看，LingBot-Map 一次前向就算出 3D 结构，ArtCraft 单日涨三千七百星。开源项目在往 Agent 底座上靠，谁提供被 Agent 调用的能力，谁就吃到流量。

一句话：Agent 不缺脑子，缺的是手脚、规矩和账本。今年拼的是谁把这三样配齐。
