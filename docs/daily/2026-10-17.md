## 概览

今日共收录 **13** 个 GitHub Trending 项目。
主要语言分布：Python(5)、TypeScript(3)、JavaScript(2)、Rust(1)、Shell(1)。

今天的榜单基本是一个主题：给 AI 编程 Agent 铺基础设施。 第一条线是插件标准化。Anthropic 出了官方插件目录，Cursor 出了插件规范仓库，Google 出了给 Agent 看的 Android 开发说明书。SKILL.md、plugin.json 这类清单文件正在变成事实标准。以前每个工具各写各的提示词，现在讲的是“一次配置、多处复用”。有项目直接把 7 种编程助手的技能和安全规则打包成一套，就是这个思路。 第二条线是省上下文。有项目把工具返回的原始数据挡在上下文外，号称省 98%；有项目一条命令索引目录，省 2.7 倍输出 token；还有项目用 SQLite 帮长会话找回记忆。大家解决的是同一个问题：Agent 能干活，但记不住，也塞不下。 第三条线是补接口。CLI-Anything 给桌面软件自动生成命令行封装，音频工具做了本地 MCP 接口。Agent 要操作真实软件，缺的不是智力，是入口。 另外，本地优先很明显。求职流水线、声音克隆都强调数据不出本机。 一句话收束：这一波不是造更强的模型，而是给模型修路——统一插件格式、压缩上下文、补齐软件接口。谁先理顺这三件事，谁就握住 Agent 时代的入口。

### [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)

 `Python` ⭐ +2,301 今日新增 · 71,519 总星数

> 把 ElevenLabs 的声音克隆、配音、转写整套流程放到本地跑的开源桌面应用。音频不用上传云端，还带本地 API 和 MCP 接口，能直接给 AI Agent 调用。

**亮点**

- 桌面外壳从 Tauri 重写成 Electron，底层是 Python 后端。这样既能打包成 macOS/Windows/Linux 安装包，也能让 Intel Mac 只运行 UI、把推理放到远程后端，或直接向已有的 Docker 后端发起请求
- 安装脚本会先探测硬件，再决定安装 CUDA、MPS 还是 CPU 版 PyTorch，用一条 curl 命令处理完依赖问题；另外还写了给 AI Agent 看的安装文档和 skills 分发命令（npx skills add），让 Agent 自己完成安装和测试生成

**核心功能**

- 语音引擎可插拔：默认用 k2-fsa/OmniVoice，也能换其他 TTS/ASR 引擎；模型在应用内按需下载和管理，不必手动配置环境
- 全部推理都在本地运行：NVIDIA 显卡走 CUDA，Apple Silicon 走 Metal\(MPS\)，没有独立显卡就安装约 5GB 的 PyTorch CPU 小包，在 CPU 上跑，只是速度慢一些
- 同时提供本地 HTTP API 和 MCP server，支持 watch folder 批量任务，Claude Code、Cursor 这类 Agent 可以直接调用它生成语音或转写
- 视频配音先把语音按时间轴对齐再合成，支持多语言、有声书和批处理任务队列

**适用场景**: 短视频和播客创作者需要批量生成多语言配音，或者制作有声书；企业里法务、医疗等不能把录音上传到云端的场景需要做转写；Agent 开发者通过 MCP 给自己的 AI 工作流加上本地语音合成能力。

**竞品对比**: ElevenLabs 是云端服务，按字符收费，音频需要离开本机。开源这方面，XTTS、F5-TTS、GPT-SoVITS、Kokoro 这些是模型或库，不带 GUI、配音时间轴、批量任务和 Agent 接口。VoiceStudio 的差异在于它已经把这些能力整合进一个可用的桌面产品。

**成熟度**: 早期项目，版本还在 0.x，Desktop 外壳刚完成从 Tauri 到 Electron 的迁移，旧版 Tauri 用户必须重新安装，API 和目录结构可能还会变动。

**趋势信号**: 本地 TTS 模型（OmniVoice 等）的音质已经接近能用，加上 MCP 生态正在兴起、需要本地语音工具，而且 ElevenLabs 这类云端方案的费用和隐私顾虑一直存在，这几个因素正好在这个时间点汇合。

### [xerj-org/xerj](https://github.com/xerj-org/xerj)

 `Rust` ⭐ +1,648 今日新增 · 7,065 总星数

> 一条命令索引任意目录（代码/PDF/日志），让 Claude Code、Cursor 这类 agent 查片段替代 grep 整文件，官方实测省 2.7 倍输出 token。Elasticsearch 兼容、MCP 原生。

**亮点**

- `xerj def` 提供跨文件符号定位（返回 file:line + 签名），agent 拿的是定义而不是整份文件，这是 2.7 倍 token 节省的直接来源
- `/_memory` 命名空间把同一套索引复用成 agent 的长期记忆；`xerj gain` 统计实际省下的 token 数，而不是拍脑袋估算

**核心功能**

- autoindex 会逐个嗅探文件类型（源码、PDF、SQLite、CSV、日志），按类型自动建索引，不用写 schema 也不用配 ETL 管道
- 检索层是 BM25 词法 + kNN 向量 + 混合排序；默认只跑离线词法，神经向量模型要手动开、约 90MB 下载，避免默认场景依赖模型
- 对外是 Elasticsearch 兼容的 HTTP 接口（ES-YAML 一致性 1366/1369 个用例），现有 ES 客户端改个地址就能查；同时原生 MCP，`xerj init` 一条命令写进 Claude Code/Cursor 配置
- Rust 编译成单静态二进制，不依赖 JVM，也就不存在 ES 那套 JVM 堆调优和集群运维

**适用场景**: 手里有私有或内部代码库、又用 Claude Code / Cursor 写代码的开发者 —— 让 agent 先查已索引片段再动笔，而不是 grep 完把整文件塞进上下文。也适用于安全审计、RAG 建库、翻日志和 PDF 文档的团队。

**竞品对比**: 对比 ripgrep/grep 是逐个文件往上下文里灌；对比 Sourcegraph 要起服务且偏企业；对比 Elasticsearch 要 JVM 和调参；对比 Qdrant/Chroma 只管向量不管词法。XERJ 的差异点是单二进制 + 零配置 autoindex + ES 协议兼容三件套。

**成熟度**: 早期可用：有基准案例和 ES 兼容测试，但公开示例一律带 `--insecure` 跑无鉴权模式，说明认证和部署这块还没收尾，适合开发机自用。

**趋势信号**: 赶上 Claude Code / Cursor 普及后大家开始算 token 账单，README 又直接给一段“让 agent 自己装自己配”的提示词，传染性很强；加上“交一份使用报告换会员”的玩法在拉 PR 和讨论。

### [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official)

 `Python` ⭐ +1,552 今日新增 · 40,762 总星数

> Anthropic 官方维护的 Claude Code 插件目录，用一条命令就能装插件；它刚随插件市场功能上线，就冲上了趋势榜。

**亮点**

- 官方只做索引，不托管代码：插件仓库留在作者那边，marketplace 只存引用和锁定的 commit sha。README 里明说 Anthropic 不控制也不验证插件内容，安全责任直接推给用户；这样省掉了托管和审计成本，也避免了背书风险
- 双轨制：内部 plugins/ 由 Anthropic 自己写，外部 external_plugins/ 需要过质量与安全审核才能进来，相当于给社区插件开了个白名单入口

**核心功能**

- 目录本身是一个 marketplace.json 清单，Claude Code 插件加载器直接读取它，输入 `/plugin install 名字@claude-plugins-official` 就能装完；每个插件必须按固定结构放置文件，包括 plugin.json 元数据，以及可选的 .mcp.json、commands/、agents/、skills/
- 插件 name 被定为不可变 slug，改名会触发 plugin-not-found。为了兼容，marketplace.json 里提供了顶层 renames 映射，老名字会在用户下次 sync 时被透明改写成新名字，这是包管理器级别的兼容处理
- 当源仓库只有 SKILL.md、没有 plugin.json 时，用 `strict:false` 加 git-subdir 源和固定 commit sha 直接挂 skills 数组，还支持 `./libA/skill-1` 这种跨多级目录挑子集，每个技能注册成 `&lt;插件名&gt;:&lt;技能名&gt;`

**适用场景**: 给 Claude Code 用户用：想让 agent 接 Jira、查数据库、跑代码审查，不必自己写 MCP server，直接 /plugin 里搜到就装。第三方工具厂商则通过提交表单，把自己的 MCP 服务放进 Claude Code 的工作流。

**竞品对比**: 对标 MCP 目录站（Smithery、mcp.so、Glama）和 Cursor 的扩展市场。最大差别是它被 Claude Code 加载器原生读取，装插件跟装包一样一条命令，还带 renames 迁移和固定 SHA 这些包管理器才有的东西；MCP 目录站大多只给你一段复制粘贴的配置 JSON。

**成熟度**: 早期项目：上线没几天就冲到 4 万星，处在生态卡位阶段；插件由第三方自维护，官方不做安全验证，生产环境用之前得自己审代码。

**趋势信号**: Claude Code 的插件市场功能刚发布，Anthropic 亲自下场做官方目录，等于给“agent 插件生态”定标准，用户和工具厂商同时涌进来。

### [affaan-m/ECC](https://github.com/affaan-m/ECC)

 `JavaScript` ⭐ +1,057 今日新增 · 281,640 总星数

> 把 Claude Code、Cursor、Codex 等 7 种 AI 编程助手的技能、记忆和安全规则打包成一套插件，一次配置多处复用，省得每个工具各维护一份。

**亮点**

- 核心是把各 harness 私有的规则格式抽象成一层公共配置，再分别转译到各个 harness；这是它比单工具规则包更有价值的地方
- 开源用 MIT 保持不变，商业收入放在托管的 GitHub App 和私有仓库订阅（$19/seat/月）；这个取舍既让社区能改，也让作者能靠托管服务赚钱

**核心功能**

- 同一套 skill/规则源文件走三条分发通道：Claude Code 插件（ecc@ecc）、npm 包 ecc-universal、GitHub App，装一次就能推到 7 个 harness，不用给每个编辑器各写一份配置
- 安全模块单独发成 npm 包 ecc-agentshield，在装插件前先检查 Agent 的配置和权限，挡掉提示词注入和危险命令这类常见问题
- 带持久状态：把项目约定和纠正过的错误保存成可供之后复用的记忆（instincts），新会话不用重新解释背景；research-first 流程要求 Agent 先查资料再改代码

**适用场景**: 适合同时使用 Claude Code、Cursor、Codex 的开发者和平台团队：给几十号人的研发团队统一 Agent 行为规范，或让同一个人在不同工具之间切换时保持一致的规则和记忆。

**竞品对比**: 同领域里，awesome-claude-code 这类仓库只是规则文件的清单合集，mem0、claude-mem 只解决记忆这一件事，Cursor rules 仓库绑定在单一工具上。ECC 的区别是一份配置跨 7 个 harness，外加安全层和付费托管服务。

**成熟度**: 有 npm 包、GitHub App 和付费席位，说明已具备生产可用基础；但由单个维护者维护，28 万 star 与实际装机量差距很大，可能过于夸张，接入前建议先看 issue 和实际用户反馈。

**趋势信号**: 2025-2026 年编程 Agent 从 Claude Code 一家独大变成 Claude Code、Codex、Cursor、Opencode 多 harness 并存，社区缺少跨工具统一的配置标准，这个项目正好抓住了跨工具这一空位。

### [obra/superpowers](https://github.com/obra/superpowers)

 `Shell` ⭐ +973 今日新增 · 300,751 总星数

> 一套给编程 Agent 用的开发方法论，用可组合的 skills 强制 Agent 先问清需求、写规格、做计划，再派子 Agent 按 TDD 执行。装一次就能在 20 多个 Agent 工具里生效。

**亮点**

- 把方法论做成“插件 + 技能”而不是文档：规则以 skill 形式随会话自动加载，等于给每个 Agent 装上了同一套工作习惯，比让每个人抄 CLAUDE.md 或 .cursorrules 更可控
- 子 Agent 驱动开发：主 Agent 只做拆解和评审，具体任务派给子 Agent 执行并回检，让单次自主运行能持续一两个小时而不跑偏——这是把“长时自治”拆成可验证的小步，而不是赌模型一次做对

**核心功能**

- skill 自动触发机制：往 harness 里注入一个 using-superpowers 引导 skill（Claude Code / Codex / Pi 走 SessionStart 钩子），会话一开始、以及上下文被压缩（compaction）之后重新注入一次，用户不用手动 /skill 调用
- 分阶段的流程编排而不是单条提示词：先逼 Agent 停下来澄清需求 → 把规格拆成短块给你逐段确认 → 生成“给一个没品味、不看上下文、不爱写测试的初级工程师也能照做”的实施计划 → 再启动子 Agent 逐个任务开发、自检、评审
- 把工程纪律写死进技能里：明确要求真红/绿 TDD（先写失败测试再写实现）、YAGNI（用不到的功能不写）、DRY，用规则约束 Agent 而不是指望模型自觉
- 一份仓库内容适配 20+ 种 harness：Claude Code、Codex App/CLI、Cursor、Gemini CLI、Copilot CLI、Grok Build、Kimi Code、Qwen Code、OpenCode、Devin、Factory Droid 等各自用原生插件机制安装（/plugin、gemini extensions、droid plugin marketplace 等），Shell 只是承载脚本和安装逻辑

**适用场景**: 日常用 Claude Code / Cursor / Codex 写业务代码的开发者，尤其是接手陌生代码库、或者被 Agent “没问清就乱改文件”坑过的人；也适合技术负责人想把团队里“Agent 怎么写代码”的规范统一成一份可安装的插件。 企业侧可以配合作者提供的商业支持（sales@primeradiant.com）做托管开销和额外工具集成。

**竞品对比**: 同类有 GitHub 的 spec-kit、BMAD-METHOD、以及各家自带的 CLAUDE.md / AGENTS.md / Cursor Rules。最大差异是 harness 无关：竞品基本绑死一家工具或只给模板文档，Superpowers 用各家原生插件市场分发同一套技能，并且靠钩子自动触发、压缩后重注入，不需要用户记着去调用。

**成熟度**: 已进 Anthropic、OpenAI、xAI 等官方插件市场并有商业支持，可用；但方法论类项目随模型能力变化迭代快，技能内容可能过期，且装多个 harness 时要分别安装、各 harness 钩子能力不一致（如 Hermes 无压缩后钩子）。

**趋势信号**: Anthropic 推出 Agent Skills 规范、各家 CLI 同期开放插件市场（Codex /plugins、Grok marketplace、Kimi /plugins），让“一份技能跨工具复用”第一次真正可行，这个项目刚好卡在这个窗口上。

## 趋势观察

今天的榜单基本是一个主题：给 AI 编程 Agent 铺基础设施。 第一条线是插件标准化。Anthropic 出了官方插件目录，Cursor 出了插件规范仓库，Google 出了给 Agent 看的 Android 开发说明书。SKILL.md、plugin.json 这类清单文件正在变成事实标准。以前每个工具各写各的提示词，现在讲的是“一次配置、多处复用”。有项目直接把 7 种编程助手的技能和安全规则打包成一套，就是这个思路。 第二条线是省上下文。有项目把工具返回的原始数据挡在上下文外，号称省 98%；有项目一条命令索引目录，省 2.7 倍输出 token；还有项目用 SQLite 帮长会话找回记忆。大家解决的是同一个问题：Agent 能干活，但记不住，也塞不下。 第三条线是补接口。CLI-Anything 给桌面软件自动生成命令行封装，音频工具做了本地 MCP 接口。Agent 要操作真实软件，缺的不是智力，是入口。 另外，本地优先很明显。求职流水线、声音克隆都强调数据不出本机。 一句话收束：这一波不是造更强的模型，而是给模型修路——统一插件格式、压缩上下文、补齐软件接口。谁先理顺这三件事，谁就握住 Agent 时代的入口。
