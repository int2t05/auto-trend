### [elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)

 `Python` ⭐ +1,652 今日新增 · 23,498 总星数

> 把 85 个 Claude Code 技能打包成一套 bug 赏金 / 外部红队作业流程，从 681 份公开 HackerOne 报告里提炼出检测模式和攻击链模板，让 Claude 按流程干活而不是瞎猜。

**亮点**

- 分层设计而不是堆技能数量：Think（方法论和红队心态）/ Hunt（Web 漏洞）/ Perimeter（企业边界设备链）/ Ship（验证和报告）四层，每层解决不同阶段的问题，避免模型一上来就乱打 payload。
- 强制“留在范围内”：把 scope 检查、证据脱敏（PII redaction）、报告交付物写成技能规则，这在提示词类工具里少见，减少模型自作主张扫范围外资产的风险。

**核心功能**

- 技能全是纯文本 SKILL.md，按你描述的目标自动匹配加载（说"测 GraphQL"就调 hunt-graphql），不用记命令名。本质是知识库分发，没有可执行扫描器。
- 681 份已披露 HackerOne 报告被拆成 24 类漏洞的检测模式、payload 表、WAF 绕过表和攻击链模板，其中 433 条单独标注了原始报告出处可回溯。
- 通过 MCP 接两个外部系统：Burp Suite MCP 让 Agent 直接读代理历史和重放请求；HackerOne API 用来查私有项目范围和搜重复报告，避免报了别人已交的洞。
- 安装脚本探测本机已装的 Agent harness，把同一份技能复制到 ~/.claude/skills、~/.agents/skills、~/.hermes/skills、~/.gemini/config/skills 四条路径，一份知识喂 Claude Code / Codex CLI / OpenCode / Hermes / AntiGravity。
- triage-validation 技能用“7-Question Gate”逐条追问（能否复现、影响谁、是否需要交互）配合 VRT 漏洞评级标准打分，专门用来卡误报和写 OOS 申诉。

**适用场景**: 独立赏金猎人或小团队接 HackerOne / Bugcrowd 项目时，用它做资产梳理、排序攻击面、按类套检测模板，省掉查 writeup 的时间；企业红队在授权的外部打点阶段，用它对照 M365/Entra、Okta、vCenter、SSL VPN 这些设备的 2024–2026 CVE 链做初筛。 安全培训场景：作者自己在 DVWA、OWASP Juice Shop、Hacker101 上跑过，适合新手跟着流程学“下一步该测什么”。

**竞品对比**: 跟 PentestGPT 比，它不做自动推理循环，只是把方法论和模式喂给现成 Agent；跟 Nuclei 比，它不执行任何检测，模板是给 LLM 读的自然语言而不是可跑的 YAML；跟 HackerOne 的 Hai 这类官方 AI 助手比，它是第三方、跨平台、跟自己项目绑定。最大差异是强调每条模式能追溯到公开报告。

**成熟度**: 文档比较完整（安装、使用、多 harness、技能目录都有），但没看到版本号和自动化测试，靠作者一人维护，输出质量强依赖模型表现，建议先在小范围授权目标上试。

**趋势信号**: Anthropic 的 Agent Skills 格式被 Claude Code、Codex CLI、OpenCode 等多家 harness 同时采纳，加上 AI 辅助漏洞挖掘和自动化赏金最近话题度高，这类“纯提示词技能包”正好踩在生态标准化的窗口上。

### [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)

 `HTML` ⭐ +1,141 今日新增 · 73,365 总星数

> 给 AI 编程助手用的画图技能包，内置 52 种图表模板，输出单个自包含的 HTML+SVG 文件，还能自动套上你网站的配色字体。

**亮点**

- 刻意绕开 Mermaid 那条链路：不让模型输出一段文本 DSL 再交给渲染器，而是让模型直接写 HTML+SVG。好处是留白、字号、颜色、连线路由都能手动调，不受渲染器固定布局和默认主题的限制
- 把“审美”当成技能资产来管：模板、配色规则、字体搭配都写死在 references 里，模型不需要临场发挥设计，风格由技能保证一致

**核心功能**

- 以 Agent Skill 的形式分发：一个 SKILL.md 加上 references/assets/scripts，一份技能包同时装进 Claude Code、Codex、Copilot、Cursor、Qoder 等十几家宿主，靠各家自己的 plugin marketplace 或 npx skills CLI 安装
- 产出是单个 HTML 文件，图形全部内联成 SVG，没有 CDN、没有外链依赖，双击就能打开，也能直接拷进仓库当文档配图
- 内置 52 种图表类型的模板（架构图、时序图、象限图、甘特图等），Agent 会先声明选哪种图、怎么排，再写文件；另外提供 /import-mermaid 和 /import-plantuml 命令，把现有的图转成同一种风格
- onboarding 流程会去抓你指定站点的配色和字体，写进技能变量，之后画的所有图沿用同一套品牌样式

**适用场景**: 后端工程师或架构师让 Claude Code 读一遍代码库，直接产出系统架构图贴进 README 或技术方案。产品经理、咨询顾问要一张排版像杂志的象限图或流程图放进汇报材料，不想为一张图打开 Figma。 已经有大量 Mermaid、PlantUML、draw.io 存量图，想批量换成统一风格的团队。

**竞品对比**: Mermaid、PlantUML、D2 是“文本 DSL + 渲染器”，图和渲染器绑死，样式基本改不动；Excalidraw、draw.io 得手画。这个项目把画图交给 Agent，直接交付可编辑的成品 HTML/SVG，不依赖任何渲染器。最大差异是它压根不是画图工具，是给 Agent 用的提示词和模板包。

**成熟度**: 有 CI、CHANGELOG、画廊和多家 marketplace 分发，迭代很勤；但核心是提示词加模板集合，输出细节会随版本变动，还不能算冻结的 API。

**趋势信号**: 2025 年底 Claude Code Skills 和 skills.sh 这类技能市场起来，加上大家对“模型生成的一坨 Mermaid 丑图”集体疲劳，这个专门解决“图能不能看”的技能正好卡在这个缺口上。

### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 `TypeScript` ⭐ +1,135 今日新增 · 210,373 总星数

> Firecrawl 现在做三件事：本地 Rust 单文件爬虫、云服务、自托管，把网页转成干净 markdown 喂给 AI agent。这轮火的原因是它刚把「本地二进制 + MCP 一键接入」放到最前面，赶上 agent 本地化部署的势头。

**亮点**

- 本地/云混合路由：默认先在本地爬，JS 渲染失败的单页静默交给云，结果里用 `source` 字段标明来源，用户可选 `FIRECRAWL_CLOUD=off` 完全断云——在『数据不出本机』和『别让我配浏览器环境』之间做了折中
- 把 MCP 安装做成 CLI 子命令而不是让用户手改 JSON 配置，还先备份原文件，本质是把『接入 agent』这一步的摩擦降到零，这是纯爬虫库做不到的

**核心功能**

- Firecrawl Local 是一个 Rust 单文件二进制（cargo install firecrawl-local），不需要数据库、队列或 Docker，直接调用你机器上已有的 Chrome/Chromium 渲染 JS 页面，PDF 和 Office 文档也在本地解析
- 跑 `firecrawl-local init` 会自动扫描 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 的配置文件，备份后把它们全都注册成 MCP server，agent 里的 scrape/crawl/map 工具直接走本机
- `serve` 在本机 3002 端口起一个 Firecrawl v2 API，官方 Python/Node SDK 只改 base URL 就能连，本地路由不需要 API key；本地渲染失败的单页会转交云端抓取，结果里标 `source: firecrawl-cloud`

**适用场景**: 面向给 agent 接网页数据的开发者：用 Cursor 或 Claude Code 写代码时要 agent 直接读官方文档、issue，或者做 RAG 的团队要批量爬站又不想把内网数据发到第三方云上。

**竞品对比**: 对比 Crawl4AI（Python 库，得自己装 Playwright 和维护浏览器）、Jina Reader（纯云端 API）、以及 Firecrawl 自己以前只卖云服务。最大差异是单体 Rust 二进制 + 一键 MCP 注册 + 本地云混合，装完就能被 Claude Code / Cursor 直接调用，不用写胶水代码。

**成熟度**: 整体生产可用：有付费云服务和自托管两条线，Python/Node SDK 齐全、文档完整、issue 响应快；但 Local 二进制是刚上 crates.io 的新东西，命令和参数可能还会变。

**趋势信号**: README 明显改版，把 Rust 本地二进制和 MCP 一键接入提到最前，同时上线 550+ 数据源的 Alexandria 和免注册每月 1000 credits 的 keyless 额度——踩的是『agent 要本地跑、要私有数据、要少配环境』这波转向。

### [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

 `Python` ⭐ +1,106 今日新增 · 65,934 总星数

> 给桌面软件批量套一层命令行壳加 SKILL.md 技能文件，让 Claude Code、Cursor 这类 Agent 能直接操作 FreeCAD、LibreOffice、Obsidian 等没有 API 的软件。

**亮点**

- 不做 GUI 点击模拟，也不要求软件官方改造，而是给软件套一层命令行壳，把“用鼠标点按钮”翻译成“输入子命令、输出 JSON”。Agent 执行命令比看截图找坐标稳定得多，也更省 token
- CLI-Hub 把社区写的壳做成 pip 可安装的注册表（pip install cli-anything-hub 后 cli-hub install &lt;name&gt;），新增软件是提 PR 而非等官方支持，扩展靠社区推动

**核心功能**

- 每个软件都生成一个用 Click 写的命令行壳：子命令对应软件的真实操作，输出同时提供两种格式——JSON 给 Agent 解析、文本给人阅读，并配有 pytest 单元测试和端到端测试，仓库目前已有 2461 个测试通过
- 同时生成 SKILL.md 技能文件，用 npx skills add 装进 Claude Code、Cursor 等客户端；Agent 读一遍文档就知道命令怎么用，不需要看源码
- 带 preview / 实时预览 / 轨迹回放：Agent 每执行一步都能拿到渲染出来的中间产物（CAD 图、3D 场景、字幕），不必只靠文本猜结果对不对
- 解析外部文件时统一走 defusedxml，拦截 XXE；写 Rekordbox 的 SQLCipher 数据库前强制备份；token 文件做防路径穿越和符号链接逃逸

**适用场景**: 面向想让 Agent 批量操作桌面软件的个人开发者和小团队，例如用 Claude Code 自动出 CAD 图、用 LibreOffice 批量转文档、给视频自动生成字幕、整理 Obsidian/Joplin 笔记，这些软件都没有可用的命令行或 API。

**竞品对比**: 对比 MCP Server：MCP 要为每个软件手写工具接口，这里批量生成命令行壳加技能文档；对比 Playwright、computer-use 这类 GUI 自动化：后者靠截图加坐标点击，速度慢且易崩，CLI 是确定性的文本接口。

**成熟度**: 非常年轻但增长激进，日均 1000+ star，每天都有 PR 合并，有 arXiv 技术报告和 2461 个测试；但各软件壳质量参差，2026 年 5 月还在补安全漏洞和路径穿越问题，接口可能变，建议先在非关键流程上试。

**趋势信号**: 2026 年 Agent Skills 生态成型（npx skills add 成了事实标准），团队同期把技能目录统一到 skills/ 并上线 CLI-Hub 注册表，正好赶上“Agent 有能力却没工具可用”这波需求。

### [XiaoYouChR/Ghost-Downloader-3](https://github.com/XiaoYouChR/Ghost-Downloader-3)

 `Python` ⭐ +951 今日新增 · 18,595 总星数

> 一个 Qt 写的跨平台全能下载器，HTTP、BT、M3U8、B站、YouTube 全塞进一个客户端，主打弱网速度和反爬绕过。

**亮点**

- 进度不丢是核心取舍：任务暂停后改 URL、换请求头、切代理都能接着下，进度实时落盘，不用从头来。
- 浏览器扩展只负责嗅探页面媒体和转发登录态，真正的下载交给桌面端接管，绕开了扩展本身权限和性能的限制。

**核心功能**

- 分块下载不做文件合并：先预分配整个文件，多个连接直接写到同一文件的不同偏移，省掉下完再拼接的步骤和双倍磁盘占用；带宽自动探测决定分几块、开几个连接。
- 伪装真实浏览器的 TLS 指纹（ClientHello 特征）骗过按指纹拦截的站点，再配合扩展把页面的登录态一起带过来，不用复制链接重新鉴权。
- 站点专用解析器：YouTube、B 站能按分 P、清晰度、字幕挑，GitHub、HuggingFace 走镜像加速；对外还暴露 aria2 兼容的 RPC，任务跑着也能改 URL、请求头、代理。
- Android 端能边播边录直播 M3U8，并支持后台继续下载；CLI 工具 ghd 提供 probe、add、tasks、wait 等命令，可只下种子里的部分文件。

**适用场景**: 普通用户拿它替代 IDM 下大文件、BT 种子、B 站或 YouTube 视频；也能当 aria2 RPC 后端接进已有的下载面板或自动化脚本。

**竞品对比**: 对手是 Gopeed、Motrix（aria2 套壳）和 IDM。Gopeed 同样跨平台多协议但没做站点专用解析和 TLS 指纹伪装；IDM 只有 Windows 且收费。

**成熟度**: 四平台都有正式包、AUR 分发、代码签名和 Crowdin 翻译，日常可用；但 Roadmap 显示插件 API 尚未定型，仍在快速迭代。

**趋势信号**: 近几个版本补齐了 Android 端直播录制和 Feature Packs 插件体系，加上 B 站、YouTube 直下，被中文社区带起一波，单日涨了近千星。

> 一个 Agent 技能：并行搜 Reddit、X、YouTube、TikTok、HN、Polymarket 等 20 来个平台，按点赞数和市场赔率排序，再合成一份近 30 天简报。绕开了这些平台不开放 API 的死结。

**亮点**

**核心功能**

- 按真实互动量打分，不按编辑权重：Reddit 看赞数、X 看 likes、YouTube 搜完整字幕找那几句关键话、Polymarket 看用真钱压出来的赔率、GitHub 看 PR 速度和合并率，各源分数放在一起比

**适用场景**: 销售、BD、投资人见客户前查对方近 30 天干了什么：新工作、发了什么推、GitHub 提交、公司股价和 Polymarket 上的收购赔率。开发者跟 AI 圈热点时，用它在 Reddit 和 X 上捞训练数据里还没有的新东西。 也用在非工作场景，比如去迪士尼前查哪个项目在检修、社区怎么评价 Genie+。

**竞品对比**: 对标 Perplexity Deep Research、ChatGPT 搜索、Google。最大差别有两点：一是能碰到 X、TikTok、小红书这类不开放 API 的源；二是排序信号是点赞和真金白银的赔率，不是编辑相关性。代价是依赖用户自己配 key 和登录态，开箱即用的干净程度不如 Perplexity。

**成熟度**: README 自称 v4 管线，有 CI 校验、十种语言文档，但本质是一份技能规范加一堆本地 CLI，靠用户自带凭证运行，接口和合规边界都不如成熟 SaaS 稳，适合个人重度使用，团队落地要自己兜底。

**趋势信号**: Agent Skills 生态（agentskills.io）刚铺开，一个 skill 能同时装进 Claude Code、Codex、Cursor、Gemini CLI 这些宿主，正好踩在这波“技能包”分发红利上；同时大家对模型训练数据滞后几个月的抱怨越来越具体。

- 三种调用方式：交互式 REPL（带 /compact 压缩上下文、/cost 记 token 花费、/resume 续会话）、headless 的 `opensre ask` 塞进 CI 脚本一次跑完、Python 里 `start_embedded_session\(\)` 进程内调用。

**适用场景**: 几十上百个 repo、CI 常年红灯的平台/DevOps 团队；以及 on-call 工程师被告警叫起来时，先把日志和告警丢给它跑一遍，再决定要不要人工深挖。

**竞品对比**: 对手是 GitHub Copilot Autofix（绑死 Actions + 托管模型）、Greptile（本项目的赞助商，偏 code review），以及 Datadog Bits AI、Resolve AI 这类商业 on-call 工具。最大差异是 Apache 2.0、自托管、模型自选，且同时覆盖 CI 失败和生产事故两类场景。

**成熟度**: 自称 public alpha，核心流程能用但 API 和集成还会变，不适合直接进关键路径。

**趋势信号**: AI 写代码的比例上升，红灯构建越来越多，而“Agentic SRE”这个品类在 2025 年正被资本和开发者同时盯上；它开源、自托管，恰好对上企业不愿把日志交给第三方的顾虑。

### [openvinotoolkit/openvino](https://github.com/openvinotoolkit/openvino)

 `C++` ⭐ +191 今日新增 · 12,713 总星数

> Intel 开源的推理部署工具，把 PyTorch/TF/ONNX 模型转成统一中间表示，在 Intel CPU/GPU/NPU 上加速跑。AI PC 普及后本地跑 LLM 的需求让它重新受关注。

**亮点**

- 一套 IR + 多后端的做法，让代码不改就能从 CPU 切到 NPU，换硬件只改一行 compile_model 的设备名
- GenAI 仓库（openvino.genai）把 KV cache 管理、采样、连续批处理这些 LLM 推理流水线封装好了，不用自己拼推理循环

**核心功能**

- ov.convert_model 直接把 PyTorch/TensorFlow/ONNX/PaddlePaddle 的计算图转成 OpenVINO IR（一种中间格式），部署时不用再装原框架；同一份 IR 能编译到 CPU、集显/独显、NPU 三种后端
- NNCF 做训练后量化：权重压到 INT8/INT4、激活量化到 INT8，配合算子融合和常量折叠，把 7B 级 LLM 压进消费级笔记本内存跑
- 按目标硬件的指令集生成不同内核（x86 走 AVX-512/AMX，GPU 走 OpenCL/Xe，NPU 编译成独立 blob），同一模型在不同设备上的调度策略不一样

**适用场景**: 面向在 Intel 笔记本、工控机、边缘盒子上部署模型的工程师：本地 LLM 聊天、Whisper 语音转写、YOLO 质检视觉，以及想用 Core Ultra 的 NPU 省电跑推理的开发者。

**竞品对比**: 和 ONNX Runtime 比，OpenVINO 更贴着 Intel 硬件做指令级调优，NPU 支持是 ONNX Runtime 目前比不了的；和 TensorRT 比不绑 NVIDIA 卡；但它绑定 Intel，在 AMD/ARM 上没优势，通用性不如 llama.cpp。

**成熟度**: 生产可用：Intel 官方维护，版本号已到 2026.x，PyPI/Conda/Homebrew 都能装，文档和 notebook 教程齐全，工业界已有实际部署。

**趋势信号**: Intel Core Ultra 的 NPU 在 AI PC 上铺开，加上 2026 版本刚发布并加强了 GenAI/LLM 支持，本地离线跑大模型的需求把这类推理框架推到台前。

### [nginx/nginx](https://github.com/nginx/nginx)

 `C` ⭐ +176 今日新增 · 33,427 总星数

> NGINX 官方开源仓库，C 写的 Web 服务器/反向代理/负载均衡/API 网关。把它放在 GitHub 上统一了官方源码入口，方便直接看代码、提 issue 和打补丁。

**亮点**

- 用少量 worker 进程 + 非阻塞 IO 替代一线程一请求，C10K 问题当年就是靠这个思路解决的，到现在仍是高并发入口层的主流架构
- 配置即能力：负载均衡策略、缓存、限流、重写规则全靠指令组合，不用写代码就能拼出一个网关，代价是配置语法陡峭、调试靠日志

**核心功能**

- master-worker 多进程模型：master 只负责读配置、管 worker，worker 各自跑单线程事件循环（Linux 用 epoll、BSD 用 kqueue），一个 worker 扛上万连接不靠线程切换
- 配置热重载：改完 nginx.conf 发个信号，master 拉起新 worker、老 worker 把手上的请求处理完再退出，不丢连接不断服务
- worker 之间用共享内存 zone 同步状态，限流（limit_req_zone）、缓存索引、连接计数都靠这块共享内存，否则多进程各算各的
- 模块分静态和动态两种：静态编译进二进制，动态模块（.so）按需加载，nginx -V 能看到当前二进制带了哪些静态模块

**适用场景**: 运维/SRE 拿它做入口层：TLS 卸载、按路径转发到后端服务、限流防刷、静态资源和缓存加速；后端开发本地也常起一个 nginx 做反向代理调接口。

**竞品对比**: 对手是 Envoy、Caddy、Traefik、HAProxy。Envoy 走 L7 服务网格和动态 xDS 配置，Caddy 自动签 HTTPS 证书，Traefik 直接对接容器/K8s 自动发现；nginx 的优势是静态资源服务和反向代理的稳定性、资料多、云厂商默认都装，弱项是动态配置要 reload、云原生发现能力靠第三方。

**成熟度**: 生产可用，二十多年历史、几乎所有云厂商和 CDN 都在跑，主线/稳定双分支发布，文档和模块生态齐全。

**趋势信号**: 官方源码仓库迁到 GitHub 后，star 和 issue 都集中到这里，加上近期安全补丁和主线版本发布，容易被重新带回 Trending。

## 趋势观察

今天这份榜单几乎只有一个主题：大家在给 AI Agent 造“零件”和“说明书”。 一半项目是技能包和插件。有人把 85 个 Claude Code 技能打包成红队作业流程，有人给编码 Agent 装上“先问需求、再写规格、再拆任务”的开发规范，有人把 FreeCAD、LibreOffice 这些没 API 的老软件套一层命令行壳，让 Agent 能直接上手操作。Google 把 Stitch 拆成 Skills，Cursor 干脆开源了自己的插件规范和官方插件仓。信号很清楚：模型能力不再是瓶颈，“怎么让 Agent 按流程干活”才是。经验正在被固化成文件。 另一半是本地化。3 块钱、2 小时在单张 3090 上训出 64M 小模型，Firecrawl 把本地二进制和 MCP 一键接入放到最前面，Intel 的推理工具重新受关注，AFFiNE 主打自托管，AutoClip 全程本机剪辑。云端不再是默认选项。 还有一类很务实：把行业里的隐性知识变成可执行清单。App Store 拒审原因做成扫描脚本，CI 挂了自动读日志、提修复 PR，20 个平台不开放 API 就绕过去抓。这些项目不炫技，解决的是具体而琐碎的痛。 新闻热点是 Agent 生态入口之争，Cursor、Claude Code 都在抢位置。开发者生态的变化是：以前拼谁能调模型，现在拼谁把工作流做得更细、更能分发给别人用。
