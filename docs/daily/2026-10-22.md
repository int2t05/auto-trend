# GitHub Trending 日报 · 2026-10-22

## 概览

今日共收录 **11** 个 GitHub Trending 项目。
主要语言分布：Python(5)、TypeScript(3)、JavaScript(2)、Rust(1)。

这批项目看下来，主线很清楚：大家不再只卷模型本身，而是开始给 Agent 造配套。头一件事是省钱。Headroom 把工具输出、日志、RAG 片段先压缩再喂给模型，编码场景省两成 token，JSON 能省六到九成。懒资深工程师那层约束更直接，能不写就不写，代码减一半多，成本降两成多，测试覆盖率反而涨了。还有 graphify 用知识图谱代替 grep 翻文件，也是为了少烧 token。第二件事是记忆和调度。跨工具长期记忆那个项目，用 git 版 markdown 存，换 Claude Code 还是 Codex 都能接着干；桌面加手机统一调度多个 worktree 并行跑 Agent，也是同一个思路。第三件事是管住幻觉。Cloudflare 把内部漏洞挖掘 harness 开源成技能，六阶段跑审计，靠覆盖账本加独立复验，输出可机器校验的结论。这说明安全审计这种高风险场景，光靠模型自说自话不行，得加硬约束。另一条线是开源替代闭源继续热。Supabase 顶 Firebase，Twenty 顶 Salesforce，还把 CRM 写成代码、内置 AI agent；ComfyUI 用节点图把扩散模型每一步拆开，图像视频开源模型一发布它就第一批支持。再加上 vLLM 这种适配最广的推理引擎，和首个开源金融 K 线基础模型被 AAAI 2026 收录，能看出生态在两头使劲：一头把 Agent 变得更便宜、更可靠、更可管，一头用开源和 AI 能力去撬闭源 SaaS 的地盘。开发者现在关心的不是模型多大，而是这套东西能不能真的干活、花多少钱、出了错谁来兜。

### [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)

 `JavaScript` ⭐ +2,079 今日新增 · 171,980 总星数

> 给 AI 编程 agent 装一个“懒资深工程师”约束层：先看仓库里已经有什么，能不写就不写。v5 基准称代码减 53%、成本减 26%，测试覆盖率反升。

**亮点**

- 它约束的目标是“只写任务真正需要的代码”，不是“省 token”，并明确禁止砍掉校验、错误处理、安全和无障碍。因此代码量下降的同时，风险逻辑带测试的比例是 98%，不加技能是 68%。
- 用同一个 agent 开关技能做 A/B 对照：39 个任务、含真实 FastAPI + React 仓库、每个跑 5 次；把 6 个安全任务（SQL 注入、路径穿越、伪造 token、限流等）单列出来，30 次运行全过。

**核心功能**

- 先扫仓库再动手：示例里要加日期选择器，它发现项目已有 Input 组件、浏览器自带原生日期控件，于是只写 10 行；不加约束的 agent 手搓日历写了 335 行。
- /ponytail-review 不只读 diff，还会读改动波及到的下游文件。基准中它抓到一个字段改名让未被修改的 src/routes/feed.js 崩掉，这类“diff 外的问题”发现率 100%（不加技能 78%）。
- /ponytail-audit 先给整个仓库建地图（入口在哪、数据怎么流、项目预期多大负载），再按“先修哪个”排序，而不是丢一堆 lint 式告警。5.3 在 Claude Code 提示框上方加了一条状态带，实时显示本轮花费、token、复用率（示例 71%）和上次改动后测试是否通过。

**适用场景**: 日常用 Claude Code、Cursor 这类 agent 写业务代码的工程师，尤其是被 agent 生成的大段样板代码、重复造轮子拖慢 review 的团队；也适合需要判断“这次改动会不会弄坏别处”的 reviewer。

**竞品对比**: 和 CLAUDE.md / AGENTS.md 里手写规则、Cursor Rules 比：那些只是静态提示，Ponytail 打包成了技能 + 斜杠命令 + 可复现基准。和 CodeRabbit、Greptile 这类 PR 评审机器人比：它们在 diff 上留评论，Ponytail 会主动去读上下文文件并直接改代码。

**成熟度**: 版本已到 5.x、有 npm 包和 MIT 许可、README 多语言齐全，但本质是提示词/技能包，所有效果数字都是自测自报；17 万 star 与实际维护规模明显不匹配，建议先在小任务上验证再铺开。

**趋势信号**: Claude Code 推出 Skills 之后，“技能包”成了新的分发形态；同时社区对 agent 过度生成代码、账单失控的抱怨变多，v5 重写加基准报告正好在此时发布。

### [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

 `JavaScript` ⭐ +2,012 今日新增 · 37,054 总星数

> Cloudflare 把内部漏洞挖掘 harness 的起点开源成一个 Agent 技能：六阶段跑安全审计，用覆盖账本加独立复验压住模型幻觉，输出可机器校验的结论。

**亮点**

- 对抗式分工：发现问题的 Agent 和验证问题的 Agent 永远不是同一个，验证者的任务是把候选证伪，不是确认。
- 统一采用“影响优先”的判定：纵深防御少一层只算加固建议，不算漏洞；作者实测单轮只找到重复多轮能找出的约一半，所以整个流程设计成可重复叠加，复用上次账本只重验变更代码。

**核心功能**

- 六阶段流水线固化在 SKILL.md 里：侦察阶段产出 architecture.md（信任边界、输入面）和 coverage-ledger.json（覆盖账本，记录哪些攻击面查过、查到哪），狩猎阶段按账本单元派独立 hunter，再由 coverage critic 专找没覆盖的窟窿。
- 结论只允许三态：confirmed 必须有完整源码调用链和可观测结果，needs_validation 必须写清具体哪个事实没解决且不许给严重级别，rejected 记录被推翻的候选。findings.json 用 report-schema.json 校验。
- 两个零依赖 .cjs 校验脚本（validate-findings、validate-coverage-ledger）在阶段 1、4、5 反复跑，账本或结论不合 schema 直接拦；脚本自带单测和 fixture 兼容检查。

**适用场景**: 适合安全工程师或平台团队对自研仓库做比 SAST 更深的审计，也适合想给 Claude Code、Cursor 这类编码 Agent 加一套固定安全审查流程的团队，让 Agent 直接跑“security audit this codebase”。

**竞品对比**: 跟 Semgrep、CodeQL 这类规则型 SAST 比，它不做模式匹配，靠 Agent 读代码推演，能碰逻辑漏洞但更慢更贵；跟“直接让大模型把仓库审一遍”比，差异是覆盖账本和独立复验机制，专治漏报和编造漏洞。

**成熟度**: Cloudflare 生产级漏洞挖掘 harness 的源头版本，但仓库本身只是提示词加两个校验脚本，没有版本号和发布流程，按可用的早期工具看待。

**趋势信号**: Cloudflare 官方博客《Build your own vulnerability harness》刚发布，又赶上 skills.sh 这类 Agent 技能生态起量，一天涨 2000 星。

 `TypeScript` ⭐ +1,541 今日新增 · 101,623 总星数

> 把 Claude Code、Codex 等命令行 Agent 塞进各自独立的 git worktree 并行跑，桌面端加手机端统一调度、评审和合并。

**亮点**

**成熟度**: 桌面版已发布、iOS 上架 App Store，官方自称每日发版；迭代过快，界面和工作流还在大改，不适合当稳定基础设施依赖。

**趋势信号**: 2025 年 Claude Code、Codex CLI、OpenCode、Gemini CLI 一堆命令行 Agent 并存，开发者开始同时跑好几个，缺一层统一的调度台，Orca 正好卡在这个位置。

### [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)

 `Python` ⭐ +1,433 今日新增 · 131,871 总星数

> 把代码、文档、SQL schema、PDF 一起解析成可查询的知识图谱，做成 Claude Code/Cursor/Codex 的 /graphify 技能。让 AI 助手查图代替 grep 翻文件，省 token。

**亮点**

- 有意不使用 embedding 和向量库：靠 AST 抽出的确定符号关系建图，再在图上做遍历和最短路径查询（graphify path A B），用精确关系替代“切片加相似度检索”那种模糊召回。
- 产物是三个静态文件而不是一个常驻服务：graph.html（力导向图，带社区检测着色，可点可搜）、GRAPH_REPORT.md、graph.json。json 里带 schema_version 和 graphify_version 字段，agent 只需读一次图，之后反复查询。
- 社区检测把图自动切分成“社区”（把联系紧密的节点归为一组），报告里直接给出关键概念、意外连接和建议提问，不用人先想好问什么。

**核心功能**

- 代码部分用 tree-sitter 做 AST 解析，纯本地、确定性、不调用 LLM，也不联网；只有文档、PDF、图片、视频才走助手的模型或自配 API key 做一遍语义抽取。
- 每条边都打标签：EXTRACTED 表示源码里能直接读到的关系（比如 import、调用），INFERRED 表示 graphify 自己推出来的关系。这样在查询结果里一眼能分清哪些是事实、哪些是猜测。

**适用场景**: 适合在大型 monorepo 里用 Claude Code / Cursor 改代码的工程师。问“这个函数谁在调”“改这个类会波及哪些地方”“两个模块怎么连起来的”时，不用让 agent 逐个读文件、消耗几十万 token 上下文。

**竞品对比**: 最接近的是 aider 的 repo map（同样用 tree-sitter 建图加 PageRank 排序），但 aider 只把结果压成一段文本设置到提示词里；Cursor、Sourcegraph 的代码索引走的是 embedding 向量检索。graphify 的差异是把结果落成能交互遍历的图，并显式区分 EXTRACTED/INFERRED，还把代码和文档、PDF、SQL 混在同一张图里。

**成熟度**: 处于早期但迭代较快：已发到 v8 分支、有 CI/PyPI（包名 graphifyy）/文档站/Discord，背后是 YC S26 团队，同时在做 Graphify Cloud 商业化；核心 CLI 可用，但图和 API 格式还在变（所以才要 schema_version）。

**趋势信号**: 2025 下半年 Claude Code Skills 和多家 agent CLI 生态爆发，团队既想让 agent 读懂整个仓库、又不想继续消耗 token，于是“代码知识图谱/记忆层”成了新战场；叠加 YC S26 背景和 Cloud 付费版的同步推广。

### [Comfy-Org/ComfyUI](https://github.com/Comfy-Org/ComfyUI)

 `Python` ⭐ +939 今日新增 · 141,652 总星数

> ComfyUI 是一个用节点图搭工作流的本地扩散模型推理引擎，把出图、出视频、3D、音频的每一步都拆成可连线的节点。它解决的是「闭源工具改不了参数、普通 WebUI 又不够灵活」的问题。近期图像和视频开源模型密集发布，它几乎每次都第一批支持。

**亮点**

- 把「界面」和「引擎」拆开：核心是 Python 后端 + HTTP API，前端只是其中一种客户端，所以同一套工作流能在桌面版、网页版和云版跑
- Partner nodes 机制：在同一个节点图里混用本地开源模型和闭源 API 模型（Nano Banana、Seedance、Hunyuan3D 等），本地开源和付费闭源不再是两套工具

**核心功能**

- 异步权重流式加载：权重放内存/硬盘，用到哪层传哪层到显存，官方称 4GB 显存 + 8GB 内存就能跑大模型，代价是多一点传输延迟换显存占用
- 只重跑改动的部分：后端把工作流当有向无环图（DAG）执行，缓存每个节点的输出，改一个参数只重新执行受影响的下游节点，不整条重算
- 模型格式与精度支持很杂：可分开加载 diffusion 模型、VAE、文本编码器、LoRA、ControlNet，支持量化模型，也能存 16bit PNG、32bit EXR、10bit AVIF 和 HDR 视频
- 工作流存成 JSON，能通过本地 HTTP API 触发；App Mode 把复杂节点图收成一个只有输入框和按钮的简单界面给最终用户

**适用场景**: 适合需要精细控制每一步的视觉工作者和 AI 应用开发者：设计师用 ControlNet + 局部重绘（inpainting）做商业出图，视频团队用 Wan、LTX-Video 节点拼生成流水线，工程师把工作流挂在 API 后面接自家产品。

**竞品对比**: 跟 Automatic1111 WebUI、Forge、Fooocus 比，最大差别是交互模型：那些是表单填参数，ComfyUI 是自由连线的工作流图，所以能表达多模型串联、条件分支这类复杂流程；代价是上手门槛高。跟 HuggingFace Diffusers 比，它不用写代码，但灵活性不如直接写 Python。

**成熟度**: 版本号还在 0.x（当前约 v0.7），但已被大量商业工作室日常使用；周更发布节奏，自定义节点常因核心改动而挂掉，README 明确警告非 stable tag 的提交可能不稳定。

**趋势信号**: 开源图像/视频模型现在几乎每月出新（Flux.2、Qwen Image、Wan 2.2、HunyuanVideo 1.5 等），ComfyUI 基本是第一个能跑起来的本地前端，社区跟着模型发布节奏走；同时仓库刚从个人账号迁到 Comfy-Org 组织，桌面版和云服务在做商业化。

### [shiyu-coder/Kronos](https://github.com/shiyu-coder/Kronos)

 `Python` ⭐ +575 今日新增 · 42,925 总星数

> 首个开源的金融 K 线基础模型：把 OHLCV 量化成 token，用 Transformer 自回归预测，基于 45 个交易所的数据预训练，已被 AAAI 2026 收录。

**亮点**

- 把 K 线当“语言”处理是核心取舍：量化成离散 token 后，能直接复用 LLM 那套成熟的训练流程和采样技巧（top_p、温度、多路径采样），而不是自己从头设计时序回归损失
- 模型分档务实：mini 4.1M 到 base 102M 开源，能在单卡甚至笔记本上跑；large 499M 不放出来，上下文只有 512（mini 2048），长历史靠自动截断补齐

**核心功能**

- 两阶段架构：先用专用 tokenizer 把连续多维的 OHLCV（开高低收+成交量）量化成分层离散 token，再用 decoder-only Transformer 在这些 token 上做自回归预训练，把“预测价格”变成“预测下一个 token”
- 预训练数据来自 45 个全球交易所的 K 线，专门针对金融数据高噪声、低信噪比的特点建模，并非把通用时序模型直接套用到金融数据上
- 推理时支持概率预测：temperature 温度、top_p 核采样、sample_count 多条路径取平均，输出预测分布而非单点价格；predict_batch 可多标的并行

**适用场景**: 量化研究员和交易团队用它做短周期价格与成交量预测、回测前的信号生成；开发者也能用 KronosPredictor 几行代码接进自己的系统，再在自己的行情数据上微调。

**竞品对比**: 和 TimesFM（Google）、Chronos（Amazon）、Moirai（Salesforce）这类通用时序基础模型比，Kronos 是专门面向金融 K 线：输入是多维 OHLCV 而非单变量序列，明确针对金融噪声建模；代价是通用性不如它们。

**成熟度**: 有 AAAI 2026 论文支撑、Hugging Face 上四个规模的权重和微调脚本，但 large 模型未开源、上下文仅 512，属于研究可用、上生产需自己验证的阶段。

**趋势信号**: 2025.11.10 被 AAAI 2026 收录，加上 8 月放出微调脚本和 arXiv 论文，正好赶上 AI 量化这波热度，星标因此冲高。

### [supabase/supabase](https://github.com/supabase/supabase)

 `TypeScript` ⭐ +504 今日新增 · 113,119 总星数

> Supabase 是基于 Postgres 的开源后端平台，用一套工具替代 Firebase 的数据库、认证、存储和实时订阅功能。近期因为 AI 应用和向量检索需求上涨，它作为开源 Firebase 替代品持续受到关注。

**亮点**

- 不自研全家桶，而是给 Postgres 生态里的成熟开源件（PostgREST、GoTrue、Realtime、Envoy）做统一集成和托管。工具缺什么就自己补并开源
- 把权限收敛到 Postgres 的 RLS 一处，数据库、REST、GraphQL、Storage、Realtime 共用同一套规则，避免多套权限系统各管一摊

**核心功能**

- 核心思路是把一批现成开源件拼起来：PostgREST 直接把 Postgres 表映射成 REST API（不用写后端接口），GoTrue 负责 JWT 登录鉴权，Realtime 用 Elixir 订阅 Postgres 自带的复制日志（WAL）把增删改转成 JSON 推给 websocket 客户端
- pg_graphql 是一个 Postgres 扩展，在数据库内部直接暴露 GraphQL 接口；权限复用 Postgres 的行级安全策略（RLS，即按行控制谁能读写），同一条策略同时管 API、存储和实时推送
- 客户端库按模块拆分，supabase-js 里 postgrest-js、auth-js、realtime-js、storage-js 各自独立，也能单独拿去用
- 内置 pgvector 支持向量存储和嵌入检索，可以直接给 RAG（检索增强生成，先查资料再让大模型回答）当向量库用

**适用场景**: 前端或全栈开发者快速搭 MVP、SaaS、移动 App 后端，不想自己拼数据库、登录、文件存储和实时推送；做 AI 应用的团队用它存向量做 RAG 检索。典型用户是 Next.js、Flutter 开发者。

### [headroomlabs-ai/headroom](https://github.com/headroomlabs-ai/headroom)

 `Python` ⭐ +474 今日新增 · 77,353 总星数

> Headroom 是一个跑在本地的上下文压缩层，把 Agent 读进来的工具输出、日志、RAG 片段和文件先压缩再喂给 LLM。编码 Agent 省约 20% token，JSON 省 60-95%，原文缓存在本地，可按需取回。

**亮点**

- 压缩可逆（CCR）：原文存在本地，模型需要细节时调 headroom_retrieve 把完整内容取回来，这样压缩不再是有损操作，也敢对日志这类“砍掉就出事”的内容动手
- headroom learn 会翻失败的会话，把教训自动写进 CLAUDE.local.md / AGENTS.md 这类 Agent 记忆文件，等于把“压缩踩过的坑”反馈成下一轮的规则，也顺带做了跨 Agent 的共享记忆去重

**核心功能**

- 内容路由分发：ContentRouter 先判断这段是 JSON、源码还是自然语言，再分别交给 SmartCrusher、CodeCompressor 和 HuggingFace 上的 Kompress-v2-base 小模型处理，不同格式使用不同压缩算法
- 代码用 AST 压缩而不是截断：CodeCompressor 按语法树砍掉函数体和样板，保留签名和结构，所以压缩后模型仍能看懂代码在做什么
- CacheAligner 专门标记会冲掉 KV-cache 前缀的易变内容（时间戳、随机 ID 这类），只做提示不改写 prompt，避免省了输入 token 却让 provider 端缓存失效反而更贵

**适用场景**: 使用 Claude Code、Cursor、Codex、Aider 等编码 Agent 的开发者，以及跑 SRE 排障、代码搜索这类“一次返回上百条结果”的 Agent 流水线。接入方式有三种：改一行 import 走 SDK，起一个 headroom proxy 走代理（不改任何代码），或 headroom wrap claude 一条命令包住现有 Agent。

**竞品对比**: 和微软 LLMLingua 系列相比，Headroom 不做通用 prompt 压缩，而是按内容类型分流并强调关键行逐字节保留（demo 里 FATAL 那行压缩后原样还在）；和 Claude Code 自带的 /compact、各家 provider 的 prompt caching 相比，它不挑模型、跨 Agent 通用，且压缩发生在客户端、原文不出本机。

**成熟度**: 接入面铺得挺全（PyPI 库、npm SDK、代理、MCP server、CLI 全都有，带 CI 和在线文档），但压缩靠启发式加小模型，关键信息是否真的一条不漏，得自己在业务日志上验一遍再上生产。

**趋势信号**: 编码 Agent 普遍被上下文窗口和 token 账单卡住，同一天还挂了 HuggingFace 上自己的 Kompress-v2-base 压缩模型、Trendshift 日榜第一，属于踩在“Agent 上下文成本”这个当下最痛的点上。

### [vllm-project/vllm](https://github.com/vllm-project/vllm)

 `Python` ⭐ +441 今日新增 · 94,963 总星数

> vLLM 是一个大模型推理和服务引擎，靠 PagedAttention 管显存、连续批处理提高吞吐，让一张 GPU 能同时服务更多请求。它是目前开源推理栈里适配模型和硬件最广的一个。

**亮点**

- PagedAttention 是把操作系统的分页思路搬到 KV cache 上，这是它 2023 年那篇 SOSP 论文的核心，也是整个项目的地基，后来 SGLang 等方案都受它影响。
- 不绑单一硬件：除了 NVIDIA、AMD、Intel GPU 和 x86/ARM CPU，还用插件方式接了 Google TPU、Intel Gaudi、华为昇腾、IBM Spyre、Apple Silicon 等，换卡时上层代码基本不动。

**核心功能**

- 用 PagedAttention 管理 KV cache：把注意力缓存按固定大小的块切分、用页表映射，像操作系统管虚拟内存那样，避免为每个请求预留连续大块显存，显存浪费从原来的六七成降到个位数百分比。
- 连续批处理 + 分块预填充（chunked prefill）+ 前缀缓存：请求一进来就插进当前批次跑，长 prompt 切成小块和 decode 混跑，公共系统提示词只算一次，短请求不用再等长请求算完。
- 内核层按硬件和精度逐个手写：注意力用 FlashAttention / FlashInfer / FlashMLA / Triton，矩阵乘和 MoE 用 CUTLASS / CuTeDSL，还支持 FP8、NVFP4、MXFP4、INT4、GPTQ/AWQ、GGUF 等量化格式；投机解码支持 n-gram、suffix、EAGLE。
- 把 prefill、decode、encode 拆到不同机器上跑（disaggregated serving），再通过 OpenAI 兼容 API、Anthropic Messages API 和 gRPC 对外服务，多 LoRA 可在稠密层和 MoE 层同时挂载。

**适用场景**: 适合要把模型部署成在线服务的团队：AI 应用公司自建推理集群、云厂商做大模型 API、企业内部跑私有化 Qwen/Llama/DeepSeek。典型流程是把 Hugging Face 权重直接拉下来起一个 OpenAI 兼容端点，替换掉原来的 OpenAI 调用。

**竞品对比**: 主要对手是 SGLang、NVIDIA TensorRT-LLM 和 Hugging Face TGI。SGLang 在部分场景延迟和结构化输出上更快，TensorRT-LLM 在纯 NVIDIA 卡上性能榨得更狠但生态封闭、适配慢；vLLM 赢在支持的模型（200+）和硬件最全，社区迭代最快，基本成了开源推理的默认底座。

**成熟度**: 生产可用，已有大量企业在线上跑，2000+ 贡献者；但版本号还在 0.x，小版本之间 API 和配置项仍会变动，升级要读 changelog。

**趋势信号**: 推理成本成了企业上大模型的主要瓶颈，加上近期新模型（DeepSeek、GPT-OSS、Qwen 系）和新硬件（NVFP4、各家 NPU）都优先在 vLLM 上做适配，它自然成了流量入口。

## 趋势观察

这批项目看下来，主线很清楚：大家不再只卷模型本身，而是开始给 Agent 造配套。头一件事是省钱。Headroom 把工具输出、日志、RAG 片段先压缩再喂给模型，编码场景省两成 token，JSON 能省六到九成。懒资深工程师那层约束更直接，能不写就不写，代码减一半多，成本降两成多，测试覆盖率反而涨了。还有 graphify 用知识图谱代替 grep 翻文件，也是为了少烧 token。第二件事是记忆和调度。跨工具长期记忆那个项目，用 git 版 markdown 存，换 Claude Code 还是 Codex 都能接着干；桌面加手机统一调度多个 worktree 并行跑 Agent，也是同一个思路。第三件事是管住幻觉。Cloudflare 把内部漏洞挖掘 harness 开源成技能，六阶段跑审计，靠覆盖账本加独立复验，输出可机器校验的结论。这说明安全审计这种高风险场景，光靠模型自说自话不行，得加硬约束。另一条线是开源替代闭源继续热。Supabase 顶 Firebase，Twenty 顶 Salesforce，还把 CRM 写成代码、内置 AI agent；ComfyUI 用节点图把扩散模型每一步拆开，图像视频开源模型一发布它就第一批支持。再加上 vLLM 这种适配最广的推理引擎，和首个开源金融 K 线基础模型被 AAAI 2026 收录，能看出生态在两头使劲：一头把 Agent 变得更便宜、更可靠、更可管，一头用开源和 AI 能力去撬闭源 SaaS 的地盘。开发者现在关心的不是模型多大，而是这套东西能不能真的干活、花多少钱、出了错谁来兜。
