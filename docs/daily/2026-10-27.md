### [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)

 `Python` ⭐ +2,297 今日新增 · 89,684 总星数

> 本地跑的开源 ElevenLabs 替代品：语音克隆、配音、听写、有声书一站搞定，支持 646 种语言，不联网也能用。

**亮点**

- 把『一个 TTS 模型』做成完整桌面工作台：克隆、设计音色、按时间轴配音、听写浮窗、有声书流水线全在一个 Electron 界面里，模型按需下载而不是一次打包几百 GB
- 明确把 MCP 当一等公民，让 Claude Code / Cursor 这类 Agent 直接调用本地语音合成，这是 ElevenLabs 云端 API 做不到的隐私边界

**核心功能**

- 默认引擎基于 k2-fsa/OmniVoice，同时提供 GGUF 量化版本，Windows/Linux 上可选开 Vulkan 加速，没有独显也能纯 CPU 跑（装的是约 5GB 的精简版 PyTorch）
- 按硬件自动选后端：NVIDIA 走 CUDA、Apple Silicon 走 Metal\(MPS\)、AMD 可选配 ROCm 或原生 CosyVoice GGUF+Vulkan，Intel Mac 只能当远程客户端用
- 后端是 Python API，前端用 Electron 重写（0.5.3 之后彻底弃用 Tauri），同时暴露本地 HTTP API 和 MCP 服务，Agent 可以直接调用合成语音
- 带批处理能力：watch folder 监听目录、可复用 recipe 配方、整本有声书的批量任务；Android/iOS 预览版把模型放到手机本地跑，下载后可离线

**适用场景**: 做视频和播客的独立创作者，需要给多语种视频配音又不想按字符给 ElevenLabs 付费；企业内部要把会议录音转写、做语音助手或给 AI Agent 配声音，但数据不能出内网。

**竞品对比**: 对标 ElevenLabs（云端付费、按字符计费、数据上传）；和 GPT-SoVITS、F5-TTS、Chatterbox 这些单模型开源项目比，差异在于它提供装好即用的跨平台桌面 App、多引擎切换和配音/有声书这类成品级工作流，而不只是给你一个推理脚本。

**成熟度**: 早期项目，版本 0.5.x 未到 1.0，前端刚从 Tauri 迁到 Electron、移动端还是 Preview，API 和目录结构可能还会变。

**趋势信号**: ElevenLabs 的按量计费和声音版权纠纷让『本地跑、不上传』变得有吸引力，加上 MCP/Agent 语音接口这波需求，让它一天涨两千多星。

### [Nutlope/hallmark](https://github.com/Nutlope/hallmark)

 `CSS` ⭐ +2,244 今日新增 · 36,905 总星数

> Together AI 开源的设计技能包，插进 Claude Code、Cursor、Codex 里，让 Agent 建站时按 48 套主题出图，并用真实浏览器渲染查错，堵住一眼就是 AI 生成的那类页面。

**亮点**

- 先只建 hero，单独渲染、冷审查过一轮，再写页面其余部分——避免一次性吐出一整页再大改
- 把「AI 味」从提示词里的形容词拆成可机器检查的具体特征清单，交给静态检查加浏览器渲染去判，而不是指望模型自觉
- 主题（材料）和布局（计划）彻底解耦，主题只管视觉语言，页面结构由「访客来干什么」决定，预约页就完成预约、商店页就完成下单

**核心功能**

- sloplint.mjs 用 puppeteer-core 驱动 Chrome，在 8 种屏幕宽度下真渲染页面，再按具体特征判负：每个标题上方的小眉标、字距拉开的全大写标签、标题里只有一个彩色词、满屏空卡片或纯图片、首屏撑不出屏幕、页尾一律挂邮件订阅、表单点提交只说 thanks 实际没发出去
- 48 个主题是「材料」而不是「模板」：每个就是 references/themes/ 下一个不超过 8KB 的单文件，只定义纸张、字体、配色、组件和质感，不规定页面放什么、什么顺序，一次构建只读一个，所以同一主题两次提示出两个不同页面
- 闸门分三级：Floor（对比度、焦点态、reduced-motion、编造事实、手机布局崩）直接不许交付；Reflex 是模型最容易掉进去的惯性套路，写明理由可以破例；Finish 只是工艺细节，不拦发布。最后由一个全新上下文的 subagent 冷眼复审一遍
- redesign/audit 走保护式改写：sloplint --before 先把原页所有链接、表单字段、事件处理和标题记下来，改完用 --kept 比对，少一个就判定失败

**适用场景**: 适合用 Claude Code / Cursor 半天要出一条落地页或官网的独立开发者和小团队；也适合手上已有页面、嫌 AI 味太重，想跑 /hallmark audit 或 redesign 做体检和重做的团队。

**竞品对比**: 和 v0.dev、Lovable、Bolt.new 这类一次生成整页并托管的产品不同，Hallmark 不提供托管，只输出自包含的 HTML/CSS，是套在编码 Agent 上的规范和检查器；和 shadcn、21st.dev 这类给组件的库也不同，它给的是约束和查错。

**成熟度**: 早期项目，v2 刚发布，本质是 prompt 加脚本，强依赖各家 Agent 的 skill 机制，接口会随平台变；但 MIT、有官网和安装脚本、star 数已经很高，日常用没问题。

**趋势信号**: Anthropic 的 Agent Skills（SKILL.md、npx skills add）生态刚铺开，加上 2025 年底对「AI 味网站」的集体吐槽，Hallmark v2 一次性放出 48 套主题和浏览器级 lint，正好踩在这两个点上。

### [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

 `Rust` ⭐ +1,506 今日新增 · 89,439 总星数

> 给 AI 编码代理补设计判断力的技能包：1 个 skill、24 条命令、62 条确定性规则，专治 AI 生成前端的模板味。

**亮点**

- 把设计品味写成可 lint 的条目：禁用 Inter/Arial/系统默认字体、禁紫到蓝渐变、禁灰字压在彩色底上、禁纯黑纯灰（必须带色调）、禁卡片套卡片、禁 bounce 弹性缓动。规则是确定性的，同一次输入结果可复现，不像提示词那样看模型心情
- live 模式在真实浏览器里选中元素直接生成视觉变体，改完回写代码，省掉「改代码→刷新→截图→再改」这一圈。generate 命令还能对指定元素自动出变体，不用手动点选

**核心功能**

- 62 条确定性检测规则编进一个 Rust 自包含二进制，CLI 和浏览器扩展本地跑，不调 LLM、不要 API key，所以能塞进 CI 或 pre-commit 每次提交都跑；只有 critique 这种主观评审才交给模型
- 把「产品事实」和「视觉方向」拆成两个文件：/impeccable init 问清受众、场景、约束、语气后写 PRODUCT.md，DESIGN.md 单独记现有或新建的视觉系统，后续每条命令都读这两份文件，不用每次对话重新解释项目背景
- 一套技能按宿主分发：安装时探测 ~/.claude、~/.codex、~/.cursor 等目录，写入各家原生 hook 清单（Claude Code hook、Codex 的 .codex/hooks.json、Grok 的 hooks 目录），24 条命令在 Claude Code、Cursor、Copilot、Gemini CLI、Codex 里同名可用

**适用场景**: 用 Claude Code、Cursor、Copilot 批量生成前端页面的独立开发者和小团队。典型流程是先 /impeccable shape 定 UX 再 craft 出代码，交付前跑 audit 查 a11y、响应式和错误态，跑 polish 对齐设计系统。

**竞品对比**: 起点就是 Anthropic 官方的 frontend-design skill，Impeccable 在它之上加了 62 条可离线执行的检测规则和 24 条命名命令。和 v0、shadcn 主题这类「直接给成品页面」的工具路线不同，它不产出页面，只约束你现有 AI harness 的输出质量。

**成熟度**: 文档站点、十几家 harness 适配和多安装方式都齐了，但仍是一个快速演进的技能包，命令和规则会变，建议当开发期辅助用，别硬绑进关键构建链路。

**趋势信号**: Claude Code、Cursor 这类代理大量代写前端后，产出高度同质化（Inter 字体、紫蓝渐变、卡片套卡片），Anthropic Agent Skills 生态又刚铺开，社区正好需要一个能离线跑、可复现的「AI 设计 lint」。

### [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents)

 `Python` ⭐ +1,395 今日新增 · 116,435 总星数

> 用多个 LLM 智能体扮演交易公司的分析师、研究员、交易员和风控，一起研究个股并给出买卖决策，开源可回测。

**亮点**

- 带持久化决策日志：每轮决策留档，后续运行时当作记忆参考，能复盘"当时为什么这么判"，而不是每次从零开始。

**核心功能**

- 模型和数据源解耦：可以给分析师和经理层分别配不同 provider（OpenAI 兼容端点、Bedrock、Groq、Mistral、NVIDIA 等），结构化输出约束研究员/交易员/组合经理的返回格式，还能直接借用本机 ChatGPT Plus/Pro 订阅跑而不是烧 API key。

**适用场景**: 量化研究员和金融 AI 方向的学生，用来做多智能体投研流程的实验和消融对比；也适合个人投资者拿单只股票跑一遍，看四个视角的分析报告和辩论过程，但它本身不是下单系统。

**竞品对比**: 同赛道有 virattt/ai-hedge-fund、FinRobot、FinMem 等。差异在于它死磕回测的 point-in-time 数据完整性和可结算的评分方式，多数同类项目只演示 agent 对话，不保证不偷看未来数据。

**成熟度**: 版本 0.7.0 还没到 1.0，几乎每月一版且改过 import 路径，文档和 Docker/CI 齐全；官方明说仅供研究、不构成投资建议，属于可玩可研究的早期项目。

**趋势信号**: 2026-10 发的 v0.7.0 允许用自己 ChatGPT Plus/Pro 订阅跑、并给回测加了可核对的结算口径，加上多智能体 + 炒股这个组合本身自带传播度，当天冲上 trending。

### [makecindy/cindy](https://github.com/makecindy/cindy)

 `TypeScript` ⭐ +1,296 今日新增 · 6,755 总星数

> 把 Claude Code、Codex 等多个 harness 塞进一个开源桌面+手机客户端，本地跑真实文件，任务中途能换模型。

**亮点**

- 计费上让你授权已经付费的 Claude Code / Codex 订阅直接在 Cindy 里用，不重复收一份钱，也能换成自己的 API key 或本地模型——多数 agent 客户端要么只支持自带额度，要么只支持 API key，它两边都留了口子

**核心功能**

- Harness 抽象层：Claude Code 和 Codex 是可插拔的执行引擎，中途换 harness/model 时工作区、记忆、skills、工具保持连续；一个任务能拆成规划、并行执行、复核，分别交给不同的 harness×model 组合去跑

**适用场景**: 同时订了 Claude Code 和 Codex 的独立开发者、小团队：想在一个客户端里让 agent 读本机代码、开已登录的浏览器和 IM 干活，还能挂定时任务自动跑；不想为了用 AI 再开三四个窗口的人。

**竞品对比**: 对 Claude Code CLI、Codex CLI 本身是单一 harness、官方 GUI 各管各的；对 Cherry Studio、OpenHands、Conductor 这类客户端，差异在于多 harness 混编、任务中途切换、不重复计费，外加手机端。

**成熟度**: 官方桌面端和手机端已发布、CI/DCO/架构文档齐全，但插件市场、SkillHub 迁移、原生 harness 都还在建，插件生态属于早期。

**趋势信号**: 现在很多人手里同时压着 Claude Code 和 Codex 两份订阅，官方各做各的客户端；Cindy 打「开源聚合壳 + 不重复付费」，正好接住这波对封闭客户端的反弹，一天涨 1296 星。

### [JetBrains/thinkrail](https://github.com/JetBrains/thinkrail)

 `TypeScript` ⭐ +1,173 今日新增 · 3,148 总星数

> JetBrains 孵化器项目，把 pi 编码 agent 包进一个轻量 IDE：用 git worktree 隔离每个工作区，用 SPEC.md 规格图谱给 agent 持久项目记忆。现在火是因为 JetBrains 亲自下场做 agent IDE。

**亮点**

- 没用自研 agent，直接复用 npm 上的 pi 编码 agent 当引擎，ThinkRail 只做界面、工作区隔离和知识层——省掉重造模型调度和工具调用的成本
- 工作区会自己"休眠"：PR 合并/关闭或闲置一周后自动收进每个项目的 shelf，再点开就恢复，避免几十个 worktree 堆成垃圾场
- MCP 服务器默认按只读标记做信任分级，仓库里自带的 MCP 配置必须你手动批准才启用，防止 clone 一个仓库就被挂上恶意工具

**核心功能**

- 每个任务从主仓库切一个 git worktree 当独立工作区（同一仓库多份检出，各有分支和目录），agent 并行干活互不干扰，用完合分支删目录
- 项目知识存成一张 SPEC.md 文件连成的图，agent 通过专用 spec_* 工具读写；规格跟代码一起放仓库里，跨会话不丢上下文
- 同一个工作区能并发跑多个 pi 会话，每个会话独立选模型、显示 token 和成本，可以中途插话改方向或排队下一轮，还能派子 agent
- 编辑器是 Monaco（VS Code 用的那个浏览器编辑器内核），配文件树、终端、diff 视图；在文件或 diff 上留批注，可以直接当结构化上下文发给对话

**适用场景**: 面向已经在用 Claude Code / Cursor 写代码、但嫌单会话串行太慢的开发者。典型场景：一个需求拆成几个分支让 agent 并行改，再逐个 review 合并 PR。

**竞品对比**: 对手是 Cursor、Windsurf、Zed 和 Claude Code。差异在于别人是自研 agent 绑自研编辑器，ThinkRail 是拿现成 pi agent + git worktree 隔离 + 规格图谱，且复用你已有的 pi 配置和 Agent Skills，不锁定账号。

**成熟度**: 早期项目，JetBrains 孵化器标签，装在本地跑但 API 和扩展机制还在改（官方说扩展支持是"下一步"）。

**趋势信号**: JetBrains 官方孵化项目上线并在 Product Hunt 打榜，赶上各家 IDE 厂抢 agentic IDE 的窗口期，一天涨 1173 星主要是品牌和话题驱动。

### [affaan-m/ECC](https://github.com/affaan-m/ECC)

 `JavaScript` ⭐ +896 今日新增 · 290,010 总星数

> ECC 是一套给编码 Agent 用的「行为配置包」，把技能、规则、记忆、安全校验打包成插件，一次安装就能在 Claude Code、Codex、Cursor 等 7 种工具里复用，解决换工具就要重写一遍 prompt 和规则的问题。

**亮点**

- 把「Agent 该怎么干活」当作可版本化的仓库资产来管，而不是散落在每个人本地的 prompt 和 .cursorrules 里，换工具、换人时不用重讲一遍
- 开源（MIT）和托管 GitHub App 并行的模式：仓库永久免费，私有仓库审查按每位 $19/月收费，赞助商包括 CodeRabbit、Greptile、Moonshot Kimi，用这笔钱维持单人每周发版

**核心功能**

- 技能（skills）和规则（instincts）用 Markdown 写成，装成 `ecc@ecc` 插件后由 Claude Code、Codex、Opencode、Cursor 等 7 种 harness 共用同一份配置，不用为每家工具各维护一套

## 趋势观察

今天的榜单几乎是同一件事的不同切面：大家都在给编码 Agent 修配套。第一层是规则和技能开始标准化。ECC、CLAUDE.md 原则文件、设计技能包、NVIDIA 的安全扫描器，本质都是往 Agent 里塞插件：把 prompt、规则、记忆、安全检查打包，一次写好，七种工具通用。开发者已经受够了换个工具就重写一遍。第二层是多 Agent 混装。一个客户端塞进 Claude Code、Codex、Grok，任务中途还能换模型；JetBrains 亲自下场做 Agent IDE，用 git worktree 隔离工作区，用 SPEC.md 做长期记忆。IDE 厂商开始抢 Agent 的入口了。第三层是补短板。设计品味治 AI 模板味，一条命令读登录墙后的推特、B站、小红书，安全审计查提示注入，这些都是模型本身搞不定、只能靠外围工具补的活。还有一条暗线：本地化和开源替代。ElevenLabs 的本地平替，自托管排期工具 Postiz 接上 MCP 让 Agent 直接发帖。数据不出门，成本压到零。合起来看，热点已经从“哪个模型更强”转向“怎么把模型管起来”。模型是发动机，现在大家在造底盘、刹车和安全带。开发者生态的重心，正从调用 API 挪到编排、约束和审计。
