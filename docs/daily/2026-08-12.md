### [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

 `TypeScript` ⭐ +1,138 今日新增 · 14,185 总星数

> 开源编码代理，用递归语言模型思想把上下文当变量，通过持久IPython和自改进harness支持长时间自主任务。

**亮点**

- 守护进程分离：终端断开后agent继续跑，随时attach回来，还支持心跳和计划任务重入会话。
- 技能就是可导入的Python包，内置技能创建器把重复工作流变成项目或个人技能，复用直接import。

**核心功能**

- 持久IPython是内置工具，文件操作、shell、子代理都通过Python代码调用，模型用代码而不是单次工具调用操作环境。
- RLM把子代理当函数：rlm()生成真实子代理并行或后台干活，结果直接返回给主代理。
- harness状态可精炼：/refine基于证据小步更新记忆、技能描述、子代理规格，支持回滚，不碰基础系统提示。

**适用场景**: 需要长时间自主跑编码或研究任务的开发者、AI研究员，比如跑评估、批量改代码、后台监控，用命令行/TUI操作。

**竞品对比**: 和Claude Code、OpenHands比，难点是RLM编程模型和自改进harness，不是靠上下文窗口硬撑，而是把经验持久化到可回滚的会话状态里。

**成熟度**: 开源MIT，有CI和文档，但项目较新，API可能还在变，生产用需谨慎。

**趋势信号**: RLM+自改进是热点，加上PrimeIntellect的PRIME-RL开源生态，今天涨星快。

### [nvm-sh/nvm](https://github.com/nvm-sh/nvm)

 `Shell` ⭐ +22 今日新增 · 94,497 总星数

> nvm 是 Node.js 版本管理器，用 bash 脚本安装和切换多个 Node 版本，解决不同项目需要不同 Node 环境的痛点。它诞生已久，但仍是 Linux/macOS 上的事实标准，因为 Node 版本迭代快，切换需求一直存在。

**亮点**

- 作者坚持用 bash + 子进程而非编译语言实现，换来极低的安装成本和全平台（sh/bash/zsh/fish/kush）兼容性，代价是启动稍慢
- 安装脚本能在不污染系统全局的情况下按用户安装，并自动配置环境变量，还支持 XDG_CONFIG_HOME 等自定义目录

**核心功能**

- 纯 bash 实现，只依赖 POSIX 环境，无需额外运行时，安装时通过修改 PATH 和符号链接切换当前 Node 版本
- 支持 .nvmrc 文件，在项目目录里记录 Node 版本，配合 shell 钩子可实现 cd 进目录自动切换
- 可从 Node 官网或镜像下载预编译二进制，并支持自定义镜像源和离线安装

**适用场景**: 前端或 Node.js 开发者，尤其是同时维护多个项目、依赖不同 Node 大版本（如 v18/v20/v24）的人；CI/CD 流水线中需要快速指定 Node 版本时也常用。

**竞品对比**: 相比 fnm（Rust 编写，速度快）和 volta（能锁定全局包管理器），nvm 最老牌、生态文档最全，社区脚本和教程引用最多；缺点是基于 shell 启动慢，功能相对简单。

**成熟度**: 版本号仍为 0.x，但已维护十余年，是 npm 官方文档推荐的版本管理器，社区极其庞大，生产环境使用广泛，API 稳定。

**趋势信号**: Node.js 每年发布新版本（如 v24），开发者需要快速在不同大版本间切换；nvm 作为默认工具，持续获得关注，近期 stars 增长稳定。
