### [debpalash/VoiceStudio](https://github.com/debpalash/VoiceStudio)

 `Python` ⭐ +2,125 今日新增 · 73,664 总星数

> 一个完全本地运行的 ElevenLabs 替代品：桌面端做声音克隆、配音、听写、有声书，覆盖 646 种语言，还开放本地 API 和 MCP 给 AI Agent 调用。

**亮点**

- 定位很明确：不是又一个 TTS 库，而是把克隆、配音、听写、有声书、模型管理打包成一个 Electron 桌面工作流，装完就能用，不用自己拼 pipeline
- 桌面壳从 Tauri 整体迁移到 Electron，0.5.3 是最后一个 Tauri 版本，旧壳和旧 UI 入口直接删掉，换取前端和 Python 后端更统一的打包方式——代价是老用户必须重装

**核心功能**

- 多引擎可切换：默认用 k2-fsa/OmniVoice，也能换别的 TTS/ASR 引擎，模型按需下载放在本地管理，不强制联网
- 硬件自适应安装：NVIDIA 走 CUDA，Apple Silicon 走 Metal\(MPS\)，没独显就装约 5GB 的精简版 CPU PyTorch，同一套代码三种后端
- 本地 HTTP API + MCP server，Claude Code、Cursor 这类 Agent 能直接调它做语音克隆和朗读；还提供了可粘贴给 Agent 的安装提示词，让它自己检测硬件、下模型、跑一次测试生成
- 语音设计（voice design）：用一段文字描述音色直接生成声音，不需要参考录音；视频配音按时间轴对齐定时语音

**适用场景**: 自媒体和播客作者需要给视频批量配音、做有声书，又不想把素材传到云端；开发者想给自家 App 或 AI Agent 接 TTS/听写，但受合规限制不能调用外部语音 API。

**竞品对比**: 对标 ElevenLabs（闭源云端、按字符计费、音频要上传）和 Coqui TTS / XTTS、GPT-SoVITS 这类开源库（只有模型和脚本，没有配音、听写、模型管理的完整界面）。差异点是一体化桌面工作流 + MCP 接口。

**成熟度**: 早期项目，版本 0.5.x 未到 1.0，刚完成 Tauri→Electron 的破坏性迁移，安装方式和目录结构还可能变；AGPL-3.0 许可对闭源商用集成有约束。

**趋势信号**: 云端语音服务按量计费加数据外传的顾虑在涨，同时 MCP 生态爆发，让"本地跑语音 + 直接给 Agent 当工具"这个组合正好踩在两个热点上。

### [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official)

 `Python` ⭐ +1,397 今日新增 · 41,934 总星数

> Anthropic 官方维护的 Claude Code 插件市场目录，把内部和第三方插件集中登记，用户一条 /plugin install 命令就能装。插件功能刚开放，官方出来做聚合和审核，所以现在热度高。

**亮点**

- 用 renames 映射表解决插件改名破坏已安装用户的问题，把破坏性变更降级成加载器层面的一次透明重写，而不是让用户重装
- strict: false 让市场能直接收录只有 SKILL.md 的仓库，不用作者回头补 manifest，降低了把现有技能包接进来的成本

**核心功能**

- 市场用一份 marketplace.json 描述所有插件，插件目录里用 plugin.json 声明元数据，可选 .mcp.json 挂 MCP 服务器、commands/ 放斜杠命令、agents/ 放子代理、skills/ 放技能包
- 插件名是不可变 slug，改名时必须往顶层 renames 映射表加一条 old→new，Claude Code 加载器下次同步时自动改写旧名，避免用户装着的插件报 plugin-not-found
- 支持 strict: false 的 skill-bundle 模式：源仓库只有 SKILL.md 没有 plugin.json 时，直接在市场条目里列出 skills 相对路径，可以跨多个子目录挑子集，每个技能注册成 &lt;plugin-name&gt;:&lt;skill-name&gt;
- 安装走 Claude Code 内置插件系统，/plugin install {name}@claude-plugins-official 或 /plugin &gt; Discover 里浏览，不用手动 clone 和配路径

**适用场景**: 已经日常用 Claude Code 写代码的开发者，想给它加现成能力（连数据库、调内部 API、跑特定代码审查流程）时，从这里挑插件装；第三方工具厂商和团队想把自己的能力打包分发成 Claude Code 插件，也走这个入口提交审核。

**竞品对比**: 对标 Cursor 的扩展市场、VS Code Marketplace 和 Smithery 这类 MCP 服务器目录。最大差异是它绑定 Claude Code 自身的 /plugin 命令和加载器，安装即生效；同时官方明说不对插件内容做功能和安全验证，把关程度弱于 VS Code Marketplace 的审核。

**成熟度**: 刚上线，主体是目录 JSON 加提交表单，插件质量取决于各作者，README 明确声明 Anthropic 不担保插件里的 MCP 服务器和文件，生产使用前需自行审查。

**趋势信号**: Claude Code 的插件和 Skills 能力刚开放，社区插件散落在各个仓库，Anthropic 此时推出官方目录做统一入口，叠加 Claude Code 本身的使用量上涨，一天涨了近 1400 星。

### [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)

 `Python` ⭐ +1,365 今日新增 · 50,714 总星数

> 一个跑在自己电脑上的求职工作流：基于 Claude Code 的斜杠命令，抓招聘网站、评估匹配度、改简历写求职信、准备面试。作者用它投了 69 份拿到 offer，代码开源可 fork 改成自己的。

**亮点**

- 把 git fork 当成配置机制：整个仓库就是你的求职档案，profile、documents/ 目录、LaTeX 模板都在自己仓库里。README 还专门警告——公开仓库的 fork 一定是公开的，/setup 会把姓名、联系方式、薪资期望写进被 git 跟踪的文件，所以自己用应该建私有仓库 + upstream 而不是 fork
- 每个招聘网站一个薄 CLI，而不是写一个万能爬虫，站点挂了或改版只影响那一个目录；linkedin-search 和 freehire-search 做到零运行时依赖，普通 bun 就能跑

**核心功能**

- 工作流拆成几个斜杠命令：/setup 建个人档案、/scrape 抓岗位、/rank 批量打分排序、/apply 投递、/interview 面试准备，每步是一个独立 skill 目录而非一个大脚本
- 岗位抓取做成一个个独立 CLI，放在 .agents/skills/*/cli/ 下用 Bun 跑；install_portal_clis.py 自动扫描目录批量装依赖，所以你新加一个网站不用改安装脚本，遇到带 install 生命周期脚本的包会跳过并报告
- 简历和求职信用 LaTeX 生成：CV 走 lualatex（避开 fontawesome5 在 MiKTeX 上的字体展开报错），求职信走 xelatex（cover.cls 需要 fontspec）；生成后用 pypdf 或 pdftotext 做一次 ATS 可解析性检查，看机器能不能把你 PDF 里的关键词读出来
- 草稿-评审两段式：先由 drafting agent 出 CV 和求职信，再交给独立的 reviewer agent 按评价标准挑毛病，改完才出终稿，避免一份稿子自我感觉良好直接发出去

**适用场景**: 正在找工作的技术人或转行者，尤其是投递量大、每份都要改简历写求职信的场景；本地跑意味着薪资期望、履历这些敏感信息不用上传给第三方 SaaS 想把自家招聘流程或行业岗位模板做成 agent 工作流的人——它目前只接了丹麦的 Jobindex、Jobnet、Akademikernes Jobbank，换成本地招聘网站要自己写 portal CLI

**竞品对比**: 和 Teal、Simplify、Jobscan 这类简历优化 / 一键投递 SaaS 比，最大差异是全部本地跑、模型走你自己的 Claude 订阅、产物是 LaTeX 源码而不是锁在别人后台的文档；和 AIHawk 那类自动批量投递工具比，它不做无人值守海投，而是卡在「评估匹配度 + 人工确认」这一步。

**成熟度**: 能跑通个人求职的实用阶段，有 CI、SETUP.md、AGENTS.md 和社区 fork 讨论；但它不是库而是工作流模板，强依赖 Claude Code 付费订阅 + 本地 LaTeX + Bun，无版本号，接口随作者自己用而变。

**趋势信号**: 作者把自己的真实求职漏斗（69 份定制投递 → 20 个一面 → 1 个 offer，2026 年 6 月入职 AI 工程师）公开在 LinkedIn 上，加上 Claude Code 的 skills/slash command 生态正热，一个「fork 就能改成自己」的完整工作流模板很容易被转发。

### [xerj-org/xerj](https://github.com/xerj-org/xerj)

 `Rust` ⭐ +1,160 今日新增 · 7,926 总星数

> 本地 AI 检索服务：一条命令索引任意文件夹，让编码 Agent 取到具体段落而不是整文件 grep，同样 16/16 正确率下输出 token 少 2.7 倍。

**亮点**

- 把「参考编码」做成正经用法：先 clone 并索引跟当前任务相近的开源仓库，检索它当年怎么解的，再动手写自己的代码。README 也老实说这招在模型已熟知的流行库上没用甚至有害
- `xerj gain` 直接统计省了多少 token，不是拍脑袋估。对照实验用真实 `claude -p` 的 token 计数，还公开了 278x 那个单任务极端值和边界条件
- 安全边界写得很直白：默认只绑 127.0.0.1，明文绑其他网卡默认拒绝启动，`--insecure` 关掉 TLS 和 API key 后任何能连上端口的人都是超级用户，能读能删所有索引

**核心功能**

- `xerj autoindex &lt;folder&gt;` 一把梭：代码、文档、日志、PDF、SQLite、CSV 自动切成带类型的索引，不用写 schema、不用配 pipeline
- 检索是 BM25 词法 + kNN 向量 + 混合排序三路。默认 embedder 是离线的词法向量（不下载模型），神经 embedding 要手动开，下一个约 90MB 的模型
- Rust 写的单个静态二进制，不依赖 JVM；MCP 原生，`xerj init` 一条命令接进 Claude Code/Cursor，还带 `xerj def` 做 go-to-definition 返回 file:line + 签名

**适用场景**: 用 Claude Code、Cursor 写代码的开发者，面对私有/内部/小众的代码库（模型没训练过的那种），让 Agent 少读整文件。也能拿来检索日志和 PDF 做 RAG、做安全审计、当 Agent 的长期记忆。

**竞品对比**: 对标 ElasticSearch（省掉 JVM、集群和运维，单二进制起）以及各类 RAG/embedding 框架；跟 grep/ripgrep 的差别是返回排好序的段落和 file:line，不是一个文件列表。ES-YAML 兼容性测试过了 1366/1369 条，算是认真在做可替换性。

**成熟度**: 早期项目：默认 `--insecure` 无鉴权，靠用户提交 field report 驱动迭代，别急着拿它顶替生产环境的 ES。

**趋势信号**: Agent 编码的 token 账单越来越疼，MCP 生态又刚好成熟，加上它直接点名「grep 是 1974 年的工具」这个说法在社区里传得快，一天涨 1160 星。

### [stablyai/orca](https://github.com/stablyai/orca)

 `TypeScript` ⭐ +830 今日新增 · 95,586 总星数

> Orca 是一个把多个编码 Agent（Claude Code、Codex、OpenCode、Pi）并行管起来的桌面应用：每个 Agent 独占一个 git worktree，桌面、手机、SSH 远端都能盯和接管。现在火是因为大家开始同时开好几个 Agent 干活，但缺一个统一调度台。

**亮点**

- 不做自己的 Agent 运行时，只做外壳：只要能在终端里跑就能接进来，并且用的是用户自己的 Claude/Codex 订阅而不是按 token 走 API 计费，这直接决定了很多人的成本账
- 账号热切换 + 用量面板：显示 Claude 和 Codex 的额度消耗和 rate-limit 重置时间，额度用满时切账号不用重新登录，这是重度用户每天都会遇到的痛点

**核心功能**

- 并行 worktree 编排：一条 prompt 分发到 5 个 Agent，每个 Agent 在不同 git worktree（同一仓库的多份独立工作副本）里跑，跑完对比 diff，只 merge 赢的那个，隔离全靠 git 不加容器
- Design Mode：内嵌真实 Chromium 窗口，点任意 UI 元素就抓出该元素的 HTML、CSS 和裁剪后的截图，直接塞进 Agent 的 prompt，省掉手写「按钮偏了 3px」这类描述
- 终端用 WebGL 渲染（对标 Ghostty），支持无限分屏、重启后 scrollback 不丢；SSH 远端 worktree 带自动重连和端口转发，Agent 可以跑在性能更强的机器上，本地只做展示
- Orca CLI 让 Agent 反过来操作 Orca 自己：orca worktree create / snapshot / click / fill，等于给 Agent 一套 computer use 的接口去驱动 GUI

## 趋势观察

今天这份榜单几乎被一件事占满：AI 编程 Agent 的「外挂层」集体爆发。Anthropic 亲自下场做插件市场，一条命令就能装插件；第三方跟着补位，有的统一技能和记忆，有的把桌面软件封成命令行，有的给科研、Android 写 SKILL.md 操作手册。共同点很清楚——模型本身不再是卖点，卖点变成了怎么把 Agent 喂饱、管住。 第二个信号是多 Agent 同框。很多人手上同时开着 Claude Code、Codex、Cursor、OpenCode，问题是每换一个就得重讲一遍背景。于是记忆层、插件抽象层、Orca 这种并行调度台全冒出来了。它们不负责写代码，负责省下重复沟通的成本。 第三个是省 token、要准头。本地检索服务号称同样正确率下输出少 2.7 倍。大家开始算账了，光堆上下文不行。 还有个细节：求职工作流投了 69 份拿 offer，本地声音克隆覆盖 646 种语言。都是个人开发者拿 Agent 拼出来的实用工具，不再是 demo。一句话收束：开发者生态正从「哪个 Agent 最强」转向「一堆 Agent 怎么协作、怎么装技能、怎么记住事」。插件和标准成了新的入口。
