### [ZhuLinsen/daily_stock_analysis](https://github.com/ZhuLinsen/daily_stock_analysis)

 `Python` ⭐ +506 今日新增 · 69,257 总星数

> LLM 把多市场行情和新闻汇总成每日股票决策报告，用 GitHub Actions 零成本定时推送到企业微信、飞书、Telegram 等 IM。

**亮点**

- 产品形态是日报而不是聊天框：模型输出被压成结构化字段，可直接渲染成推送卡片，也存进 Web/桌面工作台做历史对比和回测

**核心功能**

- 行情源做成可插拔的降级链：AkShare、Baostock、YFinance 等免费源打底，配了 Tushare、Longbridge token 就自动补量比、换手率、PE 等字段，单个源限流或接口改版时切下一个
- 拿 GitHub Actions 的 cron 当调度器，默认工作日 18:00（北京时间）跑，内置 A/H/US 节假日判断和断点续传，用户 fork 后只填 Secrets，不需要服务器
- 把 LLM 输出约束成固定字段的「决策仪表盘」——结论、评分、趋势、买卖点位、风险警报、催化因素、操作清单，再渲染成 Markdown 卡片推 6 个渠道；另配 15 种内置策略（均线、缠论、波浪等）做多轮追问
- 新闻侧接 SerpAPI、Tavily、博查、Brave、SearXNG 等多源搜索，可选 Reddit/X/Polymarket 社交舆情（仅美股），喂给模型做舆情和事件判断

**适用场景**: 适合没时间盯盘的上班族散户：收盘后自动收到 A股/港股/美股/日股自选股的分析日报。也适合做投研或量化的人，拿它当「多源行情 + 新闻聚合 + LLM 摘要」的脚手架二次开发。

**竞品对比**: 和 OpenBB（开源金融数据终端）、TradingAgents（多智能体投研框架）、FinGPT 比，那些偏研究或本地跑，这个更像成品日报工具，差异点在于开箱即用的推送渠道和零成本托管。数据层本身还是靠 AkShare/Tushare 这些上游。

**成熟度**: 迭代快、文档全（中英繁三语 + docs/INDEX + CI + Docker Hub 镜像），但没看到 1.0 版本号，README 明说免费行情源稳定性不保证，加上大量赞助商返佣链接，适合自用，生产环境要自己兜底数据源。

**趋势信号**: 项目刚挂出 arXiv 论文（2608.26990），README 里还贴着 Trendshift「当日 Python 榜第一」的徽章，叠加当下 LLM 调用成本下探，「AI 炒股日报」这类需求被零成本 Actions 模板放大，社区二次传播明显。

**适用场景**: 天天泡在 Claude Code、Codex、Cursor 里的开发者或创始人，想让 Agent 记住见过谁、聊过什么、还欠着哪些事；小团队做共享公司大脑，靠 source/operation 授权加可见性过滤，约束远程客户端只能看该看的部分。

**竞品对比**: 对标 Mem0、Zep、Letta（原 MemGPT）这类 Agent 记忆层。差异在：自托管 MIT、每条记忆带来源和撤回、跨 harness 走 MCP 共用一份，且作者有 15.5 万页的真实个人部署在跑。

**成熟度**: MIT 自托管，作者自用在生产跑（15.5 万页、2.4 万人、5 千家公司），但只经个人和小团队验证；文档很细，同时自己标注了「尚待验证步骤」，并明确说共享访问的隔离不是万能防漏保证。

### [ruvnet/RuView](https://github.com/ruvnet/RuView)

 `Rust` ⭐ +172 今日新增 · 103,672 总星数

> 用几美元的 ESP32 采集 WiFi 信道状态信息，不用摄像头就能测人体位置、呼吸和心率，并直接接进 Home Assistant 和 Matter。

**亮点**

- README 没有夸大：多传感器融合的“统一 RF 世界模型”自己标注了精度仍是合成数据、尚未经真实数据验证，没有把论文指标当作产品指标
- 每条感知事件都附带隐私策略、置信度、数据来源和见证记录，把“这个结论凭什么得出”变成可查询的数据结构，而不是只给一个布尔值

**核心功能**

- 从 ESP32 固件侧抓 CSI（信道状态信息，指 WiFi 每个子载波的幅度和相位；人走动、呼吸都会轻微扰动这些数值），后端再从扰动反推位置和体征
- 用 CSI 时序做 17 个身体关键点的姿态估计，思路接近 WiFi DensePose 这类研究，输入端只有射频信号，没有一帧画面
- 每个节点对外暴露 21 个实体：11 个原始信号量加 10 个语义状态（有人睡觉、可能跌倒、浴室占用、老人长时间无活动），通过 MQTT 推给 Home Assistant，同时用 Matter 桥和 HAP-1.1 桥接进苹果家庭、谷歌、Alexa

**适用场景**: 适合 Home Assistant 玩家在卧室、浴室做存在检测又不想装摄像头；也适合养老看护场景，在不拍到人的前提下判断老人是否起床、是否长时间没动静。

**竞品对比**: 同领域有 MIT 的 RF-Pose、CMU 的 DensePose from WiFi 等论文方案，商业侧有 Origin Wireless、Aerial 这类卖整套硬件的公司。主要差异是它开源、跑在廉价的 ESP32 上，并直接对接 Home Assistant 和 Matter，而不是绑定厂商硬件。

**成熟度**: 早期项目，部分精度自己承认未用真实数据验证；10 万+ star 与项目体量不太匹配，建议当技术验证看，别直接上生产。

**趋势信号**: 赶上“无摄像头感知”这波隐私讨论，加上刚接进 Home Assistant/Matter 生态并在推自家 Cognitum Seed 硬件，所以被推上趋势榜。

### [sherlock-project/sherlock](https://github.com/sherlock-project/sherlock)

 `Python` ⭐ +4,267 今日新增 · 107,784 总星数

> 一个 Python 命令行工具，输入用户名就批量探测它在 400+ 个社交网站有没有注册账号。适合 OSINT 调查和隐私自查。

**亮点**

- 核心思路是"每个站点自带一套失败特征"，而不是统一用 HTTP 200 判断存在。这个取舍直接决定了准确率，也让维护变成了纯数据工作
- 数据和代码彻底分离，社区靠提 PR 往 JSON 里加站点，项目能滚到 400+ 站点而主程序基本不变

**核心功能**

- 站点规则全放在 resources/data.json 里，每个站点写清 url、urlProbe、errorType（status_code 或 message）、regexCheck、headers。加新站点只改 JSON，不用动代码
- 用 ThreadPoolExecutor 线程池并发请求所有站点，边跑边流式打印结果，不用等一个站点返回后再发下一个，全量几百个站点几十秒跑完
- 判断账号是否存在有两条路：一是看 HTTP 状态码；二是 errorType=message 时在页面正文里搜索"该用户不存在"之类的关键字。因为很多站点对不存在的用户也返回 200，只看状态码会误判
- 支持 --tor/--proxy 通过 SOCKS 代理发请求，结果可导出 CSV/JSON/XLSX

**适用场景**: 安全研究者和渗透测试人员做前期信息收集：从一个人常用的用户名出发，摸清他在哪些平台有账号；普通用户也可以拿它查自己的用户名被哪些站占用了

**竞品对比**: 最直接的对手是 Maigret（Sherlock 的分支），站点数量更多，还能递归爬取关联账号并生成 PDF/HTML 报告；WhatsMyName 提供网页版和公开站点清单。Sherlock 的优势是站点库更新快、CLI 简单、安装即用。

**成熟度**: 版本还在 0.x（约 0.15），长期维护、社区大，但准确性受站点改版影响，误报和漏报要靠持续更新 data.json 来修，属于"能用但要自己核对结果"的阶段。

**趋势信号**: 具体导火索不明，可能是社交平台上 OSINT、隐私自查类内容的二次传播带火；项目本身一直是 OSINT 入门的标配工具。

### [meta/astryx](https://github.com/meta/astryx)

 `TypeScript` ⭐ +3,278 今日新增 · 20,893 总星数

> Meta 把内部用了八年的设计系统开源了：150+ 组件、主题就是一组 CSS 变量、CLI 为 AI 编码助手设计，人和 agent 用同一套工具搭界面。

- 「指南优先于强制」：组件不拦你传什么值，设计意见只放在文档和示例里，不写成运行时校验。代价是靠自觉，收益是不会跟业务代码打架

- CLI 管组件文档、模板、脚手架、主题和 codemod，官方建议全局装一份——这样任何目录下跑 Cursor/Claude Code 都能读到同一份 API 参考

**适用场景**: 适合做多产品线、多品牌中后台的前端团队，一套系统覆盖 13000 个应用那种规模；也适合已经在用 AI 编码助手批量生成页面、但苦于助手猜不准组件 API 的团队。

**竞品对比**: 对比 MUI、Ant Design、Chakra：那些要么绑死自家样式方案，要么主题靠 JS 配置对象；Astryx 主题是纯 CSS 变量、样式层可整体绕过、还能 swizzle 出源码，接进已有项目阻力小。思路接近 shadcn/ui 的「源码归你」，但 Astryx 还额外提供 150+ 组件的托管包和一套 CLI。

**成熟度**: Beta 阶段、npm 未到 1.0，公开 API 可能还会变；但组件在 Meta 内部跑了八年、13000+ 应用验证过，文档、Storybook、Sandbox 都齐。

**趋势信号**: Meta 头一回把自家最大的设计系统对外开源，正好踩在「agent ready」这个风口上，单日 3000+ 星基本是发布事件本身带来的。

### [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot)

 `TypeScript` ⭐ +1,587 今日新增 · 20,106 总星数

> 一个开源的“AI 机器人通讯录”桌面应用：每个联系人都由本机的 Claude/Codex/Grok CLI 实际驱动，各自有独立人格、模型、虚拟机和授权应用，数据留在本地。趁着几款闭源个人 agent 密集发布，它补上了开源本地版的位置。

**亮点**

- 把 agent 做成即时通讯的形态：侧边栏每个“联系人”是一个独立 agent，有自己的模型、线程记忆、电脑和已授权应用，人像发消息一样派活，不用在多个终端之间切换
- 复用用户已有 CLI 登录而不自带账号体系，等于不承担模型成本，也不做中间代理，这是它能开源免费跑起来的关键取舍

**核心功能**

- bot 实际就是本机已装的 claude、codex、grok 命令行进程；一个监听 127.0.0.1 的本地小型服务统一启动并托管所有 agent 子进程，直接复用你现有的登录和订阅，中间没有代理服务器，聊天记录和密钥保存在 ~/.openmausbot
- 每个 bot 有独立执行环境，三选一：云端 Linux 桌面、隔离的本地虚拟机，或在 macOS / Ubuntu Xorg 上显式同意后接你本机。Ubuntu Wayland 的主机控制被主动关掉（issue #345 未解决），用平台边界换取安全
- 通过 Composio 接 500+ 个第三方应用；bot 做敏感操作时弹出审批卡片等你点确认，登录走 OAuth 不存密码；引擎可插拔，Settings → Engines 里能指向任意自定义 CLI 二进制或 wrapper

**适用场景**: 适合已经有 Claude / ChatGPT / Grok 订阅、又不想把代码和账号交给云端的开发者或小团队：开几个 bot 分别管写代码、跑脚本、连 Slack 和邮箱，人在聊天窗口里盯进度、点审批。

 `Rust` ⭐ +916 今日新增 · 48,727 总星数

> Vercel Labs 出的浏览器自动化命令行工具，让 AI Agent 用一条条 shell 命令开网页、读页面、点元素。Rust 写的原生 CLI，靠常驻守护进程保持浏览器不关，每步调用不用重新启动。

**亮点**

- 选 CLI + 常驻守护进程而不是 Node 库：Agent 每步只发一条短命令，不用背着长驻的 Playwright 进程，也不需要每次冷启动浏览器，天然适配只会执行 shell 的 Agent

**核心功能**

- 点击失败要报错而不是假装成功：目标隐藏、禁用、在视口外、被同意弹窗遮住都会返回失败，逼 Agent 先关遮挡物再重新快照重试，减少自动化流程里的假阳性
- 技能包跟 CLI 版本绑定：装进 Agent 的只是一个薄壳，运行时执行 `agent-browser skills get core` 拉当前版本的正确指令，避免文档和实际命令对不上；另外提供 stdio 的 MCP server

**适用场景**: 写代码的 AI Agent（Claude Code、Cursor 这类 CLI Agent）需要真正打开网页验证前端改动、填表单、抓登录后的数据时用它。也可用于 QA 自动化、需要复用登录态的爬取和日常网页操作脚本。

**竞品对比**: 对手是 Playwright/Puppeteer 的 MCP 封装、browser-use、Stagehand、Browserbase。最大差异是不做库而做 CLI：Agent 每步一次 shell 调用、浏览器常驻，相对 Playwright MCP 省掉长连接和整页快照的 token；同时能挂 Lightpanda、iOS 模拟器 Safari、Browserbase 等云端浏览器，引擎可换。

## 趋势观察

今天的榜单几乎被 Agent 的工具层占满了。Anthropic 连发两个官方仓库，一个把技能拆成带 SKILL.md 的文件夹，一个把客服、电脑操作、浏览器自动化做成能直接跑的例子。这说明竞争点已经从模型跑分，转移到了“agent 到底怎么干活”。接口正在统一。记忆层走 MCP，Home Assistant 被包成 87 个 MCP 工具，Vercel 的浏览器工具干脆把 shell 命令当成 API。大家都想让自己的东西被任意 agent 调用，MCP 成了事实上的统一接口。另一条线是工具本身在重做。Meta 的设计系统明说 CLI 是给 AI 编码助手设计的，人和 agent 共用同一套组件。工具不再只服务人。开源也在填补空缺。Garry Tan 的记忆层、本地 AI 通讯录，都是赶在闭源个人 agent 密集发布时上场的，数据留本地，模型可以换。还有一层是软硬结合。DeepMind 的物理引擎成了人形机器人仿真的默认底座，几美元的 ESP32 就能测呼吸和心率。Agent 正从屏幕里往外走。汇总下来：agent 不再是聊天窗口，而是有记忆、有工具箱、有标准接口的执行体。谁把工具链接好，谁就先拿到下一轮的入场券。
